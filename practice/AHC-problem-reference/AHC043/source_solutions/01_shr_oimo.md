## 解法の全体像

全ての駅を1つの連結成分として扱い、駅間の接続は最短マンハッタン経路に制限する。この制限の上で、まずビームサーチにより駅の追加順と駅同士の接続関係を作る。ただしビーム中は線路をグリッド上に確定せず、各駅・各接続が使える上下左右方向をビット集合として持ち、矛盾しない範囲で候補を狭める。

ビームで得た木を初期解にし、駅を頂点、線路接続を辺とする根付き木に対して焼きなましを行う。木の局所変更に対して、必要線路数と収入増分を差分計算し、最終資金を高速に評価する。最後に接続方向を確定し、実際の線路経路を構築して実行可能性を検査する。延長戦では、駅建設待ちの間に将来必要な線路を先に置く「線路先置き」も評価と出力へ組み込んでいる。

## 主要アイデア

- 全駅を単一連結成分にし、駅間は最短距離でつなぐという制約で問題を単純化する
- ビーム中は線路マスを陽に持たず、接続方向の候補集合だけを持つ
- 方向候補の伝播により、局所的に矛盾しない接続だけを探索する
- 既存の未確定線路の最短経路領域に新駅を差し込める場合は、線路コストを増やさずに駅を追加する
- 評価は最終資金予測で、片側だけカバーされた住民の将来価値や複利的な成長も近似的に入れる
- 序盤の駅は後から焼きにくいため、ビーム幅を序盤ほど太くする
- 焼きなましでは根付き木を状態とし、頂点 swap、移動、親付け替え、追加、挿入、削除、貪欲改善を使う
- 部分木の最小設置番号を使い、ある駅の設置時にどこまで線路を伸ばす必要があるかを高速に判定する
- 実行可能性に不安が残るため、定期的に実際の線路構築を試し、失敗した候補は捨てる
- 線路先置きでは、収入閾値を超えたら待機の代わりに将来の線路を置く

## 最終コードの構造

Browserで読めた提出 #63120208 と記事本文から読み取れる実装構造である。提出は非常に大きいため、完全な行単位追跡ではなく主要型と方針の照合に留める。

### 状態表現

- `Problem`: 入力と、各駅候補座標が距離2以内に含む住民側情報 `stationToPlaces` を持つ。
- `Tile`: 線路タイル種別。直線・曲線・駅を持ち、接続方向判定を行う。
- `Connection` / `Station`: 駅座標、接続先、方向候補を持つ。`possibleDirBitsForPos` で相手座標から候補方向を絞る。
- 駅を頂点、駅間接続を辺とする木を持つ。
- 接続方向候補は上下左右を4ビットで表し、1つの辺の両端について候補を管理する。
- 焼きなましでは、0番駅を根とした根付き木を持つ
- 各頂点に「部分木内の最小設置番号」を持つ
- 各家・職場について、それをカバーする駅番号集合を持つ
- 各駅設置時の収入増分、必要線路数、スコア再計算用の累積値を持つ
- 実行可能候補のスタックを持ち、構築失敗時に巻き戻せるようにする

### 観測・制約・入力の扱い

- 家・職場は駅からマンハッタン距離2以内ならカバーされる
- 住民の収入は、家側と職場側の両方が同じ連結成分内の駅でカバーされた時点で発生する
- 駅は4方向まで接続できるが、線路は分岐できないため、未設置駅の位置でT字路が生じないようにする
- 接続方向候補が空になる状態、線分が交差する状態、後で線路を復元できない状態を避ける
- 同じ端点を共有する線分同士は交差扱いしないが、片方の端点が他方の内点に乗る場合は交差扱いにする

### 評価関数

- 基本評価は、最後までシミュレーションしたときの最終資金の予測値である
- ビームでは、追加駅に必要な線路数と、その駅で増える収入を使う
- 片側だけカバーされている住民は、もう片方を後でカバーしたときの価値として収入の一部を上乗せする
- 最後の駅設置後に単純に待つだけでなく、次の駅を建てるために必要なターン数も近似的に見る
- 焼きなましでは、各駅の必要線路数と収入増分が分かれば駅数 `S` に対して `O(S)` で生スコアを計算できる
- 線路先置き導入後は、先置きした線路数だけ複利にかかるターン数を上乗せする近似評価を使う

### 探索・構築・更新

- ビームサーチ:
  - 初期2駅は別評価で有望ペアを絞り、上位500個程度を始点にする
  - 駅を1つ追加して既存木に最短接続する
  - 接続方向候補を伝播し、局所的な矛盾を弾く
  - 評価値の上界で候補をソートし、厳密評価が必要な候補だけ計算する
  - 序盤ほどビーム幅を太くする
- 焼きなまし:
  - 木の頂点番号 swap
  - 頂点の微小移動
  - 親の付け替え
  - 頂点追加
  - 既存辺への頂点挿入
  - 頂点削除
  - 悪化しない貪欲改善
- 差分更新:
  - 部分木最小設置番号を更新し、線路が必要になる境界を平均 `O(1)` で求める
  - 家・職場をカバーする駅集合の最小番号を更新し、収入発生駅を差分更新する
  - 木の一部が変わった場合、変更前までのスコア配列を再利用する

### 操作・クエリ・出力選択

- 探索終了後、各接続で使う出口方向を確定する
- 未確定方向はランダムに選び、矛盾したら別候補を試す
- 実際の線路経路を構築し、失敗した場合は実行可能な候補まで巻き戻す
- 線路先置き導入版では、収入が閾値を超えたら待機せず将来必要な線路を先に出力する
- 最終出力は800ターン分の行動列で、資金が負にならないようシミュレーションして決める

### 時間配分・パラメータ

- ビーム幅は序盤ほど大きくする
- 初期2駅候補は上位500個程度
- 定期的に実行可能性検査を行う。記事では全体時間の10%ごとにベスト候補を検査する方針が述べられている
- 近傍選択確率は、焼きなまし進捗と `M` に応じてバイリニア補間する
- 近傍重みは4点、すなわち開始・終了時点と `M=50`・`M=1600` の組で持つ
- ハイパーパラメータは Optuna で調整したとある
- 線路先置き閾値は `M` に応じて110から600程度の範囲を使う

接続方向候補の伝播:

```text
add_edge(u, v):
    dir[u][v] = shortest_direction_candidates(u, v)
    dir[v][u] = shortest_direction_candidates(v, u)
    queue.push((u, v), (v, u))
    while queue not empty:
        e = queue.pop()
        new_mask = restrict_by_other_edges(e)
        if new_mask is empty:
            reject state
        if new_mask changed:
            propagate related edges
```

木から必要線路数を計算する考え方:

```text
rails_for_station(v):
    if subtree_min[v] < order[v]:
        return 0
    rails = 0
    while parent[v] exists and subtree_min[v] >= order[v]:
        rails += dist(v, parent[v]) - 1 or edge_part_cost
        v = parent[v]
    return rails
```

```text
activation(person):
```

## この解法の本質

この解法の本質は、線路をグリッド上のマス列として持つ難しさを最後まで遅延し、探索中は「駅と木」と「接続方向の制約」に落とし込む点である。実際の線路を確定しないため、後から駅を既存経路に差し込む自由度が残り、局所探索も高速になる。

一方で、線路を遅延したままでは不可能な木も混ざる。そこで接続方向候補、線分交差、部分木最小番号、定期的な復元検査を組み合わせ、探索の自由度と出力可能性のバランスを取っている。収入が増えるほど後の建設が楽になる複利構造を評価に入れ、序盤を厚く探索する点も重要である。

## 真似するならまず実装する部分

まずは全駅を1つの木として扱い、駅候補を追加して最短距離で既存駅へ接続する貪欲または細いビームを作るのがよい。評価は「現在資金、現在収入、最後まで待った場合の資金、片側カバーの期待値」から始める。

次に、木の局所変更を焼きなましするなら、線路経路そのものではなく駅順と親関係だけを状態にする。上位化するなら、部分木最小番号による必要線路数計算、家・職場のカバー駅集合による収入差分、実行可能性検査、線路先置きを順に入れる。

## 注意点・未理解点

- 接続方向候補の伝播は記事でも実装困難とされており、提出 #63120208 でも関連実装が大きい。完全な仕様は短時間の精読では再現できない。
- ビームの評価関数に入れる複利係数、片側カバー係数、初期2駅評価は調整依存である
- 焼きなまし近傍ごとの重みと温度は Optuna 調整で、具体値は公開されていない
- 線路を陽に持たないため、最後に復元できない候補が残る可能性がある
- 線分交差判定は端点共有と内点接触の扱いを間違えると、可能な接続を捨てたり不可能な接続を採用したりする
- 線路先置きの近似評価は多くのケースで効くとされるが、不要な先置きが発生するケースでは実スコアより低く見積もる
