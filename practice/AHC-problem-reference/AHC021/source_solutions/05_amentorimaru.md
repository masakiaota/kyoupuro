## 解法の全体像

小さい番号から順に処理し、そのボールを置ける候補位置まで動かす経路選択を最短経路問題として扱う。上方向以外へ動く操作には大きい固定コストを置き、上方向へ動く場合は交換相手の番号 `x` に対して `465 - x` のコストを置く。つまり、大きい番号のボールを通る経路ほど安くなり、結果的に大きい番号を下へ落とす経路が選ばれる。

本番中は、この Dijkstra による経路復元付き貪欲だけで21位だったとされる。さらに、その経路コスト総計を評価値にしてビーム幅40のビームサーチにしたものが、本番1位相当まで伸びた改善として紹介されている。

## 主要アイデア

- 小さい番号から貪欲に選ぶ。
- 置ける候補位置を複数考え、各候補までの移動経路を最短経路として解く。
- 上方向以外の移動はコスト465とし、基本的には避ける。
- 上方向移動では、上にあるボール番号を `x` としてコスト `465 - x` を使う。
- 大きい番号を通るほど低コストになるため、大きい番号を下に押し下げる経路が自然に選ばれる。
- Dijkstra の経路復元で、そのまま swap 列を作る。
- 改善版は、同じコスト設計を状態評価にしたビームサーチで幅40。

## 最終コードの構造

Browserで読めた提出 `64234033` と記事本文を分けて読む。本文はDijkstra貪欲と幅40ビームの説明で、読めた提出は汎用BeamSearchを用いた後日提出である。

### 観測・制約・入力の扱い

- 入力は通常どおり三角形盤面として読む。
- 0は頂点に固定されるなど、小さい番号ほど候補位置が強く制限されることを利用する。
- 「全ての置ける候補」に対し、現在位置からの最短経路を比較する。
- 記事には候補位置の厳密な判定実装はないため、別解の `fixed` 管理のような仕組みが必要になる。

- 貪欲版では、候補位置までの最短路コストが評価である。

  - 上以外へ動く: `465`
  - 上へ動く: 交換相手の番号を `x` として `465 - x`
- ビーム版では、この経路コストの総計を状態評価として用いる。

### 探索・構築・更新

- 各番号について、現在位置から置ける候補位置群へ Dijkstra を実行する。
- 最小コストの候補を選び、親ポインタから経路を復元する。
- 復元した経路に沿って隣接 swap を行い、盤面と逆引きを更新する。
- ビーム版では、候補選択または経路選択の分岐を幅40で保持する。

### 操作・クエリ・出力選択

- Dijkstra の経路復元結果がそのまま出力操作列になる。
- 貪欲版は各番号で最小コスト候補を1つ選ぶ。
- ビーム版は累積コストの良い状態を残し、最後に最も良い完成状態の操作列を出すと考えられる。

### 時間配分・パラメータ

- 貪欲版の主要パラメータはコスト定数 `465` と `465 - x`。
- ビーム幅は40。
- 記事からは実行時間管理、同点処理、打ち切り条件は分からない。

## 実装上重要な断片

```text
for ball in 0..464:
    goals = all currently placeable cells
    dist, parent = dijkstra(current_position(ball), move_cost)
    goal = argmin(dist[g] for g in goals)
    path = restore_path(parent, goal)
    apply swaps along path
```

```text
move_cost(from, to):
    if to is upward from from:
        x = board[to]
        return 465 - x
    else:
        return 465
```

## この解法の本質

経路選択を局所的な二択ではなく、三角形グラフ上の最短路として定式化している点が本質である。上方向以外を強く罰しつつ、大きい番号を通る上方向移動を安くすることで、「短い経路」と「将来のために大きい番号を下げる経路」の両方を1つのコストにまとめている。これにより、単純貪欲より広い経路選択ができる。

## 真似するならまず実装する部分

まず、置ける候補位置の管理と、三角形グラフ上の Dijkstra を実装する。ビームサーチに進む前に、`上以外=465`、`上=465-x` のコストで経路復元し、貪欲に1解を作るところまでが最小実装である。ビーム幅40は、その貪欲評価が動くことを確認してから導入するのがよい。
