## 解法の全体像

基礎となるのは、小さい番号 `i` から順に、そのボールの上に `i` より大きいボールがあれば交換して上へ移動する貪欲である。親2候補の両方が `i` より大きい場合、単に大きい親を選ぶのではなく、左右それぞれを1手だけ仮適用した後、残りを基礎貪欲で最後までシミュレーションし、総操作回数が少なくなるほうを採用する。

再帰的な先読みはせず、分岐点ごとに「片方を選んだ後は貪欲で進める」という1段先読みを行う。実行時間は記事によれば約50msで、ビームサーチを使わずに大きく改善している。

## 主要アイデア

- 小さい番号から順に処理すれば、上に置くべき候補の制約が強い順に決まる。
- 通常時は、上方向にある `i` より大きい親と交換する。
- 親2候補がどちらも交換可能なときだけ、2通りを仮に試す。
- 仮に1手交換した盤面から、残りを単純貪欲で完了させる操作回数を計算する。
- 先読みの評価はスコア式ではなく、単純に追加操作回数の小ささで行う。
- 候補数が2しかない局所分岐に限定することで、実装量と計算量を抑える。

## 最終コードの構造

### 状態表現

- `b[x][y]`: 三角形盤面のボール番号。
- `pos[value]`: ボール番号から現在座標への逆引き。
- `ans`: 実際に採用した操作列。
- `inside(x, y)`: 三角形範囲判定。
- 上方向は `(-1, 0)` と `(-1, -1)` の2候補として扱う。

### 観測・制約・入力の扱い

- 入力を行ごとの可変長 `vector<vector<int>>` に読み、同時に `pos` を作る。
- 操作数が `K = 10000` に達したら処理を止める。
- 範囲外の親候補は `inside` で除外する。
- 交換時は盤面と逆引きを必ず同時に更新する。

### 評価関数

- 明示的な盤面評価値は使わない。
- 分岐評価は `simulate(i)` が返す「現在値 `i` 以降を単純貪欲で進めたときの操作回数」である。
- 親2候補の両方が交換可能な場合だけ、2つの仮適用に対して `simulate(i)` を比較する。

### 探索・構築・更新

- 外側ループは `i = 0..464`。
- 各 `i` について、上に `i` より大きい親がある限り `while` で移動する。
- 親2候補の両方が交換可能なら:
  - 右上側を仮交換して `simulate(i)`。
  - 巻き戻す。
  - 左上側を仮交換して `simulate(i)`。
  - コストが小さいほうの交換を本採用する。
- 片方だけ交換可能なら、その親と交換する。
- `simulate` は盤面と逆引きをコピーし、そこから基礎貪欲を実行して操作数だけ数える。

### 操作・クエリ・出力選択

- 採用した交換を `ans` に積む。
- `ans` の各要素は `(交換先の親座標, 現在座標)` の形で出力できるように保持する。
- 最終的に `ans.size()` と全操作を出力する。

### 時間配分・パラメータ

- 制限時間を使い切る探索ではない。記事では約50ms程度とされている。
- 固定パラメータは操作上限 `K = 10000` 程度で、温度やビーム幅はない。
- `simulate` は毎回盤面全コピーを行うが、盤面が465個で小さいため成立している。

## 実装上重要な断片

```text
choose_when_two_parents(i):
    apply swap with parent A
    cost_a = greedy_simulation_from(i)
    rollback

    apply swap with parent B
    cost_b = greedy_simulation_from(i)
    rollback

    commit the parent with smaller simulated remaining cost
```

```text
greedy_simulation_from(v):
    copy board and positions
    for i in v..464:
        while an upper parent is larger than i:
            if both parents are larger:
                swap with the larger parent
            else:
                swap with the available larger parent
            count += 1
    return count
```

## この解法の本質

この解法は、分岐の少ない箇所だけを先読みする「軽量なロールアウト」である。完全な探索ではなく、分岐後の未来を基礎貪欲で近似するため、実装はほぼ貪欲のままで済む。それでも、左右どちらを選ぶかが後続の手数に効く場面を拾えるため、単純な「大きい親を選ぶ」より大きく改善する。

## 真似するならまず実装する部分

まず k_k_pyrhon 氏の改良版相当、つまり小さい番号から上げ、親2候補では大きい番号の親を選ぶ貪欲を実装する。次に、両親がどちらも交換可能な場合だけ盤面コピーと `simulate` を入れる。ビームサーチなしで改善を体感できるため、最初の強化として扱いやすい。

## 注意点・未理解点

- 仮交換後の巻き戻しは `b` と `pos` の両方で必要である。片方だけ戻すと以後の `pos[i]` が壊れる。
- コードでは `cost < ncost` の分岐に合わせて、片方の仮交換状態を残したまま本採用する形になっている。読みにくいので自分で実装するなら明示的な `commit_swap` に分けるほうが安全である。
- `simulate` の中では、両親が使えるとき基礎貪欲どおり大きい親を選ぶ。ここを同じ先読みで再帰させると計算量が膨らむ。
- eijirou 氏の AHC015 記事は、この問題の直接解法ではなく「候補を試し、残りを簡易方針でシミュレーションして選ぶ」という発想元として読んだ。
