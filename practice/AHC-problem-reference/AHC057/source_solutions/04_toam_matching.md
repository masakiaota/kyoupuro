## 解法の全体像

この解法は、最終的な30個x10を一気に作らず、連結成分サイズの遷移をあらかじめ決め打つ。各段階で「この期間中にどの成分同士をマージするか」を重み付きマッチングとして解く。辺重みは、対象期間中に2成分が最も近づく距離である。

例えば最初の段階では、300個のサイズ1成分から140組を作り、20個は未マージで残す。未マージを許すためにdummy頂点を追加し、最小重み完全マッチングに帰着する。後続段階も、許されるサイズ組だけ辺を有限重みにし、許されない組は無限大にすることで同じ枠組みで処理する。

## 主要アイデア

- 成分サイズの遷移を固定し、グループ構築を段階的なマッチング問題へ落とす。
- 未マージで残す成分はdummy頂点との0コストマッチで表現する。
- 許されないサイズ同士のマージは辺重みを無限大にして禁止する。
- 各辺重みは、指定時間区間における成分間の最小距離である。
- そのままマッチングすると序盤で速度ベクトルが打ち消されるため、速度損失にペナルティを入れる。
- step1を長め、たとえば `t=500` 程度まで許すと、速度を残しながら短い結合を選べて改善する。

## 最終コードの構造

以下は記事本文とキャッシュ実装 `#71292861` から確認した構造である。

### 状態表現

- 連結成分:
  - メンバー原子集合
  - サイズ
  - 現在時刻
  - 成分速度
  - 各原子の位置
  - 出力済み結合列
- 段階:
  - 対象サイズ分布
  - 許可するマージ組
  - 対象時間区間
- マッチンググラフ:
  - 実成分頂点
  - 未マージ用dummy頂点
  - 辺重み

### 観測・制約・入力の扱い

- 入力原子は最初すべてサイズ1成分として扱う。
- 各stepのサイズ分布を満たすように、必要な本数だけマッチングで選ぶ。
- 例として、step1は `1x300 -> 1x20 + 2x140` とし、140組だけ実成分同士をマージする。
- step2以降は、サイズ1同士などその段階で不要な組を無限大にして禁止する。

### 評価関数

- 基本重み:
  - 成分Aと成分Bについて、対象時間区間内で取れる最小トーラス距離。
  - 実際に出力する際は、その最小距離を達成する時刻と原子ペアを記録する必要がある。
- 改善重み:
  - 序盤は、結合後速度が小さくなりすぎる組にペナルティを与える。
  - キャッシュ実装では、結合前後の速度ノルム低下を `lambda` 倍し、さらに小さな時刻ペナルティを加えている。

### 探索・構築・更新

- サイズ遷移:
  - `1x300 -> 1x20 + 2x140`
  - `1x20 + 2x140 -> 4x60 + 3x20`
  - `4x60 + 3x20 -> 7x20 + 8x20`
  - `7x20 + 8x20 -> 15x20`
  - `15x20 -> 30x10`
- 各段階で重み付きマッチングを解き、選ばれたペアを対象時刻でマージする。
- マージ後、成分の速度・位置・メンバー集合を更新し、次段階の頂点にする。
- 固定200ターン区切りでも高得点だが、step開始時刻を固定せず、前段階の各成分マージ後から可能にすると改善する。

### 操作・クエリ・出力選択

- マッチングで選ばれた成分ペアについて、記録した最小距離時刻 `t` と、その時刻で最も近い原子ペア `i,j` を出力する。
- 同一時刻に複数の結合を出せるため、同じstep内の独立なマッチング辺は時刻順に並べればよい。
- dummyと結ばれた実成分はそのstepでは出力しない。

### 時間配分・パラメータ

- 初期タイムスタンプは `{0,400,700,800,900,1000}`。
- 速度損失ペナルティの重みは `{80,40,0,0,0}`。
- dummy数は第1段階で20。
- 乱択局所探索では後ろ側のタイムスタンプを0.95倍/1.05倍する16bit摂動を試し、約1.78秒まで回す。
- 重み付き一般グラフマッチング実装が必要である。

## 実装上重要な断片

キャッシュ実装の `calc_best_cost_over_time` は、2成分について `max(last_merge_time)` からステップ終端まで1時刻ずつ走査し、全原子ペアの最短距離と最良時刻を求める。辺重みには丸め距離に加えて、結合前後の速度ノルム低下を `lambda` 倍した非負ペナルティと、`0.001 * lambda * best_t` の時刻ペナルティを足す。

各段階は一般重み付きマッチングで解く。実装では最小化を `2000000 - cost` の最大重みへ変換し、dummy頂点で未マージを表す。禁止サイズ組は段階ごとに落とし、第1段階はdummy20、第2段階は `(1,1)` 禁止、第3段階は `(3,3)` 禁止、第4段階は `(7,7),(8,8)` 禁止という形でサイズ遷移を実現している。

```text
solve_stage(components, target_rule, time_range):
    build graph with one vertex per component
    add dummy vertices for components that should remain unmatched
    for each component pair:
        if size pair is allowed:
            w = min_distance_in_time_range(pair)
            w += velocity_loss_penalty(pair)
        else:
            w = INF
    run minimum weight matching
    merge selected real-real pairs at their best times
```

## この解法の本質

この解法は、AHC057の厳しいサイズ制約を「成分サイズの分布を段階的に決め打つ」ことで単純化している。最終グループ全体を探索するのではなく、各段階で局所的に最適なペアリングを選ぶため、実装上の制約違反が起きにくい。重み付きマッチングを使うことで、貪欲より広い範囲のペア選択を一度に最適化できる。

## 真似するならまず実装する部分

まずはstep1だけを実装し、300個から140ペアを作る重み付きマッチングを動かす。dummy頂点で未マージを表現できることを確認した後、5段階のサイズ遷移へ拡張する。速度ペナルティや可変開始時刻は、固定200ターン版が動いてから入れるのがよい。

## 注意点・未理解点

- 一般グラフの最小重み完全マッチング実装が必要で、ここが実装難度の中心になる。
- キャッシュ実装では、代表点ではなく全原子ペアを整数時刻ごとに走査している。
- 速度損失ペナルティの具体式と係数は提出コードで確認できたが、記事本文だけでは分からない。
- サイズ遷移を決め打つため、そのスケジュール自体が悪いと上限が出る。
- 記事の「step1を500程度」より、提出コードの初期値は400で、後段時刻を乱択摂動する実装になっている。
