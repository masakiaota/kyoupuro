## 解法の全体像

AHCラジオは、公式スライドの内容を補足しながら、この問題でなぜ解法が分かれたかを説明している。焦点は、速度が平均化されること、グループ分けを先に固定するか動的に決めるか、最終サイズ制約をどう壊さないか、残り原子をペア化して速度を変える発想である。

放送では、Writer解法の団子生成・割り当て・ローリングホライゾン・ペア化に加え、toam式のサイズ段階マッチング、kaede_2020 の未来位置クラスタリングと悪い葉の交換、wata式の集合場所を決める方針、1位解法らしきグループと時刻を焼く方針にも触れている。

## 主要アイデア

- グループ分けを先に決めると最終サイズ制約は守りやすいが、近い点を柔軟に使えなくなる。
- グループ分けを最後まで保留すると柔軟だが、30個ちょうどを10グループにする制約で詰みやすい。
- 大きな連結成分へ小さい原子をぶつける方針は、大きい側の速度があまり変わらず、局所変更の影響が読みやすい。
- 同じくらいのサイズ同士を結合する方針は、速度が大きく変化し、局所探索で変更の影響が広がりやすい。
- 2点だけなら最近接時刻は相対位置・相対速度から求められる。T=1000なので全時刻を試す実装でも現実的である。
- ペア化は、ある時刻で同じ集合先に向かう2点をまとめることで、ばらつきを小さくし、後続の貪欲結合を楽にする。

## 最終コードの構造

コードなし。ここでは放送で説明されたWriter最終解法と参加者解法の実装構造を整理する。

### 状態表現

- 原子: 位置、速度、所属成分。
- 連結成分: メンバー集合、現在時刻、現在速度、各メンバーの位置、出力する結合列。
- グループ割り当て: 原子またはペア候補がどの最終グループへ行くか。
- ペア候補: 2原子をどの時刻で結合し、その後どの速度で移動するか。

### 観測・制約・入力の扱い

- 最終サイズ30を必ず満たす必要があるため、残容量を持つグループとして管理する。
- 既に大きくなった成分は速度変化が小さいので、残り原子の割り当て先として安定した対象になる。
- 逆に、単体や小さいペアは速度自由度が高く、後半まで残す価値がある。

### 評価関数

- 基本は結合距離の総和である。
- 割り当て型の解法では、候補原子・候補ペアが各クラスタへ最も近づく距離をコストにする。
- kaede_2020 型の改善では、シミュレーション後に高コスト辺やその葉を悪い要素として選ぶ。
- 集合場所型では、ペア作成コストと集合先への近さを評価する。

### 探索・構築・更新

- Writer解法:
  - まず10個程度の団子を作る。
  - 残り原子を容量付きマッチングで割り当てる。
  - 改善版では、早い時刻の結合だけ確定し、割り当てを解き直す。
  - さらに、残り原子の一部をペアにして、単体候補と合わせて割り当てる。
- toam型:
  - 1から2、3から4、7から8、15+15から30のようにサイズ段階を決め、重み付きマッチングで組ませる。
- kaede_2020型:
  - 未来位置でクラスタリングし、貪欲結合で評価する。
  - 長い辺の葉を別グループへ動かす、または押し出す局所探索を行う。
- 焼きなまし型:
  - グループ分けと、グループへ入る時刻を変数にする方針が話題になっている。

### 操作・クエリ・出力選択

- 出力は時刻付きの結合列で、各解法とも最終的には「いつ、どの2成分を、どの代表原子同士で結ぶか」を決める。
- 放送では、ペア化後の接続はほぼ貪欲でもまだ改善余地があると説明されている。

### 時間配分・パラメータ

- 放送内での具体パラメータは公式スライド側に準じる。
- T=1000なので最近接時刻は全探索でも間に合う場合がある。
- ローリングホライゾンは、全未来を考えた割り当てを解くが、確定するのは早い時刻の一部だけにする。

## 実装上重要な断片

```text
rolling_horizon():
    while unassigned atoms exist:
        solve assignment from current state to final groups
        choose only earliest few merges
        apply merges and update component velocities
        recompute all affected distances
```

```text
pairing_view():
    enumerate free atom pairs that can meet cheaply
    for each singleton or pair:
        estimate cost to each destination group
    choose assignments under group capacity and one-use-per-atom constraints
```

## この解法の本質

放送から読み取れる本質は、速度平均化によって「早く大きくまとめるほど将来の選択肢が減る」ことを、構築・割り当て・局所探索のどこかで明示的に扱う必要があるという点である。単に近いペアを結ぶだけではサイズ制約で詰む。単に最終グループを固定するだけでは未来の近接を逃す。そこで、大クラスタをアンカーにし、残りの小さい成分を高速な可動候補として扱う設計が有効になる。

## 真似するならまず実装する部分

まずは、2点の最近接時刻を求める関数と、連結成分の速度・位置更新を正しく作る。次に、10個のクラスタを作って残り原子を容量付き割り当てする。放送で強調されるローリングホライゾンやペア化は、その後に入れるべき改善である。
