## 解法の全体像

kaede2020の解法は、生成AIと対話しながら「未来位置でグループ分けし、グループ内を貪欲に結合する」方針を育てたものである。初期は時刻0のK-meansと閾値貪欲だったが、代表点同士ではなく成分間の最短原子ペアを結ぶ、未来位置でグループ分けする、長い辺の葉を交換・移動する焼きなましを入れる、結合判断を10ターン先で見る、といった改善で4位まで伸ばしている。

最終的には、未来時刻 `t=350` 付近での位置を使って30個x10のグループを作り、貪欲シミュレーションで各グループを結合する。その後、高コストな辺の葉を別グループへ移す/押し出す局所探索を行い、グループ分けを改善していると読める。

## 主要アイデア

- 時刻0の近さだけでなく、未来の位置で近い原子を同じグループにする。
- 各グループの結合では、代表点同士ではなく、2成分間で最も距離が短い原子ペアを結ぶ。
- 結合閾値は時間とともに緩める。記事中の良かった断片は `th = 35000.0 + t * 10.0`。
- あるグループの長い辺の先にある葉を別グループの葉と交換し、悪い辺を直接狙って改善する。
- さらに、高コスト辺の葉を1000ターン分シミュレーションし、最も相性がよいグループへ入れる。あふれたグループからは悪い葉を押し出す。
- 現在距離だけでなく、10ターン先に近づくかを見て結合判断する。

- 10個のグループへの割り当て。各グループは最大30原子。
- 貪欲シミュレーション結果として、各グループ内の結合辺、結合時刻、コスト、親子関係または葉情報。

### 観測・制約・入力の扱い

- 未来時刻の位置を計算し、その座標でK-means風に30個x10へ分割する。
- 最初は `t=300` を使い、最終盤に複数時刻を試して `t=350` に変更した。
- グループサイズは常に30を保つ必要があるため、交換または押し出しでサイズを保つ。
- 局所探索で変更したグループだけを再評価する高速化が最終盤に入ったと読める。

### 評価関数

- 基本評価は、貪欲シミュレーションで得た結合コスト総和。
- 初期の交換評価では、2つの葉を入れ替えたときの「新しい2辺の長さの和」が元より短いかを近似評価している。
- 後半では、省略版ではなく実際にシミュレーションしてスコア計算する版も試し、改善を確認している。
- 高コスト辺の葉を選ぶため、辺コストまたはその葉の接続コストが悪さの指標になる。

### 探索・構築・更新

- 初期構築:
  - 未来時刻の予測位置でK-means風に10グループを作る。
  - グループごとに、距離閾値を満たす近い成分を貪欲に結合する。
  - 終盤は無理にでも30個に到達させる。
- 貪欲結合:
  - 成分間の代表点ではなく、成分Aと成分Bに含まれる全原子ペアを見て最短の組を結ぶ。
  - 現在だけでなく10ターン先の距離推移を見て、まだ近づきそうなら待つ。
- 局所探索:
  - 長い辺の葉を候補にする。
  - 葉を別グループへ移す、または別グループの葉とswapする。
  - 移動先グループが31個になったら、そのグループの悪い葉を切り離して元グループへ押し出す。
  - 記事では長い辺上位5個から8個へ候補数を増やした調整が効いた。

### 操作・クエリ・出力選択

- 出力は、各グループ内の貪欲シミュレーションで得られる結合列である。
- グループ割り当てが最終的に10個x30を保証するため、結合列も各グループを木として29本ずつ、合計290本出す形になる。
- 最後に高速化し、残り3分で最高点を更新している。

### 時間配分・パラメータ

- 初期グループ改善の山登り: 約0.8秒
- 葉移動・押し出しの焼きなまし: 約0.5秒

- 閾値: 実装では `30000 + t * 20`
- 結合判断の先読み: 実装では10ターンではなく、次ターンで距離が縮むかだけを見る

## 実装上重要な断片

キャッシュ実装では、初期割当は4時刻の将来位置を使う容量付きK-meansで作る。各原子について将来単独位置を特徴にし、20反復後、重心への距離順に各グループ30個へ詰める。

グループ評価は `simulate_group` が担当する。時刻ごとに成分内全原子ペアの最短トーラス距離を探し、次ターンでもう縮まない、かつ `current_dist < 30000 + t * 20` なら結合する。結合後速度はサイズ重み付き平均で更新し、悪い辺探索用に小さい側・大きい側のメンバー集合も記録している。

局所探索は、全グループを毎回作り直すのではなく、悪い辺を持つ上位グループから小さい側の原子を選び、50ターン刻みの位置履歴で相性の良い移動先グループを探す。移動先からはランダムに10原子を候補にしてswapし、変更した2グループだけ再シミュレーションして差分受理する。記事中の「移動して押し出す」より、提出コードはswap中心の実装である。

```text
simulate_group(group):
    while component_count > 1:
        enumerate feasible component pairs
        for each pair, find shortest atom-to-atom connection
        if still getting closer within lookahead:
            wait
        else:
            merge best pair and record edge
    return total_cost, edges
```

```text
improve_partition():
    choose a bad leaf from high-cost edges
    find destination group where the leaf has lowest simulated cost
    move leaf there
    if destination size > 30:
        eject a bad leaf from that group
    accept if score improves, or by annealing rule
```

## この解法の本質

この解法の本質は、最適化対象をいきなり結合列全体にせず、まず「最終グループ割り当て」を最適化対象にして、結合は貪欲シミュレーションで評価する点にある。未来時刻のクラスタリングにより、同じ時刻に近くなる原子をまとめる。さらに、貪欲シミュレーションで実際に悪かった辺の葉を近傍に使うため、ランダムswapよりもスコア悪化原因を直接叩ける。

## 真似するならまず実装する部分

最初に作るべきなのは、未来時刻を1つ決めたK-means風グループ分けと、グループ内の貪欲結合シミュレーションである。次に、シミュレーション結果から長い辺の葉を取り出して、2グループ間のswapを山登りで試す。焼きなましや押し出し、10ターン先読みはその後でよい。
