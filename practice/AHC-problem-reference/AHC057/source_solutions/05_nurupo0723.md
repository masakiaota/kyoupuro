## 解法の全体像

この解法は、290回の結合を1000ターンで行う必要があることから、約3秒に1回結合すると決め打つ。各結合時刻で、現在可能な成分ペアのうち距離が最も短いものを選ぶ。ただし、どのペアでも結んでよいわけではなく、将来的に30個x10へ到達できるペアだけを許す。この到達可能性判定を、成分サイズの組に対するメモ化DFSで行う。

最終グループを事前に固定せず、時刻ごとの近さを素直に利用する貪欲解法だが、サイズ制約だけはDFSで強く守るのが特徴である。

## 主要アイデア

- 290回の結合を1000ターンで行うので、3ターンに1回のペースで結合すれば回数には余裕がある。
- その時刻で最も短い成分ペアを選ぶと、序盤は非常に短い辺を多く拾える。
- ただし、成分サイズの作り方を間違えると30個x10に到達不能になるため、候補ごとに将来可能性を判定する。
- 可能性判定は、現在の成分サイズ集合から30を10個作れるかをメモ化DFSで調べる。
- 同じサイズの成分が多数ある場合は区別しなくてよく、メモ化も効くため間に合ったとされる。

## 最終コードの構造

以下は記事本文とキャッシュ実装 `#71291016` から確認した構造である。

### 状態表現

- DSUまたは成分ID:
  - 成分サイズ
  - メンバー原子集合
  - 成分速度
  - 成分内各原子の位置
- 現在の成分サイズの多重集合。
- DFSメモ:
  - サイズ分布を正規化したキー
  - その状態から10個の30を作れるかどうか。
- 出力する結合列。

### 観測・制約・入力の扱い

- 時刻を0から進め、各原子/成分位置を速度に従って更新する。
- 3ターンごとに結合候補を列挙する。
- 候補は異なる連結成分同士で、結合後サイズが30以下のものに限るはずである。
- 記事では距離をマンハッタン距離と書いているが、問題文のスコア上の結合コストはトーラス上のユークリッド距離の丸めである。このメモでは問題文側を前提にする。

### 評価関数

- 候補ペアの評価は、その時刻の成分間最短距離。
- 成分間距離は、成分Aの全原子と成分Bの全原子のペアで最小を取るのが自然である。
- 将来可能性はスコアではなく制約判定で、マージ後サイズ分布が30x10へ到達可能なら許可する。

### 探索・構築・更新

- 各結合時刻で全成分ペアを距離順に見る。
- 候補ペア `(A,B)` について、サイズ分布から `|A|, |B|` を消し、`|A|+|B|` を追加した状態を作る。
- その状態に対してメモ化DFSを呼び、到達可能ならそのペアを採用する。
- 採用したら成分をマージし、速度を重み付き平均で更新し、結合列に追加する。
- 到達不可なら次に短い候補を試す。

### 操作・クエリ・出力選択

- 3ターンごとに最大1本ずつ結合する設計と読める。
- 最終的に290本出すまで続ける。
- 終盤は制約により候補が少なくなり、遠い結合が増える。

### 時間配分・パラメータ

- 結合間隔: 実装では `DT=3`。
- ビーム幅: `BEAM_W=2`、各状態からの分岐数 `BRANCH=2`。
- 候補距離ソートは4096件程度のチャンクで処理し、短い候補から試す。
- メモ化DFSはサイズ個数配列をキー化し、到達可能性をキャッシュする。

## 実装上重要な断片

キャッシュ実装は単純な1本貪欲ではなく、幅2のビームサーチである。`State` は座標、DSU、成分数、時刻、サイズ個数 `cnt[31]`、累積距離 `Dsum`、出力列を持つ。各展開ではまず3ターン進め、成分サイズ30以下の全原子ペア候補を距離順に見て、到達可能性を満たす上位2手を子にする。

到達可能性判定は、Best-Fit Decreasingの高速チェック後、10本の容量30箱へ残り成分サイズを詰められるかをDFSする。キーは処理位置とソート済み残容量を59bit程度に詰める。さらに `count_ge16 <= 10`、成分数が10より多いなら少なくとも1回は結合可能、といった軽い枝刈りも入る。

```text
can_finish(size_counts):
    if size_counts == {30: 10}: return true
    if memo has state: return memo[state]
    choose two component sizes a, b with a + b <= 30
    merge them in size_counts
    if can_finish(next): return memo[state] = true
    rollback
    return memo[state] = false
```

```text
for t in 0, 3, 6, ...:
    update all component positions to t
    candidates = all component pairs sorted by current distance
    for pair in candidates:
        if can_finish(size_counts_after(pair)):
            merge pair
            output (t, best_atom_in_A, best_atom_in_B)
            break
```

## この解法の本質

この解法の本質は、スコア面では単純な現在距離貪欲に徹しつつ、破綻しやすいサイズ制約だけを厳密に判定する点である。AHC057では、多少長い辺があっても合計距離なので致命傷になりにくい一方、サイズ制約を破ると即WAになる。そこで、複雑な未来位置最適化よりも「今短い辺を拾う」ことを優先し、DFSで許される貪欲だけを実行する。

## 真似するならまず実装する部分

まず、サイズ分布だけを入力にして30x10へ到達可能かを返すメモ化DFSを作る。その後、3ターンごとの全成分ペア距離計算と、最短の到達可能ペアを結ぶ貪欲を実装する。局所探索や未来予測は、この単純貪欲の挙動を見てからでよい。

## 注意点・未理解点
