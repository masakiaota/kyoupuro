## 解法の全体像

公式解説は、まず「適当につなぐ」「時刻0でMST」「時刻0でクラスタリングしてMST」「MSTする時刻を変える」という段階的なベースラインを示し、この問題の本質を「どの点を、いつ、どのグループとしてつなぐか」の同時決定だと整理している。

Writer解法は、大きな連結成分を先に10個程度作り、残った高速な単体原子をそれらへ割り当てる方針から始まる。最終版では、残った原子を単体だけでなく「途中で2点ペアにした小グループ」として候補化し、各クラスタの残容量をちょうど満たすように整数計画で割り当てる。ペア化によって速度ベクトルを変え、どの大クラスタにも近づけない原子を目的方向へ曲げるのが大きな改善点である。

## 主要アイデア

- 結合後の速度は平均化されるため、大きな成分同士を早く作ると動きが鈍くなり、後半に長い辺が残りやすい。
- 大きめの「団子」を10個作り、残った単体原子を団子へ割り当てると、団子側の速度変化が小さく、残容量制約も扱いやすい。
- 2点間の最近接時刻・距離を、相対位置と相対速度から求め、割り当てコストや結合時刻に使う。
- Writer解法1は、団子生成後に残り原子を最小費用流で一括割り当てる。
- Writer解法2は、割り当てを一度で固定せず、ハングリアン法で割り当てを解き直しながら早い結合だけ確定するローリングホライゾンにする。
- Writer解法3は、残り原子のうち近づける2点をペア化し、単体またはペアをクラスタへ割り当てる整数計画へ拡張する。

## 最終コードの構造

最終コードとして、1位相当の提出 #71281125 を中心に読む。比較用に #71330042 と #71194501 も確認した。

### 状態表現

- `Atom`: 原子ID、初期位置、速度を持つ。任意時刻の位置を `position + velocity * t` で返す。
- `Cluster`: 現在時刻、重み、成分速度、各原子の現在位置、出力済み結合列を持つ大きな連結成分。
- `AtomsGroup`: 残り原子を単体または2点ペアとして表す。ペアの場合は内部結合時刻、内部コスト、ペア化後速度、内部結合列を持つ。
- `TorusGeometry`: トーラス距離と、相対速度で最も近づく時刻・距離を計算する。

### 観測・制約・入力の扱い

- 入力の300原子を `Atom` に変換する。
- 初期クラスタは、未使用原子から始点を選び、一定距離以下で近づく原子を貪欲に追加して作る。
- クラスタ候補が小さすぎる場合や既存クラスタ重心と近すぎる場合は捨てる。
- 残り原子は、全ペアを見て `MERGE_TIME_LIMIT` 以内に `MERGE_THRESHOLD` 未満まで近づくなら2点ペア候補にする。単体候補も常に追加する。
- 整数計画では、各原子がちょうど1回使われること、各クラスタの残容量をちょうど満たすことを制約にする。

### 評価関数

- クラスタと単体/ペア候補のコストは「クラスタ内のどれかの原子」と「候補内のどれかの原子」が最も近づく距離。
- ペア候補は、内部で先に結合するコスト `d` を加算する。
- 整数計画の目的関数は、割り当て候補ごとの `最近接距離 + ペア内部コスト` の総和最小化である。
- 距離が大きすぎる割り当ては変数を0固定して探索空間から外す。

### 探索・構築・更新

- 初期クラスタ生成:
  - `CLUSTER_FORMATION_TIME_FACTOR = 500` 付近までを見て、距離閾値内の最良候補を貪欲追加する。
  - 追加時にクラスタ内原子位置を現在時刻へ進め、速度を重み付き平均で更新する。
- ペア候補生成:
  - 残り原子同士の最近接距離を計算し、閾値未満なら `AtomsGroup` として登録する。
  - 単体候補も登録するため、整数計画側が「単体で使うか、ペアで使うか」も選ぶ。
- 割り当て:
  - OR-Tools の `MPSolver + SCIP` で 0/1 変数 `x[group][cluster]` を解く。
  - 各原子の利用回数制約と各クラスタの容量制約を置く。
- 接続:
  - 解かれた割り当てを時刻順に処理し、接続直前に近傍を再計算して `t + 10` 程度の範囲で最良結合時刻を取り直す。

### 操作・クエリ・出力選択

- 出力は、初期クラスタ内の貪欲結合、ペア内部結合、クラスタと候補グループの結合をまとめた `N-M=290` 本の結合列である。
- 連結成分同士を結合するときは、クラスタ側と候補側の原子ペアのうち最も距離が短くなるものを選ぶ。
- 全クラスタが容量30になるよう割り当て制約を置くため、最終サイズ制約を満たしやすい。

### 時間配分・パラメータ

- `CLUSTER_FORMATION_TIME_FACTOR = 500`
- `INITIAL_CLUSTER_DISTANCE_CRITERIA = 2500`
- `MERGE_THRESHOLD = 3300`
- `MERGE_TIME_LIMIT = 700`
- 大きすぎる割り当てコストは `20000` 超で禁止
- 接続時の再探索は概ね `t+10` まで
- 整数計画はプログラム開始から約1.8秒の残り時間で打ち切る

## 実装上重要な断片

```text
make_initial_clusters():
    repeat until M clusters:
        start from unused atom
        while size < K:
            find unused atom with nearest distance <= threshold before formation_time
            add it at nearest time and update cluster velocity
        reject too small or too close cluster

make_atom_groups():
    for each pair of unused atoms:
        if nearest_distance_before_limit < pair_threshold:
            add pair candidate with internal merge edge
    add each unused atom as singleton candidate

solve_assignment():
    minimize sum((cluster_to_group_distance + internal_pair_cost) * x)
    subject to each atom used exactly once
    subject to each cluster receives exactly remaining capacity
```

## この解法の本質

この解法の本質は、最終30個グループを最初から完全に固定せず、「安定した大クラスタ」と「高速で自由度が高い残り原子」を分けて扱う点にある。大クラスタは速度が変わりにくいため、残り原子との最近接距離を比較的安定したコストとして使える。一方で、どのクラスタにも届かない原子はペア化で速度を変えられる。クラスタ容量制約を整数計画に押し込むことで、AHCでありがちな「局所的には良いが最後にサイズ制約で破綻する」問題を避けている。

## 真似するならまず実装する部分

まずはペア化や整数計画を入れず、Writer解法1に近い「10個の初期クラスタを貪欲生成し、残り原子を最小費用流またはハングリアン法で容量付き割り当てする」部分を作るのがよい。次に、割り当てを何度も解き直すローリングホライゾンを入れる。最後に、残り原子の2点ペア候補を作り、単体候補と一緒に0/1最適化する。

## 注意点・未理解点

- 公式最終コードは OR-Tools/SCIP を使うため、AtCoder環境で利用可能なライブラリ前提が必要である。
- ペア候補を増やしすぎると整数計画が重くなり、少なすぎると速度変更の効果が出ない。
- 最近接時刻はトーラスの折り返しを考慮する必要がある。単純なユークリッド平面の式だけでは外す。
- #71330042 は速度を整数寄りに近似している部分があり、提出出力の計画用としては成立しても、厳密シミュレーションとずれる可能性がある。
- スライドの図の細部は完全にはテキスト化できていないが、解法本文と提出コードの構造は確認できた。
