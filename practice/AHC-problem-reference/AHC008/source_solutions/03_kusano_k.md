## 解法の全体像

中央付近に犬猫用のゲートを作り、犬猫をそこに誘導して閉じ込める。犬猫以外は、人が追いかけて壁を置くことで小さい領域へ分離する。ゲートを作らないケースでは、全員が追跡担当になる。

記事の序盤では、局所的なモンテカルロや単純追跡が試されている。しかし最終方針は、シミュレーションで次手を評価するのではなく、盤面中央のゲートと追跡ロジックを手で設計したものになっている。

コードでは、最初に犬猫の数からゲート数を決める。5人をゲート構築と閉鎖に割り当て、残りの人は追跡に回す。ゲート構築後は、犬猫がゲート内に入った瞬間に上下から閉じる。通常ペットは、中央から遠いものをターゲットにして、距離2から3の位置に壁を置く。

## 主要アイデア

- 犬は人へ向かうため、誘導可能な対象として扱える。人の待機位置を使ってゲートへ寄せる
- 猫は目的地がランダムだが、犬猫が残っている間はゲート構造で捕まえる方針を取る
- ゲート数は犬猫数に応じて増やすが、最大14程度に制限する
- 追跡では、中央から見て遠いペットを狙う。遠いペットほど、中央主領域から分離しやすい
- 壁設置候補は、置いた後に人を孤立させないか、捕獲領域が広すぎないかをBFSで判定する
- 最後16ターンは、1手だけ壁を仮置きしてスコアが上がるなら置く

## 最終コードの構造

### 状態表現

- `Field`
  - `pp`, `pt`: ペット位置と種類
  - `hp`, `hp_old`: 人の現在位置と移動前位置
  - `F`: 壁
  - `H`, `P`: 各マスの人・ペット数
  - `turn`, `turn_sub`: ターンと同一ターン内の処理対象
  - BFS用の `D`, `Q`
- `AI`
  - `gate_num`: 作るゲート数
  - `current_gate`: 現在閉じようとしているゲート
  - `P`: 内部処理上の人の並べ替え
  - `states`: 各人の状態。`PREPARE`, `GATE`, `TRAP`, `CHASE`
  - `targets`: 追跡対象のペット
  - `target_up_down`: 上半分・下半分の担当

### 観測・制約・入力の扱い

- 入力は0-indexに変換し、座標を `pos = row * 30 + col` で持つ
- `can_block(pos)` で壁設置制約をまとめて判定する
- BFSは現在の壁のみを通行不能として計算し、人・ペットの重なりは通行可能として扱う
- `Field::move` は人とペットを `turn_sub` によって逐次適用する。人の移動元はターン末に人数を減らすことで、同一ターンの壁設置制約を合わせている

### 評価関数

最終スコア計算は問題文に沿って、各人の連結成分をまとめて処理する。

```text
for each human component:
    cn = reachable cell count
    hn = humans in component
    pn = pets in component
    score += cn * hn * 2^(N - pn)
normalize by 900 * M * 2^N
```

追跡中の壁設置候補は、明示的なスコア式よりも条件判定が中心である。

- 置いた壁によって人が主領域から分断されない
- 新たに閉じ込めたペット領域の平均面積が30以下なら置く
- ペットまでの最短経路上で、距離2または条件付き距離3の位置なら壁候補にする

### 探索・構築・更新

- 初期化
  - 犬猫数から `gate_num` を決める
  - ゲート構築担当5人を初期位置に近い順で割り当てる
  - 残りは上下バランスを見て追跡担当にする
- ゲート構築
  - 4人が左側の縦ゲート列、1人が右側フェンスを作る
  - 壁が置けない場合は待機し、既に置けていれば次へ進む
- ゲート捕獲
  - 犬猫が現在ゲート内の2マスに入っており、上下の閉鎖位置が安全なら同時に閉じる
  - ゲートに到達可能な犬猫がいなくなったら追跡状態へ移る
- 追跡
  - 中央入口から到達可能で、他人と重複しない遠いペットを選ぶ
  - 犬猫はゲートが残っている間は基本的に追わない。猫だけ残った場合などは例外
  - BFS距離を使い、ペットに近づくか壁を置く
- 終盤改善
  - 現在位置の隣接4マスに壁を仮置きし、実スコアが上がるなら置く

### 操作・クエリ・出力選択

`AI::get_moves` が内部順の人ごとに動きを決め、最後に元の人番号順へ戻す。各人の状態に応じて次の関数が呼ばれる。

- `get_moves_gate`: ゲート列を作る
- `get_moves_fence`: 右側フェンスを作る
- `get_moves_chase`: ターゲットを追い、閉じ込める
- `get_moves_score_up`: 終盤にスコア上昇壁を探す

### 時間配分・パラメータ

- 300ターン中、終盤16ターンはスコア改善の仮置き判定を優先する
- ゲート数は犬猫数+1を基本に、最大14
- 捕獲領域の平均面積しきい値は30
- 記事中の補助コードでは、モンテカルロは8ターン先、各候補8回程度の試行をしているが、最終 `A.cpp` は手設計ロジック中心である

## 実装上重要な断片

```text
can_block(cell):
    if wall[cell] or human[cell] or pet[cell]:
        return false
    if any adjacent cell has pet:
        return false
    return true
```

```text
chase_target:
    target = farthest reachable pet from central entrance
    if target is dog/cat and gate remains:
        skip unless special case
    if adjacent block creates small isolated pet region:
        block it
    else:
        move toward cells at distance 3 from target
```

```text
final_score_up:
    best = current_score
    for each adjacent blockable cell:
        put temporarily
        if score() > best:
            choose this block
        rollback
```

## この解法の本質

この解法の本質は、犬を「厄介なランダム要素」ではなく「人に寄ってくる性質を利用できる対象」と見た点である。犬猫用ゲートを作ることで、最も扱いづらい種類を中央の狭い場所に誘導し、通常ペットは別の追跡ロジックで処理する。

また、BFSを多用して「置いてよい壁」だけを選ぶ堅さがある。局所的にペットを分離できても、人を分断したり、大きすぎる領域を捨てたりすると得点が伸びない。壁設置をすべて `can_block` と到達可能性検査に通すことで、WAと大崩れを避けている。

## 真似するならまず実装する部分

最小実装としては、ゲート全体より先に追跡ロジックを作るのがよい。

1. `Field` と `can_block` とBFSを実装する
2. ターゲットペットを1匹選ぶ
3. 距離3まで近づき、距離2のマスを壁で塞ぐ
4. 壁を仮置きして、人の連結性と捕獲領域面積をチェックする
5. 終盤にスコア上昇壁だけ置く

その後、犬猫が多いケースへの改善として、中央ゲートと人の待機位置を追加するとよい。

## 注意点・未理解点

- ゲートの座標はかなり手設計であり、少しずらすと捕獲タイミングが崩れる
- `Field::move` の人の移動元処理は、同時ターン制約に合わせるため慎重に実装する必要がある
- 追跡対象の選び方はヒューリスティックで、全ケースで最適ではない
- ゲート構築に5人使うため、人が少ない場合や犬猫が少ない場合は過剰になることがある
- 記事ではいくつかの没方針も紹介されているため、最終コードの方針と混同しないようにする
