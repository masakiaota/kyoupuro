## 解法の全体像

固定の壁候補パターンをいくつか持ち、まず人を効率よく配置して大きな区画構造を作る。構築後は、ペットの位置と扉候補を見ながら、ペットだけを小部屋に閉じ込める操作を選ぶ。終盤では、通常の部屋閉鎖を続けるか、捕まえきれていないペットを人が追うモードへ切り替えるかをモンテカルロで比較する。

単純な固定盤面ではなく、次の3段階を組み合わせている。

- 初期壁を置く順序と担当者をbit DPで最適化する
- ペットが入った部屋を扉で閉める候補を列挙し、マッチングと評価関数で担当者を割り当てる
- 残りターンが少なくなったら、仮想ジャッジで通常モードと追跡モードを比較する

記事本文では、序盤の人員割当、部屋閉鎖候補の評価、犬猫の移動シミュレーション、最小カットやマッチングによる割当が重点的に説明されている。提出コードも、`first_phase` から `fifth_phase` までの段階的な実装になっている。

## 主要アイデア

- 最終得点はペット数の `2^{-n}` が支配的なので、人がいる連結成分からペットを消すことを第一にする
- 全面を細かく区切ると人の到達面積が減るため、固定の通路と部屋候補を作り、必要な扉だけ閉じる
- 初期壁構築は「誰がどの壁列を担当するか」で大きくターン数が変わるため、経路生成後にbit DPで割当を選ぶ
- 部屋閉鎖では、部屋ごとの扉候補、室内のペット数、室内面積、人からの距離を使って候補スコアを作る
- 犬猫は移動規則が特殊なので、仮想ジャッジ内で犬の目標人、猫の目標マスを保持してシミュレーションする
- 終盤は貪欲に閉め続けるだけでなく、通常モードと追跡モードを乱数シードを変えて比較する
- 盤面パターンの選択に、初期入力の特徴量を入れた小さなニューラルネットを使う

## 最終コードの構造

### 状態表現

- `Input`: ペット、人、壁、ターン、種類、個数を保持する
- `Config`: 固定盤面候補、通路行列、扉列、部屋構造を表す
- `Coordinate`: 30x30盤面上の座標
- `Command`: 移動、壁設置、何もしない
- `Room`: 部屋の左右扉、室内ペット数、部屋面積を持つ閉鎖候補
- `barricade_assigns`: 各人に割り当てた初期壁設置タスクのキュー
- `next_placeable_map`, `next_barricade_map`: このターンの同時行動で壁を置けるか、置いた後どうなるかを判定するための盤面

提出コードは、通常モードを複数フェーズに分ける。

```text
solve:
    inputを読む
    config候補から1つ選ぶ
    初期壁タスクをbit DPで割り当てる
    for turn in 0..300:
        if turn == 275:
            通常継続と追跡モードを仮想評価
        if 通常:
            first_phaseからfourth_phaseを順に適用
        else:
            fifth_phaseの追跡を適用
        不正コマンドを除去して出力
        ペット移動を読み、状態更新
```

### 観測・制約・入力の扱い

- 入力は完全観測で、毎ターンのペット移動を読んで現在位置を更新する
- 壁設置可否は、対象マスに人・ペット・既存壁がないこと、隣接マスにペットがいないこと、このターンに人が移動する予定のマスでないことを満たす必要がある
- 人が同時に移動するため、先に移動コマンドを `next_placeable_map` に反映し、その後に壁設置コマンドを検証する
- 仮想ジャッジでは犬猫の内部目標も状態として持ち、問題文と同じ確率的移動を再現する

### 評価関数

主評価は最終スコア近似である。コード中の仮想ジャッジは、人の連結成分ごとに到達可能マス数 `r` とペット数 `n` を数え、問題文通りに `r / 900 * 2^{-n}` を計算する。

部屋閉鎖候補では、概ね次の要素を組み合わせる。

- 部屋までの移動距離が短いほど良い
- 閉じ込めるペット数が多いほど良い
- 部屋面積が小さいほど、後続で無駄な領域を捨てずに済む
- すでに人が使う主連結成分を壊す候補は避ける
- ペナルティを掛けて「遠いが良い部屋」と「近いが弱い部屋」を比較する

終盤の通常/追跡の選択は、同じ現在状態から残りターンを複数回シミュレーションし、合計スコアが高い側を採る。

### 探索・構築・更新

- 初期壁構築: 固定パターンから壁設置パスを生成し、各人への割当をbit DPで決める
- 第二フェーズ: まだ置けていない初期壁や周辺タスクを、必要時間でソートしたマッチング候補として割り当てる
- 第三フェーズ: 部屋候補を列挙し、扉2箇所を担当する人の組み合わせを評価する。ペットの将来位置はモンテカルロで予測する
- 第四フェーズ: 残った必要壁や通路側の封鎖を、マッチングで割り当てる
- 第五フェーズ: 捕まえきれない状況では、ターゲットペットに近づいて壁を置く追跡型に切り替える

### 操作・クエリ・出力選択

各ターンで全フェーズが `people_commands` に候補コマンドを書き込む。後段の `clean_up_commands` が、移動先予約と壁設置可否をチェックし、不正な壁設置を落とす。

壁設置は小文字、移動は大文字、何もしない場合は `.` で出力する。対話問題なので、出力後にペット移動文字列を読み込んで状態を更新する。

### 時間配分・パラメータ

- 通常/追跡モードの判断は `turn = 275` 付近
- 仮想比較は `2700ms` 程度まで回す設定
- 盤面候補は複数あり、初期入力特徴量からニューラルネットで選ぶ
- 追跡やモンテカルロでは乱数シードを変えて複数試行する
- コードには、部屋評価のペナルティや候補打ち切りのチューニング値が多い

## この解法の本質

この解法の本質は、AHC008を「毎ターンの局所貪欲」ではなく「固定構造の建設と局所的な閉鎖判断」に分けたことだ。固定構造により探索空間を大幅に減らし、その中で割当、部屋選択、終盤モード選択だけを最適化する。

特に強いのは、人の行動が複数人同時である点を割当問題として扱っていることだ。誰がどの壁や扉に向かうかを雑に決めると、300ターンのうち数十ターンを失う。bit DPやマッチングで人の移動コストを制御することで、同じ盤面パターンでも成功率が上がる。

また、犬猫の内部目標を仮想ジャッジで持つことにより、通常のランダム移動ペットより難しい対象をシミュレーションで評価している。固定盤面と確率評価の組み合わせが上位解法らしい部分である。

## 真似するならまず実装する部分

最初に真似するなら、ニューラルネットやモンテカルロ比較ではなく、固定盤面と担当割当を作るのがよい。

1. 壁候補の固定パターンを1つだけ用意する
2. 人ごとに壁設置タスクのキューを持つ
3. BFSで目的地へ移動し、到着したら壁を置く
4. ペットがいる小部屋の扉を閉じる候補を列挙する
5. 余裕があれば、扉担当を貪欲からマッチングへ置き換える

ここまでで「固定構造を作って閉じる」という骨格が得られる。その後に、盤面候補を増やす、部屋評価を入れる、終盤だけ追跡モードを入れる、という順で強くするのが自然だ。

## 注意点・未理解点

- 固定盤面候補ごとの細かい意図は、記事とコードから読める範囲でも完全には分解できない。候補選択のニューラルネット重みも、学習データや学習手順までは不明である
- モンテカルロ評価は犬猫の内部状態まで合わせないと実際の挙動とずれる
- 同時行動の衝突処理を誤ると、壁設置可否の制約違反でWAになる
- 初期壁を作る速度が遅いと、部屋閉鎖フェーズに入る前にターンが尽きる
- 固定構造は強いが、ペットが壁設置予定地の近くに居座ると遅延する。代替タスクや待機処理が必要になる
