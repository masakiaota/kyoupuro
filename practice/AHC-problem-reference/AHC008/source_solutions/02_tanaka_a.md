## 解法の全体像

事前に決めた通路付き固定構造を作り、各ペットがいる小領域の入口を閉じて捕獲する。基本形は、格子状に壁を置いて通路と小部屋を作り、人間は担当位置へ移動して建設と封鎖を行う。

最終的には、担当割り、ペットごとの捕獲優先度、犬への対策、壁数削減、評価式の調整を重ねている。記事は改善過程が中心で、最初は単純な固定構造から始まり、スコアが悪いケースを見て、構造と割当を詰めていく流れになっている。

## 主要アイデア

- 固定構造を作ると、ペット捕獲を「どの入口をいつ閉じるか」に単純化できる
- 初期の人の担当位置を決め、通路構築と捕獲タスクを分担する
- 捕獲候補は、ペット数、領域面積、人との距離で評価する
- 犬は人に向かってくるため、通常ペットと同じ入口閉鎖だけでは不安定になる。専用の誘導や待機場所を考える
- 壁を置きすぎると、人の最終到達面積が減りスコアが落ちるため、必要な壁だけに絞る
- スコアの悪いケースを可視化して、固定構造の局所的な弱点を直す

## 最終コードの構造

in-app Browser で読んだ提出 #29656161 の構造である。記事の固定構造・犬対策・壁削減という流れと一致するが、実装では複数の固定構造候補を仮想シミュレーションしてから選ぶ。

### 状態表現

- 30x30盤面の壁、ペット、人の位置を `State` が持つ。
- 固定構造は `RoomPattern3` が `WP` bitmask として持ち、部屋・入口・壁候補を管理する。
- `Room` が `wallToCreate`、`wallToCreateMaster`、入口、部屋面積、ロック状態を持つ。
- 人ごとの行動は `Task` として表現され、建設、部屋捕獲、通路追跡、袋小路捕獲、緊急捕獲などに分かれる。
- `Algorithm` が実行中タスク、候補タスク、割当、出力、ペット移動更新を管理する。

固定構造を使うため、状態は「自由な壁配置」ではなく、事前に決めた候補マスのうちどこまで建設済みか、どの部屋が閉じたかを持つ。

### 観測・制約・入力の扱い

- 毎ターン、出力後にペット移動を読み、現在位置を更新する
- 壁設置は、対象マスと隣接ペット制約を満たす必要がある
- 固定構造の壁予定地にペットが近い場合は、そのターンの設置を待つ
- 犬がいる場合は、犬が人に寄ってくる挙動を考慮して捕獲順や人の配置を変える

### 評価関数

記事では、最終的に単純な「捕まえられるか」だけでなく、捕獲後の満足度を意識している。提出コードではまず `decidePattern` が候補盤面を仮想シミュレーションし、累積スコアで良い `RoomPattern3` と `RowCreateFirstAlgorithm` の組を選ぶ。

```text
candidate_value =
    捕獲できるペット数の価値
  - 閉じ込める領域面積の損
  - 人の移動ターン数
  - 犬や猫で失敗しやすい場合のペナルティ
```

スコア式上は、ペットが人の領域に1匹でも残ると満足度が半減する。したがって「小さな領域にペットを1匹閉じ込める」価値は高い。ただし、人が使える領域を削りすぎると `|R_i| / 900` が悪化するため、壁数削減が必要になる。

### 探索・構築・更新

- `decidePattern` で `RoomPattern3(in, 3/4/5)` と犬対応有無の候補を作り、最大 1000 seed の `simulate()` で候補を絞る。
- 序盤は `RowCreateTask` で作業列へ移動し、左右に壁を置いて部屋列を作る。
- 毎ターン `Algorithm.execute` が完了タスク削除、候補タスク生成、idle 人間への割当、実行、出力、ペット入力更新を行う。
- `RoomCaptureTask` は入口の上下などに人を配置し、両側に人が着いて `canPut` とロック判定を満たしたら2マス同時に壁を置いて部屋を閉じる。
- `AislePetFollowTask`、`DeadEndCaptureTask`、`EmergencyCaptureTask` で通路追跡や袋小路・緊急捕獲を扱う。

### 操作・クエリ・出力選択

人ごとに次の優先順位で操作を決める方針と考えられる。

```text
if 現在位置で必要な壁を置ける:
    壁を置く
elif 担当タスクがある:
    BFSで目的地へ移動する
elif 捕獲すべき入口がある:
    入口担当へ向かう
else:
    待機または終盤改善
```

同時行動なので、同じ壁を複数人が狙わない、他人が移動するマスに壁を置かない、といった調整が必要になる。

### 時間配分・パラメータ

- 固定構造の完成に使うターンと、捕獲に使うターンの配分が重要である
- 記事では、壁数削減や犬対策がスコア改善の大きな要素として扱われている
- 領域面積、捕獲対象までの距離、待機列などがチューニング対象になる
- 候補盤面選択は 2300ms 程度まで仮想シミュレーションし、候補数を段階的に絞る。
- 犬対応有無も候補に含めて比較している。

## この解法の本質

本質は、ランダムに動くペットを追い回すのではなく、ペットがどこにいても捕獲候補になるような固定構造を先に作ることだ。AHC008では、壁を置く条件が厳しく、ペットの隣に壁を置けない。ペットが来てから即興で囲うより、あらかじめ通路と入口を用意しておく方が成功しやすい。

また、固定構造型では「壁をたくさん置くほど強い」とは限らない。人の最終領域が狭くなるため、必要最小限の壁でペットを外に追いやる設計が重要になる。tanaka-a氏の記事は、構造設計と壁数削減の試行錯誤が参考になる。

## 真似するならまず実装する部分

まずは、1種類の固定構造だけを実装するのがよい。

1. 30x30上に通路列と小部屋を決める
2. 壁設置予定マスをタスク列にする
3. 各人を近いタスク列に割り当てる
4. BFSで移動し、着いたら壁を置く
5. 部屋入口の閉鎖判定を実装する

犬対策、壁削減、複数構造の切り替えは後回しでよい。最初から全改善を入れると、どの改善が効いたか分からなくなる。

## 注意点・未理解点

- 記事中に提出リンクはないため、順位表から `rabot` の提出を辿った。著者名とAtCoderユーザー名が異なる点に注意が必要である。
