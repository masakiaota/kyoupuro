## 問題の本質

AHC008は、最終的に「人がいる連結成分からペットをどれだけ排除しつつ、人の到達可能面積をどれだけ残すか」を競う問題である。スコアは `|R| / 900 * 2^{-n}` なので、到達面積を多少失ってもペットを1匹減らす価値が大きい。ただし、壁を置きすぎると人の領域が小さくなり、全捕獲後の伸びが悪くなる。

制約上、ペットやその隣に壁を置けないため、ペットを見てから即興で囲うのは難しい。強い解法はほぼ共通して、先に通路、部屋、ゲート、導線を作り、ペット捕獲を「入口を閉じる問題」に変換している。

## 共通している考え方

- ペットを人の主連結成分から外すことを最優先する
- 人を全員同じ主領域に残すと、スコア計算と安全判定が簡単になる
- 壁候補を完全自由にせず、固定構造上の壁だけに絞る
- 捕獲は「ペットを囲う」ではなく「ペットがいる領域の入口を閉じる」と見る
- BFSで移動経路、領域面積、連結性、壁設置後の影響を何度も確認する
- 犬猫は通常ペットと別扱いにする。犬は人へ向かう性質、猫は広範囲移動の不安定さがある
- 終盤は残りターンが少ないため、大きな構築よりも、今置ける壁がスコアを上げるかを直接見る

## 解法の分類

- 固定盤面構築型: tanaka-a、syamashi、eijirou、terry_u16
- 通路・入口閉鎖型: eijirou、tanaka-a
- ゲート誘導型: kusano_k、terry_u16の一部、syamashiの犬用盤面
- 割当最適化型: terry_u16
- 追跡型: kusano_k、terry_u16の終盤、syamashiの余剰人処理
- モンテカルロ評価型: terry_u16、kusano_kの検討コード
- 盤面手設計型: syamashi、tanaka-a

## 推奨して理解すべき順序

1. eijirouの通路・ロック型を読む。AHC008を入口閉鎖問題として見る基本が分かる
2. kusano_kを読む。`Field`、BFS、`can_block`、追跡、終盤スコア改善の実装が分かる
3. tanaka-aを読む。固定構造を改善していく観点、犬対策、壁数削減を理解する
4. syamashiを読む。固定盤面と導線を分ける手設計の強さを見る
5. terry_u16を読む。割当最適化、部屋評価、仮想ジャッジ、終盤モード選択まで含む上位化を見る

## 実装するならどのルートか

理解のための最小実装は、eijirou型がよい。

```text
固定通路を作る
通路外の各連結成分に入口lockを持たせる
ペット位置からlockを引く
近い人を入口へ向かわせて閉じる
全人連結を保つ
```

上位化するなら、次の順で足す。

1. kusano_k型の `can_block`、捕獲領域面積判定、終盤仮置きスコア改善
2. tanaka-a型の壁数削減と犬対策
3. syamashi型の導線マップ分離と犬専用固定盤面
4. terry_u16型のタスク割当DP、扉候補マッチング、終盤モンテカルロ比較

## 重要な実装要素

- 状態表現: 壁、人、ペット数、種類、ターン、人ごとのタスクキュー、固定壁予定マップ、通路/部屋ID
- 評価関数: 到達可能面積、連結成分内ペット数、閉鎖領域面積、人の移動距離、犬猫ペナルティ
- 候補管理: 壁予定地、部屋入口、ロックタスク、ゲート閉鎖点、追跡対象
- 差分更新: 1ターン内の人移動元と移動先、壁設置予定マス、ペット移動後の占有
- 出力判定: 移動先に壁が置かれないか、壁設置対象と隣接にペットがいないか、既存壁でないか
- パラメータ: 通路間隔、領域面積しきい値、終盤切替ターン、犬猫専用構造の有無、担当割当の距離重み

## 落とし穴

- ペット隣接マスへの壁設置禁止を忘れるとWAになる
- 同一ターンに人が移動するマスへ壁を置くと不正になる
- 人の移動元はそのターン中はまだ人がいる扱いに近く、壁設置判定で注意が必要である
- 人を複数連結成分に分けると、スコア計算と安全判定が難しくなる
- 固定壁を置きすぎると、全ペット排除後でも到達面積が小さくなる
- 犬を通常ペットと同じロック処理に任せると、人へ寄ってきて事故りやすい
- 猫は目的地再選択で想定外の領域へ行くため、細い入口だけに頼ると逃がしやすい
- 構築フェーズが長すぎると、捕獲に使うターンが残らない

- 実装する場合、ローカルビジュアライザで壁予定地、通路、連結成分、入口lockを可視化して検証すべきである
