## 解法の全体像

縦横グリッドに限定し、各線の位置を焼きなましで動かす。初期解は、要求人数に対して少し余裕を持たせた正方形グリッドである。状態は、縦線・横線の座標、各セルに含まれる点リスト、イチゴ数ごとのピース数を持つ。

線を1本動かすと、その線に隣接するセルだけが変わる。コードでは、移動方向に応じて点リストを隣接セルへ移し、影響する行または列のヒストグラムだけを更新する。評価関数は公式スコアに加え、目標分布と現在分布のズレを序盤ほど強く罰する補助項を加えている。

## 主要アイデア

- 任意直線ではなく、縦横グリッドの切断だけを使う。
- 初期線数は `sqrt(合計人数)` より少し多い程度にする。
- グリッドのセルだけでなく、線上に乗った点用の領域も状態に持つ。
- 近傍は、縦線または横線を1本選び、隣接線を越えない範囲で最大100程度動かす。
- 変更前後で影響を受ける2列または2行だけ、ピース数ヒストグラムを引いて足し直す。
- 評価関数は、終盤は公式スコアに近づき、序盤は「欲しいピース数分布に近いか」を重視する。
- 不採択時は逆向きの移動を適用してロールバックする。
- 改善版では縦横の本数を非対称にして、横7本、縦多数のような形も試している。

## 最終コードの構造

### 状態表現

- `Input`: `n`, `k`, `counts`, `count_sum`, `points`, 開始時刻。
- `Point`: `x`, `y`。
- `State`:
  - `v_cut`: 縦方向カットのx座標。両端の番兵も含む。
  - `h_cut`: 横方向カットのy座標。両端の番兵も含む。
  - `cut_count`: 内部カット本数。
  - `box_count`: セル数。
  - `boxes`: セルまたは線上領域ごとの点リスト。偶数indexが通常セル、奇数indexが線上を表す。
  - `counts`: `counts[c] = c個入りピース数`。
- 改善版では `cut_count_v`, `cut_count_h` を分け、縦横で異なる本数を管理する。

### 観測・制約・入力の扱い

- 初期化時に、各点を縦線・横線配列へ二分探索し、該当セルへ入れる。
- 点座標がちょうど切断線上なら奇数indexの線上領域へ入る。これは問題上どのピースにも含まれない点に対応する。
- 出力は軸平行線として出している。記事の「できなかったこと」では、他参加者が使った「イチゴを切らないための少し斜めの線」を導入できなかったことに触れている。

### 評価関数

- `calc_score` は公式スコアと同じく `sum min(要求数, 現在ピース数)` を最大化する。
- `calc_annealing_score` は、公式スコアに分布補助項を加える。
- 補助項は、要求側のピース分布と現在のピース分布を小さいイチゴ数から貪欲に対応させ、個数差の二乗を負の値として足す形である。
- 補助項の重みは `1000 * (1 - time)` で、時間が進むほど弱くなる。
- これにより、序盤は「10個入り要求を1個入り大量生成で代替する」ような偏りを抑え、終盤は実スコアを重視する。

### 探索・構築・更新

- 初期解:
  - `cut_count * cut_count >= 合計人数` となるまで `cut_count` を増やす。
  - さらに少し余裕を足し、最大50本に丸める。
  - `[-10001, 10001]` の範囲を等分する。
- 焼きなまし:
  - 制限時間は約2.97秒。
  - ランダムに縦または横を選ぶ。
  - ランダムに内部線indexを選ぶ。
  - 隣接線を越えないように、現在位置から最大100だけ動かす。
  - 移動後の状態を直接反映し、評価差に基づいて採択する。
  - 不採択なら逆方向の移動関数を呼び、座標も戻す。
- 差分更新:
  - 縦線移動なら、対象線に隣接する左右2列だけ `counts` から一度引く。
  - 点リストを旧セルから新セルまたは線上領域へ移動する。
  - 移動後の左右2列を `counts` に足し直す。
  - 横線も対称である。

### 操作・クエリ・出力選択

- 最終出力は最良状態の縦線と横線である。
- `Display` 実装で、まず線数を出し、縦線、横線の順に直線を出力する。
- コンテスト中コードでは縦横同数、改善版では縦横本数を分けて出す。

### 時間配分・パラメータ

- 焼きなまし時間: `2.97` 秒。
- 移動幅上限: `100`。
- 温度: `temp0 = 1e4`, `temp1 = 1e2` の幾何補間。
- 乱数: `Pcg64Mcg::new(42)`。
- 改善版の縦横選択確率は、縦線数と横線数の比から決めている。

セルと線上領域を偶奇indexでまとめて持つ設計により、点が線上に来るケースも同じデータ構造で処理できる。ただし、スコア上は線上の点は失われるので、高得点化には線上事故を避ける工夫が別途有効である。

## この解法の本質

この解法の強みは、実装可能な範囲で状態を正確に持ち、差分更新を局所化している点である。線を動かすたびに全点を数え直すのではなく、影響する2列または2行だけを更新するため、3秒でも十分な試行回数を確保できる。

また、補助評価を時間で弱める設計が実用的である。序盤は分布の形を作り、終盤は公式スコアの改善に集中するため、公式スコアだけでは見えない勾配を探索初期に与えられる。

## 真似するならまず実装する部分

まず、TERRY版の構造を簡略化して、縦横同数グリッド、線移動のみ、全点再計算の焼きなましを作る。次に、`counts` とセル内点リストを持つ差分更新へ置き換えるのがよい。

補助評価は後からでよい。最初に実装すべきなのは、線を動かしたときに `counts[c]` が正しく変わること、逆移動で完全に戻ることの検証である。

## 注意点・未理解点

- コンテスト中コードは軸平行線をそのまま出すため、点が線上に乗る可能性がある。問題上その点はどのピースにも入らない。
- `boxes` に線上領域を含める設計は堅いが、配列indexの偶奇を間違えるとバグになりやすい。
- 不採択時の逆移動は、移動関数が完全に可逆であることに依存する。
- 改善版の縦横本数の非対称化は効果があるが、どの比率がよいかは入力分布と評価関数に依存する。
- `valid_iter % 100000 == 0` で標準出力している箇所がコード中にある。複数解出力の扱いはジャッジ仕様に依存するため、実装を真似る場合は余分な標準出力を削るのが安全である。
