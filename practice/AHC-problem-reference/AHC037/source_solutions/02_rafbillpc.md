## 解法の全体像

解を、入力点を葉、中間点を内部ノードとする全二分木として符号化する。内部ノードの座標は、その2つの子の座標 `p, q` から `min(p.x,q.x), min(p.y,q.y)` として決まる。したがって、探索すべきものは中間点座標そのものではなく、どの点同士をどの順でマージするかを表す木構造になる。

初期解は単純な近距離ペアマージで作り、その後は焼きなましで木構造を変更する。主な近傍は、あるノードを別のノードの近くへ移す操作と、木回転である。変更後は、影響を受ける祖先方向だけ座標とコストを再計算し、コストが下がるなら採択、悪化なら温度に応じて採択する。

## 主要アイデア

- 解を全二分木として持つ。
- 各内部ノードの座標は子の `min` で決まるので、座標を独立変数にしない。
- コストは各内部ノードについて `L1(child0.point, child1.point)` を足す。
- 初期化の良し悪しはあまり重要でなく、提出コードでは近距離ペアを順にマージしている。
- 主要近傍は「ノード `x1` を別ノード `x2` の新しい隣に移す」操作で、約85%を占める。
- 補助近傍として木回転を行う。
- ノードが互いに祖先関係にある場合は、木が壊れるため遷移しない。
- 遠すぎるノード移動は、差分下界のような値で枝刈りする。
- 更新は親方向に進め、内部ノードの座標が変わらなくなったら打ち切る。

## 最終コードの構造

### 状態表現

- `pt { x, y }`: 座標。
- `node`:
  - `is_leaf`: 入力点か内部ノードか。
  - `point`: 葉なら入力座標、内部ノードなら子2つの `min` 座標。
  - `children[2]`: 二分木の子。
  - `parent`: 親。
  - `cost`: 子2つのマンハッタン距離。
- `state`:
  - `nodes[2N-1]`: 葉 `N` 個と内部ノード `N-1` 個。
  - `cost`: 内部ノードコスト合計。

### 観測・制約・入力の扱い

- `N=1000` を固定として読み込む。
- 葉ノードは入力点そのものとして作る。
- 全体の根はすべての葉の `min` なので、問題制約により `(0,0)` になる。
- `reconstruct()` では根からDFSし、親座標から子座標への辺を出力する。
- 出力辺数は二分木の辺数程度なので `5N` 制限に収まる。

### 評価関数

```text
combine(p, q) = (min(p.x, q.x), min(p.y, q.y))
combine_cost(p, q) = |p.x - q.x| + |p.y - q.y|
state.cost = sum(combine_cost(child0, child1) for all internal nodes)
```

焼きなましでは `state.cost` を最小化する。得点は `1/(1+C)` 型なので、コスト最小化と一致する。

### 探索・構築・更新

- 初期化:
  - 有効ノード集合 `I` に全葉を入れる。
  - マンハッタン距離が最小の2点をマージして内部ノードを作る。
  - これを根が1つになるまで繰り返す。
- 共通操作:
  - `cut(i)` で親から子 `i` を外す。
  - `link(i, p)` で子 `i` を親 `p` の空きスロットへつなぐ。
  - `update(p)` で `p` から祖先へ、子コストと `min` 座標を再計算する。
- 近傍1: ノード移動
  - `x1` と `x2` をランダムに選ぶ。
  - `x1` の兄弟 `y1`、`x2` の兄弟 `y2`、親 `p1,p2` を見る。
  - `x1` と `x2` を同じ内部ノード `p1` の子にし、`p1` を `p2` 側へ挿入する。
  - `y1` は元の `p1` の親側へつなぎ直す。
  - 祖先関係や粗い差分が悪すぎる場合は打ち切る。
- 近傍2: 木回転
  - 親子2段の局所構造を回転し、部分木の組み合わせを変える。
- 採択:
  - `delta = new_cost - old_cost` が非正なら採択。
  - 悪化なら `delta <= temp * randomDouble()` の形で採択する。指数関数ではなく、乱数との線形比較で温度を使っている。
  - 不採択時は `cut/link/update` を逆順に実行してロールバックする。

### 操作・クエリ・出力選択

- `reconstruct()` が根を探し、`dfs(root, (0,0))` で `parent_point -> node.point` を列挙する。
- 内部ノードも葉も同じように辺として出力する。
- マージで作った後ろ向き木を、前向きの生成操作列に戻す形で出力する。

### 時間配分・パラメータ

- 制限時間定数は `TL = 1.99`。
- 温度は `5e8` から `5e2` へ指数的に下げる。
- `niter` を `1<<13` ごとに時間確認し、`done > 1.0` で終了する。
- ノード移動と回転の比率は `36:4` 程度で、約90%がノード移動になっている。
- ノード移動では、近似差分 `delta > 2.5e8` の候補を捨てる。
- 記事では慎重な実装で 2 秒に 5000万から6000万反復程度が可能と述べている。提出コードのコメント上は数千万反復級を意識した作りである。

## 実装上重要な断片

```text
update(p):
    while p != -1:
        x, y = children[p]
        new_cost = L1(point[x], point[y])
        total += new_cost - old_cost[p]
        old_cost[p] = new_cost

        new_point = min(point[x], point[y])
        if new_point == point[p]:
            break
        point[p] = new_point
        p = parent[p]
```

ノード移動の考え方は次である。

```text
move_node(x1, x2):
    p1 = parent[x1]
    y1 = other_child(p1, x1)
    p2 = parent[x2]

    if ancestor_relation(x1, x2):
        reject candidate
    if rough_delta_too_large:
        reject candidate

    detach x1, y1, x2, p1
    make p1 children = (x1, x2)
    attach p1 under p2
    attach y1 where p1 used to be
    update affected ancestors
    accept or rollback
```

出力は木をDFSするだけでよい。

```text
dfs(v, parent_point):
    output parent_point -> point[v]
    if v is internal:
        dfs(child0, point[v])
        dfs(child1, point[v])
```

## この解法の本質

この解法の本質は、AHC037 を「点集合を足してから親を選ぶ問題」ではなく「葉のマージ木を最適化する問題」として固定する点である。木構造が決まれば、各中間点の最良座標は子から自動で決まる。これにより、座標生成、親選択、出力順序が一つの木状態にまとまる。

また、部分木移動と木回転は、単なるペアの選び直しより広い変更を少ない差分で表現できる。マージ順のかなり大きな組み替えを、親子リンク数本の変更として実行できるため、2秒内でも大量反復できる。

祖先方向だけの更新で済む点も重要である。内部ノードの座標が変わらなくなれば、その上の祖先も変わらないため、更新を途中で打ち切れる。これは二分木表現と `min` 座標の決定性があって初めて効く。

## 真似するならまず実装する部分

最初に作るべきなのは、焼きなましではなく二分木状態と復元である。

- 葉 `N` 個、内部ノード `N-1` 個の配列管理。
- 子2つから内部ノードの座標とコストを計算する関数。
- 近距離ペア初期化。
- 根からのDFS出力。
- `cut/link/update` とロールバック可能な小さな近傍。

これが動いたら、まず木回転かノードswapだけで山登りを試し、最後にノード移動、枝刈り、温度付き採択を入れるのがよい。

## 注意点・未理解点

- 提出コードには `transition_swap` もあるが、メインループではノード移動と回転だけが使われている。
- `is_ancestor_of` 内に `nodes[j].point.y < nodes[j].point.y` という常に偽になる比較が見える。意図は `nodes[j].point.y < nodes[i].point.y` の枝刈りだった可能性があるが、提出はACしており、主機能は親をたどる祖先判定で成立している。
- 悪化採択は典型的な `exp(-delta/temp)` ではなく、`delta <= temp * random` である。再実装時に同じ挙動を期待するなら注意する。
- `delta > 2.5e8` の枝刈りは経験的なチューニングであり、一般に正当化されるものではない。
- 2秒で数千万反復を狙う実装なので、配列固定、inline、差分更新が前提である。素直な `vector` 木で同じ反復数は出にくい。
