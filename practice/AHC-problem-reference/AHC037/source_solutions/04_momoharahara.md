## 解法の全体像

強い貪欲や焼きなましではなく、前向きに点を作る貪欲を段階的に改善している。最初は既に作った点から到達可能な一番近い点を親にして入力点を作る。そこへ、中継点を追加してもコストが悪化しない性質を使い、L字経路上の右下・左上の点、既存の左方向・下方向の直線へ接続できる点を足していく。

最終方針では、作った中継点集合をそのまま出すのではなく、不要な頂点を削除し、残った点を再度「既に作った点から最短で作る」形にして出力する。局所探索はないが、問題の幾何性を使った高速な構築で71位に入っている。

## 主要アイデア

- 前向きに、既存点から作れる点のうちコストが小さい親を選ぶ。
- `x` と `y` のコストは独立なので、`(x',y')` へ直接行く代わりにL字の中継点を挟んでも総距離は変わらない。
- 直接の辺の途中に中継点を作っておくと、別の点がそこへ短く接続できる可能性がある。
- 右下側の中継点が使われなければ、左上側の中継点を試す。
- 既に左側や下側に直線状の経路があるなら、そこへ直接伸ばした方が良い場合がある。
- 最後に、どの最短路にも使われない余計な中継点を取り除く。
- 実行時間は非常に短く、チューニング探索なしで安定する。

## 最終コードの構造

### 状態表現

- `ab`: 入力点。ソートして処理する。
- `s`: 作成候補として保持する点集合。入力点と中継点を含む。
- `par`: 各点の親index。
- `child`: 親子関係の子リスト。
- `op`: 最終的な出力操作列。

途中提出 #57820618 では `create(pari,a,b)` の中で点を追加し、追加した点を使った方が良くなる既存点を探して親を更新する構造が見える。最終提出 #57822298 では、さらに不要頂点削除と最終的な最短親選び直しが入っている。

### 観測・制約・入力の扱い

- 入力点は座標でソートして処理する。
- 既に作った点 `s[j]=(x,y)` が目標 `(a,b)` を作れる条件は `x<=a && y<=b`。
- 作れる点の中で、`(a-x)+(b-y)` が最小の親を選ぶ。
- `(0,0)` は初期点として `s` に入れる。

### 評価関数

- 明示的な探索評価関数はない。
- 各入力点追加時には、現在選べる親からの生成コストを最小化する。
- 中継点追加時には、それを使うことで既存または新規の接続コストが短くなるかを見る。
- 最終出力構築では、残った点集合をソートし、既に出力済みの点から各点への最短生成コストを選ぶ。

最終コードでは、構築した点集合から最短路に使われない頂点を除く処理が入り、その後に残った点集合から出力操作を組み直す。

### 操作・クエリ・出力選択

- 出力時には、残った点集合 `s` をソートする。
- 既に作った点集合 `ss` を `(0,0)` から始める。
- `s` の各点について、`ss` の中から到達可能かつ距離最小の親を選び、操作として出力する。
- これにより、内部で持っていた親子関係をそのまま使うのではなく、最終点集合に対する貪欲な最短生成木として出す。

### 時間配分・パラメータ

- 焼きなましやビーム幅はない。
- 最終提出は16 ms程度で、時間制限に対して非常に余裕がある。
- 中継点を足しすぎても `5N` を超えないように注意が必要だが、最終案では不要頂点削除により操作数も抑えられる。

## 実装上重要な断片

既存点から最短親を選ぶ処理は次の形である。

```text
best_parent = (0,0)
best_cost = a + b
for p in built_points:
    if p.x <= a and p.y <= b:
        cost = (a - p.x) + (b - p.y)
        if cost < best_cost:
            best_parent = p
```

右下中継点の考え方は次である。

```text
make target (a,b) from parent (x,y):
    if a != x:
        create (a, y)
    create (a, b)
```

最終出力の組み直しは次である。

```text
ss = [(0,0)]
for point in sorted(kept_points):
    pre = nearest reachable point in ss
    if point != (0,0):
        output pre -> point
        ss.push(point)
```

## この解法の本質

この解法の本質は、「中継点は辺の上に置けば損をしない」という性質を前向き構築に利用している点である。直接作る辺をL字に分解しても距離は同じなので、将来の別点がその中継点に乗れるなら得だけが残る。

強い貪欲や二分木焼きなましほど抽象化された最適化ではないが、視覚的に改善しやすい。左側・下側の既存直線へ接続するという発想は、座標軸方向にコストが分離している問題では自然で、実装も短い。

最後に不要点を削除するのも重要である。中継点を積極的に足す方針では、使われなかった点が出力操作数とコストの見通しを悪くする。点集合を整えてから出力の親を選び直すことで、構築過程の都合を最終解に残しすぎない。

## 真似するならまず実装する部分

まず、既存点から到達可能な最短親を選ぶ案1を作る。次に、各操作をL字に分解して中継点を残す案2を足す。ここまでで問題の性質を確認できる。

その後、左・下の直線へ接続する改善と不要頂点削除を追加する。上位スコアを狙うなら、この解法をそのまま複雑化するより、強い貪欲やビームサーチへ移る方が伸ばしやすい。

## 注意点・未理解点

- 記事は段階的な説明で、最終提出コードの全意図が本文だけで逐一説明されているわけではない。
- `par/child` を更新しながら中継点を増やすため、不要頂点削除時に親子関係が壊れないよう注意が必要である。
- 最終出力で親を選び直すため、内部構築の親子関係と出力操作は一致しない場合がある。
- 中継点追加は損をしないように見えても、使わない点を残すと操作数や後処理が増える。
- 強い貪欲に比べるとスコア上限は低いが、実装が高速で理解しやすい。
