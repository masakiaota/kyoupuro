## 解法の全体像

AHC037を、平面上の右上方向の有向木を作る問題として整理している。中間点なしなら、各入力点を既存点の右上に接続する木を作る問題になる。しかし、2点 `p, q` の共通祖先として `r=(min(p.x,q.x),min(p.y,q.y))` を置くとコストを下げられるため、良い中間点集合と接続を探す問題になる。

記事は、強い貪欲、ビームサーチ、局所探索、二分木表現、Rectilinear Steiner Arborescence Problem との関係を横断的に整理している。特定の完成コードではなく、どの発想がどの上位解法につながるかを理解するためのメモである。

## 主要アイデア

- 点を右上方向に伸ばす有向木と見る。
- 中間点なしなら、既存点から近い点を親にする木が自然だがスコアは伸びにくい。
- 2点を同じ親から作るとき、中間点 `r=(min px qx, min py qy)` を入れるとコストが減る。
- 中間点は原点から遠いほど削減量が大きい。
- 強い貪欲は、そのような中間点を原点から遠い順に選ぶ方針である。
- ビームサーチは、ペア選択列を複数持つ拡張である。
- 局所探索では、親頂点と中間点集合の両方を変える必要がある。
- 上位解法では、解を二分木として見て、部分木移動や木回転で構造を変える。
- 問題は Rectilinear Steiner Arborescence Problem と関連し、強い貪欲は既知の2近似に近い性質を持つらしい。

## 最終コードの構造

コードなし。記事本文から読み取れる実装構造を書く。

### 状態表現

- 強い貪欲・ビーム:
  - 有効点集合。
  - マージ履歴。
  - スコアまたはコスト削減量。
  - 重複除去用の集合表現。
- 局所探索:
  - 点集合、中間点集合、各点の親。
  - 中間点追加・削除に伴って周辺の接続を更新する構造。
- 二分木:
  - 葉を入力点、内部ノードを中間点とする木。
  - 各内部ノードの座標は子の `min` で決まる。

### 観測・制約・入力の扱い

- 入力点を平面にプロットし、左下原点から右上へ辺を伸ばす。
- 操作で元点が残るため、木の分岐として表現できる。
- 中間点は入力にない座標でも出力できる。
- 操作回数は `5N` だが、二分木や強い貪欲の出力は `O(N)` 辺で済む。

### 評価関数

中間点なしの直接生成コストを基準に、2点を中間点でまとめる削減量を考える。

```text
direct = p.x+p.y + q.x+q.y
r = (min(p.x,q.x), min(p.y,q.y))
via_r = (r.x+r.y) + dist(r,p) + dist(r,q)
gain = r.x + r.y
```

したがって、`r.x+r.y` が大きい中間点を優先する強い貪欲が自然に導かれる。

### 探索・構築・更新

- 中間点なし山登り:
  - 各点の親をランダムに入れ替える。
  - 記事では 3,430,697,513 点程度と紹介されている。
- 強い貪欲:
  - 2点 `p,q` を選ぶ。
  - `r=(min(p.x,q.x),min(p.y,q.y))` を追加し、`p,q` を有効集合から外す。
  - `r.x+r.y` が大きいペアを優先する。
- ビームサーチ:
  - 強い貪欲のペア選択を幅付きにする。
  - 候補ペア数が重いので、マンハッタン距離や座標和で枝刈りする。
- 局所探索:
  - 親頂点の付け替え、中間点の追加・削除を考える。
  - 中間点を足すと周辺の最適な接続も変わるため、不要中間点の処理が必要になる。
- 二分木探索:
  - 木構造に対し、頂点移動や部分木回転を近傍にする。
  - 木の形を変えた後、内部ノード座標とコストを再計算する。

### 操作・クエリ・出力選択

- 後ろ向きマージなら、記録した辺を逆順で出力する。
- 二分木なら、根からDFSして親座標から子座標への操作を出す。
- 中間点を出力してから、それを使う子点を出力する順序を守る。

### 時間配分・パラメータ

- 記事本文には具体的なビーム幅や温度はない。
- 枝刈りとして、離れすぎている2点から作る中間点は採用されにくいため候補を減らせる、とある。
- 焼きなましではスコアのスケールが大きいので温度調整が必要と指摘している。

## 実装上重要な断片

強い貪欲の導出は次である。

```text
all-from-origin cost = sum(p.x + p.y)
if p and q share r:
    saved amount includes r.x + r.y
therefore choose large r.x + r.y first
```

二分木化は次の形で考える。

```text
internal_node(v):
    left = child0(v)
    right = child1(v)
    point[v] = (min(point[left].x, point[right].x),
                min(point[left].y, point[right].y))
    cost[v] = L1(point[left], point[right])
```

枝刈りの直感は次である。

```text
for candidate pair p, q:
    r = min_pair(p, q)
    if p and q are too far apart or r is too close to origin:
        skip with high probability / deterministic threshold
```

## この解法の本質

この参照元の本質は、複数の強い解法を同じ幾何的原理に結びつけている点である。中間点 `r` は、2点の座標ごとの共通部分であり、`r` が右上にあるほど共通化できる距離が長い。強い貪欲、ビームサーチ、二分木焼きなましは、いずれも「どの共通部分をどの順で確保するか」の違いとして理解できる。

また、Rectilinear Steiner Arborescence Problem との関連を示している点が有用である。AHC問題としてはヒューリスティックに解くが、強い貪欲が単なる偶然ではなく、既知問題の近似アルゴリズムに対応している可能性がある。

## 真似するならまず実装する部分

理解目的なら、まず記事の「コスト関数から導出」に従って、強い貪欲を実装する。`r.x+r.y` の累積が直接コスト削減に対応することを確認すると、なぜ右上からマージするのかが分かる。

次に、同じ状態表現でビームサーチへ進む。さらに上を狙るなら、Rafbill のような二分木状態に変換し、木構造の局所探索を実装する。
