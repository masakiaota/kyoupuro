## 問題の本質

AHC037 は、原点から右上方向の有向辺だけで指定点をすべて生成する、Rectilinear Steiner Arborescence に近い構築問題である。前向きに考えると「どの中間点をどこに置くか」「どの親から伸ばすか」が同時に絡んで難しい。

重要な変換は、後ろ向きに2点をマージする見方である。2点 `p, q` を同じ親から作るなら、最も深い共通祖先は

```text
r = (min(p.x, q.x), min(p.y, q.y))
```

でよい。この `r` が原点から遠いほど、2点へ共通化できる距離が長く、コスト削減量が大きい。したがって解法視点では、「どの点同士をどの順で `min` 座標へまとめるか」が中心問題になる。

前向き解法も同じ性質を使っている。既存辺の最短経路上に中継点を挿入しても、その辺の総コストは悪化しない。そこへ別の点を接続できれば、無料に近い形で共通部分を増やせる。

## 共通している考え方

どの強い方針も、コストが `x` と `y` で独立し、2点の共通部分が `min` 座標で表せることを使っている。直接辺の途中に点を置いても損しないこと、2つの葉を後ろ向きにまとめると中間点が一意に決まることが共通の核である。

後ろ向き方針では、マージ履歴を逆順に出すだけで前向き操作列になる。これにより、出力順序の難しさをマージ順管理に押し込める。

また、強い貪欲、ビーム、二分木焼きなましは連続している。強い貪欲は幅1のペア選択、ビームは複数のペア選択列、二分木焼きなましは完成したマージ木の構造変更である。

## 解法の分類

- 前向き中継点追加型: momoharahara、Gobi。既存辺の途中に中継点を足し、別点の親として再利用する。
- 強い貪欲型: official、peroon、jetbead、kaede2020。`min(p,q).x + min(p,q).y` 最大のペアを順にマージする。
- 近距離マージ型: officialの貪欲1、peroonの近い葉マージ。局所クラスタ化で弱い比較対象になる。
- ビームサーチ型: official、peroon、kaede2020。強い貪欲を幅付きにし、ペア選択列を探索する。
- 二分木焼きなまし型: official、Rafbillpc、jetbead。入力点を葉とする全二分木を直接最適化する。
- 理論整理型: jetbead、AtCoder editorial。RSA問題や2近似貪欲との関係を示す。

## 推奨して理解すべき順序

1. まず jetbead と公式PDFを読む。`min` 座標の中間点、強い貪欲の導出、後ろ向きマージを把握する。
2. 次に peroon の強い貪欲コードを見る。優先度付きキュー、有効点削除、新点追加、逆順出力を確認する。
3. momoharahara または Gobi を読む。前向きに中継点を足す見方を確認すると、`min` マージの幾何的意味が掴みやすい。
4. kaede2020 と peroon のビーム部分を読む。幅1一致、小ケース確認、候補枝刈り、状態重複除去を理解する。
5. 最後に Rafbillpc を読む。二分木、部分木移動、木回転、祖先方向差分更新に進む。

## 実装するならどのルートか

理解のための最小実装は、強い貪欲である。全ペア優先度付きキューで `min x + min y` 最大を取るだけなら短く、スコアも高い。これを実装すると、後ろ向きマージと逆順出力の基本が身につく。

次に進むならビームサーチがよい。幅1で強い貪欲と一致させ、`MiniState` と履歴復元を入れ、同じ生存点集合をハッシュで重複除去する。枝刈りは最後に、必ず幅1や小ケースで検証しながら足す。

上位化を狙うなら Rafbillpc 型の二分木焼きなましである。実装の最初の目標はスコアではなく、二分木状態、`cut/link/update`、DFS出力、ロールバック可能な近傍を壊さず動かすことになる。

前向きに理解したい場合は、momoharahara 型のL字中継点か Gobi 型の辺繋ぎ替えから始めるとよい。ただし、スコアを伸ばす主ルートとしては強い貪欲・ビーム・二分木へ移る方が自然である。

## 重要な実装要素

- 状態表現:
  - 強い貪欲は有効点集合、使用済みフラグ、マージ履歴。
  - ビームは有効点集合、スコア、ハッシュ、親状態index、選択ペア。
  - 二分木は `node{point, children, parent, cost, is_leaf}`。
- 評価関数:
  - 基本はコスト最小化。
  - マージ選択では `gain = min(p.x,q.x)+min(p.y,q.y)` を最大化する。
  - 二分木では内部ノードごとに `L1(child0, child1)` を足す。
- 近傍:
  - ビームは次ペア選択。
  - 二分木は部分木移動、木回転、必要ならノードswap。
  - 前向き型は辺上中継点追加と繋ぎ替え。
- 差分更新:
  - マージ貪欲は新点と未使用点の候補だけ追加する。
  - ビームは候補段階では差分だけ持ち、採用時に状態更新する。
  - 二分木は変更した親から祖先へ、座標が変わらなくなるまで更新する。
- 候補管理:
  - ペア全列挙は `O(N^2)` なので、ビームでは枝刈りとソート済み順序が重要。
  - 同じ生存点集合はハッシュで重複除去する。
  - 誤った枝刈りはスコアを壊すため、幅1や小ケースで検証する。
- 出力判定:
  - 後ろ向きマージの辺は逆順に出す。
  - 生成元が既に作られている順序を守る。
  - `(0,0)` や同座標辺を特別扱いする。
- パラメータ:
  - peroon のビーム幅は70。
  - kaede2020 は最終的に幅3でも強い貪欲を超えたと記載。
  - Rafbillpc は `TL=1.99`、温度 `5e8 -> 5e2`、ノード移動中心。

## 落とし穴

- 近い点からマージすると局所クラスタができ、終盤に遠いクラスタ間接続を払う。
- 後ろ向きマージで記録した辺をそのまま順方向に出すと、生成元が未作成になり得る。逆順出力が必要である。
- `r=(min x,min y)` が子のどちらかと同じ座標になる場合、ゼロ長や重複座標の扱いを誤るとWAになる。
- `(0,0)` が入力点に含まれるケースで、必要な出力を漏らす、または不要な自己辺を出す実装になりやすい。
- ビームの状態に出力列全体を持つと重くなる。履歴復元か軽量差分が必要である。
- 生存点集合の重複を除かないと、マージ順だけ違う同一状態でビーム幅を浪費する。
- 枝刈り条件は、ソート順から本当に打ち切れる場合だけ `break` にする。将来もっと良い `min` 座標が出る可能性を潰すとスコアが落ちる。
- 二分木焼きなましでは、祖先関係を無視してつなぎ替えると閉路や壊れた木になる。
- `cut/link/update` のロールバック漏れは、親子リンク、内部ノード座標、総コストの不整合を生む。
- 中継点追加型では、追加点を残しすぎると操作数や出力順序の管理が複雑になる。
