## 解法の全体像

盤面を順番に埋める構築貪欲である。評価は、隣接する親ペアについて各次元の `max` を足すことを基本にし、現在の各次元最大値を持つ希少な種には追加ボーナスを与える。良い種から中心に置くため、配置順は中心付近から外側へ向かう。未配置マスには仮の「全次元 100 の神 seed」を置いたものとして評価し、後から埋まる隣接先にも良い成分が来る前提で、局所的に候補を選ぶ。

## 主要アイデア

- 隣接ペアの子は各次元で片親から値を受け継ぐため、ペアの価値は `max(a_l, b_l)` の和で見る。
- 内側に置いた種は多くの辺に関わり、良い成分を次世代へ残しやすい。
- 各次元の現在最大値を持つ種を「現実度」または希少性ボーナスで優遇する。
- 最大値を持つ種が少ない次元ほど、その最大値を持つ種を強く残す。
- ボーナスは `10 - turn` に比例して減らし、終盤では隣接ペア評価の比重を相対的に上げる。
- 追記版では、中心から渦巻きに近い順で埋めることで、単純な内側優先を少し改善している。

## 最終コードの構造

### 状態表現

- `Crops[60][15]`: 現在の種ベクトル。
- `Best[15]`: 各次元の現在最大値。
- `BestCount[15]`: その最大値を持つ種の個数。
- `Reality[60]`: 各種が現在最大値を持つ次元数と希少性を反映したボーナス。
- `Ans[6][6]`: 出力する盤面。初期値は `-1`。
- `Used[60]`: すでに盤面に置いた種かどうか。
- `SeeOrder`: 盤面を埋める順序。追記版は中心付近から外へ広がる固定順。

### 観測・制約・入力の扱い

- 毎ターン、60 種のベクトルから `Best`, `BestCount`, `Reality` を再計算する。
- 同じ seed id を複数回置かないよう `Used` で管理する。
- 出力後に 60 個の次世代ベクトルを読み、次ターンへ進む。

### 評価関数

候補 seed `s` を位置 `p` に置くとき、すでに置かれた隣接マスとの局所評価を計算する。未配置の隣接先は全次元 `100` の仮 seed とみなす。

```text
local_score(p, s):
    score = 0
    for q in neighbors(p):
        t = seed_at(q) if q is filled else GOD
        score += sum_l max(Crops[s][l], Crops[t][l])
    score += 15 * Reality[s] * (10 - turn)
    return score
```

`Reality[s]` は、種 `s` が各次元最大値を持つ場合に加算される。最大値を持つ種の個数が少ないほど加点が大きくなる。

### 探索・構築・更新

- 焼きなましや局所探索は使わず、固定順で盤面を 1 マスずつ埋める。
- 各マスについて、未使用の 60 種すべてを候補にし、`local_score` が最大のものを置く。
- 盤面全体を後から swap する処理はない。
- 計算量は `10 * 36 * 60 * 4 * 15` 程度で非常に軽い。

### 操作・クエリ・出力選択

- `SeeOrder` の順番に 36 マスを埋める。
- 最終的に `Ans` を 6 行で出力する。
- 追記版の `SeeOrder` は中心 4 マス周辺から始まり、外側へ広がる順序になっている。

### 時間配分・パラメータ

- 主な固定値は希少性ボーナスの係数 `15` とターン残数係数 `(10 - turn)`。
- 実行時間は軽く、時間配分より評価式の調整が重要である。
- 未配置マスの仮 seed は全次元 `100` で、将来の隣接相手への期待を強く見る設定になっている。

## 実装上重要な断片

```text
for each dimension l:
    Best[l] = max_k Crops[k][l]
    BestCount[l] = count_k(Crops[k][l] == Best[l])

for each seed k:
    Reality[k] = 0
    for l in dimensions:
        if Crops[k][l] == Best[l]:
            Reality[k] += 1 + 2 / BestCount[l]
```

盤面構築は次の形である。

```text
for p in SeeOrder:
    best_seed = argmax unused s of local_score(p, s)
    Ans[p] = best_seed
    Used[best_seed] = true
```

## この解法の本質

単純な価値合計ではなく、辺から子が生まれることに合わせて「隣接ペアが各次元でどれだけ高い値を持つか」を直接見る点が効いている。また、現在最大値を持つ成分は一度消えると復活しにくいため、希少な最大成分を明示的に守っている。探索せずに 1 マスずつ決める方針でも、問題構造に合う評価を入れることで高い点が出る。

## 真似するならまず実装する部分

まず、中心優先の固定順と `sum max` の局所貪欲を実装する。次に、各次元最大値の希少性ボーナスを追加する。追記版の渦巻き順は簡単に入れられるので、行優先の内側順より先に採用してよい。

## 注意点・未理解点

- 未配置マスを全次元 `100` とみなす評価は強い仮定であり、順序やボーナスとの相性に依存する。
- 局所貪欲なので、後から見れば悪い配置を修正できない。
- 希少性ボーナスが強すぎると、隣接ペアとしては弱い種を中心に置く可能性がある。
- 記事中には複数の途中提出があるが、個別メモでは最終付近と追記版を中心に読んだ。
