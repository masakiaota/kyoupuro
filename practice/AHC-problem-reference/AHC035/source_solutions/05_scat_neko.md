## 解法の全体像

固定の中心優先順に、評価値の高い種を並べる高速な貪欲解法である。評価値は、各次元の現在最大値で正規化した値のべき乗和を基礎にする。さらに、ある次元で最大値付近の種が少ない場合、その次元を希少とみなして重みを上げる。序盤は各次元最大値を必ず残す処理を入れ、終盤は希少性重みを弱めて、最終的な合計値に寄せる。

## 主要アイデア

- 良い種を中心へ置く固定順だけでもかなり強い。
- 種の単体評価は、現在の各次元最大値で割った比率のべき乗和にする。
- 各次元で最大値を持つ種を優先して残し、最大成分の消失を防ぐ。
- ある次元で高い値を持つ種が少ないほど、その次元の重みを大きくする。
- 希少性重みは終盤で弱める。終盤は多様性保持よりも最終的な価値合計が重要になる。
- 隣接ペア評価や探索を使わず、単体評価と配置順だけで軽く実装する。

## 最終コードの構造

### 状態表現

- `X[60][15]`: 現在の種ベクトル。
- `max_v[15]`: 各次元の現在最大値。
- `factor[15]`: 各次元の希少性を表す平均値。値が小さい次元ほど重くなる。
- `val[60]`: 種の評価値。
- `order`: 中心から外側へ向かう固定マス順。
- `used[60]`: 出力に使った種かどうか。

### 観測・制約・入力の扱い

- 各ターン、現在の 60 種から各次元最大値と `factor` を再計算する。
- 最大値を持つ種を先に選ぶ処理では、同じ seed id を重複選択しないようにする。
- 出力後、次世代の 60 種を読み込む。

### 評価関数

最終付近の説明では、希少性 `factor` と種評価 `val` は概ね次の形である。

```text
factor[l] = average_k (X[k][l] / max_v[l])^degree1

seed_score(k, turn):
    return sum_l (X[k][l] / max_v[l])^degree2 / factor[l]^schedule[turn]
```

代表値は `degree1=3`, `degree2=6`。`schedule` は終盤ほど小さくなり、最後に近いほど希少性重みが弱くなる。

### 探索・構築・更新

- 各 seed の評価値を計算して降順に並べる。
- 序盤から中盤では、各次元最大値を持つ seed を優先して選ぶ。
- 残りのマスは評価値順に未使用 seed を選ぶ。
- 盤面配置は固定順で、swap や焼きなましは行わない。

### 操作・クエリ・出力選択

- 中心優先の固定順 `order` に従って seed id を並べる。
- 最終ターンでは、最大値保持の優先処理を弱めるまたは省き、評価値順に寄せる。
- 出力は 6x6 の seed id 配列で行う。

### 時間配分・パラメータ

- 探索がないため実行時間は非常に短い。記事中の最終提出は CPython で十分高速である。
- 重要なパラメータは `degree1=3`, `degree2=6`, 終盤調整用の `schedule`。
- 配置順は手作業で用意された中心優先の固定順である。

## 実装上重要な断片

```text
for l in dimensions:
    max_v[l] = max_k X[k][l]
    factor[l] = average_k (X[k][l] / max_v[l])^degree1

for k in seeds:
    val[k] = sum_l (X[k][l] / max_v[l])^degree2 / factor[l]^schedule[turn]
```

出力 seed の選択は次の流れになる。

```text
selected = []
if turn is not final:
    for l in dimensions:
        choose an unused seed with X[k][l] == max_v[l] and large val[k]
        selected.append(k)

append remaining unused seeds in descending val order until 36
place selected seeds by center-first order
```

## この解法の本質

この解法は、問題を「最大成分を消さずに、希少な高成分を中心へ運ぶ」問題として単純化している。探索やペア評価を使わなくても、最大値保持、希少次元重み、中心優先配置の 3 つが噛み合うと強い。特に、各次元最大値の喪失を防ぐ処理は、世代交代で情報が消える問題に対する基本的な保険になっている。

## 真似するならまず実装する部分

まず、各次元最大値で正規化したべき乗評価と中心優先順の配置を実装する。次に、各次元最大値を持つ seed を先に確保する。最後に、希少性 `factor` と終盤用 `schedule` を入れるとよい。探索を入れないため、最初の実装として扱いやすい。

## 注意点・未理解点

- 隣接ペアを直接見ないため、補完的な親同士を隣に置く工夫は入らない。
- 固定順の良し悪しがスコアに影響するが、順序の最適性は記事からは分からない。
- 希少性重みを強くしすぎると、希少だが総合力の低い種を過大評価する。
- 終盤 schedule の値はチューニング依存で、一般化できる根拠までは示されていない。
