## 解法の全体像

公式解説は、良い種を単に価値順に残す問題ではなく、各評価項目の最大値に近い成分を次世代へ残す問題として捉えている。まず「価値順に中央へ置く」程度の貪欲から始め、隣接ペアごとの評価関数を設計して配置を焼きなましで改善する方向へ進む。最終ターンでは、次世代を観測できないため、出力した辺集合から生まれる 60 個の子の最大価値の期待値を直接評価する。

## 主要アイデア

- 各種の合計値よりも、評価項目ごとの尖りを重視する。
- 内側のマスほど次数が大きく、置いた種の成分が次世代へ残りやすい。
- 盤面全体を、隣接ペア評価の総和として評価する。
- ペア評価では `max(a_l, b_l)` を重視する。子は各次元を片親から選ぶため、片方が高ければその成分は残る可能性がある。
- 目標ベクトルとの差分や logsumexp を使い、最大値に近い成分を滑らかに高評価する。
- 最終ターンだけは通常の近似評価ではなく、各辺から出る子の価値分布を用いて最大値の期待値を評価する。

## 最終コードの構造

Browserで読んだ提出 #55746489 の実装構造である。スライドの logsumexp 的な代理評価と、最終ターンだけ別評価にする方針が実装に入っている。

### 状態表現

- 現在の 60 個の種の `M=15` 次元ベクトルを持つ。
- 盤面は `6x6` の seed id 配列として持つ。
- 評価時は、盤面上の上下左右 60 辺を列挙する。
- 最終ターン評価では、各辺ごとに「そのペアから生まれる子の価値分布」または閾値未満確率を持つ。
- 実装では `intermediate_turn::Env` が `genes` とペア評価表 `adj_dict` を持つ。
- `State` は `map: Map2d<usize>` と `used` を持ち、盤面内外の種を交換しながら焼きなます。
- `final_turn::calc_gene_map` は別モジュールで、最終ターン用に長めの時間を使う。

### 観測・制約・入力の扱い

- 各ターンで 36 個の相異なる種を出力する。
- 出力後、次世代の 60 個のベクトルを読み直す。
- 初期入力の各次元最大値を、正規化や得点上限の基準として保持する。

### 評価関数

- 基本形は、盤面評価を隣接ペア評価の和とする。

```text
board_score(board):
    return sum(pair_score(seed[u], seed[v]) for (u, v) in grid_edges)
```

- 初期の有効な例として、各次元で `max(a_l, b_l)^2` を足す評価が紹介されている。
- 改善版では、現在の目標値または各次元最大値との差分を使い、目標に近い成分を高く評価する。
- logsumexp によって「最大を取りたいが、探索中に滑らかに比較したい」箇所を近似する。
- 最終ターンは、各辺から生成される子の価値分布を使い、60 個の子の最大値の期待値を評価する。

### 探索・構築・更新

- 基本的には盤面配置に対する焼きなましを想定している。
- 近傍は、盤面上の種の swap、または盤面内外の seed id の交換で実装できる。
- 盤面評価が辺の和なので、swap に関係する近傍辺だけを差分更新できる。
- 最終ターンも、辺ごとの確率を持てば、変更された辺の寄与だけを更新できる。
- 提出コードでは中間ターンに `intermediate_turn::calc_gene_map(genes, 0.05)`、最終ターンに `final_turn::calc_gene_map(genes, 1.4)` を呼ぶ。
- `Env::new` で各次元最大値との差を logsumexp 風に滑らかにまとめ、`adj_dict` として全ペア評価を前計算する。

### 操作・クエリ・出力選択

- 各ターンで、現在の 60 種から 36 種を選び盤面へ配置する。
- 中盤までは近似的な隣接ペア評価を最大化する。
- 最終ターンでは、出力後に次世代を操作できないため、次世代 60 種の最大価値の期待値が高い盤面を選ぶ。

### 時間配分・パラメータ

- スライド上では複数の評価関数とスコアが比較されているが、最終的な温度や反復数の詳細コードは公開されていない。
- logsumexp の係数、目標差分評価の重み、温度はチューニング対象になる。
- 最終ターン評価は重いため、閾値ごとの確率や辺ごとの差分を前計算・差分更新する必要がある。

## 実装上重要な断片

```text
for turn in 0..T-1:
    init_board()
    while time remains:
        move = choose_swap_or_replace()
        old = local_edge_score(move.affected_edges)
        apply(move)
        new = local_edge_score(move.affected_edges)
        accept_or_rollback(new - old)
    output(board)
    read_next_generation()
```

最終ターンの期待値評価は次の形になる。

```text
expected_max(edges):
    ans = 0
    for w in 1..max_possible_value:
        p_all_less = product(prob_child_value_less_than(edge, w) for edge in edges)
        ans += 1 - p_all_less
    return ans
```

各辺の子は、15 次元それぞれで片親を選ぶため、価値分布は小さな DP で計算できる。

## この解法の本質

この問題では、最終的に欲しいのは合計値の高い一粒だが、途中で保存すべき情報は「各評価項目で高い成分がどれだけ次世代に残るか」だ。隣接ペア評価は、子が辺から生まれるという構造に合っている。さらに最終ターンだけ期待値を直接見ることで、途中の代理評価と最終目的のずれを小さくしている。

## 真似するならまず実装する部分

まずは、盤面を辺の和で評価する焼きなましを実装するのがよい。ペア評価は `sum_l max(a_l, b_l)^p` から始める。次に、各次元最大値との差分や正規化を入れる。最終ターンの期待値評価は強いが実装量が増えるため、基本の局所探索が動いてから追加するのが現実的だ。
