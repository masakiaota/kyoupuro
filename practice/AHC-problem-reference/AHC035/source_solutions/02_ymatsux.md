## 解法の全体像

乱択探索ではなく、毎ターン「残す 36 種の集合を選ぶ」「選んだ種を中央から順に置く」「隣接関係が良くなるように並べ替える」という貪欲で高スコアを出す解法である。種集合の評価には各評価項目の p-ノルムを使い、少数の高い成分だけでなく、同じ項目に高めの値を持つ候補が複数残ることも評価する。配置は中央渦巻き順を基礎にし、上位種を中心に集めながら、隣接ペアの max/min 評価で局所的に良い並びを作る。

## 主要アイデア

- 種集合の良さを、各次元の最大値の和ではなく p-ノルムの和で評価する。
- 値を次元最大値で正規化し、さらにべき乗してから p-ノルムに入れる。
- 36 個の選択は貪欲に 1 個ずつ追加し、集合評価の増分が大きい種を採用する。
- 配置は中央から外側へ向かう渦巻き順を使い、良い種ほど次数の高い内側へ置く。
- 隣接ペア評価では `max` を重視しつつ、`min` も少し混ぜて両親の補完性を評価する。
- 全 36 個を自由に並べ替えると強い種が外側へ出ることがあるため、中央 16 個と外側 20 個を分けて並べ替える。

- 各ターンで 60 種から 36 種を選ぶ。
- 同じ種を複数回出力しないよう、選択済みフラグを持つ。
- 出力後に次世代 60 種を読み、同じ手順を繰り返す。

### 評価関数

集合評価は、概ね次の形で説明されている。

```text
set_score(S):
    score = 0
    for l in dimensions:
        score += p_norm({ normalized_value(k, l)^q | k in S })
    return score
```

記事では `p=3, q=2` が良い例として挙げられている。p-ノルムにより、単純な最大値だけでなく、同じ次元で高い値を持つ種が複数残ることも評価される。

隣接ペア評価は次の発想である。

```text
pair_score(a, b):
    return sum_l alpha * max(r[a][l], r[b][l])^q
               + (1 - alpha) * min(r[a][l], r[b][l])^q
```

記事では `alpha=0.8` が示されている。`max` は片親から高い成分が残る期待、`min` は両親がともに高い場合の安定性を表す。提出コードでは `MAX_W` 相当の重みで `max` と `min` を混ぜ、すでに置かれた隣接セルとのスコア和を最大にする種を選ぶ。

### 探索・構築・更新

- 36 種の選択は貪欲追加で行う。
- 各ステップで、未選択の各種を仮追加し、集合評価の増分が最大のものを選ぶ。
- 配置は、中央渦巻き順に従うだけの版と、隣接評価を見て貪欲に並べる版がある。
- 最終的に強い版では、選択順の上位 16 個を中心領域、残り 20 個を外周領域として分け、各領域内で配置を貪欲に決める。
- 実装では `cell_to_id` で既配置の隣接セルを調べ、`std::max(adjusted_vectors[k0][d], adjusted_vectors[k1][d])` と `std::min(...)` のべき乗和を候補スコアにする。

### 操作・クエリ・出力選択

- 毎ターン、選んだ 36 種を `6x6` に配置して出力する。
- 中央渦巻き順により、序盤に選ばれた強い種が次数 4 の中心付近に置かれる。
- 最終ターンだけ大きく別の処理をする記述は見当たらない。

### 時間配分・パラメータ

- 記事で明示されている代表値は `p=3`, `q=2`, `alpha=0.8`。
- 焼きなましではなく貪欲中心なので、反復回数より評価関数の定数調整が重要になる。
- 集合評価を毎回全計算すると重いが、`60` 種・`36` 選択・`15` 次元なので素直実装でも十分現実的だ。

## 実装上重要な断片

```text
S = []
while len(S) < 36:
    best = argmax candidate not in S of set_score(S + [candidate])
    S.append(best)
```

配置は中央と外側を分ける。

```text
inner = S[0:16]
outer = S[16:36]
place_group(inner, inner_spiral_cells, pair_score)
place_group(outer, outer_spiral_cells, pair_score)
```

`place_group` は、すでに置かれた隣接種との `pair_score` が大きくなる候補を順に選ぶ貪欲で実装できる。

## この解法の本質

子の生成は各次元で片親を選ぶため、1 個の種の合計値だけで判断すると、希少な高成分を捨てやすい。この解法は、集合全体が各次元でどれだけ高い成分を保持しているかを p-ノルムで測る。さらに中心渦巻き配置で、保持した高成分が多くの辺に出るようにしている。探索をほぼ使わず、評価関数設計だけで強い構築にしている点が本質だ。

## 真似するならまず実装する部分

まず `p=3, q=2` の集合貪欲と、固定の中央渦巻き配置を実装するのがよい。これだけで高成分保持と中心優先が入る。次に、隣接ペア評価を使った中心 16 個・外側 20 個の分割配置を足すと、実装量に対して伸びやすい。
