## 問題の本質

AHC036 は、移動距離そのものではなく、移動に必要な青信号集合をどれだけ再利用できるかを最適化する問題である。B に入る頂点集合が連結なら、その集合内は信号操作なしで移動できる。したがって、A の連続区間を「よく使う連結頂点集合」または「長く進めるパス」として設計することが重要になる。

解法視点では、問題は次の2段に分かれる。

1. A 構築: どの頂点集合・パス・グループを A 上に並べるか。
2. 旅行最適化: 構築済み A から、いつどの区間を B にコピーし、どの経路で目的地を辿るか。

上位解法ほど、この2段を分けつつ、評価で再び結び直している。特に soumat 解法は、A の構造変更を実スコア DP で評価し、焼きなましに載せている。

## 共通している考え方

- A の連続区間を、グラフ上で移動しやすい連結集合として作る。
- A 構築と旅行最適化を分け、A が決まった後は DP、BFS、01BFS で操作列を選ぶ。
- 目的地間の個別最短路をそのまま使うだけでは弱く、経路や頂点集合を共有させる必要がある。
- LB の大きさで有効方針が変わる。大きい LB は中央共有や太いグループが強く、小さい LB は長いパスや細い経路再利用が重要になる。
- BitSet や配列による高速な集合判定が重要で、HashSet や毎回 BFS はボトルネックになりやすい。
- 最後の復元を毎回行わず、探索中は抽象状態だけで評価する方が反復しやすい。

## 解法の分類

- 連結グループ最適化型: soumat、公式の中央共有方針
- ターミナル木・幹線型: kiri8128、公式の中央共有方針
- 長いパス構築型: 公式、kiri8128、utac の候補列マージ
- レイヤー DP/01BFS 型: utac、kiri8128
- route 先固定・候補抽出型: vvani07
- 後処理改善型: soumat の A 圧縮、vvani07 の部分コピーと乱択並べ替え、utac の未使用レイヤー変更

## 実装するならどのルートか

理解のための最小実装なら、vvani07 型から始めるのがよい。目的地間最短路をつなげた route を作り、route の連続頂点を A に詰め、必要な頂点が B にないとき A の区間をコピーするだけで、出力まで到達しやすい。

次に、utac 型の「A の長さ LB 区間をレイヤーにした 01BFS」を実装する。これは任意の A に対する評価器・復元器になるため、以後の A 改善が測れる。

上位化するなら、kiri8128 型のターミナル木・パス合体か、soumat 型の連結グループ山登りへ進む。最終的には soumat 型のように、A 構築を実スコア DP で評価し、非関節点置換や A 圧縮で改善する方向が強い。

## 重要な実装要素

- 状態表現: A 区間、B の現在集合、グループ bitset、レイヤー番号、目的地 index、現在頂点。
- 評価関数: 信号操作回数を直接 DP/01BFS で計算する。A 候補生成では目的地頻度、未使用頂点数、共通辺数、長い連続集合を代理評価に使う。
- 近傍: 非関節点を隣接頂点へ置換する、候補列を反転・シャッフルする、未使用 A 区間を近傍頂点に変える、パスを合体する。
- 差分更新: グループ間辺と最短距離、頂点出現回数、bitset、DP スコアを差分化すると試行回数が増える。
- 候補管理: `use_layer[u]`、`move_memo[layer][u]`、頂点ごとの A 開始位置、グループを含む頂点の逆引きが効く。
- 出力判定: 信号操作と移動の合計 10^5 回以下、移動先が隣接かつ B に含まれる、目的地順序を満たすことを必ず確認する。
- パラメータ: LB による方針切り替え、焼きなまし温度、候補数、再試行時間、部分コピーで見る未来長。

## 落とし穴

- B に頂点が含まれていても、現在位置からその頂点へ青頂点だけで連結していない場合は移動できない。集合の包含だけでなく実経路復元が必要である。
- A の同じ LB 窓に同じ頂点を何度も入れると無駄になりやすい。
- 長さ LB 固定だけに制限すると実装は楽だが、部分コピーで拾える改善を逃す。
- 目的地間の最短路を独立に選ぶと、A での再利用性が低くなる。
- DP の状態を「目的地に初めて到達したレイヤー」だけに潰すと、次目的地への移動で損をする。utac が残しているように、目的地到達レイヤーの違いを保持する必要がある。
- 焼きなましで連結性を壊す近傍を入れると、評価と出力復元の両方が破綻しやすい。
- 差分更新は高速だが、バグるとスコア計算だけが壊れて不正解に近い状態を良いと誤認する。

## 未解決・要検証事項

- kiri8128 解法は記事中にコードリンクがないが、Browserで提出 #57404598 を読めた。非連結状態の扱いとA生成は確認済みである。
- vvani07 の PR は最終コードと主要コミットログを中心に読んだ。BrowserでAtCoder提出一覧 `f.User=vvani07` / `VVani07` は該当なしだった。
- 公式スライドPDFはBrowserで `net::ERR_BLOCKED_BY_CLIENT` となった。方針紹介であり、実装パラメータや提出コードはない。
- LB ごとの最適な方針切り替え、特に小さい LB での長いパス型と大きい LB での中央共有型の境界は、手元実験で検証が必要である。
- soumat 型の距離差分更新と A 圧縮は強力だが、簡略実装でどこまで効果が残るかは要検証である。
