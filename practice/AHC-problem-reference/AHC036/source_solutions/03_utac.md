## 解法の全体像

A から長さ LB 固定で B にコピーすることに制限し、A が決まれば移動最適化は DP/01BFS で解けると見る。したがって、前半では A をよい状態に作ることへ集中する。

A 生成では、目的地間の経路ができるだけ同じ辺を共有するように、蟻コロニー最適化風に辺重みを育てる。得られた経路群を候補列に変換し、端同士や LB 範囲内の内側同士が接続できる候補をマージし、重複や近距離の同一頂点を削る。A ができたら、各長さ LB 区間をレイヤーとした 01BFS 風 DP で、目的地列を回る最小操作数と操作列を復元する。

## 主要アイデア

- A の区間をレイヤーとして扱い、「同じレイヤー内の移動はコスト0、レイヤー変更はコスト1」とする。
- レイヤー数は `LA - LB + 1` であり、B の自由度を大きく制限する代わりに探索を安定させる。
- 目的地間経路は、蟻コロニー風の辺重み更新で共通辺を使いやすくする。
- 経路候補は、未使用頂点を多く含む経路から優先的に追加し、多様な A 部品を作る。
- 候補列同士は端だけでなく、LB の範囲まで内側を見てマージする。
- DP 探索では `Node=(到達目的地数, 現在レイヤー, 現在頂点, 親ノードindex, 移動コスト, 到着フラグ)` を持ち、親を辿って出力を復元する。
- 使われなかった A 区間の変更、候補列シャッフル、反転で余り時間に再試行する。

## 最終コードの構造

### 状態表現

- `Solver` が入力、グラフ、A、候補列、レイヤー情報、最良解を持つ。
- `Node` は到達目的地数 `turn`、現在レイヤー `layer`、現在頂点 `pos`、親ノード、スコア、目的地到達フラグを持つ。
- `can_move[layer]` は、そのレイヤーで B に入る頂点集合を BitSet として表す。
- `use_layer[u]` は、頂点 u から移る価値があるレイヤー、つまり u の隣接頂点を含むレイヤーのリストである。
- `move_memo[layer][u]` は、レイヤー layer の青頂点だけで u から到達できる頂点リストをメモ化する。
- `layerBitSet` は、探索中に使われたレイヤーを記録し、後段の A 変更に使う。

### 観測・制約・入力の扱い

- LB が5以下の場合のみ、目的地順序の局所的な組み換えを入れる。`0 -> 1 -> 2` より `0 -> 2 -> 1` が大きく悪化しないなら、後者で共通経路を増やす。
- 辺重みの初期値は大きめに置き、目的地に関係しない辺は重みを落として使われにくくする。
- 候補生成では、近距離の同じ数字を削る。同じ LB 窓に同じ頂点が複数入るのは無駄になりやすいためである。

### 評価関数

- A の候補生成では、経路中の「まだ候補に含まれていない頂点」と「その経路が使う頂点」の交差数が大きい経路を優先する。
- 蟻コロニー風前処理では、使われた辺の重みを増やし、使われない辺の重みを下げる。次の経路選択時に共通辺が選ばれやすくなる。
- 最終評価は DP/01BFS による信号操作回数で、最良解を保持する。

### 探索・構築・更新

- `preProcessing` で距離や経路選択に必要な情報を準備する。
- `routeSearch` で、重み付きの目的地間経路を作り、候補列へ変換・マージする。
- `solve` では A から `can_move`、`use_layer`、`move_memo` を準備し、`breamSearch` を呼ぶ。
- `breamSearch` は 01BFS 風にノードを deque へ追加する。同じレイヤー内移動は前方、レイヤー変更は後方へ入れる。
- 目的地に到達したときは、同じ目的地でもレイヤーが異なるならノードを残す。到達レイヤーにより次目的地への最適性が変わるためである。
- 探索後、最後のノードから親を辿り、各区間の実移動経路を BFS で復元する。

### 操作・クエリ・出力選択

- レイヤー変更時に `s LB layer 0` 相当の信号操作を出し、同一レイヤー内の移動は `m v` を連ねる。
- 復元では、親ノード間の現在位置と次位置をつなぐ青頂点内経路を BFS して、移動列を出す。
- 最終出力は、最良解の操作列を逆順に保持しておき、出力時に反転して表示する構造である。

### 時間配分・パラメータ

- 提出コードの実行時間は約 2918ms。`solve` は `cpuTime` で制限時刻を見ながら反復する。
- 記事では seed=0 などで主要処理が 200ms 程度で終わることがあり、余り時間を A の再構成・ランダム変更に使うとある。
- A 候補の近距離重複削除は `max(2, LB // 3)` 程度の範囲で行う。

## 実装上重要な断片

```text
getMovePoint(layer, u):
    if memo[layer][u] exists:
        return memo
    BFS from u using only vertices in can_move[layer]
    memoize reachable vertices
```

```text
search():
    dp[0][0] = 0
    push Node(turn=0, layer=-1, pos=0)
    while deque not empty:
        node = pop
        next_target = t[turn]
        try same-layer moves with cost 0
        try use_layer[pos] transitions with cost 1
        when target reached:
            keep node per reached layer
    restore by parent links
```

## この解法の本質

この解法は、A 構築と旅行最適化を分けたうえで、旅行最適化をレイヤー付き 01BFS にしている点が本質である。長さ LB 固定コピーに制限することで、B の複雑な部分更新を捨て、代わりに「A の各窓が作る青信号連結成分」を高速に扱える。

また、A の構築では、目的地間の個別最短路をただ並べるのではなく、共通辺を誘導して A 区間の再利用性を上げている。強い A は、1回の信号操作で長い移動や複数目的地への接続を可能にするため、経路同士を似せることが効いている。

## 真似するならまず実装する部分

まず、任意の A に対して `can_move[layer]` と `use_layer[u]` を作り、レイヤー付き 01BFS で操作数を最小化する部分を実装するのがよい。A は最短路を LB ごとに並べる程度でも、評価器として機能する。

次に、目的地間経路を候補列化し、端同士が隣接する候補をマージして A にする。最後に、蟻コロニー風の辺重み更新と未使用レイヤー変更を入れる。

## 注意点・未理解点

- 記事とコードでは `breamSearch` という名前だが、実質的にはビーム幅制限ではなく DP 更新時だけノードを増やす 01BFS である。
- 長さ LB 固定コピーに制限しているため、部分コピーを多用する上位解には届きにくい可能性がある。
- `move_memo` のメモ化は強力だが、A を変更したら必ず破棄・再構築が必要である。
- LB が大きいケースで上位との差があると記事にあり、長い経路同士のマージや目的地順序入れ替えの効果はケース依存である。
