## 解法の全体像

配列 B を毎回ほぼ全長で書き換え、B に載る頂点集合を「連結なグループ」とみなす。A は複数の連結グループを並べたものとして作り、各グループ間に少なくとも1本の道路があれば、信号操作1回でグループを乗り換えられると考える。

最終スコアは、目的地を含むグループ列を選ぶ DP で実スコア相当に評価する。焼きなましでは、グループ内の非関節点を隣接頂点に置き換える近傍だけを使い、グループの連結性を保ったまま DP スコアが良くなるグループ集合を探す。最後に、重複を利用してグループ列を A に圧縮し、余り領域には現解で弱い区間の最短路を詰める。

## 主要アイデア

- B の状態を「連結な頂点グループ」として扱い、移動問題をグループ間最短路問題に落とす。
- 各グループは基本的に長さ LB の A 区間で表し、グループ数は `LA / LB` より少し多めに作ってから A へ圧縮する。
- グループ内の頂点置換は、削除しても連結性が壊れない非関節点だけを選ぶ。
- 評価は近似ではなく、目的地列に対する信号操作回数を DP で計算する。
- 頂点置換で変わるグループ間グラフの最短距離を差分更新し、焼きなましを高速化する。
- A の圧縮では、グループ同士の共通部分を見て貪欲に重ね、空いた領域を追加の有用パスで埋める。

## 最終コードの構造

### 状態表現

- `InitA::State` は初期のグループ列 `A`、各頂点の出現回数 `cnt`、各グループの頂点集合 `set_A`、削除可能頂点集合 `nart_A` を持つ。
- `SA::State` は圧縮前後の A、グループ区間、グループ間距離、DP スコアを持つ。
- グループ集合は `bitset<600>` で保持され、隣接判定や頂点の有無判定を高速に行う。
- LowLink でグループ内の関節点を求め、置換候補から外す。

### 観測・制約・入力の扱い

- N と T は固定で 600、LB は 4 から 24 と小さいため、グループ内集合は bitset、グループ間距離は配列で持つ。
- 目的地頂点と開始頂点 0 は初期グループ集合に含める対象として重く扱う。
- 平面グラフであること自体を直接幾何計算に使うより、道路グラフ上の BFS・隣接判定を主に使う。

### 評価関数

- 初期解構築では、グループに含まれる目的地・開始点を高く評価する。提出コードでは目的地を 1000 点、その他を 1 点相当に重くして、重要頂点の取りこぼしを避けている。
- 最終焼きなましでは `calcScore()` が実際の信号操作回数相当を返し、その負値を最大化する形で扱う。
- DP は「i 番目の目的地に到達済みで、現在グループが s のときの最小操作回数」を持つ。前目的地を含むグループから、次目的地を含むグループへのグループ間距離で遷移する。

### 探索・構築・更新

- 初期グループは、目的地や 0 を含むように BFS ベースで作る。
- 焼きなましの近傍は、1グループを選び、非関節点1つをグループ外かつグループ隣接頂点へ置換する操作である。
- 置換後、出現回数、bitset、削除可能頂点集合、グループ間辺、グループ間距離、DP スコアを更新する。
- 辺削除時の距離再計算が重いため、最短木の部分木情報だけ更新すれば済む場合を判定し、全再計算を避ける。
- 失敗しやすい遷移、特に辺追加なしで多くの辺を削る遷移は早めに失敗扱いにして時間を守る。

### 操作・クエリ・出力選択

- 圧縮後の A と利用可能区間 `section` をもとに、目的地列を辿る操作列を復元する。
- 信号操作は基本的に `s l P_A P_B` で区間を B にコピーし、その後に青頂点上の実移動 `m v` を列挙する。
- 余り領域へ追加した区間も `section` として扱い、行動生成時の候補に入れる。

### 時間配分・パラメータ

- 提出コードの `main` では、初期 A の焼きなましに約 1000ms、最終 A 改善に約 2850ms の TimeKeeper を使う。
- 記事では焼きなましループが 5万から50万回程度、温度は低め、近傍は1種類としている。
- 最終コードでは初期焼きなまし温度が `10.0 -> 1.0`、後段が `0.8 * N / LA -> 0.0001` である。

## 実装上重要な断片

```text
transition(group):
    removable = non_articulation_vertices(group)
    old = random(removable)
    new = random(neighbor_of_group_without_old - group)
    replace old by new
    update occurrence counts
    update group adjacency
    update shortest distances incrementally
    score = -dp_score()
```

```text
dp_score():
    states = groups containing start or previous target
    for each target:
        next_states = groups containing target
        dp[next] = min(dp[prev] + group_dist[prev][next])
        keep only the best previous representative when equivalent
```

## この解法の本質

この解法の強さは、B の自由度をいったん「連結グループ」に制限し、移動経路探索と A 構築をグループグラフ上の最短路・DP・局所探索に変換した点にある。頂点単位で信号を考えると操作の自由度が大きすぎるが、連結グループ単位にすると、信号操作回数がグループ間遷移回数として直接評価できる。

さらに、近傍を非関節点置換に限定することで、連結性という壊れやすい制約を常に保つ。評価を実スコア DP に近づけ、距離更新を差分化したため、焼きなましの試行回数を稼げている。

## 真似するならまず実装する部分

まず、A を長さ LB の連結グループ列として作り、各グループを bitset で持つ。次に、グループ間に辺を張り、目的地を含むグループ間の DP でスコアを計算する部分を作るのがよい。

最初から差分更新や圧縮を入れる必要はない。固定グループ列で DP が正しく動くことを確認し、その後に「非関節点を隣接頂点に置換する山登り」を足す。スコアが見えたら、最後に A 圧縮と距離差分更新へ進む。

## 注意点・未理解点

- グループ間距離の差分更新は実装量が大きい。特に辺削除時の最短木部分木更新は、バグると DP スコアが壊れる。
- グループ内連結性を LowLink で保つ方針は強いが、グループサイズが小さいケースで削除可能頂点が少なくなり、近傍が細くなる可能性がある。
- A 圧縮の貪欲マッチングは記事とコードから概要は追えたが、どの重なりを優先するかの細部はチューニング依存が大きい。
- 記事中で参照されている最短距離差分更新の外部解説は補助資料であり、このメモでは soumat の提出コード内で使われた用途に限って整理した。
