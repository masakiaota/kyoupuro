## 解法の全体像

グラフの中央的な1頂点をターミナルに選び、各目的地や必要頂点をターミナルへ最短で結ぶ木を作る。A は、根から葉へのパスを並べたものとして構築する。LA に収まらない場合は、共通接頭辞を持つ類似パスを合体し、長さを節約する。

A が決まった後は、A の長さ LB 区間だけをコピーする操作を基本単位とし、取り得る B 状態間の遷移コストを BFS で求める。そのうえで、目的地列全体を DP で最適化する。LB 未満の部分コピーが明らかに得になる戻り道のような場合だけ、別途処理する。

## 主要アイデア

- 1つのターミナルを根にした木を作り、どの頂点へもターミナル経由で移動しやすくする。
- ターミナルから葉へのパスを A の基本部品にする。
- 共通接頭辞を持つパスを合体し、A の長さを節約する。
- パス合体は、節約できる共通長と、遅くなる到達頻度の比で貪欲に決める。
- A 区間を長さ LB 固定に制限すると、状態数は `LA - LB + 1` 個程度になり、BFS と DP で行動最適化できる。
- 部分コピーは状態爆発を避けるため全面的には扱わず、引き返しなど得になりやすいパターンだけを愚直に処理する。
- 複数回試行して最良解を採用する。

## 最終コードの構造

Browserで読んだ提出 #57404598 の実装構造である。記事本文のターミナル木、パス合体、A区間状態DPに対応している。

### 状態表現

- ターミナル頂点 `root`。
- `parent[v]`: root を根とする木での親。
- `paths`: 葉から root まで、または root から葉までのパス集合。
- `A`: 合体・連結後のパス列。
- `states`: A の各長さ LB 区間が作る B 状態。非連結成分を分ける必要がある場合は、下位互換状態を除いて有効状態のみ持つ。
- `dp[t][s]`: t 番目の目的地に到達した時点で状態 s にいるとき、残りを回るための最小コスト。
- 実装では `TimeManager`、`calc_best_center`、`merge_paths`、`calc_A_from_pairs`、`connected_area_breakdown` などの関数に分かれる。
- `calc_A_split` で `terminal` を区切りにAを分割し、長さ `lb` の窓ごとに連結成分を調べる。

### 観測・制約・入力の扱い

- 目的地の出現頻度をターミナル選定と木構築に使う。
- 行き先になる回数で重み付けしたターミナル距離総和が小さい頂点をターミナルにする。
- 不要な頂点、つまり目的地でも中継にもならない頂点は A に含めない。
- 木は、各頂点からターミナルまでの距離を悪化させない親辺を選ぶ。例外的に、1頂点の距離を少し伸ばす代わりに不要頂点を省けるなら採用する。

### 評価関数

- ターミナル選定では、目的地出現回数で重み付けした距離総和を小さくする。
- パス合体では、共通部分で節約できる長さ `x` と、非共通部分の遅延コストを比べる。記事では、共通でない長さや目的地出現回数から効率を見積もっている。
- A 決定後は、長さ LB 区間状態間の BFS 距離を使い、目的地列全体の信号操作回数を DP で最小化する。

### 探索・構築・更新

- まずターミナルを1つ選ぶ。
- 各頂点からターミナルへ近づく辺を1本選び、部分木を作る。
- 葉から根へのパスを抽出する。
- 共通接頭辞を持つパスを、節約効率の高い順に合体する。
- パス同士を連結して1本の A にする。ターミナルを挟む2パスは連続目的地を含むもの、ターミナルを挟まない2パスは互いに隣接するものを優先する。
- A の長さ LB 区間から状態グラフを作り、状態間 BFS と後ろ向き DP で信号操作を選ぶ。
- 提出コードでは `merge_paths(paths)` で共通接頭辞を持つパスを合体し、さらにペア順を焼きなまし風に入れ替えて `calc_A_from_pairs` でAを作る。
- `connected_area_breakdown(st)` が `A[st:st+lb]` の連結成分をUnion-Findで分解し、旅行DPの状態として使う。

### 操作・クエリ・出力選択

- 基本は、A の長さ LB 区間を B 全体へコピーし、その区間内で到達可能な頂点を移動する。
- 目的地に到達した後に元の道を戻るケースなど、LB 未満の部分コピーで明らかに得する場合だけ別処理する。
- DP で得た状態列から、信号操作と実移動を復元する想定である。

### 時間配分・パラメータ

- Python 実装では1周 800ms から 1800ms 程度と書かれており、全体を2から4回程度試して最良を採用している。
- ターミナル数は1または3も検討したが、最終的には1個にしたと脚注で述べている。
- 有効状態数は実験上 500 から 1000 程度、状態間辺は4万から40万程度と見積もっている。

## 実装上重要な断片

build_A():
    root = argmin weighted_distance_sum(root, targets)
    parent[v] = neighbor that keeps distance_to_root small
    paths = root_to_leaf_paths(parent)
    while total_length(paths) > LA:
        merge pair with best saved_length / delay_estimate
    A = connect_paths(paths)
```

solve_with_A(A):
    states = all length-LB windows of A
    state_graph = reachable transitions between states
    dist = BFS on state_graph
    dp from last target to first target
    restore operations
```

## この解法の本質

この解法は、都市間を直接最短路で結ぶのではなく、「どの目的地へも一度ターミナル網へ戻れば安く移動できる」という幹線構造を A に埋め込む。A を木の根から伸びる複数パスとして作ることで、連続した長さ LB 区間が移動可能なまとまりになりやすい。

また、A の構築と行動最適化を分けている点も重要である。A の作り方は木・パス合体の構築問題として扱い、A が決まった後は状態グラフと DP のアルゴリズム問題として解く。

## 真似するならまず実装する部分

最初は、目的地出現回数で重み付けした1ターミナルを選び、BFS 木から root-to-leaf パスを抽出して A に並べるだけでよい。次に、A の長さ LB 窓を状態として、目的地ごとに到達可能な状態へ DP する。

上位化するなら、パス合体の効率評価、パス連結順の焼きなまし、部分コピーの限定導入を足す。
