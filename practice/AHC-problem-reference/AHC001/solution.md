## 問題の本質

AHC001は、各希望点を含む非重複矩形を作り、その面積を要求面積に近づける問題である。高得点では、希望点を含まない広告を出す余裕はほぼない。したがって本質は「全点を確保したまま、限られた10000x10000の面積を全広告へなるべく均等に近い満足度で配る」ことである。

スコア式は、要求面積に少し届かなくても高い満足度を与える。一方で、1社だけを満点にして別の1社を極端に低くするより、複数社にほどほどの面積を配る方が得になりやすい。そのため、単純に空きを奪い合うのではなく、詰まった矩形を縮めて別の矩形を伸ばす遷移、または複数広告をまとめて作り直す遷移が重要になる。

## 共通している考え方

- まず全広告が希望点を含む正当な解を作る。
- 矩形は半開区間で持ち、点包含、正面積交差、盤面内判定を何度も使う。
- 個別スコアを持ち、変更された広告だけ差分計算する。
- `n <= 200` なので、最初は他広告との交差を愚直 `O(n)` で見ても十分に戦える。
- 拡大だけでは詰まるため、縮小、平行移動、押し潰し、破壊再構築のような「一度悪くする」遷移が必要である。
- 面積を完全に要求値へ合わせるより、全体の満足度を均すことを重視する。
- ビジュアライザで詰まり方を見て近傍を増やす発想が有効である。

## 解法の分類

- 貪欲・構築型: Mathenachiaの等分スライス、再帰分割、hakomofのgreedy初期解。
- 山登り型: hakomofのメイン近傍、Mathenachiaの局所破壊受理。
- 焼きなまし型: TERRY初心者、TERRY参加記、ARMERIA。
- 後処理改善型: TERRY参加記の仕上げ `grow`、Mathenachiaの伸長改善。
- 局所破壊型: TERRY参加記の2広告破壊、Mathenachiaの近い5個破壊、hakomofの9広告キック。
- 候補最適化型: hakomofの1広告最適化、TERRY参加記のヒストグラム最大矩形。

## 実装するならどのルートか

理解のための最小実装は、TERRY初心者ルートがよい。1x1初期解、`O(n)` 交差判定、個別スコア、1広告の拡大・平行移動・縮小、焼きなまし受理を作る。これで問題固有の制約とスコアの扱いを確認できる。

次の改善は、ARMERIAの押し潰し近傍またはMathenachiaの `max_delta` 伸長である。押し潰しは既存の1マス変更を拡張しやすく、`max_delta` は試行1回の質を上げやすい。

上位化の方向は2つある。1つはMathenachia型に、再帰分割で初期解を安定化し、近いK個を破壊して伸ばし直すルート。もう1つはTERRY参加記型に、2広告を壊して最大空き矩形として再構築するルートである。後者の方が強いが、実装難度も高い。

## 重要な実装要素

- 状態表現: `rect[i] = (x0, y0, x1, y1)` を半開区間で持つ。希望点 `(x_i, y_i)` は `x0 <= x_i < x1` かつ `y0 <= y_i < y1`。
- 評価関数: `s = area(rect[i])` とし、`1 - (1 - min(r_i, s) / max(r_i, s))^2` を個別スコアにする。
- 近傍: 最小は1辺拡大、平行移動、縮小。改善版では押し潰し、方向転換、`max_delta` 伸長、2広告破壊を足す。
- 差分更新: 1広告近傍なら対象広告だけ、押し潰しなら変更された複数広告だけ、2広告再構築なら2広告分だけ更新する。
- 候補管理: 最初は愚直でよい。上位化では近い広告リスト、座標圧縮、端点のソート済み構造、粗い区画ビットを検討する。
- 出力判定: 出力前に全矩形の正面積、盤面内、希望点包含、任意2矩形非交差を検査する。
- パラメータ: 時間、温度、変化幅、破壊個数、候補数はスコアに効く。序盤は粗く、終盤は小さく動かす設定が多い。

## 落とし穴

- 右端・上端を含む閉区間として扱うと、点包含や交差判定がずれる。
- 希望点を外した矩形は個別スコア0になり、高得点では致命的である。
- 面積が0の矩形、盤外矩形、正面積交差はWAになる。
- 拡大だけの山登りは、早い段階で矩形同士が接して動けなくなる。
- 面積を要求値に合わせすぎると空きがなくなり、後続の探索が動きにくくなる場合がある。
- 破壊近傍はロールバック漏れが起きやすい。矩形、スコア、補助データ構造をすべて戻す必要がある。
- 高速化データ構造を早く入れすぎると、候補生成の正しさより実装バグに時間を取られる。

## 未解決・要検証事項

- hakomof解法はコード非公開で、Browserで記事と `f.User=hakomof` などのAtCoder提出一覧を確認しても提出コードに辿れなかったため、greedy初期解、山登りの細部、実際の時間配分は推測が残る。
- TERRY参加記の疑似黄金分割探索は単峰性の保証がない。どのケースで外しやすいかは別途検証が必要である。
- 可変要求面積の倍率0.7は参照解法では有効だが、自分の近傍構成でも最適とは限らない。
- 近いK個破壊、2広告破壊、9広告キックのどれが実装コストに対して効くかは、同一コードベースで比較したい。
- 愚直 `O(n)` 判定から高速化へ移るタイミングは、実測で決めるべきである。
