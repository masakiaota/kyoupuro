## 解法の全体像

1x1矩形を初期解とし、焼きなましで少しずつ面積を増やす。近傍は3種類ある。基本は1広告を1マス伸ばす近傍で、たまに他広告を押し縮めながら伸ばす近傍を入れる。後半には、1広告をいったん1x1へ戻してランダムな方向優先順で伸ばせるだけ伸ばす近傍を加える。

コードはシンプルで、重なり判定は対象広告と他の全広告を愚直に見る。スコアは変更された広告だけ差分計算する。

## 主要アイデア

- 全広告が希望点を含むことが高得点の前提なので、初期解は各希望点の1x1矩形。
- 面積が希望面積を超えるとスコアが下がるため、通常の拡大では要求面積を超えないようにする。
- 近傍1は単純拡大。盤外、面積超過、重なりなら棄却する。
- 近傍2は押し潰し。対象広告を伸ばして他広告と重なったら、その相手を反対方向へ1マス縮める。相手が希望点を失うなら棄却する。
- 近傍3は方向転換。対象広告を1x1に戻し、ランダムな方向順に可能な限り伸ばして、縦横の伸び方を大きく変える。
- 焼きなましは悪化遷移も確率的に受理する。

## 最終コードの構造

### 状態表現

- `N, X[200], Y[200], R[200]`: 入力。
- `ans[i] = (a, b, c, d)`: 広告 `i` の矩形。
- `opt`: 現在スコア。
- `coef = 1e9 / N`: スコア倍率。
- `changed_idx`, `ans_bef`: 近傍2で複数広告を一時変更するときのロールバック用。
- 時刻管理用に `elapsed`, `t_start` を持つ。

### 観測・制約・入力の扱い

- `valid(a,b,c,d,idx)` で盤面内かつ希望点を含むか判定する。
- `cross` で2矩形の正面積交差を判定する。
- `check(idx)` は、対象広告について盤面、希望点、面積上限、他広告との非交差を確認する。
- 面積が0または `R[idx]` を超える矩形は通常不可として扱う。
- 近傍2では、押し縮められた広告も希望点を含むか確認し、失敗なら全変更を戻す。

### 評価関数

- `calc_area_rate(i)` は `1 - (1 - min(r, s) / max(r, s))^2` を返す。
- `calc_single_score(i)` は個別スコアに `coef` を掛けたもの。
- `calculate()` は全体スコアを合計するが、探索中は対象広告の差分を中心に使う。
- 温度は `T * (1 - elapsed / TIME_LIMIT)`。コードでは `T=3000`。

### 探索・構築・更新

- `change1(idx, D, diff)`:
  - `D=0,1,2,3` に応じて左、下、右、上の辺を動かす。
  - `diff=1` なら拡大、`diff=-1` なら逆操作になる。

- `try_update()`:
  - 近傍1。
  - ランダムな広告と方向を選び、1マス伸ばす。
  - 対象広告の差分スコアを計算する。
  - `check` に失敗したら戻す。
  - 焼きなまし確率で受理する。

- `try_update_force()`:
  - 近傍2。
  - 対象広告を1マス伸ばす。
  - 交差した広告を同じ軸の反対方向へ1マス縮める。
  - 変更された広告IDと旧矩形を保存し、失敗または不受理ならまとめてロールバックする。

- `try_change_direction()`:
  - 近傍3。
  - 対象広告を希望点の1x1矩形へ戻す。
  - 4方向の優先順をランダムに並べ替える。
  - 各方向について `8192, 4096, ..., 1` の二分的な幅を試し、可能なら伸ばす。
  - 焼きなまし確率で受理する。

### 操作・クエリ・出力選択

- メインループでは毎回 `try_update()` を呼ぶ。
- 10イテレーションごとに `try_update_force()` を呼ぶ。
- 制限時間の半分以降、1000イテレーションごとに `try_change_direction()` を呼ぶ。
- 時間切れまで回し、現在の `ans` を出力する。

### 時間配分・パラメータ

- `TIME_LIMIT = 4950` ミリ秒。
- 温度基準 `T=3000`。
- 近傍1は毎イテレーション。
- 近傍2は10イテレーションごと。
- 近傍3は後半のみ、1000イテレーションごと。
- 近傍3の伸長幅探索は `8192` から半減して1まで。

## 実装上重要な断片

```text
try_update:
    i, dir = random
    old_score = score(i)
    expand i by 1 in dir
    new_score = score(i)
    if invalid: rollback
    else accept by exp((new_total - opt) / temp)
```

```text
try_update_force:
    expand i by 1
    for each overlapped j:
        save j
        shrink j by 1 in opposite direction
        if j loses requested point: rollback all
    accept or rollback all by annealing
```

```text
try_change_direction:
    save rect_i
    reset rect_i to 1x1
    shuffle directions
    for dir in directions:
        for step in 8192,4096,...,1:
            try expand by step
            rollback that step if invalid
    accept or restore saved rect
```

## この解法の本質

この解法は、実装をかなりシンプルに保ったまま、近傍の役割を増やしている。単純拡大で空きを埋め、押し潰しで他広告から少し面積を譲ってもらい、方向転換で細長く固まった矩形を作り直す。TERRYの上位解のような大きな再構築はないが、局所探索の「動けなさ」を近傍2と近傍3で緩和している。

愚直 `O(n)` 判定を怖がらず、変更広告だけを差分評価することで、短いコードでも十分な試行回数を確保している点が実用的である。

## 真似するならまず実装する部分

まず近傍1だけの焼きなましを実装する。次に近傍2の押し潰しを入れると、単純に接触で止まる状態を少し崩せる。

近傍3は後から追加でよい。1広告をリセットして伸ばし直す処理は、既存の `check` と `change1` を再利用できるため、実装コストに対して改善が見込める。

## 注意点・未理解点

- `check_force` では交差相手を1マス縮めるだけなので、複雑な連鎖押し出しはしない。密集状態では失敗しやすい。
- 近傍2で複数広告を変更するため、ロールバック漏れがあると状態が壊れる。
- 面積を要求値以下に制限しているため、要求値を少し超えても他広告とのバランス上よい配置は探索しにくい。
- 温度スケールは `coef` を掛けたスコア差に合わせている。個別スコア0から1の実装とは温度値が大きく異なる。
- 記事では高速化をほとんどしていないと明記されており、上位化するには候補の質や破壊近傍を増やす必要がある。
