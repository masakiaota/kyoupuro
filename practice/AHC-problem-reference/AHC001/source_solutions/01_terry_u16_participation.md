## 解法の全体像

1マス広告を全社に置いたあと、まず単純な焼きなましで要求面積を0.7倍した小さめの初期解を作る。次に、隣接していそうな2広告を選んで一度壊し、2点を分ける境界線を探索しながら、それぞれの点を含む最大空き矩形を作り直す。この破壊再構築を乱数seedを変えて複数回走らせ、最良候補を選ぶ。最後に通常の拡大・縮小・平行移動焼きなましで仕上げる。

局所的な1辺変更だけでは、すでに詰まった矩形を少し縮めて別の矩形を大きくする遷移が通りにくい。そこで、2広告をまとめて壊して再配置する大きめの近傍を中心にしている。

## 主要アイデア

- 状態は広告ごとの整数座標矩形で持つ。各矩形は必ず希望点を含み、互いに正面積で重ならない。
- 通常近傍は1広告の拡大、縮小、平行移動。変化幅は時間とともに大きめから小さめへ落とす。
- メイン近傍は2広告破壊。2点を含む最小矩形が他広告と交差しなければ「隣接」とみなし、2広告だけを作り直す。
- 2広告の再構築では、縦または横に領域を切る境界を疑似黄金分割探索で選び、各側で点を含む最大矩形をヒストグラム最大長方形問題として解く。
- 焼きなまし中は要求面積を `0.7^(1-t)` 倍から1倍へ近づける。序盤は空きを作って動きやすくし、終盤に本来の面積へ寄せる。
- 破壊再構築は多点スタートし、`400 / n` 個の候補から最良を選ぶ。

## 最終コードの構造

### 状態表現

- `Request { row, col, area }`: 希望点と要求面積。90度回転した座標系用に `rotate_right` を持つ。
- `Advertisement { row0, col0, row1, col1 }`: 半開区間の矩形。交差判定、包含判定、面積、回転を持つ。
- `Input { count, requests, since }`: 入力と時刻。
- `Hist { width, height }`: ヒストグラム最大長方形用の列幅と高さ。
- `scores[i]`: 現在の各広告のスコア。
- `raw_set`, `rotated_set`, `raw_indice`, `rotated_indice`: 2広告再構築時のオンライン座標圧縮用データ。
- `bits[i]`: 通常焼きなましでの粗い5x5区画占有ビット。交差判定の前段フィルタに使う。

### 観測・制約・入力の扱い

- 入力点 `(x_i, y_i)` はそのまま整数セルの左下として扱い、初期矩形は `[x_i, x_i+1) x [y_i, y_i+1)` にする。
- 出力前に全矩形が希望点を含むこと、任意2矩形が交差しないことを `assert` で確認する。
- 通常近傍では盤外、空矩形、希望点を含まない遷移、他矩形と交差する遷移を棄却する。
- 縦横両方向を同じコードで扱うため、破壊再構築では矩形と要求点を90度回転した配列も保持する。

### 評価関数

- 個別スコアは問題文通り `1 - (1 - min(r, s) / max(r, s))^2`。
- `grow` では実スコアまたは0.7倍要求面積用スコアを使う。
- `break_and_reconstruct` では時刻 `t` に応じて要求面積を `size0^(1-t) * size1^t` 倍に更新し、その時点の目標面積に対するスコアで焼きなましする。
- 受理判定はスコア差 `diff` に対して、改善なら必ず受理、悪化なら `exp(diff / temp)` で受理する。

### 探索・構築・更新

- `grow`:
  - 1広告をランダムに選ぶ。
  - 12種類の遷移から選ぶ。4方向拡大、4方向平行移動、4方向縮小。
  - 変化量 `shift` は時間とともに概ね50から2へ小さくする。
  - 交差候補は粗い区画ビットで絞り、その後に厳密な矩形交差判定をする。
  - 差分スコアだけを更新し、最良状態を保存する。

- `break_and_reconstruct`:
  - ランダムに2広告を選ぶ。
  - 2つの希望点を含む最小矩形が他広告と交差するならスキップする。
  - 縦割りと横割りを半々で選ぶため、必要なら回転座標系で処理する。
  - 2点の列座標を座標圧縮集合へ一時挿入し、他広告の端点と合わせて圧縮する。
  - 境界行を決めるたびに、上側と下側それぞれの空き高さをヒストグラムに変換し、希望点を含む最大矩形をスタックで求める。
  - 境界行は疑似黄金分割探索で探索する。
  - 必要以上に横幅が大きい場合は、要求面積に近づく幅へ縮め、希望点を含むよう左右どちらかへ寄せる。
  - 2広告分のスコア差だけで受理判定し、座標圧縮集合と回転済み状態を差分更新する。

### 操作・クエリ・出力選択

- 最終出力は `grow` で仕上げた最良状態。
- 出力形式は各広告の `row0 col0 row1 col1`。
- 探索中の中間状態はビジュアライズ用に保存できるが、最終提出では無効化されている。

### 時間配分・パラメータ

- `SIZE0 = 0.7`, `SIZE1 = 1.0`。
- 初期 `grow`: 0.08秒相当、温度 `1e-2 -> 1e-3`。
- 破壊再構築: 候補数 `400 / n`、各候補に `4.0 / candidate_count` 秒相当、温度 `1e-1 -> 1e-3`。
- 仕上げ `grow`: 0.89秒相当、温度 `1e-2 -> 1e-5`。
- 通常近傍の変化幅は `50 -> 2` 程度へ減衰。

## 実装上重要な断片

```text
grow:
    pick i
    propose one of expand / shift / shrink
    reject if invalid, point not included, or intersects
    diff = score(new_i) - score(old_i)
    accept if diff >= 0 or rand < exp(diff / temp)
    update rect, score, occupancy bit
```

```text
break_pair:
    pick i, j
    reject unless bbox(point_i, point_j) is free from other ads
    choose normal or rotated coordinate
    insert both point columns into coordinate compression
    row = golden_section_search over rows between two points
    for each row:
        build upper/lower histograms from blocking ads
        choose max rectangle containing each point
        score two rectangles
    accept reconstructed pair by SA
```

```text
max_rectangle_with_center:
    adjust histogram heights so candidate interval must cover center
    compute nearest lower bar to left/right with monotone stack
    choose largest area interval whose height is enough and contains center
```

## この解法の本質

この問題は「ほぼ全員にそれなりの面積を配る」ことが重要で、局所的な拡大だけでは一度詰まった配置を解きほぐせない。TERRYの解法は、要求面積を小さくした状態で空きを作り、2広告単位の破壊再構築で詰まりをほどき、最後に小さい近傍で整えるという段階設計が本質である。

また、2広告の再配置を単なる乱択にせず、残りの広告を障害物と見た「点を含む最大空き矩形」へ落としている。大きな近傍を入れても候補の質を保つことができるため、焼きなましの試行回数を有効に使えている。

## 真似するならまず実装する部分

最初に作るべきなのは、`grow` 相当の1広告拡大・縮小・平行移動焼きなましである。これだけで妥当なスコアと検証基盤が得られる。

次に、2広告を選んでその2つだけを一度1マスに戻し、交互に伸ばす簡易破壊近傍を入れるとよい。TERRY版のヒストグラム最大矩形、オンライン座圧、疑似黄金分割探索まで一気に再現する必要はない。簡易版で破壊近傍の効果を確認してから、点を含む最大矩形探索へ進めるのが現実的である。

## 注意点・未理解点

- 疑似黄金分割探索は記事中でも「嘘解法」とされている。評価関数が単峰とは限らないため、必ず最適境界を見つける保証はない。
- 破壊再構築中のスコア管理は要求面積が時間で変わるため、定期的な全再計算と差分更新の整合に注意が必要である。
- 座標系の回転、半開区間、`row/col` と出力の `x/y` の対応を混同するとWAになりやすい。
- 2広告の再構築は実装量が大きい。オンライン座圧や固定長配列化は高速化に効く一方、デバッグ難度も上がる。
- 記事では粗いビット管理単独の改善は微妙だったと述べているが、最終コードの通常焼きなましでは交差判定前のフィルタとして使われていた。
