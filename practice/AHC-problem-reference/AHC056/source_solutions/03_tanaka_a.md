## 解法の全体像

固定盤面パターンを先に作り、そのパターン上で経路を探索し、最後に遷移規則を詰め込む方針である。盤面を「可変マス」と「固定マス」に分け、固定マスでは方向ごとに決まった規則を使い回す。最終形は、市松模様から可変マスをさらに間引いた基本パターンに近い。

経路探索では、固定マスの移動規則を利用できるように経路を作る。規則構築では、当初は `(c,q)` を順に割り振っていたが、後半で色 `c` の決定を遅延させ、再利用できる規則を増やして大きく改善している。

## 主要アイデア

- 単純な `C x Q` 詰め込みで団子解に到達する。
- 4つの色に方向を割り当て、盤面の一部へ固定経路を埋め込む。
- 幅2領域の巡回のような固定経路は、常に同じ規則で進められるため効率が良い。
- 市松模様よりさらに可変マスを減らす基本パターンを構築する。
- 壁付近や幅1通路では到達不能を避けながら可変マスを減らす。
- 規則割当では、`c` の決定を必要になるまで遅延して、同じ規則へ合流できる余地を残す。
- `K` が小さいケースでは別の序盤貪欲の方が強いことがあり、複数方針を走らせて良い方を採用する。

  - `C` を固定した割当
  - 未確定色を持つキー
  - 各 `q` に対して利用済みの `c`

### 探索・構築・更新

- 初期:
  - 目的地ごとに異なる状態、マスごとに異なる色を割り当てる単純解。
  - 通らないマスには色を割り当てない。
- 団子解:
  - 経路ステップを `C x Q` に順に詰める。
  - 同一規則の再利用、方向ごとの4ルール、`C` 全探索で改善する。
- 固定パターン:
  - 方向色を使った固定経路を盤面へ埋める。
  - 市松模様から可変マスをさらに間引く。
  - 壁付近は可変マスを残すか、市松模様に戻す。
  - 幅1通路や2マス先全方向に可変マスがある箇所を色0固定にする。
- 規則割当:
  - `C` を決めた状態で割り当てる。
  - 1つの `q` で使えるキー数は `C-2` 個までとし、超えたら新しい `q` を使う。
  - 規則再利用時、両方の色が未確定なら本来は未確定のままにしたいが、後で値を割り当てられないケースを避けるため、その場で具体色を割り当てる場合がある。

### 操作・クエリ・出力選択

- 初期盤面には、固定マスの方向色と、可変マス用に決まった色を出力する。
- 固定マスでは、方向に対応する状態/色の組で同じ移動を繰り返す。
- 可変マスでは、経路の訪問順に応じて次状態・塗り替え色・移動方向を割り当てる。
- 複数規則が再利用できる場合は、将来の再利用性を下げにくいものを優先する。
- `K` が小さい場合は、固定パターン解と序盤貪欲解の両方を評価し、良い方を出力する。

### 時間配分・パラメータ

- `C` の値、パターン配置の起点、色1の回転方向の逆向きなどを全探索している。
- 終盤は乱数要素を入れて時間いっぱい回す。
- 盤面パターンの調整は、幅1通路、中央付近の可変マス、2マス先固定ルートなど、手作業に近いルールベース改善である。

## この解法の本質

この解法の本質は、探索で毎ケース自由な氷床配置を作るのではなく、強い固定盤面パターンを作り込んで、その上で規則を詰める点である。固定パターンは実装が比較的制御しやすく、ベルトコンベア的な長い再利用区間を作りやすい。

一方で、固定パターンの強さは壁や目的地密度に左右される。記事では目的地密度が高いケースに強く、低いケースに弱い傾向が述べられている。これは、固定パターン上を多く通るほど規則再利用の恩恵が大きくなるためだと考えられる。

## 真似するならまず実装する部分

まずは団子解を実装し、`C` を全探索して `C x Q` へステップを詰める。次に、4方向固定色を持つ市松模様パターンを作り、固定色で進めるステップを共通規則にする。

上位化を狙うなら、可変マスの削減パターン、壁付近の修復、色 `c` の遅延決定を順に入れるとよい。

## 実装確認（raboT 提出 71035997）

キャッシュ実装は Java で、`K < 20` のときだけ `Solver1` の単純経路圧縮も試し、その後 `Solver4` が主解を作る。`Solver1` は各目的地間の最短路を逆順にたどってステップ列を作り、`C ≈ sqrt(route.size())` 周辺を探索して絶対規則 `AbsRule` に詰める。

`Solver4` は固定盤面パターンを `LayoutCreator` で複数作る。主パターンは市松に近い2色固定/可変配置で、壁端、壁の先端、長い廊下、中央付近の例外をルールで補正する。`RouteCreator` は `LayoutSet` 上でDijkstra風に `FreeStep` を伸ばし、目的地残数、歩数、可変マス通過数、規則再利用ペナルティで比較する。

規則割当は `RuleAssigner` が後ろから行う。`RuleGroupManager`、`LzKey`、`LzRule` により、次状態と方向から同じ規則へ合流できる場合は再利用し、必要なら状態 `Q` と色 `C` を増やす。出力は `C Q M`、初期色盤面、遷移規則列である。tanaka-a記事の「固定パターン + 色遅延」方針には近いが、提出者不一致のため同一コードとは扱わない。
