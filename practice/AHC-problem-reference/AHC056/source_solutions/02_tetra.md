## 解法の全体像

パス構築と規則構築を分ける。まず色0を直進専用の氷床として使い、最後の方向転換後は同じ色・同じ状態で直進できるような経路を作る。各マスで「最後に方向転換する訪問」をなるべく早く終わらせれば、その後の訪問は色0の共通規則に吸収できる。

経路は、拡張ダイクストラで初期解を作り、目的地列の一部区間を破壊再構築する山登りで改善する。規則構築は、色0で処理できる直進ステップを削除した残りのパスを後ろから見て、差分更新ビームサーチで `(c,q)` を割り当てる。状態 `S` に対して移動方向 `D` を固定し、同じ `(A,S)` を使い回しやすくしている。

## 主要アイデア

- 色0を氷床とし、規則 `(0,q) -> (0,q,D_q)` で直進を表す。
- 色0にしたマスは後から色を戻せないため、そのマスの最後の方向転換以降だけを色0直進にする。
- 経路コストは「各マスの最後の方向転換が何回目の訪問か」の総和を中心にする。
- 目的地から遠ざかる回数を状態に持つ拡張ダイクストラで、`T` の余裕を使いながら規則再利用しやすい経路を作る。
- 規則は後ろから決める。遷移先 `(A,S,D)` が分かっている状態で、遷移元 `(c,q)` を選ぶ。
- ビーム評価は `C+Q` を主にしつつ、`C` と `Q` のバランス、確定色ルール数を探索途中の補助項にする。
- thunder の差分更新ビームサーチライブラリを Hash なしで利用する。

## 最終コードの構造

最終提出コードは 404 で読めていない。以下は記事本文と、使用されたライブラリの構造から整理した実装構造である。

### 状態表現

- 経路構築:
  - 壁つきグリッド
  - 目的地列
  - 区間ごとのパス
  - 各マスの訪問回数
  - 各マスについて、最後に方向転換した区間、最後に直進した区間
  - 現在位置、現在方向、目的地から遠ざかった回数
- 規則構築:
  - 簡約後のパス。色0直進で処理できるステップを除いた列
  - 各マスの色。色0または未確定/確定色
  - 規則集合 `(c,q) -> (A,S,D)`
  - 使用中の色数 `C` と状態数 `Q`
  - `S` ごとに固定された方向 `D_S`
  - 色が確定したルール数 `R`
  - ビーム復元用のAction

### 観測・制約・入力の扱い

- 盤面の壁を使って隣接移動可能性を構築する。
- 目的地間の最短距離を基準に、全体の `T` 余裕を各区間へ配る。
- 拡張ダイクストラでは、目的地から遠ざかる移動回数を上限付きで管理する。
- 同じマス・同じ方向で、遠回り回数が少なくコストも小さい状態が既にあれば探索を打ち切る。
- `T` を超える経路は採用できないため、破壊再構築時にも全体ステップ数制約を満たす必要がある。

### 評価関数

経路構築のコストは次を組み合わせる。

- 各マスで最後に方向転換するのが何回目の訪問か。
- 最後の方向転換後に直進しないマスは、色遷移の自由度が高く規則を再利用しやすいため、コストから引く。

規則構築のビーム評価は記事中に式がある。要約すると:

```text
score = (C + Q)
      + (a * |C - Q|^x + b * R^y) * decay(t, L)
```

- `R`: 色が確定したルール数
- `t`: 探索深さ
- `L`: 簡約後パス長
- 記事中のパラメータは `a=8.0, b=4.0, x=1.6, y=0.8, z=1.2`
- 終端では補助項が0になるよう、探索序盤だけバランスと未確定度を誘導する。

### 探索・構築・更新

- パス初期解:
  - 拡張ダイクストラで目的地間をつなぐ。
  - 状態は現在方向と、目的地から遠ざかる移動回数を含む。
  - A*風の優先度、Radix Heap、支配判定で高速化する。
- パス改善:
  - 目的地列の一部区間を壊して再構築する山登り。
  - 各区間までの訪問回数や最後の方向転換/直進区間を記録し、スコアを差分計算する。
- 規則ビーム:
  - 初期状態は `C=1`, `Q=4`。色0が氷床、4状態が方向に対応する。
  - 各ステップで候補を列挙する:
    - 既存規則と同じ `(A,S)` を使う。
    - 未確定色を確定して既存規則を使う。
    - 未使用 `(c,q)` で新規規則を作る。
    - 色または状態を増やして新規規則を作る。
  - 新規規則候補は似た状態が多いため、候補数をランダムに絞る。
  - thunder ライブラリの `move_forward` / `move_backward` により状態を差分更新する想定である。

### 操作・クエリ・出力選択

- 色0直進にできるマスは初期色0にする。
- 色0以外はビームで確定した色を出力する。
- 規則は、実際に遭遇する `(c,q)` だけを出力する。
- 色0直進ステップでは状態を維持し、`D_q` 方向へ進む。
- 簡約パスのステップでは、後ろから割り当てた規則により、次に必要な色 `A` と状態 `S` を書き込む。

### 時間配分・パラメータ

- Radix Heap は yosupo の記事を参考に pair 型対応へ改造したと記述されている。
- ビームサーチのパラメータは記事本文に幅などの具体値はない。
- 評価関数パラメータは Optuna で調整。
- thunder ライブラリ使用時は `return_finished_immediately = true` と `max_turn` を設定し、終了判定を常に false にする運用がTLE回避に効いたと書かれている。
- ハッシュ重複除去は使っていない。規則割当の順序違いで同一状態がほぼ生じないという判断である。

```text
build_segment_path(a, b, budget):
    state = (cell, direction, away_count)

    edge cost reflects:
        last-turn index increase

```

```text
beam_from_back(reduced_path):
    initialize C = 1, Q = 4
    for step from last to first:
        try reuse existing (A, S)
        try fix an undecided color and reuse
        sample unused (c, q) for a new rule
        sample add-color / add-state transitions
        score by C+Q plus decaying penalties
```

```text
Action for differential beam:
    remember changed color assignments
    remember added rule or added color/state
    move_forward(action)
    move_backward(action)
```

## この解法の本質

この解法は、色0を「以後ずっと直進できるメモリ」にすることで、位置依存の長いパスを少数の共通規則に変換している。重要なのは、氷床化の判断を単なるセル固定ではなく「最後の方向転換」という時間軸のイベントで見る点である。

また、後ろから規則を決めると、次に必要な色と状態が既知になる。これにより、遷移元 `(c,q)` の選択問題として圧縮でき、ビームサーチが自然に使える。

## 真似するならまず実装する部分

最小実装は、色0直進と後ろからの貪欲割当でよい。まず通常の最短路を作り、各マスの最後の方向転換後だけ色0にする。次に、色0で処理できないステップを後ろから `C` 固定または `Q` 固定で貪欲に詰める。

その後、拡張ダイクストラでパスコストを改善し、最後に規則割当をビームサーチ化するのが実装しやすい。
