## 解法の全体像

最短経路をそのまま規則化するのではなく、方向転換が必要なセルと滑走するセルを分ける。まず目的地列を訪問する経路を計算し、後ろからたどって、方向転換が不要なセルは色0の滑走セルとみなして色変換を行わない。これにより、個別に規則を割り当てる必要があるセルを減らす。

経路計算では、単に最小ステップ数を求めるのではなく、`T` に余裕があるときは遠回りを許し、位置変更回数、つまり方向転換セルの削減を優先する。最後に、使い回せる状態関数をできるだけ再利用する。

## 主要アイデア

- 色0を滑走セルとして扱い、方向転換セルだけに個別規則を割り当てる。
- 経路DPの評価を「最小ステップ数」から「最小位置変更回数」に変える。
- `T` が最短距離より大きいケースでは、遠回りしてもよいので規則数を減らす経路を選ぶ。
- 経路を後ろから見て、方向転換不要なセルを色0に落とす。
- 経路から状態関数へ変換するとき、再利用できる状態はできるだけ再利用する。
- 初期解をルールベースで作り、盤面パターンを多様化・チューニングして改善する。

## 実装上重要な断片

```text
route_dp:
    for each target index k:
        for each current cell:
            relax moves
            cost = direction_change_or_position_change_cost
            keep route only if total steps <= T
```

```text
postprocess_from_back(path):
    for step from last to first:
        if this cell no longer needs direction change:
            mark color 0
        else:
            keep as switch cell
```

## この解法の本質

この解法の本質は、`T` の余裕を「距離短縮」ではなく「規則数削減」に使う点である。AHC056では全目的地を訪問できれば実際のステップ数はスコアに直接入らず、`C+Q` がスコアになる。そのため、多少遠回りしても方向転換セルを減らせるなら得になる。

また、経路を後ろから見ることで、そのセルの以後の挙動が固定されるタイミングを検出できる。これは公式解説や tetra の氷床方針にも通じる考え方である。

## 真似するならまず実装する部分

まず通常の最短経路DPを作り、次に評価値を「曲がる回数」へ変える。経路復元後、後ろから見て直進だけで済むセルを色0へ落とす処理を作る。状態関数の再利用は、最初は同一 `(A,S,D)` の完全一致だけでよい。

## 実装確認（提出 71035891）

キャッシュ実装は C++ で、盤面上の「スイッチ」集合を先に作り、スイッチから1方向へ出て、次のスイッチまで直進する辺 `SwitchEdge` のグラフを構築する。スイッチ集合は斜め縞、三角波、既存候補の追加・削除・移動・行列再構成で生成し、各行各列にスイッチがある制約を保つ。

経路探索は `SwitchGraphMinTurns` と `SwitchGraphMinEdges` の2種類で、目的地indexを含む状態上の最短路を探す。`T/X` が小さいとターン数最小寄り、大きいと辺数最小寄りに確率を寄せる。探索では各目的地からの距離とsuffix距離で下界枝刈りを行い、`SwitchEdgePostprocessor` が往復のような連続辺を後ろからマージする。

規則生成は `EdgeProcessor` が後ろから行う。ダミー辺を先頭に足し、辺列上の同一スイッチ再訪情報を使って色bucketを割り当て、`C` を `sqrt(edges)` 付近から上下に試し、`C+Q` が良いものを選ぶ。全体は1.92秒まで候補生成を続け、終盤0.35秒で未詳細評価候補を遷移規則へ変換する。
