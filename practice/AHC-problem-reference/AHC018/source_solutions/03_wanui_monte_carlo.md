## 解法の全体像

斜め格子上に代表点を置き、代表点グラフ上で経路候補を扱う。まず試し掘りフェーズで、有力な代表点だけを選んで上限付きで掘る。有力性は、硬さをランダムに割り当てたモンテカルロシミュレーションを何度も行い、最短路に現れやすい代表点ほど重要とみなして決める。

開通済み代表点だけで全ての家を水源へつなげられるようになったら、試し掘りを終了する。その後、代表点間の経路を決定し、代表点の隙間を順に掘る。隙間セルのパワーは、近くの開通済みセルから硬さ範囲を推定し、期待値DPで決める。

## 主要アイデア

- 試し掘りと本掘りを分離し、十分な代表点情報を得てから経路を確定する。
- 代表点の硬さは `[下限, 上限]` の区間として扱う。
- 期待値DPにより、硬さ区間が一様だと仮定したときの掘削パワー列を求める。
- モンテカルロで「最短路に乗りやすい代表点」を数え、試し掘り対象を選ぶ。
- 未試行の代表点には選択回数の下駄を履かせ、情報の偏りを避ける。
- 代表点を必ず破壊するのではなく、合計パワー上限付きで試し掘りする。
- 経路確定時は、開通済み代表点を安く、未開通代表点を非常に高く評価する。

## 最終コードの構造

Browserで AtCoder 提出 `39276723` を読んだ。以下は記事本文と提出コードから確認できた実装構造である。

### 状態表現

- `pws`, `phs`: 水源、家の座標。
- `ps`: 水源、家、斜め格子点を含む代表点列。
- `es`, `g`, `grev`: 代表点グラフと逆辺。
- `history_t`: 代表点やセルの掘削履歴。累積パワー、破壊済みかどうか、最後の結果を持つ。
- `srange_t`: 硬さ区間 `[lower, upper]` を表す。
- `opened`: 開通済み代表点集合。
- `sturdiness_range`: 代表点またはセルの硬さ区間。
- `powers`, `dp`: 期待値DPで求めた掘削パワー表。

### 観測・制約・入力の扱い

- `request` が出力と入力受信を担当し、結果に応じて `history_t` と硬さ区間を更新する。
- 未破壊で終わった掘削により、硬さ下限は「累積パワー + 1」になる。
- 破壊できた掘削により、硬さ上限は「累積パワー」になる。
- 試し掘りは代表点ごとに合計パワー上限を持つ。
- 初回・2回目・3回目以降で合計パワー上限を変え、硬い点への深入りを避ける。

### 評価関数

- 期待値DPでは、残り硬さ上限を `T` として `dp[T]` を最小期待消費にする。
- パワー `p` を選んだとき、壊れる確率を `p/T`、壊れない確率を `1-p/T` と近似する。
- モンテカルロでは各代表点の硬さを区間から乱択し、辺コストを「両端代表点のコスト平均 × 辺長」とする。
- 硬さ乱択は一様ではなく、低い値が出やすいように `lo^(1/P)` から `hi^(1/P)` で乱択してから P 乗する。

### 探索・構築・更新

- `greedy` が、ランダムな辺コストで各家から水源側への経路を貪欲に求める。
- 家1を水源へつなぎ、以後は既に求めた経路上の点も水源扱いにしてダイクストラを繰り返す。
- 経路上に現れた代表点の選択回数を増やす。
- 100回程度のシミュレーション後、選択回数最大の未開通代表点を試し掘りする。
- `must_open`、`must_open_mid`、`check_limit` で、開通済み代表点だけで全家が接続可能か、追加で掘るべき代表点があるかを判定する。

### 操作・クエリ・出力選択

- 試し掘り対象は、モンテカルロ上の出現頻度が高い代表点。
- 試し掘りのパワーは、上限付き硬さ区間に対する期待値DPで決める。
- 本掘りでは、代表点ペア間を片方に近い側から順に開通させる。
- 隙間セルの推定は近くの開通済み点から行い、推定下限・上限を使ってパワーを決める。

### 時間配分・パラメータ

- 格子の縦横間隔は17、斜めは8または9の間隔が出る。
- モンテカルロは1回の試し掘り対象決定につき約100回。
- 試し掘り上限は、初回44、2回目170、3回目以降300程度。
- 経路確定可能後も最大20回ほど追加で試し掘りする。
- 隙間セルの初回パワーは推定上限寄り、以後は期待値DPを使う。

```text
expected_power_table(C):
    dp[0] = 0
    for T in 1..MAX:
        dp[T] = min over p:
            p/T * (p + C) + (1 - p/T) * (p + C + dp[T-p])
```

## この解法の本質

代表点を「どれだけ有望か」で選ぶために、現時点の不確かな硬さから何度も仮想的な世界を作り、その世界でよく使われる点を調べる点が本質である。単に推定平均が低い点を掘るのではなく、経路選択に影響しやすい点を掘るので、試し掘りの情報効率が高い。

また、試し掘りフェーズと経路開通フェーズを分けることで、途中で早く経路を固定してしまうリスクを抑えている。経路候補の多様性を残したまま情報を増やす設計である。

## 真似するならまず実装する部分

まず、斜め格子の代表点グラフ、各代表点の `[lo,hi]`、代表点上のダイクストラを作る。次に、簡略版として「ランダム硬さを数十回割り当て、経路に出た回数が多い点を掘る」処理を入れる。

期待値DPと隙間セル推定は後からでもよいが、本掘りのパワー効率に大きく効くため、固定パワーから始めて早めにDPへ置き換えるのがよい。
