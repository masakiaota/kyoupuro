## 解法の全体像

真の硬さが分かるテストデータで理想経路を観察し、低い地形を通る経路が重要であることを確認する。そのうえで、実際のインタラクティブ解では、各セルの硬さを最小値・最大値の区間として管理し、対数空間の分位点のような式で推定値を更新する。

全セルを自由に使うと計算も掘削も重くなるため、通行可能な場所を格子状の通路に制限する。格子点、水源、家を結ぶ候補グラフを使い、推定コストに基づいてダイクストラと最小全域木を組み合わせたルート探索を毎ターン実行する。最終経路の格子点間は線形補間で硬さを見積もって掘る。

## 主要アイデア

- 真の硬さが分かるオフラインデータで「理想に近い経路」を作り、問題の構造を観察する。
- 硬さはケースごとに大きく違うが、対数比で見ると分位の位置が安定するという統計を使う。
- 掘削結果から各セルの `MIN`, `MAX` を更新し、`exp((1-p0)lnMIN + p0 lnMAX)` で推定する。
- 局所的・大域的な盤面平滑化推定は行わず、格子点間の最終線形補間だけを使う。
- 200x200全体ではなく格子上に制限し、計算量と無駄掘りを減らす。
- 水源同士を UnionFind で最初から連結扱いにし、水源を全部つなぐ必要をなくす。
- 相対スコアと C 別 Optuna チューニングを重視する。

## 最終コードの構造

Browserで AtCoder 提出 `39277012` を読んだ。以下は本文と提出コードから確認できた実装構造である。

### 状態表現

- `Env`: 入出力、掘削回数、総消費、破壊済みセル、岩盤推定を管理する。
- `Agent`: グリッド構築、経路計算、掘削対象選択を持つ。
- `rock_min`, `rock_max`, `rock_pred`: 各セルまたは格子点の硬さ下限・上限・推定値。
- `houses`, `waters`, `grid`: 家、水源、格子点からなる候補点集合。
- `UnionFind`: 水源側の連結成分や経路構築で使う。
- `best_path`, `dig_queue`: 現在選んだ経路と次に掘るセル列。

### 観測・制約・入力の扱い

- `Env::dig` が出力と入力受信を担当する。
- 未破壊なら、累積掘削量 + 1 が硬さの最小値になる。
- 破壊済みなら、累積掘削量が硬さの最大値になる。
- `update_rock_pred` が `rock_min`, `rock_max` から推定値を更新する。
- 水源・家は問題生成上薄い傾向があるが、全体傾向の推定にはあまり使えないと判断している。

### 評価関数

- 真の硬さが分かる理想解では、セルの破壊に `硬さ + C` がかかるとして経路コストにする。
- 実解では、推定硬さ `pred` と `C` から候補辺・候補経路のコストを評価する。
- 対数空間の推定式は以下の形である。

```text
pred = exp((1 - p0) * ln(MIN) + p0 * ln(MAX))
```

- `p0` はハイパーパラメータで、水源・家かどうかでも変える。

### 探索・構築・更新

- 硬さ既知の分析では、水源・家間をダイクストラで結び、MST を作る。
- `create_grid` で格子点を作り、格子状の通路だけを通行可能にして、ダイクストラと MST を毎ターン回す。
- 水源同士は最初に UnionFind で接続しておくため、余分な水源を経由しなくてもよい。
- `compute_grid_path` で候補グラフ上の経路を選ぶ。
- 最終経路の格子点間は `interpolate_grid` でセル列に展開して掘る。

### 操作・クエリ・出力選択

- 推定コストで現在最も良さそうなルートを選ぶ。
- 選んだ経路上の掘削により `MIN`, `MAX`, `pred` を更新し、次ターンのルート探索に反映する。
- 無駄な調査掘削はほとんど行わず、経路に使う可能性がある場所を掘りながら更新する。

### 時間配分・パラメータ

- 格子点の step は最終的に9が良かったとされる。
- パラメータはコマンドライン引数から変えられるようにし、Optuna で探索する。
- チューニングは絶対スコアではなく、Myベスト基準の相対スコアで行う。
- C の値ごとに別々にチューニングするのが重要。
- C=1 は掘削回数が増えやすく時間が厳しいため、ダイクストラ更新頻度を落とすなどの妥協を入れている。

## 実装上重要な断片

```text
update_cell(cell, total_power, broken):
    if broken:
        MAX[cell] = min(MAX[cell], total_power)
    else:
        MIN[cell] = max(MIN[cell], total_power + 1)
    pred[cell] = exp((1 - p0) * ln(MIN[cell]) + p0 * ln(MAX[cell]))
```

## この解法の本質

この解法の本質は、複雑な推定器よりも「問題を格子上の安定した経路探索へ落とす」ことにある。盤面の局所平滑化を頑張りすぎず、観測で確定した区間と対数分位の統計だけで推定する。その代わり、経路探索は毎ターン丁寧にやり直して、掘削で得た情報を即座にルートへ反映する。

また、理想解分析から始めている点が重要である。真の硬さが分かると何をすべきかを先に確認してから、未知情報下でそれに近づける構造を作っている。

## 真似するならまず実装する部分

まず、格子点・水源・家だけを候補にし、推定硬さを辺コストにしてダイクストラと MST で経路を作る部分を実装する。硬さ推定は最初は `MIN=10, MAX=5000` からの対数中央値でよい。

次に、掘削のたびに `MIN/MAX/pred` を更新し、経路を再計算する。Optuna や C 別調整は、ローカル評価が安定してから入れる。

## 注意点・未理解点

- 記事中に最終 Rust コードはないが、AtCoder 提出 `39277012` のソースは読めた。ただし System Test は WA である。
- Optuna の探索範囲や具体的な最終パラメータは本文だけでは不足している。
- 局所的な盤面推定を捨てる判断は実装を軽くするが、上位のガウス過程系・モンテカルロ系との差分にもなりうる。
- C=1 の時間対策はスコアとのトレードオフが大きい。
