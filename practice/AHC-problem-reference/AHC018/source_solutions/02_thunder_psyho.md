## 解法の全体像

水源、家、固定された斜め格子点を頂点にした粗いグラフを作る。辺コストは、両端のセルについてこれまでの掘削履歴から推定した硬さとマンハッタン距離で決める。現在水が流れているセルまたは水源から、未接続の家へ向かう最短路をダイクストラで求め、その経路上の未破壊の代表点を少しずつ掘る。

経路上の代表点がすべて破壊済みになったら、その代表点列を実際の隣接セル列へ展開し、1セルずつ順番に掘って水路を作る。このとき直前に掘ったセルの硬さ情報から次セルのパワーを決める。複雑な盤面推定はせず、格子点の選び方、辺コスト式、パワー式、C 別パラメータを徹底的に調整している。

## 主要アイデア

- 盤面全体を推定せず、通る可能性が高い粗い格子グラフだけを調査する。
- 格子は縦横18、斜め9+9の辺を持つ斜めグラフにし、斜め方向も自然に候補へ入れる。
- 各セルについて `dig_lo`, `dig_hi`, `dig_last`, `extracted` を持ち、破壊済み・未破壊で別のコスト推定式を使う。
- 最短路上の未破壊代表点を掘り、硬いと分かったら次回の最短路から避けられるようにする。
- 代表点が全部破壊済みになってから、実際の細かい経路を順次掘る。
- 連続セルの硬さが似ることを利用し、前セルの硬さ範囲から次セルの掘削パワーを決める。
- 性能差の大部分は C ごとのマジックナンバー最適化に依存している。

## 最終コードの構造

Browserで AtCoder 提出 `39276503` を読み、原文 GitHub の実装説明と照合した。以下は提出コードで確認できた構造を中心にした整理である。

### 状態表現

- `VW`, `VH`: 水源、家の座標。
- `extracted[r][c]`: セルが破壊済みか。
- `good[r][c]`: 実際の水路として使う、または水が流れている扱いのセル。
- `dig_lo[r][c]`: 硬さの下限。未破壊なら「これまでの累積 + 1」。
- `dig_hi[r][c]`: これまで入れた累積パワー。破壊時は硬さ上限。
- `dig_last[r][c]`: そのセルへ最後に入れたパワー。
- `vmap`, `vv`, `vs`, `ve`: 代表点グラフ。`vs` は代表点から最寄りの水源・水路側セルを別扱いで保持する。

### 観測・制約・入力の扱い

- `dig(r,c,v)` が出力と入力受信を担当する。
- 掘るたびに `dig_lo = dig_hi + 1`、`dig_hi += v` として硬さ区間を更新する。
- 結果が破壊なら `extracted=1` とし、下限を少なくとも10にする。
- `rv == 2` なら `dig_done` を立てて以後終了扱いにする。
- `CLEV` は `C=2^CLEV` の指数で、ほぼ全パラメータの添字になる。

### 評価関数

- `edge_cost` は両端点の推定硬さと距離から辺コストを作る。
- 破壊済み点の見込み値はおおむね `(lo + hi) / 2 + 小補正`。
- 未破壊点の見込み値は、C 別の基礎値と `dig_hi` を使う非線形な式で「少し掘ったがまだ壊れていない点」を高めに評価する。
- 辺コストは距離部分、未破壊端点にかかる `C`、方向補正を足して作る。
- `find_best_power(lo, hi)` は、推定硬さ `exp=(lo+hi)/2` に対して、`ceil(exp/p)*C + p/2*係数` が小さい `p` を選ぶ。

### 探索・構築・更新

- `build_graph(GRID_SIZE=18, houses_left)` で斜め格子グラフを作る。
- 各格子点は縦横18、斜め9+9の近傍とつながる。
- 家は近い格子点へ辺を追加する。
- 水源または既に良い水路セルへは、各代表点から最も安い接続先を `vs` に保存する。
- `find_path(houses_left)` は `vs` を起点にした多始点ダイクストラで未接続家への最短路を返す。
- 経路中に未破壊代表点があれば、まだ掘り込みが浅い点を選んで試し掘りする。
- 経路中の代表点がすべて破壊済みなら、実際の隣接セル列へ展開して順に掘る。

### 操作・クエリ・出力選択

- 最初に全ての家セルを破壊して、家自体の硬さ情報を得る。
- 試し掘りは `SCAN_START`, `SCAN_POW`, `SCAND_POW` など C 別パラメータでパワーを上げる。
- 実際の水路掘削では、最初のセルは `2C+30` 付近、以後は前セルの硬さ範囲から `find_best_power` で決める。
- 斜めの代表点間を実セル列に展開するとき、2つのL字経路や中点を軽く試して、どちらの向きで曲がるかを選ぶ。
- 掘ったセルの隣接破壊済みセルから `dig_lo`, `dig_hi` を補正する。

### 時間配分・パラメータ

- 原著によると、10,000ケース単位のローカル実験を大量に回し、C 別にパラメータを合わせている。
- `GRID_SIZE=18`、C 別 `UNKNOWN_DIG_COST`、`SCAN_START`、`V_WASTE_MUL`、`LAST_V_MUL`、`ADJUST_RATIO` などが重要。
- 原著の ablation では、単純化した辺コスト、C 別調整なし、順次掘削を外した版が明確に弱くなる。
- 最終版は19番目提出の簡潔版より約3%強いが、マジックナンバーと小技が増える。

```text
find_best_power(lo, hi):
    exp = (lo + hi) / 2
    minimize over p:
        ceil(exp / p) * C + (p / 2) * waste_multiplier[CLEV]
```

## この解法の本質

本質は「推定を広げすぎない」ことにある。盤面全体の硬さ分布を高精度に復元するのではなく、格子グラフ上の少数点だけを観測し、観測結果がそのまま最短路選択に反映される形にしている。

また、実際に水路を掘る段階では隣接セルの硬さ相関を強く利用する。代表点で低コスト帯を見つけ、最後は前セルの情報で過剰掘削と掘削回数を抑える、という分業が強い。

## 真似するならまず実装する部分

まず、固定間隔の斜め格子、各代表点の `lo/hi/extracted`、`edge_cost`、多始点ダイクストラを実装する。次に、最短路上の未破壊代表点を少しずつ掘り、全代表点が破壊済みなら直線経路を順に掘る。

最初から最終版のマジックナンバーを再現するより、単純な `edge_cost = distance * estimated_hardness` と固定パワーで形を作り、C 別パラメータをあとから合わせるほうが実装しやすい。

## 注意点・未理解点

- 最終コードは短く詰められており、細かい定数の意図は原著でも「パラメータ最適化の結果」とされている。
- `edge_cost` の方向補正や斜め経路の最後の試し掘りなど、小さいが効く小技が複数ある。
- シュタイナー木を厳密に解く方向は、原著ではテスト速度低下に見合うか不明として採用されていない。
- パラメータが C に強く依存するため、別の実装へ移植するとそのままでは崩れやすい。
