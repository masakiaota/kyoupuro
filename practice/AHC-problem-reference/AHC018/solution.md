## 問題の本質

AHC018は、未知の正の頂点コストを有料で観測しながら、少数の水源と家を連結する問題である。硬さがすべて分かっていれば、セル破壊コストを重みにした最短路、または水源を特殊に扱う最小シュタイナー木に近い構築問題になる。

実際には硬さが入力で与えられないため、試し掘りで情報を得る必要がある。ただし試し掘り自体も `C + P` を消費するので、盤面全体を知るほど損をする。したがって「水路候補を選ぶのに十分な情報だけを、候補経路上から取る」ことが本質である。

## 共通している考え方

- 硬さは区間で管理する。未破壊なら下限、破壊なら上限が更新される。
- 盤面全体ではなく、格子点や経路候補に探索空間を制限する。
- 経路選択はダイクストラ、MST、シュタイナー木近似のいずれかへ落とす。
- 水源そのものだけでなく、既に水が流れているセルや接続済み家を新しい接続先として扱う。
- C が大きいほど掘削回数を減らすパワー設計が必要になる。
- 本掘りでは、隣接セルの硬さが似ることを利用してパワーを決める。
- 試し掘りは情報を増やすが、やりすぎるとサンプル解法より悪くなる。

## 解法の分類

- ベースライン型: 公式サンプル、a01sa01to序盤の固定パワー直線接続。
- グリッドサンプリング型: Psyho、wanui、ToastUz、a01sa01to。
- 経路再計算型: Psyho、ToastUz、a01sa01to。
- 試し掘り選択型: wanuiのモンテカルロ、terry_u16の不確かさ優先。
- 確率推定型: wanuiの区間DP、terry_u16のガウス過程、ToastUzの対数分位推定。
- パラメータ最適化型: Psyho、ToastUz。
- 学習・回帰型: terry_u16のガウス過程、参考としてCNN。

## 推奨して理解すべき順序

1. 公式メモで、サンプル解法、硬さ既知なら最短路・シュタイナー木になるという見方を押さえる。
2. a01sa01toメモで、グリッドサンプリングを小さい実装として理解する。
3. ToastUzメモで、硬さ区間と統計的な推定、格子上MSTの考え方を理解する。
4. Psyhoメモで、1位解法の斜め格子、辺コスト、パワー決定を読む。
5. wanuiメモで、試し掘り点をモンテカルロで選ぶ考え方を見る。
6. terry_u16メモで、ガウス過程と不確かさを使う高度なルートを読む。

## 実装するならどのルートか

理解のための最小実装は、a01sa01to型がよい。固定パワーで水源・家を壊し、`DFS_WIDTH` 間隔で試し掘りし、壊れた粗い点だけをダイクストラでつなぐ。推定器が不要で、インタラクティブ処理と水路接続の基本を確認できる。

上位化を狙うなら、Psyho型をベースにするのが最も筋がよい。粗い斜め格子、`lo/hi` に基づく辺コスト、経路上代表点の試し掘り、最後の順次掘削を作る。その後、C別パワー、斜め経路の向き選択、隣接セル補正を詰める。

探索点選択を強くしたいなら、wanui型のモンテカルロを追加する。推定を高度化したいなら、terry_u16型の1次元ガウス過程を経路確定後だけに入れるのが現実的である。

## 重要な実装要素

- 状態表現: `broken/flowing`、累積パワー、硬さ下限・上限、最後のパワー、掘削回数を分けて持つ。
- 評価関数: 辺コストは距離だけではなく、両端代表点の推定硬さ、未破壊ペナルティ、C を含める。
- 候補管理: 全セルを候補にせず、格子点、家、水源、既存水路周辺に絞る。
- 更新: 掘削結果ごとに硬さ区間を更新し、次の経路計算へ即反映する。
- 出力判定: `r == -1` と `r == 2` は即終了する。破壊済みセルを再度出力しない。
- パワー決定: 固定値から始めてもよいが、C と前セル硬さに応じた調整が大きく効く。
- 時間管理: C=1 や細かい格子では掘削回数・再帰・ダイクストラ回数が増えやすい。

## 落とし穴

- サンプル解法が意外に強いので、無計画な調査掘りは簡単に負ける。
- 硬さ推定を盤面全体へ広げすぎると、計算時間と調査コストの両方で重くなる。
- C が大きいケースで小刻みに掘ると `C` の回数コストが支配的になる。
- C が小さいケースで探索・再帰が増えるとTLEしやすい。
- 水源同士を必ず接続する必要はない。水が流れている成分へ家が接続されればよい。
- 最小シュタイナー木を厳密に解くことだけに寄せても、硬さ推定が弱いとスコアは伸びない。
- 座標の `x/y`、`row/col` の扱いが記事やコードで逆になっている場合がある。
- インタラクティブなので flush と終了条件を間違えると即TLE/WAになる。

## 未解決・要検証事項

- 斜め格子がなぜ強いのかは、複数記事で経験則として扱われており、完全には説明されていない。
- Perlin noise 生成式から、観測後の硬さ分布を解析的にどこまで導けるかは未検証。
- モンテカルロで選ぶ代表点と、ガウス過程の不確かさで選ぶ代表点のどちらが安定するかは実装・パラメータ依存である。
- 硬さ区間に対する期待値DPは一様分布仮定が多く、実分布とのズレをどう補正するかに余地がある。
- ToastUz記事、wanui記事には最終コードリンクがないが、Browserで AtCoder 提出コードを確認した。細かい定数の由来と ToastUz の A-Final WA 原因は未確認である。
- 公式動画は字幕で確認したが、図や板書に依存する細部は完全には読めていない。
