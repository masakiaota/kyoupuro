## 解法の全体像

各ブロックについて、2つのシーン内の始点と回転方向をパラメータとして持つ。そのパラメータ列を与えると、シルエット外・既存ブロック・領域外を避けながら、全ブロックを1マスずつ順番にBFS的に広げていく。広げられなくなってもシルエットが未充足なら、1x1x1の補助ブロックで埋める。

探索は、この始点・回転・順序のリストに対する焼きなましである。近傍はブロック追加、削除、始点の大移動・小移動、回転変更、順序スワップ、片側だけの対応スワップで構成される。評価は、生成した占有配列のスコアを計算して行う。

## 主要アイデア

- 直接ブロック形状を編集せず、始点・回転・順序リストを解の遺伝子として持つ。
- 形状は毎回 `expand` で再生成するため、近傍はパラメータ列への単純操作にできる。
- 1ブロックを最大まで伸ばしてから次へ行くのではなく、全ブロックを順番に1マスずつ伸ばす。
- 幅優先的に広げることで、線状より塊状のブロックを作る。
- すべてのブロックで両シーンに個別の回転を持たせる。
- シルエットが埋まらない部分は、最後に片側だけの1x1x1ブロックで補完する。
- 近傍確率と温度はOptunaで調整する。
- 拡張時に、もう二度と広げられない方向を覚えて高速化する。

## 最終コードの構造

公開コード `A.cpp` は記事方針とほぼ対応している。`A.py` は全置けるセルを1x1x1で埋める素朴解、`param_search.py` はOptunaによるパラメータ探索、`test.sh` は20ケース実行用である。

### 状態表現

- `Point { x, y, z }`:
  - 3D座標。
  - 正面投影 `idxF=z*D+x`、右投影 `idxR=z*D+y`、3D配列 `idxA=x*D*D+y*D+z` を計算する。
- `P[2]`:
  - 各ブロックのシーン0/1での始点リスト。
- `RT[2]`:
  - 各ブロックのシーン0/1での24回転ID。
- `A[2]`:
  - 生成後の占有配列。各セルにブロックID、空なら0。
- `B[i]`:
  - ブロックiのローカル座標集合。始点からの相対位置で、両シーンに回転して写像される。
- `checked[i]`, `checked_d[i]`:
  - ブロックiのBFS拡張で、どのローカルセルと方向まで確認済みかを覚える高速化用状態。
- `Score`:
  - 内部スコア、片側未使用体積らしき値、共通ブロック体積リストを持つ。

### 観測・制約・入力の扱い

- `read2D` で4枚のシルエットを1次元配列として読む。
- `checkPos(o,p)` は、始点がシーンoの置けるセルであり、既存始点と重複しないことを確認する。
- 置けるセル条件は、`F[o][z,x]=1` かつ `R[o][z,y]=1` である。
- `rotate(p,r)` は24通りの回転を手書きで返す。
- `expand` は、始点・回転リストから毎回占有配列を作り直す。
- 拡張できる条件は、両シーンで領域内、未占有、正面・右シルエット内であること。
- 拡張後に未充足の正面・右パネルがあれば、片側だけの新しい1x1x1ブロックIDを追加して満たす。

### 評価関数

- `calcScore` は、生成された `A[2]` からブロックIDごとの体積を数え、内部スコアを返す。
- 目標は問題スコアの最小化である。
- 焼きなましでは `score2 < score` を無条件採択し、悪化は `exp((score-score2)/temp)` 相当の表引き近似で採択する。
- 注意点として、公開 `A.cpp` の `calcScore` には添字の疑わしい箇所がある。共通ブロック判定で `N[0]` を2回見ている箇所や、片側未使用体積の加算先が片側に寄っている箇所があるため、公開コードの内部スコアが問題スコアを厳密に再現しているとは断定しない。

### 探索・構築・更新

- 初期状態:
  - 両シーンにランダムな始点を1つずつ置く。
  - 回転もランダムに選ぶ。
- 評価:
  - `expand` で占有配列を生成。
  - `calcScore` でスコアを計算。
  - 最良なら `bestA` を更新。
- 近傍:
  - ブロック追加: 両シーンにランダム始点とランダム回転を追加。
  - ブロック削除: 対応する始点・回転を両シーンから削除。
  - 大きく移動: 片方のシーンの始点をランダムな置ける場所に変える。
  - 小さく移動: 片方のシーンの始点を6近傍の置ける場所へ動かす。
  - 回転: 片方のシーンの回転IDをランダム変更。
  - スワップ: ブロック順序を両シーンで入れ替える。
  - 片方スワップ: 片方のシーンだけ対応関係を入れ替える。
- 採択:
  - 温度は `Temp*(1-time)` で線形に下げる。
  - `my_exp` は指数関数を1024要素の表で近似する。
- 高速化:
  - `expand` 中、各ブロックで確認済みローカルセルと方向を覚える。
  - これにより、シルエット外や既占有で失敗する方向を何度も見ない。

### 操作・クエリ・出力選択

- 最後に `bestA` を出力する。
- `output` は2つの占有配列に現れる最大ブロックIDを `n` とし、`A[0]`, `A[1]` を1行ずつ出す。
- `expand` が未充足セルを1x1x1で埋めるため、可行性は確保しやすい。
- ただし、片側だけに出る補完ブロックはスコア上は重い。

### 時間配分・パラメータ

- 時間制限は `TIME=5.8` 秒で管理する。
- 初期温度 `Temp=0.5`。
- 近傍確率は記事・コード上、追加、削除、大移動、小移動、回転、スワップ、片方スワップに固定重みを持つ。
- `param_search.py` ではOptunaで温度と近傍確率を探索している。
- 記事では、6秒で10万から200万回程度、構築処理を実行できたとされる。

```text
expand(P, RT):
    initialize A[0], A[1] empty
    for each block i:
        B[i] = [(0,0,0)]
        place start cells in both scenes

    loop:
        find first block i and direction d whose next local cell can be placed in both scenes
        if none:
            break
        add local cell to B[i]
        mark corresponding rotated cells in A[0], A[1]

    fill uncovered silhouette panels with one-cell blocks
```

## この解法の本質

形状そのものを近傍で壊したり直したりするのではなく、「形状を生成するパラメータ列」を焼きなましている点が本質である。これにより、近傍は始点・回転・順序の変更という軽い操作になる。形状の連結性は、BFS拡張で生成することにより自然に保証する。

一方で、毎回全体を再生成するため、差分更新による厳密な局所探索ではない。スコアは少しの始点移動や順序交換で大きく変わるが、実装はかなり単純になる。短期間で可行かつそこそこ強い解法を作るには合理的な設計である。

## 真似するならまず実装する部分

まず、始点・回転リストからBFSで全ブロックを順番に伸ばす `expand` を作るのがよい。未充足パネルを1x1x1で埋める補完も入れると、常に可行解が出る。

次に、始点の小移動・回転変更・ブロック追加削除だけで焼きなましを回す。順序スワップや片方スワップ、Optuna調整はその後でよい。

## 注意点・未理解点

- 公開コードの `calcScore` には、問題スコアと一致しない可能性がある疑わしい添字がある。記事の最終提出コードそのものか、ローカル調整中のコードかは断定できない。
- `switch` のスワップ近傍に `break` がなく、両側スワップ後に片側スワップへfallthroughする。意図的かミスかは不明である。
- シルエット未充足を1x1x1で補完するため可行性は高いが、補完が多いとスコアが急激に悪化する。
- 全体を毎回作り直すので、複雑な評価を入れると試行回数が落ちる。
- 近傍確率は入力や温度で最適値が変わる可能性があると記事でも述べられている。
