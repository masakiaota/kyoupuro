## 解法の全体像

各山の使用枚数を8枚に固定し、各カードから `10^15/8` を引いた差分、各Bから `10^15` を引いた差分で考える。これにより、目標は `[-2e12, 2e12]` 程度の値を8枚の差分カードの和で作る問題になる。

8枚を一度に探すのではなく、250枚ずつの2段階に分ける。前半4枚で各山の残差を小さい範囲に収め、後半4枚で残差を0にする。各段階では、初期割当をランダムに作り、山を1つ選んで「その山の既存4枚 + 未使用50枚」の54枚から、目標範囲に入る4枚組を探して置き換える。

## 主要アイデア

- 各山8枚固定により、中心値 `10^15/8` を全カードに足して実際のA制約を満たす。
- Bとの差分問題に変換することで、負のカードを含むような見通しで考えられる。
- 8枚を4枚+4枚の2段階に分け、1段階あたりの目標幅をおよそ平方根スケールにする。
- 誤差の大小ではなく、目標範囲内に入ったかどうかだけを見る。
- 54枚から4枚組を探す部分を、27枚と27枚にランダム分割して2+2の半分全列挙で高速化する。
- 探索に失敗した未調整山はランダムな4枚に置き換え、状態を動かし続ける。
- Aの差分値は一様乱数ではなく、中心密度が高い三角分布風の点列を使う。

## 最終コードの構造

### 状態表現

- `a[500]`: 出力前は差分値。実際に出力するときは各要素へ `OFFSET=10^15/8` を足す。
- `b[50]`: 入力Bから `OFFSET*8` を引いた差分目標。
- `assign[250]`: 半段階内のカードがどの山に割り当てられているか。未使用は `-1`。
- `cards[50][4]`: 各山に現在割り当てられている4枚。
- `group_sums[50]`: 各山の4枚の差分合計。
- `avail[54]`: 選んだ山の既存4枚と未使用50枚を合わせた入替候補。

### 観測・制約・入力の扱い

- 入力の `N,M,L,U` は固定値であることをassertしている。
- A出力時は差分値に `OFFSET` を足す。差分値の範囲は十分小さいので、実際のAは1以上U以下に収まる。
- B読取後は同じ中心値を引き、前半・後半の残差更新だけを扱う。
- 出力では内部 `assign` の `-1` をそのまま使わず、山番号を1-originで出す。8枚固定方針なので成功時は全カードが割当済みになる。

### 評価関数

- 各段階の判定は `abs(group_sums[g] - b[g]) <= goal` である。
- 前半は `goal = 130 * 10^4` 程度、つまり全山の残差をこの幅以内に押し込む。
- 後半は `goal = 0` とし、残差を完全に0にする。
- 探索中に総誤差もログ出力するが、採択判断は「各山が目標幅内かどうか」が主である。

### 探索・構築・更新

- `gen_a(e)`:
  - `[-e,e]` に三角分布の逆CDF風で250点を作る。
  - 前半は `e=0.9*2e12`、後半は `e=0.9*FIRST_PHASE_GOAL`。
  - 点列をシャッフルする。
- `calc_assign(a,b,goal,tl_ms)`:
  - 250枚をランダムに4枚ずつ50山へ割り当て、50枚を未使用にする。
  - ランダムに山gを選ぶ。
  - gの4枚と未使用50枚を集め、シャッフルして54枚にする。
  - `select4_mitm` で目標幅内の4枚組を探す。
  - 見つかればgの4枚を置換する。
  - 見つからず、gがすでに目標幅内なら維持する。
  - 見つからず、gが未調整ならランダムな4枚に置換する。
- `select4_mitm`:
  - 54枚を27枚ずつに分ける。
  - 左側の全2枚和を作ってソートする。
  - 右側2枚を走査し、必要な左2枚和を二分探索相当で探す。
  - 条件を満たしたら元の添字4個を復元する。
- `main`:
  - 前半・後半の試行を最大3回行う。
  - 前半に失敗した試行は後半へ進まない。
  - 後半で全残差が0なら割当を出力して終了する。

### 操作・クエリ・出力選択

- Aは2つの250枚差分配列を連結し、中心値を足して出力する。
- 前半の割当後にBの残差 `b2` から前半カードの和を引く。
- 後半は残差 `b2` を目標として4枚ずつ選ぶ。
- 成功した試行の `assign` を500枚分連結し、すべて山番号で出力する。

### 時間配分・パラメータ

- 時間制限は1950msに設定。
- 試行回数は3回。試行ごとに累積目標時刻を `TIME_LIMIT_MS*(times+1)/3` とする。
- 前半にはその試行残り時間の半分、後半には残り時間を使う。
- `FIRST_PHASE_GOAL = 1.3e6` 程度。
- 54枚の分割では、既存4枚が片側に2枚ずつ入らないようにして、同じ組が再選択されにくくしている。

## 実装上重要な断片

```text
two_phase():
    a1 = gen_a(0.9 * E)
    a2 = gen_a(0.9 * first_goal)
    b = read_B() - 8 * OFFSET
    repeat 3 times:
        assign1 = calc_assign(a1, b, first_goal)
        if residual not within first_goal: continue
        assign2 = calc_assign(a2, residual, 0)
        if residual is all zero: output(assign1 + assign2)
```

## この解法の本質

本質は、部分和問題を「計算時間で当たりを引く問題」と「カード枚数で指数的に調整する問題」の中間に分解したことだ。8枚固定のまま一気に解くと探索空間が大きすぎるが、4枚ずつ2段階にすると、各段階の目標幅が広がり、54枚から4枚を探す半分全列挙で十分当たりが出る。さらに誤差の大小を追わず「範囲内かどうか」だけを見ることで、局所探索の目的を満点達成に特化している。

## 真似するならまず実装する部分

最初に実装すべきは、差分化、250枚の4枚割当、54枚から4枚組を探す2+2半分全列挙である。満点狙いでなければ、前半目標幅を広めに取り、後半も完全0ではなく小さな誤差許容で止めるとデバッグしやすい。

## 注意点・未理解点

- 満点を狙うため、後半失敗時のフォールバック出力が実質ない。実装ミスや時間切れはWA/TLEに直結しやすい。
- `select4_mitm` は定数倍最適化が強く、単純な `C(54,4)` 全探索では時間が足りない可能性が高い。
- 目標幅、Aの分布、3回試行の時間配分はチューニング依存である。
- 記事中に「闇テク」は最終的に不要になったとあるが、その具体内容は説明されていない。
