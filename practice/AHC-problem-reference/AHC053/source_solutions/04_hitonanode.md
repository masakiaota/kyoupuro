## 解法の全体像

この解法は、固定のAを事前にうまく構築し、Bを読んだ後は極めて単純な貪欲だけで割り当てる。本番提出コードではAが定数配列として埋め込まれている。A生成はローカルで多数のBサンプルを作り、「現在のAで貪欲割当した後に残る最大空き」をもとに、次に追加すると多くのケースの空きを削れそうな値を1枚ずつ選ぶ。

実行時の割当は、Aを順に見て、現在の残り容量がA以上の山のうち残り容量が最小の山へ入れるだけである。A設計に計算を集中させ、提出コード本体は高速かつ頑健にしている。

## 主要アイデア

- 実行時の探索を重くせず、A構築をオフラインで最適化する。
- 貪欲ルールは「入る山のうち一番きつい山に入れる」。これは後で大きいカードが入らなくなるリスクを抑える。
- Aを空から始め、ローカルテストケース1000個程度に対して貪欲を繰り返しながら1枚ずつ追加する。
- 次に追加するAは、各サンプルの最大残り容量を昇順に並べ、`C_i * (K+1-i)` が最大になる `C_i` を選ぶ。
- 直感的には、その値以上の最大空きを持つケースすべてから一気にその値ぶん空きを削ることを狙う。
- 構築されたAは、先頭50枚がB分布の下限に近く、以降は概ね指数減衰のような形になる。

## 最終コードの構造

### 状態表現

- 提出コードの実行時:
  - `A[500]`: 事前生成済みの定数配列。降順に近い形で埋め込まれている。
  - `B[50]`: 割当中は各山の残り容量として直接減らす。
  - 出力 `X_i`: カードiを入れる山番号、入らなければ0。
- A生成用Python:
  - `testcases[1000][50]`: ローカル生成した昇順B。
  - `ret`: 構築中のA。
  - `remains`: 貪欲適用後の各山残り容量。

### 観測・制約・入力の扱い

- A生成時は問題の入力分布をそのままローカルに再現する。`B` は `[L,R]` の一様乱数50個を昇順ソートする。
- 実行時はBを受け取り、残り容量配列として扱う。
- Aの各値がどの山にも入らない場合、そのカードは捨てる。

### 評価関数

- A生成時の1枚選択:
  - 各テストケースについて、現在のAで貪欲割当後の `max(remains)` を集める。
  - 昇順列 `C` に対して `C_i * (K+1-i)` を最大化する値を選ぶ。
  - これは「その値以上の最大空きを持つケース数」×「削れる量」を最大化する近似である。
- 実行時の最終評価は `sum_j |remaining_j|` と同じ。貪欲は目標を超えない範囲で詰めるため、残り容量がそのまま誤差になる。

### 探索・構築・更新

- オフラインA構築:
  - `ret` を降順ソートする。
  - 各サンプルBに対して貪欲を適用する。
  - 各ケースの最大残り容量から次のAを選ぶ。
  - `ret` に追加し、500回繰り返す。
- 実行時貪欲:
  - Aの先頭から順に処理する。
  - `B[j] >= A[i]` を満たす山のうち、`B[j]` が最小の山を探す。
  - 見つかればそこへ割り当て、`B[j] -= A[i]`。
  - 見つからなければ捨てる。

### 操作・クエリ・出力選択

- Aを定数配列として出力する。
- Bを読んだ後、各Aに対して貪欲に山番号を決めて即座にXを出力する。
- 割当探索や焼きなましは実行時には行わない。

### 時間配分・パラメータ

- ローカルA生成のサンプル数は1000個程度。
- 実行時提出は2ms程度で動く。
- スライドでは、サンプル数が多すぎると先頭50枚が小さくなりすぎるなど、1000という値もチューニング対象だと述べている。

## 実装上重要な断片

```text
greedy(A, B):
    remains = sorted(B)
    for a in sorted(A, descending):
        idx = lower_bound(remains, a)
        if idx exists:
            remains[idx] -= a
            reinsert remains[idx] to keep sorted
    return remains
```

## この解法の本質

実行時にBへ適応する探索を頑張るのではなく、「単純貪欲がよく効くようなAを事前に学習的に構築する」ことが本質である。Aは提出ごとに固定なので、ローカルで乱数分布に対して大量に評価できる。この問題の入力生成が完全に既知であることを利用した、オフライン最適化寄りの解法だ。

## 真似するならまず実装する部分

まずは実行時貪欲を実装し、Aを等比数列やL固定+指数減衰で手作りする。その後、記事のA生成Pythonを再現して、ローカルサンプルからAを1枚ずつ作る。提出時は生成済みAを埋め込むだけなので、インタラクティブ風入出力のバグが少ない。

## 注意点・未理解点

- A生成はローカルサンプルの数と乱数seedに依存し、汎化性能と大失敗率のトレードオフがある。
- 実行時に目標超過を許さない貪欲なので、Aがやや大きすぎるとカードが捨てられやすい。
- 後処理をしないため、Bを少し超えてでも改善できる場面を拾えない。
- 提出コードはA定数配列が長い。メモでは長い転載を避け、生成法と割当法だけを要約した。
