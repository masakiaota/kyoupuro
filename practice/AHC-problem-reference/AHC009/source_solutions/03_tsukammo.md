## 解法の全体像

壁に向かって進むことで確率を集められることに注目し、確率分布を「集団」として扱いながらゴールへ近づける方針を試している。主方針は2つある。

1つ目は、ゴール側から直線的な経路を伸ばし、スタート側から合流しやすいマスを探すような構築である。2つ目は、各マスにゴールからの評価値を付け、確率分布を壁に擦り付けて削りながら評価が高くなる方向へ動かす貪欲である。

最終的には複数方針を作って、実スコアで良い方を選ぶ。後半では2手読み、4手読みのような先読み貪欲も試している。

## 主要アイデア

- 壁にぶつけると、その方向へ進めなかった確率が同じマスに残り、確率分布を集めやすい。
- スタートは左上、ゴールは右下なので、雑に右下へ向かうだけでも一定点は出る。
- ただし、引っかかるポイントを適度に抜けながら徐々にゴールへ近づく必要がある。
- 各マスにゴールへの近さ・到達しやすさを表す評価値を付け、その期待値が良くなる命令を選ぶ。
- 袋小路は評価を落とし、確率が広がりすぎるケースを避けようとしている。
- ビームサーチは有望と見ているが、コンテスト中は実装を断念している。
- 実スコア計算で複数方針を比較し、ベストを選ぶ。

## 最終コードの構造

in-app Browser で読んだ提出 #30422733 の構造である。記事の「壁に擦り付ける貪欲」と「複数方針を実スコアで選ぶ」方針が、そのまま Java 実装になっている。

### 状態表現

- 命令列 `ans` と別方針の `ans2`。
- 現在の存在確率 `exist[20][20]`。
- ゴールから BFS した `distMap`。右下方向で引っかかる袋小路にはペナルティを足す。
- 壁判定と `nextExist`。忘却確率 `p` と壁衝突を反映して分布更新する。
- 複数方針の実スコア `trueScore` と `trueScore2`。

### 観測・制約・入力の扱い

- 入力地図から壁を読み、各方向へ進めるか判定する。
- 全てのマスはスタートから到達可能なので、評価値計算や最短路計算は通常のグリッド探索でよい。
- 出力長は200以下。提出コードは `prepare(); init(); solve(); solve2(); output();` の順に動く。

### 評価関数

主に2種類ある。

- 実スコア: 各手のゴール到達確率を `250000 * (401 - t)` 相当で加算し、複数方針の最終比較に使う。
- 貪欲用評価: 確率分布と `distMap` の積和を小さくする。

```text
greedy_value(prob):
    return sum_cell prob[cell] * value[cell]
```

`distMap[cell]` はゴールからの距離を基本にし、右下方向で引っかかるマスに +2、左/上も壁ならさらに +1 の袋小路ペナルティを入れている。

### 探索・構築・更新

貪欲方針:

- `solve` は各手で4手先まで全探索し、4手適用後の `sum distMap[cell] * prob[cell]` が最小になる最初の方向を採る。
- 各手の後、ゴール到達確率を実スコアへ加算し、ゴール確率を分布から取り除く。

別方針:

- `solve2` は壁まで滑るような経路をゴール側から作り、同方向を何回出すかの係数 `deg` を試して最良を選ぶ。

最終選択:

- 方針1と方針2の命令列をそれぞれ生成する。
- 実スコアDPで評価して高い方を採用する。

### 操作・クエリ・出力選択

- 対話なし。最終的に1本の命令列を出力する。
- 構築中の各手は、確率分布が評価値の高いマスへ寄るかで選ぶ。
- 複数方針の切替は最終スコアで行う。

### 時間配分・パラメータ

- 提出コードでは4手読み貪欲と壁滑り経路の2方針を作り、実スコアで選ぶ。
- `solve2` では各区間の繰り返し強度 `deg` を 10..4000 で試す。
- 評価値係数と袋小路ペナルティは提出コードで確認できた。

## この解法の本質

この参加記の本質は、確率分布を1人の位置ではなく「雲」や「集団」として捉え、その集団を壁で削りながらゴールへ運ぶ見方にある。最短路ではなく、確率の塊がどこに残り、どこへ流れるかを評価している。

一方で、評価値設計だけではケース差を吸収しきれず、ビームサーチや焼きなましのように候補を広く見る手法が必要だった、という反省も重要である。

## 真似するならまず実装する部分

まず、確率分布を更新する `transition(prob, dir)` と、ゴール距離ベースの `value[cell]` を作る。次に、1手貪欲で命令列を伸ばす。

余裕があれば、2手読み・4手読みを追加する。完全な上位化を狙うなら、この貪欲を初期解生成器として使い、TERRY/Bondo型の焼きなましで後処理するのが自然である。

## 注意点・未理解点

- 評価値と袋小路ペナルティは提出コードで確認できた。
- 最終出力は `trueScore > trueScore2` なら4手読み貪欲、そうでなければ滑り経路を採る。
- 本人もビームサーチの必要性を述べており、貪欲単独ではseed差に弱い。
