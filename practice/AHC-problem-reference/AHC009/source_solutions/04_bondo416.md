## 解法の全体像

BFSでスタートからゴールへの最短経路を作り、それを初期解にして命令列を局所探索で改善する。記事上は焼きなましと説明されているが、提出コードは後述の理由で実質的には山登りに近い。評価はビジュアライザと同じ確率DPで実スコアを計算する。

近傍は1点追加、区間反転、2点swap、1点削除の4種類で、記事では遷移確率をおおむね `30/30/30/10%` としている。提出コードでも乱数 `0..99` によりほぼ同じ割合で選んでいる。

## 主要アイデア

- 初期解はシンプルにBFS最短路。
- スコア計算は確率DPで愚直に行う。
- 命令列を直接変更する局所探索で、最短路だけでは拾えない確率を改善する。
- 追加、削除、区間反転、swap のような文字列操作を近傍にする。
- ダブらせが強いことやビームサーチの有効性は知見として挙げているが、最終コードの主近傍には明示的な「隣接コピー」はない。

## 最終コードの構造

### 状態表現

- グローバル入力
  - `sh, sw, th, tw, p`
  - `fi_h`, `fi_v`: 横・縦壁
- 解
  - `current_ans`: 現在の命令列
  - `best_ans`: 最良命令列
  - `current_score`, `best_score`
- DP
  - `dp[20][20]`: 現在ターン前の存在確率

### 観測・制約・入力の扱い

- `can_move(c, h, w)` で文字 `c` の方向に移動可能か判定する。
- 壁方向または外周方向ならその場に残る。
- 追加近傍では長さ `200` 以上ならスキップする。
- 削除近傍では長さが `20` 以下ならスキップして、極端に短い列を避ける。

### 評価関数

`calculate_score(ans)` は確率DPを行う。

```text
dp[start] = 1
sum = 0
for i in 0..len(ans)-1:
    next = 0
    for each cell:
        if can_move(ans[i], cell):
            next[moved] += dp[cell] * (1-p)
            next[cell] += dp[cell] * p
        else:
            next[cell] += dp[cell]
    dp = next
    sum += dp[goal] * (400 - i)
    dp[goal] = 0
return 1e8 * sum / 400
```

これは問題文の `round(250000 * E[S])` と同じスケールのスコアを意図した計算である。ゴール到達後の確率を `0` にする点が重要である。

### 探索・構築・更新

初期解:

- BFSで通常の最短路を求める。
- `prev` からゴールからスタートへ復元し、反転して `current_ans` にする。
- 初期解の実スコアを計算し、最良解に設定する。

焼きなまし:

- 時間制限 `TL = 1990ms` までループする。
- 近傍は乱数 `c` で選ぶ。
  - `c <= 30`: ランダム位置にランダム方向を挿入
  - `30 < c <= 60`: 区間反転
  - `60 < c <= 90`: 2点swap
  - それ以外: ランダム位置を削除
- 近傍適用後に全スコアを再計算する。
- 改善なら採用する。コード上は悪化採択らしき分岐もあるが、時刻計算のため実質的にはほぼ採用されない。

提出コードの悪化採択は、スコア差を温度に入れる通常の `exp(delta/temp)` ではなく、`rest_time / (TL*50)` と乱数の比較になっている。ただしコード上は `rest_time = TL - get_ms()` になっており、`get_ms()` が絶対時刻のミリ秒を返すため実行時は負値になる。したがって、提出コードは記事の表現では焼きなましだが、実際にはほぼ改善時のみ採用する山登りとして動いていたと読める。

### 操作・クエリ・出力選択

- 最終的に `best_ans` を出力する。
- 現在解が悪化しても、最良解は別に保持する。
- 対話なし。

### 時間配分・パラメータ

- `TL = 1990ms`
- 近傍比率は追加・区間反転・swap・削除がおおむね `30/30/30/10`
- 悪化許容用と思われる定数 `C = TL * 50`。ただし提出コードでは悪化採択は実質無効に見える。
- 削除は長さ `20` 以下で禁止

## 実装上重要な断片

```text
bfs_initial():
    dist[start] = 0
    queue = [start]
    relax reachable neighbors
    restore path from goal with prev
    current = restored command string
```

```text
sa_loop():
    while elapsed < 1990ms:
        backup = current
        mutate by insert/reverse/swap/delete
        next_score = score(current)
        if next_score >= current_score:
            keep
            update best
        else:
            rollback
```

```text
score:
    update 20x20 probability grid for each command
    add goal probability to score
    remove goal probability before next turn
```

## この解法の本質

本質は、スコア計算を正確に持ったうえで、文字列の単純な近傍だけでも高得点に届くことを示している点である。BFS最短路は忘却に弱いが、挿入・反転・swap・削除により、壁で確率が溜まる動きや余分な回り込みが自然に入る。

TERRY解より初期解の多様性やダブらせが弱い一方、実装が簡潔で、AHC009の最小局所探索実装として参考にしやすい。

## 真似するならまず実装する部分

まずこの解法のBFS初期解、`can_move`、確率DPスコア、4近傍の山登りを実装するのがよい。焼きなましにするなら、悪化採択は通常の `exp(delta/temp)` などに置き換える必要がある。

次に、TERRY解のようなダブらせ初期解やコピー近傍を加えると、忘却への頑強性が上がる。

## 注意点・未理解点

- 提出コードの悪化採択は時刻計算のため実質無効であり、一般的な焼きなましではなく山登りに近い。記事の「焼きなまし」という表現とは差がある。
- BFS最短路1本に依存するため、初期経路が悪いケースでは伸びにくい。
- 記事では「行動をダブらせるのが強い」とあるが、コード上の近傍はランダム挿入であり、明示的コピー近傍ではない。
- 愚直DPなので、近傍数を増やすには定数倍高速化が必要になる。
