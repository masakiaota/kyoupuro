## 解法の全体像

最短経路をそのまま出すのではなく、まず乱択ダイクストラで複数の「本筋の経路」を作り、忘却確率 `p` に応じて一部の命令を重複させる。これを短時間で多数試し、期待値DPで実スコアが高いものを初期解にする。

その後、命令列そのものを焼きなましで変更する。評価は近似ではなく、問題文の期待スコアを確率DPで愚直に計算する。近傍は命令の重複、追加、削除、変更、移動で、長さ制約 `200` を守りながら残り時間いっぱい改善する。

## 主要アイデア

- 状態は長さ `200` 以下の命令列そのもの。
- 地図は各マスから4方向へ移動可能なら遷移先座標、壁なら `None` という形で持つ。
- 初期解はスタートからゴールまでの経路だが、辺重みをランダムにしたダイクストラで多様性を作る。
- 忘却により命令が一定割合で無効化されるため、経路長 `L` に対して `ceil(L / (1-p))` 付近までランダムに命令をダブらせる。
- 評価関数は確率DPによる厳密な期待スコア。
- 焼きなましでは局所変更で、最短路から外れた取りこぼし確率を拾う。
- `p` が大きいほど分布がぼやけ、局所変更しても評価が滑らかになりやすいため焼きなましが効きやすい。

## 最終コードの構造

### 状態表現

- `Input`
  - `start`, `goal`: 開始・目標座標
  - `probability`: 忘却確率 `p`
  - `map[row][col][dir]`: その方向へ移動可能なら遷移先座標、壁なら `None`
- 解状態
  - `Vec<CoordinateDiff>`: `U/R/D/L` に対応する移動差分列
  - `best_solution`, `current_score`, `best_score`
- DP
  - `dp[turn][cell]` 相当を1次元配列で保持し、各ターンの存在確率を更新する。

### 観測・制約・入力の扱い

- `h`, `v` の壁情報を読み、各マスから4方向に動けるかを前処理する。
- 外周方向は座標範囲外として遷移不可にする。
- 出力長が `200` を超えないよう、追加・重複近傍では長さを確認する。
- 出力文字への変換は `CoordinateDiff` から `U/R/D/L` に戻す。

### 評価関数

確率DPで各ターン後にゴールへ到達する確率を求め、到達した確率質量は以降のターンから取り除く。

```text
dp[start] = 1
score = 0
for turn, command:
    next = transition(dp, command)
    goal_prob = next[goal]
    score += goal_prob * (401 - (turn + 1))
    next[goal] = 0
    dp = next
return round(score * 250000)
```

壁方向に進む、または命令を忘れる場合は同じマスに残る。公式ローカルツールの `compute_score` も同じ考え方で、0-indexの `t` に対して `2*L - t` を足している。

### 探索・構築・更新

初期解生成:

- `dijkstra(input, seed)` で経路を作る。
- 辺重みは毎回乱数で `[10, 30]` から選ぶ。
- 経路長 `L` に対し、目標長 `ceil(L/(1-p))` までランダムな位置の命令を複製する。
- これを短時間繰り返し、実スコア最大の初期解を採用する。

焼きなまし近傍:

- 選んだ命令を直後に複製する。
- ランダムな位置にランダム方向を挿入する。
- ランダムな位置の命令を削除する。
- ランダムな位置の命令を別方向へ変更する。
- ランダムな位置の命令を削除し、別位置へ挿入する。

採択はスコア差が正なら必ず採用し、悪化でも `exp(diff / temp)` で採用する。温度は `1e5` から `1e2` へ幾何的に下げる。

### 操作・クエリ・出力選択

- 最終出力は焼きなましで見つかった `best_solution`。
- 対話やクエリはない。
- 各ターンでゴール到達確率が加点されるので、「最後に到達する」より「なるべく多くの確率質量を早めにゴールへ流す」ことを評価する。

### 時間配分・パラメータ

- 初期解生成は記事では約 `0.1` 秒、提出コードでは `0.05` 秒。
- 焼きなましは提出コードで `1.92` 秒。
- ダイクストラ辺重みは記事・最終方針で `[10, 30]`。
- 焼きなまし温度は `temp0 = 1e5`, `temp1 = 1e2`。
- 記事では最終的に約 `1.1e4` 回ほど評価を回したとされている。

## 実装上重要な断片

```text
make_initial():
    best = empty
    while initial_time remains:
        path = randomized_dijkstra(weight in [10, 30])
        target_len = ceil(len(path) / (1 - p))
        duplicated = insert copies at random positions until target_len
        if score(duplicated) > score(best):
            best = duplicated
    return best
```

```text
anneal(cmd):
    while time remains:
        next = apply one of duplicate/insert/delete/change/move
        if len(next) > 200:
            continue
        diff = score(next) - score(cmd)
        if diff >= 0 or rand() < exp(diff / temp):
            cmd = next
            best = max(best, cmd)
```

```text
score(cmd):
    probability_grid[start] = 1
    for each command:
        distribute stay/move probability
        add goal_probability * remaining_score
        remove goal_probability from grid
```

## この解法の本質

本質は、頑強な経路を直接設計するのではなく、「本筋の経路」と「忘却で遅れる分の余裕」を先に作り、残りを確率DPの実スコアで局所最適化する点にある。

命令列の問題は1文字変えると以後の挙動が大きく変わりがちだが、この問題では忘却と壁衝突で確率分布が広がるため、スコア面がある程度滑らかになる。そこで、完全な構造理解よりも、多様な初期解と正確な評価を大量に回す方が強い。

## 真似するならまず実装する部分

まず実装すべきなのは、スコア計算DPとBFS/ダイクストラ初期解である。次に、命令のランダム重複を入れる。ここまでで「忘れる分だけ余分に歩かせる」効果を確認できる。

その後、追加・削除・変更・重複の4近傍だけで山登りまたは焼きなましを入れる。移動近傍や温度調整、1次元DPによる高速化はその次でよい。

## 注意点・未理解点

- 記事では「愚直スコア計算」と書かれているが、提出コードは1次元配列や `unsafe` で定数倍をかなり詰めている。
- 削除近傍は短くしすぎると到達率が壊れるため、提出コードでは長さが `100` 未満なら削除を避けている。
- 初期解への依存が大きく、乱択ダイクストラの重み範囲や乱数の当たり外れがスコアに影響する。
- 前後DPによる差分高速化は記事の脚注で触れられているが、提出コードでは採用されていない。
