## 解法の全体像

初期解は「氷上滑り」のように、同じ方向へ壁にぶつかるまで進む動きを繰り返してゴールを目指す。ゴール側からダイクストラのような計算を行い、曲がる回数が少ない経路を求め、それを200手になるようにダブらせる。

この方法でゴールに到達できないケースでは、現在の確率分布で存在確率が最大のマスからゴールへ向かう動きを繰り返す方針に切り替える。最後に、削除・ランダム追加・ダブらせ近傍で焼きなましを行い、スコアを大きく改善している。

## 主要アイデア

- 壁に何度も進むと確率分布を1か所に集められる。
- そのため、壁まで進む動きを単位にして、曲がる回数が少ない経路を初期解にする。
- 200手まで命令をダブらせることで、忘却で遅れた確率を補う。
- 壁滑りだけでは到達不能なケースがあるため、確率最大マスからゴールへ向かうフォールバックを持つ。
- 削除近傍だけでも大きく改善し、追加・ダブらせを入れるとさらに伸びた。
- スコア計算は公式テスターのコードを見て理解したとある。

### 状態表現

- `IOServer` が壁配列と `CanMove` を持つ。
- `State` は命令列を持ち、`Simulation` が確率DPでスコアを計算する。
- `Run1` が壁滑り初期解を作る。ゴール側から priority queue で曲がり回数の少ない経路を求め、復元した方向列を200手まで均等に重複する。
- `Run2` がフォールバックで、確率最大マスから通常BFS距離が下がる方向を選ぶ。
- `SimulatedAnnealing` が現在解と最良解を管理する。

### 観測・制約・入力の扱い

- 壁情報から、ある方向へ進み続けたとき最終的に止まるマスを計算する。
- 通常移動のスコア計算では、各文字ごとに忘却・壁衝突を考慮して確率分布を更新する。
- 初期解が200手未満なら、命令の重複で長さを増やす。

### 評価関数

焼きなましの評価は実スコアDPである。記事ではスコア計算の理解に苦労し、公式テスターのコードを読んで実装したとある。

壁滑り初期解の構築では、曲がる回数が少ないことを重視した距離計算をしている。

```text
slide_graph_state = cell
edge = choose direction and move until wall
cost = mainly number of turns / command blocks
```

### 探索・構築・更新

初期解:

- `Run1` は、逆向きに壁がある状態を起点にしてゴール側から探索し、壁まで進む動きを単位にした経路を復元する。
- 復元した `minDirs` を200手になるように均等に重複する。
- `Run1` で作れないケースでは `Run2` に切り替え、存在確率最大のマスからゴール方向へ進む。

焼きなまし近傍:

- `Updater1`: ランダム位置の命令を1個削除する。
- `Updater2`: ランダム位置へランダム方向を1個挿入する。
- `Updater3`: ランダム位置の既存命令を複製してダブらせる。
- 焼きなましは startTemp=1000、endTemp=100、stepLoopCount=500 で、各 Updater を同率で使う。

### 操作・クエリ・出力選択

- 最終的に焼きなましで得た最良命令列を出力する。
- 対話なし。
- フォールバック方針は、壁滑り経路でゴールへ行けないケースのために使う。

### 時間配分・パラメータ

- 記事では、100分経過時点で壁滑り単独の弱さが分かり、残り30分でスコア計算と焼きなましを入れた流れが記録されている。
- 近傍追加後、スコアは約6.0Gから約7.0Gへ上がっている。
- 提出コードでは温度 1000 から 100、stepLoopCount 500 を使う。

## 実装上重要な断片

```text
make_slide_initial():
    for each cell and direction:
        stop[cell][dir] = move until wall
    run dijkstra-like search from goal side
    restore command blocks
    duplicate commands until length is near 200
```

```text
fallback_by_max_probability(prob):
    while not enough commands:
        cell = argmax prob[cell]
        dir = next direction from cell toward goal
        append dir
        prob = transition(prob, dir)
```

```text
anneal:
    try delete one command
    try insert random command
    try duplicate one command
    accept based on score
```

## この解法の本質

この解法の本質は、壁を「確率分布を同期させる装置」として使う点である。忘却により人の位置はばらけるが、同じ方向に進ませ続けて壁で止めると、遅れた確率も同じ場所に集まる。これは単純な最短路より頑強である。

ただし、壁滑りは地形に強く依存する。コの字型や一度戻る必要がある地形では初期解が破綻しやすく、最終的には焼きなましで補正する必要がある。

## 真似するならまず実装する部分

まずは通常のスコアDPと、命令の削除・追加・ダブらせ近傍を実装するのがよい。壁滑り初期解は面白いが、到達不能ケースの処理が必要なので、最小実装ではBFS初期解にダブらせを入れる方が安定する。

壁滑りを真似するなら、各マス・各方向について「壁まで進んだ停止位置」を前計算し、曲がり回数の少ない経路を作るところから始める。

## 注意点・未理解点

- 壁滑り初期解のコスト設計とダブらせ方は提出コードで確認できた。曲がり回数を優先し、復元方向列を均等に200手へ引き伸ばしている。
- 「存在確率最大の場所からゴールに進む」フォールバックは、記事中でも点数が低かったとされており、単独では弱い。
- 壁滑りでゴールできるケースとできないケースの判定・切替が重要である。
- 焼きなましでなぜ大きく伸びたかについて、本人も理解しきれていないと述べている。
