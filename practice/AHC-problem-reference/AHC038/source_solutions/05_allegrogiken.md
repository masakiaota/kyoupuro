## 解法の全体像

長さが2冪の直列アーム、例えば `16, 8, 4, 2, 1` を作り、先端だけを指先として使う。2冪長の組合せにより、アーム方向状態と指先の根からの相対座標がほぼ1対1に対応するため、目標座標から必要な回転状態をテーブルで逆引きできる。これを使うと、指先1本の単純貪欲でも実装しやすく、さらにVが許せば同じアームを複数本生やして同時処理できる。

## 主要アイデア

- アーム長を `16,8,4,2,1` のような2冪降順にする。
- 回転状態数 `4^k` と到達相対座標数が一致し、座標から姿勢へ変換しやすい。
- 任意の到達可能範囲内の2点間を、最悪でも数ターン、記事では基本2ターン程度で移動できると説明している。
- 盤面サイズに応じて、`8,4,2,1` や `4,2,1` の小型版を使う。
- Vが大きい場合は同じ構成のアームを複数本生やし、同時に別のたこ焼きを処理する。
- 複数アームでは、同じたこ焼きや同じ目的地を同時に扱わない予約管理だけ注意すれば、実装は比較的単純である。

## 最終コードの構造

Browserで読めた提出 #58802064 と記事本文から書く。記事は2冪アームの考え方、提出コードは貪欲運搬と複数アーム割当の具体化である。

### 状態表現

- `Coord`: 座標、距離、移動、到達座標計算を持つ。
- `PickDrop`: アーム長、根座標、向き、コストを持ち、`dest()` で指先到達先を返す。
- `Robot`: 根座標、複数 `Arm`、`pickGrid`、`dropGrid`、各アームの予約 `orderByArm` を持つ。
- `Arm`: 長さ、現在向き、保持有無を持ち、`rotate` と `toggle` で操作を出す。
- `Robot2`: 方向状態列から必要回転列を作る別実装系。提出中では `armScale = min(V - 1, N >= 18 ? 5 : 4)` として盤面に応じて2冪長を選ぶ。
- 残り初期たこ焼き集合、残り目的地集合を盤面boolとして持ち、複数アームの同一対象衝突は予約で避ける。
- 前計算テーブル:
  - `state -> relative_pos`
  - `relative_pos -> state`
  - `current_state, target_state -> required rotations`

### 観測・制約・入力の扱い

- 盤面サイズ `N` に応じて、四隅まで届く程度の2冪長を選ぶ。
- 記事では、`N=15` なら `8,4,2,1`、`N=18..30` では `16,8,4,2,1` が必要になると説明している。
- 初期と目的が重なるマスは動かす必要がないため除外するのが自然である。
- 根を少し動かせば、2冪アームの到達格子の隙間も補える。

### 評価関数

- 記事は特定の評価関数を提示していない。
- 単純実装では、現在の指先位置から到達しやすい未処理たこ焼き・目的地を選び、必要ターン数や根移動距離を小さくする貪欲になる。
- 複数アームでは、同時に処理できる個数を優先する評価が自然である。

### 探索・構築・更新

- 前処理:
  - 全ての方向状態を列挙し、根からの相対座標を計算する。
  - 相対座標から方向状態への逆引き表を作る。
- 1本アーム:
  - 次に拾うたこ焼きまたは置く目的地を選ぶ。
  - そのマスが根から見て到達可能なら、逆引きで必要姿勢を得る。
  - 各関節を1ターンに90度ずつ目的姿勢へ近づけ、到着したら `P` する。
  - 到達不可または隙間にある場合は根を1マス動かして補正する。
- 複数アーム:
  - 各アームに別対象を割り当てる。
  - 同一マスへの `P` 操作衝突を避ける。

### 操作・クエリ・出力選択

- 木は直列2冪アームを1本または複数本、根または根近くから生やす。
- 操作列は、目標姿勢との差分から各関節の `R/L/.` を出し、指先が拾う・置く位置に来たターンで `P` を出す。
- 複数アームでは、頂点番号順の `P` 処理順を考慮し、置く先が既に埋まらないようにする。

### 時間配分・パラメータ

- 前計算は `4^k` 状態で、`k=5` なら1024程度なので軽い。
- アーム本数は `V` に応じて決める。
- 記事中の実演では、seed=0で1本53手、2本30手、追加の小型アーム込みで27手としている。

```text
    for state in product(4 directions, repeat=len(lengths)):
        pos = sum(direction_vector[state[i]] * lengths[i])
        pos_to_state[pos] = state
        state_to_pos[state] = pos
```

```text
move_fingertip_to(target_cell):
    rel = target_cell - root
    if rel not in pos_to_state:
        move root one step to make rel reachable
    desired = pos_to_state[target_cell - root]
    rotate each joint toward desired by at most 90 degrees
    if fingertip reaches target_cell:
```

## この解法の本質

2冪長のアームにすることで、木の回転操作を「座標と姿勢の変換テーブル」に落としている点が本質である。複雑な木探索をしなくても、目標座標から必要な関節状態を逆引きできるため、実装量を大きく減らせる。高順位を狙うより、まず動く強いベースラインを作るための設計思想である。

## 真似するならまず実装する部分

まず `4,2,1` の小さいアームで、全64状態の `state <-> relative_pos` 表を作る。次に、単一指で「未処理たこ焼きを拾う、未処理目的地へ置く」を繰り返す貪欲を実装する。複数アーム化は、単一アームで姿勢制御と出力が正しいことを確認してからでよい。
