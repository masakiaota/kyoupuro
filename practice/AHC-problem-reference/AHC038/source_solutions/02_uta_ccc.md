## 解法の全体像

`V` に応じて手動気味にアーム構造を決め、最大 `2M` ターン程度を深さとするchokudaiサーチを行う。各状態からは、その場を含む5方向へ根を動かした後、候補姿勢の中で評価値が最大の行動を1つ生成して次ターンのheapへ入れる。1周ごとにアーム長や初期位置を乱択で変え、同じ探索を回して良かった解を採用する。

評価は、拾うときは目的地集合の中心から遠い初期たこ焼きを高く、置くときは初期たこ焼き集合の中心から遠い目的地を高くする。残しにくい外側を先に処理するための評価である。

## 主要アイデア

- 多腕より多指を重視し、指先を増やして同時に複数個を処理する。
- 関節の相対角を `0..3` で持ち、根から順に姿勢を計算する。
- 指先の長さを変え、同じ親から伸びる葉が同じ対象を掴みにくいようにする。
- 葉操作は全組合せではなく、指先ごとに3通りを評価して独立に決める。
- 持つ・置くターンを分けず、各指の保持状態に応じて同じターンで持つ指と置く指を混在させる。
- 各ターンのheapに上位状態だけを残す。`IntervalHeap` で最小・最大を両方扱い、メモリを抑える。
- `HashSet` ではなくbitset、出力文字列のindex化、配列再利用などでNimの速度とメモリを詰める。

## 最終コードの構造

### 状態表現

- `State`
  - `score`: 累積評価値
  - `takoBitSet`: 残り初期たこ焼き集合
  - `destBitSet`: 残り目的地集合
  - `rotate`: 各頂点の親との相対角
  - `length`: 各辺長
  - `lengthKey`: 姿勢候補メモ用の長さキー
  - `pos0`: 根座標
  - `grab`: 各頂点が保持中か
  - `ans`: 出力文字列テーブルへのindex列
- `Vertex`: 親、長さ、手の基点か、指先かを持つ。
- `Solver`: 入力、アーム、残り集合、中心座標、マス評価、文字列テーブル、最良解をまとめる。
- `BitSet[450]`: 残りたこ焼き・目的地・使用予定マスをbit集合で表す。

### 観測・制約・入力の扱い

- 初期と目的が重なるマスは最初から完了として除外する。
- 残り初期たこ焼き `takoSeq` と残り目的地 `destSeq` にindexを振り、bitsetで管理する。
- 初期たこ焼き集合の中心 `s0`、目的地集合の中心 `t0` を座標平均で計算する。
- `N` に応じた `tempMap` から基幹アーム長を選ぶ。
- 初期根座標は中心付近、最終コードでは山登りにより長さや初期位置を変える。

### 評価関数

- たこ焼きを拾う位置 `p`: `10000 + dist2(T0, p)`。
- 目的地へ置く位置 `p`: `10000 + dist2(S0, p)`。
- 操作できない移動は、近い未処理対象までの距離に比例したペナルティを入れる。
- 状態スコアは、拾った・置いた操作の評価累積で、heapでは大きいものを残す。

### 探索・構築・更新

- `armDesign`:
  - `V` が大きいほど関節数と手の数を増やす。
  - 先端側に多くの指先を付け、指先長は `1,2,3,...` 系列を使う。
- `getPoints`:
  - 現在の基幹関節角と長さから、到達可能な基点座標・方向・操作列を列挙する。
  - 同じ長さ・回転状態はメモ化する。
- `getComb`:
  - ある手の基点位置と向きに対して、各指先の3回転を評価し、掴む・置く操作を決める。
  - 同じ対象を複数指で取らないよう `used` bitsetを使う。
- `getMove`:
  - 候補姿勢を全列挙し、手が2本ある場合は2本目の接続部の3回転も試す。
  - 最大評価の `armMove` と `operate` を返す。
- `chokudaiSearch`:
  - `turnHeap[t]` にターン `t` の候補を入れる。
  - 各状態から5方向を試し、次ターンheapへ上位だけ入れる。
  - 解が見つかったら `bestTurn` を短縮し、それ以降の探索範囲を狭める。
  - ループごとに長さまたは初期位置を1点変更する近傍で山登りする。

### 操作・クエリ・出力選択

- 出力文字列は直接状態に持たず、`strTable` で重複文字列をindex化して、状態にはindex列だけを持たせる。
- 最良状態の `ans` に、木定義、初期根座標、操作列の文字列indexが入る。
- 完了判定は `destBitSet.popCount() == 0`。

### 時間配分・パラメータ

- `eTime = 開始 + 2900ms`。
- 探索深さの初期上限は `2M`。
- 各ターンheapの保持数は概ね `300/N`。
- `M/V` が大きいケースでは貪欲寄りの解を先に使う発想が記事で述べられている。
- Nim向け高速化として `--mm:arc` 再コンパイル、bitset化、文字列index化、グローバル配列再利用、整数clock利用などが入る。

## 実装上重要な断片

```text
for t in 0..bestTurn:
    state = pop_best(turnHeap[t])
    for root_move in 5 directions:
        moved = copy(state)
        moved.root += root_move
        if getMove(moved, armMove, operate):
            apply rotations and P operations
            push top states to turnHeap[t+1]
        else:
            add distance penalty or skip
```

```text
getComb(hand_base):
    for each finger:
        for rotation in '.', 'R', 'L':
            leaf_pos = base + rotated_vector
            if can_put_or_take(leaf_pos) and not used:
                keep highest cell score
        reserve chosen target
```

## この解法の本質

「各ターンで良い1手を作る貪欲」と「ターンごとの複数状態を残すchokudaiサーチ」を組み合わせている。全操作組合せを展開せず、1状態あたりの分岐を5方向程度に抑えることで、探索の幅を状態多様性に使っている。さらに、中心から遠いマスを先に処理する評価により、終盤に孤立マスが残る状況を減らそうとしている。

## 真似するならまず実装する部分

最初はchokudaiサーチを入れず、`getPoints` と `getComb` による1手貪欲を作るのがよい。次に、状態をbitset化し、各ターンheapに上位数十個を残す簡易chokudaiサーチへ拡張する。アーム長の山登りは、完了解が安定してから入れるべきである。

## 注意点・未理解点

- 最終コードは高速化と調整が多く、パラメータの意図が記事だけでは完全には追えない。
- `getPoints` の姿勢メモは、長さキーと回転キーが崩れると誤った候補を返すため壊れやすい。
- 指先を独立に決める近似は厳密ではない。同じ対象や置き順の衝突を完全に扱うには追加管理が必要である。
- 記事でも、評価値の性能が探索の上限になると述べており、実行時間を増やしても評価が悪いと伸びにくい。
