## 問題の本質

AHC029は、所持金をカードに変換し、カードをプロジェクト進捗に変換し、プロジェクト完了で所持金に戻す循環を、1000ターンでどれだけ大きく回せるかの問題である。

増資カードにより、未来のカード・プロジェクト・報酬のスケールが倍々になるため、序盤から中盤は「何回増資できるか」が支配的になる。一方で、増資のコストで金欠になると良いカードを買えず、プロジェクトを現金化できない。したがって、単に増資を買うだけではなく、所持金、手札労働力、プロジェクト残務のバランスを保つ必要がある。

評価関数の中心は、カードとプロジェクトという未現金の資産を、どれだけ所持金相当として見るかである。カードは使うまで価値が実現しない。プロジェクトは完了するまで所持金にならない。ここを高く見積もりすぎると、手札や未完了プロジェクトを抱えたまま終わる。低く見積もりすぎると、良い先行投資や増資を逃す。

## 共通している考え方

- 増資カードは最重要だが、買う価格と残りターンを見ないと所持金を壊す。
- 通常労働は過剰労働、全力労働は過剰と悪いプロジェクト巻き込みを割り引く。
- プロジェクトは `v/h`、`v-h`、残務の小ささを組み合わせて評価する。
- カード・プロジェクト・所持金の単位を揃えないと、ルール同士が矛盾する。
- 終盤は有料カード購入を強く制限する。買ったカードを回収できないためである。
- カード種類の隠し分布は観測できるため、カード生成の推定に使える。
- 相対スコアでは、生スコア合計だけでなく、ログスコアやケース別勝率を見る必要がある。

## 解法の分類

- 貪欲型: utac、kaede2020の中心方針。カード使用と補充を別々またはまとめて評価する。
- ルールベース型: kaede2020、Moegi氏メモ。if文で増資、労働、キャンセル、終盤停止を決める。
- 終盤モンテカルロ型: rareshana。終盤だけ最終所持金を直接比較する。
- 短期プレイアウト型: eijirou、chokudai。上位候補だけを数ターン先読みする。
- 確率推定型: eijirou、rareshana、chokudai。観測カード種類から隠し分布を推定する。
- 評価関数設計型: eijirou、jetbead/chokudai。状態を所持金単位に換算する。

## 推奨して理解すべき順序

1. kaede2020を読み、問題の入出力、増資の重要性、単純貪欲の改善点を理解する。
2. utacを読み、カード使用・補充評価を具体的な式に落とす方法を学ぶ。
3. rareshanaを読み、終盤だけでもモンテカルロを入れる狙いと、同一未来条件の重要性を理解する。
4. jetbeadを読み、評価関数設計を「お金」基準で整理する。
5. eijirouを読み、上位候補モンテカルロと状態価値の作り込みを見る。

## 実装するならどのルートか

理解のための最小実装は、utacとkaede2020を混ぜた2段貪欲がよい。

- 使用カード:
  - 増資は即使用。
  - 通常労働は `w - overkill_penalty` 最大。
  - 全力労働は各プロジェクトへの同式の和。
  - キャンセルは `h-v` が大きいプロジェクトに使う。
- 補充カード:
  - 所持金不足は除外。
  - 終盤は無料カード優先。
  - 通常労働は `0.8*w - cost`。
  - 全力労働は `0.6*M*w - cost`。
  - 増資は価格上限と残りターンで判定。

上位化の方向は、eijirou型の「貪欲上位候補だけを短いモンテカルロで比較」である。全候補を深く読むのではなく、評価式で候補を7個程度に絞り、同じ未来分布で5から9ターン先読みするのが現実的である。

## 重要な実装要素

- 状態表現:
  - `money`, `L`, `turn`, `cards`, `projects`。
  - プレイアウト用には状態コピーを軽くする。プロジェクト残務は `damage` 差分で持つ方法もある。
- 評価関数:
  - 所持金はそのまま、または少し高めに評価する。
  - 通常労働は `w` より少し低い価値。
  - 全力労働は `M*w` より明確に低い価値。
  - プロジェクトは `v-h` と `v/h` の両方を見る。
  - 金欠・足踏み状態はペナルティを入れる。
- 近傍・候補:
  - 補充カード `r`、使用カード `c`、対象 `m` の組。
  - 同一手札カード、下位互換補充カード、特殊カードの同種高コストを削る。
- 差分更新:
  - 労働で完了したプロジェクトだけ補充。
  - キャンセルは該当プロジェクトの差し替え。
  - 増資は未来生成スケールだけを変える。
- 候補管理:
  - まず1手評価でソート。
  - 上位数候補だけ先読み。
  - 試行途中で悪い候補を落とす。
- 出力判定:
  - 全力労働、業務転換、増資は `m=0`。
  - 所持金が負になる補充カードを出さない。
  - 増資は20回まで。
  - 最終ターン後の補充は無料カードにする。
- パラメータ:
  - 増資価格上限。
  - 終盤購入停止ターン。
  - 全力労働の係数。
  - プレイアウト候補数、深さ、試行数。
  - カード種類分布の初期値。

## 落とし穴

- ローカルテスタと本番インタラクティブの入力順を混同するとTLEやREになる。
- 補充カードは使った手札位置に入る。別スロット管理にすると状態が壊れる。
- プロジェクト補充も完了・キャンセルされた同じ位置に入る。
- 提示カードの1枚目は無料通常労働カードなので、隠し分布推定に含めると偏る可能性がある。
- `2^L` はすぐ大きくなる。32bit整数では危険である。
- 増資を20回超えて出すとWA。
- 終盤に有料カードを買うと、絶対スコアが静かに下がる。
- 絶対スコア合計だけで改善判定すると、相対スコアで悪化することがある。
- モンテカルロで候補ごとに違う未来乱数を使うと、候補評価が乱数運に汚染される。

## 未解決・要検証事項

- 増資カードを即使用せず、手札にスタックしてまとめて使う戦略が本当に有効か。
- 所持金価値を何倍にするか、金欠ペナルティをどう滑らかに入れるか。
- 全力労働カードの価値係数を `M`、プロジェクト品質、残務分布でどう変えるか。
- `v/h` と `v-h` のどちらをどの局面で重視するか。
- N/Kが小さいケースに特化した別方針を入れるべきか。
- プレイアウト深さは9ターン程度がよいのか、ケースによって可変にすべきか。
