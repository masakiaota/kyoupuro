## 解法の全体像

最終方針は、カード使用と補充カード選択をそれぞれ独立した貪欲評価で選ぶ実装である。モンテカルロは記事序盤の構想にあるが、最終提出コードは状態コピーによる深い探索ではなく、評価式を詰めた高速な貪欲としてまとまっている。

カード使用では、労働力を大きく使いたい一方で過剰労働を強く罰する。補充カードでは、その場で使う価値と将来の買い置き価値を分けて評価し、正規分布の相補累積分布を使って「この価格ならどれくらい良い買い物か」を近似している。増資は、残りターンで回収できる見込みと価格上限を見て買う。

## 主要アイデア

- 使用カードの評価は、労働力、過剰労働、残務量の小ささを辞書順のように扱う。
- 通常労働・全力労働とも、`power - max(0, power - work - 2^L) * 2` を基礎にして、少しの過剰は許しつつ大きな過剰を避ける。
- キャンセルは `work - reward - const*2^L` で、残務に対して価値が悪いプロジェクトを消す。
- 業務転換は、労働カードが少ない、または同種カードを複数抱えるなど手札が悪い場合に強く使う。
- 補充カードの買い置き価値に、正規分布の生存関数 `ccdf` を使う。価格が平均との差でどの程度良いかを連続値で評価する。
- 増資カードは、現状維持で稼ぐ見込み `stay` と増資後の見込み `exc` を比較し、さらに `700 - 50*K` 程度の価格上限で足切りする。
- 終盤10ターン以下では、コストがかかるカードや非通常カードを選ばない。

## 最終コードの構造

### 状態表現

- `Status`
  - `project`: `M` 個の `[残務量, 価値]`。
  - `card`: `N` 枚の `[種類, 労働力, コスト]`。
  - `money`: 所持金。
  - `projectCnt`: ローカル再生用のプロジェクト消化数。
  - `investCnt`: 増資回数。
  - `investRate`: `2^L`。
- `AHC`
  - 入出力、ローカル更新、使用貪欲、補充貪欲を持つ。
  - `cardTypeDict`: 現在手札の種類数。
  - `cardTypeCnt`: これまで観測したカード種類数。補充評価の確率補正に使う。
  - `gList`: 標準正規乱数をソートした近似CDF用配列。

### 観測・制約・入力の扱い

- ジャッジ時とローカル時で入力順が異なるため、`isLocal` で分岐している。
- ジャッジ時は、カード使用後のプロジェクト一覧と所持金をそのまま受け取り、ローカル時は生成済み配列から補う。
- 補充候補は毎ターン `cardTypeCnt` に加算される。
- 増資カード使用時はジャッジから数値更新を受ける前に `investCnt` と `investRate` を更新する。
- 所持金が負になる補充カードは候補から外す。

### 評価関数

- 使用貪欲:
  - 通常労働: `s = power - max(0, power - work - 2^L) * 2`、同点補助に `-work`。
  - 全力労働: 各プロジェクトについて同様の値を足し合わせる。終盤は実際に削れる `valid` を重視する。
  - キャンセル: `work - reward - 2*2^L`。
  - 業務転換: 各プロジェクトのキャンセル価値を合計。労働カードが少ない、または増資を複数抱える場合は極大評価。
  - 増資: 極大評価で即使用。
- 補充貪欲:
  - 通常労働の買い置き価値は `power * ccdf((cost-power)*3/power) * 0.6 - cost`。
  - 全力労働の買い置き価値は `power*M * ccdf((cost-power*M)*3/(power*M)) * 0.7 - cost`。
  - その場で使う価値は、現在のプロジェクトに当てたときの削り価値からコストを引く。
  - キャンセル系は所持枚数上限を設け、悪いプロジェクトがあるときにだけ買う。
  - 増資は `exc - cost > stay` なら買う。`exc` は残りターン、`K`、`M` を使った増資後期待値。

### 探索・構築・更新

- `greedy` が1000ターンを回すメイン。
- 各ターンで `useGreedy` により使用候補を全列挙し、最大評価の `(c, m)` を選ぶ。
- カード使用後、ジャッジからプロジェクトと所持金、補充候補を受け取る。
- `choiceGreedy` で補充候補を評価し、最大評価の `r` を選ぶ。
- コード中にはプロジェクト・カード生成配列や正規分布近似があるが、最終提出の意思決定は貪欲であり、記事上のプレイアウト構想は使われていない。

### 操作・クエリ・出力選択

- まず `useGreedy` の結果を `c m` として出力する。
- `card[c]` を欠番扱いにし、手札種類カウントを減らす。
- 補充候補を読み、`choiceGreedy` の結果 `r` を出力する。
- `card[c]` に選んだ補充カードを入れ、所持金からコストを引く。

### 時間配分・パラメータ

- PyPy で 587ms 程度の実行時間。2秒制限に対してかなり軽い。
- 終盤10ターンでは有料カード・特殊カードを買わない。
- キャンセルカードは終盤950ターン以降は買わない。
- 増資の価格上限は概ね `700 - 50*K` に `2^L` を掛けたもの。
- 全力労働の買い置き係数は `0.7`、通常労働は `0.6`。
- 観測済みカード種類数を使って正規分布評価やカード希少性を補正する。

## 実装上重要な断片

```text
use_greedy(state):
    for each hand card:
        if normal:
            for each project:
                score = power - overkill_penalty(power, h, L)
        if all:
            score = sum(power - overkill_penalty(power, h_i, L))
        if cancel:
            score = h - v - margin
        if invest:
            score = INF
    return max(score)
```

```text
choice_greedy(candidates):
    if late_turn:
        choose only free normal card
    for candidate:
        if cost > money: continue
        score = max(immediate_use_value, stock_value)
        if invest:
            score = exc if exc - cost > stay and price_ok
    return max(score)
```

## この解法の本質

強い探索を入れるより、カード使用と購入の評価式を現実の挙動に合わせて細かく調整した解法である。特に「過剰労働を避ける」「ただし労働力を小さくしすぎない」「増資は残りターンと価格で判断する」「終盤は買わない」という、スコアを壊しやすい点をルール化している。

## 真似するならまず実装する部分

`useGreedy` と `choiceGreedy` の2段貪欲を最初に実装するのがよい。通常労働、全力労働、増資だけで始め、その後キャンセル系と終盤の買い控えを足す。正規分布の `ccdf` は後回しでもよく、まずは `w - cost` と `M*w - cost` の係数調整で近い形を作れる。

## 注意点・未理解点

- 記事本文の「最終方針」とコードの細部は一部対応が読み取りにくい。特に補充カード評価の式は脚注表示が崩れている箇所があり、コードを優先して解釈した。

- 増資の `exc` 係数はパラメータ調整依存が大きい。
- 全力労働カードは過剰労働とターン短縮のバランスが壊れやすく、記事中でも一度大きく悪化している。
