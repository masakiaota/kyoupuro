## 解法の全体像

序盤から中盤はルールベース貪欲で進め、終盤だけモンテカルロで先読みする方針である。最初はコスパの良いプロジェクトとカードを選び、増資は買える限り買って使う。終盤に最終所持金を最大化するため、800ターン頃から50から100ターン先までランダム生成つきでシミュレーションし、カード使用・補充選択を評価する。

改善の中心は、未来生成の分布を観測済みカード種類から推定すること、候補ごとのシミュレーション条件を揃えること、無料キャンセルカードや極端に悪いプロジェクトへのキャンセルを使うことである。

## 主要アイデア

- まず `v/h` が高いプロジェクトを狙い、カードのターンあたり利益を最大化する。
- 増資カードは買えるなら買い、持っていれば最優先で使う。
- 全力労働カードも候補に含めるが、最初は最良プロジェクトに対する利益で近似する。
- 終盤だけモンテカルロを入れ、最終所持金が下がるルールベースの欠点を補う。
- カード種類の隠し分布を、基本分布と観測頻度の混合で推定する。
- モンテカルロで候補比較するとき、生成される未来カード・未来プロジェクトを候補間で同一にする。
- 無料キャンセルカードを持っていないなら買い、残務量が価値の30倍程度あるプロジェクトを消す。
- N/M/Kに応じてモンテカルロ試行回数を調整し、時間制限を使い切る。

## 最終コードの構造

### 状態表現

- `Project { h, v }`
- `Card { t, w, p }`
- `Solver`
  - `turn`, `invest_level`, `money`
  - `projects`, `cards`
  - `prob_upper`: 未来カード生成用の累積確率。
  - `card_ctr`: 実際に出たカード種類の観測数。
  - `monte_num`: モンテカルロ試行数。
  - `monte_start`: モンテカルロ開始ターン。中間コードでは900、記事では改善後に800頃から。
- ローカル用 `Judge` がプロジェクト・カードを問題文通り生成する。
- 最終提出では `TimeKeeperDouble`, `Randomize`, `prob_initialize`, `use_card_local`, `select_normal_next_card`, `select_next_card` があり、未来生成と終盤評価の実装が残っている。

### 観測・制約・入力の扱い

- 実際に提示されたカード種類を数え、基本分布と混ぜて `prob_upper` を作る。
- `turn >= 500` では観測分布を優先し、それ以前は基本分布との線形混合にする中間コードがある。
- 未来プロジェクトは問題文の生成式でランダム生成する。
- 補充候補1枚目は無料通常労働カードとして生成する。
- 所持金不足の補充カードは候補外にする。
- `invest_level <= 20` を常に確認する。

### 評価関数

- ルールベースの使用:
  - 増資カードは即使用。
  - 全力労働カードがあれば優先して使う。
  - 通常労働カードは、良いプロジェクトに対し過剰労働が少ないものを選ぶ。
  - キャンセルは、極端にコスパの悪いプロジェクトに使う。
- プロジェクト選択:
  - 早期は `v/h` が最大のプロジェクト。
  - 終盤・モンテカルロ中は残務量が小さいプロジェクトを重視するコードがある。
- 補充カード:
  - 増資カードは投資レベルが一定未満なら優先。
  - 労働カードは、良いプロジェクトに対するターンあたり利益 `(v - turn*p) / turn` で比較する。
  - 全力労働カードはプロジェクト数を掛けた補正を入れる。
  - キャンセルカードは無料かつ未保持なら買う。

### 探索・構築・更新

- `solve_simulated` が、指定した初手の使用または補充を適用し、その後は `select_normal_action` と `select_normal_next_card` で最後まで、または一定深さまで進める。
- `select_action` はモンテカルロ開始前なら通常貪欲、開始後なら各カード・対象を試して平均所持金が最大のものを選ぶ。
- `select_next_card` もモンテカルロ開始後は各補充候補を試し、平均所持金が最大のものを選ぶ。
- 候補間で同一の未来カード・未来プロジェクトを使う改善により、乱数の当たり外れで候補評価が歪むのを減らす。
- 最終提出では `monte_num` を持ち、確率初期化後に局所シミュレーションで補充候補を比べる構造が確認できる。

### 操作・クエリ・出力選択

- 通常時:
  - `select_normal_action` で `(c, m)` を選び出力する。
  - ジャッジ更新を読み、`select_normal_next_card` で `r` を出力する。
- 終盤モンテカルロ時:
  - 使用候補や補充候補ごとに状態コピーを作る。
  - 複数回シミュレーションして平均所持金で比較する。
  - キャンセル系補充は基本的に除外する中間コードもある。

### 時間配分・パラメータ

- 初期は最後100ターンのみモンテカルロ。
- 改善後は、50ターン先まで見る代わりに800ターン頃からモンテカルロ。
- さらに計算改善後は先読みを100ターンまで伸ばしたとある。
- `monte_num` は `N*M*K` に応じて調整。中間コードでは `18*35/(N*M)` のような補正がある。
- 極端に悪いプロジェクトのキャンセル目安は、残務量が価値の30倍程度。

## この解法の本質

終盤の「今買ったカードが最後までに回収できるか」「今進めたプロジェクトが最終所持金に変わるか」を、短いルールだけで判断するのは難しい。そこで、序盤は安い貪欲で走り、終盤だけランダム未来を揃えて比較することで、最終所持金を直接最適化しようとしている。

## 真似するならまず実装する部分

まず `v/h` が高いプロジェクトを狙う貪欲、増資即使用、労働カードのターンあたり利益評価を作る。その後、800ターン以降だけ、候補ごとに同じ未来列を使う短いモンテカルロを追加する。カード種類の観測分布混合は、その次に入れるとよい。
