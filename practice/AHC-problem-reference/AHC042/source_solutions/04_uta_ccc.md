## 解法の全体像

鬼を落とす順番を焼きなましで最適化する。順番が1つ決まると、シミュレーションでその順に鬼を処理する。各鬼について、上下左右4方向に落とす場合の評価値を計算し、最もよい方向を選ぶ。進路上に福があれば、直交方向へ1マスずらせるならどかす。進路近くに鬼がいれば、直交操作で巻き込んで一緒に落とす。

焼きなましの状態は、初期の鬼に付けたIDの順列である。近傍はswap、挿入、先頭末尾移動、完全シャッフル。評価は、その順列を使って実際に操作列を構築したときの手数であり、全鬼を落とせなければ `inf` になる。

## 主要アイデア

- 盤面上の鬼を左上から順にID付けし、落とす順番を順列として持つ。
- 順番が決まったら、各鬼をその時点の位置から4方向評価で貪欲に落とす。
- 方向評価は、外周までの距離、進路上の福を逃がす手数、巻き込める鬼の数を使う。
- 進路上の福は、外周に福が出ない直交方向へ1マス動かして退避する。
- 進路近くの鬼は、福退避と同じような直交操作で対象ラインへ引き込む。
- 焼きなましは順列だけを変更し、操作列は毎回シミュレーションで作り直す。
- 同じ順列の評価をハッシュでメモ化する。

## 最終コードの構造

### 状態表現

- `Solver`:
  - `oni`: 鬼数。
  - `pos0`: 初期鬼IDごとの初期座標。
  - `pos`: 現在シミュレーション中の鬼IDごとの座標。落ちた鬼は `(-1,-1)`。
  - `state`: 現在盤面。
  - `cur`: 焼きなまし中の順列。`Deque[int]`。
  - `ans`: 現在順列から生成した操作列。
  - `res`: ベスト操作列。
  - `turn`: 現在シミュレーションの手数。

### 観測・制約・入力の扱い

- `prepare` で入力盤面を保持し、`x` の座標を `pos0` に登録する。
- 各 `solve` 呼び出しで、`pos = pos0`、`state = C`、`turn = 0` に戻す。
- `checkUp/Down/Left/Right` は、対象操作で外へ出る外周セルが福でないかを見る。
- 各 `shift` は盤面を1マス動かし、同じ行・列にいる鬼IDの座標も更新する。
- 鬼が盤外へ出たら、その鬼IDの座標を `(-1,-1)` にする。
- 全鬼が盤外なら手数を返し、残っていれば `inf` を返す。

### 評価関数

焼きなましの評価は、順列を使って作った操作列の手数である。

```text
eval(order) = solve(order)
if all oni removed:
    return turn_count
else:
    return INF
```

各鬼を落とす方向選択では、4方向に局所スコアを作る。

- 基本は外周までの距離。
- 進路上の福は、逃がせるなら `+1`。
- 逃がせない福があれば `inf`。
- 進路上の空きマスの直交隣に鬼がいて、外周に福を出さず引き込めるなら `-1`。

コードでは、左・右・上・下それぞれについて同じ形の判定を手書きしている。

### 探索・構築・更新

- `solve`:
  - 順列 `cur` の先頭から鬼IDを見る。
  - すでに他の操作で落ちている鬼はスキップする。
  - 現在位置から4方向の局所スコアを計算する。
  - 最小スコアの方向を選び、実際に福退避・鬼引き込み・排出操作を行う。
  - 最後に全鬼が落ちていなければ `inf`。
- `annealing`:
  - 初期順列は `0,1,...,oni-1`。
  - 温度は `10.0` から `1.0` へ指数的に下げる。
  - 近傍重みは `[80, 50, 20, 20, 1]`。
  - 近傍は2点swap、別位置へ挿入、先頭を末尾へ、末尾を先頭へ、完全シャッフル。
  - `diff = best - score` とし、改善または温度付き確率で採択する。
  - 不採択なら順列変更を巻き戻す。

### 操作・クエリ・出力選択

- 方向決定後、必要なら福を直交方向に1手逃がす。
- 進路上の空きマスに隣接する鬼を見つけたら、直交方向へ1手動かして対象ラインに入れる。
- その後、目的方向に1手ずつ押して鬼を外へ出す。
- ベスト更新時の `self.ans` を `self.res` に保存し、最後に `res` を出力する。

### 時間配分・パラメータ

- 焼きなまし時間は約1.98秒。
- 温度は `t0 = 10.0`, `t1 = 1.0`。
- 近傍重みはswap 80、挿入 50、先頭末尾 20、末尾先頭 20、完全シャッフル 1。
- 記事によると、実装時に近傍のインデックス範囲を `0..N-1` にしていたバグがあり、修正すると平均2,3ターン縮んだとのこと。提出コードにも `rand(N-1)` が残っており、この点は記事で自覚されている。

## 実装上重要な断片

順列評価は次の形である。

```text
solve(order):
    reset board, positions, ans
    for id in order:
        if pos[id] is outside:
            continue
        scores = evaluate four directions from pos[id]
        dir = argmin(scores)
        if score[dir] == INF:
            continue
        while target oni is not outside:
            move blocking fuku away if needed
            pull adjacent oni into path if beneficial
            shift target line toward dir
    return turn if all oni outside else INF
```

焼きなましは次の形である。

```text
cur = [0, 1, ..., oni-1]
while time remains:
    typ = weighted_random([swap, insert, rotate_left, rotate_right, shuffle])
    apply typ to cur
    score = memo.get_or_insert(hash(cur), solve(cur))
    if accept(best - score, temperature):
        if score < best:
            best = score
            res = ans
    else:
        rollback cur
```

## この解法の本質

この解法の本質は、大域的に難しい「どの操作をするか」を、鬼の処理順という小さな順列最適化に落としている点である。順番さえ決めれば、各鬼をどう落とすかは4方向評価の貪欲に任せる。この分解により、焼きなましの状態が40要素程度の順列になり、実装しやすい。

また、方向評価に「巻き込める鬼」を直接入れている点が効いている。AHC042は1体ずつ落とすと平均手数が足りないため、進路周辺の鬼を集めて同時に落とす必要がある。順番焼きは、この巻き込みが起きやすい順序を探す探索になっている。

## 真似するならまず実装する部分

まずは鬼IDの順列を固定し、その順に「4方向のうち最も外周距離が短く、福を落とさない方向へ押す」シミュレータを作る。その後、進路上の福を直交方向へ逃がす処理を追加する。

次に、進路隣接の鬼を1手で引き込む処理を入れる。最後に、順列に対するswap・挿入だけの山登りまたは焼きなましを実装するとよい。

## 注意点・未理解点

- 提出コードでは近傍の乱択インデックスが `N-1` ベースになっており、鬼数 `2N` 全体を十分に触れていない。記事でもこのバグに触れている。
- 方向評価で「経路上の鬼の数は見落としていた」と記事にある。評価は完全ではない。
- 各方向処理が手書きで長く、上下左右の添字ミスが起きやすい。
- 福を退避できるかの判定は、外周セルと隣接セル条件に依存する。ここを間違えると福を落としてWAになる。
- 順番焼きは、1回の近傍で解全体が大きく変わることがある。メモ化しても評価コストは重めである。
