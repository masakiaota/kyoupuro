## 解法の全体像

記事は、本番中の方針と感想戦での改善解析を段階的に説明している。本番中は、まず「今すぐ落とせる鬼を多く含む行・列を選ぶ」貪欲を実装し、その後、同じ評価関数を使ってchokudaiサーチ風のビームに拡張している。候補は、福にぶつかるまでの区間をまとめて押す操作であり、`殺せる鬼数 / 手数` のような効率で選ぶ。

感想戦では、wata氏の「過去改変型貪欲」を解析している。これは操作列の末尾だけでなく、既存操作列の途中にも新しい操作を挿入する貪欲である。ある時刻に操作を挿入した場合の最終位置を、操作列を逆から辿って評価し、外周までの距離総和を改善する操作を選ぶ。さらに、1手挿入だけでは詰むため、同じ操作の連打挿入を許すと大幅に伸びると説明している。

## 主要アイデア

- 本番貪欲では、福に遮られるまでの行・列区間を候補にし、複数手を一括実行する。
- 候補評価は、おおむね `kill_count / move_count`。
- chokudaiサーチ版では、各状態から一括操作候補を展開し、`現在手数 + 貪欲見積り` の小さい状態を残す。
- 感想戦の過去改変型貪欲では、操作列の任意位置へ操作を挿入する。
- 挿入候補の評価では、逆向きに操作を辿り、現在時刻のマスが最終的にどこへ行くかを計算する。
- 評価は、鬼の外周までの距離総和と残り鬼数を使う。
- 1手挿入だけでなく、同じ操作の `k` 手連打挿入を許すと詰みを回避しやすい。

## 最終コードの構造

記事中の最終相当コード `62421026` は読めなかったため、読めた提出群と記事本文から分けて整理する。

### 状態表現

本番貪欲・chokudaiサーチ:

- 盤面は `vector<string>` または `array<string,20>`。
- 操作は `(char dir, int lane, int repeat)` のように、同じ操作の連打をまとめて持つ。
- chokudaiサーチの `Game` は以下を持つ。
  - `s`: 盤面。
  - `op`: ここまでの操作列。一括操作と回数の列。
  - `cur`: 現在手数。
- ビーム候補は深さごとのsetと固定配列で管理する。

過去改変型貪欲:

- `res`: 現在の操作列。1手単位の `(dir,lane)`。
- `fie`: `res` を適用した現在盤面。
- `finp[20][20]`: ある時点の各マスが、最終的にどの座標へ行くかを表す対応表。盤外は `out`。
- `revins`: 逆再生時に、盤外へ出ていた文字を戻すための列。

### 観測・制約・入力の扱い

- `act(d,p,k,s)` は、同じ操作を `k` 回まとめて盤面へ適用する。
- 候補生成では、行・列を外側から見て、福に当たった時点でその方向の区間を打ち切る。
- 福が外へ出る候補はそもそも生成しない。
- 過去改変型では、ある時刻に操作を入れた場合に福が盤外へ出るかを、最終位置対応 `finp` と現在盤面 `fie` から判定する。

### 評価関数

本番貪欲:

```text
f(kill, move) = 1_000_000 * kill / move
```

各行・列・方向について、福にぶつかるまでに含まれる鬼数 `kill` と必要手数 `move` を数え、最大の候補を選ぶ。一定回数、鬼を落とせない操作が続くと停止する。

chokudaiサーチ:

```text
state_estimate = current_turn + greedy_eval(board)
```

`greedy_eval` は残り盤面から本番貪欲を走らせた見積り手数であり、落とし切れない場合は大きな値を返す。

過去改変型貪欲:

```text
dist(i,j) = min(i+1, N-i, j+1, N-j)
eval(xs, xc) = 10000 * xs + xc
xs = remaining oni の外周距離総和
xc = remaining oni 数
```

`62417249` の試作コードではこの評価が使われている。記事の468028点版では、距離総和を主比較、落とした鬼数をタイブレークに使ったと説明されている。

### 探索・構築・更新

本番貪欲:

- 全行・列・方向について、福にぶつかるまでスキャンする。
- スキャン中に鬼数と手数を数え、`kill/move` が最大の候補を選ぶ。
- 選んだ操作を `k` 回まとめて実行し、操作を出力する。
- 残り鬼がある間繰り返す。

chokudaiサーチ:

- `genCand` は、福にぶつかるまでの全プレフィックス長を候補にする。
- `beam` は深さごとの小さなコンテナを持ち、良い状態から順に展開する。
- 次状態は、候補一括操作を盤面コピーに適用して作る。
- 完了状態が出たら、現在最短手数 `rf` と結果を更新する。
- 未完了なら `cur + eval(board)` が小さい状態を次深さに残す。

過去改変型貪欲:

- 現在の操作列 `res` を適用して最終盤面を作る。
- その後、操作列を末尾から先頭へ逆に辿り、各挿入位置を評価する。
- 各位置で上下左右20本の操作候補を試す。
- 操作をその時刻に挿入したとき、鬼の最終距離総和と残り鬼数がどう変わるかを差分計算する。
- 最も評価がよい位置・操作を `res.insert(pos, hnd)` で挿入する。

記事で重要視している連打挿入は、上の「1手挿入」を `k` 回同じ操作に拡張するものだと読める。

### 操作・クエリ・出力選択

- 本番貪欲とchokudaiサーチでは、一括操作 `(d,p,k)` を出力時に `k` 行へ展開する。
- 過去改変型では、操作列 `res` は1手単位なので、そのまま出力する。
- どの方針でも、福を落とす候補は生成段階で排除する。

### 時間配分・パラメータ

- chokudaiサーチ版は約1.9秒で打ち切る。
- 読めたコードでは `RANGE = 10`, `MBM = 300` を使う。
- 本番貪欲では、鬼を落とせない操作が4または5回続くと停止する。
- 過去改変型試作は最大 `4N^2` 手のループで、毎回最良挿入を1手選ぶ。
- 連打挿入版の具体的な `k` の範囲や比較式は、429でコード未読のため確認できていない。

## 実装上重要な断片

本番貪欲の核は次である。

```text
while remaining_oni > 0:
    best = none
    for each row/col and direction:
        kill = 0
        move = 0
        scan from outer edge until fuku:
            move += 1
            if cell has oni:
                kill += 1
            update best by kill / move
    if no useful move:
        break
    apply best operation move times
```

過去改変型貪欲は次のように考える。

```text
for hand in 0..4N^2:
    board = apply(current_operations)
    if no oni:
        break

    best_insert = none
    mapping = identity final-position map

    for pos from current_operations.size down to 0:
        for operation in all 80 one-step operations:
            if operation at this pos does not drop fuku:
                delta = change of final distance sum and oni count
                update best_insert

        undo previous operation one step in board
        update mapping backward

    insert best operation at best position
```

連打挿入では `operation` を1手だけでなく、同じ `(dir,lane)` の連続列として評価する。

## この解法の本質

この記事の本質は、「良い貪欲は末尾に足すだけとは限らない」という点を明確にしていることだ。AHC042では、既存操作列の途中に1手を入れても、後続操作が同じなら解が完全に壊れるわけではなく、最終位置が変わるだけで評価できる。これにより、過去の操作列を後から改変する貪欲が成立する。

もう1つの本質は、評価を最終位置から逆算している点である。途中に挿入した操作の影響を毎回全シミュレーションせず、逆から見た「この時刻のマスは最終的にどこへ行くか」を使うと、挿入位置ごとの評価を差分で計算できる。

## 真似するならまず実装する部分

まずは本番貪欲を実装するのがよい。福にぶつかるまでの区間を見て、`kill/move` 最大の行・列連打を選ぶだけなので、盤面更新と福落下判定を確認しやすい。

次に、同じ候補生成を使った小さいビームまたはchokudaiサーチを作る。過去改変型へ進むなら、まずは「末尾だけに1手追加する貪欲」を作り、評価を外周距離総和にする。その後、操作列を逆再生して途中挿入を評価する。

## 注意点・未理解点

- 468028点の `62421026` は429で読めていない。連打挿入の正確な候補数、比較式、タイブレークは記事本文ベースの理解である。
- 過去改変型の逆再生では、外へ出た文字を戻す処理と最終位置対応表の更新が壊れやすい。
- 1手挿入だけでは局所最適で詰むケースがあり、記事では連打挿入が重要とされている。
- 本番貪欲は、今すぐ落とせる鬼だけを見るため、福を避けて鬼を集めるような遠回りは弱い。
- chokudaiサーチは状態コピーが多く、候補数と深さコンテナを増やしすぎるとTLEしやすい。
