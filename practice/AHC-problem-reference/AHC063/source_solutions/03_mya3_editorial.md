## 解法の全体像

好みの色列と頭から連続一致している範囲が1つ伸びるまでを1ステップとしてビームサーチする。各ステップのテーブルに状態を保持し、評価値の良い状態を複数回展開する。完成または行き詰まりになったら、前回のテーブルを再利用して最初のステップからやり直し、制限時間まで改善を狙う。

状態展開は、いくつかの行動列をまず分岐として適用し、その後は確率的に1つずつ行動列を選びながら次ステップまで進める構成である。

## 主要アイデア

- ステップは「一致接頭長が1つ伸びるまで」。
- 評価は `操作列の長さ + 0.5 * 盤面中心から各餌までのマンハッタン距離の和`。
- 展開回数が多い状態には評価値を悪くするペナルティを与え、同じ状態ばかり展開しない。
- 蛇はdeque的な構造で持つが、コピー高速化のためリングバッファ風のvector実装にする。
- 盤面には餌色のほか、体のインデックスに対応する負値を置き、噛みちぎり判定とリリース時刻計算を簡単にする。
- 4種類のパス探索を使う。
  - 餌のないマスだけを通るターゲットへのパス。
  - 頭から正しいしっぽまでの範囲で自分を噛みちぎるパス。
  - 他色餌を食べてもよいターゲットへのパス。
  - 1マスだけ進むパス。
- 方向順は24通りからランダムに選ぶ。

## 最終コードの構造

以下はEditorial本文とキャッシュ実装 `#74942882` から確認した構造である。

### 状態表現

- 蛇
  - 体1マスごとの通しインデックスと座標。
  - 頭に近いほどインデックスが大きい。
  - 1歩進むたびに新しいインデックスを先頭へ追加し、餌を食べない場合は尾を削除する。
  - 実装はdeque相当だが、状態コピーが多いためリングバッファ風vector。
- 盤面
  - 餌の色番号。
  - 蛇の体があるマスには `-体インデックス`。
  - これにより、体のどの位置か、いつ空くか、噛みちぎりになるかを求める。
- 行動列
  - 保留中の行動列を逆順で保持。
  - 必ず実行する行動列か、より良い行動列で更新可能な仮行動列かを区別する。

### 観測・制約・入力の扱い

- 「正しいしっぽ」は、頭から連続一致している範囲の末尾。
- 「ターゲット」は、次に付け足したい目標色の餌。
- 探索1は正しいしっぽが現在のしっぽであるときだけ行う。
- 探索1で見つからなかった場合、次に餌を食べるか噛みちぎるまでは再探索しない。
- 体インデックスから、あるマスを通れるようになるタイミングを考慮する。ただし、時間稼ぎで後から通れるようになるパターンまでは扱わない。

### 評価関数

評価値は次の形で、小さいほど良い。

```text
turns + 0.5 * sum(distance(center, food_pos) for each remaining_food)
```

餌が中心付近にまとまっていれば、後で回収に回る距離が短くなりやすい、という直感による評価である。

展開対象になるたびに評価値を1.1倍し、有望な状態を複数回使いつつ、同じ状態への偏りを弱める。

### 探索・構築・更新

- ビーム幅は20、展開対象は10個。
- 状態圧縮は、頭、頭の1つ後ろ、体長中央、しっぽの4点の位置をキーにし、同じなら評価値の良い状態を残す。
- 探索1
  - 餌なしマスのみを通ってターゲットへ向かう。
  - 短い順にいくつか見つけ、最短との差 `d_i` に対して `1/sqrt(1+d_i)` の重みで選択する。
- 探索2
  - 正しいしっぽまでの範囲で自分を噛みちぎり、復元後に探索1でターゲットへつなぐ。
  - ターゲット色を既に尾側に取り込んでいる場合、その位置も利用してステップを進める。
  - 噛みちぎり探索は移動距離15まで。
- 探索3
  - 探索1,2で見つからないときの仮行動。
  - 他色餌を食べてもよいターゲット探索で、探索1/2が見つかったら中断される。
- 探索4
  - 1マスだけ進む。
  - 優先度は餌なしマス、餌ありマス、噛みちぎり。

### 操作・クエリ・出力選択

- 初期行動列は `(探索1+2) -> 探索3 -> 探索4` の優先度で設定する。
- その後、`探索1 -> 探索2 -> 探索3 -> 探索4` の優先度で実行と再探索を繰り返し、次ステップまで進む。
- 完成、または行き詰まり時には探索テーブルを使い回して再試行し、制限時間内で最良解を出す。

### 時間配分・パラメータ

- ビーム幅は `kWidBeam=20`。
- 展開対象は `kWidExpand=10`。
- 直接探索の列挙上限は4、噛みちぎり候補は2、噛みちぎり探索距離は15。
- 他色餌あり探索の許容量は3。
- 時間制限は約1970ms。

## 実装上重要な断片

キャッシュ実装の `State` は、餌を正値、蛇体を負のbody indexとして `field` に埋める。蛇はhead offsetとサイズを持つvectorで、色列、正しく一致している長さ、保留移動列、再探索フラグ、二次移動フラグ、履歴移動、中心距離和をまとめて持つ。

`Advance` は餌を食べる場合、target色なら `correct_len` を伸ばし、違う色なら距離記録へ回す。体を噛む場合は、噛んだindexまで尾側を餌として盤面へ戻し、`correct_len` と回復用の移動列を調整する。beam node評価は `step + dsm/2` で、展開回数に応じて `score * 1.1^cnt` のように悪化させる。

候補生成は、正しい蛇かつ再探索必要なら餌なしstrict path、次に噛みちぎり+復元、次に他色餌ありtarget path、最後に1手進む順で行う。方向順は24通りをxorshiftでシャッフルして使い、状態重複は頭・尾・2番目・中央の4点で圧縮する。

```text
expand_state(state):
    initial = first_available([search1_or_2, search3, search4])
    branches = apply_initial_patterns(initial)
    for branch in branches:
        while prefix_not_extended:
            action = first_available([search1, search2, search3, search4])
            apply(action)
```

```text
after_bite_recovery:
    bite a body cell within correct prefix
    follow old body cells toward tail
    recover the same color order
    then let search1 handle the next target
```

```text
beam_loop:
    table[step].keep_best(width=20, compressed_by=4_body_points)

    restart from first step with table retained
```

## この解法の本質

この解法は、噛みちぎり後に「元の体を辿れば同じ順で復元できる」性質を中心にしている。正しい接頭長を守りながら体を短くしたり向きを変えたりできるため、噛みちぎりを探索上の安全な整理操作として扱える。

また、評価関数は操作列長と餌の集まり具合に絞られている。個々の経路選択は確率的なパス選択や4種類の探索優先度に任せ、評価は大局的な状態選別に使う構成である。

## 真似するならまず実装する部分

1. 体インデックスを盤面に埋めるシミュレータ。
2. 餌なしマスだけを通るターゲットBFS。
3. 噛みちぎり後に古い体を辿る復元。
4. `turn + 中心距離和/2` の評価で小さなビーム。
5. 探索3/4を詰まり対策として追加する。

状態圧縮や展開回数ペナルティは、基本の探索が動いた後に入れるのがよい。

## 注意点・未理解点

- キャッシュ実装で、状態表現、保留行動列、候補生成の細部は確認できた。
- 探索2で、ターゲット色を取り込んだ位置集合をどう効率よく管理するかは実装依存である。
- 「時間稼ぎで後から通れるようになるパターン」を捨てる近似は、再実装時に詰まりの原因になる可能性がある。
- 状態圧縮キーが4点だけなので、同じキーでも実際にはかなり違う状態が混ざる。評価値との相性が重要である。
