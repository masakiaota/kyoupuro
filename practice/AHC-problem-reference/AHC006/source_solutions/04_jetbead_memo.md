## 解法の全体像

このページは単一の実装解説ではなく、AHC006 の有効そうな方針を整理したメモである。問題を「50 件の注文選択」と「pickup-before-delivery 制約付きの TSP」として見ており、注文入れ替え時の最適位置挿入、依存関係を壊さない 2-opt、貪欲解、注文挿入ビーム、レストランと配達先を独立に計算して結合する方法、偏角ソートなどを列挙している。

特に強調されているのは、注文を削除して別注文へ置き換えるとき、置き換え注文を最適位置に挿入することの重要性である。

## 主要アイデア

- AHC006 は TSP に見えるが、50 注文の選択と pickup-before-delivery の依存関係が加わっている。
- 2-opt は依存関係があるため無条件には使えないが、依存関係が壊れない範囲なら有効である。
- 実際の良い解では、レストランが連続する区間や配達先が連続する区間があるため、2-opt が効く場面はある。
- 注文置換近傍では、削除した後のルートへ新注文を最適位置に挿入するのが強い。
- 挿入位置を全探索すると重いが、累積的な最小値を使うと軽くできる可能性がある。
- 他の候補方針として、単純貪欲、注文を挿入するビームサーチ、レストラン・配達先を独立に解く方法、偏角ソートが挙げられている。

## 最終コードの構造

### 状態表現

- 注文置換型なら、選択済み注文集合と、pickup/delivery を含む訪問順を持つ。
- 2-opt 型なら、ルート上の各訪問点がどの注文の pickup/delivery かを識別し、反転後に依存関係が守られるか判定する情報が必要である。
- ビーム型なら、部分ルート、選択済み注文、未配達注文集合、距離を状態に含めると考えられる。

### 観測・制約・入力の扱い

- 1000 注文から 50 件を選ぶ。
- pickup は対応する delivery より前に現れなければならない。
- 2-opt や順序変更では、反転区間内外の pickup/delivery の順序関係を壊さない判定が必要である。

### 評価関数

- 基本評価は総移動距離。
- 注文置換では、削除と挿入による距離差分を評価する。
- 挿入位置評価は、辺を点で分割する増分の和で表せる。

### 探索・構築・更新

- 有望な近傍:
  - 依存関係を壊さない 2-opt。
  - 選択済み注文を削除し、別注文を最適位置へ挿入する置換。
  - 注文を 1 件ずつ挿入していくビームサーチ。
- 置換近傍では、pickup の挿入位置と delivery の挿入位置を探索する。
- pickup より後ろに delivery を置く制約があるため、累積最小を使う設計が向いている。

## 実装上重要な断片

```text
valid_2opt(route, l, r):
    reverse route[l..r]
    for each affected order:
        pickup_position < delivery_position must still hold
    accept only if valid and distance decreases or SA accepts

replace_order(route):
    remove pickup/delivery of one selected order
    for each candidate new order:
        find best pickup position
        find best delivery position after pickup
    commit best or use as SA neighbor
```

## この解法の本質

このメモの本質は、AHC006 の改善操作を「ルート順序の改善」と「注文集合の改善」に分けて見ている点である。単純な TSP と違い、注文を入れ替えるだけでもルートが変わり、ルートを変えるだけでも依存関係を壊す可能性がある。そのため、近傍設計では制約を守りつつ十分大きく状態を動かす必要がある。

特に、注文置換を最適挿入と組み合わせる考え方は、threecourse や terry_u16 の方針とも共通している。

## 真似するならまず実装する部分

まずは注文置換ではなく、1 注文の最適挿入を実装するのがよい。次に、現在ルートから 1 注文を削除して別注文を最適挿入する山登りへ進む。2-opt は依存関係判定が壊れやすいため、ルートと注文位置を管理する実装に慣れてから入れるべきである。
