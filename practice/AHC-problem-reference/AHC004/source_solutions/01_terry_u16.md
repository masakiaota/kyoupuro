## 解法の全体像

入力文字列をそのまま20x20盤面に置くのではなく、まず重なりの大きい文字列ペアを長さ20以下の長い文字列へ貪欲にマージする。その後、マージ済み文字列列の「置く順番」と「横/縦向き」を状態として持ち、状態からは毎回決定的な配置貪欲で盤面を作る。

配置貪欲では、指定された順番で文字列を見て、既存文字と矛盾せず、かつ新しく埋めるマス数が最小の開始位置へ置く。順番と向きの初期値は長い順・全て横向きで、山登りでは近い位置のswapと1文字列の向き反転だけを試す。盤面を直接更新する探索ではなく、順序・向きという上位の構築パラメータを探索している。

## 主要アイデア

- 文字列同士の重なりは本質的な情報なので、前処理で長い文字列へまとめる。
- マージ後の文字列は20文字を超えない範囲に制限する。1行または1列に置ける単位として扱うためである。
- 状態は盤面そのものではなく、`(文字列ID, 向き)` の列で持つ。
- 盤面構築では、各文字列を既存盤面と最も多く重なる場所へ置く。評価は問題スコアを愚直に再計算する。
- 山登り近傍は、順番のswapと向き反転。改善したときだけ採択する。
- 実装では高速化よりも、文字列マージと構築方針を短時間で入れることを優先している。

## 最終コードの構造

### 状態表現

- `Input { m, s, since }`: 元の入力文字列と開始時刻。
- `InputStr = Vec<Vec<char>>`: 重複削除・マージ後の文字列列。
- `Output = Vec<Vec<char>>`: 20x20盤面。空きは `.`。
- `OrderAndDirection { order, direction }`: マージ後文字列の添字と、横 `(0, 1)` または縦 `(1, 0)` の向き。
- `orders: Vec<OrderAndDirection>`: 山登りで動かす状態。盤面はこの状態から都度再構築する。

差分更新用の盤面スコアや出現フラグは持たない。近傍を試すたびに `try_put` で盤面を作り直し、`compute_score_detail` で全文字列の出現を調べる。

### 観測・制約・入力の扱い

- 入力の `N` は読まず、定数 `N = 20` として扱う。
- 元文字列を長い順にソートする。
- `remove_duplicated_str` で完全同一の文字列を除く。ただし、別文字列に含まれる部分文字列を一般に削除する処理ではなく、同一文字列の重複削除である。
- `match_str` で前処理マージを行う。重なり長を11から4まで下げながら、suffix-prefix一致する2文字列を長さ20以下なら結合する。
- トーラスの添字は `mod_n` で0..19へ戻す。配置と出現判定は横・縦とも循環を考慮する。
- `.` は任意文字ではなく空きマスとして扱う。出現判定では、対象文字列の各文字と盤面文字が完全一致する必要がある。

### 評価関数

- 最終評価は問題文のスコアをそのまま再計算する。
- `compute_score_detail` は全入力文字列について、20x20の全開始位置と2方向を走査し、1つでも一致すればカウントする。
- `try_put` 中の配置候補評価は問題スコアではなく、新しく埋める `.` の個数 `exceed` の最小化である。矛盾なしで既存文字と最も重なる位置を選ぶ。

### 探索・構築・更新

- 前処理:
  - 元文字列を長い順にする。
  - 同一文字列を削除する。
  - 重なり長が大きいペアから、長さ20以下の結合文字列へ置き換える。
  - マージ後に再び長い順へ並べる。
- 構築:
  - 空盤面から始める。
  - `orders` の順に文字列を取り出す。
  - 指定向きで全開始位置を試し、既存文字と矛盾する候補を捨てる。
  - 新規に埋めるマス数が最小の候補へ実際に書き込む。
  - 置ける場所がなければその文字列は無視する。
- 山登り:
  - 初期状態はマージ後文字列を長い順、全て横向き。
  - 近傍1: 近い範囲内の2要素をswapする。コードでは `SELECT_WIDTH = 40`。
  - 近傍2: 1要素の向きを横/縦で反転する。
  - 新状態を全再構築し、問題スコアが改善した場合だけ採択する。

記事ではswapと縦横変更の2種類と説明されている。コードにも3つ目の「取り出して挿入」風の分岐が残っているが、乱数範囲が `0..2` なので実行されない。

### 操作・クエリ・出力選択

- 出力は山登り中の最良盤面である。
- 20行の文字列としてそのまま出力する。
- `.` を残すことへの積極的な最適化はない。全入力文字列を含めるボーナスは実質狙っていない。

### 時間配分・パラメータ

- 時間制限は `TL = 2.9` 秒で管理する。
- 山登りは時間いっぱいまで回す。記事では高々3000回程度と述べられている。
- swap対象は近い `SELECT_WIDTH = 40` 個以内から選ぶ。
- マージの最小重なりは4。重なり長11から4へ順に下げる。
- マージ後文字列数が50になったらマージを打ち切る。

## 実装上重要な断片

```text
try_put(orders):
    board = all '.'
    for (word_id, dir) in orders:
        best = none
        for start in all 20x20 cells:
            if word conflicts with existing letters:
                continue
            exceed = number of newly filled cells
            keep candidate with minimum exceed
        if best exists:
            write word to board
    return exact_score(board), board
```

```text
hill_climb:
    orders = words sorted by length, all horizontal
    score, board = try_put(orders)
    while time remains:
        new_orders = swap nearby pair or flip one direction
        new_score, new_board = try_put(new_orders)
        if new_score > score:
            orders = new_orders
            score = new_score
            board = new_board
```

```text
merge_words:
    for min_overlap from 11 down to 4:
        scan words
        find another word with largest suffix-prefix overlap
        if merged length <= 20:
            replace pair by merged word
        stop if word count reaches target count
```

## この解法の本質

この問題では、20x20の真の行列を復元するよりも、与えられた短い文字列をなるべく矛盾少なく詰め込む方が直接スコアに効く。TERRYの解法は、短い断片をまず「同じ行または列に由来しそうな長い断片」へまとめ、その長い断片を重なり最大で詰める。これにより、1つの配置操作が複数の元ヒントを同時に満たしやすくなる。

また、盤面を直接少しずつ変えると評価が重く、局所的な文字変更の意味も弱い。順番と向きだけを探索対象にし、盤面は強い貪欲で再生成することで、実装を短期コンテスト向けに抑えながら重要な構造だけを探索している。

## 真似するならまず実装する部分

最初に実装すべきなのは、マージなしの `try_put` である。文字列を長い順に見て、矛盾せず新規マス数が最小の場所へ置く。これでスコア計算、トーラス処理、横縦配置の基盤ができる。

次に、順番swapと向き反転の山登りを足す。最後に、suffix-prefix重なりで長さ20以下へマージする前処理を追加するのがよい。上位化の核はマージなので、盤面構築の高速化より先にマージを入れる価値が高い。

## 注意点・未理解点

- 記事では「部分文字列が4文字以上一致しているペアをマージ」とあるが、最終コードで確認できる主処理はsuffix-prefix一致のマージである。
- 最終コードは同一文字列を削除するが、一般の包含削除はしていないように読める。記事説明と完全には一致しない可能性がある。
- 山登りは改善のみ採択なので、局所解から抜ける力は弱い。記事でも焼きなましへの発展は望み薄としている。
- マージ時に「輪っかにする必要性」に本番中は気付いていなかったと注記されている。循環行として最適に結合する処理ではない。
- `.` を活かした全問包含後のボーナス獲得は狙っていない。
