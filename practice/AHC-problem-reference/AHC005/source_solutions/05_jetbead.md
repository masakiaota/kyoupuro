## 解法の全体像

この記事は実装済みコードの解説ではなく、AHC005の問題構造と上位勢の解法断片を整理するメモである。中心にある見方は「全道路が視界に入るような交差点の部分集合を通って戻るTSP」である。

記事の個人的メモでは、被覆判定を高速化するため、道路マス単位ではなく連続した道路列、つまり線分や辺にIDを振る方針が示されている。交差点を追加・削除したときに、その交差点から見える線分IDのカウントを更新すれば、全道路の被覆管理をマス単位の `O(N)` 更新から線分単位の軽い更新へ落とせる。

さらに、交差点集合の最適化とTSP順序の最適化を一緒に焼きなます方針、または道路列巡回として `(線分ID, 交差点ID)` の順番を最適化する方針が挙げられている。

## 主要アイデア

- 問題を「全道路が視界に入る交差点部分集合の巡回」と見る。
- 被覆判定は道路マス単位ではなく、連続道路列にIDを振って管理する。
- 交差点を選ぶと、その上下左右に対応する線分IDが被覆される。
- 交差点の追加・削除では、被覆カウントを増減し、未被覆線分数を差分更新する。
- 交差点巡回の場合は、交差点の追加・削除近傍と2-opt近傍を同じ探索に入れる。
- 道路列巡回の場合は、明示的に踏む線分と交差点の組を列として持つと自然である。
- 関連Tweetでは、上位勢の多くが「線分・辺・通りの順序」と「それを踏む交差点」を状態にしている。

### 状態表現

- 交差点ID。
- 縦横の連続道路列ID、または道路列を辺と見たID。
- `cover_count[line_id]`: 現在選択中の交差点集合により、その線分が何回見えているか。
- `uncovered_count`: `cover_count == 0` の線分数。
- 交差点集合ベースなら `selected_intersections` と巡回順。
- 線分巡回ベースなら、`targets = [(line_id, intersection_id)]` の列。
- 交差点間距離、または「あるマスからある線分へ最短で到達する交差点・距離」の前計算。

### 観測・制約・入力の扱い

- 縦方向・横方向の連続道路列を列挙し、それぞれにIDを振る。
- 各交差点について、上下左右に見える線分IDを前計算する。
- 線分上の各交差点との対応 `(線分ID, 交差点ID)` を持つと、どの線分をどの交差点で踏むかを明示できる。
- 被覆はマス単位で判定せず、全線分が1回以上被覆されるかで判定する。

### 評価関数

- 全線分が被覆されている状態では、巡回距離を最小化する。
- 交差点集合ベースでは、選択交差点を巡回するTSP近似距離が評価値になる。
- validでない状態を一時的に許すなら、未被覆線分数に大きなペナルティを置く必要がある。
- 線分巡回ベースでは、明示的に踏む線分列に沿った移動距離を評価する。

### 探索・構築・更新

- 交差点集合ベース:
  - 交差点を追加する。
  - 交差点を削除する。
  - 巡回順を2-optする。
  - 追加・削除時は線分被覆カウントを差分更新する。
- 線分巡回ベース:
  - 明示的に踏む線分の順番を入れ替える。
  - 線分に対応する交差点を選び直す。
  - 一部を破壊し、未被覆の遠い線分から再構築するような近傍も関連Tweetにある。
- phocom氏Tweetでは、辺を頂点と見る「辺の巡回順」の焼きなまし、2点swap・区間reverse・1点抜き挿しを同程度に混ぜる方針が示されていた。
- c7c7氏Tweetでは、訪れる線分順と各線分を訪れる交差点を解表現にし、1個または複数個を消して最適位置へ挿入する近傍が示されていた。

### 操作・クエリ・出力選択

- 最終状態が全線分を被覆していることを確認する。
- 巡回対象の交差点列または線分到達点列を、グリッド上の最短経路でつなぐ。
- 開始点から出発し、最後に開始点へ戻る移動列を出力する。

### 時間配分・パラメータ

- 記事自体に具体的な温度、試行回数、時間配分はない。
- 上位解法断片からは、交差点集合最適化とTSP最適化を同じ焼きなまし内で回すため、差分更新の軽さが重要と読める。
- 被覆管理を線分IDに落とすことは、交差点追加・削除近傍を多く回すための前提である。

## 実装上重要な断片

```text
add_intersection(v):
    for line in visible_lines[v]:
        if cover_count[line] == 0:
            uncovered_count -= 1
        cover_count[line] += 1

remove_intersection(v):
    for line in visible_lines[v]:
        cover_count[line] -= 1
        if cover_count[line] == 0:
            uncovered_count += 1
```

## この解法の本質

このメモの本質は、AHC005の制約を「見えるマス集合」ではなく「見える線分集合」として管理する点にある。視界は障害物で切られた縦横の連続道路列全体に広がるため、線分IDは問題構造とよく合っている。交差点を1つ選ぶだけで複数線分の被覆カウントが変わるので、局所探索の近傍を高速に評価できる。

また、上位勢のTweetからは、単に交差点集合を選んでからTSPを解くのではなく、被覆対象の線分順序と実際に踏む交差点を一体化して探索する方向が強かったことが分かる。これは、巡回対象が交差点そのものではなく「線分を見える状態にする行為」だからである。

## 真似するならまず実装する部分

まずは線分IDによる被覆管理を実装する。各交差点がどの線分を見えるか、各線分が現在何回被覆されているかを差分更新できるようにする。

その後、交差点集合の追加・削除と、巡回順の2-optを同じ状態で動かす。最初から線分巡回ベースの複雑な近傍に行くより、交差点集合ベースで被覆差分更新を正しく作る方がよい。
