## 解法の全体像

本番中は、単純に番号順でペアを連続回収する方針から始め、より近いペアを選ぶ貪欲、蛇腹走査、1枚目の順序を焼く方針へ進んでいる。最終的には、1枚目を取る順序を持ち、2枚目を逆順で取る構造をベースに、順序swapや1枚目・2枚目の入れ替えを焼きなまししたと読める。

復習では、1枚目を積んで2枚目を逆順で取る解に対して、1点削除・1点追加・2-optの山登りを試し、2枚連続回収や操作 `X`、多点スタート、移動型の `X` を追加して段階的に改善している。記事は完成コードの解説ではなく、どの方針が効いたかを記録する性格が強い。

## 主要アイデア

- まず全カードを消すことを優先し、番号順や距離貪欲で確実な解を作る。
- 「1枚目を取る順」と「2枚目を逆順で取る」を使えば、常にスタック制約を満たす。
- 初期解候補を複数作り、良いものを選ぶと改善が大きい。
- 近傍として、順序入れ替え、1枚目と2枚目の入れ替え、1点削除・1点追加、2-optを試している。
- 2枚連続で取るケースを混ぜると改善した。
- 操作 `X` を使う改善も復習で試し、最終的に大きな改善が出ている。
- 多点スタートは局所解脱出に有効だった。

## 最終コードの構造

以下は本文とキャッシュ実装 `#72856631` から確認した構造である。

### 状態表現

本番解法の中心は、おそらく次のような状態である。

- `order`: 1枚目を取るカード番号の順序。
- `dir[id]`: 同番号2枚のどちらを1枚目として扱うか。
- 出力順は `first(order[0]), first(order[1]), ..., second(order[-1]), ..., second(order[0])`。

復習後半では、全部の並び順を保持し、「開き括弧がある境界で閉じ、その間が完結した部分列」という制約で2枚を動かす方針も試している。これは正しい括弧列を直接持つ方向だが、記事ではスコアが伸びなかったとされている。

操作 `X` を入れた版の詳細な状態表現は本文からは分からない。移動型の `X` でPhase1/Phase2の改善が出たと記録されている。

### 観測・制約・入力の扱い

- 入力から各番号の2座標を持つ。
- 単純貪欲では、現在位置から1枚目までの距離と、1枚目から2枚目までの距離を足して近いペアを選ぶ。
- 渦巻きや外周・中心寄りの仮説を試し、初期解の平均を改善している。
- 1枚目順・2枚目逆順の形では、スタック制約は構造的に満たされる。

### 評価関数

主評価は移動回数 `K` である。記事ではseed0の `K` とスコア推移を使って改善を確認している。

```text
reverse_stack_order(order, dir):
    seq = []
    for id in order:
        seq.push(first(id, dir[id]))
    for id in reversed(order):
        seq.push(second(id, dir[id]))
    return move_distance(seq)
```

操作 `X` を含む版も、最終的な比較は同じく移動回数である。キャッシュ実装では、カードを空きマスへ移した場合の移動短縮量が正になる候補だけを実際に `Z`/`X` で挿入する。

### 探索・構築・更新

本番中の流れ:

- 番号順に近い方の1枚目、次に2枚目を連続回収。
- 現在位置からのペア回収距離が小さい順に選ぶ貪欲。
- 蛇腹状に1枚目を取り、山札トップにある2枚目を順に回収。
- 1枚目を取る順を焼きなましし、近傍は順序入れ替えと1枚目・2枚目の入れ替え。
- 実行時間を1.9秒から1.99秒へ伸ばす小調整。

復習の流れ:

- 1枚目を出し、2枚目を逆順で取る。
- 1点削除・1点追加・2-optの山登り。
- 2枚連続で取る動きを追加。
- 初期貪欲で「今の場所から近い」だけでなく「1枚目と2枚目が遠い」候補も増やす。
- 貪欲のみでも改善。
- 正しい括弧列全体を持って2枚を動かす方針は伸びなかった。
- 多点スタートを追加。
- 操作 `X` の移動を追加し、Phase1/Phase2でさらに改善。

### 操作・クエリ・出力選択

- `X` なし版では、`order` から決まる順に移動して `Z` を出す。
- 2枚連続で取る追加は、同じ番号をすぐ閉じる `()` 型の部分を混ぜるものと解釈できる。
- `X` あり版は、記事から具体的な置き場所・タイミングは読み取れない。

### 時間配分・パラメータ

- 実装では10個の初期候補にそれぞれ0.12秒のPhase1山登りを行う。
- Phase1近傍比率は再挿入5%、2-opt85%、double切替10%。
- Phase2は0.75秒で、再挿入30%、2-opt69%、double切替1%。
- 多点スタート候補は、始点近傍とペア距離の長短を混ぜて作る。

## 実装上重要な断片

キャッシュ実装では、状態は200個の値順 `seq` と、各値を2枚連続で回収するかを表す `is_double` で持つ。非doubleの値は1枚目を順に取り、残り側を逆順で取りに戻る。`eval_with_double_correct` がこの列を実際の移動距離に評価し、各値の向き `flip` も同時に決める。

初期解は、始点候補を10個作ってから、現在位置 `cur` と逆順回収側の末尾 `last` の両方を見て未使用値を貪欲に追加する。近傍は1点再挿入、2-opt、2枚連続回収フラグ切替で、Phase1/Phase2とも改善した場合だけ採用する山登りである。

出力時には `X` も使う。予定された回収順を進める途中で、現在位置と目標の矩形内に空きマスがある場合、最大30個の空きと最大80個の将来カードをサンプリングし、移動短縮効果が正なら `Z` で拾って空きへ運び `X` で置く。これにより本文の「移動型X」を実装している。

1枚目順・2枚目逆順の最小実装は、常に正しいスタック操作になる。

```text
make_sequence(order):
    for id in order:
        take first[id]
    for id in reverse(order):
        take second[id]
```

山登りの基本形は、順序を少し変更して距離が短くなれば採用する。

```text
try_neighbor():
    old = current_sequence_cost
    modify order or orientation
    new = current_sequence_cost
    if new <= old:
        keep
    else:
        rollback
```

多点スタートは、初期解生成の揺らぎを増やし、各初期解から局所改善する。

## この解法の本質

競技中に実装可能な単純構造から始め、正しさを保ったまま段階的に探索対象を広げている点が本質である。特に「1枚目順、2枚目逆順」は制約処理が非常に簡単で、初期解や山登りの土台として扱いやすい。一方で、上位解法のように任意の入れ子構造を高速に動かすには、配列や木の状態設計が必要になることも記事の失敗記録から分かる。

## 真似するならまず実装する部分

理解目的なら、まず1枚目順・2枚目逆順の解を作る。次に、`order` のswap、2-opt、各番号の向き反転を山登りする。これでスタック制約を意識せずに改善できる。上位化したいなら、正しい括弧列全体や木構造へ移行し、2枚連続回収や部分列を包む操作を扱えるようにする。

## 注意点・未理解点

- キャッシュ実装では、状態、評価、Phase比率、`X` の置き換え処理まで確認できた。
- `X` は厳密最適化ではなく、矩形内の空きと将来カードをサンプリングして正の移動短縮がある場合だけ使う貪欲後処理である。
- 「全部の並び順を保持して2枚を動かす」方針が伸びなかった理由は、近傍・差分・初期解のどれが支配的か不明である。
- 1枚目順・2枚目逆順は実装しやすいが、入れ子構造の自由度が狭く、上位解法には届きにくい。
