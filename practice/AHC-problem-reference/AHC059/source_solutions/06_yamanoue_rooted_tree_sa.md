## 解法の全体像

操作 `X` を避け、入れ子が維持された回収順、つまり正しい括弧列を焼きなましする方針である。正しい括弧列は「子の順序情報付き根付き木」として見なせるため、状態は根付き木と、各番号の2枚の訪問順情報になる。

木に対して、同じ番号の2枚の訪問向き入れ替え、子ノードの訪問順序reverse、ノード移動、ノード交換といった近傍を用いる。記事では長時間焼くと大きく改善したが、最終的には初期温度を低くした方が良く、実質的に山登りが強かったと振り返っている。

## 主要アイデア

- `X` を捨てて、拾う順だけを最適化する。
- 入れ子維持の順序を根付き木として表す。
- 各ノードはペア1組、子順はそのペアの内側で取るペア順を表す。
- 2枚のどちらを先に訪れるかも状態に含める。
- 木の近傍として、向き入れ替え、子順序reverse、node移動、node交換を使う。
- node移動が強く、子順序の区間reverseは弱めだったという観察がある。
- 低温の方が良く、悪化受理より山登り的な改善が効いた。

## 最終コードの構造

コードなし。以下は本文から読み取れる構造である。

### 状態表現

- 根付き木。根はダミーで、各ペアが1ノード。
- 各ノードはカード番号、2枚の訪問向き、子ノード列を持つ。
- DFSで `entry(node), children..., exit(node)` の順に出力する。
- スコアはDFS列のマンハッタン移動距離。

木の模式図は次のように考えられる。

```text
root
├─ A
│  ├─ B
│  └─ C
└─ D

出力: A_in, B_in, B_out, C_in, C_out, A_out, D_in, D_out
```

### 観測・制約・入力の扱い

- 入力から各番号の2座標を取得する。
- 操作 `X` は使わない。
- 木のDFS順なら、任意のノードの内側に子部分木が完全に含まれるため、スタック制約を満たす。
- 向き入れ替えは、この問題固有の近傍として扱う。

### 評価関数

DFSで得られるカード位置列の総移動距離を最小化する。

```text
score(tree):
    seq = dfs_sequence(tree)
    return sum distance(seq[t-1], seq[t])
```

全カードを消せる前提では、この距離が小さいほど得点が高い。

## 実装上重要な断片

木状態では、正しさはDFSで保証する。

```text
dfs(node):
    take node.first
    for child in node.children:
        dfs(child)
    take node.second
```

node移動の典型形は次のようになる。

```text
move_node(v, new_parent, pos):
    if new_parent is in subtree(v):
        reject
    remove v from old_parent.children
    insert v into new_parent.children at pos
    update score by affected edges
```

## この解法の本質

正しい括弧列を根付き木にして、木の局所変形を焼く点が本質である。配列の括弧列を直接いじるより、ノード移動や部分構造の交換が意味を持ちやすい。記事の知見としては、複雑な `X` を追うより、`X` なしの木構造を高速に改善するだけでもかなり戦えること、そして温度を下げた山登り寄り探索が強いことが重要である。
