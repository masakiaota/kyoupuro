## 解法の全体像

操作 `X` は使わず、`Z` でカードを取る順序だけを最適化する。状態は、実際に `Z` を行うカード位置列 `p` である。ただし、同じ番号の2枚目を取るときに1枚目が山札トップにある、というLIFO制約を常に満たす列だけを扱う。

最初に空列へ未使用ペアを1つずつ最良挿入して貪欲初期解を作る。その後、現在列の短い区間を壊し、その区間に含まれるカード番号の両方を列から消し、消した番号をランダム順で最良挿入し直す。これはLNSに近い部分破壊・再構築である。採択は通常の山登り版と、既知最良コストに少し余裕を持たせるRRT版がある。

## 主要アイデア

- 問題を「正しい括弧列に対応するカード位置列の移動距離最小化」と見る。
- 未使用ペア2点を既存の正しい列に挿入する最良位置を `O(|p|)` で求める。
- 最良挿入を使うことで、初期構築も再構築も同じ部品で書ける。
- 破壊対象は連続区間だが、そこに現れた番号の相方も同時に削除するため、残り列は必ず実行可能なまま残る。
- RRT版では悪化を完全には捨てず、`next_cost <= best_cost + 2` なら現在解を動かす。
- 出力は列の順にマンハッタン移動して `Z` を出すだけで、`X` は一切使わない。

## 最終コードの構造

### 状態表現

- `Point { x, y }`: 盤面座標。
- `Map A`: 座標からカード番号への対応。
- `v2points[color]`: 各番号の2座標。
- `State = vector<Point>`: `Z` を行うカード位置列。列中の同番号2回の入れ子関係がスタック制約を表す。
- `InsertionPos`: 挿入する2点と、それぞれの挿入添字、差分コスト。

このコードでは列自体を評価対象にしており、山札の中身は明示的には持たない。列が正しい括弧列であることを保つことで、山札の正しさを暗黙に保証する。

### 観測・制約・入力の扱い

- `N=20`, `M=200` を定数として扱う。
- 入力盤面を読み、各番号の2つの座標を `v2points` に集める。
- `BestInsertPositions()` は、既存列が実行可能である前提で、ペア2点を挿入しても実行可能な位置だけを探索する。
- 実行可能性は走査中の深さで管理する。同じ深さにある境界同士を対応させるため、交差する挿入を避けられる。

### 評価関数

評価値は移動回数そのものである。

```text
Cost(state):
    cost = 0
    prev = (0, 0)
    for p in state:
        cost += manhattan(prev, p)
        prev = p
    return cost
```

全カードを消せる前提では、得点最大化はこの `Cost` の最小化と等価である。`Z` の回数は常に400で、評価の移動回数には入らない。

### 探索・構築・更新

初期解は全未使用番号に対して最良挿入位置を試し、追加コストが最小の番号を1つ採用する操作を200回繰り返す。

最良挿入では、走査位置ごとに以下を候補にする。

- 2枚を隣接して `a,b` または `b,a` と挿入する。
- 先に `a` を入れて、同じ深さの後ろ側に `b` を入れる。
- 先に `b` を入れて、同じ深さの後ろ側に `a` を入れる。

LNSの1反復は次の流れである。

```text
repair(state):
    l = random index
    r = min(len(state), l + 15)
    removed_colors = colors appearing in state[l:r]
    next = state without all cards whose color in removed_colors
    shuffle(removed_colors)
    for color in removed_colors:
        insert its two points into next at BestInsertPositions
    return next
```

山登り版では `Cost(next) <= Cost(state)` のときだけ採択する。RRT版では `Cost(next) <= best_cost + 2` なら現在解として採択し、最良更新時だけ `best_state` を更新する。

### 操作・クエリ・出力選択

- 最終的な `State` の順に現在位置からカード位置へ移動する。
- 各カード位置で `Z` を出力する。
- 置く操作 `X` は使わない。
- 生成列が実行可能であれば、2回目の同番号を取った瞬間にトップ2枚が一致して消える。

### 時間配分・パラメータ

- 再実装コードではLNS反復を35000回行う。
- 破壊区間長は最大15程度。
- RRTの許容幅は `theta = 2`。
- 乱数は `mt19937` 固定シード。
- 実行時間は提出で約2秒、RRT版はほぼ上限まで使っている。

## 実装上重要な断片

最良挿入は、括弧列の深さごとに「ここまでで片側を置くなら最良だった境界」を持つのが核である。

```text
scan boundaries i = 0..len(state):
    try adjacent insertion around boundary i
    try second insertion using best first-boundary at current depth
    update best first-boundary at current depth
    if next card is first occurrence of its color:
        push depth
    else:
        pop depth
```

破壊は座標区間そのものではなく番号集合に拡張する。

```text
colors = set(color(state[i]) for i in [l, r))
next = [p for p in state if color(p) not in colors]
```

この処理で、片方だけ消えて不正な列になることを防いでいる。

## この解法の本質

スタック制約を「正しい括弧列」として扱い、正しさを壊さない挿入操作に閉じ込めた点が本質である。最良挿入を `O(|p|)` で解けるため、貪欲構築もLNSの修復も高速に回せる。局所的に順序を少し動かすのではなく、短い区間に含まれる複数ペアをまとめて抜いて再配置することで、入れ子構造をそこそこの大きさで作り直せる。

## 真似するならまず実装する部分

まず `X` なしに限定し、`State` を正しい括弧列として持つ。次に `Cost` と出力生成を書く。その上で、2点の最良挿入を実装する。ここまでで貪欲初期解が作れる。上位化するなら、同じ最良挿入を使った区間破壊・再構築とRRT採択を足すのが自然である。

## 注意点・未理解点

- `BestInsertPositions()` の深さ管理を誤ると、見た目にはペアが2回ずつ出てもスタックで消えない列ができる。
- `State` の添字へ2点を挿入するとき、1点目の挿入で2点目の添字がずれる。コードでは挿入位置をその前提で持っている。
- RRTは最良解ではなく現在解を悪化方向にも動かすため、返すべき状態は `best_state` である。
- `X` を使う可能性は完全に捨てている。今回の上位コードではそれでも強いが、問題全体の探索空間をすべて使っているわけではない。
