## 解法の全体像

店から店までの短いパスを事前に列挙し、各木の赤化ターン `R_i` を山登りで最適化する。シミュレーションでは、現在の店から始まる列挙済みパスを順に見て、そのパスを通ると到着店の在庫が増えるなら即採用する。増えるパスがなければ別の店へ移動し、それもなければ現在店へ戻るパスを使う。

在庫判定は、最大パス長が小さいことを利用して `hold[shop][encoded_cone]` の固定配列で O(1) にする。近傍は1つの木の `R_i` をランダムなターンに変えるだけで、スコアが同じなら受理する山登りを行う。単点更新でスコアが変わらないことが多いため、`Δ >= 0` を受理するだけで局所解から動き続けやすいという主張である。

## 主要アイデア

- 店から店までの長さ `d` 以下のパスを全列挙する。
- 各木 `i` に、`R_i` 以降に侵入したら赤化するという閾値を持たせる。
- 近傍は `R_i` の1点更新で、値は `[0, T)` から一様に取り直す。
- シミュレーションは列挙済みパスを短い順に見て、新規在庫になる最初のパスを採用する。
- 在庫判定はビット列を `1` 始まりで符号化し、店ごとの固定長配列で管理する。
- 受理条件は `new_score >= current_score`。同点受理により広く探索する。
- 復習コードは約200行で、焼きなまし温度を使わず山登りだけで強い点が特徴である。

## 最終コードの構造

### 状態表現

- `g`: 隣接リスト
- `path[shop]`: その店から到達できる店までのパス列。各パスは移動先頂点の列
- `R[N]`: 各頂点の赤化閾値。店は `1e9` として赤化対象外
- `col[N]`: シミュレーション中の現在色。0がW、1がR
- `hold[K][1 << 20]`: 店ごとの在庫判定配列。attempt番号を入れてクリアを省く
- `cur[T]`, `best[T]`: 現在試行と最良試行の出力列
- `v`, `prev`, `tm`: 現在店、直前頂点、現在ターン
- `pid`: コーンを表す整数。初期値1で、木を踏むたびに左シフトして色ビットを足す

### 観測・制約・入力の扱い

- 座標は読み捨てる。
- `MAX_DEP = 16` として、DFSで店から店へのパスを列挙する。
- DFSは直前頂点への即戻りだけを禁止し、店に到達したらそのパスを保存して打ち切る。
- `path[i]` は長さ順に入るため、シミュレーションで先に見つかるパスほど短い。
- Uターン禁止は、パスの先頭が `prev` と等しい場合にそのパスを使わないことで守る。

### 評価関数

- シミュレーション中、新規在庫になるパスを採用し、ターン数が足りれば `nsc++` する。
- 1試行の評価は `nsc`。
- 現在解のスコア `csc` に対して `nsc >= csc` なら `R` の変更を受理し、そうでなければ元に戻す。
- 最良スコア `bsc` も同様に更新し、対応する出力列を保存する。

### 探索・構築・更新

- 初期 `R_i` は、店以外について `rng(T)` でランダムに置く。
- 各attemptでランダムな木 `mx` を1つ選び、`R[mx]` を新しいランダムターンに置き換える。
- その `R` をコピーした `cR` と色配列 `col` で、Tターン分の貪欲シミュレーションを行う。
- パス候補の評価では、そのパスを進んだ場合に赤化が発生するかを一時的に反映し、到着店の `pid` が新規かを判定する。
- 採用時は移動頂点を `cur[tm]` に入れ、赤化条件を満たした木では続けて `-1` を入れる。
- 赤化後は `cR[ny] = 1e9` として同じ木で再度赤化しないようにする。

### 操作・クエリ・出力選択

- 新規在庫になるパスがあれば、そのパスをそのまま行動1列として出力候補にする。
- パス上の木で `tm >= cR[ny]` になった場合、移動後に `-1` を出力し、その木を赤にする。
- 新規在庫になるパスがない場合、現在店以外に移動できる最短パスを選ぶ。
- それも無い場合、現在店に戻るパスも許して移動する。
- 最終的に `best` に保存されたT個の行動を出力する。

### 時間配分・パラメータ

- 時間は `current_clock() > 1950000` マイクロ秒で打ち切る。
- `MAX_DEP = 16`。
- 在庫配列は `K * 2^20`。長さ16程度までのビット列を長さ込みで扱える。
- 近傍は1点更新のみ。
- 受理条件は `csc <= nsc`、最良更新も `bsc <= nsc`。

## 実装上重要な断片

```text
buildPath():
    for each shop s:
        dfs(s, prev=-1, depth=0)
        collect paths that first reach any shop
```

```text
simulate(R):
    v = 0
    prev = -1
    tm = 0
    while tm < T:
        for path in paths_from[v]:
            if path[0] == prev:
                continue
            pid = cone_id_after_path(path, R, col, tm)
            if hold[path.last][pid] is new:
                execute(path, inserting -1 on red timing)
                score += 1
                break
        if no scoring path:
            execute_shortest_non_backtracking_path()
    return score
```

```text
hill_climb():
    choose tree x
    old = R[x]
    R[x] = random_turn()
    score = simulate(R)
    if score >= current_score:
        keep
    else:
        R[x] = old
```

## この解法の本質

この解法は、経路探索を事前列挙に寄せることで、評価のたびに重いBFSをしない。さらに、パス長が小さいという制約を在庫判定の固定配列化に使い、赤化ターンの山登り反復数を増やしている。焼きなましの温度設計ではなく、同点受理で平坦なスコア地形を動き回る点が特に重要である。

## 真似するならまず実装する部分

まず `MAX_DEP` を小さめにして店から店へのパス列挙と `hold[shop][pid]` の O(1) 在庫判定を作るのがよい。次に、固定 `R_i` で貪欲シミュレーションし、最後に1点更新の山登りを追加する。焼きなましより先に、パス列挙と高速評価を固める方が効果が大きい。

## 注意点・未理解点

- `MAX_DEP=16` でもパス列挙数はグラフによって増える。直前戻り禁止だけなので、メモリと時間の見積もりが必要である。
- `hold` は `1 << 20` 固定で、符号化する最大長を超えると壊れる。パス長と赤化挿入を含む実際の文字列長を意識する必要がある。
- パス評価中に一時的に色を変え、後で戻す処理は壊れやすい。
- 本番提出 `72939944` はBFSと焼きなましを使う別構造で、最終復習コードとはかなり違う。記事で主張する最終解法は復習提出 `72946553` と見るべきである。
- X本体は読めなかったため、記事中に引用された範囲以外の文脈は確認できていない。
