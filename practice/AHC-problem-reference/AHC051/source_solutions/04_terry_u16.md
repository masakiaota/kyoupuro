## 解法の全体像

他の上位解法とはかなり異なり、汎用的な DAG を焼くのではなく、幾何的に分割された「分別アセンブリ」を構築する方針である。

1つの分別ユニットは、同種の分別器を複数個組み合わせ、特定のごみを高確率で片側へ寄せる小さな構造である。このユニットを直列につないで分別アセンブリを作る。各アセンブリは1つのごみ種類を担当し、そのごみを処理装置へ落とし、他のごみは次のアセンブリへ流す、という直列分類器として機能する。

幾何面では、各アセンブリを平面上の扇形・凸包領域に埋め込む。まず全体の凸包・領域割り当てを作り、各領域内で1個組・2個組・3個組の分別ユニットを何個作れるかを DP で求める。最後に、どのアセンブリがどのごみを担当し、どの分別器種別・ユニットサイズの多重集合を使うかを山登り・ビーム的に決める。

## 主要アイデア

- 分別器を単独で使うのではなく、同種分別器を複数個組み合わせて鋭い確率分離を作る。
- 分別ユニットを直列に並べることで、特定のごみだけを処理装置へ高確率で分岐させる。
- ごみ種類ごとにアセンブリを用意し、アセンブリ列を通過させながら順に取り除く。
- アセンブリの幾何配置は、凸包や扇形領域を使って交差しにくい構造に制限する。
- 各領域で作れるユニット数は DP で見積もる。
- 分別器種類は出口反転込みで `2K` 候補として扱う。
- ユニット多重集合を局所探索し、担当ごみに対する分別性能を最適化する。

## 最終コードの構造

以下は記事本文から推測していた実装構造である。キャッシュ実装で確認できた部分は後述する。

### 状態表現

- `assembly[i]`: 直列に並ぶ第 `i` アセンブリ。
- 各アセンブリの担当ごみ `target[i]`。
- 各アセンブリに割り当てられた処理装置位置。
- アセンブリ領域を表す凸包・扇形・境界頂点。
- 領域内で使用できる分別器設置場所の順序。
- 分別ユニット:
  - 使用する分別器種類 `k`。
  - 出口反転の有無。
  - ユニットサイズ `1, 2, 3`。
  - ユニット内で使う設置場所列。
- ユニット多重集合 `multiset[(virtual_kind, unit_size)]`。
- 確率評価用に、各アセンブリが対象ごみを通す確率、対象外ごみを誤って通す確率。

### 観測・制約・入力の扱い

- 平面制約を満たすため、アセンブリは凸包・扇形のような限定された幾何構造へ埋め込む。
- 分別器設置場所は、偏角順や領域内の順序で使う。
- 記事では、単純な偏角順だけでは効率が悪く、より自由度を持つ DP へ変更している。
- 出口反転により、`p` と `1-p` のどちらを「対象ごみを通す側」として使うかを選べる。
- アセンブリは直列につながるため、前段で処理装置へ落ちたごみは後段に来ないというモデルになる。

### 評価関数

- アセンブリ `a` が担当ごみ `t` を処理装置へ落とす確率を高くし、他のごみを誤って落とす確率を低くする。
- 同じ分別器を `k` 個組み合わせると、確率は累乗やその補集合の形になる。
- 複数ユニットを直列にすると、通過確率はユニットごとの確率の積になる。
- ユニット多重集合の目的関数は、担当ごみの成功確率と、対象外ごみの誤分類確率を合わせたものと読める。
- 全体では、アセンブリ列を通した各ごみの正しい処理確率を最大化する。

### 探索・構築・更新

- 凸包・領域構築:
  - まずアセンブリを置く大枠を決める。
  - 目標として、後ろのアセンブリほど必要頂点数が減るような重みを持たせる。
  - 凸包の形や頂点順序を焼きなましで改善する。
- 分別ユニット数 DP:
  - 領域内で1個組、2個組、3個組ユニットを何個作れるかを求める。
  - 単純な偏角順 DP では効率が悪いため、前線を表す状態を持つ疑似的な DP に変えて自由度を上げる。
  - 記事では、すべての状態を厳密には見ない「嘘DP」として説明されている。
- アセンブリ内部のユニット選択:
  - 担当ごみを固定し、分別器種類とユニットサイズの多重集合を変数にする。
  - 貪欲に良いユニットを追加する。
  - 各ユニットを「別の分別器種類・サイズ」または削除に置き換える山登りを行う。
- 全体割り当て:
  - アセンブリが担当するごみの順序と処理装置を決める。
  - 内部ユニット構造と合わせてビーム的に比較する。

### 操作・クエリ・出力選択

- アセンブリ列を入口から順に接続する。
- 各アセンブリ内の分別ユニットを、あらかじめ確保した分別器設置場所へ配置する。
- 対象ごみを落とす側の出口を処理装置へ、通過側を次のアセンブリへつなぐ。
- 最後まで残るごみは終端の処理装置へ接続する。
- 仮想分別器の反転は、出力時に出口1・出口2の行き先を入れ替えることで実現する。

### 時間配分・パラメータ

- 幾何構築、ユニット数 DP、アセンブリ内部探索のそれぞれが重い。
- 記事では、幾何の実装量とコーナーケースが非常に大きいことが強調されている。
- ユニットサイズは主に1、2、3個組に絞る。
- 凸包・領域構築の焼きなまし入口はキャッシュで確認できたが、DP の遷移制限の具体値はファイル末尾欠落のため不明である。

    p1 = p[kind][garbage]
    if flipped:
        p1 = 1 - p1
    # 同種分別器を size 個組み合わせた通過/除去確率を計算する

## この解法の本質

この解法は、確率的な分別器を「弱い二値分類器」と見て、それを直列・並列風に組み合わせて強い分類器を作る発想が中心である。一般の DAG を探索するのではなく、最初から「1種類のごみを取り除くアセンブリ」という意味を持つ部品に分解している。

そのため、確率最適化の見通しはよい。各アセンブリでは、担当ごみをどれだけ落とせるか、他ごみをどれだけ通せるかを直接評価できる。一方で、この構造を平面上に多数埋め込む幾何処理が非常に難しく、実装量が大きい。

## 真似するならまず実装する部分

まず、幾何を無視した小さなモデルで、分別ユニットとアセンブリ列の確率計算を実装するのがよい。次に、固定した単純な扇形領域に1個組ユニットだけを置き、出力可能な形へ落とす。

その後、2個組・3個組、ユニット多重集合の山登り、領域内 DP、凸包最適化へ進む。最初から記事の全体構造を再現すると、幾何の実装だけで詰まりやすい。

## 実装確認（提出 68414359、部分）

読めた範囲では、初期解は分別器位置の最近傍順序に2-optをかけるTSP風パスと、min-cost flowによる処理装置親割当で作る。`sorter::place_sorters` はパスを処理装置親が出る最後までtrimし、前から確率を流しながら処理装置と分別器種類・出口反転を貪欲に選ぶ。

`or_and::convex_hull` では、KDTree近傍グラフを使って処理装置ごとの凸包/領域を作る。必要頂点数は残りごみ種数の `1/3` 乗に近い比率で配分し、`AddPoint`、`RemovePoint`、`ChangeInOut`、`MovePoint` 近傍で約300ms焼く。

記事で中心になっている分別ユニット/アセンブリのDPは、キャッシュが途中で切れているため読めない。したがって、本文メモのユニットDP部分は記事ベースの整理として扱う。
