## 解法の全体像

全座標から Delaunay 三角形分割を作り、その辺を非交差な候補グラフとして使う。候補グラフ上で、入口を根とする二分木状の DAG を作り、まず貪欲に初期木を構築する。その後、木構造、処理装置配置、分別器種類を段階的に焼きなまし・山登りで改善する。

最終的な流れは、前処理、初期解作成、木構造焼きなまし、処理装置割り当て山登り、分別器種類焼きなましの順である。木構造の評価では、正確な確率計算だけでは重いため、各頂点から各処理装置への「良さ」を表す近似評価値を逆順に伝播する。最後は固定した木と処理装置割り当てに対して、分別器種類と左右反転を正確な DP で調整する。

## 主要アイデア

- Delaunay 三角形分割を使い、非交差な候補辺集合を最初から用意する。
- 似た分別器種類をユークリッド距離とコサイン類似度で除外し、候補種類を削減する。
- 入口を根、処理装置を葉に近いノードとして、二分木構造を構築する。
- 初期木は処理装置からの多点 BFS 距離を使い、遠いノードから子を伸ばす貪欲で作る。
- DAG 制約は親リスト、深さ、祖先方向の確認で守る。
- 木構造探索では、正確スコアの代わりに `evaluate[i][n]` の近似評価を使う。
- 最終段階では、固定木上で分別器種類と左右 swap を焼きなましする。

## 最終コードの構造

以下は記事本文から推測していた実装構造である。キャッシュ実装で確認した差分は後述する。

### 状態表現

- Delaunay 三角形分割から得た無向候補グラフ。
- 入口、処理装置、分別器設置場所を含む頂点集合。
- 各ノードの親、子、深さ。
- `children[v]`: 二分木なので最大2個。
- `processor_at[d]`: 各処理装置設置場所に置くごみ種類。
- `kind[v]`: 分別器種類。
- `swap[v]`: 出口1・出口2を入れ替えるか。
- `evaluate[v][processor]`: 頂点 `v` から処理装置 `processor` へ行ける良さの近似値。
- 正確スコア計算用の到達確率または後ろ向き成功確率。

### 観測・制約・入力の扱い

- Delaunay の辺だけを候補にすることで、線分交差を原則避ける。
- 分別器種類はランダム生成なので、似すぎているものを前処理で削る。
- DAG を保つため、辺追加時は親リストや深さを見て矛盾を解消する。
- 子を持たない分別器ノードは最後に再帰的に削除して、正しい木に直す。
- 初期木は、処理装置から候補グラフ上の距離を計算し、入口から遠い側へ伸ばすイメージで作る。

### 評価関数

- 木構造探索用の近似評価:
  - 処理装置ノードでは、自分自身の処理装置に `1`、他に負の小ペナルティを置く。
  - 分別器ノードでは、2つの子の評価を `0.7` と `0.3` のような重みで合成する。
  - これは、分別器が完全ではないが片側をやや強く選べるという近似である。
- 処理装置割り当て:
  - 木構造を固定し、処理装置に置くごみ種類を swap・回転で山登りする。
  - 分別器種類は、到達確率と `evaluate` を見て貪欲に仮決定する。
- 最終評価:
  - 固定木上で、分別器確率 `p[k][g]` を使い正確な DP を計算する。
  - 誤分類確率の和、または正解確率の和を評価する。

### 探索・構築・更新

- 前処理:
  - 全座標で Delaunay 三角形分割。
  - 似た分別器種類を除外。
- 初期解:
  - 処理装置からの多点 BFS。
  - 入口から二分木を貪欲構築。
  - 葉でない不要ノードを削除。
- 木構造焼きなまし:
  - 葉ノードを親と子の間へ挿入する。
  - 葉ノードを周辺ノードへ接続する。
  - 子が1つのノードに子を追加する。
  - 子が2つのノードから部分木を切る。
  - 子が2つのノードから切って別の場所へつなぐ。
- 処理装置配置最適化:
  - 処理装置割り当ての回転や swap を試す。
  - 分別器種類を評価値で貪欲に仮決定してスコアを見る。
- 分別器種類最適化:
  - 木と処理装置配置を固定。
  - 分別器種類変更と左右 swap を焼きなまし。
  - 記事後半では、差分更新の不備を直すより全体再計算で安定化したと読める。

### 操作・クエリ・出力選択

- 最終木に含まれる分別器だけを出力する。
- 木から外れた分別器は `-1`。
- 二分木の子が1つしかない場合や不要葉は、出力前に処理装置へ直結するなどして有効な出力に直す。
- `swap[v]` がある場合、出力時に出口1・出口2の行き先を入れ替える。

### 時間配分・パラメータ

- 記事では、木構造焼きなましを先に行い、処理装置配置、分別器種類の順に最適化している。
- 木構造探索は1秒程度まで行う説明がある。
- 処理装置配置は一定回数または時間で山登りする。
- 最終の分別器種類 SA は残り時間を使う。
- 近似評価の重みとして `0.7` と `0.3` が使われている。

```text
build_initial_tree():
    graph = delaunay_edges(all_points)
    dist = multi_source_bfs(from processors)
    start at inlet
    greedily add child nodes along graph while keeping DAG and degree <= 2
    remove recursively unused leaves
```

```text
approx_evaluate_tree():
    for processor node d:
        evaluate[d][d] = 1
        evaluate[d][other] = -0.1
    for v in reverse_topological_order:
        if v is sorter:
            a, b = children[v]
            evaluate[v] = 0.7 * max(evaluate[a], evaluate[b])
                        + 0.3 * min(evaluate[a], evaluate[b])
```

```text
final_sorter_sa():
    while time remains:
        choose sorter v
        try changing kind[v] or swapping outlets
        recompute or update exact score
        accept by SA rule
```

## この解法の本質

この解法の本質は、平面グラフ問題を Delaunay 辺上の二分木探索へ落としている点である。Delaunay 三角形分割は全体として非交差な辺集合を与えるため、任意線分の交差判定を繰り返すより実装が簡単になる。その代わり、候補辺が制限されるので、木構造探索と処理装置割り当てでどれだけ補えるかが勝負になる。

評価も段階的である。木構造を動かす段階では正確な確率 DP より軽い近似評価を使い、最後に固定木上で正確に分別器種類を詰める。構造・処理装置・分別器種類を一度に焼くのではなく、粗いものから順に固定していく実装寄りの方針である。

## 真似するならまず実装する部分

まず Delaunay で候補グラフを作り、入口を根とする二分木を構築して有効出力を作る。次に、固定木上で正確な後ろ向き DP と分別器種類の貪欲選択を実装する。

その後、木構造近傍、処理装置 swap、最後の分別器種類 SA を追加するとよい。Delaunay 実装が重ければ、最初は近傍距離で作った非交差風の候補辺でも、DPと出力形式の理解には使える。

## 実装確認（提出 68679901）

キャッシュ実装は Nim で、分別器種類をまず削減する。`sum(0.5-|p-0.5|)^2` で種類を並べ、ユークリッド距離とcos類似度、反転込みの類似判定で近すぎる種類を捨て、`candK` だけを探索対象にする。

候補グラフは全処理装置・分別器・ROOTに対するDelaunay三角分割で作る。処理装置から逆BFSし、ROOT隣接のうち距離が大きい分別器を入口先に選ぶ。初期二分木はBFS/greedyで作り、不要な葉分別器は削除し、DAG順を `checkDagUp` で保守する。

評価は段階的で、木構造SAでは処理装置に1、それ以外に-0.1を置く粗い `evaluate1` と、子を `0.7/0.3` で混ぜる `calcProb` を使う。`sa1` は接続構造、`sa2` は処理装置割当、`sa3` は分別器種類と左右swapを焼く。最終出力は処理装置配列、入口先、各分別器の `sorter c1 c2` で、未使用は `-1`。

## 注意点・未理解点

- 提出 `68679901` により、Delaunay実装、DAG順更新、近傍の種類、温度、時間配分は確認できた。
- Delaunay 辺だけに制限すると、最適な長距離接続やアセンブリ的構造を作りにくい可能性がある。
- 近似評価 `0.7/0.3` は実確率を粗く表すだけなので、木構造探索の評価ずれが起こる。
- 記事では差分更新のバグに触れられており、部分更新より全体再計算で検証する段階が必要である。
- 類似分別器削除は高速化には効くが、特定ケースで必要な分別器を消す危険がある。
