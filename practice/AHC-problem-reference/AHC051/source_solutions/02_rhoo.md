## 解法の全体像

コンテスト中の改善過程を追う参加記である。最終方針は、固定したトポロジカル順序を持つパス状の骨格を作り、その中で分別器種類・行き先・処理装置割り当て・入口の行き先を焼きなましで改善するものだと読める。

初期は二分木やグリッド状埋め込みを試しているが、最終的には「使う分別器をある順序で並べ、その順序の前から後ろへ辺を張る」形へ寄せている。トポロジカル順序を固定すると、閉路判定が単純になり、候補辺も順序差で制限できる。交差しない辺の候補は事前計算し、ランダムに選んでも高速に有効辺を引けるようにしている。

スコア計算では、前向き DP と後ろ向き DP を使って、分別器種類や接続先変更の差分を `O(N)` または区間更新で計算する。分別器種類の候補を全 `K` から選ぶのではなく、その頂点に来やすいごみに対して有効そうな分別器を少数に絞ることで探索回数を稼ぐ。

## 主要アイデア

- 最終的にはトポロジカル順序を固定したグラフに寄せ、閉路制約を扱いやすくする。
- 分別器の並び順は、左側から並べるだけでなく、処理装置から遠いものを前にするような順序も試している。
- 候補辺は「順序が近い後方頂点」へ張るものを中心にし、交差しない辺を事前計算する。
- 1つの分別器変更は前向き・後ろ向き DP で差分評価する。
- 複数頂点に影響する変更では、トポロジカル順序上の区間だけを再計算する。
- 処理装置割り当ても近傍として焼きなましに含める。
- その頂点に到達しやすいごみ種類を見て、分別器候補を上位少数に絞る。

## 最終コードの構造

以下は記事本文から推測していた実装構造である。キャッシュ実装で確認した差分は後述する。

### 状態表現

- `order`: 分別器頂点と処理装置頂点のトポロジカル順序。
- `used[v]`: 分別器設置場所を使うかどうか。
- `kind[v]`, `to1[v]`, `to2[v]`: 使用分別器の種類と2出口。
- `device_type[d]`: 各処理装置設置場所に置くごみ種類。
- `root_to`: 搬入口からの行き先。
- `fdp[v][g]`: ごみ `g` が頂点 `v` に来る確率。
- `bdp[v][g]`: 頂点 `v` から正しく処理される確率。
- 事前計算した「交差せず、トポロジカル順序も満たす候補辺」のリスト。

### 観測・制約・入力の扱い

- 閉路はトポロジカル順序を固定し、順序の後ろへだけ辺を張ることで避ける。
- 交差判定は候補辺生成時にかなり前処理する。
- 候補辺は各頂点から順序上の近い後続頂点に制限する。記事では、候補幅を広げることで最終スコアが伸びたと説明されている。
- 処理装置への辺は、終端側の構造と相性がよいものを選ぶ。
- 途中段階では使う分別器の割合を落として、交差なしの埋め込みを安定して得ている。

### 評価関数

- 主評価は平均正解確率の最大化である。
- `fdp` と `bdp` を持つことで、ある頂点の種類や接続先を変えたときの総正解確率差を小さく計算する。
- 分別器種類選択では、その頂点に来ているごみ分布と、子側の成功確率の差を組み合わせて評価する。
- 記事の初期段階では、分別器割り当てだけなら焼きなましでほぼ最適化できると見込み、高速化を先に行っている。

### 探索・構築・更新

- 初期検討:
  - 二分木型。
  - グリッド状に分別器を埋め込む型。
  - 5列程度の格子を増やす山登り。
  - 使う分別器割合を落として交差を避ける実装。
- 最終に近い方針:
  - 分別器を固定順序に並べる。
  - その順序の後方へ辺を張る。
  - 分別器種類、行き先、処理装置割り当て、入口位置を焼きなましする。
- 近傍:
  - 分別器種類の変更。
  - 出口の接続先変更。
  - 処理装置割り当ての swap。
  - 搬入口から入る頂点の変更。
  - 記事後半では、接続先候補を「少し前からかなり後ろ」へ広げている。
- 分別器種類候補:
  - その頂点に来やすいごみ種類に対して、有効な分別器を上位候補として持つ。
  - 全探索ではなく少数候補をランダムに試す。

### 操作・クエリ・出力選択

- 固定順序上で使う分別器だけを出力し、未使用頂点は `-1` にする。
- 処理装置配列は焼きなまし後の割り当てを出力する。
- 入口からの行き先も近傍で改善した結果を出力する。
- 出力前には、すべての接続先が設置済み分別器または処理装置であること、交差がないこと、閉路がないことを検証する必要がある。

### 時間配分・パラメータ

- 候補辺の事前計算で、ランダムな非交差辺選択を高速化する。
- 分別器種類候補を上位数個に絞る。
- 単一変更は `O(N)` 差分、多頂点変更はトポロジカル区間 DP で更新する。
- 候補幅や近傍比率の具体値はキャッシュ実装で確認できた。記事では候補幅拡大が改善に効いたとされる。

## この解法の本質

この解法は、問題を「自由な平面 DAG 探索」として解くのではなく、トポロジカル順序を持つパス状構造の上で辺を付け替える問題に変換している。順序を固定すると閉路判定がほぼ消え、候補辺の前処理もできる。交差判定を毎回重く行うのではなく、ランダム近傍が最初から有効辺を選びやすい状態を作るのが重要である。

また、分別器種類を全候補から毎回選ばない点も実践的である。頂点に到達するごみ分布が分かっていれば、その頂点で分けるべきごみは限られる。確率 DP で現在状態を観測し、候補集合を絞ることで、同じ時間でも意味のある変更を多く試せる。

## 真似するならまず実装する部分

まず、全分別器を使わなくてもよいので、トポロジカル順序固定の非交差グラフを作る。次に、`fdp`/`bdp` を実装し、分別器種類変更と処理装置 swap の焼きなましを行う。

接続先変更は、候補辺リストを作ってから追加するのがよい。最初は候補幅を狭くしてバグを減らし、正しい出力が安定したら候補幅を広げる。

## 実装確認（提出 68414355）

キャッシュ実装は Rust で、`make_tour` が分別器位置をグリッド状ツアーへ入れ、最近処理装置ペアを挿入してからSAと交差解消で非交差順序を作る。`solve` では順序近傍、goal近傍、start近傍から候補辺を作り、`Lines` が候補辺同士の交差関係をグリッド分割と `HashSet` で前処理する。

状態は `fdp`、`bdp`、トポロジカル順序、使用中辺集合を持つ。辺変更では、交差する候補を `IndexSet` から外した上で有効候補をランダムサンプルし、閉路回避と順序組み替えを行う。`get_diff` / `get_diff_multi` と `do_fdp` / `do_bdp` で差分評価・差分反映する。

分別器種類変更は、到達確率が大きいごみ種から事前生成した `selector_cand` を引く。`selector_cand` は `1/min(p,1-p)` に応じて重複投入され、特定ごみを強く分ける種類が出やすい。温度は `T0=6e-2`, `T1=4e-5`、最後に処理装置割当swapやroot変更も焼く。
