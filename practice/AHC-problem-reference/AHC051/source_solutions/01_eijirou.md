## 解法の全体像

大きく「交差しない有向グラフを作る段階」と「そのグラフ上で分別器種別・行き先・処理装置割り当てを焼きなましで改善する段階」に分ける。

初期解は、まず全分別器をできるだけ多く使う長い非交差パスを作る。スライドでは TSP を利用して分別器配置を一筆書き状に並べ、終端側を処理装置へ接続する方針が説明されている。その後、処理装置を前から貪欲に割り当て、各分別器の種類も「特定のごみを他の残り集合からよく分ける」観点で初期化する。

改善は焼きなましで行う。固定した DAG 上の確率計算を前向き DP と後ろ向き DP に分け、1つの分別器の種類・接続先を変えたときのスコア差を `O(N)` で計算する。さらに高速化として、序盤は `log` 近似スコアを使い、確率配列の更新には SIMD を使って大量の近傍を評価する。

## 主要アイデア

- まず平面制約を満たす大きな骨格を作り、その上で確率最適化を行う。
- TSP で分別器を長い順序に並べ、交差しにくいパスを初期グラフにする。
- 処理装置の割り当ては、処理装置側へ向かう順に「残りのごみから1種類を分ける」貪欲で決める。
- 分別器の種類を変更したときのスコア差は、前向き到達確率と後ろ向き成功確率を使って `O(N)` で計算する。
- 焼きなまし中は、分別器種類だけでなく接続先も変える。候補接続先はトポロジカル順序や幾何制約を満たす範囲から選ぶ。
- 序盤は正解確率が小さすぎて差が見えにくいので、成功確率そのものではなく `log` 系の評価を併用する。
- 乱択焼きなましを高速に回すため、差分計算と乱数生成を SIMD 化する。

## 最終コードの構造

以下はスライド本文から推測していた実装構造である。キャッシュ実装で確認した差分は後述する。

### 状態表現

- 処理装置位置 `D[N]` と、各位置に置くごみ種類 `device_type[pos]`。
- 分別器位置 `S[M]`、使用有無、分別器種類 `sorter_kind[v]`、出口1・出口2の行き先 `to1[v], to2[v]`。
- 搬入口の行き先 `root_to`。
- グラフのトポロジカル順序、またはトポロジカル順に並んだ分別器列。
- `fdp[v][g]`: ごみ種類 `g` が頂点 `v` に到達する確率。
- `bdp[v][g]`: ごみ種類 `g` が頂点 `v` に来たとき、正しい処理装置に届く確率。
- 現在スコア、焼きなまし用の現在解・ベスト解。

### 観測・制約・入力の扱い

- 入力の確率 `p[k][g]` は分別器種類 `k` がごみ `g` を出口1へ流す確率として保持する。
- 出口を反転すれば `1-p[k][g]` の分別器として扱えるため、実装上は反転込みの候補を持つと探索しやすい。
- ベルトコンベアは線分交差と DAG 制約を満たす必要がある。
- 初期骨格は TSP 的な順序で非交差に近いパスを作り、処理装置は終端側に接続する。
- 焼きなましで接続先を変える場合、トポロジカル順序上で後ろへ向かう辺だけを許すなどして閉路を避ける。

### 評価関数

- 実スコアの本体は平均正解確率 `sum_g q_g / N` の最大化である。問題の絶対スコアは `1 - q_g` の平均なので、解法側では正解確率の和を最大化すればよい。
- 固定グラフ上では、処理装置頂点 `d` の `bdp[d][g]` を `device_type[d] == g` なら1、それ以外なら0とし、分別器では
  - `bdp[v][g] = p[k][g] * bdp[to1[v]][g] + (1 - p[k][g]) * bdp[to2[v]][g]`
  と計算する。
- 入口からの成功確率は `bdp[root_to][g]`、または前向き DP で各処理装置に到達する確率から計算する。
- 序盤の焼きなましでは、成功確率が低いケースの差を見やすくするために `log(q_g)` 系の評価を使う。スライドでは「まず log スコア、短時間後に通常スコアへ切り替える」趣旨が説明されている。

### 探索・構築・更新

- 初期解構築:
  - 分別器配置を TSP で長い順序に並べる。
  - 入口から分別器列へつなぎ、終端側で処理装置へ分岐する。
  - 処理装置のごみ種類を貪欲に決める。
  - 各分別器には、分けたいごみに対して出口確率の差が大きい種類を割り当てる。
- 焼きなまし:
  - 分別器種類の変更。
  - 出口1・出口2の行き先変更。
  - 処理装置割り当て変更。
  - トポロジカル順序に沿って候補を選び、閉路を避ける。
  - スコア差と温度で採択する。
- 差分計算:
  - ある頂点 `v` の分別器種類や行き先だけを変えるとき、`fdp[v][g]` と変更後の子の `bdp` から全体差分を `O(N)` で出す。
  - 採択したら、影響を受ける下流の `fdp` や上流の `bdp` を必要に応じて更新する。

### 操作・クエリ・出力選択

- 最終的に処理装置の配置配列、入口の行き先、各分別器設置場所の行を出力する。
- 未使用の分別器設置場所は `-1`。
- 使用分別器は `k v1 v2` として、設置した分別器種類と2出口の行き先を出力する。
- 接続先が分別器なら、その分別器が設置済みである必要がある。

### 時間配分・パラメータ

- スライド上では 2 秒制限内で非常に多くの近傍を評価するための高速化が重視されている。
- 序盤の短い時間は `log` 評価を使い、その後に通常評価へ寄せる。
- 乱数生成や確率配列演算は SIMD 化する。
- 近傍の試行回数、温度、採択率目標、候補接続先の範囲などの具体値は公開コードがないため未確認である。

## 実装上重要な断片

```text
backward_dp():
    for device d:
        for g:
            bdp[d][g] = 1 if device_type[d] == g else 0
    for sorter v in reverse_topological_order:
        k = sorter_kind[v]
        for g:
            bdp[v][g] =
                p[k][g] * bdp[to1[v]][g]
              + (1 - p[k][g]) * bdp[to2[v]][g]
```

```text
delta_change_sorter(v, new_kind, new_to1, new_to2):
    delta = 0
    for g:
        old = p[old_kind][g] * bdp[old_to1][g]
            + (1 - p[old_kind][g]) * bdp[old_to2][g]
        new = p[new_kind][g] * bdp[new_to1][g]
            + (1 - p[new_kind][g]) * bdp[new_to2][g]
        delta += fdp[v][g] * (new - old)
    return delta
```

```text
anneal():
    while time remains:
        move = sample_kind_or_edge_change()
        if violates_cycle_or_crossing(move):
            continue
        diff = delta(move)
        if accept(diff, temperature):
            apply(move)
            update_dp_around_changed_area()
```

## この解法の本質

この解法の強さは、難しい平面 DAG 制約を「最初に大きな有効骨格を作る」ことで扱いやすくし、その後のスコア改善を確率 DP の差分問題へ落としている点にある。グラフ構造を完全自由に探索すると、交差判定・閉路判定・確率更新が同時に重くなる。そこで、TSP 由来の順序とトポロジカル順序を使い、破綻しにくい候補だけを高速に試す。

また、分別器の種類変更は高次元の確率ベクトル最適化だが、前向き到達確率と後ろ向き成功確率に分けると、1変更あたりの評価差がごみ種類数だけで計算できる。AHC051では `N <= 20` なので、この線形差分を極限まで高速化して試行回数を稼ぐことが上位化の中心になる。

## 真似するならまず実装する部分

まずは非交差の木またはパスを固定して、`bdp` による正解確率計算と、分別器種類の `O(N)` 差分変更だけを実装するのがよい。次に処理装置割り当ての貪欲または山登りを追加する。

グラフ接続先変更、TSP 初期化、SIMD、`log` 評価はその後でよい。最初から全部再現しようとすると、幾何制約のバグと確率更新のバグを同時に抱える。

## 実装確認（提出 68576903）

キャッシュ実装は Rust で、時間配分は TSP 構築、log 評価期間、通常評価期間、出力準備に分けている。`GraphBuilder` は入口、分別器、最後の処理装置を含む順序をTSP/2-opt風に作り、交差区間を反転してから、処理装置の親分別器を非交差に確保する。

状態は processor/sorter/inlet のノード列、`child0/child1`、`parents`、平面埋め込み用 `rotation` を持つ。確率配列は `f32` のflatten配列で、`fwd`、`bwd`、`res` をalignedに保持し、AVX2対応の `try_sorters` 系で分別器候補をまとめて評価する。

改善は入口からDAG順に進め、前半は `sum log2(max(res, EPS))`、後半は通常の `sum res` を使う。近傍は分別器種類変更、左右入替、子接続先変更で、接続先変更時は平面埋め込みの面から候補を取り、`can_add_edge` と `update_graph` で交差・閉路・親子関係を保つ。

## 注意点・未理解点

- 提出 `68576903` により、近傍分布、更新順序、候補接続先の作り方、SIMD分岐はかなり確認できた。一方、スライド上のAblation表の細部は依然として未確認である。
- TSP 初期解の詳細な終端処理や、処理装置をどの順に割り当てるかはスライドから完全には復元できない。
- `log` 評価は低確率の改善を拾うために有効だが、最後は本来の正解確率へ戻さないと提出スコアとずれる。
- 差分 DP は、採択後に前向き・後ろ向き配列をどこまで更新するかを誤ると評価が壊れる。
- 線分交差は端点共有の扱いが重要で、出発点・終点を共有する許容ケースと、無関係な線分の交差を分けて判定する必要がある。
