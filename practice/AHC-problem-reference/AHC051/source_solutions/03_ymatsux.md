## 解法の全体像

有効なグラフを保ったまま、分別器を1つずつ追加していく方針である。基本遷移は、既存の辺 `(a, b)` を外し、新しい分別器 `c` を挿入して `(a, c)` と `(c, b)` を張り、もう一方の出口を別の頂点 `d` へ向ける操作である。この操作を、交差や閉路が発生しない場合だけ採用する。

まず処理装置だけを含む木を作り、その上に分別器を追加していく。初期の処理装置木は、まだ木に入っていない処理装置を `d` として追加する遷移で作る。次に、処理装置のごみ種類割り当てを山登りで決める。その後、分別器追加をビームサーチで行い、候補数を動的に調整しながらスコアのよいグラフを伸ばす。

高速化の中心は、DAG 判定、線分交差判定、可視グラフ更新、確率差分計算である。特に線分交差には AABB 木、可視な頂点候補の管理には visibility graph を使い、確率計算には eijirou の前後 DP と SIMD 的なベクトル演算を取り入れている。

## 主要アイデア

- 制約を満たす状態だけを保持し、分別器を1つずつ追加する。
- 追加操作は「既存辺に新分別器を挿入し、余った出口を別頂点へ向ける」形にする。
- まず処理装置全体をつなぐ木を作り、その後に分別器を増やす。
- 処理装置割り当ては、ランダム初期解からの swap 山登りと、グラフ固定時の分別器貪欲割り当てで評価する。
- 分別器の出口反転を考慮し、`2K` 個の仮想分別器として扱う。
- 分別器追加はビームサーチで行い、時間経過に応じてビーム幅を調整する。
- 交差判定には AABB 木、閉路判定にはビットセット化した推移閉包、候補更新には可視グラフを使う。

## 最終コードの構造

以下は記事本文から推測していた実装構造である。キャッシュ実装で確認できた部分は後述する。

### 状態表現

- 頂点集合:
  - 搬入口。
  - 処理装置 `N` 個。
  - 使用済み分別器。
  - 未使用分別器候補。
- 辺集合 `E`: 各使用分別器から最大2本、入口から1本。
- `kind[v]`: 分別器種類。出口反転込みなら仮想種類として管理する。
- `device_type[d]`: 各処理装置位置のごみ種類。
- 推移閉包 `reach[v]`: `v` から到達可能な頂点集合をビットセットで保持する。
- 交差判定用の線分集合と AABB 木。
- 可視グラフ `visible[v]`: 頂点 `v` から現在の辺を交差せずに直接つなげる頂点候補。
- 各頂点の可視候補集合の bounding box。
- 確率評価用の `fdp`、`bdp`。

### 観測・制約・入力の扱い

- 線分追加時は、既存線分と交差しないかを調べる。
- 閉路判定は、追加辺 `u -> v` に対して `v` から `u` へ到達可能なら拒否する。
- 推移閉包更新は、ビットセットで頂点集合を持つことで高速化する。
- 線分交差の候補削減に AABB 木を使う。線分の bounding box が重なるものだけ詳細判定する。
- AABB 木の構築では、線分中点を Hilbert 曲線順にソートし、近い線分を配列上でも近くする。葉には複数要素を持たせる。
- 可視グラフの削除更新には、厳密でないが実用上影響が小さいヒューリスティックを使っている。

### 評価関数

- 実評価は平均正解確率の最大化。
- 処理装置割り当ての山登りでは、グラフ固定後に分別器種類を貪欲に選んだときのスコアを使う。
- 分別器を1個追加するビームサーチでは、追加後に分別器種類も含めた確率評価を行う。
- 分別器種類変更の差分計算は、eijirou のスライドと同様に、後ろ向き成功確率と前向き到達確率から `O(N)` で求める。

### 探索・構築・更新

- 基本遷移:
  - 既存辺 `(a, b)` を選ぶ。
  - 未使用分別器 `c` を選ぶ。
  - もう一方の接続先 `d` を選ぶ。
  - `(a, b)` を削除し、`(a, c)`, `(c, b)`, `(c, d)` を追加する。
- 処理装置木の構築:
  - `d` を未接続処理装置に限定して、処理装置が全て木へ入るまで追加する。
  - 評価は、未接続処理装置をどれだけ近づけるかと辺長増加のバランスを取る。
- 処理装置割り当て:
  - ランダムな割り当てから開始。
  - ごみ種類の swap を繰り返す。
  - 各候補について、分別器種類を貪欲に割り当ててスコアを評価する。
- 分別器追加:
  - 未使用分別器のうち、使用済み頂点から遠いものを優先して `c` にする。
  - 可能な追加操作を生成し、ビームサーチで上位状態を残す。
  - 時間が少なくなるほどビーム幅や候補数を調整する。
- 後処理:
  - 辺の付け替えによる改善。
  - 分別器種類の貪欲改善。

### 操作・クエリ・出力選択

- ビームで得た最良状態を出力する。
- 仮想分別器として出口反転を扱っている場合、出力時には実際の `k` と `v1, v2` の順番へ戻す。
- 未使用分別器は `-1`。
- 出力前に交差、閉路、未設置分別器への参照がないかを検査する。

### 時間配分・パラメータ

- ビーム幅は固定ではなく、残り時間や候補数に応じて調整する。
- 推移閉包は `O(|V||E|)` 相当だが、ビット演算で大きく高速化する。
- AABB 木の葉サイズは記事では8が使われている。
- 交差判定、可視グラフ更新、確率差分にかなり時間を使うため、各部の定数倍削減が重要である。
- SIMD の具体コードはキャッシュ前半で一部確認できたが、ファイル末尾欠落のため全体の組み込みは未確認である。

    remove edge a -> b

## この解法の本質

この解法の本質は、平面 DAG 制約を「有効状態から有効状態への局所遷移」として扱う点にある。最初から任意のグラフを生成して検査するのではなく、既存辺への挿入という操作に限定すると、グラフが連結したまま増え、処理装置へ到達する構造も壊れにくい。

一方で、この操作を大量に試すには幾何と閉路判定が重い。AABB 木、推移閉包ビットセット、可視グラフは、探索の自由度を保ったまま候補生成を高速化するための基盤である。探索方針そのものよりも、「有効遷移を高速に列挙できる状態管理」が上位化の核になっている。

## 真似するならまず実装する部分

最初に作るべきなのは、既存辺に分別器を挿入する基本遷移と、交差・閉路検査である。処理装置木を構築し、そこへ分別器を数個ずつ追加できるようにする。

次に、グラフ固定での分別器種類貪欲割り当てと、処理装置割り当て swap を入れる。その後、ビーム化、推移閉包ビットセット、AABB 木、可視グラフの順で高速化すると理解しやすい。

## 実装確認（提出 68414321、部分）

読めた範囲では、基本遷移は既存辺 `(v0,v1)` を未使用分別器 `v3` で `(v0,v3)`, `(v3,v1)`, `(v3,v2)` に置換する `AddTransition` である。候補生成は `node_distance_scores` で未使用分別器を並べ、AABB、線分交差、推移閉包で有効性を判定する。

`StateCompanion` は active nodes、active node neighbors、bounding boxes、AABB tree、transitive closure を保持する。`OptimizeSorterTypes` は `ComputeGradTable` と確率テーブルを使って各分別器の種類と左右反転を全探索し、AVX2でごみ種8/16/24程度までベクトル化する。

`RunSingleStep` はビーム各状態に対して遅延で `StateCompanion` を作り、既存辺付替え候補、分別器種類最適化、追加候補生成を行う。幅は完了数と時間から動的推定し、ハッシュ重複除去も入っている。ただしキャッシュが途中で切れているため、最終ループと出力は確認不能である。

- 分別器を「使用済み頂点から遠いもの」優先で追加する意図は、空間的に余裕のある候補を使うためと推測できるが、最適性は保証されない。
