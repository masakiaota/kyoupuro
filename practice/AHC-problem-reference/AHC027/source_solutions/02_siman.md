## 解法の全体像

ビームサーチで短めの初期解を作り、その初期解に対して焼きなましで経路の一部削除と再構築を繰り返す方針である。初期解は1回の探索で全マス訪問と帰還を同時に達成しようとせず、通常探索、未到達領域を埋める処理、初期位置へ戻る処理に分けて作る。

通常探索では、スコアそのものよりも未到達セルを減らすことを優先する。最後に残った未到達セルは、既存経路から枝のように往復する短い経路を差し込んで埋める。焼きなましでは短い区間を削除し、制約付きの小幅ビームサーチで代替区間を作る。

## 主要アイデア

- 初期解生成に約500ms、焼きなましに約1500msを使う。
- 初期解は、通常探索を複数回行い、未到達領域を枝パスで埋め、最後に始点へ戻す3段構成にする。
- 通常探索の主評価は到達済みセル数である。スコア評価だけだと汚れにくいマスへ行きにくいためである。
- 未到達セルの `d` を一時的に +25 して、探索が未到達領域へ向かいやすくする。
- 未到達セルは、隣接する到達済みセルから `到達済み -> 未到達 -> 到達済み` の枝を生やすように追加する。
- 焼きなましでは、長さ2から8程度の区間を消し、幅3程度の小さいビームで作り直す。
- 作り直しでは、最大長、重複回避、短すぎる再訪間隔の回避、全セル訪問維持などの制約をかける。

## 最終コードの構造

BrowserでAtCoder順位表から最終提出 #48408787 を辿り、C++コードを読めた。以下は提出コードと記事本文を合わせた構造である。

### 状態表現

- 盤面は壁付きグリッドとして持つ。
- 経路はマス列または移動文字列で持つ。
- 各マスについて到達済みか、現在経路中で何回訪れているかを持つ。
- 焼きなまし用に、各マスの訪問時刻列を持つ。
- 区間削除時に未到達になるマス集合を一時的に管理する。
- 提出コードでは `RecurringCleaningRoute` が盤面・距離・経路を持ち、`PathNode` / `Node` がビーム状態を表す。

### 観測・制約・入力の扱い

- 壁で移動可能な隣接マスを前計算する。
- 通常探索では、直前に通ったセルやすでに探索済みのセルへ戻る動きをなるべく禁止する。ただし行き止まりや壁が多い場所では例外を許す。
- 未到達領域は、到達済みセルに隣接していれば枝パスで1セルずつ埋める。
- 最終経路は全マス訪問、始点帰還、壁非衝突を満たす必要がある。

### 評価関数

- 通常探索の最重要評価は残り未到達セル数、または到達済みセル数である。
- 生スコアとして、現在の汚れ総和とこれまでの汚れ総和も評価に入れるが、未到達削減より重みは低い。
- 未到達セルの評価用 `d` を +25 して、汚れにくい未訪問マスも探索候補に入りやすくする。
- 焼きなましで代替区間を作るときの評価は、削除した汚れの総和を主に使い、乱数を足して同じ経路ばかりになるのを避ける。
- 採択時の評価は生スコアをそのまま使う。記事では差分ではなくフル計算だったと述べられている。

### 探索・構築・更新

- 通常探索は、数百手程度の短い経路をビームで作り、それを複数回つなぐ。
- 未到達セル数が一定以下になるまで通常探索を繰り返す。
- 未到達領域が少数になったら、既存経路の途中へ枝パスを挿入して埋める。
- 始点へ戻る最後の経路は、最短距離を基本にしつつスコアがよくなる経路を選ぶ。
- 焼きなましではランダム区間を削除し、削除区間の前後をつなぐ代替経路を小幅ビームで探索する。
- 代替経路が見つからない場合は、重複禁止や再訪間隔チェックなどの制約を緩めて再探索する。

### 操作・クエリ・出力選択

- 焼きなまし後の経路をそのまま `UDLR` 文字列として出力する。
- 区間削除で一度も訪れないセルが発生した場合は、代替経路がそのセルを通らなければ無効にする。
- 小さい `N` で時間に余裕がある場合は、初期解を複数作って最もスコアのよいものを焼きなましの起点にする。

### 時間配分・パラメータ

- ビームサーチによる初期解生成は約500ms。
- 焼きなましは約1500ms。
- 未到達セルの `d` 底上げは +25。
- 焼きなましで削除する区間長は2から8。
- 代替経路探索のビーム幅は3程度。
- 代替経路の最大長は削除区間長 + `2,4,6` のいずれかで、偶奇性を考えて偶数だけを使う。

## 実装上重要な断片

```text
build_initial_route:
    while unvisited_count > threshold:
        run short beam search
        append found route
        mark visited cells
    while unvisited cells remain:
        insert branch path from adjacent visited cell
    append route back to (0, 0)
```

```text
rebuild_deleted_segment(l, r):
    required = cells whose visit_count becomes 0 after deletion
    max_len = (r - l) + random_choice([2, 4, 6])
    run tiny beam from route[l-1] to route[r]
    reject if required cells are not visited
    reject if immediate revisit interval is too short
```

## この解法の本質

この解法の本質は、初期解生成で「スコアのよい巡回路」と「全マス訪問」を無理に同時最適化しない点である。まず未到達を減らす専用評価で大枠を作り、最後に枝パスで訪問制約を満たす。焼きなましの時間を確保するため、初期解は完璧さより短さと制約充足を優先する。

また、局所再構築で短い区間だけを小幅ビームに任せることで、単純な1手近傍より大きく状態を変えつつ、探索空間を制御している。制約を満たす代替経路が見つからないときに制約を緩める設計も実装上重要である。

## 真似するならまず実装する部分

まず、DFSなどで全マスを通る初期経路を作り、訪問時刻列から生スコアを計算する関数を作る。次に、短区間を削除して BFS または小幅ビームで前後をつなぎ直す近傍を作るのがよい。

上位化を狙うなら、未到達セルの底上げ付きビーム初期解と、枝パス挿入を実装する。枝パスは実装が比較的軽く、初期解を短く保ちやすい。

## 注意点・未理解点

- 最終コードが公開されていないため、評価重み、通常探索のビーム幅、未到達閾値、焼きなまし温度は記事からは分からない。
- フルスコア計算で焼きなましを回すため、経路長を伸ばしすぎると反復回数が減る。
- 枝パスは全マス訪問制約を満たしやすいが、低 `d` のマスへの往復が増えすぎると周期全体の効率が落ちる。
- 代替区間の制約を強くしすぎると候補が見つからず、弱くしすぎると短周期再訪でスコアが悪化する。
