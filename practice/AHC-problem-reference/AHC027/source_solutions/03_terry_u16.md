## 解法の全体像

まず、各マスをどの頻度で掃除するべきかを緩和問題から考察し、汚れやすさ `d` の平方根に比例する頻度を目標にする。これをそのまま実現するのは難しいため、訪問頻度を2冪に丸め、頂点列 `P` を段階的に構築する。

`P` は、高 `d` のマスから順に貪欲挿入と焼きなましで整え、各段階の後に列を2倍化する。これにより、高 `d` の頂点ほど列の中に多く現れる。最後に `P` の隣接頂点間を、汚れやすいマスを通りやすいようコスト調整したダイクストラで接続し、実際の経路 `R` を得る。`R` に対してさらに焼きなましを行う。

## 主要アイデア

- 位置や整数時刻を無視した緩和問題では、マスの掃除回数はおおむね `sqrt(d)` に比例するのがよい。
- この緩和解を下界として使い、手元実験のスコアを下界比で管理する。
- 訪問頻度を2冪に丸めると、頂点列を「高頻度部分を複製しながら低頻度頂点を差し込む」形で作れる。
- 高 `d` の頂点集合から順に、既存の `P` から遠い頂点を選び、挿入後の生スコアがよい位置へ入れる。
- 挿入候補は、経路長増加が小さい位置を複数選んでから詳細評価する。
- `P` 上の焼きなましでは、グリッド上の距離だけでなく、`P` からの Voronoi 的なグループサイズを距離に足して評価する。
- 最後は `P` を実歩行可能な経路 `R` へ変換し、挿入・削除と乱択ダイクストラによるつなぎ直しで改善する。

## 最終コードの構造

BrowserでAtCoder順位表から最終提出 #48408786 を辿り、Rustコードを読めた。以下は提出コードと記事本文を合わせた構造である。

### 状態表現

- `P`: 掃除したい代表マスの周期列。隣接要素はグリッド上で隣接しているとは限らない。
- `R`: `P` の各隣接ペアを実際の移動列で接続した周期路。
- 各マスの `d` と `sqrt(d)` 相当の目標頻度を持つ。
- `P` に含まれるマス集合から BFS し、各マスがどの `P` 頂点に近いかとグループサイズ `s` を持つ。
- `R` の生スコア計算用に訪問時刻列を持つ。
- 提出コードでは `SinglePath` / `DoublePath` が抽象列、`DistEnv` が距離環境、`AreaEnv` がグループ情報、`LoopInsertionSolver` が挿入・削除系の改善を担う。

### 観測・制約・入力の扱い

- 壁付きグリッドをグラフとして扱い、最短距離やダイクストラ接続に使う。
- `P` の段階構築では、`d` の閾値帯ごとに追加対象のマスを決める。
- 記事では理論上の区切りは `256,64,16,4,1` だが、実際には `N` ごとに少しずらしたとある。
- `R` は最終的に全マスを訪問し、`(0,0)` に戻る周期路でなければならない。

### 評価関数

- 緩和問題では、長さ `L` の周期でマス `i` を `c_i` 回掃除すると、そのマスの汚れ寄与はおおむね `d_i * L^2 / (2 c_i)` になる。
- 平均汚れは `L / 2 * sum(d_i / c_i)` に対応し、これを小さくするには `c_i` を `sqrt(d_i)` に近づけるのがよい。
- `P` の貪欲挿入では、`P` に一度以上入った頂点だけを考え、頂点間は最短経路を通ると仮定した生スコアで評価する。
- `P` 焼きなましでは、移動コストを `dist(u,v) + 0.5 * s_v` のように補正する。`s_v` は移動先頂点が受け持つグループサイズである。
- `R` の焼きなましでは、生スコアを愚直計算する。

### 探索・構築・更新

- 空の `P` から始める。
- 高 `d` のマス集合を選び、`P` に含まれる頂点集合から遠い順に追加する。
- 各追加では、挿入による経路長増加が小さい候補位置を絞り込み、その候補だけを全探索してよい挿入位置を選ぶ。
- 追加後、`P` に対して焼きなましを行う。
- その後 `P = P + P` として列を2倍にし、次に低い `d` 帯のマスを追加する。
- 全マスが `P` に含まれたら、隣接ペアをダイクストラで接続して `R` を作る。
- `R` の焼きなまし近傍は、`P` の適当な箇所へのマス挿入、`P` のマス削除、それに伴う `R` の乱択ダイクストラつなぎ直しである。

### 操作・クエリ・出力選択

- `P` は抽象的な訪問順序であり、そのまま出力できない。
- 出力は `R` を `UDLR` の移動列に変換したものになる。
- ダイクストラ接続では、その時点で `d` が大きいマスを通りやすくなるようにコストを調整する。
- 最終的に `R` を `(0,0)` 始まりの周期路として出力する必要がある。

### 時間配分・パラメータ

- 閾値帯は記事上は `d >= 256`, `64 <= d < 256`, `8 <= d < 64` のように説明されている。
- 理論上の区切りは2冪だが、実装では `N` ごとに実験的にずらしたとある。
- `P` 焼きなましの近傍は、1マス削除挿入、連続複数マス削除挿入、2-opt。
- グループサイズ補正の係数は `0.5`。
- 生スコアは差分ではなく愚直計算だったため、差分計算ができれば伸びた可能性があると述べられている。

## 実装上重要な断片

```text
build_P:
    P = []
    for each dirtiness band from high to low:
        for v in cells_of_band sorted by distance_from(P) desc:
            candidates = positions with small distance increase
            insert v at candidate minimizing estimated raw score
        anneal_vertex_sequence(P)
        P = P + P
```

```text
connect_P_to_R:
    R = []
    for each consecutive pair (P[k], P[k+1]):
        path = dijkstra(P[k], P[k+1], cost adjusted to prefer dirty cells)
        append path to R
```

## この解法の本質

この解法の本質は、問題を「どのマスを何回掃除するべきか」という頻度設計に落としてから経路構築へ戻している点である。移動制約をいきなり最適化するのではなく、まず `sqrt(d)` 頻度という目標分布を持つことで、初期解が大局的に破綻しにくくなる。

2冪化と列の2倍化も重要である。高頻度にしたいマスを先に入れて列を複製すると、高 `d` マスは自然に多く現れ、低 `d` マスは後から隙間に入る。頻度設計をデータ構造上の繰り返しで表現しているのが強い。

## 真似するならまず実装する部分

まず `sqrt(d)` を目標頻度とみなし、`d` の大きいマスから順に巡回順序へ挿入する簡単な `P` 構築を作るとよい。焼きなましやグループサイズ補正を入れる前に、`P` を最短路でつないでスコア計算できるところまで作る。

次に、`P = P + P` による頻度調整と、挿入位置の貪欲評価を入れる。最後に `P` 上の2-optや削除挿入を追加すると、記事の方針に近づく。

## 注意点・未理解点

- 最終コードが公開されていないため、閾値、温度、乱択ダイクストラの具体的なコスト式は記事本文以上には分からない。
- `P` の生スコア評価は実経路 `R` を近似しているため、接続時に大きく崩れる可能性がある。
- `P` の2倍化は長さを急激に増やす。`10^5` 制限と焼きなまし反復回数の両方を見て調整する必要がある。
- 差分計算なしで生スコアを愚直計算すると、近傍の試行回数が伸びにくい。
