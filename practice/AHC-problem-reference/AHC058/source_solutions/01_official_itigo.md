## 解法の全体像

公式解説は 1 つの完成コードではなく、複数の有効方針を段階的に強くしていく構成である。最初は「今買える中でよさそうなものを買う」貪欲から始め、次に購入列を焼きなましで直接最適化する。さらに、最終的には 1 つの ID に集中投資する傾向が強いことを利用して、集中投資先と到達すべきチェックポイントを全探索する強い貪欲を作る。この強い貪欲を初期解や補助方針として焼きなましに渡し、さらに状態をまとめるビームサーチと組み合わせることで上位スコアに近づけている。

## 主要アイデア

- ID ごとに独立した 4 段階の生産連鎖があるため、最終的には 1 つまたは少数の ID に集中投資しやすい。
- 「この後何も強化しなかった場合の最終りんご数」を評価値として使うと、候補の将来価値を比較しやすい。
- 焼きなましは「どの機械をいつ強化するか」の順序探索に強いが、安い局所的 ID に閉じこもると高い A の ID へ移りにくい。
- 貪欲では集中投資する ID と、そこへ到達するためのチェックポイントを全探索する。
- 強い貪欲は、チェックポイント到達前と到達後で評価関数を切り替える。
- ビームサーチでは、購入順が違っても同じ `P` 配列になる状態をハッシュでまとめる。
- 高速評価では、以降に何もしなかった場合の生産量を多項式的に計算し、ビーム幅を大きく取れるようにする。
- 最終的には、ID 選択に強いビーム・貪欲と、購入時刻の最適化に強い焼きなましを補完的に使う。

## 最終コードの構造

以下はスライドとキャッシュ実装 `#71635590` から確認した構造である。

### 状態表現

- `K`: 現在のりんご数
- `B[i][j]`: Level `i`, ID `j` の機械数
- `P[i][j]`: Level `i`, ID `j` の強化回数
- `actions`: 500 ターン分の行動列、または強化対象列
- ビームサーチでは `P` のハッシュを持ち、同じ強化結果に至る状態を重複排除する
- 差分更新には、強化前後の `K`, `B`, `P` と、以降何もしない場合の評価値が必要になる

### 観測・制約・入力の扱い

- 入力は固定で `N=10, L=4, T=500, K=1`。
- 毎ターン出力は 1 行で、強化するなら `i j`、何もしないなら `-1`。
- 強化コストは `C[i][j] * (P[i][j] + 1)` であり、支払えない行動は候補から外す。
- 生産処理は Level 0 から Level 3 の順に行う。この順序を間違えると同じターン内の増加が変わる。

### 評価関数

- 基本評価は「現在の状態から以降何もしなかった場合の最終りんご数」。
- 焼きなましでは、最終スコアに加えて各ターンの `log` の和に時間減衰係数を掛けた項を入れる方針が示されている。
- 強い貪欲では、チェックポイント到達前は「対象を買えるまでのターン数」を短くする評価、到達後は「最終りんご数」を大きくする評価へ切り替える。
- ビームサーチでは、無強化時の将来生産量を高速に計算する。スライドでは厳密計算可能とされているが、詳細式は省略されている。

### 探索・構築・更新

- 簡単な貪欲:
  - Level 1, ID 0 を強化するまでは、強化可能な Level 0 のうち `A` が最大のものを強化する。
  - それ以降は、強化可能な ID 0 のうち Level が最大のものを強化する。
- 焼きなまし:
  - 購入順序を解として持つ。
  - 近傍は変更、削除、追加、交換。
  - 初期解として 0 ターン目に `(0,0)` を強化する列が挙げられている。
- 二段階貪欲:
  - 集中投資する `j1` と投資開始レベル `i1` を全探索する。
  - `(i1,j1)` を最速で強化するまでは、そこへ到達しやすい手を選ぶ。
  - 到達後は ID `j1` に絞って最終りんご数を最大化する。
- 三段階貪欲:
  - 中間投資先 `(i2,j2)` を追加し、`(i2,j2)`、`(i1,j1)`、ID `j1` 全力投資の順にする。
- ビームサーチ:
  - ノードは現在状態と行動履歴を持つ。
  - 遷移は強化候補または待機。
  - `P` のハッシュで同一強化結果をまとめる。
  - ビーム幅の例として 5000 が示されている。

### 操作・クエリ・出力選択

- 各ターンで 1 つの強化、または `-1` を選ぶ。
- 貪欲ではその場の評価最大候補を出力列に追加する。
- 焼きなましでは、購入列を実際の 500 ターン行動へシミュレートし、支払えない間は待機する実装が自然である。
- ビームサーチでは最終評価が最大のノードから親を辿って行動列を復元する。

### 時間配分・パラメータ

- キャッシュ実装のビーム幅は400。
- 三段階貪欲は `(i1,j1)` と `(i2=1,j2)` を全探索し、上位2候補だけをビームへ渡す。
- 焼きなましは約1.95秒まで購入列を直接近傍更新する。
- 焼きなまし評価は `log2(final_apple) + score_log_sum * weight` で、`weight` は0.002から0へ減衰する。

## 実装上重要な断片

キャッシュ実装には `wata's beam search + itigo's simulated annealing` というコメントがあり、強い貪欲で候補を絞ったあと幅400のビームを走らせ、その購入列を焼きなましで後処理する構造になっている。`State` は平坦化した `B`/`P`、りんご数、ターン、trace idを持ち、`future_K` は4レベルの組合せ式で無強化時の将来りんご数を閉形式計算する。

ビームは3フェーズで、まず `(i2,j2)`、次に `(i1,j1)`、最後に `j1` 全力投資へ誘導する。重複排除は第1フェーズでは完全な `P`、第2/第3フェーズでは対象列の強化回数を粗く割ったキーを使う。焼きなまし近傍は変更、削除、挿入、swapで、購入列を実シミュレーションして支払えない場合は待機する。

```text
checkpoint_greedy(target):
    while target is not upgraded:
        choose affordable move minimizing turns until target becomes affordable
        apply one turn
    while turns remain:
        choose affordable move with same target_id maximizing final apples after no more upgrades
        apply one turn
```

```text
beam_step(states):
    next = []
    for state in states:
        for action in candidate_upgrades(state) + wait:
            child = simulate_one_turn(state, action)
            child.score = future_value_if_no_more_upgrade(child)
            next.add(child)
    merge by hash(P)
    keep top beam_width
```

## この解法の本質

この問題では、1 回の強化の価値が単独で決まらず、同じ ID の上位 Level と下位 Level が掛け算的に効く。したがって、短期的に安い機械を買い続けるだけでは高い `A` の系列に移れず、逆に高い系列へ行こうとしすぎると序盤の資金生成が遅れる。公式解説の本質は、局所的な購入順の最適化と大局的な集中投資先の選択を別々に扱い、それぞれに向いた探索を使う点である。

## 真似するならまず実装する部分

まず、状態シミュレータと「以降何もしない場合の最終りんご数」評価を実装する。その上で、集中 ID を 10 通り全探索し、対象 ID の評価を優遇する貪欲を作るのが最小実装としてよい。焼きなましやビームサーチは、貪欲の出力と評価関数が正しく動くことを確認してから追加する。

## 注意点・未理解点

- 公式スライドに実コードはないが、キャッシュ実装で提出コードの接続部分は確認できた。
- 無強化時の高速評価式は、提出コードでは4レベルの組合せ式として実装されている。
- `P` ハッシュだけで状態をまとめる場合、`K` や `B` が異なる同一 `P` 状態をどう代表させるかを設計する必要がある。
- 焼きなましで購入列を持つ場合、支払えない行動を待機で先送りするのか、無効化するのかで評価が変わる。
