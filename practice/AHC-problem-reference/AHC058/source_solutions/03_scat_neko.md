## 解法の全体像

評価値貪欲をベースに、集中投資する ID と序盤評価のパラメータをグリッドサーチする解法である。各ターンで、候補 `(i,j)` を 1 回強化した後に何も強化しない場合のりんご数増分を評価する。固定した集中投資先 ID の候補は評価値を 1000 倍して優遇する。序盤だけは最終ターンではなく数十ターン後のりんご数差分で評価し、早めに資金生成力を伸ばす。最後に、数ターン待てば未購入の次 Level に届く状況では `-1` を出して待つ改善を入れている。

## 主要アイデア

- 1 手の価値を「その手を買った場合」と「何もしなかった場合」の将来りんご数差分で測る。
- 最終ターン評価だけだと ID 0 付近に寄りやすいため、集中投資先 ID を固定して評価値を強くする。
- 集中投資先 ID、序盤モード終了ターン、序盤評価 horizon の 3 種類をグリッドサーチする。
- 序盤は最終ターンではなく、近い未来の資金力を評価する。
- あと 5 ターン待てば未購入の次 Level を買えるなら、低価値な購入より待機を選ぶ。
- 焼きなましやビームサーチを使わず、実装量を抑えたまま高得点を狙う。

## 最終コードの構造

以下は本文の説明とキャッシュ実装 `#71760160` から確認した構造である。

### 状態表現

- `K`: 現在のりんご数。非常に大きくなるため多倍長整数か対数管理が必要である。
- `B[4][10]`: 機械数。
- `P[4][10]`: 強化回数。
- `turn`: 現在ターン。
- `actions[500]`: 出力する行動列。
- パラメータとして `focus_id`, `early_until`, `early_horizon` を持つ。

### 観測・制約・入力の扱い

- 各ターンの候補は、支払い可能な `(i,j)` と `-1`。
- 候補評価のために、現在状態をコピーし、候補を 1 回適用した後、評価時点まで無強化でシミュレートする。
- 比較対象として、現在状態から何も強化しない場合の同じ評価時点のりんご数も計算する。
- 「未購入の次 Level」は、キャッシュ実装では集中ID `best_series` のうち `P=0` で最初に見つかるLevelを指す。

### 評価関数

- 通常評価:
  - `value(i,j) = apples_after_upgrade_and_idle(T) - apples_after_idle(T)`
- 集中 ID 補正:
  - 候補の `j == focus_id` なら `value *= 1000`
- 序盤評価:
  - `T` の代わりに、現在ターンから `early_horizon` ターン先のりんご数差分を使う。
  - 序盤モードは `turn < early_until` の間だけ使う。
- 待機改善:
  - 5 ターン以内に未購入の次 Level を買える見込みがある場合、今の購入候補より `-1` を選ぶことがある。

### 探索・構築・更新

- ベース貪欲:
  - 各ターンで全 `(i,j)` を試す。
  - 強化後に以降何もしなかった場合の最終りんご数が最大の候補を買う。
- 改善版:
  - `focus_id` を固定する。
  - 評価は「候補あり」と「候補なし」の差分。
  - `focus_id` 候補に倍率をかける。
  - 序盤は短期 horizon 評価にする。
- パラメータ探索:
  - `focus_id`、序盤モード終了ターン、序盤評価 horizon を探索する。
  - 本文ではグリッドサーチ、終了後の試行ではランダムサーチの方がやや強いとされている。

### 操作・クエリ・出力選択

- 毎ターン、評価値最大の `(i,j)` を出力する。
- 支払えない候補は除外する。
- 待機改善が発火した場合は `-1` を出力し、資金を貯める。
- 500 ターンすべてを逐次確定するため、親復元などは不要である。

### 時間配分・パラメータ

- `focus_id`: 実装では各再始動で乱択する `best_series`。
- `focus_multiplier`: 実装では1000ではなく `approve *= 10000`。
- `early_until`: `initial_stage_turn` を30..100から乱択。
- `early_horizon`: `initial_check_turn` を10..50から乱択。
- `wait_threshold`: あと 5 ターン。
- 制限時間約1950msまでランダム再始動し、最良の最終りんご数を採用する。

## 実装上重要な断片

キャッシュ実装はグリッド固定ではなく、約1950msのランダム再始動貪欲である。各runで `initial_stage_turn`、`initial_check_turn`、集中IDを乱択し、最良結果を保持する。状態は `usize` のりんご数、4x10の機械数・強化回数、行動列を持つ。

候補評価 `marginal_gain` は組合せ式を `u128` 飽和で計算し、候補を1回買った場合の追加りんご数からコストを引く。0ターン目は `C[0][i]==1` のうち `A` 最大のLevel0を強制購入する。待機判定は、集中IDでまだ未購入の最初のレベルを見つけ、その次コストが現在りんごより大きく `apples_in_turn()*5` 未満なら `-1` を出す。

```text
eval_candidate(state, action, horizon_turn):
    base = simulate_idle(copy(state), horizon_turn).K
    next = copy(state)
    apply_upgrade(next, action)
    simulate_one_turn(next)
    score = simulate_idle(next, horizon_turn).K - base
    if action.id == focus_id:
        score *= 1000
    return score
```

```text
for turn in 0..499:
    horizon = turn + early_horizon if turn < early_until else T
    best = argmax_affordable_action(eval_candidate(state, action, horizon))
    if can_buy_unpurchased_next_level_after_waiting_at_most_5_turns(state):
        best = wait
    output best
    simulate_one_turn_after_action(state, best)
```

## この解法の本質

この解法は、AHC058 の難所を「良い ID に集中投資すること」と割り切っている。評価値貪欲だけでは安くて早い ID に寄るが、集中 ID の評価を 1000 倍することで、高 `A` 系列へ移るための一時的な不利を超えやすくしている。また、序盤評価を短期 horizon にすることで、最終ターンの巨大な将来価値に引っ張られすぎず、資金生成の立ち上がりを優先できる。

## 真似するならまず実装する部分

まず無強化シミュレーション評価を作り、ベース貪欲を動かす。次に `focus_id` を 10 通り全探索し、`j == focus_id` の評価値を大きくする。さらに、序盤だけ horizon を短くする 2 パラメータを探索する。待機改善は最後に足すのがよい。

## 注意点・未理解点

- キャッシュ実装では、多倍長ではなく `u128` 飽和で候補評価を行い、最終状態も `usize` を使う。
- キャッシュ実装では、本文の評価値1000倍ではなく10000倍で集中IDを優遇している。
- 「未購入の次 level」は、集中IDで `P=0` の最初のレベルとして実装されている。
- 終了後のランダムサーチが強いという本文の記述に近く、提出コードも固定グリッドよりランダム再始動型になっている。
