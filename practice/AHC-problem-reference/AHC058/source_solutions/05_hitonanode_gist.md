## 解法の全体像

低収入フェーズの貪欲、高収入フェーズのブロック計画、パラメータ全探索、最後の山登り後処理を組み合わせる方針である。序盤は、次に買う機械を全探索し、できるだけ早く買えて最終りんご数が大きくなる候補を選ぶ。毎ターンの収入が閾値を超えた後は、10 ターン単位で 1 つの ID に対する Level 別強化回数の割当を全探索する。さらに固定 ID に移る閾値などを全探索し、得られた強化列を山登りで改善する。

## 主要アイデア

- 収入が少ない間は、支払い可能性と最終価値を見た貪欲で立ち上げる。
- 収入が増えた後は、10 ターンブロックごとに同一 ID へ集中投資する。
- ブロック内では Level 3,2,1,0 の順に、割当が残っていて支払えるものを買う。
- 一定以上の収入になったら、以降の高収入フェーズは特定 ID に固定する。
- `fixed_j_threshold`, `fixed_j`, `low_income_threshold` を全探索する。
- 生成された強化対象列に対して山登りを行う。
- 評価時は、列の途中まで使った場合の最終りんご数も見て、最良 prefix を採用する。
- 列が T 前に尽きた場合は、末尾 ID の Level 0 強化が無限に続くものとして延長する。

## 最終コードの構造

コードなし。`STRATEGY.md` から実装構造を復元する。

### 状態表現

- シミュレーション状態は `K`, `B[4][10]`, `P[4][10]`, 現在ターン。
- 解は「過去、どのターンに何を行ったか」として保持する。
- 後処理では、状態を「強化を行う `(i,j)` の列」として持つ。
- 最良解を常に保存し、最後に最良解を出力する。
- 評価高速化のため、現在状態から無強化で `t` ターン進めたときのりんご数を多項式関数として扱う。

### 観測・制約・入力の扱い

- 支払えない候補は原則採用しない。
- 低収入フェーズでは、すぐ支払えない候補は避け、最も早く強化できる候補群の中から評価する。
- 高収入フェーズでは、ブロック内で割当があっても支払えないときは `-1` を出す。
- `B = min(10, 残りターン)` としてブロック長を調整する。

### 評価関数

- 低収入フェーズ:
  - 「その機械をできるだけ早く買う」前提で、T ターン後のりんご数が最大のものを選ぶ。
  - ただし、買えるまでが遅い候補は避ける。
- 高収入フェーズ:
  - 次の `B` ターンで同じ ID の Level 0..3 に何回ずつ強化を割り当てるかを全探索し、T ターン後のりんご数で評価する。
- 後処理:
  - 近傍ごとにシミュレーションし、列の `k` 個目まで処理した時点で打ち切った場合の最終りんご数を高速計算する。
  - 最良の `k` を採用し、それ以降の要素は捨てる。

### 探索・構築・更新

- 貪欲本体:
  - 低収入フェーズと高収入フェーズを収入閾値で切り替える。
  - 高収入フェーズでは 10 ターンの割当を全探索する。
- パラメータ全探索:
  - `fixed_j_threshold`: 10, 100, 1000, 10000, 100000, 1000000
  - `fixed_j`: 0..9
  - `low_income_threshold`: 10, 100, 1000
  - 合計 180 通りを試す設計である。
- 山登り後処理:
  - 隣接 swap。
  - ある要素の Level を大きくし、更新前と同じ要素を末尾に追加する。
  - ランダム要素を挿入する。挿入 ID は左右どちらかの隣接要素と同じ ID、Level はランダム。
  - 改善したら解を更新する。
  - 1.9 秒程度まで反復し、乱数 seed は固定する。

### 操作・クエリ・出力選択

- 低収入フェーズでは毎ターン 1 手ずつ決める。
- 高収入フェーズではブロック計画に従い、Level 3 から 0 の優先順で支払える強化を出力する。
- ブロック内で支払えない場合は `-1`。
- 後処理で得た強化列は、実際のターン列へシミュレートして出力する。
- 最良 prefix 以降は捨て、必要なら末尾 ID の Level 0 強化で延長する。

### 時間配分・パラメータ

- 高収入フェーズのブロック長 `B` は基本 10。
- `fixed_j_threshold` は 6 通り。
- `fixed_j` は 10 通り。
- `low_income_threshold` は 3 通り。
- 後処理は実行時間約 1.9 秒まで。
- 乱数 seed は固定して再現性を持たせる。

## この解法の本質

この方針は、ターンごとに完全な自由度を持たせず、収入状態に応じて探索空間の形を変えている。序盤は「買えるかどうか」が支配的なので早期購入可能性を重く見る。中盤以降は同一 ID への集中投資が強いので、10 ターン単位の Level 割当に落とす。最後に、生成列に対して局所的な順序変更や挿入を試し、貪欲の硬さを山登りで補う。

## 真似するならまず実装する部分

まず低収入フェーズの貪欲と、無強化時の最終りんご数評価を作る。次に高収入フェーズの 10 ターン割当全探索を追加する。パラメータ全探索はループで包むだけなので入れやすい。山登りは最後に、隣接 swap だけから始めるとよい。

## 注意点・未理解点

- gist には実コードがなく、`main.cpp` は読めない。
- 多項式による高速評価は「書けるはず」とされており、具体式は実装者側で導出が必要である。
- 高収入フェーズのブロック割当は、ブロック内の順序を Level 3 優先に固定するため、場合によっては細かい時刻最適化を落とす。
- 山登りの採択条件は改善のみで、悪化受理は書かれていない。局所解からの脱出力は近傍の大きさに依存する。
- 低収入から高収入への切替閾値はケース依存が大きそうで、全探索範囲外に最適値がある可能性がある。
