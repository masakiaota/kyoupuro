## 解法の全体像

この記事は単一解法ではなく、勉強会で出た方針の比較である。方針は貪欲、ビームサーチ、焼きなましの 3 系統に分かれる。共通して、最終りんご数を高速に見積もる評価、ID を固定または偏らせる工夫、局所解から脱出するための列操作が重要になっている。作問体験記からは、コストのランダム幅を大きくしたことで「常に最大 `A` へ全力投資」では済まない問題になり、集中投資先の選択が難所になったことが読み取れる。

## 主要アイデア

- 貪欲勢は、次の購入候補を選ぶ評価として、数十ターン後または最終ターンのりんご数を使う。
- 集中投資先 ID を固定、全探索、または評価倍率で優遇する方針が多い。
- ビームサーチ勢は、行動を「今すぐ買う」だけでなく「指定機械が買えるまで待つ」として扱う。
- Zobrist hash などで同一または類似状態をまとめ、ビームの重複を減らす。
- chokudai サーチでは、後半から ID 固定制約を入れて探索空間を削る。
- 焼きなまし勢は、操作列または購入対象列を解として持ち、変更、挿入、削除、交換などの近傍で局所解を崩す。
- 大局的な ID 選択だけを先に焼き、その後 ID と Level を含む細かい列を焼く二段階法もある。

### 状態表現

- 共通のシミュレーション状態は `K`, `B[4][10]`, `P[4][10]`, 現在ターン。
- 貪欲では現在状態だけを持ち、毎ターン候補 `(i,j)` を全探索する。
- ビームサーチでは状態列を持ち、親参照または行動履歴で出力を復元する。
- 焼きなましでは「500 ターンの操作列」または「購入対象 `(id, level)` の列」を解として持つ。
- ID 固定系では `fixed_id` や「80 ターン目以降はこの ID だけ」のような制約を状態または候補生成に持たせる。

### 観測・制約・入力の扱い

- 入力生成上、`A` は昇順だがコストには大きなばらつきがある。高 `A` が常に正解とは限らない。
- 出力は 500 行ちょうど必要で、列ベース探索でも最終的には支払い可能性を確認しながらターン列へ変換する。
- 支払えない機械を目標にした場合は、買えるまで待つか、途中で資金生成用の別機械を買う必要がある。

### 評価関数

- 多くの方針で「以降何もしなかった場合の最終りんご数」を評価する。
- Kiri8128 の方針では、ターゲット到達までのターン数と、50 ターン後のりんご数を使う。
- scat_neko の方針では、最終りんご数差分を基本にし、集中 ID の評価値を強める。
- momohara / terry_u16 のビームサーチでは、最終りんご数を評価関数にする。terry_u16 はこれを O(1) で求めるとしている。
- yochan の焼きなましでは、採用されやすい ID を `A` とコスト群から作る重みで偏らせる。

### 探索・構築・更新

- Kiri8128:
  - ターゲットを設定する。
  - ターゲットを買えるまでのターン数を最小化する。
  - 50 ターン後のりんご数が最大になる強化を選ぶ。
  - 貪欲で作った列を購入種類の焼きなましで改善する。
- scat_neko:
  - 最終りんご数差分最大の貪欲をベースにする。
  - 集中投資先 ID を全探索する。
  - 集中 ID の評価を大きくして、高 `A` 系列へ移りやすくする。
  - 序盤は数十ターン後評価に切り替える。
- momohara:
  - ビームサーチ。
  - アクションは ID と Level を指定し、それが買えるようになるまで待つ。
  - Zobrist hash で状態をまとめる。
- terry_u16:
  - 1 つの ID に集中投下する前提でビームサーチする。
  - 固定 ID は全探索する。
  - 最終りんご数評価を O(1) 化する。
- G4NP0N:
  - chokudai サーチ。
  - 80 ターン目以降は特定 ID しか買えない制約を置き、固定 ID を 10 通り全探索する。
- MathGorilla:
  - ローリングホライゾン焼きなまし。
  - 現在ターンから 20 ターン分を焼き、前半 10 ターンを確定して進める。
- aaaaaaaaaa2230:
  - `(id, level)` の購入順序を焼きなましする。
  - 近傍は insert, remove, swap, change。
  - 反復回数は 1 万から 3 万程度。
- yochan:
  - 操作列を初期解なしで焼く。
  - 近傍は 1 点変更、隣接 swap、insert、erase。
  - 反復回数は 6 万程度。
- takumi152:
  - 1 段階目で ID 列を焼き、その ID 内で買える最高 Level を買う。
  - 近傍は変更、順序移動、swap、ある点以降を同一 ID にする操作。
  - 2 段階目で ID と Level を含む列を焼く。

### 操作・クエリ・出力選択

- 貪欲は毎ターン 1 手を確定して出力列へ入れる。
- ビームサーチは最終状態から親を辿って 500 手を復元する。
- 購入列の焼きなましでは、列を先に作り、実際のシミュレーションで支払えないときの待機を挿入する実装が考えられる。
- ローリングホライゾンでは、焼いた 20 ターン全体ではなく、前半 10 ターンだけを確定出力に近い形で採用する。

### 時間配分・パラメータ

- 数十ターン後評価の horizon。
- 序盤モードを何ターン続けるか。
- 固定 ID を開始するターン。G4NP0N の例では 80 ターン目以降。
- ビーム幅、chokudai サーチの各深さの保持数。
- 焼きなましの反復回数、温度、近傍比率。
- ID 採用確率の重み式。

## この解法の本質

勉強会レポートから分かる本質は、AHC058 では「どの ID に寄せるか」と「いつ上位 Level に投資するか」が絡み合って局所解を作る点である。貪欲は評価値を工夫すればかなり強いが、集中先を誤ると伸びない。焼きなましは順序を崩せるが、巨大な探索空間をそのまま焼くと ID 選択が安定しにくい。ビームサーチは複数の道筋を残せるが、状態数を抑えるために固定 ID やハッシュが必要になる。

## 真似するならまず実装する部分

最初は scat_neko 型の評価値貪欲を実装し、次に固定 ID 全探索を入れるのがよい。ビームサーチを試すなら、terry_u16 型の「ID を固定してからビーム」を先に作ると、状態数を抑えやすい。焼きなましは、購入対象列を持つ簡単な swap/change 近傍から始めるとよい。
