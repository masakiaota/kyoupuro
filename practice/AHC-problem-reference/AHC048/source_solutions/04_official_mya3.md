## 実装キャッシュで確認した内容

- 実装は公式解説の `W_iP_j` 候補群をほぼそのまま探索する貪欲で、`SimplePalette` は1次元の区間ウェルとして管理される。
- 初期壁は蛇行した1本の長い通路状。右下付近の単独セルと長い区間から始まり、`SetWall`/`RemoveWall` で区間を分割・結合する。
- `CalcScore` は `1e4*norm + (add-1)*D` に、未確定将来の絵の具量・廃棄・ウェル数が目標 `N^2/2.5` から離れる項を加える。進行率 `t` が上がるほど将来項は弱くなる。
- 各提出で `FindBestW1`, `WnFull`, `W2`, `Wn`, `P1..P4`, `W1P1..W1P3`, `W2P1` を順に試す。時間が厳しい場合は重い4色/一部候補をスキップする。
- 2色/3色/4色の混合比は幾何式や事前計算した逆行列で求め、区間長に丸めて仕切り位置を決める。
- `ApplyFounds` が `FoundAdd`, `FoundDeliver`, `FoundDiscard`, `FoundSet`, `FoundRemove` を操作列へ変換し、同時に実スコアを更新する。
- `SolveBeam` もあるが `main` は `solver.Solve()` を呼ぶ。提出時はビームではなく貪欲逐次選択である。

## 解法の全体像

絵の具の混ぜ方を、パレット上に残っているウェル `i` 個と、チューブ絵の具 `j` 本を混ぜる操作 `W_iP_j` として分類する。各ターゲットについて、すべてのウェルに対して `W_0P_1` から `W_0P_4`、`W_1P_0` から `W_1P_3`、`W_2P_1`、`W_nP_0` を試し、評価値が最も良い候補を貪欲に採用する。

2色、3色、4色の最適混合比は、色空間上の線分・平面・四面体への射影や連立方程式で計算する。実際のパレット操作では、ウェルのマス数を変えて、分割時に量が容量比で分かれる性質を利用し、目的の混合比に近い比率を作る。

## 主要アイデア

- 操作候補を `W_iP_j` という型に分解し、型ごとに最適混合比と実操作を計算する。
- ターゲットごとに候補を全列挙し、評価値最小の候補を貪欲に採用する。
- `W_0P_2` は、2色を結ぶ線分への射影で混合比を求める。
- `W_0P_3`、`W_1P_2` は、3点が張る平面への射影で混合比を求める。
- `W_0P_4` は、4色の行列を解き、正の重みなら四面体内部の点として扱う。
- ウェルのマス数 `n` を変えることで、分割後の量比を混合比へ対応させる。
- `W_nP_0` は連続ウェルの累積量・累積色を前計算し、高速に評価する。

## 最終コードの構造

以下は公式解説本文由来の整理を含む。提出 #66662857 の実装差分は上の「実装キャッシュで確認した内容」を優先する。

### 状態表現

- パレット:
  - 現在のウェル一覧
  - 各ウェルのマス集合、マス数、代表マス
  - 各ウェルの絵の具量、色ベクトル
  - 隣接関係と仕切り状態
- 候補:
  - 操作型 `W_iP_j`
  - 使うウェル番号、使うチューブ色
  - 必要なマス数変更 `n0, n1, n2`
  - 追加量、廃棄量、作成色、ターン数
- 評価:
  - ターゲット進行割合 `t`
  - 加えた絵の具量 `p_a`
  - 廃棄した絵の具量 `p_d`
  - パレット上のウェル数 `w`

### 観測・制約・入力の扱い

- 全ターゲットに対して貪欲に1手ずつ作成する。
- 候補のターン数が残りターンに収まるかを確認する。
- `W_0P_0` から `W_0P_4` では、操作前に対象ウェルへ残っている絵の具をすべて廃棄する。
- `W_1P_0` から `W_1P_3` では、ウェル内の残りがなくならない範囲で廃棄を許す。
- `W_nP_0` はウェル5つの連結を上限とし、1ターゲットあたりに使ってよいターン数を残りターン平均までに抑える。
- 3色混合では線形従属、4色混合では行列の特異性や負重みを弾く必要がある。

### 評価関数

記事の評価は、ターゲットとの誤差 `e`、絵の具コスト `c`、追加量 `p_a`、廃棄量 `p_d`、現在ウェル数 `w`、目標ウェル数 `w0`、進行割合 `t` を使う。小さいほど良い評価値である。

大まかには次の要素を含む。

- `10000*e`: 本来スコアの色誤差項。
- `D*(p_a-p_d-1)`: 絵の具追加量のコスト。ただしパレット上に残る分は将来使えるとして調整する。
- `(1+1e-3*c)*p_d`: 廃棄のペナルティ。Dが大きいほど廃棄を避ける。
- `|w-w0|` 系の項: ウェル数を目標値へ寄せ、将来候補を作りやすくする。
- `1-t`: 終盤に近づくほど、通常のスコアに近い評価へ寄せる。

### 探索・構築・更新

- `W_0P_1`:
  - チューブ色を全探索し、目標色との距離で評価する。
- `W_1P_0`:
  - 各ウェルの現在色をそのまま提出する候補を評価する。
- `W_0P_2`:
  - 2色を全探索する。
  - 目標点を2色の線分へ射影し、正の混合比なら候補化する。
  - 実操作では、比率の小さい色を先に入れ、ウェルのマス数変更で `n1/n0 : 1 = w1 : w2` を満たすようにする。
- `W_1P_1`:
  - 現在ウェル色と1チューブ色の2色混合として扱う。
  - 既存量 `m` を考慮し、`m*n1/n0 : 1 = ww : w1` からマス数を計算する。
- `W_0P_3`, `W_1P_2`:
  - 3色または既存ウェル+2色を全探索する。
  - 3点平面への射影で混合比を計算する。
  - `n2/n0 : n2/n1 : 1 = w1 : w2 : w3` からマス数を逆算する。
- `W_2P_1`:
  - 隣接2ウェルをそれぞれ分割し、間の仕切りを外して、1色を追加する。
  - 2つの既存ウェル量と追加色の3成分比から、必要なマス数を求める。
- `W_nP_0`:
  - 連続する複数ウェルをつなぐ候補。
  - 累積 `m_i * color_i` と累積量を前計算し、混合色を高速に計算する。
- `W_0P_4`:
  - 4色を全探索する。
  - 4x4行列で重みを解き、すべて正なら目標色を理想的に作れる候補とする。
  - 4色組ごとの逆行列を前計算すると高速化できる。

### 操作・クエリ・出力選択

- 初期仕切りは、候補操作をしやすいウェル構造を作る。
- 各ターゲットで最良候補を決めた後、その候補に対応する操作列を出力する。
- 候補に応じて、廃棄、チューブ追加、仕切り設置・削除、提出を行う。
- 1ターゲットごとに必ず操作2を1回出力し、合計H回にする。

### 時間配分・パラメータ

- `W_nP_0` は最大5ウェル連結。
- `W_nP_0` の使用ターンは、残りターン数を残りターゲット数で割った平均以下にする。
- 目標ウェル数 `w0` は、パレット幅 `N` に対して `N^2/2.5` としている。
- 4色組の逆行列前計算により、`W_0P_4` の混合比計算を高速化する。

    wa = 1 - wb

## この解法の本質

この解法は、自由度の高いパレット操作を、有限個の操作テンプレートへ落としている点が本質である。テンプレートごとに「理想の色空間上の混合比」と「それをパレットの分割・結合で作るためのマス数」を対応させることで、全探索可能な候補集合を作る。

また、評価関数にウェル数や廃棄量を入れて、現在ターゲットの最良だけでなく次以降の作りやすさを少し残す設計になっている。完全な長期探索ではないが、候補の型が豊富なので貪欲でも強くなる。

## 真似するならまず実装する部分

まずは `W_0P_1`、`W_1P_0`、`W_0P_2` だけでよい。2色混合の線分射影と、マス数変更による比率実現を実装すると、この解法の核を確認できる。

次に `W_1P_1`、`W_0P_3`、`W_1P_2` を足す。`W_2P_1` と `W_nP_0` は状態管理と操作列が複雑なので、最後に入れるのがよい。

## 注意点・未理解点

- 公式解説にはコードがないため、ウェル管理の具体的データ構造や初期配置は推測を含む。
- 3色混合で線形従属になる場合、Eigen等がNaNを返すことがあり、単純な `min < eps` 判定では弾けない。
- `W_0P_*` と `W_1P_*` で廃棄可能範囲が異なるため、量の更新を間違えるとWAになりやすい。
- 分割後の量は容量比で変わるため、色だけでなく量とマス数を同時に更新する必要がある。
- 候補数が多く、4色全探索やウェル連結候補は高速化なしだと重い。
