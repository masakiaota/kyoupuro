## 解法の全体像

公式解説は、簡単な貪欲から強い焼きなましまで段階的に説明している。最初は全頂点を根にするだけ、次に BFS 木、DFS 木、DFS の探索順改善、根順序の貪欲・焼きなましへ進む。さらに上位方針として、親配列で表される木そのものを焼きなます。

木を直接焼く解法では、各頂点の親を状態とし、部分木の高さが一括で変わる遷移を差分評価する。高速化のために、各頂点に親、子、部分木の `A` の和、部分木内の最大高さを持たせる。高さ制限を常に厳密に守ると遷移が通りにくいため、終盤に向けて強くなる高さ超過ペナルティを入れる方針も示している。

## 主要アイデア

- BFS より DFS の方が深い頂点を作りやすく、スコアが伸びる。
- DFS では `A` が小さい頂点から先に探索すると、`A` が大きい頂点が深くなりやすい。
- 根を適当に選ぶのではなく、各根候補から作る木の `score / size` を見て貪欲に選べる。
- 根の順序を解とし、順に DFS して森を作る方針は焼きなましに乗せやすい。
- さらに強い方針は、親配列そのものを解として焼きなます。
- 部分木を付け替えると、その部分木内の全頂点の高さが同じ差分だけ変わるため、`delta_h * subtree_sum_A` でスコア差分を計算できる。
- 部分木の最大高さを持てば、高さ制限のチェックを高速化できる。
- 高さ制限違反をペナルティ化すると、探索序盤に大きく動かしやすい。

## 最終コードの構造

Browserで読めた提出 #61870326 とスライドから書く。スライドの「木を直接焼く」方針に対応する実装である。

### 状態表現

- DFS系:
  - `used[v]`: 既に森に含めたか。
  - `parent[v]`: 出力する親。
  - `depth[v]`: 根からの高さ。
  - 根順序配列: 焼きなまし対象。
- 木を直接焼く系:
  - `parent[v]`
  - `children[v]`
  - `depth[v]`
  - `subtree_sum_A[v]`
  - `subtree_max_depth[v]`
  - 必要なら高さ超過量やペナルティ。

### 観測・制約・入力の扱い

- 隣接リストを作る。
- DFS/BFS では未使用頂点のみを追加し、高さ `H` を超えないように探索を止める。
- 木を直接焼く場合、親変更で閉路を作らないこと、根付き木集合として全頂点をちょうど一度含むこと、高さ制限またはペナルティ付き制約を管理する。

### 評価関数

- 基本スコアは `sum_v (depth[v]+1) A[v]`。
- 根候補貪欲では、構築される木の `score / vertex_count` を採用基準にする。
- 直接焼きなましでは、親変更による部分木の高さ差分でスコア差を出す。
- 高さ制限違反を許す場合は、スコアから違反量に応じたペナルティを引く。ペナルティ係数は時間とともに大きくする。

### 探索・構築・更新

- 解法例1:
  - 全頂点を根にする。
  - 未使用頂点から BFS 木を作る。
  - 未使用頂点から DFS 木を作る。
  - DFS の隣接探索順を `A` 昇順にする。
  - 根を全探索し、効率の良い木を採用する。
  - 根順序を焼きなまして、順に DFS 構築する。
- 解法例2:
  - 親配列を状態にする。
  - 近傍は親の付け替えや木構造変更。
  - 受理されたら、影響する祖先と部分木情報を更新する。
  - 差分計算と制約チェックを、部分木情報で高速化する。

### 操作・クエリ・出力選択

- 最終的に `parent[v]` をそのまま出力する。
- 根は `-1`。
- 複数回出力しても最後だけが採点されるが、スライドの方針では基本的に最終解を一度出力する。

### 時間配分・パラメータ

- スライドの得点例:
  - 全頂点根: 7,584,268点
  - BFS木: 55,988,632点
  - DFS木: 67,252,287点
  - DFS探索順改善: 69,853,969点
  - 根全探索貪欲: 72,646,442点
  - 根順序焼きなまし: 74,282,453点
  - 木を直接焼きなまし: 76,105,950点
  - 高さ制限違反ペナルティ込み: 76,858,739点
- 直接焼きなましでは、差分更新を頑張ることで `deg + subtree_size` 程度の更新を狙う説明になっている。

## 実装上重要な断片

```text
dfs_build(root):
    visit root as depth 0
    for neighbor sorted by A ascending:
        if unused and depth < H:
            parent[neighbor] = current
            dfs_build(neighbor)
```

```text
try_reparent(subtree_root, new_parent):
    delta_h = depth[new_parent] + 1 - depth[subtree_root]
    score_delta = delta_h * subtree_sum_A[subtree_root]
    if subtree_max_depth[subtree_root] + delta_h <= H:
        accept_or_reject_by_annealing(score_delta)
```

## この解法の本質

公式解説の本質は、構築貪欲から探索へ進むときに、状態表現と差分更新がスコアを決めるという点である。単純な DFS でも BFS より深い頂点を作れるため強く、探索順を `A` と結びつけるだけでさらに伸びる。

一方、上位化するには木を直接動かす必要がある。部分木付け替えは一見重いが、部分木の `A` 和と最大高さを持つことで、スコア差分と高さ制約を局所的に処理できる。制約違反を一時的に許すペナルティは、探索空間を狭めすぎないための工夫である。

## 真似するならまず実装する部分

理解用には DFS 木を `A` 昇順で作る方針から始めるのがよい。次に、根候補を全探索して `score / size` で選ぶ貪欲を実装する。

上位化を狙うなら、親配列を状態にして、部分木の `A` 和と最大高さを差分更新する直接焼きなましへ進むのがよい。ただし実装難度は一段上がる。

## 注意点・未理解点

- スライドは公式解説であり、完全な提出コードはない。近傍の細かい種類、温度、ペナルティ係数はスライドからは完全には分からない。
- 直接焼きなましでは、親変更による閉路、部分木情報の破壊、根の扱いが壊れやすい。
- 高さ違反ペナルティを入れる場合、最後に正しい解へ戻せる設計が必要である。
- DFS 貪欲は実装しやすいが、根や探索順の選び方だけでは上位解法との差が残る。
