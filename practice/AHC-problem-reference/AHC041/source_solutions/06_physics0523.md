## 解法の全体像

自解法は、低い `A` の頂点だけで幹となるパスを列挙し、その末端から BFS 的に枝を広げる初期解を作る。その初期解を複数生成し、最後に葉の親を付け替える高速な局所改善で伸ばす。

記事後半では、他者の強い方針として、低い高さに固定する頂点を削っていく貪欲と、高さ列を直接焼きなます方針も解析している。これらの提出コードも記事リンクから読めた。

## 主要アイデア

- 高さ10の頂点を多く作りたいが、幹に大きい `A` を使うのは損である。
- `A[i] <= X` の低価値頂点だけを使って長さ7程度のパスを全列挙する。
- パス末端から残り高さ以内で BFS し、距離が大きい頂点から順に木へ取り込む。
- 初期解を複数作り、良いものを選ぶ。
- 葉を1つ選び、親をより深い隣接頂点へ変える近傍は高速で扱える。
- 葉だけを動かすので、部分木全体の高さ更新が不要である。
- 擬似焼きなましとして、受理閾値を負から0へ線形に上げ、序盤は少し悪い移動も許す。
- 追加解析では、低い高さから固定する集合被覆風貪欲と、高さ列焼きなましが強いことを確認している。

## 最終コードの構造

### 状態表現

- `parent/res[v]`: 現在の親。根は `-1`。
- `d[v]`: 現在の高さ。
- `used[v]`: 初期解構築で使ったか。
- `path`: 低価値頂点からなる候補パス列。
- `p_wl`: パスの評価値とパス番号のリスト。
- `chi[v]`: 子数。
- `ll`: 葉リスト。
- `invl[v]`: 葉リスト上の位置。葉でなければ `-1`。
- `dist`: 全点対 BFS 距離を前計算している提出もある。

### 観測・制約・入力の扱い

- 隣接リストを作る。
- 自解法コードでは全点対 BFS 距離も作っている。
- 初期解のパス列挙では `BP_BORDER=25`, `BP_MDEP=7` により、`A<=25` の頂点だけで深さ7まで DFS 列挙する。
- 親付け替えでは、葉だけを対象にすることで子孫の高さ制約を気にしなくてよい。
- 新しい親候補は高さ `H` 未満の隣接頂点から選ぶ。

### 評価関数

- `eval(parent)` は根から BFS して深さを求め、`sum (d[v]+1)A[v]` を返す。高さ超過なら不正値。
- パス評価は、パス上の頂点に対して浅い位置に置く損を `A[path[j]] * (EXP_DEP - j)` の形で加え、短いパスには大きい罰則を足す。
- 葉付け替えの差分は、葉 `v` の深さだけが変わるため `(new_parent_depth - old_parent_depth) * A[v]`。
- 最終提出の局所改善では、閾値 `clim` 以上の gain を受理する。`clim` は約0.8秒で `-150` から `0` へ線形に変化する。

## 実装上重要な断片

```text
enumerate_paths(v, depth):
    if A[v] > BP_BORDER: return
    add current path
    if depth == BP_MDEP: return
    for to in adj[v]:
        if not in_current_path:
            enumerate_paths(to, depth + 1)
```

```text
improve_leaf_parent():
    v = random leaf
    new_parent = adjacent vertex with maximum depth < H
    gain = (depth[new_parent] - depth[parent[v]]) * A[v]
    if gain >= threshold:
        parent[v] = new_parent
        depth[v] = depth[new_parent] + 1
        update child counts and leaf list
```

## この解法の本質

幹と枝を分けて考えている点が本質である。幹はスコア係数が低い位置に置かれるため、低い `A` の頂点で作りたい。枝側は高さ9や10に多くの頂点を置けるため、末端から BFS 的に広げる。

最後の葉付け替えは、影響範囲を葉1個に限定することで非常に軽い近傍にしている。部分木を動かすほど強くはないが、短時間で大量に試せる。

## 真似するならまず実装する部分

まず単純な親配列、深さ計算、スコア計算を作る。次に、低 `A` パス列挙と、パス末端からの BFS 拡張で初期解を作る。

局所改善は葉付け替えから始めるとよい。子数と葉リストを差分管理できれば、実装量に対して効果がある。

## 注意点・未理解点

- 自解法はパス選びの評価がかなり経験的で、`BP_BORDER` や `EXP_DEP` への依存が大きい。
- 葉付け替えは軽いが、葉以外の構造は動かせないため改善余地に限界がある。
- 記事本人も、初期解の構成が甘く、スコア関数の考慮が足りなかったと反省している。
- 追加解析の risujiroh 型貪欲 [#61904481](https://atcoder.jp/contests/ahc041/submissions/61904481) は、低い高さに固定する頂点を `A` 降順で削れるだけ削る方針で76.1M級だった。
- 追加解析の Trineutron 型高さ焼きなまし [#61912747](https://atcoder.jp/contests/ahc041/submissions/61912747) は、全頂点未確定相当から高さを一点更新し、親候補喪失だけ局所判定する方針で76.7M級だった。変更先を一様高さにする [#61913648](https://atcoder.jp/contests/ahc041/submissions/61913648) は75.0M程度で劣ると記事で比較されている。
