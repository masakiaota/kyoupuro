## 解法の全体像

最初は未訪問頂点から BFS で森を作る貪欲を実装し、その後、葉や部分木を深い位置へ付け替える局所改善を重ねる。改善の途中で、高さごとの頂点数と葉数を見て「高さ10の葉を増やす」方向へ進めている。

後半では、葉だけでなく部分木を付け替える山登り、部分木を新しい根付き木にする操作、同点遷移の採用、焼きなまし化を行い、最終的に55位まで伸ばしている。実装は ChatGPT を使いながら進めた参加記であり、コード詳細よりも方針遷移と観察が中心である。

## 主要アイデア

- BFS で全頂点を一度ずつ訪問して森を作る。
- 根候補の順序を `A` 大きい順から小さい順に変え、重い頂点を後から深い位置に入りやすくする。
- 「高さ10の葉が多いほどよい」という観察に基づき、葉の深さを上げる。
- 葉単体の付け替えより、部分木の付け替えの方が大きく改善する。
- 同じスコアの遷移も採用すると、プラトーを移動して後で改善できる。
- 焼きなましにすると、同点・悪化を含む移動が入り、局所最適から抜けやすくなる。
- 複数の初期解や同じコードの複数提出で上振れを狙う。

## 最終コードの構造

Browserで読めた提出 #61963043 を主実装として書く。記事本文のBFS/DFS初期解と部分木付け替え改善に対応する。

### 状態表現

- `parent[v]`: 現在の森の親。根は `-1`。
- `depth[v]`: 根からの高さ。
- `children[v]` または子数: 葉判定や部分木移動に必要。
- `subtree(v)`: 部分木付け替えで動かす頂点集合。
- `score`: 現在スコア。
- 高さ分布と葉数分布をデバッグ・観察用に出す。

### 観測・制約・入力の扱い

- 隣接リストを作り、BFS で未訪問頂点を高さ `H` 以内に追加する。
- 付け替え時は、高さ10を超えないこと、閉路を作らないこと、全頂点がちょうど1つの木に属することを守る必要がある。
- 孤立的に根のまま残る頂点が周囲の高さ10に阻まれていた観察から、同点遷移の採用が導入されている。

### 評価関数

- 実スコア `sum_v (depth[v]+1) A[v]`。
- 山登りでは、スコア改善または同点なら採用する段階がある。
- 焼きなましでは、悪化遷移も温度に応じて採用する形に変更されたと考えられるが、温度式は記事からは分からない。

### 探索・構築・更新

- 初期解:
  - 未訪問頂点を根にする。
  - BFS で高さ `H` 以内の未訪問頂点を追加する。
  - 根候補の順序を `A` 小さい順にする改善を試す。
- 局所改善:
  - 葉をより深い親へ付け替える。
  - 部分木を別の親へ付け替える。
  - 部分木を新しい根付き木にする。
  - 同点でも採用して探索空間を移動する。
- 焼きなまし:
  - 山登りを焼きなましに変更し、seed0 で大きく伸びた。
  - 高速化後、同じコードを複数回提出して上振れを狙った。

### 操作・クエリ・出力選択

- 最後に `parent` 配列を出力する。
- 複数提出のうち最大スコアの提出を採用している。

### 時間配分・パラメータ

- 葉・部分木付け替えの山登りは1.5秒と書かれている。
- 最終盤で焼きなまし、高速化、同コード複数提出を行う。

## 実装上重要な断片

```text
build_initial_bfs(order):
    for root in order:
        if used[root]: continue
        parent[root] = -1
        bfs from root while depth <= H
```

```text
try_move_subtree(v, new_parent):
    if new_parent is inside subtree(v): reject
    delta_depth = depth[new_parent] + 1 - depth[v]
    if max_depth_in_subtree(v) + delta_depth > H: reject
    delta_score = delta_depth * sum_A_in_subtree(v)
    accept if hillclimb/annealing condition passes
```

## この解法の本質

この参加記の本質は、可視化と分布観察で「何が足りないか」を見つけながら改善している点である。BFS だけでは高さ10の葉が足りず、葉単体より部分木を動かした方が深い構造をまとめて改善できる。

また、同点遷移の採用が重要である。スコアが変わらない移動でも、孤立した根や詰まった構造を崩し、次の改善遷移へつながることがある。

## 真似するならまず実装する部分

まず BFS 初期解とスコア計算、深さ・葉数分布の可視化またはログを作る。次に、葉の親付け替えではなく、部分木付け替えを実装するのがよい。

焼きなましは、部分木付け替えの差分評価が安定してから追加する。最初から温度調整に入るより、同点採用の山登りで改善の余地を確認する方が安全である。

## 注意点・未理解点

- 提出 #61963043 では、`build_forest_bfs`、`build_forest_dfs`、`calc_height_all`、`calc_score`、`TreeState` を持つ。初期解は `A` 昇順/降順/ランダム順のBFS/DFS候補を比べ、改善は部分木再接続を中心に行う。
- BFS 初期解は実装しやすいが、公式解説でも述べられている通り DFS より浅くなりがちで、初期解として弱い可能性がある。
- 部分木付け替えは閉路判定と高さ更新が壊れやすい。
- 同じコードの複数提出による上振れは競技中の戦術であり、再現性のある改善とは分けて考える必要がある。
