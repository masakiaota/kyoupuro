## 問題の本質

各頂点のスコア係数は高さ `h+1` なので、価値 `A` が大きい頂点をできるだけ高さ10に近づけ、価値が小さい頂点を根や幹に回す問題である。ただし、平面グラフ上で各頂点は高さが1小さい隣接頂点を親に持つ必要があるため、「高くしたい」だけではなく、低い高さの少数頂点が残り全体を支配できる構造を作る必要がある。

解法視点では、親配列を直接最適化する問題とも、高さ列 `h[v]` を最適化する問題とも見られる。上位解法ほど、高さ列の制約の単純さ、または部分木差分更新の効率を利用している。

## 共通している考え方

- 高さ10に近い頂点を増やすほど強い。
- 低い高さには `A` が小さい頂点を置きたい。
- BFS は実装しやすいが浅くなりやすく、DFSや葉側構築の方が深さを稼ぎやすい。
- 木を直接持つ場合は、部分木の `A` 和と最大高さが差分更新の鍵になる。
- 高さ列を持つ場合は、隣接する高さ `h-1` の存在数が実行可能性判定の鍵になる。
- 同点や一時的悪化を許すと、根が詰まった状態や孤立頂点を動かせる。

## 解法の分類

- 貪欲構築型: DFS/BFS、葉からDFS、低 `A` パス列挙。
- 集合被覆型: hitonanode、risujiroh 型の低高さ固定貪欲。
- 高さ列焼きなまし型: niuez、Trineutron 型。
- 木直接焼きなまし型: 公式解説の親配列・部分木付け替え。
- 後処理改善型: kaede2020 と physics0523 の葉・部分木付け替え。

## 推奨して理解すべき順序

1. 公式解説で、BFSよりDFSが深さを稼ぐこと、直接木焼きの差分更新を見る。
2. niuez メモで、高さ列を状態にする発想と実装の軽さを理解する。
3. physics0523 と kaede2020 で、初期解と局所改善の具体的な試行錯誤を見る。
4. uta_ccc で、葉側から作る構築貪欲を見る。
5. 最後に hitonanode で、CP-SAT観察から集合被覆ビームへ行く高度な方針を見る。

## 実装するならどのルートか

理解のための最小実装は、高さ列焼きなましがよい。全頂点高さ0から始め、近傍を「頂点を隣接頂点+1にする」「頂点を0にする」だけにすると、親配列や部分木を直接管理しなくてよい。

上位化の方向は2つある。1つは niuez 型に swap 近傍と高速な隣接高さカウントを足す方向である。もう1つは hitonanode 型に進み、低い高さから集合被覆として固定し、ビームサーチで多様化する方向である。木を直接焼く公式方針も強いが、部分木差分更新の実装難度が高い。

## 重要な実装要素

- 状態表現: `parent[v]` で木を持つか、`h[v]` で高さ列を持つかを最初に決める。
- 評価関数: `sum (h[v]+1)A[v]`。高さ列では一点差分、木では部分木差分を使う。
- 近傍: 高さ一点更新、隣接swap、葉の親変更、部分木付け替え、根順序変更。
- 差分更新: `count_neighbor_height[v][h]`、または `subtree_sum_A` と `subtree_max_depth`。
- 候補管理: 葉リスト、候補パスリスト、集合被覆の cover bitset、ビームの重複ハッシュ。
- 出力判定: `h[v]>0` の頂点に高さ `h[v]-1` の隣接親があるか、木の高さが10以内かを検証する。
- パラメータ: 温度、近傍比率、探索時間、パス長、低 `A` 閾値、ビーム幅、同点採用。

## 落とし穴

- 高さ列から親を復元するとき、親は高さが1小さい隣接頂点である。向きを逆にすると不正になる。
- 高さ一点更新で、自分を親候補にしていた隣接頂点が親を失う場合がある。
- 部分木付け替えで、移動先が自分の部分木内だと閉路になる。
- BFS初期解は浅い頂点が増えやすく、スコア上限が見えやすい。
- 葉だけの改善は高速だが、内部構造を動かせない。
- 集合被覆の cover 条件を雑にすると、終盤に高さ10以内で全頂点を収められなくなる。
- 悪化遷移を許しすぎると最後に正しい解へ戻りにくい。ペナルティや温度の終盤処理が必要である。
