# AHC problem_description.txt audit TODO

## 目的

AHC001 から AHC064 までの各 `problem_description.txt` を、AtCoder 公式問題ページの表示と照合し、AI が解説ブログと合わせて読むための問題参照文書として十分な品質にする。

各コンテストについて、Browser Use で公式問題ページを実際に開き、画像として表示を確認する。HTMLや既存ファイルだけを見て完了扱いにしない。

## してはいけないこと

- Browser Use による公式ページ確認を省略しない。
- 公式HTMLや既存ファイルの一括変換だけで完了扱いにしない。
- 複数件をまとめて流し読みして、1件ごとの判断を曖昧にしない。
- ユーザーの許可なく、効率化のために確認品質を落とさない。
- 入力例・出力例・サンプル説明を残さない。
- ツール、入力ジェネレータ、ビジュアライザ、配布ツール、ダウンロード案内を残さない。
- テストケース数、相対評価システムについて、実行時間について、順位決定やシステムテストの詳細など、問題本体と直接関係しない章を残さない。
- 画像の alt、figcaption、Figure などの変換残骸を残さない。
- 空の見出し、参照先のない「例」「図示している」「上図」「下図」などを残さない。
- `Big/`, `90^circ`, `\frac`, `\left`, `\right`, `\begin`, `\end` など、変換に失敗した数式断片を残さない。
- 不必要に大きい連続改行を残さない。
- 既存のユーザー変更や無関係なファイルを巻き戻さない。

## チェックすべきこと

- 公式ページの URL が正しいこと。例外 URL がある場合は公式ページ到達を優先する。
- Browser Use のスクリーンショットで、問題文・図・数式・入出力形式を目視確認すること。
- `problem_description.txt` だけあれば問題を理解できるようにすること。
- `problem_description.txt` に、問題の目的、状態、操作、制約、得点、入力形式、出力形式、入力生成方法が必要十分に残っていること。
- 入力形式と出力形式は必ず残すこと。対話型・逐次出力型は `## 入出力` でもよい。
- 図が問題理解に必要な場合は、画像を貼るのではなく、文章として意味を転記・補足すること。
- 図が単なるサンプル出力やビジュアライズ結果なら削除すること。
- 数式は、Markdown 上で読める通常表記にすること。崩れた LaTeX 断片をそのまま置かないこと。
- 公式ページにある赤字注意のうち、入出力や WA 条件に関係するものは残し、相対評価やテストケース運用だけのものは落とすこと。
- `入力例`, `出力例`, `例を見る` が残っていないこと。
- `ツール`, `ビジュアライザ`, `配布ツール` が残っていないこと。
- `テストケース数`, `相対評価システムについて`, `実行時間について` が残っていないこと。
- `公式ページ`, `補足:`, `Figure`, `figcaption`, `alt=` が残っていないこと。
- 連続する空行が過剰でないこと。
- 修正後に対象ファイルを再読し、チェック項目を満たすこと。

## 1件ごとの完了条件

- Browser Use で公式問題ページを開き、画像として確認済みである。
- ローカルの `problem_description.txt` を最初から最後まで読み、公式表示と照合済みである。
- 修正点があれば手動で修正済みである。
- 修正後に再検査済みである。
- そのコンテストのTODOをすべて `[x]` にしている。
