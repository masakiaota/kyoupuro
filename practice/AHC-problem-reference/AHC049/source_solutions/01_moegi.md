## 実装キャッシュで確認した内容

- 初期状態は出口以外399箱をそれぞれ単独グループにする。グループは箱ID列と往復移動距離 `cost` を持つ。
- グループ評価は箱列を後ろから見て、上に載る箱の重量と残り移動距離によるダメージを累積する。`d <= presssum` なら `INF` で invalid。
- 初期の sort 近傍では箱を重さ降順に並べるが、実際に多用する non-sort 近傍は順序を保ったまま挿入・swap・末尾交換を行う。
- 候補ペアは `min(d1,d2)/max(d1,d2) >= 1/3` を満たす箱ペアから作り、距離 `^-1.5` の alias sampling で近い箱を選びやすくする。
- 近傍は1点移動、1点移動 non-sort、2点 swap、2点 swap non-sort、末尾区間 swap。実際の比率は non-sort 移動25%、non-sort swap50%、末尾swap25%で、sort版は初期10ms以外ほぼ使わない。
- 詳細評価前に局所移動距離差 `delta > 2` の候補は再帰的に引き直す。無駄遷移の事前リジェクトで反復数を稼ぐ。
- 採択は `score=1/cost_sum` の比率で、`co=15000`, 温度0.99から0.0。採択時に空グループを削除し、`inv_groups` を更新する。
- 出力は各グループを出口から順にたどって `1` で拾い、最後に出口へ戻る。操作2は使わない。

## 解法の全体像

箱をいくつかまとめて拾い、出口へ戻る一連の往復を 1 つの「グループ」として扱う。全体解は、399 個の箱を複数のグループへ分け、各グループ内で箱を拾う順序を持つ状態になる。

この状態に対して焼きなましを行う。主な近傍は、箱を別グループへ 1 個移す操作、2 グループ間の箱を交換する操作、グループ末尾の連続部分を交換する操作である。各遷移では、変更されたグループだけの移動距離と耐久判定を再計算し、移動回数が少なく、かつ箱が潰れない解を探す。

操作 2 の「置く」は明示的には使わず、各グループを「出口から出発して箱を拾い、出口へ戻る」独立した回収単位として最適化する方針である。

## 主要アイデア

- 1 回の出口往復をグループとみなし、問題をグループ分割とグループ内順序の最適化に変換する。
- 良い解では 1 グループあたりの箱数が平均 4.5 から 5.0 程度に収まるため、グループ単位の再計算が軽い。
- スコア再計算では、グループの移動距離と箱の潰れ判定だけを確認すればよい。
- 潰れ判定は後ろから見ると、各箱より上に載る箱の重量が残り移動距離に与えるダメージを累積できる。
- 初期実装では箱を重さ降順に固定していたが、十分な反復を回すなら順序制限を外した方が探索空間が広がる。
- 採択されにくい無駄遷移を事前に捨てる。特に移動距離が大きく悪化する遷移は、詳細な耐久計算前に選び直す。
- 1 点移動や 2 点 swap だけでなく、グループ末尾のランダム長 swap が強い近傍として機能する。
- 座標変換の割り算・剰余を避け、距離などを前計算して反復数を増やす。

## 最終コードの構造

以下は記事本文由来の整理を含む。提出 #67103781 の実装差分は上の「実装キャッシュで確認した内容」を優先する。

### 状態表現

- `groups`: グループごとの箱 ID 列。箱 ID から `(i,j)`, `w`, `d` を引ける。
- `belong[box]`: 各箱が属するグループ ID。1 点移動や swap の更新に使う。
- `group_cost[g]`: グループ `g` の往復移動距離。全体の `T` の寄与。
- `group_valid[g]`: グループ内順序で全箱が潰れずに運べるか。
- `dist[a][b]`: 箱または出口間のマンハッタン距離。2 次元座標から毎回計算しないための前計算。
- `score`: 全グループの移動距離合計、またはそれに対応する生スコア。

### 観測・制約・入力の扱い

- `N=20` 固定なので、箱は出口を除く 399 個である。
- 全箱を単独で出口へ運んでも、移動回数と pickup 回数を合わせて操作上限内に収まりうるため、初期解は作りやすい。
- 持った箱を置かない方針では、各箱はちょうど 1 つのグループに属し、グループごとに `1` 操作で拾われ、出口到達時にまとめて消える。
- WA 回避には、移動後の耐久力が 0 以下にならないこと、出力経路が盤面内にあること、既に消えた箱を拾わないことが重要である。

### 評価関数

全箱を運び切ることを前提にすると、最大化対象は `N^2 + 2*N^3 - T` であり、探索中は `T` の最小化として扱える。

グループ `g = [v0, v1, ..., vk-1]` の移動距離は次の形になる。

```text
route_len(g) =
    dist(exit, v0)
  + sum dist(vt, vt+1)
  + dist(vk-1, exit)
```

耐久判定は、各箱が拾われた後に上へ載せられる箱の重量と、その箱が載っている残り移動距離の積を累積する。記事では、グループを後ろから見ることでこの計算を高速化できると説明している。

### 探索・構築・更新

- 初期状態は、各箱を単独グループに置くか、軽い貪欲でグループ化したものだと考えられる。
- 近傍は、箱 1 個の移動、箱 2 個の swap、グループ末尾どうしのランダム長 swap。
- 変更前の影響グループのコストだけ退避し、遷移後に同じグループだけ再計算する。
- invalid なグループを作る遷移は採択しない。
- valid であれば、移動距離の差分に対して焼きなましの確率採択を行う。
- 移動距離が一定以上悪化することが事前に分かる遷移は、スコア再計算前にリジェクトして選び直す。

### 操作・クエリ・出力選択

- グループの順序自体はスコアに影響しない。各グループは出口から始まり出口で終わるため、どの順に実行しても移動距離合計は同じである。
- 出力では、各グループについて出口から最初の箱へ最短路で移動し、箱を拾い、次の箱へ移動することを繰り返し、最後に出口へ戻る。
- 最短路の上下左右の選び方は本文に詳細がない。箱のあるマスにも移動できるため、単純なマンハッタン経路でよい。
- 操作 2 は使わない前提なので、出力は移動文字と pickup の `1` だけで構成される。

### 時間配分・パラメータ

- 2 秒制限下で焼きなましを回す。
- グループ平均サイズが小さいことを前提に、数千万回級の近傍試行を目指す設計である。
- 主なパラメータは、温度、近傍選択比率、移動距離悪化を事前リジェクトする閾値、末尾 swap の長さ分布である。
- 記事に明示された改善量は、後ろからの再計算高速化、順序制限解除、無駄遷移の事前リジェクト、末尾ランダム長 swap、割り算・剰余の削減である。

## この解法の本質

この問題では、箱を一度地面へ置かないなら、各箱回収は出口から出口へ戻る独立した巡回になる。したがって、全体の難しさは「どの箱を同じ巡回にまとめるか」と「その巡回でどの順に拾うか」へ落ちる。

この変換により、盤面上の長い操作列を直接探索せず、短い箱列の集合を探索できる。しかも、遷移で壊れるのは少数のグループだけなので、差分再計算が効く。耐久制約も、グループ内の後ろ向き累積で高速に判定できる。

さらに、順序制限を外す、採択されにくい遷移を事前に捨てる、末尾ブロック swap を入れる、といった工夫は、探索空間を広げながら反復効率を落とさないためのものだと捉えられる。

## 真似するならまず実装する部分

まず、各箱を単独グループにする初期解、グループの距離計算、後ろからの耐久判定、`1` と移動だけの出力を実装するのがよい。これで必ず全箱を運べる基盤ができる。

次に、箱 1 個を近い別グループへ移す近傍と、2 箱 swap を追加する。焼きなまし自体より先に、グループ評価とロールバックが壊れないことを確認するべきである。最後に、順序を重さ降順に固定しない探索や、末尾ブロック swap、事前リジェクトを足すとよい。
