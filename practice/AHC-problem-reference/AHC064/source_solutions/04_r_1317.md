## 解法の全体像

この解法は、バケットソートに近い確実構築をベースにしている。まず全車両を同じ番号の待避線へ退避し、待避線先頭の車両を目的出発線へ移す。次に、各出発線の末尾から車両の1の位に対応する待避線へ分配し、最後に待避線番号順に戻すことで各出発線内の順序を揃える。

初期版は逐次操作で301ターン程度を狙う構築だったが、以後は各段階で同時実行できる移動集合を焼きなましで選ぶ。最終版a04では、候補の中から非交差な部分集合をビットマスクで表し、移動両数を最大化しつつ、最も遠い移動を必ず含める制約を入れている。さらに、同じ宛先グループが連続している場合は2両まとめて動かす。

## 主要アイデア

- 全車両をいったん `siding[i]` に退避すると、以後は先頭から取り出すバケット処理にできる。
- 待避線から出発線へ戻すときは、車両IDの10の位で目的出発線を決める。
- 出発線から待避線へ再分配するときは、車両IDの1の位で待避線を決める。
- 最後に待避線0,1,...,9から戻すと、各出発線内でID昇順になる。
- 並列化は、その時点で可能な候補移動から非交差な部分集合を選ぶ問題として扱う。
- 部分集合選択は焼きなましで行い、評価は主に移動できる両数である。
- 遠い移動を放置すると詰まりやすいため、`abs(i-j)` 最大の候補を必ず含むようにする。

## 最終コードの構造

### 状態表現

- `vector<vector<int>> departures`: 出発線。末尾側を `back()` として扱う。
- `vector<deque<int>> sidings`: 待避線。先頭側を `front()` として扱う。
- `Operation { type, i, j, k }`: 1操作。
- `Candidate { i, j, payload }`: 並列選択候補。`payload` に実際の操作を持つ。
- `turns`: 各ターンの操作集合。

### 観測・制約・入力の扱い

- `is_valid_pairs` で、同一ターン内の出発線・待避線重複と交差を検査する。
- 交差検査は、候補ペアを出発線番号でソートし、待避線番号が厳密増加かを見る。
- 初手の全退避は `(i,i)` の10本なので非交差で同時実行できる。
- 最終戻しは1両ずつ逐次実行しており、並列化していない。

### 評価関数

- 焼きなまし中の評価は、選択した候補の移動両数 `sum(k)` が主である。
- 候補集合が空なら巨大負点。
- `abs(i-j)` 最大の候補を1つも含まない場合は巨大負点。
- 非交差でない場合も巨大負点。
- 有効な集合なら移動両数がそのままスコアになる。

### 探索・構築・更新

- `greedy_initial_mask` で、出発線・待避線が単調になる候補を貪欲に選び初期マスクを作る。
- `sa_select` で候補数 `n` のビットマスクを状態にする。
- 近傍はランダムな1ビット反転。
- スコア改善なら採用、悪化なら `exp(diff/temp)` で採用する。
- 温度は `SA_START_TEMP=2.5` から `SA_END_TEMP=0.01` まで冷却率 `0.995` で下げる。
- 各選択に `SA_TIME=0.0185` 秒を使う。

### 操作・クエリ・出力選択

構築は4段階である。

1. 全出発線から同番号の待避線へ10両ずつ移す。
2. 各待避線の先頭車両を見て、10の位に対応する出発線へ戻す。先頭2両が同じ10の位なら2両まとめる。
3. 各出発線の末尾車両を見て、1の位に対応する待避線へ移す。末尾側2両が同じ1の位なら2両まとめる。
4. 待避線0から9まで順に、先頭車両を10の位の出発線へ1両ずつ戻す。

### 時間配分・パラメータ

- a02では `SA_TIME=0.02` がTLEし、0.01でACしている。
- a03では最遠候補を強制する工夫が入る。
- a04では連続2両をまとめる工夫と `SA_TIME=0.0185` が使われている。
- 乱数シードは固定 `mt19937 rng(0)` で、提出ごとのランダム性はない。

## 実装上重要な断片

```text
sa_select(candidates):
    force = candidates with maximum abs(i-j)
    mask = greedy_non_crossing_initial()
    ensure mask contains one force candidate
    while time remains:
        next = mask xor (1 << random_bit)
        accept by score or temperature
    if best invalid:
        fallback to one forced move
```

## この解法の本質

本質は、問題を難しい全体最適化として扱わず、確実に揃うバケットソートへ落としている点である。10の位で線を揃え、1の位で順序を作るという二段階に分けることで、正しさは非常に分かりやすい。

そのうえで、スコア改善は「同じ構築手順をどれだけ並列化できるか」に集中している。焼きなましは盤面全体の評価ではなく、候補移動集合の非交差部分集合を選ぶためだけに使われるため、実装範囲が狭い。

## 真似するならまず実装する部分

まずa01相当の逐次バケットソートを実装するのがよい。正しく完成すること、順序が保存されること、待避線先頭・出発線末尾の向きが合っていることを確認する。

次に、各段階の候補移動を列挙し、貪欲に非交差集合を選ぶ。焼きなましは最後に置き換えればよい。最遠候補強制と2両まとめ移動は、貪欲版にも移植しやすい。

## 注意点・未理解点

- 最終戻しを並列化していないため、上位解法に比べるとターン数の下限が高い。
- `SA_TIME` は各選択ごとに使われるため、値を大きくするとTLEしやすい。
- 評価関数は移動両数中心なので、将来の連番形成や距離の良し悪しはほぼ見ていない。
- 最遠候補を強制する方針は詰まり防止として効くが、常に最適とは限らない。
- `k=2` までしかまとめないため、3両以上の同グループ連続を活かし切れていない可能性がある。
