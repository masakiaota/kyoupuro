## 解法の全体像

公式スライドは、まず「1両ずつ正しい位置へ運ぶ」構築でACする入口を示し、その後、同一ターン内の非交差並列化、2列単位の5分割構築、最後に「正しい連番ブロックを増やす評価関数」へ視点を切り替える流れで解説している。

最終的に重要なのは、各出発線を個別に完成させることではなく、盤面全体で「正しい隣接関係」を増やすことである。1ターン内で選ぶ移動集合は、出発線番号と待避線番号の両方が単調増加になるマッチングとして扱えるため、DPやビームサーチで選べる。

## 主要アイデア

- 完成状態は、各車両が「直前に来るべき車両」と隣接している状態の集合として見られる。
- ID `10r` の車両が出発線 `r` の先頭にあること、または `x` の直後に `x+1` があることを加点対象にする。
- 1ターン内の非交差制約は、左から右へ使用済み出発線・待避線の境界を進めるDPで扱う。
- 単純なDPは「今すぐ連結できるペア」しか評価しないと停滞するため、次に連結できそうな上下ペアに小さく加点する。
- DPの同点・近い候補をビームとして残すと、ターン内の選択の幅が広がり大きく改善する。
- 長い斜め移動は他の移動を塞ぎやすいため、距離や目的地からの離れ具合にペナルティを入れる。

## 最終コードの構造

コードなし。以下は公式解説から復元できる実装構造である。

### 状態表現

- 出発線 `D[10]` と待避線 `S[10]` を配列またはdequeで持つ。
- 各線は先頭・末尾の向きを問題文に合わせて明確に定義する。
- 評価用に、現在成立している正しい隣接関係数を持つ。
- 差分更新用に、各移動で変化する線の端付近の隣接関係だけを再計算できるようにする。

### 観測・制約・入力の扱い

- `R=10` 固定として実装してよい。
- 出発線容量15、待避線容量20を移動候補生成時に必ず確認する。
- 同一ターンでは出発線・待避線を重複使用しない。
- 出発線 `i1<i2` なら待避線 `j1<j2` でなければ同時実行できない。

### 評価関数

- 基本評価は「正しい連結がいくつできているか」で、最大100を目指す。
- 例として、`10r` が出発線 `r` の先頭にあれば加点、`x` の次に `x+1` があれば加点する。
- 近い将来に連結できる配置、つまり出発線末尾と待避線先頭に連続IDが向かい合う状態にも小さく加点する。
- 斜めに遠い移動や、目的出発線から離れる移動にはペナルティを与える。

### 探索・構築・更新

- 各ターンで候補移動を列挙する。方向は出発線から待避線、待避線から出発線の両方を考える。
- 1ターン内の移動集合は、使用済みの出発線・待避線の境界を状態にしたDPで最大評価を選ぶ。
- DP状態はおおむね `(次に使える出発線境界, 次に使える待避線境界)` で表せる。
- DPのタイブレークをランダムにするだけでは弱い。各DP状態に複数候補を残すビームサーチにする。
- 公式説明では、幅200程度、特に状態 `(0,0)` に多くの候補が集まるためその状態だけ幅を大きくする工夫が示されている。

### 操作・クエリ・出力選択

- 評価が最大、すなわち全車両の正しい隣接関係が揃うまでターンを繰り返す。
- 各ターンで選んだ非交差な移動集合をそのまま出力する。
- 完成していればスコアは `5000 - T` 相当になるため、出力時はTの短縮だけを重視する。

### 時間配分・パラメータ

- DP単体は軽いが、ビーム幅と候補生成の差分更新が重要である。
- 幅200程度、`(0,0)` 状態の幅を10倍にする方針が説明されていた。
- 追加加点は、次に連結できるペアへ0.5点程度、距離ペナルティは手元のチューニング対象である。

## 実装上重要な断片

```text
evaluate_board():
    score = 0
    for each departure line r:
        if head(D[r]) == 10*r:
            score += 1
    for each adjacent pair (a, b) on every line:
        if b == a + 1 and a/10 == b/10:
            score += 1
    add small future-connection bonuses
    subtract distance penalties
```

```text
choose_turn_by_dp():
    dp[0][0] = empty move set
    for state (i, j):
        try each move using departure i2 >= i and siding j2 >= j
        next = (i2+1, j2+1)
        update candidate score by delta evaluation
    return best non-crossing set
```

## この解法の本質

本質は、完成形を「10本の完成列」ではなく「正しい隣接関係100個」へ分解した点にある。これにより、どの列から完成させるかという硬い順序を捨て、盤面全体で並列に良い連結を作れる。

さらに、非交差制約を単なる実装上の制約ではなく、単調なマッチング選択問題としてDP化している。AHCでは「1ターン内でできること」を貪欲に選びがちだが、この問題ではターン内選択がスコアの大半を決めるため、そこを探索対象にしている。

## 真似するならまず実装する部分

まずは、正しい隣接関係を数える評価関数と、1ターン内で非交差な移動集合を選ぶDPを作るのがよい。いきなりビームや距離ペナルティまで入れるより、DPで「今すぐ連結できるペア」を拾えることを確認する。

次に、上下で次に連結できるペアへの小加点を入れる。ここまでで、単純DPが偶然待ちになる弱さをかなり補える。最後にビーム幅、距離ペナルティ、差分更新を詰める。

## 注意点・未理解点

- PDFからコードリンクは確認できなかった。
- PDFのテキスト抽出は文字化けしたため、細かい文言はスライド画像と動画側の説明で補った。
- 距離ペナルティの具体式や重みはスライドだけでは完全には再現できない。
- DPは「ターン内の最適選択」をしているだけで、将来価値を正確に最適化しているわけではない。
- ビーム幅200、`(0,0)`幅10倍などは実装速度に強く依存する。
