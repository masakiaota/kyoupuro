## 解法の全体像

参加記は、本番中の試行錯誤と復習後の改善が時系列でまとまっている。本番中は、1両ずつ運ぶ解から始め、車両をまとめて動かす、同時に戻す、ターンを圧縮する、並列パターンを複数試す、という方向で改善して平均77.3ターンまで到達した。

復習では公式解説を踏まえて、2列単位に車両を分ける5分割解法を実装し、さらに振り分け部分をDPと乱択で短縮した。最終的には、STEP1の候補操作を列挙し、非交差最大スコアDPで選び、制限時間いっぱい乱択してベストを出す方針で145位相当まで改善している。

## 主要アイデア

- まずは1両ずつ運ぶことで確実に完成する解を作る。
- 交差していない複数ターンの操作は同じターンへ圧縮できる。
- 待避線への移動・戻しの両方を並列化すると、本番中に平均93ターン程度まで改善した。
- スコアが悪いケースでは、9から0のような遠い斜め移動が並列性を壊していた。
- 復習では、待避線を2列単位の5グループに使い、各グループ内で並べ替える。
- 振り分け部分は、候補操作をすべて作り、非交差制約下の最大スコア集合をDPで選ぶ。
- 連続する車両ペアに加点すると、復習版のスコアがさらに改善した。

## 最終コードの構造

以下は記事本文とキャッシュ実装 `#75390296` から確認した構造である。提出コードは記事の5分割DPそのものではなく、評価関数付きビームサーチと終盤貪欲仕上げで構成されている。

### 状態表現

- 出発線10本、待避線10本を配列で持つ。
- 復習版5分割では、目標ID範囲を2列単位のグループへ割り付ける。
- 各車両について、目標グループ、目標出発線、`mod 10` の位置を参照する。
- 各ターン候補として、移動方向、出発線、待避線、まとめて動かす両数を持つ。

### 観測・制約・入力の扱い

- 出発線容量15が実装上の大きな罠として扱われている。
- 奇数列の処理中に、完成済み偶数列へ邪魔な車両をまとめて置くと16両以上になりWAになるケースがあった。
- 待避線へ移す順序を `mod 10` が大きい順にするなど、容量違反を避ける実装上の調整が入っている。
- 同一ターン内の向きが混ざるとまとめられる数が少なくなる観察があり、振り分け方向を揃える試行もしている。

### 評価関数

- 本番中の主評価は最終ターン数で、制限時間内に複数パターンを試して最短を採用する。
- 復習版のSTEP1 DPでは、候補操作にスコアを付け、非交差最大スコアを選ぶ。
- 同じグループの隣接車両をまとめて動かせる場合を高く評価する。
- 連続する車両ペアができる操作に加点する。
- ランダム要素を入れた候補生成でも、最終的なターン数でベストを比較する。

### 探索・構築・更新

- 本番中は、操作列の圧縮と並列化を中心に改善している。
- 復習版は次の流れで構築する。
  - STEP1: 目標ID範囲を5グループに振り分ける。
  - STEP2: 各2列グループ内で、正しい出発線・順序になるように並べる。
  - STEP1の候補操作を列挙し、非交差最大スコアDPでそのターンの移動集合を選ぶ。
  - DPに乱数を加え、1.95秒ほど複数解を作って最短を採用する。
- 最後に公式1位解法系のビームサーチ実装も試しているが、完成までは到達していない。

### 操作・クエリ・出力選択

- 生成した全ターンをシミュレーションし、容量・非交差制約を満たすものだけを候補にする。
- 制限時間いっぱい複数解を試し、ターン数が最小のものを出力する。
- 復習版のseed0では70ターンまで短縮している。

### 時間配分・パラメータ

- ビーム探索の制限時間は `TIME_LIMIT=1.90`。
- 探索深さ上限は120。
- ビーム幅は深さ0..14で80、15..29で60、それ以降30。
- 乱択DP子数は深さ0..14で6、15..29で4、それ以降2。ただしrootでは最低30回乱択する。
- 終盤は単独ターン列の貪欲仕上げを最大1000反復行う。

## 実装上重要な断片

キャッシュ実装の状態は、出発線10本の末尾スタック `dep[10][15]` と待避線10本の先頭スタック `side[10][20]` である。操作は `type=0` が出発線末尾から待避線先頭、`type=1` が待避線先頭から出発線末尾で、同一ターン内の `(i,j)` は出発線・待避線の重複なし、かつ `i` と `j` が同時に増加する非交差集合だけを許す。

評価 `calc_penalty` は、各出発線の先頭車両 `10*r` が正しい先頭に来ているか、同一グループの連番 `a,a+1` が同じ線で正順隣接しているか、すぐ連結可能か、露出して操作可能かをペナルティ化する。正しいprefixは `good*80` だけ優遇し、待避線上の車両は軽く加点する。

各状態からは、各 `(i,j,type)` について移動両数 `1,2,3,5,mx` を候補化する。候補gainは現在ペナルティ差に、正しいprefix後ろのsuffixを逃がすbonus、連番ブロックbonus、目的出発線へprefixを伸ばすbonusを足す。同じ `(i,j)` では最良候補だけ残し、`select_turn_by_randomized_dp` が非交差な増加列をDPで選ぶ。乱択時は正のgainに0.3..1.0の倍率を掛け、悪化手も軽く許す。

ビーム後は `greedy_finish_blocks` が、cleanな出発線prefixを伸ばす、dep末尾の欲しいblockを2手で戻す、side/dep内に埋まった欲しいblockを掘り出す、cleanでないdepの邪魔suffixを逃がす、という順に単独ターンで仕上げる。完成保証用の安全側処理で、記事の5分割STEP2とは別の実装である。

```text
    for each possible grouped move:
        if capacity is safe:
            score = moved_count
            if adjacent cars stay in same group:
                score += bonus
            if move creates consecutive pair:
                score += bonus
            add candidate
```

## この解法の本質

この参加記の本質は、実装しやすい構築解を段階的に強くする過程にある。公式上位解法のようにいきなり全盤面評価へ行かず、まず5分割で交差の影響を局所化し、振り分け部分だけをDPで最適化している。

また、容量違反や向きの混在など、理屈上は簡単に見える5分割が実装では壊れやすいことが具体的に分かる。上位方針を読む前の中間実装として非常に参考になる。

## 真似するならまず実装する部分

理解用には、まず2列単位の5分割を実装するのがよい。次に、同じグループで隣り合う車両をまとめて移動し、容量検証付きでシミュレーションする。

その後、STEP1の候補操作を列挙して非交差DPで選ぶ。公式ビームまで行かなくても、この段階で「ターン内の非交差集合を最適化する」感覚がつかめる。
