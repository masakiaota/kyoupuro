## 解法の全体像

特定の1実装の参加記ではなく、AHC010 の有効方針を整理したメモである。中心は「サイクル生成」と「サイクル拡大」で、最初から巨大な閉路を一気に作るより、小さめの閉路やパスを作り、それを拡大・接続していく方が現実的だと整理している。

具体的には、DFS によるサイクル生成、領域分割してパスを作ってからつなぐ方法、乱択ビームサーチ、タイル4/5の性質を利用したサイクル拡大、部分破壊して DFS で再構築する方法が挙げられている。また、2つのサイクルのサイズが極端に偏ると積スコアが伸びないため、全体を2分割する、小さい方を拡大する、多点スタートする、拡大縮小を近傍にする、といった調整も述べている。

## 主要アイデア

- サイクルは最初から大きいものを狙いすぎず、探索量を抑えて小さめのものから拡大する。
- DFS は方向選択が多く見えても、各タイルの回転で変わる候補は基本的に少ない。
- タイル4/5は2本の曲線を持つため、同じタイルを共有するサイクルや、片側だけの回転による拡大が使える。
- 部分破壊 + DFS 再構築は、AHC002 的な長経路問題の有効パターンである。
- 2本のサイクルは同程度の大きさが望ましい。片方が変な形で領域を塞ぐと、もう片方が伸びにくい。
- サイクルを明示的に持つ場合、タイル列だけではなく、タイル内のレール端点や方向まで保持する方が扱いやすい。
- `to[t][d]` を「方向ベクトル」ではなく「タイル内の端点どうしの対応」として考えると実装混乱を減らせる。
- 最初にタイルの向きを正規化しておくと、回転の扱いが軽くなる。
- スコア計算は変更タイルを通るサイクルだけ再計算するなど、高速化余地がある。

## 最終コードの構造

コードなし。以下は記事本文から読み取れる実装構造である。

### 状態表現

- 盤面のタイル状態。
- サイクルを明示的に扱うなら、サイクルごとの列を持つ。
- 列の要素はタイル座標だけでは不十分で、タイル内のどの端点から入り、どの端点へ出るかを含める。
- タイル4/5では1タイルを複数のサイクルまたは同一サイクルが共有し得るため、使用回数や端点使用状況が必要になる。
- 複数サイクルを同時に伸ばす場合は、サイクル長、占有領域、各タイルの利用状況を持つ。

### 観測・制約・入力の扱い

- タイルの回転規則を、端点間の接続として前処理する。
- 問題文の `to[t][d]` をそのまま使えるが、方向と端点の意味を混同しないことが重要である。
- 正規化方針を取るなら、同じ形のタイルを基準向きへそろえ、最後に出力回転数へ戻す。
- 盤面外へ出るパス、既存サイクルを壊して戻せない遷移、端点利用が矛盾する遷移を弾く。

### 評価関数

- 基本評価は2つのサイクル長の積である。
- 構築途中では、閉路長そのもの、目標領域への近さ、2本の長さのバランス、塞いでいる領域の少なさなどの補助評価が考えられる。
- 2サイクルのサイズ調整では、小さい方を優先的に伸ばす評価や、極端な偏りへのペナルティが有効になる。
- スコア再計算を高速化するなら、変更タイルを通るサイクルだけを追跡して差分評価する。

### 探索・構築・更新

- サイクル生成:
  - DFS で閉じるパスを探す。
  - 深さ制限や時間制限を置き、遠くへ行きすぎる探索を止める。
  - 進行方向はランダムまたは固定順で試す。
- サイクル拡大:
  - 既存サイクルの一部を壊す。
  - 壊した区間の両端をつなぐ別経路を DFS で見つける。
  - タイル4/5の片側レールや共有性を利用して、既存サイクルを広げる。
- 領域分割:
  - 盤面を小領域に分け、領域内で始点・終点を固定した長いパスを作る。
  - 後で領域間のパスをつなぎ、全体のサイクルにする。
- 乱択ビームサーチ:
  - 状態をパスの先端や利用タイル集合として持ち、評価の高い候補だけ残す。

### 操作・クエリ・出力選択

- 最終的には盤面上の各タイル状態を、入力からの回転回数へ変換して900文字で出力する。
- サイクルを明示保持する方針では、採択済みサイクル列から盤面の回転状態を復元できる必要がある。
- 複数サイクルが同一タイル4/5を使う場合、両方の接続が同時に成立する向きを選ばなければならない。

### 時間配分・パラメータ

- DFS には深さ制限または時間制限を置く。
- 1回で長いサイクルを探すより、探索量を抑えたサイクル拡大を繰り返す方針が推奨されている。
- ビームサーチを使う場合はビーム幅、評価式、合流条件がパラメータになる。
- 焼きなましで拡大・縮小を近傍にする場合は、温度と小さいサイクル優先の重みが調整対象になる。

## 実装上重要な断片

```text
cycle_expand(cycle):
    segment = choose_interval(cycle)
    unuse(segment)
    new_path = dfs_between(segment.start, segment.end, limits)
    if new_path exists and valid:
        replace segment by new_path
    else:
        restore segment
```

端点として考える場合の表現は次の形が分かりやすい。

```text
rail_endpoint = (cell_i, cell_j, side)
connection[tile_state][side] = opposite_side_inside_same_tile

move(endpoint):
    out_side = connection[tile_state][endpoint.side]
    next_cell = neighbor(cell, out_side)
    next_side = opposite(out_side)
```

サイクルサイズ調整は次のように考えられる。

```text
while time remains:
    target = smaller_cycle()
    candidate = expand_or_shrink(target)
    accept by score or annealing
```

## この解法の本質

このメモの本質は、AHC010 を「タイルを900個独立に回す問題」ではなく、「端点接続から閉路を作り、その閉路を保ちながら拡大する問題」として見る点である。特にタイル4/5は、1枚の中に2本の曲線があるため、単なる通過済みセル集合では情報が落ちる。端点や使用回数を状態に含めることで、共有や再利用を正しく扱える。

また、2本の閉路の積がスコアなので、最長1本だけを伸ばしても不十分である。閉路の生成・拡大だけでなく、2本の大きさと占有領域の干渉まで考える必要がある。

## 真似するならまず実装する部分

まずは端点ベースのサイクル追跡を実装するのがよい。問題文の `to` をそのまま配列として使う場合でも、内部では「タイルのどの辺から入り、どの辺へ出るか」として統一する。

次に、小さいサイクルを1つ見つけて、部分破壊 + DFS 再構築で長くなるなら採用する処理を作る。2本同時のサイズ調整や領域分割は、その後に足す方がよい。

## 注意点・未理解点

- 本文は方針整理であり、特定の最終コードはない。そのため温度、ビーム幅、DFS 制限などの実値は参照元からは確定できない。
- X/Twitter リンク先に追加の実装情報があった可能性はあるが、本文取得できなかった。
- タイル4/5の「共有するサイクルを見つけて回転させる」操作は有効そうだが、具体的な差分更新手順は本文だけでは完全には分からない。
- 領域分割してパスを後でつなぐ方針は、境界端点の整合と2本サイクルの干渉処理が難しいと推測される。
- `to[t][d]` を端点として扱う実装方針は理解しやすいが、問題文の方向番号との変換を混ぜるとバグになりやすい。
