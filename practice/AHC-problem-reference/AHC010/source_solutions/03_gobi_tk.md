## 解法の全体像

盤面の外周に沿って大きな四角形ループを作ることを狙う方針である。当初は二重四角を作る予定だったが、記事によれば実装は大外の四角を作るところまでで終了している。

提出コードは、左上付近から開始し、ビームサーチでパスを伸ばす。状態は現在位置、どの方向から入ったか、各マスの回転回数、現在のモードを持つ。モードは「下へ進む」「右へ進む」「上へ進む」「左へ進む」「始点へ合流する」を表し、盤面外周に沿うように評価する。各遷移では現在タイルを可能な回数だけ回転させ、`TO[tile][from]` で次方向を求め、未使用マスなら進む。始点に戻れたら完成状態とする。

## 主要アイデア

- 自然に閉路を探すのではなく、作りたい形を「大きな四角」として固定する。
- ビームサーチの状態は、現在カーソル、回転回数盤面、進行フェーズである。
- 遷移は、現在タイルを 0 回から回転周期分だけ回し、進める方向を全列挙する。
- 既に使ったマスへは基本的に入らず、最後だけ始点への合流を許す。
- 評価値は `(mode, pos_point)` で、まず進行フェーズが進んでいること、次に目標方向へ進んでいることを優先する。
- ビーム幅は 2000。
- 終了時は最も評価が高い状態の `ans` を出力し、未使用マスは回転0にする。

## 最終コードの構造

### 状態表現

- `Input { t }`: 入力タイルを `usize` の30x30配列として保持する。
- `Coord { x, y }`: 座標。コードでは `mat[y][x]` としてアクセスする。
- `Cursor { pos, from }`: 現在位置と、現在タイルへどの方向から入ったか。方向は左・上・右・下を `0,1,2,3` とする。
- `State`:
  - `cursor`: 現在のパス先端。
  - `ans[30][30]`: 各マスの回転回数。未使用は `!0`。
  - `mode`: 四角形をたどるフェーズ。0から3が4辺、4が始点への合流、5が完成。
  - `sp`: 始点。
- `ROTATE`: タイルを反時計回りに1回回した後のタイル ID。
- `TO[tile][from]`: タイルへ `from` 方向から入ったときの出方向。進めない場合は `!0`。

### 観測・制約・入力の扱い

- 始点は左上付近 `(1..=3, 1..=3)` の中から、タイル番号が0から3の単曲線タイルを探して選ぶ。見つからなければ初期値 `(2,2)` のままになる。
- 初期カーソルは `pos = sp, from = 2` で始める。
- 現在タイルに対して、回転0回と、タイル種別に応じた回転候補を試す。
  - タイル0から3は4種類だが、0回を別に試し、追加で1から3回を試す。
  - タイル4/5、6/7は周期2なので、追加で1回だけ試す。
- 盤面外へ出る遷移は捨てる。
- 既に `ans` が入っているマスへは入らない。ただし `mode == 4` で始点へ戻る合流は特別扱いする。

### 評価関数

評価値は大きいほどよい辞書順タプルである。

```text
eval(state) = (mode, pos_point)
```

`pos_point` はモードごとに変わる。

- `mode = 0`: 下方向へ進みたいので `y` を大きく評価する。
- `mode = 1`: 右方向へ進みたいので `x` を大きく評価する。
- `mode = 2`: 上方向へ進みたいので `SIDE - y` を評価する。
- `mode = 3`: 左方向へ進みたいので `SIDE - x` を評価する。
- `mode = 4`: 始点に近づきたいので `SIDE - dist(sp, pos)` を評価する。
- `mode = 5`: 完成として最大評価にする。

問題の本来スコア `L1 * L2` は直接評価しない。まず外周四角を1本作ることを優先するため、記事の点数も低めである。

### 探索・構築・更新

- ビーム幅は `BEAM_WIDTH = 2000`。
- `stack` に現在ビームを持つ。
- 各反復で最大2000状態を取り出し、各状態から現在タイルの全回転候補を試す。
- `try_go_to(to, rotate_num, input)` が遷移生成を行う。
  - `to` が無効なら失敗。
  - 次位置が盤面外なら失敗。
  - 合流モードで次位置が始点、かつ戻り方向が条件に合えば完成状態にする。
  - 次位置が未使用なら、現在マスに回転回数を記録し、カーソルを次位置へ移す。
  - 移動後に `try_to_change_mode()` で辺のフェーズを進める。
- 生成した次状態を評価値でソートし、次のビームにする。
- 完成状態 `mode == 5` が出たら探索を止める。

### 操作・クエリ・出力選択

- 最終状態の `ans` を900文字で出力する。
- 未使用マスは回転0として出力する。
- 二重四角までは未実装なので、最終出力が2本の長いループを保証する構成ではない。

### 時間配分・パラメータ

- ビーム幅は2000。
- 明示的な時間制限ループではなく、ビームが尽きるか完成状態が出るまで回す。
- 実行時間は提出結果で最大 1844 ms。
- 四角形のモード切替閾値は固定で、下端 `y >= SIDE - 2`、右端 `x >= SIDE - 2`、上端 `y <= 2`、左側 `x <= 6` 付近を使う。

## 実装上重要な断片

```text
stack = [initial_state]

loop:
    next = []
    repeat up to BEAM_WIDTH:
        st = pop stack
        for each rotation count of current tile:
            tile2 = rotate(tile, count)
            to = TO[tile2][st.cursor.from]
            if next state is valid:
                next.push(next_state)

    if next is empty:
        break
    sort next by eval
    stack = next
    if best state is completed:
        break

print best state's answer
```

評価の意図は次のように固定図形をなぞることである。

```text
mode 0: go downward near left side
mode 1: go rightward near bottom side
mode 2: go upward near right side
mode 3: go leftward near top side
mode 4: return to start
mode 5: completed
```

## この解法の本質

この解法は、閉路探索の難しさを「形を決め打つ」ことで下げている。任意の長いループを探すのではなく、外周四角という分かりやすい目標を設定し、ビームサーチの評価値をその形に沿うように作る。複雑なサイクル構造やタイル4/5の再利用を扱わない代わりに、状態と遷移は比較的単純になる。

一方で、AHC010 の得点は2本の長いループの積であり、外周1本だけでは伸びに限界がある。記事にもある通り、DFS + 焼きなましで自然に閉じるサイクルを拡大する上位方針とは別系統の、実装時間内に形を作るための割り切りである。

## 真似するならまず実装する部分

まずは `State` と `try_go_to` を実装し、1本の外周四角を閉じるビームサーチを作るのがよい。`ans` に未使用を表す値を入れておき、使ったマスだけ回転回数を確定していくと、パスの自己交差を避けやすい。

次に改善するなら、固定四角を2本作るか、完成した四角の内側で2本目を同様に作る処理を追加する。ただしその方向へ進めるより、上位方針のようにサイクル部分破壊 + DFS へ移行した方がスコア上限は高い。

## 注意点・未理解点

- 記事本人が「途中までしか実装できなかった」と書いており、二重四角構想の完成版ではない。
- `try_go_to` の引数 `input` は提出コード上では使われていない。遷移は現在位置、回転候補、`ans` の使用済み判定だけで決まる。
- 始点の選び方は左上付近の単曲線タイル依存であり、必ず強いとは限らない。
- 合流条件は固定的で、任意方向から自然に閉じる一般的な閉路探索ではない。
- 評価値は本来スコアを見ないため、閉じても1本の外周ループに偏り、2本目が作れないと低得点になる。
