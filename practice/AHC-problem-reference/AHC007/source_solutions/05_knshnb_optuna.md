## 解法の全体像

yokozuna57 型の「現在辺を採らなかった場合の代替辺コスト」を、サンプリング範囲のチューニングで改善する解説である。基本アルゴリズムは、未確定辺長をサンプルし、現在辺を除いた Kruskal で両端が初めて連結する辺長を集計するものだ。違いは、未知辺長を `[d, 3d]` から素直にサンプルせず、`[l_ratio * d, r_ratio * d]` の範囲からサンプルする点である。

記事では Optuna を使い、`l_ratio` と `r_ratio` をローカルテストで探索している。最終コードはコマンドライン引数からこの 2 パラメータを受け取り、デフォルトとして `1.14094` と `3.01629` を使う。

## 主要アイデア

- オンライン戦略の評価には、問題文どおりの真の分布をサンプルすることが最適とは限らない。
- サンプリング範囲を調整すると、代替辺コスト推定の分散やバイアスが変わり、採用判断が改善する。
- Optuna で `l_ratio` と `r_ratio` を探索し、ローカルの複数 seed 平均スコアを最大化する。
- 探索対象はアルゴリズム全体ではなく、既に強いモンテカルロ方針のパラメータに絞る。
- コードは `n_sample = 170` のサンプルを作り、各サンプルで仮想辺長順に将来辺を走査する。

## 最終コードの構造

### 状態表現

- `V`: 座標を持つ頂点配列。
- `E`: 端点 `u, v` と基準距離 `d` を持つ辺配列。
- `e_ds`: 各辺の基準距離。コード上は座標差から整数距離を計算して保持する。
- `rand_ds`: `n_sample` 個の仮想辺長配列。
- `sorted_rand_ds`: 各サンプルで `(仮想長, 辺 index)` を昇順に並べたもの。
- `global_uf`: 採用済み辺の Union-Find。

### 観測・制約・入力の扱い

- 起動時に `l_ratio` と `r_ratio` をコマンドライン引数から読む。未指定なら `1.14094`, `3.01629`。
- 各サンプルで、辺 `i` の仮想長を `rand(l_ratio * d_i, r_ratio * d_i)` から作る。
- 各ターンでは真の長さ `d` を入力として読み、既に同成分なら不採用にする。
- 将来辺だけを使うため、サンプル走査では `j <= step` の辺をスキップする。

### 評価関数

各サンプルで、現在辺を採らない場合に現在の両端成分を初めて連結する辺を探す。見つかった辺長から現在辺の真の長さを引いた値を集計する。

```text
sum += replacement_length - current_length
```

全サンプルの `sum` が非負なら、代替辺の方が平均的に高いので現在辺を採用する。

```text
take if sum >= 0
```

これは `average(replacement_length) >= current_length` と同値である。

### 探索・構築・更新

- 初期化時に全サンプルの仮想長とソート済み順序を作る。
- 各ターンで、サンプルごとに `global_uf` をコピーする。
- ソート済み辺を前から見て、過去辺と同成分辺は飛ばす。
- 未来辺を unite していき、現在辺の両端が同じ成分になった時点でそのサンプルの代替辺が決まる。
- 全サンプルを集計して採否を決める。

### 操作・クエリ・出力選択

- `global_uf.same(s, t)` なら `0`。
- そうでなければ各サンプルで代替辺長を推定する。
- `sum >= 0` なら `1`、そうでなければ `0`。
- 採用した場合は `global_uf.unite(s, t)`。

### 時間配分・パラメータ

- `n_sample = 170`。
- デフォルトの `l_ratio = 1.14094`、`r_ratio = 3.01629`。
- Optuna では 500 seed 程度で評価し、48 並列で探索していたと記事にある。
- 記事中では 134 回目の trial で良いパラメータが出たとされる。

## 実装上重要な断片

```text
prepare_samples(l_ratio, r_ratio):
    for sample in 1..n_sample:
        for edge e:
            len = random_int(l_ratio * e.d, r_ratio * e.d)
            rand_ds[sample][e] = len
        sorted_rand_ds[sample] = sort_by_len(rand_ds[sample])
```

```text
decide(step, current_length):
    if global_uf.same(u, v):
        return false

    sum = 0
    for sample in samples:
        uf = global_uf.copy()
        for (len, j) in sorted_rand_ds[sample]:
            if j <= step:
                continue
            if uf.same(E[j].u, E[j].v):
                continue
            uf.unite(E[j].u, E[j].v)
            if uf.same(u, v):
                sum += len - current_length
                break

    return sum >= 0
```

## この解法の本質

本質は、強い手法そのものを新しく作ることではなく、オンライン判断に合うようにシミュレーション分布を意図的に歪める点である。真の生成分布を正確に再現するだけでは、サンプル内のオフライン最適が現実のオンライン戦略より良くなりすぎる。そこでサンプリング範囲を調整し、採用判定に都合のよいバイアスと分散へ寄せている。

## 真似するならまず実装する部分

まず yokozuna57 型の代替辺コスト推定を実装し、サンプリング範囲を `[d, 3d]` に固定して動かす。次に `l_ratio`, `r_ratio` を引数化し、ローカルテスタで複数 seed の平均を取れるようにする。Optuna はその後でよく、最初は手動で `[1.1d, 2.9d]` 付近を試すだけでも改善を確認しやすい。

## 注意点・未理解点

- Optuna の評価はローカル seed 集合に依存する。過学習気味のパラメータになる可能性がある。
- 記事中の X リンクは直接読めていないため、リンク先固有の補足は確認できていない。
- コード上の距離計算は問題文の `round` と完全一致しているか注意して読む必要がある。実装するなら問題文どおり丸める方が安全である。
- `n_sample = 170` は時間制限と実装速度に依存するため、他言語ではそのまま使えない可能性がある。
