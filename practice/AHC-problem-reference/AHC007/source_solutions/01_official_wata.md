## 解法の全体像

現在見えている辺を採るべきかを、将来の辺を含むカット上の最適停止問題として近似する。基本は「現在の辺がまたぐ 2 分割カットで、今採るコストと、以後の辺から 1 本採る期待コストを比較する」判定である。さらに 3 分割カットを見て「今の辺を採ると残り 1 本でよいが、採らないと 2 本必要になる」状況も評価する。

高得点提出では、単純な全カット列挙ではなく、現在の Union-Find で確定済み連結成分を縮約し、今の辺より十分安そうな将来辺も先に縮約してから、ランダム Prim で現在辺の両端を別側に含むカットを複数生成する。各カットに対して DP で期待値を計算し、どれかのカットで採用が有利なら現在辺を採る。

## 主要アイデア

- MST の性質として、あるカットをまたぐ辺は少なくとも 1 本必要であることを使う。
- 現在辺を含むカットを作り、カット上の未確定辺を到着順に並べて「この辺を採るか、後続に任せるか」の期待値 DP を行う。
- 2 分割カットでは、現在辺の長さ `c` と、現在辺を見送った場合の期待最小コストを比較する。
- 3 分割カットでは、3 種類の境界辺のうち 2 種類を採る必要がある状況を bitmask DP で扱う。
- カットはランダム Prim により多数作り、局所的に現在辺が重要になる証拠を探す。
- 期待値計算では、将来辺の長さを `[d, 3d]` の一様分布と見なし、`E[min(X, next)]` を解析的に計算する。

## 最終コードの構造

### 状態表現

- `edges`: 各辺の端点とユークリッド距離 `d`。
- `cs`: 既に真の長さが分かった辺の長さ。未判明辺は `-1`。
- `uf`: 採用済み辺での Union-Find。
- `g`: 現在辺 `f` 以降だけで作る縮約グラフの隣接リスト。既に同じ成分の辺や、平均的に現在辺より十分安い辺で縮約済みの辺は除く。
- `vs`: ランダム Prim 中に確定した縮約頂点。値は `0` が未確定、`1`/`2` が現在辺の一方側、`3` が第三領域のように使われる。
- `cuts`: 各側の境界辺集合。頂点を追加するたびに隣接辺との対称差分で更新する。

### 観測・制約・入力の扱い

- 最初に全座標と全候補辺を読み、各辺の `d` を計算する。
- 各ターンで真の長さ `c` を読み、採用済み Union-Find で両端が既に連結なら必ず不採用にする。
- 現在辺より前の辺は既に判断済みなので、DP 対象のカットは現在辺以降の辺だけから作る。
- 出力後は `flush` し、採用した場合のみ `uf.unite` する。

### 評価関数

2 分割カットの DP は、カット辺を到着順に見たときの期待最小採用コストを後ろから計算する。

```text

dp[k] = edge k 以降からカットをまたぐ辺を 1 本採る期待コスト
e = dp[k + 1]
X ~ UniformInt(d_k, 3d_k)
dp[k] = E[min(X, e)]
```

現在辺を採る判定は、おおむね `c <= dp[1]` である。`dp[1]` は現在辺を見送った後の期待コストである。

3 分割カットでは、必要な接続種類を bitmask で持つ。後ろから、各辺を採る場合と採らない場合の期待値を比べる DP を作り、現在辺を採る場合の残り期待コストと、見送る場合の期待コストを比較する。提出コードでは補正定数 `C3 = 3.0` を引いてやや採用寄りにしている。

### 探索・構築・更新

- 現在辺 `f` の両端を含む成分を別々の開始点にして、ランダム Prim で縮約グラフ上の領域を伸ばす。
- 次に拡張する境界辺の優先度は、辺ごとに `[d, 3d]` から乱択した値で決める。
- 頂点を片側に追加したら、その側のカットを隣接辺集合との対称差分で更新する。
- 各ステップで現在の 2 分割カットを `dp2` にかける。
- 両側のカットができたときは、辺がどの 2 領域を結ぶかを分類して `dp3` にかける。
- 200 回程度のランダム試行のどこかで採用判定が出れば採用する。

### 操作・クエリ・出力選択

- 既に連結なら `0`。
- 連結でなければ、ランダムに生成した複数の 2 分割・3 分割カットで採用が有利かを調べる。
- 1 つでも採用が有利なカットがあれば `1`、なければ `0`。
- 採用した場合は確定 Union-Find を更新する。

### 時間配分・パラメータ

- ランダム Prim の試行回数は最大 200 程度。
- 現在辺より十分安いと期待される辺は縮約に使う。提出コードでは `mean + 10 < c` のような条件で事前縮約している。
- 3 分割 DP の補正定数は `C3 = 3.0`。
- 計算量は、全辺全カットを厳密に見るのではなく、ランダムカット生成と小さい DP を繰り返す形で 2 秒に収めている。

## 実装上重要な断片

```text
dp2(cut):
    dp[last + 1] = INF
    for edge in reversed(cut):
        e = dp[next]
        dp[cur] = E[min(random_length(edge), e)]
    return current_length <= dp[after_current]
```

```text
random_cut(current_edge):
    contract accepted edges
    contract future edges whose expected length is clearly below current_length
    start two regions from current endpoints
    while frontier exists:
        update cut of expanded region by symmetric difference
        if dp2(cut) or dp3(two_region_cuts):
            accept current edge
        expand next boundary edge by random priority
```

## この解法の本質

オンライン MST を「各時点で MST 全体を予測する問題」ではなく、「現在辺を含むカットを満たすために今払うか、後で払うか」という局所的な期待コスト比較へ落としている点が本質である。カット性質は MST の必須条件なので、1 本の辺の採否を判断するための根拠として強い。さらに 3 分割を入れることで、現在辺を採ると将来必要な辺数が 1 本減るような状況も拾える。

## 真似するならまず実装する部分

まずは 2 分割カットだけを実装するのがよい。現在 Union-Find の成分を縮約し、現在辺の両端を分けるカットを適当に作り、そのカット上で `E[min(X, next)]` DP を行う。これが動いた後に、ランダム Prim によるカット生成数を増やし、最後に 3 分割 DP を足すのが自然である。

## 注意点・未理解点

- カット生成の質がそのままスコアに効く。単に BFS や固定順で切るだけだと、現在辺の重要性を示すカットを見逃しやすい。
- 3 分割 DP は公式コードを読めたが、補正定数 `C3` の最適性は理論値ではなく調整値だと見るべきである。
- 「十分安い将来辺を先に縮約する」判定は強い近似であり、閾値を変えると採用判定が変わる。
- 採用数は最終的に `N-1` 本になることが期待されるが、オンライン出力なので Union-Find 更新と既連結判定を間違えると簡単に WA になる。
