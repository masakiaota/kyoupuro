## 解法の全体像

毎ターン、まだ不確定な辺長をランダムに決め、Kruskal で MST を複数回作る。その複数回の MST のうち、現在辺が半分以上で使われたら採用する。方針自体はシンプルな多数決型モンテカルロで、記事の中心はこの方針を 2 秒内に回すための高速化である。

具体的には、事前に全辺をランダム長にした MST を実装では 170 回作り、常に使われる辺を採用確定、全く使われない辺を不採用確定にする。毎ターンの MST 試行では、最初の数回で明らかに不採用なら早期終了し、採用閾値を超えたらそこで終了する。Union-Find も確定辺を入れた直後の状態を保存して復元する。

## 主要アイデア

- サンプルした MST に現在辺が含まれる頻度を採用確率の代理指標にする。
- 50% 以上のサンプル MST で使われる辺を採る多数決型。
- 全サンプルで必ず入る辺・必ず入らない辺を前処理で確定し、毎ターンの候補を減らす。
- 最初の 5 回すべて不採用なら、そのターンの現在辺は不採用として早期打ち切りする。
- 採用閾値を超えたら、残り試行を待たず採用として終了する。
- 残り全試行で採用されても閾値を超えないと分かった時点でも終了する。
- 確定辺を unite した後の Union-Find 状態を保存し、各 MST 試行で復元して使う。

## 最終コードの構造

### 状態表現

- 採用済み辺・不採用確定辺・採用確定辺の状態。
- 現在までに出力で採用した辺を反映した Union-Find。
- 前処理で作った 170 回分のランダム MST 結果に基づく確定情報。
- Kruskal 対象の未確定辺リスト。確定した辺は順次 `vector` から削除する。
- Union-Find の親配列と rank 配列のスナップショット。

### 観測・制約・入力の扱い

- 未知辺長は `[d, 3d]` からランダムに決める。
- 現在辺の真の長さが分かった後、そのターンのサンプル MST を複数回作る。
- 既に確定した採用辺は Kruskal 前に unite 済みとして扱う。
- 確定不採用辺や過去に判断済みの辺は候補から除く。

### 評価関数

評価値は現在辺がサンプル MST に含まれた回数である。

```text
take_count = sampled MSTs containing current edge
take if take_count * 2 >= trial_count
```

記事では、実際には早期終了するため、最後まで全試行を回さずに同じ判定が確定した時点で止める。

### 探索・構築・更新

- `Kruskal` クラスが辺配列、長さ順 `perm`、使用フラグ、Union-Find の親/rank と保存用配列を持つ。
- 各試行で未確定辺長をランダムに決める。
- 1回目は `calc_all(fixed)`、2回目以降は保存した Union-Find から復元して `calc()` を呼ぶ。
- 未確定辺を長さ順に処理し、Kruskal で MST を作る。
- 現在辺が MST に含まれたかを数える。
- 途中で採用・不採用が確定したら打ち切る。

### 操作・クエリ・出力選択

- 現在辺が多数のサンプル MST に含まれれば `1`。
- そうでなければ `0`。
- 採用した辺や確定情報を反映し、以後の Kruskal 候補から確定済み辺を削除する。

### 時間配分・パラメータ

- 前処理 MST は提出コードでは 170 回。
- 毎ターンの試行回数は進行度で変わり、前から 71、57、45、31 回を使い分ける。
- 早期不採用判定は「はじめの 5 回すべて不採用」。
- 記事後半では、乱数範囲を `[d, 3d]` ではなく `[1.13d, 2.87d]` のように内側へ寄せると 14.2G を超えたと書かれている。

## 実装上重要な断片

```text
precompute():
    cnt[e] = 0
    repeat 170:
        assign random length to all edges
        T = kruskal(all edges)
        for e in T:
            cnt[e] += 1
    if cnt[e] == 170: mark always_take
    if cnt[e] == 0:   mark never_take
```

```text
decide_current_edge():
    used = 0
    for trial in 1..max_trials:
        restore UF after fixed edges
        T = random_mst()
        if current_edge in T:
            used += 1

        if trial == 5 and used == 0:
            return false
        if used reaches majority threshold:
            return true
        if used + remaining_trials cannot reach threshold:
            return false
```

## この解法の本質

「サンプルされたオフライン MST に入る頻度」を、その辺が今採るべき辺かどうかの直接的な票として使っている。採用時・不採用時のコスト差を明示的に計算しないため実装は単純である一方、試行回数が少ないと弱い。その弱さを、確定辺前処理、早期打ち切り、Union-Find 復元、候補削除で補っている。

## 真似するならまず実装する部分

まずは「ランダム長を割り当てて MST を作り、現在辺が入った回数で多数決する」だけを作る。次に、採用済み Union-Find のコピーを軽くする。最後に、前処理の常時採用・常時不採用確定と、早期打ち切りを入れる。

## 注意点・未理解点

- 記事にコードリンクはない。提出一覧から辿った #27881268 では、`INUM/2` を閾値にして、進行度に応じて試行回数を減らす実装だった。
- 多数決は直感的だが、現在辺の真の長さが高い場合でもサンプル MST に入りやすい構造なら採ってしまう可能性がある。
- 確定辺の前処理は強力だが、サンプル数 150 に依存する近似であり、誤確定すると以後の判断が歪む。
- Union-Find の親・rank 復元は速いが、経路圧縮込みの状態管理を間違えると壊れやすい。
