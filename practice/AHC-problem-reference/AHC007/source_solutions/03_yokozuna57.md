## 解法の全体像

現在辺を使わないと仮定したとき、将来どの辺が代わりに両端成分を初めてつなぐかをモンテカルロで推定する。未知辺長をランダムに決め、Kruskal のように安い順に辺を足していき、現在辺の両端が初めて同じ成分になる瞬間の辺長を「代替辺コスト」として集計する。この代替辺の期待値が現在辺の真の長さより十分大きければ、現在辺を採用する。

terry_u16 型が「採用時と不採用時の全体 MST コスト差」を比較するのに対し、この解法は現在辺の採否で直接差が出る量を、現在辺の両端を結ぶパス上の最大辺相当として局所化している。補正として、現在辺の長さ側に `0.95` を掛けた基準を使う。

## 主要アイデア

- 現在辺を採る価値は、採らなかった場合に代わりに必要になる辺の長さで測る。
- 未知辺長をサンプリングし、現在辺を除いた Kruskal で両端が初めて連結する辺を探す。
- その辺長の平均が `0.95 * current_length` 以上なら採用する。
- `0.95` は、不採用時の理想的なオフライン MST が実際のオンライン戦略より良く見えすぎることへの補正である。
- Kruskal のソートはバケットソートで高速化できる。辺長の上限が小さいため、比較ソートより向いている。
- 延長戦ではサンプリング範囲を `[1.13d, 2.87d]` に縮めるとスコアが伸びたと報告している。

## 最終コードの構造

### 状態表現

- `E`: 各辺の端点と基準距離 `d`。
- `costs` またはランダム距離配列: 各試行での仮想辺長。
- `uf`: 採用済み辺の確定 Union-Find。
- `order`/bucket: サンプルごとに未処理辺を仮想長順に処理するための並び。
- 現在辺の両端成分 `s`, `t`: 代替辺探索で初めて同成分になるかを見る対象。

### 観測・制約・入力の扱い

- 現在辺の真の長さを読んだら、まず採用済み Union-Find で同成分かを確認する。
- 同成分なら採らない。
- 非連結なら、現在辺以降の未知辺長をサンプルし、現在辺は使わずに将来辺を安い順に見る。
- 提出 #27894297 ではランダム範囲を問題本来の `[d, 3d]` ではなく、内側に寄せた範囲へ変更している。

### 評価関数

サンプルごとに「現在辺を採らない場合の代替辺長」を得る。

```text
replacement(sample):
    uf2 = accepted_uf.copy()
    for future_edge in sorted_by_sample_length:
        if uf2.same(a, b):
            continue
        uf2.merge(a, b)
        if uf2.same(s, t):
            return sample_length(future_edge)
```

平均代替コスト `avg_replacement` が現在辺の補正コスト以上なら採る。

```text
take if avg_replacement >= 0.95 * current_length
```

記事では、現在辺を採る場合の影響を `current_length`、採らない場合の影響を代替辺長と見なし、後者はオフライン仮定で楽観的なので前者を `0.95` 倍してバランスを取る、と説明している。

### 探索・構築・更新

- 探索は多数のサンプル Kruskal。
- 各試行では確定 Union-Find をコピーし、未処理辺を仮想長順に見る。
- 辺を追加した結果、現在辺の両端成分が初めて連結したら、その辺長だけを集計して試行を終える。
- 全体 MST コストを最後まで計算しないため、terry_u16 型より 1 試行あたりの打ち切りが早くなりやすい。

### 操作・クエリ・出力選択

- `uf.same(u, v)` なら `0`。
- そうでなければ、代替辺長の平均を推定する。
- `avg_replacement >= 0.95 * current_length` なら `1`、そうでなければ `0`。
- 採用した場合は確定 Union-Find を更新する。

### 時間配分・パラメータ

- 補正係数 `0.95` が重要な調整値。
- バケットソートにより試行回数を増やす方針。
- 延長戦の改善では、サンプリング範囲を `[1.13d, 2.87d]` にすることで分散を下げ、スコアが 14,241,733,941 から 14,243,380,547 に上がったと記事にある。
- 記事内で紹介された別参加者の試行回数は前半 361 回、後半 701 回だが、これは埋め込みツイート由来の参考値であり、yokozuna57 本人の提出パラメータと同一とは限らない。

## 実装上重要な断片

```text
estimate_replacement(edge i):
    s = uf.leader(u_i)
    t = uf.leader(v_i)
    sum = 0
    for sample in samples:
        uf2 = uf.copy()
        for e in bucket_sorted_future_edges(sample):
            if e == i or e is already decided:
                continue
            if uf2.same(e.u, e.v):
                continue
            uf2.merge(e.u, e.v)
            if uf2.same(s, t):
                sum += sample.length(e)
                break
    return sum / samples
```

## この解法の本質

採用時・不採用時の総コストを丸ごと比べるのではなく、現在辺の採否で入れ替わる局所的な代替辺だけを見る点が本質である。MST では、ある非木辺を追加したときの差はパス上の最大辺と対応するため、現在辺の両端を初めて連結する辺の長さは良い代理指標になる。これにより、1 試行で最後まで MST を作らず早期終了でき、試行回数を増やせる。

## 真似するならまず実装する部分

まず、確定 Union-Find をコピーして「現在辺を除いた将来 Kruskal で両端が初めてつながる辺長」を返す関数を作る。ソートは最初は通常の sort でよい。次に試行回数を増やすためにバケットソートへ置き換え、最後に `0.95` やサンプル範囲 `[1.13d, 2.87d]` を調整する。

## 注意点・未理解点

- `0.95` はチューニング値であり、導出された厳密値ではない。
- 代替辺長はオフライン MST 的な値なので、実際のオンライン方針が到達できるコストより楽観的になりやすい。
- バケットソートは辺長上限に依存する。距離計算と bucket サイズを間違えると高速化どころか壊れる。
