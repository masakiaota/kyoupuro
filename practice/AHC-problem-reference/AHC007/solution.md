## 問題の本質

AHC007 は、真の辺長が順番に公開されるオンライン MST 問題である。最終的には連結な辺集合が必要で、スコアは真の全辺長を事前に知っていた場合の MST コスト `B` に対する、実際に採用した総長 `A` の比で決まる。したがって本質は「今見えている辺を採らなかった場合、将来どれくらい高い代替コストを払うことになるか」を推定する問題である。

同時に、終盤で連結不能になると WA なので、単に高い辺を避けるだけでは不十分である。採用済み Union-Find の成分を常に意識し、現在辺が成分間をつなぐ価値をどれだけ持つかを評価する必要がある。

## 共通している考え方

共通する中心は、未知の将来辺長を何らかの形で仮定し、現在辺を採る価値を推定することである。terry_u16、yokozuna57、assy0000、knshnb はいずれもモンテカルロで仮想的な未来を作る。公式解説はサンプリングではなくカット上の一様分布期待値 DP を使うが、「今採らなければ将来の辺で同じ接続要求を満たす必要がある」という見方は同じである。

もう一つの共通点は、真の生成分布をそのまま信じるだけでは不十分だという点である。yokozuna57 の `0.95`、assy0000 の `[1.13d, 2.87d]`、knshnb の Optuna 調整は、オフライン仮定で楽観的になりすぎる推定をオンライン方針に合うよう補正している。

## 解法の分類

- 確率推定型: terry_u16、yokozuna57、assy0000、knshnb。
- 差分コスト型: terry_u16 は採用/不採用の全体コスト差、yokozuna57 と knshnb は代替辺コスト差を見る。
- 多数決型: assy0000 はサンプル MST に現在辺が含まれる頻度で決める。
- カット DP 型: official_wata は 2 分割・3 分割カットを作り、将来辺の期待最小コストを DP で評価する。
- 高速化・後処理改善型: assy0000 の確定辺前処理、yokozuna57 のバケットソート、knshnb の Optuna。

## 推奨して理解すべき順序

1. まず terry_u16 を読む。採用した世界と採用しない世界をサンプル Kruskal で比較するため、問題のオンライン性を理解しやすい。
2. 次に yokozuna57 を読む。全体コストではなく、現在辺の代替辺だけを見る発想に進む。
3. assy0000 を読む。単純な多数決型を高速に回すための実装上の工夫を学ぶ。
4. knshnb を読む。強い方針に対して分布補正を探索する考え方を理解する。
5. 最後に official_wata を読む。カット性質と DP による、モンテカルロとは別系統の高得点方針を理解する。

## 実装するならどのルートか

理解のための最小実装なら、terry_u16 型が最もよい。サンプル数を少なめにし、現在辺を採用した場合と不採用の場合の Kruskal コストを比較するだけで、オンライン MST の基本判断を体験できる。

スコアを伸ばすなら、次は yokozuna57/knshnb 型へ移るのがよい。現在辺を採らなかった場合に両端が初めて連結する代替辺長だけを集計すれば、1 試行あたりの計算を軽くできる。そこからサンプリング範囲や補正係数をローカルテストで調整する。

さらに上位化するなら、official_wata のカット DP を別ルートとして実装する。これは実装難度が高いので、まず 2 分割カットだけを作り、`E[min(X, next)]` の DP で採否判定を行う小さい版から始めるべきである。

## 重要な実装要素

- 状態表現: 採用済み辺の Union-Find、各辺の端点と基準距離 `d`、現在ターン index、サンプル別仮想辺長。
- 評価関数: 採用/不採用の将来 MST コスト差、代替辺長 `replacement - current_length`、サンプル MST 採用頻度、カット上の期待最小コスト。
- 近傍・候補管理: この問題では局所探索の近傍というより、将来辺を仮想長順に見る候補管理が重要である。
- 差分更新: 採用した辺だけ Union-Find に反映する。サンプル試行では Union-Find コピーまたは復元を高速化する。
- 候補管理: 過去辺、既に同成分の辺、確定不採用辺をスキップする。バケットソートやソート済み配列で高速化する。
- 出力判定: 既連結なら必ず `0`。非連結なら評価値に基づいて `1/0` を出し、採用時のみ merge する。
- パラメータ: サンプル数、補正係数 `0.95`、サンプリング範囲 `[l_ratio*d, r_ratio*d]`、早期打ち切り閾値、カット生成回数。

## 落とし穴

- 既に連結な辺を採ると無駄なコストになる。必ず Union-Find で弾く。
- 終盤に必要辺を取り逃がすと連結不能で WA になる。`pass_cost` 連結不能時の扱いや、代替辺が見つからないケースを大きなコストにする必要がある。
- サンプル数を増やすだけでは TLE しやすい。Union-Find コピー、ソート、早期終了を削らないと回らない。
- オフライン MST による代替コストは楽観的である。問題文どおりの `[d, 3d]` 分布だけを使うと、オンライン実行時の採否とズレる場合がある。
- 距離 `d` は問題文ではユークリッド距離の四捨五入である。切り捨てや浮動小数誤差でサンプリング範囲がずれると、評価が変わる。
- 出力後の `flush` を忘れるとインタラクティブ形式で TLE する。

## 未解決・要検証事項

- 公式解説の 3 分割 DP における補正定数 `C3 = 3.0` の最適な値は、記事とコードからは理論的に確定できない。
- `0.95` や `[1.13d, 2.87d]`、knshnb の `1.14094`, `3.01629` は seed 集合や実装速度に依存するため、再実装時には再調整が必要である。
- assy0000 は記事中に提出リンクがないが、in-app Browser で AtCoder ユーザー `assy` の #27881268 を確認した。前処理170回、進行度別の試行回数、Union-Find復元、候補削除まで確認済みである。
