## 解法の全体像

問題を「全単語の順序と、各単語をどのマスで終えるかを決める問題」と捉え直し、単語内部の最短入力は事前計算したDPに任せる。解は `(単語W, 終了位置E)` の列として持ち、全体コストは隣り合う2要素の和で表せる。

初期解は貪欲で作り、その後、単語1個を取り出して別の位置へ移す近傍を焼きなましで繰り返す。ただし移動先と終了位置は完全ランダムではなく、全候補を調べて最も良いものを選ぶ。ランダム性は「どの単語を動かすか」に集中させ、残りは貪欲に最適化する構成である。

## 主要アイデア

- 単語に関係ない文字を打つメリットはないため、単語順序問題として見る
- `dp[w][filled][now][end]` を事前計算し、単語内の最適な打ち方を再利用する
- `common[a][b]` で、単語 `a` の後に `b` を置いたときに省ける接頭辞長を持つ
- 解を `(W,E)` の列にすると、全体コストは隣接ペアごとの和になる
- 差分計算では、1個の `(W,E)` を移動したときに壊れる辺と新しくできる辺だけを評価すればよい
- 近傍は「ランダムに1単語を選ぶ、移動先と終了位置は全探索して最良を選ぶ」
- 高速化版ではDP値を `uint8_t` に圧縮し、逆向きアクセス用の `memo013` を持って内側ループを速くしている

## 最終コードの構造

### 状態表現

- 位置は `p=i*N+j` の1次元整数で持つ
- `KEYBOARD[p]` はそのマスの文字
- `char2points[c]` は文字 `c` があるマス一覧
- `distance_table[p][q]` は `p` から `q` へ移動して打鍵するコスト
- `commons[a][b]` は `a` の接尾辞と `b` の接頭辞の最大一致長
- `operations` は `({word_id}, {end_pos})` の列で、先頭に開始位置を表す番兵 `{M, START}` を置く
- `memonxt[w][filled][pt][ep]` はDP復元用の次状態
- 高速化版では `memo012[w][filled][pt][ep]` と、添字を入れ替えた `memo013[w][filled][ep][pt]` を持つ

### 観測・制約・入力の扱い

- 入力の `N,M` は読むが、実装では `N=15, M=200, LEN=5` を定数として扱う
- 盤面文字は `A` を0にする整数へ変換する
- 各単語も文字コードを0から25へ変換する
- 番兵単語 `WORDS[M]` を置くが、最初の遷移では `commons[M][w]` がグローバルゼロ初期化で0になることを利用している
- 各単語の終了位置 `E` は、その単語の最後の文字が存在するマスに限定する

### 評価関数

- `setdp(w, filled, pt, ep)` は、単語 `w` の先頭 `filled` 文字がすでに重なりで埋まっており、現在位置 `pt` から始めて、最後に `ep` で終わる最小コストを返す
- 全体コストは次で計算する

```text
cost = sum over i:
    memo[W_i][common[W_{i-1}][W_i]][E_{i-1}][E_i]
score = -cost
```

- 焼きなまし中はスコアを「負のコスト」として最大化する
- 提出得点自体は全単語を含む前提で `10000 - cost` だが、探索内部ではコスト最小化だけを見る

### 探索・構築・更新

- `datainit` で距離表、文字位置表、重なり表、単語DPをすべて作る
- 初期解は、未使用単語と終了位置を全探索し、現在列の末尾に追加したときの `calc_score` が最も良いものを選ぶ貪欲で作る
- 焼きなましでは、`operations` からランダムに1要素 `x` を選んで削除対象にする
- すべての挿入位置 `ins` と、`x` の終了位置候補を調べ、差分が最大となる移動先を選ぶ
- 差分は `a x b ... c d` から `a b ... c x d` へ変わる部分だけで計算する
- 採択は線形温度の焼きなましで、改善は必ず、悪化は確率的に受理する
- ベスト解を別に保存し、最後にベスト解を復元出力する

### 操作・クエリ・出力選択

- `output` は `operations` の隣接ペアを順に見て、重なり長 `filled` から `memonxt` を辿る
- 復元中に得た `pt` を座標 `(pt/N, pt%N)` に戻して出力する
- 各単語の先頭重なり部分は復元開始時点で `filled` として省略されるため、出力文字列には前単語との重なりが反映される

### 時間配分・パラメータ

- コンテスト中コードの終了時刻は約1950ms
- 高速化版では終了時刻を約1820msにしてもスコアが上がっている
- 焼きなまし温度は `begin_temp=1`, `end_temp=0.5`
- 記事によるとコンテスト中コードは手元で6万回程度遷移が回り、スコア計算は1億回程度
- 高速化版は約5倍速くなったとされる

## 実装上重要な断片

単語DP:

```text
setdp(w, filled, pt, ep):
    if filled == LEN:
        return 0 if pt == ep else INF
    ans = INF
    c = WORDS[w][filled]
    for np in char2points[c]:
        ans = min(ans, dist(pt,np) + setdp(w, filled+1, np, ep))
    store next state for reconstruction
```

1単語移動の差分:

```text
remove x from a-x-b:
    old1 = cost(a,x) + cost(x,b)
    new1 = cost(a,b)

insert x between c-d:
    old2 = cost(c,d)
    new2 = cost(c,x) + cost(x,d)

diff = (new1 + new2) - (old1 + old2)
```

高速化版の内側:

```text
v1 = memo012[x][common[c][x]][E_c]
v2 = memo013[d][common[x][d]][E_d]
for E_x in possible_end_positions:
    new_cxd = -v1[E_x] - v2[E_x]
```

## この解法の本質

この解法は、探索対象を「単語内部の打ち方」から「単語列と各単語の終端位置」へ圧縮している。単語内部はDPテーブルで完全に解き、焼きなましは隣接関係だけを触る。全体コストが隣接2項の和になる状態表現を選んでいるため、局所変更の差分計算が非常にきれいになる。

また、近傍の作り方が特徴的である。単語選択だけをランダムにし、挿入先と終了位置は貪欲に全探索することで、無駄な悪手を減らしつつ、ボトルネックを局所化して高速化しやすくしている。

## 真似するならまず実装する部分

まず `dp[w][filled][now][end]` と `common[a][b]` を実装し、`operations` のコストを隣接和として計算できるようにする。次に、初期解を作る末尾追加貪欲を実装する。

その後、1単語を削除して全挿入位置・全終了位置を試す近傍を差分計算で実装するのがよい。高速化は後回しでよいが、最初から `char2points[last_char]` だけを回す設計にしておくと拡張しやすい。

## 注意点・未理解点

- `memo` を `uint8_t` に圧縮する高速化は、長さ5単語のDPコストが255未満であることに依存している。問題制約では妥当だが、汎用化すると壊れる
- グローバル配列のゼロ初期化や番兵の扱いに依存している箇所がある
- 1単語移動近傍だけなので、公式解説の複数区間入れ替えや単語マージに比べると探索の形は限定的である
- `done` と `memo012` の4次元配列はメモリを大きく使う
- 高速化版の `memo013` は添字の意味を間違えると差分計算が壊れやすい
