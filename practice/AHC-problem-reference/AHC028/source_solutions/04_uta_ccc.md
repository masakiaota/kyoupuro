## 解法の全体像

短期AHC向けに、強い貪欲を素早く作る方針である。まず、重なりが大きい単語同士を事前に合体して候補文字列数を減らす。次に、現在位置から各候補文字列を打つ最短経路をDPで評価し、評価値が最も良い文字列を選んで出力へ追加する。

選んだ文字列についてはDPの遷移元座標を保存し、最短経路を復元して座標列へ追加する。焼きなましやビームには進まず、DP+貪欲でまとめている。

## 主要アイデア

- 最大でも200単語×5文字なので、操作回数5000はほぼ気にしなくてよい
- 前後の単語で重ねられる部分は重ねた方がよい
- 4文字、3文字、2文字の重なりがある単語を事前に合体する
- 各マスから各文字へ移動する候補をコスト順に前計算する
- 現在位置から候補文字列を打つ最短コストはDPで求める
- 直前に出力済みの末尾と候補文字列の先頭が重なる場合、その重なり分を省いた文字列だけを打つ
- 候補選択では、単純コストをそのまま使わず、合体済み文字列や重なりが効いた候補を優遇するための割り算補正を入れる

## 最終コードの構造

### 状態表現

- `Status` は `check`, `ans`, `curStrList`, `cost` を持つ
- `ans` は出力する座標列
- `curStrList` はこれまで実際に打った文字列
- `Tlist` は未処理の候補文字列リストで、前処理でマージされる
- `slice[i]` は候補文字列の接頭辞・接尾辞を取り出すための辞書
- `strMap[y][x][char]` は、現在マス `(y,x)` から文字 `char` を打てる移動先候補 `[cost, ny, nx]` のリスト

### 観測・制約・入力の扱い

- 入力は `N, M, start, A, T` として読む
- `N=15, M=200, |T_i|=5` を前提に設計している
- 事前マージでは `range(-4, -1)` を使っており、4文字、3文字、2文字重なりを両方向に探している
- `strMap` は全マス間のマンハッタン距離+1を列挙し、文字ごとにソートしておく
- 全単語を含めることを前提に、`Tlist` が空になるまで貪欲に処理する

### 評価関数

- 候補文字列 `searchStr` を現在位置から打つ最短コストをDPで求める
- 候補選択時は、そのコストを `diff=max(5, 5+abs(5-len(searchStr)))` で割る
- `searchStr` が長い、または直前出力と重なって短くなるほど、通常の長さ5単語とは異なる候補として優遇される意図がある
- 同程度の評価では `diff` が大きい候補を選びやすい条件になっている
- 探索内部のスコアは `10000 - stat.cost`

### 探索・構築・更新

- 前処理で、候補文字列同士の重なりを見て貪欲にマージする
- 各貪欲ステップで、残りすべての `Tlist` を候補として見る
- 候補ごとに、現在の出力末尾との最大4文字重なりを調べ、重なる接頭辞を省いた `searchStr` を作る
- `seachMemo[cy][cx][searchStr]` に、現在位置と文字列ごとのDP結果をキャッシュする
- 最良候補が決まったら、再度DPを実行して遷移元座標を保存し、経路復元する
- 復元した座標列を `ans` に追加し、対応文字を `curStrList` に追加する
- 処理済み候補を `Tlist` から削除する

### 操作・クエリ・出力選択

- `output` は `ans` に入っている座標を1行ずつ出力する
- 出力文字列自体は `curStrList` に対応する
- 事前マージと直前重なり省略により、元単語が部分文字列として含まれるようにしている
- DP復元では、最後の座標から遷移元を辿って逆順に戻し、最後に反転して出力へ追加する

### 時間配分・パラメータ

- 時間制御ループはない
- Python PyPy 3.10で提出し、実行時間は最大1034ms
- 近い順3つに候補を絞るコメントがあるが、最終コードでは使っていない
- 乱択は使っておらず、`seed(0)` は実質影響しない

## 実装上重要な断片

候補文字列のDP:

```text
dp[0][current_pos] = 0
for i, ch in enumerate(searchStr):
    for pos in dp[i]:
        for (move_cost, next_pos) in strMap[pos][ch]:
            relax dp[i+1][next_pos]
```

直前出力との重なり省略:

```text
for k in 4..1:
    if suffix(current_output, k) == prefix(candidate, k):
        searchStr = candidate[k:]
        break
```

候補選択:

```text
raw = min_cost(current_pos, searchStr)
factor = max(5, 5 + abs(5 - len(searchStr)))
value = raw / factor
choose smallest value, preferring larger factor on ties
```

## この解法の本質

この解法は、短時間で実装可能な範囲に問題を落としている点が本質である。単語順全体を深く探索する代わりに、局所的に「今から一番安く、かつ重なりや合体の恩恵がありそうな文字列」を選ぶ。

DPで経路だけは正確に最小化しているため、貪欲の評価が多少粗くても、選んだ候補の打ち方で無駄が出にくい。事前マージと直前重なり省略が、単純な最短候補貪欲より強くするための主要な工夫である。

## 真似するならまず実装する部分

まず `strMap` と、現在位置から任意の短い文字列を打つDPを作るのがよい。次に、残り単語を全探索して最小コストのものを選ぶ貪欲を作る。

その後、直前出力との重なり省略を入れ、最後に4・3・2文字重なりの事前マージと `cost / factor` の評価補正を足すと、この解法の骨格になる。

## 注意点・未理解点

- 事前マージは貪欲であり、マージ順によって結果が変わる
- 重なりだけでマージしているため、キーボード上の移動コストまで見たマージではない
- `check` や `distMap` など、最終的にほぼ使われていない構造がある
- 候補選択用DP結果はキャッシュしているが、実際の復元時には再計算している
- 焼きなましに進めなかったと記事で述べられており、上位解法と比べると順序探索の深さは限定的である
