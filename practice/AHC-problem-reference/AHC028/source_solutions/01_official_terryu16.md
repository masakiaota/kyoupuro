## 解法の全体像

公式解説は、単純な「単語を順に打つ」貪欲から始め、固定された出力文字列に対する最短経路DP、単語順序を選ぶ貪欲・ビームサーチ、base cost による評価補正、単語マージ、焼きなましと近傍絞り込みへ段階的に発展させる構成である。

最終的な見方は、「どの単語をどの順に並べるか」と「重なりをどう使うか」を決め、実際のキー座標列はDPで最適化するという分解である。さらに、単語そのものの作りやすさと、前後関係で生じる余計な移動コストを分けて評価する。

## 主要アイデア

- 最終文字列 `S` が決まれば、各文字をどのマスで打つかはDPで最小化できる
- 前単語の接尾辞と次単語の接頭辞が一致する部分は重ね、入力を省略する
- 長さ5のランダム単語では1文字重なりはほぼ必ず、2文字重なりもそれなりに起こるため、重なりを探索対象にする価値がある
- 単語単体を最短で作るコストを `base(s)` とし、実コストから base cost を引いて「余計な移動」を評価する
- ビームサーチでは評価値を「DPテーブルの最小値 - 使用済み単語のbase cost和」とし、残り単語の推定コストを含んだ形で状態を比べる
- 明らかに連続させたい単語は事前にマージし、単語数 `M` を減らして探索を軽くする
- 焼きなましでは単語順を直接動かし、挿入・2分割入れ替え・3分割入れ替えなどの近傍を使う
- 近傍の絞り込みでは、隣接単語同士の相性 `f(a,b)=base(a)+base(b)-base(ab)` を使い、相性総和の悪化が大きい遷移を枝刈りする

## 最終コードの構造

コードなし。以下はスライドから読み取れる実装構造である。

### 状態表現

- キーボードを `0..N^2-1` の1次元座標にして扱う
- 文字ごとに、その文字が置かれたマス集合を持つ
- 固定文字列に対するDP状態は `dp[l][p]`: 出力文字列の先頭 `l` 文字を確定し、指がマス `p` にあるときの最小コスト
- 単語順探索の状態は、使用済み単語集合、現在末尾の文字列または最後の単語、最後の指位置、累積DPコストを持つ形になる
- 単語マージ後は、元の長さ5単語ではなく、複数単語を含む短い文字列列を探索単位にする

### 観測・制約・入力の扱い

- 全単語を含めないと得点が大きく下がるため、実質的には全単語を含む出力だけを考える
- 操作回数上限5000は、長さ5の200単語を単純連結しても1000文字なので基本的に支配的ではない
- 各文字は必ず盤面に存在するため、DP遷移は常に可能である
- DPでは次に打つ文字と一致するマスだけを候補にすればよい

### 評価関数

- 固定文字列の評価は、DPで求めた総移動コスト `T`
- 貪欲で生コストだけを見ると、単語そのものが作りやすいかどうかに引っ張られる
- base cost を使い、追加候補の評価をおおむね `追加コスト - base(追加単語)` と見る
- ビームでは `現在までのDP最小コスト - 使用済み単語のbase cost和` を小さくする
- 単語相性は `f(a,b)=base(a)+base(b)-base(merge(a,b))` とし、隣接させたときの得を測る

### 探索・構築・更新

- 最初の貪欲は、未使用単語を全探索し、末尾に追加したときのコストが最小のものを選ぶ
- DP+貪欲では、候補単語を末尾へ追加した場合の最短経路コストをDPで評価する
- ビームサーチでは、各深さで複数候補を保持し、base cost 補正付き評価で枝刈りする
- 単語マージでは、`base(a)+base(b) >= base(merge(a,b))+X` のような条件で、マージしても損しにくい組を事前結合する
- 焼きなましでは、単語列に対して挿入、部分列入れ替え、3分割入れ替えを試す
- 近傍絞り込みでは、相性総和 `g(P)=sum f(P_i,P_{i+1})` の差分を `O(1)` で計算し、悪そうな近傍を評価前に捨てる

### 操作・クエリ・出力選択

- 最終的に得られた単語列またはマージ済み文字列列を1本の出力文字列にする
- 重なり分は省略して連結する
- 最後に固定文字列に対するDPを復元し、各文字を打つ座標列を出力する
- 各行は座標だけを出し、操作回数行数が5000を超えないことを確認する

### 時間配分・パラメータ

- ビーム幅は、単純ビームでは200程度、単語マージ後は1000程度まで伸ばせたとされる
- 単語マージにより単語数を200から50から60程度まで減らす例が示されている
- マージ閾値 `X` は、ビーム側では0程度、焼きなまし側では -3 程度が良さそうだとされる
- 近傍絞り込みの閾値 `T` は -1 の例が示されている
- 焼きなましの単純挿入近傍だけでは約10万回程度回せるが、賢い貪欲に負けるとされる

## 実装上重要な断片

固定文字列の経路DP:

```text
dp[0][start] = 0
for l in 0..len(S)-1:
    for p with finite dp[l][p]:
        for q in positions[S[l]]:
            relax dp[l+1][q] by dp[l][p] + dist(p,q) + 1
```

単語追加の重なり:

```text
overlap(a, b):
    return largest k such that suffix(a,k) == prefix(b,k)

append b after a:
    type only b[k:]
```

近傍絞り込み:

```text
before = f(left, x) + f(x, right)
after  = f(left, right)
if after - before is too bad:
    skip expensive DP evaluation
```

## この解法の本質

この問題の難しさは、文字列長の短縮とキーボード上の移動短縮が一致しない点にある。公式解説の本質は、文字列構成と経路選択を分離し、経路はDPで正確に処理しつつ、探索側では base cost によって「単語自体の難しさ」と「並べ方の悪さ」を切り分けることだと言える。

単語マージや相性評価は、ランダムな長さ5単語の局所的な重なりを利用して探索空間を縮める工夫である。単に重なり文字数だけを見ると移動コストで損する場合があるため、base cost を通した実コスト基準で判断する点が重要である。

## 真似するならまず実装する部分

まずは固定文字列に対するDPと、単語間の最大重なり計算を実装するのがよい。次に、未使用単語を全探索して `追加コスト - base(word)` が小さいものを選ぶ貪欲を作る。

その後、状態数を少し増やしてビームサーチにし、base cost 評価を導入する。上位化を狙うなら、単語マージと相性に基づく近傍絞り込みを追加する。

## 注意点・未理解点

- 公式スライドには完成コードはないため、データ構造や差分更新の細部は実装者側で設計する必要がある
- 単語マージは重なり文字数だけで判断すると悪化する場合があり、base cost に基づく判定が必要である
- `base(merge(a,b))` の計算対象を、重なり込みの結合文字列として一貫させる必要がある
- 近傍絞り込みは強力だが、閾値を厳しくしすぎると良い遷移を捨てる
- スライド上のスコア・順位は「相当」であり、提出そのものの順位として扱わない
