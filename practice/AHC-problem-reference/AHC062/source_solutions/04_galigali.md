## 解法の全体像

この解法は、盤面全体に固定の往復ジグザグパスを作り、その後で隣り合う列ペア内の訪問順を入れ替えてスコアを上げるシンプルな構築である。

最初に、列方向に縦へ進むパスを4列周期で作る。前半は左から右へ、後半は右から左へ戻るように全セルを通る。次に、各列ペア `(k, k+1)` の内側行について、人口が大きいセルが早く訪問されている場合は2セルをswapする。記事は、このswap後も前後のセルとの8近傍隣接が保たれることを図で説明している。

## 主要アイデア

- まず必ず可行な固定パスを作る。
- 4列周期の往復構造にすることで、後から列ペア内の局所swapを安全に行える。
- 各行の隣接列ペアで、小さい人口セルを早く、大きい人口セルを遅くする。
- 大きな探索をせず、O(N^2)程度の構築と局所入れ替えだけで高い実行速度を得る。

## 最終コードの構造

### 状態表現

- `ans`: 訪問順の座標列。
- `ni, nj`: 固定パスを生成するときの現在座標。
- `mp: map<P, ll>`: 各セルが `ans` の何番目にあるかを保持する。
- `a[n][n]`: 人口値。

### 観測・制約・入力の扱い

- `N=200` で `n/4=50` 回のループを2フェーズ実行する。
- 固定パス生成後、最後に原点側へ戻ってしまう余分な1セルを `ans.pop_back()` で削る。
- `mp` はswap前の各座標の位置を調べるために使う。swap後に `mp` は更新されないが、各列ペアごとに独立したセル位置を一度だけ参照するため、この用途では問題にならない。

### 評価関数

- コード内では最終スコアを計算していない。
- 局所改善の評価は、隣接列ペア `(i,k)` と `(i,k+1)` について `a[i][k] > a[i][k+1]` なら入れ替える、という単純比較である。
- これは、小さい値を早い訪問順、大きい値を遅い訪問順に置くことを狙う。

### 探索・構築・更新

- パス構築:
  - `(0,0)` から開始する。
  - 4列ずつ、下方向に進む列、隣列への接続、上方向に戻る列、次の列への接続を繰り返す。
  - 盤面右側まで行った後、同様の構造で右から左へ戻る。
- 局所swap:
  - `k=0,2,4,...` の列ペアを対象にする。
  - 端付近を避け、`i=2..n-3` の範囲で比較する。
  - 左列の値が右列より大きければ、`ans` 上の2セルをswapする。
  - この2セルは構造上、前後のセルと斜めまたは縦横に隣接し続ける。

### 操作・クエリ・出力選択

- 最後に `for (P e: ans)` で全座標を出力する。
- 最良パターン選択や焼きなましはない。

### 時間配分・パラメータ

- 記事では実行時間が約24msと説明されている。
- パラメータはほぼなく、列周期4、swap対象行 `2..n-3` が固定である。
- 乱択は使わない。

## 実装上重要な断片

```text
make_base_path:
    ans = [(0, 0)]
    repeat N/4 times:
        go down current column
        move to next odd column near bottom
        go up next even-like column
        move to next block
    repeat N/4 times in reverse direction:
        symmetric traversal from right to left
    remove final duplicate-like extra cell
```

```text
pair_swap:
    position[cell] = index in ans
    for k in 0, 2, ..., N-2:
        for i in 2..N-3:
            if A[i][k] > A[i][k+1]:
                swap(ans[position[(i,k)]], ans[position[(i,k+1)]])
```

## この解法の本質

この解法の本質は、「swapしても壊れない固定パス」を先に設計している点である。一般のハミルトン路で2点swapをすると隣接制約が壊れるが、この4列周期の構造では、特定の列ペア・行範囲に限れば前後のセルとの関係が保たれる。その安全な自由度を使って、小さい値を前、大きい値を後へ局所的に並べ替えている。

実装が短く、探索をしないため、短時間で強いベースラインを作れる方針である。

## 真似するならまず実装する部分

まず固定パスだけを実装し、`N^2` 個、重複なし、全隣接を検査する。次に列ペア内swapを足し、swap後にも検査を入れるのがよい。

この方針は、フロンティアDPより先に実装する練習として適している。局所swapの安全範囲を誤らないことが最重要である。

## 注意点・未理解点

- swap対象を端まで広げると接続が壊れる可能性がある。コードでは `i=2..n-3` に制限している。
- `mp` をswap後に更新しない設計は、この近傍が一度きりで各セルの元位置を使う前提に依存している。複数回swap探索へ拡張するなら更新が必要である。
