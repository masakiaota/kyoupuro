## 解法の全体像

この解法は、左右端1列を温存しながら中央を2行単位で走査し、後半で端列を使って未訪問セルを回収する往復型の構築である。2行の各列では、原則として小さい人口のセルを先に訪問し、もう片方を後半に回す。これにより、全体を一度なぞったあとにもう一度戻ってくるような訪問順を、全セル一度訪問の制約内で実現している。

最後に、同じ構築を4種類の座標変換で試し、元座標に戻してスコアが最大のものを出力する。

## 主要アイデア

- 2行単位の帯で、各列の低人口セルを前半、高人口セルを後半に分ける。
- 左右端列を最初に使い切らず、後半の戻り経路として残す。
- 各2行帯の端付近では、多少スコアを犠牲にしても次帯へ確実に移れる形を優先する。
- 後半は、前半で選ばなかった相方セルを逆向きに回収する。
- 通常、左右反転、転置、転置+反転の4パターンを試し、最良スコアを選ぶ。

## 最終コードの構造

### 状態表現

- `path`: 出力予定の座標列。
- `used[n][n]`: 既訪問セルの真偽。
- `row_choice[pair][c]`: 2行帯 `pair` の列 `c` で、前半に訪問した行を記録する。後半で相方行を回収するために使う。
- `best_path`, `best_score`: 4座標変換の中の最良解。
- 座標変換は `transform_grid(a, mode)` と `inverse_point(i, j, n, mode)` で扱う。

### 観測・制約・入力の扱い

- `N` が奇数なら構築失敗扱いにしているが、問題では `N=200` なので常に偶数である。
- `append_cell` が範囲外、重複、直前セルとの8近傍隣接を全て検査する。
- 構築後に `valid_path?` で長さ、重複、隣接性を再検査する。
- 座標変換後に構築し、元座標へ戻した後にも再検査する。

### 評価関数

- `score_path(path, a)` は `sum day * a[i][j]` を直接計算する。
- 構築中の局所選択では、2行の同じ列で `a[r0][c] <= a[r1][c]` なら上側を前半にするという貪欲を使う。
- 端や帯の接続では、スコア最適より可行性を優先する固定選択が入る。

### 探索・構築・更新

- `build_requested_path(n, a)` が中心である。
- フェーズ1:
  - 2行帯ごとに処理する。
  - 偶数番目の帯は左から右、奇数番目の帯は右から左へ進む。
  - 中央列 `1..n-2` のうち、最初の列は上段、折り返し手前は下段を固定し、それ以外は低人口行を選ぶ。
  - 選んだ行を `row_choice` に記録する。
  - 帯の終端で下段へ移り、次の2行帯へ降りる。
- フェーズ2:
  - 最下部から上へ戻る。
  - 各2行帯について、`row_choice` の反対側の行を列順に回収する。
  - 左右端の未訪問セルは、現在位置からつながる順を試し、失敗時は保存状態に戻して別順を試す。
- `main`:
  - 4モードの座標変換を順に試す。
  - 成功した構築だけ元座標に戻してスコア計算し、最良を出力する。

### 操作・クエリ・出力選択

- インタラクティブではないため、最後に `best_path.each` で全座標を出力する。
- 4パターン全て失敗した場合は標準エラーに失敗理由を出し、終了コード1にする。ただし `N=200` では通常成功する設計である。

### 時間配分・パラメータ

- 焼きなましや時間制御はない。
- 試す座標変換は4パターン固定である。
- 後半端処理では、`Marshal` で `used` のスナップショットを取り、順序を2通り試す実装になっている。

## 実装上重要な断片

```text
phase1 for each two-row band:
    cols = left_to_right ? 1..N-2 : reverse(1..N-2)
    for c in cols:
        if first column:
            row = upper
        else if one_before_edge:
            row = lower
        else:
            row = row with smaller A
        row_choice[band][c] = row
        append(row, c)
```

```text
phase2 for each band from bottom to top:
    align to preserved edge
    enter upper edge cell if needed
    for c in reverse traversal direction:
        row = opposite(row_choice[band][c])
        append(row, c)
    settle remaining edge cells with fallback order
```

## この解法の本質

この解法の本質は、複雑なハミルトン路探索を避け、「2行の片方を先に、片方を後に」という非常に分かりやすい構造へ問題を落としている点である。左右端列を温存することで、前半で飛ばした相方セルを後半で無理なく回収できる。8近傍の斜め移動があるため、2行帯の端や相方セルへの切り替えが成立しやすい。

また、4パターン比較は簡単だが有効である。構築ルールには端・上下・左右の癖があるため、座標変換を試すだけで局所的な不利を避けられる。

## 真似するならまず実装する部分

まずは座標変換なしで、2行帯のフェーズ1・フェーズ2構築を作るのがよい。`append_cell` と `valid_path` を最初に用意し、可行性を常に検査しながら作る。

次に4パターン比較を足す。焼きなましを足すよりも、まずこの構築を落ちない形にする方が学習効果が高い。

## 注意点・未理解点

- 端列の処理は場合分けが壊れやすい。コードでは保存・ロールバックで2順序を試している。
- 最初の列と折り返し手前を固定するため、その部分では局所的に大きいセルを前半に置くことがある。
- 4パターンは回転全8通りではなく、通常・左右反転・転置・転置+左右反転の4通りである。
- 記事で触れられている初期の4x4ブロックDFS案は最終採用されておらず、提出コードにも残っていない。
