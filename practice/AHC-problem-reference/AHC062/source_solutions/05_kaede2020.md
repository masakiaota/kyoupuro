## 解法の全体像

記事は本番中の試行と復習を詳しく書いている。本番解法は、初期解を作り、それを2-optやブロック移動などの近傍で改善する局所探索型である。最初はビジュアライザから「前半に小さい値の地域、後半に大きい値の地域を通る」ような解を意識し、平滑化したポテンシャルや開始位置調整を試している。しかし入力はランダム permutation で、空間的な低地・高地はほぼないため、地域性だけでは伸びにくい。

復習では、Warnsdorff則風の「行ける先が少ないセルを優先する」初期解や、2-opt、区間移動、ブロック移動、パラメータ調整を検討している。最終的には、構築である程度の可行パスを作り、局所探索で訪問順と人口の相関を高める方針である。

## 主要アイデア

- まず必ず全セルを一度ずつ通る可行パスを作る。
- 平滑化ポテンシャルで低い地域から高い地域へ向かうような初期解を試す。
- ただし、入力値はランダムに散らばるため、空間的なポテンシャルだけでは限界がある。
- Warnsdorff則風に、未訪問近傍が少ないセルを優先して詰まりにくいパスを作る。
- 2-opt、ブロック移動、近傍選択のパラメータ調整で後処理改善を行う。
- パスを逆順にした方が得点が高い場合は反転する。

## 最終コードの構造

以下は記事本文とキャッシュ実装 `#74150809` から確認した構造である。

### 状態表現

- `path`: 現在の訪問順。
- `used`: 各セルの訪問済み判定。
- `pos`: 局所探索時に各セルの訪問位置を引くための配列を持つのが自然である。
- `score`: 現在スコア、または差分更新用の値。
- 平滑化ポテンシャルを使う場合は、各セルの周辺平均または加重平均値を持つ。

### 観測・制約・入力の扱い

- 入力値は `1..N^2` のランダム permutation であるため、隣接セルの値に強い相関はない。
- 可行パスを作る制約が強く、局所改善は隣接条件を守る候補だけを採用する必要がある。
- 記事では1ケースWAが出たことにも触れており、構築後の検証が重要だと分かる。

### 評価関数

- 基本は `sum k*A[path[k]]`。
- 平滑化ポテンシャルでは、各セル単体の値ではなく周辺値を平均した指標で、低い方から高い方へ向かうことを狙う。
- 後処理では、2-optやブロック移動のスコア差分を評価する。
- 逆順の方が高ければパスを反転する。

### 探索・構築・更新

- 初期解:
  - 単純な可行パス、またはWarnsdorff則風の貪欲で作る。
  - Warnsdorff風では、次候補のうち未訪問近傍数が少ないセルを優先し、将来の詰みを避ける。
  - 平滑化ポテンシャルで、低いセルを序盤、高いセルを終盤へ寄せる候補選択を試す。
- 改善:
  - 2-optで区間の向きを入れ替える候補を試す。
  - ブロック移動で連続区間を別位置へ移す。
  - 近傍の採択や候補サイズを調整しながら提出を繰り返している。

### 操作・クエリ・出力選択

- 最後に可行な `path` を出力する。
- `path` と `reverse(path)` の得点を比較し、高い方を出力する考え方が記事中で示されている。

### 時間配分・パラメータ

- 初期解は偶数N向けのsnake/return型の決定的パスで、奇数Nでは単純列snakeにfallbackする。
- 焼きなまし時間は約2.90秒。
- 温度は `3e8 -> 20`。
- 近傍はlane pair swap、vertical pair swap、order swap、local swap、reverse、3/4点cycle shift。
- reverseの差分はprefix補助配列で遅延再計算する。

## 実装上重要な断片

キャッシュ実装は、Warnsdorff型ではなく固定構造の初期パスから始める。偶数Nでは往復snake/returnを作り、必ず全セル一度訪問と8近傍隣接を検証する。初期後に `greedy_pair_improve` で縦隣接ペアやレーンペアを4pass見て、値が大きいセルを後ろへ送れるswapだけ貪欲に採用する。

焼きなましでは、現在の訪問位置 `pos` とスコアを持ち、近傍比率を進行度で変える。候補選択は完全ランダムではなく、値差、位置差、レーン構造へのbonus/penaltyを使って複数試行から有望候補を選ぶ。最終パスが壊れていれば初期解へ戻すfallbackもある。

```text
warnsdorff_like_initial_path:
    start from chosen cell
    while unvisited cells remain:
        candidates = unvisited adjacent cells
        choose candidate with small onward_degree
        optionally break ties by low potential / low A in early phase
        append candidate
```

```text
reverse_if_better:
    if score(reverse(path)) > score(path):
        path.reverse()
```

```text
block_move_improvement:
    choose segment [l, r)
    choose insertion position p
    if boundary adjacency remains valid:
        delta = score_after - score_before
        accept if delta improves or annealing condition accepts
```

## この解法の本質

この解法の本質は、可行性を壊さない初期解と、局所探索の候補設計の試行錯誤にある。問題の入力はランダムなので、「地形のような低地から高地へ向かう」直感は限定的にしか効かない。一方で、どんな近傍を採用するにも、全セル一度訪問と8近傍隣接を守る必要があり、候補生成の安全性がスコア以前に重要になる。

復習部分は、構築型の強い解法とは違い、一般的なハミルトン路改善アプローチの落とし穴を示している。2-optやブロック移動は強そうに見えるが、初期解の構造が弱いと大きく伸びにくい。

## 真似するならまず実装する部分

まずは可行性検査付きの初期パス生成と、逆順比較を実装する。次に、隣接条件を壊さない小さなブロック移動を入れるのがよい。

高得点を目指すなら、この参加記だけをベースにするより、公式解説や2行・4行の構築型解法で強い初期解を作り、その上にこの記事の近傍改善の考え方を載せるのが現実的である。
