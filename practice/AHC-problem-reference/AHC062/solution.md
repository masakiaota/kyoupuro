## 問題の本質

AHC062 は、8近傍移動のハミルトン路を作り、訪問時刻 `k` と人口 `A` の相関をできるだけ高くする問題である。人口値は `1..N^2` のランダム permutation なので、空間的な地域差を読むよりも、経路構造の中で低い値を前半、高い値を後半へ送ることが重要になる。

完全に人口順へソートすることは隣接制約で不可能である。そのため強い解法は、まず可行な幾何構造を設計し、その構造の中で小側・大側を選ぶ。典型形は、前半用の `small` パスと後半用の `large` パスを作り、`small + reverse(large)` として出力する形である。

## 実装キャッシュ反映

poisonkumaa `#74068987` と kaede2020 `#74150809` の提出コードを読んだ。poisonkumaaは記事メモ上の幅4DPより具体的には5レーンDPで、8変換の初期解上位2つだけをSAする。kaede2020はWarnsdorff/平滑化ではなく、決定的snake/return初期解、pair貪欲改善、多近傍SAだった。

## 共通している考え方

- 低人口セルを前半、高人口セルを後半へ寄せる。
- まず可行なハミルトン路構造を作る。
- 8近傍、特に斜め移動を使うと、2行帯や4行帯の折り返しが作りやすい。
- 経路全体を自由に並べ替えるのではなく、壊れない局所自由度だけを使う。
- 座標変換を複数試すだけでも、端や折り返しの偏りを減らせる。
- 局所探索は、強い初期解の上に乗せた方が効きやすい。

## 解法の分類

- 構築型:
  - galigali の固定4列往復パス。
  - yoto1980yen の2行帯フェーズ分割。
- ペア分割型:
  - 公式のペア解法。
  - galigali の列ペア内swap。
- DP型:
  - 公式の3重解法。
  - 公式・poisonkumaa の4行幅DP。
  - wata版のフロンティアDP。
- 後処理改善型:
  - poisonkumaa の1点Swap・2-opt焼きなまし。
  - wata版の区間移動焼きなまし。
  - kaede2020 の2-opt・ブロック移動系。
- パターン比較型:
  - yoto1980yen の4変換比較。
  - poisonkumaa の8変換比較。

## 推奨して理解すべき順序

1. まず galigali の固定パスと列ペアswapを読む。可行性を壊さない局所自由度の作り方が分かる。
2. 次に yoto1980yen の2行帯解法を読む。`small + reverse(large)` に近い往復構造を実装レベルで理解できる。
3. 公式のペア解法と3重解法を読む。なぜグループ数を増やすと相関が上がるかが分かる。
4. 公式の4行フロンティアDPを読む。上位解法の状態設計と復元を理解する。
5. 最後に poisonkumaa と wata版焼きなまし、kaede2020 の近傍設計を読み、初期解後の改善を考える。

## 実装するならどのルートか

理解のための最小実装なら、galigali の固定4列パスから始めるのがよい。可行な全訪問パスを作り、列ペアswapでスコアを上げるところまでが短い。

次の段階では、yoto1980yen の2行帯解法を実装する。端列温存と相方セル回収により、前半・後半分離の効果をより直接的に確認できる。

上位化を目指すなら、公式の4行フロンティアDPが本命である。実装難度は高いが、局所的な小大分割をDPで最適化できる。さらに伸ばすなら、wata版やpoisonkumaaのように、構築後の区間移動・Swap・2-opt焼きなましを追加する。

## 重要な実装要素

- 状態表現:
  - `path`、`used`、`pos` は全方針で基本になる。
  - `small`/`large` の2本のパス表現は、構築型DPで特に重要である。
  - フロンティアDPでは、アクティブ境界の端点、欠片、内部を小さな状態に圧縮する。
- 評価関数:
  - 真の `sum k*A` を計算できる関数を必ず用意する。
  - 構築中は「低人口を前半へ送る」局所評価へ変換する。
  - 焼きなましでは差分更新が必要である。
- 近傍:
  - 安全な列ペアswap。
  - 2-opt。
  - 区間移動。
  - ブロック移動。
- 差分更新:
  - 区間移動では prefix sum で `delta` を計算する。
  - 採択後は `pos` と prefix sum の更新範囲を限定する。
- 候補管理:
  - フロンティアDPでは状態数が爆発するため、接続不可能状態の除外と枝刈りが必要である。
  - 局所探索では、境界隣接を満たす候補だけを生成する。
- 出力判定:
  - 長さ `N^2`、全セル一意、各連続セルが8近傍であることを毎回検査する。
  - 座標変換後は、元座標へ戻してから再検査する。
- パラメータ:
  - 座標変換数は4または8。
  - フロンティア幅は4が主要。
  - wata版SAは `TL=2.95`, `T0=1e7`, `T1=1e6`。

## 落とし穴

- 一般の2点swapや2-optは簡単に隣接制約を壊す。安全な構造上のswapか、境界判定付きの近傍に限定する必要がある。
- `small` と `large` をそれぞれ連結にしても、`small` の末尾と `large` の末尾が隣接していないと `small + reverse(large)` は不正になる。
- 端列や折り返しを貪欲に使い切ると、後半で未訪問セルを回収できなくなる。
- 座標変換でスコア計算だけ変換後座標のまま行うと、元の `A` とずれてしまう。
- 入力に空間的な滑らかさはない。平滑化ポテンシャルだけに頼ると、本質的な人口順位の並べ替えが弱くなる。
- フロンティアDPは復元が難しい。DP値が正しくても、列内の具体的な通過順が誤るとWAになる。

## 未解決・要検証事項

- poisonkumaa のDP状態、焼きなまし温度、近傍比率はキャッシュ実装で確認済み。
- kaede2020 の最終提出コードはキャッシュ実装で確認済み。記事本文の平滑化/Warnsdorff試行は提出コードには残っていない。
- wata版フロンティアDPの枝刈り上位100とSA温度は、理論値というより提出用チューニングだと考えられる。
- 4行DPと区間移動SAを自前実装する場合、復元後の全ケース検証が必要である。
