## 解法の全体像

記事は、非常に単純なルールベースから始め、3分割ルールベース、最後にルールベースを未来方策として使うプレイアウト型モンテカルロへ発展させる構成である。

最終解法では、現在の実盤面に対して次の出力候補 `F/B/L/R` を1手だけ固定する。その後の未知の配置位置を乱数で複数生成し、以降の出力は高速な3分割ルールで決めて最後までシミュレーションする。各候補の平均最終スコアを比較し、最大の方向を出力する。

## 主要アイデア

- 次のキャンディの種類から、次に出現しやすい領域を制御する。
- 1種類だけを上下分割する単純ルールでも一定スコアになる。
- 3種類を上・左下・右下に分けるルールベースは盤面シミュレーションなしでも強い。
- モンテカルロでは、将来の出力を完全ランダムにせず、強いルールベースでプレイアウトする。
- プレイアウト数を固定値にして実装を単純化する。
- 盤面操作とスコア計算を高速化して、1ターンあたり多くの未来を試す。

## 最終コードの構造

### 状態表現

- `board`: `10 x 10` の `vector<vector<int>>`。0 が空き、1..3 が種類である。
- `types`: 100ターン分のキャンディ種類列。
- `last_fb`: 最後に出した上下方向の操作。`F/B` 以外なら `X`。
- `remaining_types`: 現在ターン以降の種類列。
- `remaining_positions`: プレイアウト用の未来配置番号列。

### 観測・制約・入力の扱い

- 各ターンで実際の `position_id` を読んだら `PlaceCandy` で現盤面に置く。
- プレイアウト中は、残り空き数 `j` に対して `1..j` の一様乱数を生成して未来の `p_t` とする。
- `last_fb` は、3分割ルールで上下に集まっているかを判定するために保持する。

### 評価関数

- `ComputeScore` は Union-Find で同種隣接マスを結合し、連結成分サイズ二乗和を求める。
- 分母は各種類の最終個数二乗和で、提出コードは公式スコア式どおり `round(1e6 * numerator / denominator)` を返す。

### 探索・構築・更新

- `ChooseActionGreedy(next_type, last_fb)` が3分割ルールで将来手を決める。
  - 次が type 1 なら `B`。
  - それ以外で直近上下が `F` でなければ `F`。
  - 直近上下が `F` なら、type 2 は `R`、type 3 は `L`。
- `RunPlayout` は、盤面コピーに対して乱数配置列を使って残りを最後まで進め、各配置後の操作は `ChooseActionGreedy` で決める。
- `ChooseActionByPlayouts` は、200本の `remaining_positions` を先に生成し、4方向それぞれについて全200本を走らせて合計スコア最大の方向を返す。

### 操作・クエリ・出力選択

実ターンでは、観測済みキャンディを置いた後、4方向をすべて候補として評価する。選んだ方向を実盤面にも適用し、`F/B` なら `last_fb` を更新して出力する。

### 時間配分・パラメータ

- リファクタリング後コードではプレイアウト数 `kPlayoutCount = 200` 固定。
- 実行時間管理はせず、盤面サイズと定数回数から2秒に収まるようにしている。
- 104M の単純上下分割、133M の3分割、157M のプレイアウト版という段階的な比較が記事に示されている。

## 実装上重要な断片

```text
choose_action_by_playouts(board, last_fb, remaining_types):
    random_position_sets = [sample_future_positions() for _ in 1..200]
    for first_dir in F,B,L,R:
        b = board.copy()
        execute(first_dir, b)
        lb = update_last_fb(last_fb, first_dir)
        total = 0
        for positions in random_position_sets:
            total += greedy_playout(b, lb, remaining_types, positions)
    return direction with max total
```

## この解法の本質

プレイアウトの質は、未来の方策に強く依存する。完全ランダムな未来手順では、候補方向の差よりランダムな悪手の影響が大きくなりやすい。ymatsux 解法は、短く強い3分割ルールを未来方策に使うことで、現在の1手が「まともに進めた場合の最終盤面」に与える影響を測っている。

## 真似するならまず実装する部分

3分割ルールベースを先に作るのがよい。これだけで高速なベースラインになり、プレイアウト中の未来操作にも使える。次に、固定200回程度の共有乱数プレイアウトで4方向比較を追加する。

## 注意点・未理解点

- 記事では本番コードそのものではなくリファクタリング後コードがリンクされている。構造は読めるが、本番時の細かい時間配分差は不明である。
- 固定200プレイアウトは環境依存で余裕が変わる。言語や実装が遅い場合は回数を下げる必要がある。
- `last_fb` の意味を誤ると、スイカ・パンプキンを左右へ分ける条件が崩れる。
