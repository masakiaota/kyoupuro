## 解法の全体像

前半から中盤は「2048 的に3種類を端へ寄せる」ルールベースで進める。最頻種類を右側へ寄せる対象にし、残り2種類を上下へ寄せるように、次のキャンディ種類と直前の左右移動の状態で方向を決める。

終盤だけは残り手数が少ないため、全ての配置可能性を列挙した期待値探索を行う。候補方向を1手固定し、その後は配置番号の全通りを平均し、操作側は最大スコアを選ぶ再帰で残りを解く。

## 主要アイデア

- 盤面を小さい「2048」と見て、同種を端に寄せて連結成分を太らせる。
- 100手全体の探索は無理なので、序盤は安いルールベースで形を作る。
- 最頻種類を一方向に固定的に集めると、最大成分を作りやすい。
- 終盤は空きマスが少ないため、未知 `p_t` の全通り平均と操作の全通り最大化を再帰で計算できる。
- 終盤探索の評価は最終スコア分子、つまり連結成分サイズ二乗和を使う。

## 最終コードの構造

### 状態表現

- `Input::fs`: 100個の種類列。
- `Input::candy_nums`: 各種類の総数。
- `Input::ps`: 観測済みの配置番号。
- `State::board`: `10 x 10` の盤面。
- `State::t`: 現在までに傾けた回数。
- `State::last`: 最後の設置位置。提出コードでは大きく利用されていない。
- `ok_flag`: 右寄せ対象に関する直前状態を持ち、上下動してよいかを表すフラグ。

### 観測・制約・入力の扱い

- 各ターンで `p_t` を読んで `apply_put` し、現在ターンの種類 `fs[t]` を空きマス番号に従って置く。
- `apply_move` は `F/B/L/R` ごとに全行・全列を詰める。
- 終盤探索では、次の配置番号 `p` を `1..残り空き数` で全列挙する。

### 評価関数

- `compute_score` は DFS で同種連結成分を列挙し、サイズ二乗和を返す。
- 分母は固定なので、探索中の比較では分子のみでよい。

### 探索・構築・更新

- `LAST_SEARCH_TURN = 93`。コード上は `ti <= 93` まではルールベース、`ti = 94..98` は再帰探索、最後はダミー方向である。
- ルールベース:
  - `target_candy` は最も数が多い種類。
  - 次が `target_candy` なら `L`。次の出現位置を右側へ作る意図である。
  - 直前に target 用の処理をした直後なら `R` で戻す。
  - それ以外で次が `second` なら `F`、残りなら `B`。
- 終盤探索:
  - `simulate` は現在盤面から4方向を試し、それぞれ `simulate_put` で期待値を評価する。
  - `simulate_put` は次の配置番号を全列挙し、各配置後に `simulate_move` を呼ぶ。
  - `simulate_move` は操作側の4方向最大を取る。最終直前ならスコアを返す。

### 操作・クエリ・出力選択

序盤はルールベースの方向を即出力する。終盤は `simulate(&st, &input)` の返す方向を出力する。出力後は必ず実盤面へ `apply_move` する。

### 時間配分・パラメータ

- ルールベースから終盤探索へ切り替える閾値は 93。
- 提出実行時間は 407ms 程度で、2秒に対して余裕がある。
- 終盤全探索は残り約6手の範囲に限定している。

## 実装上重要な断片

```text
simulate_move(state):
    if next placement is final:
        return component_square_sum(state)
    return max over dir:
        s = state.copy()
        s.move(dir)
        simulate_put(s)

simulate_put(state):
    total = 0
    for p in all empty positions by index:
        s = state.copy()
        s.put(p)
        total += simulate_move(s)
    return total / number_of_positions
```

## この解法の本質

大半の手では、将来のランダム性よりも「どの種類をどの端へ流すか」という粗い構造が重要である。一方、終盤は不確定性の分岐数が急に小さくなるため、期待値を直接計算できる。Gobi 解法は、粗い構造作りと終盤の厳密寄り探索を切り分けている。

## 真似するならまず実装する部分

最頻種類を一方向に寄せ、他2種類を上下に分けるルールベースを作る。その後、残り5手程度だけ `配置は平均、操作は最大` の再帰探索を追加するのが最小実装になる。

## 注意点・未理解点

- 提出コードの `simulate_put` はコメントでは「最も悪い値」とあるが、実装は配置全通りの平均に見える。また初期値が `usize::MAX` で、Rust のリリース実行では実質的に折り返しを含む。この意図は記事からは確定できなかった。
- 終盤探索はコピーが多いので、切り替えターンを早めると急に重くなる。
- ルールベースの種類割当は `target, second, third` の順序に依存し、種類数の偏りによって最適とは限らない。
