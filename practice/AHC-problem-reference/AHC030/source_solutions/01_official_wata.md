## 解法の全体像

この解説は、AHC030 を「隠れた油田配置を、ノイズ付き観測から推定する問題」として整理している。油田配置全体を状態 `x` と見なし、これまでの占い結果 `R` が得られたときの事後確率 `P(x | R)` をベイズの定理で扱う。

`M = 2` のように油田配置を全列挙できる場合は、全状態について尤度 `P(R | x)` を計算し、正規化して事後確率を得る。確率が十分高い配置が見つかれば、その配置から `v(i,j)>0` のマス集合を回答する。確信が足りなければ、相互情報量が大きいマス集合を追加で占う。

一方、一般の `M > 2` では状態数が概ね `N^(2M)` 規模になり、全列挙できない。そのため、対数尤度を目的関数とした焼き鈍しで尤度の高い配置を多数サンプリングし、得られた候補集合 `X'` 上で `M = 2` と同様に事後確率や相互情報量を近似する。

全体の流れは次の形になる。

```text
過去の占い結果 R を保持する
候補配置 X' を作る
各候補の対数尤度 log P(R | x) を計算する
候補上で事後確率 P(x | R) を近似する
十分確信できるなら回答する
そうでなければ相互情報量 / cost が大きい集合 S を占う
R に結果を追加して繰り返す
```

## 主要アイデア

### ベイズ推定

配置全体の集合を `X = {x1, x2, ...}` とする。これまでに占ったマス集合を `S1, ..., St`、結果を `R = (r1, ..., rt)` とする。知りたいのは `P(x | R)` である。

事前分布を一様と見ると、ベイズの定理から次の比例関係になる。

```text
P(x | R) proportional to P(R | x)
```

つまり、観測結果がその配置からどれくらい起きやすいか、すなわち尤度を評価すればよい。

### 尤度計算

`k` マス集合 `S` を占い、真の石油埋蔵量が `s = v_x(S)` のとき、占い結果が `r` となる確率を `q(k, s, r)` とする。この値は、問題文で定義された正規分布からサンプルされた値が丸め後に `r` になる確率であり、正規分布の累積分布関数で計算できる。

配置 `x` に対する尤度は次の積で表される。

```text
P(R | x) = product_i q(|Si|, v_x(Si), ri)
```

実装では積が極小になりやすいため、対数尤度を使う。

```text
log_likelihood(x) = sum_i log q(|Si|, v_x(Si), ri)
```

`q(k, s, r)` は何度も使うので、`k, s, r` ごとの値を前計算するのが自然である。

### 相互情報量による占いマス生成

次にどの集合 `S` を占うべきかは、「その観測によって事後分布の不確実性がどれだけ減るか」で評価する。解説ではエントロピーと相互情報量を使う。

占う前の配置分布 `P(x)` があるとする。集合 `S` を占った結果を確率変数 `Y` とすると、結果 `y` が出る確率は次で計算できる。

```text
P(y) = sum_x q(|S|, v_x(S), y) P(x)
```

結果 `y` が得られた後の事後分布もベイズ更新できる。

```text
P(x | y) proportional to q(|S|, v_x(S), y) P(x)
```

よって、占う前のエントロピー `H(X)` と占った後の期待エントロピーを比べれば、期待される情報量の増加を評価できる。この値は `X` と `Y` の相互情報量 `I(X;Y)` である。

AHC030 では占いコストが `1 / sqrt(|S|)` なので、評価値としては次のようにコスト当たりの相互情報量を見る。

```text
score(S) = I(X; Y) / cost(S)
         = I(X; Y) * sqrt(|S|)
```

すべてのマス集合を試すことはできないため、解説では `S` にマスを追加・削除する山登りで、相互情報量 / cost が大きくなる集合を探す方針が示されている。

### M > 2 への拡張

`M > 2` では全状態列挙が不可能になる。そこで、尤度の低い配置は事後確率計算や相互情報量計算への影響が小さいと考え、尤度の高い配置だけをサンプリングして候補集合 `X'` を作る。

解説で示されている方針は、対数尤度を目的関数とした焼き鈍しである。

```text
目的関数: log P(R | x)
候補状態: 各油田の配置位置
出力: 尤度の高い配置集合 X'
```

焼き鈍しで得た `X'` 上で、事後確率、回答判定、相互情報量による次クエリ選択を近似する。

## 実装に落とすなら必要な整理

### 状態

最低限、次の情報を持つ。

```text
shape[m]          : 油田 m の相対座標集合
placements[m]     : 油田 m の合法な左上位置一覧
state.pos[m]      : 状態における油田 m の配置 ID
queries[i]        : 過去に占った集合 Si と返値 ri
state.sum[i]      : 状態 x における v_x(Si)
state.log_like    : 過去クエリに対する対数尤度
```

最終回答に必要なのは配置そのものではなく `v(i,j)>0` のマス集合である。候補状態から全油田のマス集合を OR すれば回答候補を作れる。候補配置が複数残っていても、正マス集合が一致しているなら回答できる可能性が高い。

### 尤度

占い結果の確率は次のように計算する。

```text
mu = (k - s) * epsilon + s * (1 - epsilon)
sigma = sqrt(k * epsilon * (1 - epsilon))

if r == 0:
    q = Pr[X < 0.5]
else:
    q = Pr[r - 0.5 <= X < r + 0.5]
```

実装では `q` を小さい正値で下限クリップし、`log(q)` を使う。`q(k,s,r)` のテーブルを作ると焼き鈍しと相互情報量計算の両方で使い回せる。

### クエリ選択

候補集合 `X'` と重み `P(x)` があるとき、集合 `S` の評価は次の形で行う。

```text
evaluate(S):
    for each possible y:
        py = sum_x P(x) * q(|S|, v_x(S), y)
        posterior_y[x] = P(x) * q(|S|, v_x(S), y) / py
        hy = entropy(posterior_y)
    return (H_before - sum_y py * hy) * sqrt(|S|)
```

`S` の探索は、解説ではマスの追加・削除による山登りが示されている。実装するなら、追加、削除、入れ替えを近傍にして、候補状態ごとの `v_x(S)` を差分更新できる形にするとよい。

### 候補生成

焼き鈍しの状態は、各油田がどこに置かれているかの配列で持つ。解説に出ている近傍は次である。

```text
1. 1つの油田を上下左右に動かす
2. 1つの油田をランダムな合法位置に移動する
3. 2つの油田の位置をスワップする
```

高速化として、次のテーブルを前計算する方針が示されている。

```text
contrib[m][p][i] =
    油田 m を位置 p に置いたとき、
    過去に占った集合 Si に含まれる石油埋蔵量への寄与
```

これがあると、近傍で油田を 1 つ動かしたときに各 `Si` の埋蔵量を `O(t)` で更新できる。`t` は占い回数である。対数尤度の差分計算も `O(t)` になる。

## 実装上重要な断片

長いコードは参照元にないため、実装するときの短い疑似コードとして整理する。

```text
build_candidates():
    repeat until time limit:
        x = random_initial_state()
        anneal x with objective log_likelihood(x)
        store high-likelihood states
    remove duplicates
    normalize weights by logsumexp(log_likelihood)
```

```text
main_loop():
    candidates = build_candidates()
    if confident(candidates):
        answer positive_cells(best_or_consensus_state)
    S = hill_climb_query_set(candidates)
    r = ask(S)
    append (S, r)
```

```text
move_one_oilfield(state, m, new_pos):
    for each query i:
        old_s = state.sum[i]
        new_s = old_s
                - contrib[m][old_pos][i]
                + contrib[m][new_pos][i]
        state.log_like += logq[k_i][new_s][r_i] - logq[k_i][old_s][r_i]
        state.sum[i] = new_s
    state.pos[m] = new_pos
```

## この解法の本質

本質は、油田配置を確率分布として扱うことにある。占い結果から「もっともらしい配置」を 1 つ選ぶだけではなく、候補配置全体の事後分布を推定し、その分布をもっとも効率よく狭める占い集合を選ぶ。

ただし、`M > 2` では全分布を厳密に持てない。そのため、最後は高尤度配置をどれだけ取りこぼさずに集められるか、つまり焼き鈍しの性能が解法の強さを大きく左右する。公式解説も、推測ゲームに見えて結局は焼き鈍しの性能を競う問題だった、という趣旨で締めている。

## 真似するならまず実装する部分

まず実装すべきなのは、対数尤度で配置を評価できる基盤である。

1. 各油田の合法配置を列挙する。
2. `q(k,s,r)` と `log q(k,s,r)` を計算できるようにする。
3. 状態 `pos[m]` から、過去クエリに対する `v_x(Si)` と対数尤度を計算する。
4. 1 つの油田を動かす近傍で対数尤度を差分更新する。
5. 焼き鈍しで高尤度配置を複数集める。
6. 集めた候補上で重みを正規化し、最尤または合意した `v>0` 集合を回答する。

その後に、相互情報量によるクエリ集合 `S` の山登りを追加するのがよい。最初から相互情報量を完全実装しようとすると、候補生成が弱い場合に評価値自体が信用できなくなる。

## 注意点・未理解点

- 公式解説には最終コードやパラメータはない。焼き鈍しの温度、候補数、時間配分、回答閾値などは自分で設計・調整する必要がある。
- `q(k,s,r)` の計算では丸めと `max(0, round(x))` の扱いに注意する。特に `r=0` は下側が `-inf` 相当になる。
- 尤度の積はすぐにアンダーフローするため、必ず対数尤度と `logsumexp` で扱う。
- 相互情報量計算は候補集合 `X'` の品質に強く依存する。焼き鈍しが真の高尤度領域を取りこぼすと、よさそうに見えるクエリが実際には悪くなる。
- 問題の回答対象は配置ではなく `v(i,j)>0` の集合である。複数の配置候補が残っていても、正マス集合が同じなら回答可能である。
- 公式解説では 1 マス掘りの使い方は主題ではない。最終確認や高ノイズ時の補助としてどう組み込むかは別途検討が必要である。
