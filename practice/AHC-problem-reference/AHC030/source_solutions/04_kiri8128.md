## 解法の全体像

この解法は、油田配置全体を直接当てるのではなく、各油田が取り得る配置候補の直積を「潜在状態」とみなし、クエリ結果から状態の候補を削っていく方針である。候補状態を全部保持できるときは全列挙し、できないときはランダムサンプリングした状態集合で近似する。

クエリ選択では、候補集合に対する期待獲得情報量を評価し、情報量が大きいマス集合を占う。記事中では、厳密なベイズ事後分布を毎回更新するのは重いので、返答値ごとの状態数の偏りを使って情報量を近似している。提出コードでも、候補状態集合 `possible_states` を持ち、各クエリ候補について状態ごとの埋蔵量総和を数えて、エントロピー減少に相当する評価値を計算している。

最終的には、候補状態から各マスが油田に含まれる確率を集計し、十分確からしいマス集合を回答する。外した場合は、確率の高いマスから1マス掘りを行い、確定情報を増やして再回答する。

## 主要アイデア

- 各油田ごとに合法な配置を列挙し、その直積を状態とする。
- 状態数が小さい場合は全列挙、大きい場合はランダム状態で候補集合を作る。
- 既存クエリの結果と矛盾する状態を削る。
- 次の占いは、候補状態をよく分割できる集合を選ぶ。
- 期待獲得情報量を厳密に計算しきらず、候補状態上の返答分布のエントロピーで近似する。
- 最終回答後に失敗したら、候補上で油田確率が高いマスを掘って検証する。

## 最終コードの構造

### 状態表現

- `Polyomino` が油田形状を持つ。
- `possible_mino_positions[m]` が油田 `m` の合法配置一覧である。
- `possible_states` は「各油田の配置ID列」を並べた候補状態集合である。
- `mined` は1マス掘りで得た確定値を持つ。
- `queries` は複数マス占いの履歴を持つ。

候補状態は、各油田の位置IDを1つずつ持つだけでよい。状態から盤面の `v` を復元し、クエリ集合の総和や回答集合を計算する。

### 観測・制約の持ち方

1マス掘りは正確な制約なので、状態から復元した `v(cell)` が観測値と一致しなければ削除対象になる。

複数マス占いはノイズ付きなので、返値と真の総和が完全一致する必要はない。ただしKiri8128氏の実装は、候補削除ではある程度の許容幅を持つ近似的な判定をしている。厳密な尤度重みを持つというより、候補状態を「あり得る/薄い」に近い形で扱っている。

### 評価関数

クエリ候補 `S` に対して、各状態 `x` の真の総和 `s_x = v_x(S)` を計算する。その分布が偏りすぎていると、どの返答が来ても候補があまり減らない。逆に分布がよく割れていると情報量が大きい。

疑似コードは次の形である。

```text
score_query(S):
    count_by_sum = empty map
    for state in possible_states:
        s = sum_v(state, S)
        count_by_sum[s] += 1
    return entropy(count_by_sum)
```

実際の返答はノイズでぼけるので、返答値ごとの確率へ畳み込む方が自然だが、最小実装では「候補状態上で真値が散らばる集合」を選ぶだけでも効果がある。

### 探索・更新

候補状態集合が小さい場合は全列挙する。大きい場合は、各油田の配置IDをランダムに選んだ状態を多数生成する。クエリや掘りで候補を絞ったあと、候補が少なすぎる場合は再サンプリングする。

クエリ集合の探索は、全てのマス集合を見られないため、いくつかの候補集合を生成して評価する方式である。記事中では期待獲得情報量の最大化が中心だが、コードでは実装可能な範囲に落とし込まれている。

### クエリ選択

クエリ候補は、候補状態間で値が割れやすいマス集合から選ぶ。固定集合だけではなく、状態ごとの `v>0` 推定が分かれる部分を集めるとよい。

実装へ落とすなら、次の順で十分である。

```text
1. 候補状態から各マスの油田確率 p[cell] を計算する
2. p[cell] が 0.2 から 0.8 の範囲にあるマスを集める
3. その中からサイズ k の候補集合をランダム生成する
4. score_query(S) が最大のものを占う
```

### 回答判定

候補状態から各マスが油田である確率を計算する。確率が閾値を超えたマスを回答集合に入れる。失敗したら、高確率マスを掘って実測値を得る。これにより、誤った回答を何度も繰り返すよりは、情報を増やして候補を縮められる。

### 時間配分

記事では情報量評価に重い処理があり、提出コードも候補数・クエリ候補数を実行時間に合わせて制限している。実装上は、1ターンで候補状態の更新とクエリ探索に使う時間を固定し、終盤は回答と検証に寄せるのが安全である。

## 実装上重要な断片

候補状態から回答集合を作る処理は重要である。

```text
estimate_answer(possible_states):
    oil_count[cell] = 0
    for state in possible_states:
        covered = union of placements in state
        for cell in covered:
            oil_count[cell] += 1
    return { cell | oil_count[cell] / len(possible_states) >= threshold }
```

また、候補集合を使ったクエリ評価は次のように最小化できる。

```text
choose_query():
    best = none
    for trial in 0..T:
        S = random uncertain cells
        score = entropy of sum_v(state, S) over possible_states
        update best
    return best.S
```

この2つを入れるだけで、固定パターン占いよりは「候補を分けるための占い」になり、`solution.md` の相互情報量方針に近づく。

## この解法の本質

本質は、状態候補を「解空間の近似」として明示的に持ち、その候補集合を最も割る観測を選ぶことである。完全なベイズ重みがなくても、候補状態上での返答分布を使えば、情報量最大化の実装版になる。

また、最終回答は最尤状態だけでなく、候補集合上のマスごとの確率から作る点が重要である。配置が一意に絞れていなくても、`v>0` の集合が高確率で一致していれば回答できる。

## 真似するならまず実装する部分

1. 各油田の合法配置を列挙する。
2. ランダム状態集合 `possible_states` を作る。
3. 1マス掘りと複数マス占いの履歴で状態をフィルタする。
4. 候補状態上で各マスの油田確率を出す。
5. 油田確率が割れているマスからランダムなクエリ候補を作り、総和分布のエントロピーが大きいものを占う。
6. 確率閾値で回答し、失敗時は高確率または不確実なマスを掘る。

## 注意点・未理解点

- 提出コードは比較的長く、すべてのパラメータ調整意図までは読み切れていない。
- ノイズ付き占いを厳密な正規分布尤度で扱うというより、候補削除・情報量近似に寄せている部分がある。
- この方針は候補状態集合の質に強く依存する。ランダム状態が真の近傍を含まないと、回答確率もクエリ評価もずれる。
- 状態数が大きいケースでは、単純ランダムだけでなく、観測に合う状態を再サンプリングする仕組みが必要である。
