## 解法の全体像

焼きなましではなく、乱択初期値からの貪欲構築を時間いっぱい繰り返す。目標は、基本的に異なる色の大きな単色クラスタを2個作ることである。密な盤面では1色だけを大きくする場合もある。異なる色の PC はクラスタ内で接続しない。

1回の貪欲では、クラスタの初期値として1点、または異なる色の2点を乱択で選ぶ。既存クラスタと同色で、まだクラスタに属していない PC を1個選び、クラスタの見える位置まで移動させて接続する。この「取り込み」をできなくなるまで繰り返す。2色を選んだ場合は、おおよそ交互に取り込む。

取り込み対象と移動先は、多始点ダイクストラで決める。クラスタ内の PC や既存ケーブル上から直線方向へ初期コストを伸ばし、その初期コストを起点に盤面上を探索する。他色 PC を通る経路には退避コスト相当のペナルティを乗せる。経路上に邪魔な PC があれば、予約済みでない空白へ BFS で退避させる。退避先が無ければ、再帰的に別の PC を先に退避させる多段退避を行う。

## 主要アイデア

- 単色クラスタだけを作り、異色混入による負点を避ける。
- 1色だけでなく2色の巨大クラスタを同時に育てる。
- 乱択初期値から貪欲を100から1000回程度繰り返し、最良解を採用する。
- クラスタ拡張は「同色 PC をクラスタへ移動させて接続する」取り込み操作に分解する。
- 取り込み対象選択は多始点ダイクストラで、移動距離と邪魔 PC 数のトレードオフを評価する。
- 既存ケーブル上にもコスト0の接続候補を置き、ケーブルを分割して PC を挟み込めるようにする。
- 邪魔な PC は BFS で空白へ退避する。
- 退避できない PC は、その隣接 PC を先に退避させる再帰的な多段退避で処理する。
- 多段退避の深さ上限は最終的に5程度。提出コードでは `ESCAPE_DEPTH_LIMIT = 3`、`ESCAPE_LEVEL_LIMIT = 5` から 6、`TO_ESCAPE_LIMIT = 5` が使われている。

## 最終コードの構造

Browserで AtCoder 提出 `34095139` を読んだ。以下は記事本文と提出コードから確認できた実装構造である。

### 状態表現

- `state.colors`: 各セルの PC 種類。空は負値で扱う。
- `state.moves`: 出力用の移動列。`push_move` / `pop_move` で盤面と同期する。
- `state.lines`: 現在採用している接続線分。`push_line` で `online` を更新する。
- `state.online`: 既存ケーブルまたは接続済みセルを通れないようにする予約情報。
- `dijkstra::costs`, `dijkstra::frm`: 多始点ダイクストラの距離と復元元。
- `reserved`: 取り込み操作中の移動経路・接続予定セル。
- `bfs_escape`: 予約セル上の邪魔 PC を空きセルへ退避する処理。
- `best_st`: 時間内に得た最高スコア状態。

### 観測・制約・入力の扱い

- 入力盤面から種類ごとに PC を100個ずつ管理する。
- 接続は同色クラスタ内だけで行うため、スコア計算はクラスタサイズの組数に近い形になる。
- 接続予定の線分と移動経路上のセルは予約済みとし、邪魔 PC を退避させる。
- 予約済みでない空白セルを退避先にする。
- まだ実際には線を張っていない予定線分上は、移動や退避の通過点として使える場合がある。この扱いがスコア改善に効いたとされる。
- 操作回数 `moves + connections` が `100K` に達したら貪欲を終了する。

### 評価関数

- 各貪欲試行の最終評価は問題本来のスコア。
- 単色クラスタだけを作るので、サイズ `s` のクラスタはおおむね `s(s-1)/2` 点を生む。
- 取り込み候補選択の内部コストは、移動距離と邪魔な他色 PC の数を足したもの。
- 記事では説明図の比率は `移動コスト:他色コスト = 1:10`、提出コードで良かった比率は `10:14` とされている。
- 他色 PC コストは、後で退避する平均手数を先取りした近似である。

### 探索・構築・更新

- 1回の貪欲試行:
  - 初期クラスタを1点または2点乱択で選ぶ。
  - 2点の場合は異なる色を選び、交互に取り込みを試みる。
  - 取り込み不能または手数上限まで繰り返す。
- 取り込み:
  - クラスタ内 PC と既存ケーブル線分から、同一行・列に初期コストを割り当てる。
  - 初期コスト付きセルを始点として多始点ダイクストラを行う。
  - 最小コストで到達した同色・未所属 PC を取り込み対象にする。
  - `t -> m` の移動経路と、`s <-> m` の接続線分を復元する。
  - 経路・線分を予約済みにする。
  - 予約セル上の邪魔 PC を退避させる。
  - 対象 PC を目的地へ移動し、接続を追加する。
- 多段退避:
  - 邪魔 PC を直接空白へ動かせなければ、隣接4方向の PC を先に退避できるか再帰で試す。
  - 子の退避が成功したら、空いた位置へ親 PC をスライドさせる。
  - 深さ上限まで失敗したら、その取り込み候補を諦める。
- ダイクストラ内で取り込み試行を早期に行い、成功したら探索を打ち切る高速化が入っている。

### 操作・クエリ・出力選択

- 出力は、貪欲で確定した移動列と接続列をそのまま使う。
- 既存ケーブル上のセルを目的地にした場合、元のケーブル1本を2本に分割して、取り込んだ PC を挟む。
- 退避操作も移動列に追加するため、取り込み操作では対象 PC だけでなく邪魔 PC の移動順序も管理する。
- 複数試行のうち、本来スコアが最も高い出力を採用する。

### 時間配分・パラメータ

- 3秒間、乱択初期値の貪欲を繰り返す。
- 手元環境では100から1000回程度の試行が可能だったとされる。
- 他色 PC 通過コストは最終的に移動コスト10に対して14程度。
- 多段退避の深さ上限は5程度。
- 疎な盤面では2点初期値の優先度を高めると良かったとされる。

## 実装上重要な断片

```text
greedy_trial():
    clusters = choose one seed or two different-color seeds
    while ops < 100*K:
        c = choose cluster to expand
        if not absorb_one(c):
            mark c as blocked
        if all clusters blocked:
            break
    return moves, connections, score
```

```text
absorb_one(cluster):
    initialize dist from rays of cluster computers and cable cells
    run dijkstra with costs:
        step_cost = 10
        other_color_penalty = 14

    for target in increasing dist order:
        restore move path t->m and connection line s-m
        reserve their cells
        if evacuate_all_obstacles(reserved, depth_limit=5):
            move target to m
            add or split connection
            return true
    return false
```

```text
evacuate(pc, depth):
    if depth == limit:
        return false
    if bfs_to_free_cell(pc, forbidden=reserved):
        move pc along path
        return true
    for neighbor in adjacent occupied cells:
        if evacuate(neighbor, depth + 1):
            move pc into neighbor's old cell
            return true
    return false
```

## この解法の本質

この解法の本質は、難しい全体最適化を「1個の PC を既存クラスタへ取り込む」操作に落とした点である。クラスタを大きくするたびに得点増加が大きくなるため、局所的な取り込み操作でも高スコアに届く。

また、多始点ダイクストラの初期コスト設計が重要である。単に PC から PC への最短路を探すのではなく、「クラスタから直線接続できる任意の位置」を目的地候補にすることで、接続可能性と移動コストを同じ探索で扱っている。既存ケーブルを分割して PC を挿入できるようにした点も、木としてクラスタを伸ばす問題設定に合っている。

多段退避は、密な盤面を局所的なスライドパズルとして解く仕組みである。退避先が直接見つからないときに諦めず、邪魔 PC の周囲を再帰的に空けることで、密度が高いケースにも貪欲が届くようになる。

## 真似するならまず実装する部分

まずは移動なしで同色の見える PC をつなぐクラスタ構築を作る。次に、1つのクラスタに対して、多始点 BFS またはダイクストラで最も近い同色 PC を取り込む処理を実装する。

最初は他色 PC を通行不能にし、退避なしでよい。動いたら、他色 PC に大きいペナルティを付けて通過を許し、経路上の邪魔 PC を単段 BFS で退避する。最後に多段退避、ケーブル分割、2色交互拡張、乱択初期値の多試行を足すのがよい。

## 注意点・未理解点

- 実装は読めたが、退避探索の打ち切り値や `ESCAPE_LEVEL_LIMIT` の変更条件などは経験的な調整で、本文だけからは導けない。
- ケーブル交差判定と、線分上セルを移動に使えるタイミングの管理が壊れやすい。
- 多段退避は少ない行数で書けたとされるが、失敗時の巻き戻しと出力順序管理を雑にすると WA になる。
- 取り込み候補を低コスト順に試すだけでは、後続クラスタの成長を邪魔する可能性がある。2色交互拡張と乱択初期値でこの弱さを補っている。
- 密な盤面では1色を大きくする方が良い場合もあるため、常に2色戦略が最適とは限らない。
- パラメータ、特に他色コストと多段退避深さへの依存が大きい。
