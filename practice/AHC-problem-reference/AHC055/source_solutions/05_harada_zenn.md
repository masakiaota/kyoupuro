## 解法の全体像

焼きなましやビームサーチを使わない純貪欲である。手持ち武器がなければ、硬さが最小の未開封宝箱を素手で開けて武器を得る。手持ち武器があれば、キューから武器を1回分取り出し、未開封宝箱の中から評価値が最大のものを攻撃する。攻撃で宝箱が開けば、その宝箱の武器を使用可能キューへ追加する。これを全宝箱が開くまで繰り返す。

評価値は単純なダメージ量から出発し、最後に残りやすい宝箱を優先する補正を加えている。記事では、宝箱 `t` に対して将来使える武器の総攻撃力が小さいほど最後に残りやすいと観察し、そのような宝箱を今狙いやすくする式を採用している。提出コードでは、残り武器の二乗ダメージ和を定数で割って `A[key][box]` から引き、値が大きい箱を選ぶ。

## 主要アイデア

- 手持ち武器がないときは、最小 `H` の宝箱を素手で開けて選択肢を増やす。
- 手持ち武器は FIFO キューで管理する。
- 武器1回ごとに、未開封宝箱を評価値で並べ、最大のものを攻撃する。
- 単純評価 `min(H[t], A[w][t])` では、有効な武器が少ない宝箱が最後に残りやすい。
- 残り武器の `Σ C_i A[i][t]^2` が小さい宝箱を優先する補正を入れる。
- 補正用の除数 `D` を乱数化し、時間いっぱい複数解を作って最良を出す。
- 提出コードでは `mt19937 mt(0)` を使い、1950 ms まで試行を繰り返す。

## 最終コードの構造

### 状態表現

- `Input`: `N`, `H`, `C`, `A` を持つ構造体。
- `input`: 各試行中に破壊状況や耐久値を更新する作業用状態。
- `input_copy`: 初期状態を保持し、試行ごとにコピーする。
- `remaining_keys`: 利用可能な武器を1耐久回数ずつ入れる `queue<int>`。
- `remaining_boxes`: 未開封宝箱数。
- `ans`: 試行中の攻撃列。
- `best_ans`, `best_score`: 最良攻撃列とスコア。

### 観測・制約・入力の扱い

- `H[i] <= 0` の宝箱は開封済みとして扱う。
- 手持ち武器が空なら、`get_minH_id` で未開封かつ硬さ最小の宝箱を選び、素手攻撃を硬さ回数ぶん出す。
- 宝箱が開くと、その宝箱の残り `C[box]` 回数ぶんを `remaining_keys` に push する。
- 武器攻撃するたびに `input.C[key]--` する。

### 評価関数

- 記事の最終形は `S(t) = min(H[t], A[w][t] - (Σ_{i in B} C_i A[i][t]^2) / D)` という趣旨である。
- 提出コードでは、未開封宝箱 `i` ごとに `remaining_key_sum[i] = Σ_j A[j][i]^2 * C[j]` を計算する。
- 各候補箱の値は `val = min(H[i], A[key][i] - remaining_key_sum[i] / div)`。
- `div` は `4000`, `5000`, `6000` のいずれかを疑似乱数で選ぶ。
- `remaining_key_sum` が小さい宝箱ほど減点が小さく、狙われやすい。

### 探索・構築・更新

- 1950 ms まで同じ貪欲構築を繰り返す。
- 各試行で初期状態へ戻し、`remaining_keys` と `ans` を空にする。
- 手持ち武器が空なら最小硬さ宝箱を素手で開ける。
- 手持ち武器がある間、武器を1回分 pop し、未開封宝箱の評価値を全計算して最大を攻撃する。
- 攻撃で宝箱が開いたら、その宝箱の武器をキューへ追加する。
- 提出コードでは、記事にある「一定確率で2番目の候補を選ぶ」分岐が `iter != 0` 条件で無効化されているように見える。`iter` は初期化後に更新されていないためである。
- ランダム性は主に `div` の選択から入っている。

### 操作・クエリ・出力選択

- 各試行で実際に `ans` に攻撃列を積む。
- 素手は `(-1, box)` を硬さ回数ぶん追加する。
- 武器攻撃は `(key, box)` を1回追加し、硬さを `A[key][box]` 減らす。
- 全宝箱を開けたら `sum_H - ans.size() + 1` をスコアとして、最良なら保持する。
- 最後に `best_ans` をそのまま出力する。

### 時間配分・パラメータ

- 時間制限 2 sec に対して 1950 ms で打ち切る。
- 補正除数 `div` は 4000, 5000, 6000。
- 記事では一定確率で2番目を選ぶ、`D` を乱数にする、時間いっぱい最良を出すと説明されている。
- 提出コードの top2 選択分岐は実質無効で、除数乱数だけが効いている可能性が高い。

## 実装上重要な断片

```text
while remaining_boxes > 0:
    if weapon_queue is empty:
        b = unopened box with minimum H
        output H[b] hand attacks
        open b and push weapon b C[b] times

    while weapon_queue is not empty:
        w = pop weapon_queue
        for each unopened box b:
            future = sum_x A[x][b]^2 * C[x]
            value[b] = min(H[b], A[w][b] - future / D)
        b = argmax value
        output attack w -> b
        update H[b], C[w]
        if b opened:
            push weapon b C[b] times
```

## この解法の本質

純貪欲でありながら、最後に残る宝箱の性質を評価値に入れている点が本質である。高ダメージを今使うだけでは、代替攻撃が少ない宝箱が放置され、終盤に素手で大量に殴ることになる。そこで「将来その宝箱を攻撃できる総力」を補正として使い、残りにくい宝箱より残りやすい宝箱を優先する。実装は単純だが、評価値が問題の失点構造を捉えている。

## 真似するならまず実装する部分

最小硬さを素手で開け、手持ち武器キューで貪欲に攻撃する骨格を作る。最初は `min(H[b], A[w][b])` 最大でよい。その後、宝箱ごとの `Σ C_i A[i][b]^2` 補正を入れ、`D` を複数試す。DAG 割当や焼きなましより実装が短く、出力列を直接作るため WA になりにくい。

## 注意点・未理解点

- 記事本文と提出コードに差があり、提出コードでは top2 選択の乱択が無効化されているように見える。
- `remaining_key_sum` はコード上、現在キューにある武器だけではなく、未使用耐久を持つ全武器に近い値で計算されている。記事の「残っている武器集合」と完全に同じかは解釈が必要である。
- FIFO キューなので、強い武器の使う順序までは最適化していない。
- 純貪欲は局所的で、DAG 割当型に比べると後から攻撃配分を組み替えられない。
