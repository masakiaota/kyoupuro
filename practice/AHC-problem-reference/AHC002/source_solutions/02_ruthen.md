## 解法の全体像

固定順 DFS で初期経路を作り、その経路の 2 点を選んで間を別経路でつなぎ直す焼きなましを行う。最初は単純 DFS と小さな経路変形から入り、最終的には、座標の 1 次元化、移動可能隣接リストの前計算、探索方向の両向き化、温度や削除距離などのハイパーパラメータ調整でスコアを上げている。

この解法は thunder の記事と同じ巨大近傍系だが、実装面では `cst_ps` と `nst_ps` という現在状態と候補状態の座標列を明示し、近傍評価を「2 点間の再接続」としてかなり直接的に書いている。

## 主要アイデア

- 初期解生成では探索順をランダムにせず、方向の偏りで遠くまで伸びることを期待する。
- 経路から 1 点だけ選ぶ再接続より、2 点を選んでその間を作り直す方が、削除した中間マスを再利用できて密な経路を作りやすい。
- 経路状態は移動方向列よりも実際に通った座標列で持つ方が近傍実装が楽になる。
- 隣接候補を前計算し、再接続 DFS では隣接方向の順列を前計算したリストからランダムに選ぶ。
- 2 点間再接続では、片方向だけでなく逆方向からも探索し、DFS の浅い分岐に引っ張られる偏りを減らす。
- 最終的な上積みは、定数倍改善よりも `T0/T1/D_MAX/DFS_MAX_CALL` の調整の寄与が大きいと整理している。

## 最終コードの構造

### 状態表現

- 座標は `x * 50 + y` 型の 1 次元整数で保存する。
- `t` と `p` は 2500 要素の配列として読み込む。
- `adj[pos]` に、その座標からタイル制約上移動可能な隣接座標を持つ。
- `fac[k]` に長さ `k` の順列を全列挙し、DFS 中の探索順をランダムに選ぶ。
- `cst_score/cst_ps` が現在解、`nst_score/nst_ps` が候補解である。

### 観測・制約・入力の扱い

- 入力時にタイル ID の最大値からタイル数 `M` を求める。
- 隣接リストは、盤面内かつ移動元と移動先のタイル ID が異なるものだけを入れる。
- 近傍生成時は、選んだ 2 点間以外のタイルを訪問済みとし、間のタイルだけ再利用可能にする。
- 既訪問タイルへ進もうとした場合でも、それが再接続先の端点なら成功扱いにする。

### 評価関数

- 最終評価は通過マスの得点合計。
- 初期段階では DFS で見つけた最大スコア経路を採用する。
- 焼きなましでは `exp((nst_score - cst_score) / T)` で候補を受理する。
- 記事の考察では、2 点再接続の優位性を「削除した中間部分の空間を使って高密度な経路にできるから」と説明している。

### 探索・構築・更新

- `init_dfs()` は 100 ms 程度だけ DFS し、見つかった最良経路を初期解にする。
- `update()` で `mi < mj` を選び、`mj - mi <= D_MAX` に制限する。
- 区間外の座標を固定し、固定部分の得点を `constant_score` として持つ。
- DFS は `DFS_MAX_CALL` 回で打ち切る。
- DFS が端点へ到達すると、`nst_ps = prefix + new_middle + suffix` を作る。
- `solve()` は制限時間まで温度を線形に下げつつ、100 回に 1 回程度温度を更新する。

### 操作・クエリ・出力選択

- 最終的な `cst_ps` の隣接差分を `D/R/U/L` に変換して出力する。
- 採用しない候補は `nst_ps` のみ破棄し、`cst_ps` は維持する。

### 時間配分・パラメータ

- 最終コードは `TL = 1950 ms`、初期 DFS 用に `TL1 = 100 ms` を使う。
- 最終パラメータは `T0 = 180`、`T1 = 2`、`D_MAX = 40`、`DFS_MAX_CALL = 800`。
- `#pragma GCC target("avx2")`、`O3`、`unroll-loops` も最終提出に入っている。
- 記事では温度を `T0 = 150, T1 = 0` に寄せた段階と、さらに上記パラメータへ調整した段階で大きく改善している。

## 実装上重要な断片

```text
update():
    mi, mj = choose two indices with mj - mi <= D_MAX
    tile = visited tiles outside (mi, mj)
    constant_score = score outside (mi, mj)

    if random:
        dfs(from cst_ps[mi], target cst_ps[mj], rev=false)
    else:
        dfs(from cst_ps[mj], target cst_ps[mi], rev=true)

    when target is reached:
        nst_score = constant_score + middle_score
        nst_ps = prefix + middle_path + suffix
```

`fac` による順列前計算は小さいが効く実装要素である。毎回 `shuffle` する代わりに、隣接数に応じた順列をランダムに選べる。

## この解法の本質

状態依存で単純な手変更ができない問題でも、経路を座標列として持てば「2 点間だけを再計算する」近傍に落とし込める。改善の本質は、全体を壊さず、依存関係が閉じる短い区間だけを作り直すことだ。記事はさらに、近傍の強さだけでなく、状態表現とハイパーパラメータが最終スコアに強く影響することを示している。

## 真似するならまず実装する部分

座標列で状態を持ち、固定順 DFS で初期解を作る。次に `mi, mj` を選んで区間外を固定し、区間内を DFS でつなぎ直す山登り版を作る。焼きなまし温度、両向き DFS、1 次元化、順列前計算はその後に足す。

## 注意点・未理解点

- 記事中の「ビーム幅」的な初期実験や途中提出は最終コードには残っていないものもある。
- 最終提出ではかなりテンプレートやマクロが多い。核心は `init_dfs`、`update`、`solve` に集中している。
- 記事では初期解の探索順を固定する方がよいと述べているが、これは乱択 DFS の偏りや盤面生成に依存する可能性がある。
- ハイパーパラメータはローカル評価に強く依存しており、他環境で同じ値が最適とは限らない。
