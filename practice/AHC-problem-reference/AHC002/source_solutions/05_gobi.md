## 解法の全体像

盤面を 10x10 マスのブロックに分け、5x5 個のブロックのうち 24 ブロックを通る巡回路を固定する。現在いるブロック内でだけ細かい経路を探索し、巡回路上の次ブロックへ到達したらそのブロックの探索を終了する。ブロック内の経路は得点合計を評価値にしたビームサーチで決める。

スタート地点が不定でも、ブロック単位の巡回路に乗せれば同じ処理で全体を回れる。右下の 1 ブロックは巡回路から外れるが、その上または左のブロックを通るときだけ侵入を許す工夫が入っている。

## 主要アイデア

- 全盤面を一気に探索すると局所的に詰まりやすいため、先に大域的な通行順を固定する。
- 10x10 ブロックを 5x5 = 25 個作り、そのうち 24 個を巡回路にする。
- 各局面では、現在ブロック内、通過済みブロック、または右下ブロックへの一部侵入だけを許す。
- 次ブロックへ入ったら、そのブロックを目標としてビームを進める。
- ブロック内では獲得スコアを評価値にする単純なビームサーチを使う。
- 実装負荷を下げるため、スタートブロックを巡回路上の位置として扱う。

## 最終コードの構造

### 状態表現

- Rust コードでは `Input` に `sij`、タイル配列 `t`、得点配列 `p` を持つ。
- ブロックサイズは `BLOCK_SIZE = 10`。
- `State` は現在位置、移動文字列、訪問済みタイル、スコアを持つ。
- ビームサーチは状態配列を展開し、スコアで並べて上位だけを残す。
- ブロック巡回路は `Block` と方向列のような形で固定パターンとして管理される。

### 観測・制約・入力の扱い

- 各移動候補は盤面内、未訪問タイル、許可されたブロック領域内であることを確認する。
- 同じタイルを 2 回踏まないように、タイル ID を訪問済み集合で管理する。
- 現在ブロックから巡回路上の次ブロックへ到達したら、次段階へ進む。
- 通過済みブロックへの侵入も許すことで、境界付近の詰まりを少し緩和する。

### 評価関数

- ビームの評価は基本的に得点合計。
- 大域的な「どこへ向かうか」は評価関数ではなく、ブロック巡回路の制約として与える。
- そのため、ビームは局所的に得点を稼ぎつつ、目標ブロックに入るまでの経路を探す役割になる。

### 探索・構築・更新

- まずスタート地点が属するブロックを求め、巡回路上の位置に合わせる。
- 各ブロックについて、現在の状態集合をビームとして持つ。
- 合法な上下左右移動を展開し、スコア順に上位 `BEAM_WIDTH` 個を残す。
- 次ブロックへ到達した状態を見つけたら、その中からよい状態を選んで次のブロック処理へ移る。
- 右下ブロックは通常の巡回路から外れるが、隣接ブロックを処理中に侵入可能にする。

### 操作・クエリ・出力選択

- 最終的に保持している移動列をそのまま出力する。
- ブロック巡回路をすべて処理するか、ビームが尽きた時点で得られた最良経路が回答になる。

### 時間配分・パラメータ

- 記事本文ではビーム幅 1,200 と説明されている。
- 提出コードの定数では `BEAM_WIDTH = 1000` が確認できた。記事とコードに差があるため、最終提出時点の実値はコード側を優先して見る。
- ブロックサイズは 10。
- 巡回路は 24 ブロックを使う。

## 実装上重要な断片

```text
for block in circular_block_order_from_start:
    next_block = successor(block)
    beam = current_states
    while beam not empty:
        candidates = []
        for state in beam:
            for move in UDLR:
                if legal_tile and allowed_block:
                    candidates.push(state + move)
        reached = states that entered next_block
        if reached not empty:
            current_states = best reached states
            break
        beam = top_by_score(candidates, BEAM_WIDTH)
```

この方法では、局所探索の評価関数よりも、ブロックレベルの通行制約が大域的な品質を支えている。

## この解法の本質

大域的な自己交差や閉じ込めを評価関数で直接扱うのではなく、最初から大域ルートを固定してしまう構築型の解法である。ビームサーチは全盤面を自由に進むためではなく、固定された回遊計画の中で各ブロックをなるべく高得点に通るために使う。評価関数を複雑にせず、制約設計で探索空間を絞るのが本質である。

## 真似するならまず実装する部分

5x5 ブロック上の巡回路を手で固定し、現在ブロック内だけを許すビームサーチを作る。右下ブロックへの侵入や通過済みブロックへの侵入は後回しでよい。最初はビーム幅も小さくし、ブロックをまたぐ判定が正しいかを可視化で確認するのがよい。

## 注意点・未理解点

- 記事本文のビーム幅 1,200 と提出コードの `BEAM_WIDTH = 1000` に差がある。
- ブロック境界で同じ 2 マスタイルを踏む可能性があり、タイル ID ベースの訪問判定を徹底しないと WA になる。
- ブロック単位の制約が強いため、高得点マスが隣にあっても取りに行けないことがある。
- 5x5 のうち 1 ブロックを巡回路から外す設計なので、その補完処理の良し悪しがスコアに影響する。
