## 解法の全体像

まず制約を満たす初期経路を DFS で作る。その後、現在の経路から連続部分を一度削除し、削除区間の両端を DFS でつなぎ直す。この大きな近傍を山登り法または焼きなまし法で繰り返し評価し、スコアが上がる、または温度に応じて許容される場合に経路を置き換える。

最終版では、つなぎ直し DFS の始点と終点を 50% で反転し、さらに焼きなましの遷移条件 `diff > temp * log(random)` を先に計算して、部分 DFS が閾値を超えた時点で打ち切る。近傍の多様化と近傍評価の高速化が主な上積みになっている。

## 主要アイデア

- 経路全体を操作列ではなく、訪問座標列として持つ。
- 単純に 1 手を変更すると後続手順が壊れるため、連続部分経路を削除して両端を再接続する巨大近傍にする。
- 削除区間外のタイルは訪問済みとして固定し、削除区間内だけを未訪問に戻す。
- 再接続は DFS で行い、削除前より高得点な部分経路、または焼きなまし条件を満たす部分経路を探す。
- つなぐ方向をランダムに反転し、DFS の探索順依存による偏りを緩和する。
- 焼きなましの受理判定を対数形に変形し、必要閾値を近傍生成前に決めて早期終了に使う。

## 最終コードの構造

### 状態表現

- 座標は `coord = y * 50 + x` の 1 次元整数で持つ。
- `tiles[coord]` はその座標のタイル ID、`points[coord]` は得点を表す。
- `next_coords[coord]` に、盤面内かつ別タイルである隣接座標を前計算する。
- `DfsSolver` は初期経路探索用で、訪問済みタイル、現在パス、ベストパス、現在スコアを持つ。
- `DfsPartSolver` は部分経路の再接続用で、固定済みタイルを受け取り、始点から終点までの候補経路を DFS する。
- `State` は現在採用している座標列 `now_path_` を持つ。

### 観測・制約・入力の扱い

- 入力後に全マスのタイル ID と得点を 1 次元配列へ格納する。
- 同じタイル内への移動はそもそも隣接候補に入れない。
- 経路の実行時制約は、タイル ID 単位の `visiteds` で管理する。
- 部分再接続では、削除区間外のタイルを訪問済みとして固定する。終点は既存経路上の固定点なので、訪問済みであっても「そこへ到達したか」は別判定する。

### 評価関数

- 最終スコアは訪問座標の `points` 合計である。
- 近傍評価では、削除区間外の定数部分は再計算せず、削除された部分の得点 `now_score` と、新しく DFS で作った部分の得点 `next_score` の差 `diff = next_score - now_score` だけを見る。
- 焼きなましでは、温度 `temp` に対して `diff > temp * log(random)` を満たせば受理する。

### 探索・構築・更新

- 初期解は、制限回数付き DFS で合法な経路を作る。
- 各反復で削除区間長を `now_path_.size() * 0.05` 程度までの乱数から選ぶ。
- 区間 `[start_path_id + 1, end_path_id - 1]` を削除対象にし、そのタイルだけ未訪問へ戻す。
- `remaining_search_cnt = 4 * delete_path_length` 程度で部分 DFS の探索量を制限する。
- 50% の確率で `start -> end` と `end -> start` を入れ替える。
- 部分 DFS が受理閾値を超える経路を見つけたら、前半、再接続部分、後半を連結して現在経路にする。

### 操作・クエリ・出力選択

- 出力直前に座標列の隣接差分を `U/D/L/R` に変換する。
- 終了時に持っている `now_path_` が回答である。別途ベスト解を保存する構造ではなく、焼きなましで採用された現在解を出力する。

### 時間配分・パラメータ

- 最終提出では制限時間を 1950 ms としている。
- 焼きなまし温度は `start_temp = 150` から `end_temp = 0` へ線形に下げる。
- 削除区間長は現在経路長の約 5% まで。
- 部分 DFS の探索回数は削除長の約 4 倍。
- 乱択は固定シードの `mt19937` を使う。

## 実装上重要な断片

```text
make_neighbor(path):
    choose l, r
    visited = tiles outside (l, r)
    old = score of path[l+1:r]
    threshold = old + temp * log(rand)

    if rand < 0.5:
        sub = dfs_connect(path[l], path[r], visited, threshold)
    else:
        sub = reverse(dfs_connect(path[r], path[l], visited, threshold))

    if sub exists and score(sub) - old > temp * log(rand):
        path = path[:l+1] + sub + path[r:]
```

実装上の要点は、削除区間外のタイル固定、終点だけは訪問済みでも到達判定対象にすること、採用時に `visiteds` と経路列を同時に更新することだ。

## この解法の本質

この問題は、操作列の一部だけを変えると後続の合法性が崩れる。そこで「合法性が壊れる範囲」を連続部分経路に限定し、その範囲を丸ごと作り直す。状態依存の強い一人ゲームでも、固定する部分と再探索する部分を分ければ、局所探索や焼きなましの形に持ち込めるという点が本質である。

## 真似するならまず実装する部分

まずは座標列、タイル訪問フラグ、スコア計算を作り、DFS で合法な初期経路を得る。次に、経路から短い連続区間を削除し、両端を DFS で再接続して改善したら採用する山登り版を作る。焼きなまし、逆向き探索、閾値による早期打ち切りはその後に足すのがよい。

## 注意点・未理解点

- 削除区間の端点の扱いを誤ると、終点へ戻れず近傍がほとんど成立しない。
- `visiteds` をコピーする実装は分かりやすいが、反復回数を稼ぐにはコピー量と DFS 回数のバランスが効く。
- 初期 DFS の経路品質が低すぎると、再接続近傍だけでは伸びにくい可能性がある。
