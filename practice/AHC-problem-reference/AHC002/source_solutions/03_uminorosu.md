## 解法の全体像

ランダムに進めるだけ進み、詰まったら数手戻る探索を繰り返して初期解を作る。その初期解に対して、現在経路の一部を壊し、壊した長さ分ランダムに動いてから接続先へ向かう形でつなぎ直す焼きなましを行う。

経路破壊の位置選択にも工夫があり、改善できた場所の近辺にはまだ改善余地があるとみなして、次もその付近を壊す。逆に改善できない場所はすでに詰まっていると考え、避ける。

## 主要アイデア

- 初期解はランダムウォークだけでなく、詰まったら数手巻き戻して探索を続ける。
- 初期解の評価は `得点合計 + 経路長 * 300` とし、焼きなまし前の素材として長い経路を重視する。
- 初期解生成を 200 ms 回し、評価値が最も高いものを採用する。
- 近傍は経路の長さ 1 から 30 程度の区間を壊してつなぎ直す。
- 壊す長さは時間とともに短くする。
- つなぎ直せた候補への遷移判断は、序盤は経路長またはスコア、終盤はスコアのみを重視する。
- 遷移がしばらく起きない場合、前回遷移が起きた温度付近まで再加熱する。

### 状態表現

- 現在の経路を座標列または移動列として持つ。
- 各状態には訪問済みタイル集合、現在スコア、経路長が必要である。
- 焼きなましでは、破壊した区間、つなぎ直し後の区間、現在の破壊候補位置を管理していると推測できる。

### 観測・制約・入力の扱い

- タイル ID 単位で訪問済み判定を行う。
- 初期解生成と焼きなましのつなぎ直しの両方で、進める方向だけを候補にする。
- 破壊した区間のタイルは再利用可能に戻し、それ以外は固定済みとして扱う必要がある。

### 評価関数

- 初期解評価は `score + path_length * 300`。
- 焼きなましの最終評価は本来のスコア合計。
- 序盤の遷移では長さも評価に入れ、終盤では最終スコアを優先する。
- 初期温度は、つなぎ直し成功時の遷移確率が約 50% になるように設定したと説明されている。

### 探索・構築・更新

- 初期解:
  - ランダムに合法手を選んで進む。
  - 行き止まりになったら数手巻き戻す。
  - しばらく評価改善がない場合は、スタートから作り直す。
- 焼きなまし:
  - 現在経路から長さ 1 から 30 程度の区間を選んで壊す。
  - 序盤ほど長め、終盤ほど短めの区間を壊す。
  - 壊した長さ分適当に動き、その後つなぎ先へ近づく。
  - 接続できない候補は棄却する。
  - 改善した場合、その付近を次の破壊候補として優先する。

### 操作・クエリ・出力選択

- 制限時間いっぱいまで焼きなましを回し、最後に保持している経路を出力する方針だと読める。
- 経路の端、つまりスタートと反対側の点は固定していたと書かれている。

### 時間配分・パラメータ

- 初期解生成に 200 ms。
- 壊す区間長は 1 から 30 程度。
- 冷却は実行時間に対して線形。
- 非線形冷却も試したが、線形がよかったと書かれている。
- しばらく遷移がないときに再加熱する。
- ローカルでは 6000 ms 程度回さないとジャッジサーバーの点数に追いつかないという速度差の観察がある。

## 実装上重要な断片

```text
make_initial():
    repeat for 200 ms:
        path = random_walk_with_backtrack()
        value = score(path) + 300 * len(path)
        keep best by value

anneal(path):
    while time remains:
        length = shrink_over_time(1..30)
        center = choose_position(prefer around last improved position)
        broken = remove_segment(path, center, length)
        middle = random_steps_then_head_to_goal(broken)
        if connected:
            accept by early length/score, late score
        if accepted:
            next center = around improved segment
```

## この解法の本質

最終スコアだけでなく、焼きなましの素材としての「伸びしろ」を初期解で作る点が重要である。長い経路は後から部分的に組み替える余地があるため、初期段階で経路長を評価に入れるのは合理的である。また、改善した場所の近辺を継続して壊すという選択は、局所的な未整理領域を集中的に整える考え方である。

## 真似するならまず実装する部分

まず `score + 300 * path_length` で評価するランダムウォーク + 巻き戻し初期解を作る。次に、固定長 10 程度の区間破壊と単純な再接続を作り、改善したら採用する。時間で破壊長を短くする処理や再加熱は、その後に追加する。
