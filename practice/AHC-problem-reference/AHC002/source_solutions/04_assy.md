## 解法の全体像

時間いっぱい DFS を繰り返し、探索順の評価関数を軽く改善してスコアを伸ばす方針である。点数の高いマスを優先するよりも、盤面を詰まらせず長いパスを作ることを重視し、外周や角を先に埋めるような探索順を試している。

途中から、毎回最初から深く DFS するのではなく、現時点のベスト経路の途中地点を選び、そこまでを固定して残りを再探索する形にしている。これは完全な焼きなましではないが、経路の後半を作り直す局所再探索として機能している。

読めた提出コードは記事内容とほぼ一致する。最終版は再帰DFSで候補手を幾何評価順に並べ、ベスト経路の先頭90%以内のランダム地点までを固定して、そこから1手だけ別方向へ外して1ms DFSを繰り返す実装である。

## 主要アイデア

- 生スコアを評価値にしたビームサーチは、長い経路を作る目的には合いにくいと判断している。
- 次に踏むタイルに隣接する使用済みマス数が多い順に DFS すると、隙間を詰める効果を狙える。
- さらに単純化して、外周からの距離を評価値にし、外周を先に埋める順序で DFS する。
- `min(x, 49-x, y, 49-y)` から `min(x,49-x) * min(y,49-y)`、さらにその 2 乗へと評価値を変え、隅をより強く優先する。
- DFS 1 回の時間を短くし、ベスト経路の途中から何度も再探索することで試行回数を増やす。
- 評価値は O(1) で計算できる軽いものに限定し、再探索回数を稼ぐ。

## 最終コードの構造

提出 #22073884 の実装に基づく構造である。

### 状態表現

- `t[50][50]`: タイルID。
- `p[50][50]`: 得点。
- `single[50][50]`: そのタイルが単独マスかどうか。
- `opp[50][50]`: 2マスタイルの場合の相方座標。`reach/unreach` で相方も訪問済みにする。
- `used[50][50]`: タイル訪問済み状態。2マスタイルは相方も同時に立てる。
- DFSノードは `(y, x, prev_dir, score, eval)`。
- `best_score`, `best_command`: 現在までの最高スコアと移動文字列。
- `c_command`: DFS中の現在移動文字列。

### 観測・制約・入力の扱い

- DFS の各遷移で、盤面内、隣接マス、未訪問タイルを満たす手だけを候補にする。
- 使用済みタイル集合を再帰 DFS の push/pop で更新する。
- 再探索時には、選んだ途中地点までの経路に含まれるタイルを訪問済みにしてから DFS を始める必要がある。

### 評価関数

- 回答の評価は得点合計。
- DFSの候補順評価は `go()` で計算する。

```text
v = min(y, 49-y) * min(x, 49-x)
eval = 10000000 - v^2
```

- 候補は `eval` 降順にソートするため、外周、特に隅寄りのマスを先に踏む。
- 記事初期案では「次に踏むタイルに隣接する使用済みマス数」も使っている。

### 探索・構築・更新

- 初回は開始地点から1msだけDFSして初期ベストを作る。
- 以降は総時間1950msまで以下を繰り返す。
  - `best_command.size() * 90 / 100` 未満のランダム位置 `r` を選ぶ。
  - 開始地点から `best_command` のprefixを辿って訪問済みを復元する。
  - `r` 以降で、元の進行方向以外に合法手があればランダムに1手外す。なければ元の進行方向を進む。
  - その地点から1ms DFSする。
- DFSは候補手を `go()` の評価順に並べ、再帰で深く潜る。
- ベスト更新はDFS中に `cn.score > best_score` なら即座に行う。

### 操作・クエリ・出力選択

- 制限時間内に見つかったベスト経路を出力する。
- 経路の途中から再探索した結果がベストを更新すれば、次回以降の固定 prefix の元になる。

### 時間配分・パラメータ

- 提出 #22073884 では、各DFSの制限は `end_time = 1` ms。
- 外側ループは実測時間が1950msを超えるまで回す。
- 再探索地点は `best_command` の先頭90%以内からランダムに選ぶ。
- 記事中の提出3ではDFS 1回を100ms、提出4では3ms、提出5以降では1ms。
- 再探索地点の範囲はパス長の 8 割から 9 割へ変更。
- 探索順評価は最終的に `(min(x, 49-x) * min(y, 49-y))^2`。

## 実装上重要な断片

```text
repeat until time limit:
    base = best_path prefix up to random index in first 90%
    visited = tiles in base
    dfs_from(base.back()):
        candidates = legal_neighbors sorted by priority(x, y)
        recurse in that order
        update best_path by real score
```

この実装では、優先度計算を重くしすぎると DFS 回数が減る。O(1) の座標関数に絞る判断が実装上の要点である。

## この解法の本質

AHC002 では、短期的に高得点マスを拾うより、盤面を広く長く歩ける形にする方が重要である。この解法は、外周や隅を早く処理するという単純な幾何的ヒューリスティックで「閉じ込め」を減らし、さらに途中からの再探索で後半の悪い分岐を何度も作り直している。

## 真似するならまず実装する部分

再帰 DFS と訪問済みタイルの push/pop をまず作る。次に候補手を `(min(x,49-x) * min(y,49-y))^2` の昇順で並べる。最後に、見つかったベスト経路の途中までを固定して、残りを短時間 DFS で再探索するループを足す。

## 注意点・未理解点

- Browserで提出 #22073884 を読めたため、ベスト更新条件、時間計測、再帰の打ち切り位置は実装上確認済みである。
- 「外周から埋める」評価は盤面生成の性質に合っているが、全 seed で必ず強いとは限らない。
- 部分改善を最初から諦めていたと反省しており、最終スコアは焼きなまし系の上位解法より低い。
- 再探索 prefix の固定処理を誤ると、タイル再訪 WA になりやすい。
