## 問題の本質

AHC002 は、正の得点を持つマスをできるだけ多く踏む経路探索である。ただし制約はマス単位ではなくタイル ID 単位であり、1x2 や 2x1 の同一タイルの片割れにも入れない。全得点が非負なので、短期的には高得点マスを拾いたくなるが、本質的には「後で行ける領域を塞がず、長く広く歩く」ことが重要である。

もう一つの本質は、解が前の移動履歴に強く依存する点である。操作列の 1 手を変えると、それ以降の全手が合法でなくなる。そのため、通常の swap 近傍のような小変更は使いにくい。上位解法はこの依存性を、連続区間を丸ごと作り直すか、そもそも大域的な通行順を固定することで扱っている。

## 共通している考え方

どの解法も、高得点マスだけを貪欲に拾うのではなく、行き止まりを避けて広く歩くことを重視している。DFS 系は探索順で閉じ込めを避け、焼きなまし系は既存経路の局所的な悪さを作り直し、ブロックビーム系は大域ルートを固定して詰まりを抑える。

状態表現では、タイル ID 単位の訪問管理が必須である。また、経路を移動文字列ではなく座標列として持つと、途中地点の固定、区間削除、再接続、出力変換を分けやすい。上位の焼きなまし系はこの恩恵が特に大きい。

## 解法の分類

- DFS 探索順型: assy。軽量な候補順序と短時間再探索でスコアを上げる。
- 区間破壊・再接続型: thunder、ruthen、uminorosu。経路の一部を壊して合法に作り直す。
- 焼きなまし型: thunder、ruthen、uminorosu。悪化遷移も許しながら再接続近傍を探索する。
- ブロック巡回構築型: gobi、sansaqua。盤面をメタブロックへ分け、全体の通行順を先に固定する。
- ビームサーチ型: gobi、sansaqua。ブロック内の局所経路をビームで構築する。

## 推奨して理解すべき順序

1. assy の DFS 方針を読み、なぜ「長く歩く」「詰まらせない」ことが重要かを掴む。
2. thunder または ruthen の 2 点再接続近傍を読み、状態依存のある経路をどう局所探索へ落とすかを理解する。
3. uminorosu の初期解評価と再加熱を読み、焼きなましの素材作りと安定化の発想を見る。
4. gobi のブロック巡回ビームを読み、評価関数でなく制約設計で大域ルートを作る方法を理解する。
5. sansaqua のコードを読み、ブロック巡回型を高めるための状態圧縮、メタパス、ビーム幅管理を見る。

## 実装するならどのルートか

理解のための最小実装なら、assy 型の DFS が最も始めやすい。訪問済みタイル、座標列、探索順評価、ベスト更新だけで動く。次に、ベスト経路の途中までを固定して後半を再探索する処理を足せば、AHC002 らしい依存性の扱いも学べる。

上位化を狙うなら、thunder/ruthen 型の区間再接続焼きなましを実装するのがよい。最初は山登りでよく、短い区間を削除して両端を DFS でつなぎ直すだけでよい。そこから温度、削除長、DFS 回数、逆向き探索、隣接前計算を順に足す。

ブロック巡回ビームは、焼きなましの近傍設計が難しいときの別ルートである。10x10 ブロックの巡回順を固定し、各ブロック内でビームを走らせる。実装はやや重いが、方針が可視化しやすく、局所評価を単純にできる。

## 重要な実装要素

- 状態表現: 座標列、スコア、訪問済みタイル集合を基本にする。出力文字列は最後に変換する。
- 評価関数: 最終評価は得点合計。初期解や探索順では経路長、外周距離、隅優先などの補助評価を使う。
- 近傍: 焼きなましでは連続区間を削除し、区間外を固定して両端を再接続する。
- 差分更新: 削除区間の得点と新しい中間経路の得点差だけを評価する。
- 候補管理: DFS では隣接候補順、ビームではスコア順上位、焼きなましでは温度付き受理を管理する。
- 出力判定: 座標差分が上下左右 1 手になっているか、同じタイルを再訪していないかを最後まで保つ。
- パラメータ: 制限時間、初期 DFS 時間、削除区間最大長、部分 DFS 回数、温度、ビーム幅が効く。

## 落とし穴

- 同じタイルの別マスへ移るのも禁止である。マス訪問済みではなくタイル訪問済みで判定する。
- 部分再接続で、削除区間外を訪問済みに戻し忘れると WA になる。
- 再接続先の端点は固定経路上にあるため、通常の訪問済み判定だけだと到達できない。終点だけは特別扱いが必要である。
- 高得点マス優先の貪欲や生スコアだけのビームは、序盤で行き止まりになりやすい。
- ビーム幅を大きくしても、大域的な通行計画がないと同じ領域で詰まる。
- ブロック巡回では、ブロック境界をまたぐ 2 マスタイルの扱いを誤りやすい。
- 乱択焼きなましは seed や実行環境速度で上振れ下振れが出る。

## 未解決・要検証事項

- uminorosu の最終コードがないため、つなぎ直しの具体的な実装、再加熱式、破壊位置選択の詳細は再現できない。
- assy の本番最終コードは提出 #22073884 をBrowserで読めたため、DFS の打ち切り、ベスト更新、途中再探索の実装は確認済みである。
- gobi の記事本文ではビーム幅 1,200 と説明されている一方、読めた提出コードには `BEAM_WIDTH = 1000` がある。
- sansaqua の記事本文のビーム幅 8000 の説明と、提出コード中の 6000 切りの対応は完全には確認できていない。
- thunder/ruthen 型の最適パラメータは実行環境に依存しやすく、現在のコンパイラやマシンで再調整が必要である。
