## 解法の全体像

各都市の存在範囲を長方形ではなく凸多角形として管理し、クエリ応答から得られる距離不等式で多角形を削る。クエリ前半は面積削減を重視し、範囲の大きい都市1つと範囲の小さい都市2つを組にして、広い都市の候補範囲を削る。後半は近い都市間の距離情報を重視し、後のグループ分け・MST構築に効く辺順序を集める。

クエリ後は、得られた距離不等式を「近い辺から遠い辺へのDAG」とみなし、トポロジカルソート風に全都市対の距離順を並べる。その順位をコストとして使い、初期グループを作った後、近い2グループをマージして再分割する操作を制限時間まで繰り返す。

## 主要アイデア

- 都市の候補範囲を凸多角形で持ち、重心を暫定座標として使う。
- MST応答から2種類の不等式を生成する。
- 不等式の関係する3都市について、多角形内のサンプル点を削除し、残りの凸包を新しい候補範囲にする。
- クエリ前半は、面積の大きい都市を小さい都市で挟むような3点セットを作り、候補範囲削減を狙う。
- クエリ後半は、まだ近距離情報が足りない大きな都市を始点に、近い都市を集める。
- 距離大小関係をDAGとして管理し、入次数0の都市対を重心距離順priority queueで取り出して距離順を作る。
- グループ改善は、2グループを合わせた集合を最遠点対から2つの木に伸ばし直す。

## 最終コードの構造

以下は公式本文由来の整理を含む。今回のキャッシュ #64370691 は簡易ベースラインであり、公式解説の高度な実装とは別物として扱う。

### 状態表現

- 都市候補範囲
  - 各都市を凸多角形として持つ。
  - 1点として扱う場合は多角形の重心を使う。
  - 多角形の頂点数は概ね10程度以下と説明されている。
- 距離不等式
  - `d(a,b) <= d(c,d)` の有向制約。
  - 都市対をノード、近い側から遠い側へ辺を張るDAGとして扱う。
- クエリ管理
  - 前半の大都市・小都市選択履歴。
  - 後半の始点選択履歴。
  - 既に「より始点に近い都市が分かっている」都市を飛ばすための情報。
- グループ状態
  - 各グループの都市集合。
  - グループ重心。
  - 距離順位から割り当てたコスト表。

### 観測・制約・入力の扱い

- クエリ応答のMSTから、各頂点 `v` について2種類の不等式を記録する。
  - `v` の隣接頂点 `u_i,u_j` に対し、`d(v,u_i) <= d(u_i,u_j)` と `d(v,u_j) <= d(u_i,u_j)`。
  - `v` を根と見たとき、隣接頂点 `u` 側の部分木内都市 `c` に対し、`d(v,u) <= d(v,c)`。
- 不等式に関わる3都市について、多角形内に一様ランダム点を生成し、既存頂点と合わせて候補点集合を作る。
- 不等式を満たす相手候補が存在しない点を削除し、残った点の凸包を新しい多角形にする。
- 全点が消える場合は重心1点にフォールバックする。

### 評価関数

- 多角形削減:
  - 明示的なスコア式ではなく、不等式を満たしうる点だけ残すことで面積を減らす。
  - 前半クエリでは都市範囲の面積を基準に、大きい都市を優先して削る。
- クエリ前半:
  - 大きな都市との距離が比較的小さい小都市を選ぶ。
  - 小都市同士の距離が大都市との距離より小さい組を優先する。これにより、大都市から小都市への2辺が両方MSTに入って削れないケースを避ける。
- 都市間距離ソート:
  - 制約DAGの入次数0都市対を、重心距離が小さい順に取り出す。
  - 取り出し順を距離順位とし、`1,2,...` のコストに割り当てる。
- グループ改善:
  - 距離順位コストの和を小さくする。

### 探索・構築・更新

- 多角形更新
  - 各多角形のバウンディングボックス内で最大100回点を生成し、多角形内に入った点を採用する。
  - 多角形頂点と合わせて20点まで使う。
  - 3都市の候補点について全探索し、不等式を満たす組がない点を削る。
- クエリ前半
  - クエリ作成ごとに都市を面積でソートする。
  - 小さい都市側を4割、大きい都市側を5割程度に分ける。
  - 未使用の大きな都市を1つ選び、近い小都市の隣接ペアから条件を満たすものを入れる。
  - 100クエリを上限とし、集合を埋められなければ後半へ移る。
- クエリ後半
  - まだ始点にしていない大きな都市を選ぶ。
  - 重心距離で近い都市を `L` 個まで入れる。
  - 既により近い都市が判明している都市は候補から飛ばす。
- 距離順構築
  - 都市対を全てノードにする。
  - 不等式 `short <= long` を有向辺として張る。
  - 入次数0の都市対を重心距離priority queueへ入れる。
  - 取り出した都市対の出辺を消し、新たに入次数0になった都市対を追加する。
- グループ分け
  - 初期解は、辞書順で未使用都市を選び、そこから近い順に要求サイズまで取る。
  - 制限時間まで、近い2グループを選んで改善する。
  - 2グループの合併集合から、座標上で最遠の都市対を2木の始点にする。
  - グループサイズの割り当て2通りを試し、距離順位コストの小さい方を採用する。
  - priority queueで、既に木に入った都市から残り都市への最小コスト辺を伸ばす。

### 操作・クエリ・出力選択

- クエリ前半は最大100回程度を面積削減に使う。
- それ以降は近距離情報の獲得に寄せる。
- クエリ後、距離順位を確定し、グループ分けを改善する。
- 各グループ内の道路は、距離順位コストで作った木を出力する構造と読める。

### 時間配分・パラメータ

- 前半クエリは100回上限。
- 多角形サンプル点は頂点と合わせて20点まで。
- バウンディングボックス内のランダム点生成は100回上限。
- 面積ソート時、小さい都市4割・大きい都市5割を使う。
- 小都市候補は、大きな都市からの距離で上位1/4程度に制限する。
- グループ改善は制限時間まで反復する。

## この解法の本質

この解法の本質は、都市の不確実性を単なる中心点ではなく「まだあり得る凸領域」として保持し、クエリで領域そのものを削る点である。連続的な座標推定を直接最適化するのではなく、不等式を満たせない候補点を消して凸包を作り直すため、更新が幾何的に分かりやすい。

もう1つの本質は、絶対距離を推定しきらず、距離順位を作って構築へ渡す点である。問題の最終出力はMSTや近辺選択が中心なので、短い順序がある程度正しければ、厳密な距離値がなくてもグループ分けを改善できる。

## 真似するならまず実装する部分

まずは各都市を長方形の4頂点からなる凸多角形として持ち、クエリ応答から `d(v,u) <= d(v,c)` 型の制約で候補点を削る処理を作るとよい。ランダム点を少数足し、残点の凸包に更新するだけでも公式方針の核を試せる。

次に、不等式DAGによる都市対ソートを実装し、距離順位コストで初期グループを作る。上位化するなら、前半・後半でクエリ目的を分け、2グループ再分割の局所探索を追加する。

## 注意点・未理解点

- 公式解説にはコードがないため、凸包更新、DAGにサイクルがある場合の処理、グループ内道路の最終作成細部は推測を含む。
- 不等式を満たす候補点が全て消えた場合に重心1点へ潰す処理は頑健だが、誤った制約やサンプル不足で過剰に範囲を狭める危険がある。
- 多角形内サンプル20点は軽い反面、細い候補領域を見落とす可能性がある。
- 都市対DAGは距離同値や矛盾制約でサイクルを含む可能性がある。記事からはその扱いを完全には確認できない。
- 距離順位をそのままコストにすると、近辺の微小差と遠辺の大差を同じ順位差として扱うため、絶対長の近似には限界がある。
