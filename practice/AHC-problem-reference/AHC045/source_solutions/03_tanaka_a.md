## 実装キャッシュで確認した内容

- `CitySample` が矩形内の代表点サンプルと確率を持ち、クエリで得た MST の隣接関係から sigmoid 制約で候補点確率を更新する。
- `updateByAdj2` は頂点 `u` と隣接2本 `a,b` から `dist(a,b)-dist(a,u)` などの不等式を使う。`updateByAdj1` は親子関係の片側制約で、確率を正規化しつつ有望矩形を分割する。
- `CityManager.query` は同一クエリをキャッシュし、返った辺を accepted、クエリ内全ペアを oracled として履歴へ保存する。`reestimate(3,TL)` で履歴を再生して座標推定をやり直す。
- 初期推定は `L/W/M` に応じて有効化する。大きめのケースでは x/y で並べたチャンクを占い、小さいケースでは高誤差都市の近傍だけを占う。
- 道路長は中心距離に不確実性由来の `sqrt(error^2+error^2)*0.30` を足す。比較では占い済み・採用済み情報も使う。
- 本体は推定座標の完全グラフ MST から始め、必要なら `ImproveSolver` でグループ/木近傍を占って MST 辺を置換し、`Dividor` が MST を指定サイズへ分割する。
- `Tree.divideByLen` は長い辺を切る候補を上位から選び、サイズ DP で分割する。失敗時は farthest-corner 起点の `divideForce` で修復する。
- 時間定数は `TL1=800`, `TL20=1500`, `TL21=1300`, `TL3=1800` ms。`L<=4 && M<=150` では初期推定・前後占いを切るなど、ケース分岐が強い。

## 解法の全体像

解法は段階的に育っている。最初は、都市を長方形中心に置き、指定グループサイズ順にプリム法でグループを作る。次に、できたグループ内の部分木を占い、返ってきたMSTで辺を置き換えることで、少なくともその部分木を改善する。

中盤では、全都市のMSTを作り、そこから辺を切って要求サイズのグループを作る方針へ寄せる。単純に木を切るだけでは分割不能なケースが多いため、DPで切れるかを判定し、失敗時は部分木を破壊して強制的に二分割し、それぞれでMSTを作り直す。

さらに、分割前の全体MSTに対して先に占いを使い、グループ分け前の距離情報を改善する。都市位置推定は、各長方形を粗い4領域に分け、占い結果由来の距離関係に対する尤度でサンプリング・細分化する。最後は、`L` や `M` に応じて占い回数を位置推定・全体MST改善・グループ内MST改善へ配分し、時間が余るグループ分け処理をランダム化して繰り返す。

## 主要アイデア

- まず成立する貪欲解を作り、占い・位置推定・分割改善を段階的に足す。
- グループ内の部分木を占うと、同じ頂点集合のMSTが返るため、その部分木は確実に改善できる。
- 全体MSTからグループを切り出すことで、極端に長い辺が残る問題を抑える。
- 木から要求サイズの部分木を切れるかはDPで判定し、復元で割り当てる。
- 分割不能時は「嘘解法」と割り切り、木を壊して都合よく二分割しMSTを作り直す。
- グループ分け前に全体MSTを占って改善し、より正しい距離情報で分割する。
- 都市位置は連続座標を直接高精度に推定せず、長方形を4分割した候補領域の尤度として粗視化する。
- `L` や `M` によって、位置推定に占いを使うか、MST改善に占いを使うかを切り替える。
- 誤差が大きい都市の接続にはペナルティを与え、サイズ1グループや次数1に寄せる。

## 最終コードの構造

以下は本文由来の整理を含む。提出 #64614584 の実装差分は上の「実装キャッシュで確認した内容」を優先する。

### 状態表現

- 都市情報
  - 入力長方形、中心座標。
  - 位置推定用の候補領域。初期は長方形を2x2に割った4領域で、それぞれ中心点と尤度を持つ。
  - 推定分散または誤差指標。後段の距離ペナルティに使う。
- 木・グループ情報
  - 全都市MSTまたは改善済み全体木。
  - 各グループの頂点集合と木辺。
  - 木を切るDP用に、部分木サイズと要求グループサイズ集合の到達可能性を持つ。
- 占い管理
  - 既に投げたクエリ集合。重複クエリを避ける。
  - 占い回数の配分。位置推定、全体MST改善、グループ内MST改善の3箇所で消費する。

### 観測・制約・入力の扱い

- 初期距離は長方形中心間距離を使う。
- 占いで得たMSTは、対象部分木や全体MST内の辺置換に使う。
- 位置推定では、MSTの隣接構造から次のような距離関係を使う。
  - 都市 `P` に隣接する `A,B` について、`dist(P,A)` と `dist(P,B)` は `dist(A,B)` 以下になりやすい。
  - `P` から見た部分木内の都市 `X` について、`dist(P,A)` は `dist(P,X)` 以下になりやすい。
- これらの関係を厳密な成立判定ではなく、距離差にシグモイドをかけた尤度として扱う。
- 同一クエリは再利用しない。記事ではこれだけで追加改善があったとされている。

### 評価関数

- プリム法・MST構築:
  - 中心または推定座標の距離を基本にする。
  - 終盤の改善では、両端都市の推定誤差を距離にペナルティとして加える。
- 位置推定:
  - 候補領域の中心点を仮座標とし、占いから得た距離関係がどれだけ自然かを尤度にする。
  - 距離差をシグモイドで0から1程度の値に変換し、尤度比で候補を選び直す。
- 分割処理:
  - 全体木から要求サイズに切れるなら、その分割を採用する。
  - 分割不能時は強制二分割後のMSTコストを使う。
- 実行条件調整:
  - 3000ケース規模で、占い回数をどのステップに配分すると良いかを比較する。
  - `L<=6` では全体MST改善寄り、`L>=7` では位置推定寄りが強い傾向。
  - `L=3` かつ `M` が小さめならグループ内MST改善の価値も上がる。

### 探索・構築・更新

- 初期グループ構築
  - 残っている都市のうち中心から遠い都市を起点にする。
  - 指定サイズに達するまでプリム法で近い都市を追加する。
  - グループを入力順に作る。
- グループ内占い改善
  - 既存グループ内の部分木から `L` 以下の頂点集合を選んで占う。
  - 返ってきたMST辺で、その部分木の辺を置換する。
  - `L` 以下のグループは1回占うと最適MSTが確定するため重複して占わない。
- 全体MST分割
  - 全都市でMSTを作る。
  - 木辺を切ったときに要求サイズ集合へ割り当てられるかをDPで判定する。
  - 成功すればそのまま分割し、失敗した部分は木を壊して二分割後にMSTを再構築する。
- 位置推定
  - 各都市の長方形を4分割し等確率候補にする。
  - 1都市に着目し、他都市の候補を固定したときの距離関係尤度を計算する。
  - 尤度比で候補を再サンプリングする。
  - 尤度差が大きければ、その候補領域をさらに4分割する。
- 終盤の時間活用
  - 分割で見る辺長順を一部ランダムにシャッフルする。
  - 制限時間まで分割処理を繰り返し、良いものを採用する。
  - 分割失敗時の強制分割処理を高速化し、反復回数を増やす。

### 操作・クエリ・出力選択

- 占いは3種類の用途に分かれる。
  - `Step.1`: 都市位置推定。
  - `Step.3`: 全体MST改善。
  - `Step.5`: グループ分け後のMST改善。
- `L` と `M` に応じて、実行するステップやクエリ配分を切り替える。
- 最終出力は、分割済みグループと各グループ内の木辺で構成する。

### 時間配分・パラメータ

- 位置推定のサンプリング数・更新回数は数回程度に制限する。
- 占い配分は3000ケース実験で傾向を見て決める。
- 終盤はグループ分けの分割処理を制限時間まで反復する。
- `L` が小さい場合は推定より全体MST改善やグループ内改善を重視する。
- 誤差ペナルティの係数は本文に具体値がない。チューニング依存と考えられる。

## 実装上重要な断片

```text
build_initial_groups:
    unused = all cities
    for each required size g:
        root = farthest city among unused
        group = Prim(root, g, distance=center_distance)
        remove group from unused

split_global_tree:
    mst = build MST over all cities
    if subtree sizes can match required G by DP:
        cut restored edges
    else:
        destroy failed subtree
        force split into two parts
        rebuild MST in each part

estimate_city_position:
    candidates = 4 cells in rectangle
    repeat small number of times:
        for city v:
            evaluate likelihood of each cell from distance relations
            resample by likelihood ratio
            if likelihood gap is large:
                subdivide selected cell into 4 cells
```

## この解法の本質

この解法の本質は、複雑な問題を「位置推定」「全体MST改善」「木の分割」「グループ内MST改善」に分け、各部分を完璧にせず積み上げている点である。特に、全体MSTから切るという自主制約により、グループ分けを難しい容量付きクラスタリングから木DPと局所的な再構築へ落としている。

位置推定も、連続最適化ではなく4分割領域の尤度比較として粗視化している。これは上位解法ほど精密ではないが、実装量と時間を抑えつつ、誤差が大きい都市を扱うための分散情報まで得られる。

## 真似するならまず実装する部分

最初に作るべきは、中心距離で全体MSTを作り、要求サイズで切れるかを木DPで判定し、失敗時は強制二分割してMSTを作り直す構築である。これだけで長すぎる辺を減らす基本形になる。

次に、グループ内の `L` 以下の部分木を占って辺を置き換える処理を足す。位置推定は最後でよく、まずは4分割候補と距離関係尤度の粗い版だけ実装するとよい。

## 注意点・未理解点

- 記事本文だけでは DP 状態や距離ペナルティ係数は推測だったが、提出 #64614584 で上記の実装を確認できた。
- 全体MSTから切る方針は構成できる解を強く制限する。分割不能時の再構築が弱いとスコアが崩れる。
- 位置推定の尤度は距離関係をシグモイド化する経験的なもので、式や係数は記事から読み取れない。
- `L`・`M` によるステップ切替は実験ベースであり、生成分布や時間制限が変わると最適配分も変わる。
- グループ内占い改善は分かりやすいが、占い対象を誤ると既に十分良い小領域にクエリを使いすぎる。
