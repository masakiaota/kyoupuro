## 解法の全体像

64から8個程度の座標サンプルを持ち、クエリで得たMST辺から「この辺はこの辺以下」という不等式制約を生成する。各サンプルの各都市座標をランダムウォークと勾配法で制約に寄せ、真の座標分布の近似として使う。

クエリは、分散が大きい都市を起点に、近い都市を候補として追加する貪欲で作る。評価は「サンプルごとに予測されるMSTがどれだけ食い違うか」を見るもので、結果が返ってきたときに座標推定へ効く集合を選ぼうとしている。

構築では、サンプル平均距離を使って容量付きの森を作る。まず目的のグループサイズ分布を満たすまで木のマージ・スプリットを繰り返し、その後は焼きなましでグループ間のマージ後再分割や木内の辺交換を行う。最後に、既知の距離大小制約から確実に短いと分かる辺へ置き換える。

## 主要アイデア

- 都市の位置を1点推定せず、複数サンプルで保持する。
- MSTのcut/cycle性質から、クエリ応答を都市間距離の大小制約へ変換する。
- 制約は重複と、既存サンプルが全て満たすものを省き、更新対象を絞る。
- 各都市に関する幾何制約を `Line`、`InCircle`、`OutCircle` に分解し、違反時だけ座標を勾配方向へ動かす。
- クエリは「分散の大きい起点」「起点に近い候補」「サンプル間でMSTが割れる集合」を重視する。
- グループ構築は、平均距離上の森を容量制約付きで改善する局所探索として扱う。
- 既知制約で「今使っている辺より短い辺」が分かる場合、連結性を保てる範囲で最終辺を置換する。
- AVX2で8サンプル同時に座標更新し、2秒内で制約付きサンプリングの反復数を稼ぐ。

## 最終コードの構造

### 状態表現

- `Estimator`
  - 入力長方形 `rects`。
  - `samples`: 8サンプル単位のSoA風座標集合。`Sample8` が都市ごとの `x,y` を8レーンで持つ。
  - `queries`: 投げたクエリと返ってきたMST辺。
  - `constraint_set`: 距離大小制約の重複排除用集合。
  - `constraints_by_vertex`: 各都市を動かすときに見る幾何制約。
  - `centered`: クエリ起点に選ばれた回数の管理。
  - `isolated`: `L` が小さく、単独グループが多い場合に大きな範囲の都市を推定対象から外すための印。
- `EdgeConstraint`
  - `d(s,t) <= d(u,v)` のような辺長大小関係を4頂点で符号化する。
  - 共通端点があるときは垂直二等分線制約、そうでないときは円内・円外制約へ展開する。
- `GroupOptimizer`
  - 各都市の親、根、部分木サイズ、隣接辺、目的サイズ数との差分 `group_cost`、辺長和 `raw_cost` を持つ。
  - 焼きなましスケジューラを差し替え、サイズ合わせ段階と改善段階で温度を変える。

### 観測・制約・入力の扱い

- 初期サンプルは各都市の長方形境界近辺を角度で均等に取る。各都市ごとにサンプル順をシャッフルし、サンプル間の偏りを避ける。
- クエリ応答のMSTから辺を1本取り除き、できた2成分を結ぶ非木辺と比較して `MST辺 <= 非木辺` の制約を追加する。
- 追加した制約が既存と重複する場合や、全サンプルで既に満たされる場合は更新対象に入れない。
- 各制約は動かす都市ごとに幾何制約へ分解して保持する。更新時は対象都市の制約だけ見る。
- サンプル座標を動かした後、入力長方形から外れた場合は長方形内へ戻す。

### 評価関数

- クエリ評価:
  - 各サンプルで候補集合上のMST `T_i` を作る。
  - 別サンプルの木 `T_j` をサンプル `i` の距離で評価し、`f_i(T_j)-f_i(T_i)` の総和を情報量の代理にする。
  - 分母にMSTコスト総和の冪を置き、絶対差と相対差のバランスを `L` に応じて変える。
- 座標更新:
  - 制約違反の距離をコストとみなし、満たしていれば更新しない。
  - `Line` は垂直二等分線をまたぐ方向、`InCircle` は円内へ、`OutCircle` は円外へ動かす。
- グループ構築:
  - `raw_cost`: 平均距離による森の辺長和。
  - `group_cost`: 現在の連結成分サイズ多重集合と要求 `G` のズレ。
  - サイズ合わせ段階では `GW * group_cost + raw_cost` 相当、改善段階では主に `raw_cost` を見る。

### 探索・構築・更新

- 座標サンプル更新
  - ランダムな都市を選ぶ。
  - その都市の各サンプル座標を現在位置周辺で軽くランダムウォークする。
  - 都市に関する制約をシャッフルして、違反制約ごとに勾配方向へ動かす。
- クエリ構築
  - まだ起点として使っていない都市のうちサンプル分散が最大のものを選ぶ。`L=3` では同一起点を数回許す。
  - 起点からの期待距離が最小の都市を入れて2点集合にする。
  - 近い30都市を候補にし、評価値が最大になる都市を1点ずつ追加する。
  - サンプルごとのMST計算を繰り返すため、辺のMST採用回数を使って評価を高速化する。
- グループ構築
  - 近い辺を選んで成分をマージし、長い木辺を切ってスプリットする。
  - `try_to_split` で要求サイズに近づく分割を試す。
  - `merge_then_split` で近い2成分を一度つなぎ、同じ合計サイズ内の別の長い辺を切る。
  - `replace_edge_in_tree` で木内に近い非木辺を追加し、サイクル中の長辺を外す。

### 操作・クエリ・出力選択

- 400回すべてクエリに使う。各ターンでクエリ後すぐサンプル更新に時間を割り、後続クエリの評価を改善する。
- クエリ終了後、平均距離表を作り、`GroupOptimizer` で要求サイズの森を構築する。
- 最良の `raw_cost` を更新したときだけ出力候補を作り直す。
- 最終的な出力辺は、既知制約からより短い辺へ置換できるなら置換する。

### 時間配分・パラメータ

- 実行時間上限はコード上 `1.9` 秒、推定パートの目安は `1.5` 秒。
- 各クエリ後の更新時間は、残り推定時間を残りクエリ数で割って割り当てる。
- サンプル数は `L` が小さいほど多く、`L<=3` で64、`L>=12` で8。
- 起点周辺候補数は30。
- 勾配ステップ、ランダムウォーク幅、クエリ評価の指数は `L` 依存で変える。
- 焼きなまし温度はサイズ調整用と改善用で別に持つ。

## 実装上重要な断片

```text
after_query(mst_edges):
    for each tree edge e:
        remove e and split queried vertices into two components
        for each non-tree edge crossing the cut:
            add constraint length(e) <= length(non_tree_edge)
            decompose it into per-vertex geometric constraints

update_samples(until):
    while time remains:
        v = random vertex
        random_walk every sample point of v inside its rectangle
        shuffle constraints_by_vertex[v]
        for constraint in constraints_by_vertex[v]:
            if violated:
                move v by one gradient step
            clamp v into rectangle

choose_query:
    c1 = unused vertex with largest sample variance
    C = {c1, nearest expected vertex from c1}
    candidates = 30 nearest expected vertices
    while |C| < L:
        add candidate maximizing sample_mst_disagreement(C + candidate)
```

## この解法の本質

占い結果を「MSTそのもの」ではなく、大量の距離大小制約として蓄積し、座標サンプルをその制約で動かすところが本質である。真座標を1点に決め打ちせず、サンプル間でまだMSTが割れる場所を質問し続けるため、推定とクエリ選択が循環して改善する。

構築側の本質は、グループ分割を個別クラスタリングではなく、容量制約付きの森の局所探索にしている点である。MST風の近い辺を使いながら、サイズ制約を破らないマージ・スプリット・辺交換で全体を調整する。

## 真似するならまず実装する部分

まずはサンプルを8個程度だけ持ち、MST応答から `MST辺 <= 非木辺` 制約を作り、違反する都市を長方形内で少し動かす処理を作るのがよい。次に、サンプル平均距離で全体MSTを作り、長辺を切る単純なグループ分割を入れる。

その後に、クエリ評価を「サンプルごとのMSTの食い違い」、グループ改善を「2グループをマージして再分割」、最後に制約による辺置換へ進むのが現実的である。SIMDは最後でよい。

## 注意点・未理解点

- 不等式制約の生成は強いが、全てのcut/cycle制約を入れると多すぎる。重複削除と、全サンプルが満たす制約の除外がないと重くなる。
- `OutCircle` 制約は非凸で、ランダムウォークがないと局所解に張り付きやすい。
- サンプル数、勾配幅、クエリ評価指数は `L` 依存で細かく調整されており、そのまま移植しても最適とは限らない。
- `replace_to_shorter_edge` は制約の向きを取り違えると、短くない辺に置換してしまう危険がある。
- 提出コードの細かな高速化、AVX2部分、スケジューラの全挙動までは詳細に追っていない。
