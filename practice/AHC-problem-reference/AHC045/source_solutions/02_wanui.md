## 解法の全体像

クエリ応答のMSTから都市間距離の大小関係ルールを大量に集め、そのルールに合うように都市座標を推定する。最初は長方形中心を仮座標とし、クエリ中に焼きなましで座標を更新する。クエリ完了後は、嘘三分探索と嘘二分探索で各都市をさらに調整し、以降はその座標を真座標の代用として使う。

クエリは、近い都市を集めつつ、まだ距離大小ルールがない3頂点組を多く含む集合を選ぶ。構築は、推定座標上の距離でプリム法ベースの初期森を作り、近い木同士を対象に破壊再構築焼きなましを行う。最後に、既知の大小関係ルールを使って、木内の長い辺を短い辺へ置き換えられるかを見る後処理も入っている。

## 主要アイデア

- MSTの木辺を切ったとき、そのcutをまたぐ非木辺は木辺以上に長い、という大小関係を全て保存する。
- クエリ集合の評価を、距離順位の良さと、未獲得の3頂点ルールの多さで決める。
- 絶対距離ではなく距離順位を使い、孤立気味の都市が永遠に質問されない問題を避ける。
- 座標推定は、ルール違反量 `max(0, d(short)-d(long))` の総和を下げる問題として扱う。
- ランダム移動の焼きなまし、座標軸ごとの嘘三分探索、違反なし領域の中央へ寄せる嘘二分探索を組み合わせる。
- 森は常に要求サイズを満たす状態を保ち、2木間の交換や再構築だけを近傍にする。
- 構築後、大小関係ルールから「現在の木辺より短い」と分かる辺を使って木を改善する。

## 最終コードの構造

### 状態表現

- `comp_rule_t` 相当の距離大小ルール
  - `d(p,q) <= d(u,v)` のように、短い側と長い側の2辺を持つ。
  - クエリ応答のMST辺を切り、2成分間の全ペアから生成される。
- 座標推定状態
  - `positions`: 各都市の現在推定座標。
  - `related_rules`: 各都市を含むルールの一覧。
  - `failures`: 各ルールの現在の違反スコア。
  - `mean_diff`: 都市を長方形中心から離しすぎないための補助スコア。コードでは焼きなまし評価に差分で入っている。
- 森構築状態
  - 各都市の `group_id`、グループの頂点集合、グループ内グラフ。
  - `distance_table` と、近傍候補 `nears`。
  - 単独グループを扱う `is_solo`。

### 観測・制約・入力の扱い

- 各都市の初期推定座標は長方形中心。
- クエリ応答ごとに、MST内の各辺を一時的に削除し、両側成分を結ぶ辺との比較ルールを追加する。
- `s=u` のように端点が共有される場合は3頂点ルールになる。記事では3頂点ルールの方が有用そうだと述べている。
- 座標更新時、移動先が入力長方形外ならその遷移を捨てる。
- `L` によって微調整手順が分岐する。コードでは `L>=10` なら嘘二分探索中心、`6<=L<10` なら嘘三分探索と嘘二分探索、`L<6` なら嘘三分探索を厚めに使う。

### 評価関数

- クエリ評価:
  - `distance_rank(u,v)`: 推定座標上で、`u` から見て `v` が何番目に近いか。
  - `has_rule(u,v,w)`: 3頂点組について既に何らかの大小関係ルールがあるか。
  - 候補クエリは `(1 - avg(has_rule)) * exp(-alpha * avg(distance_rank))` 型で評価する。
- 座標推定:
  - ルール `d(p,q) <= d(u,v)` に対し、違反量を `max(0, d(p,q)-d(u,v))` とする。
  - コード上は最大化スコアとして負値で保持し、変更した都市に関係するルールだけ差分更新する。
- 森構築:
  - 推定距離による辺長和を下げる。
  - 破壊再構築では、既存グループと新グループが変化しない場合は棄却する。

### 探索・構築・更新

- クエリ作成
  - ランダムな中心座標を選ぶ。
  - その中心に近い `L` 個の都市を候補集合にする。
  - これを15個作り、評価値最大の集合を選ぶ。
  - さらに1点交換の山登りでクエリ集合を改善してから質問する。
- 質問途中の座標焼きなまし
  - 80回質問ごとに約40msだけ実行する。
  - ランダムな都市を、ランダム方向・ランダム距離で動かす。
  - 移動距離は小さい移動と大きい移動が混ざるよう指数的に選ぶ。
  - 関係ルールの違反差分と補助項で採択判定する。
- 微調整
  - 嘘三分探索: 各都市について、x軸・y軸方向のコストが単峰に近いと仮定して改善する。
  - 嘘二分探索: 違反が増えない上下左右の幅を探索し、その中央付近へ動かす。
- 森構築
  - プリム法を繰り返して、指定サイズの木を順に作る初期解を用意する。
  - 近距離にある2木から1頂点ずつ交換する。
  - 近い2木を壊し、片方のサイズ分をプリム法で取り直し、残りでもう一方の木を作る。
  - コードでは、2木の全頂点集合からランダム始点を選び、priority queueで近い都市を足して片方の木を作り、残りをもう一度プリム法でつなぐ。

### 操作・クエリ・出力選択

- 400回の質問でルールを集め、質問中にも座標を更新して次の質問評価へ反映する。
- 質問完了後、微調整した座標から距離表を作る。
- 森を構築し、各連結成分を要求グループとして出力する。
- 後処理 `fix_forest` では、同じグループ内で `d(p,q) <= d(a,b)` が分かっており、現在使っている辺 `a-b` を外して `p-q` を入れても連結なら置換する。

### 時間配分・パラメータ

- 質問中の座標焼きなましは80質問ごとに40ms。
- クエリ候補はランダム中心から15個作る。
- クエリ改善は1点交換山登り。
- 移動距離は指数的にばらす。記事では `2^p` 型の距離を使うと説明されている。
- 最終処理は約1900msまでを目安に実行している。

## 実装上重要な断片

```text
add_rules(mst):
    for each tree edge st:
        split MST by removing st
        for u in component_s:
            for v in component_t:
                if (u,v) != (s,t):
                    add rule d(s,t) <= d(u,v)

query_score(C):
    rank = average distance_rank over pairs in C
    known = average has_rule over triples in C
    return (1 - known) * exp(-alpha * rank)

anneal_position:
    pick vertex p
    new_pos = random displacement inside input rectangle
    delta = changed violation score of related_rules[p]
    accept by annealing

rebuild_two_trees(A, B):
    pool = vertices(A) + vertices(B)
    start = random vertex in pool
    grow size(A) vertices by Prim on estimated distance
    grow size(B) vertices from remaining pool by Prim
```

## この解法の本質

この解法の本質は、クエリを「辺を直接もらう機能」ではなく、「距離順序の制約を増やす機能」と見ている点である。距離の絶対値は分からないが、MSTの構造から大量の大小関係が得られるため、それに合う座標を探せば、最終的な距離表をかなり改善できる。

もう1つの本質は、座標推定をきれいな最適化問題として解き切ろうとせず、焼きなまし、嘘三分探索、嘘二分探索という経験的だが差分実装しやすい更新で押している点である。厳密な凸性はないが、違反量が減る方向を繰り返すだけでも、構築に使える距離表へ近づく。

## 真似するならまず実装する部分

最初は、クエリ応答から大小関係ルールを集め、長方形中心を初期座標として、違反量だけで焼きなましを行う部分を実装するとよい。次に、推定座標でプリム法により要求サイズの木を作り、2木破壊再構築を入れる。

クエリ評価は後から足せる。まずはランダム中心から近い都市を聞く単純版を作り、その後に `distance_rank` と `has_rule` の評価を加えるのが現実的である。

## 注意点・未理解点

- 嘘三分探索・嘘二分探索は単峰性や凸性を仮定しているが、記事内でも直感ベースとされている。ケースによっては局所的に悪化しうる。
- ルール数は `L=15` で約15万になるため、関連ルールリストによる差分更新が必須である。
- `has_rule` は3頂点に対し何か1つルールがあるかだけを見ており、ルールの強さまでは見ない。より情報量を正確に測る余地がある。
- コードの `mean_diff` 補助項の意図は、長方形中心から不自然に離れすぎるのを抑えるものと読めるが、係数や効果の詳細は本文だけでは分からない。
- 破壊再構築の候補木の選び方や温度はチューニング依存が大きい。
