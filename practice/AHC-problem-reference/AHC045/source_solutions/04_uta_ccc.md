## 実装キャッシュで確認した内容

- 座標推定は絶対座標ではなく、非木辺は木パス上の各辺より長いという関係を `longEdges` と `shortEdgesList` に蓄積して使う。
- `updateCoords(t)` は、現在の推定で `duv <= d(short)` になった矛盾に対し、短辺側を近づけ、長辺側を遠ざけるよう矩形内で座標を動かす。最後に100回ほど反復する。
- クエリは `L==3` とそれ以外で大きく分岐する。`L==3` では近距離かつ不確実性の大きい三つ組を作り、`L>3` では不確実性の大きい都市から近い未使用近傍を集める。
- `resort` は、長辺が短辺より前にある順位矛盾を見つけると、長辺を短辺群の後ろへ押し出す。距離値そのものより辺順序を修正する実装である。
- `getScore` は辺順位 `rankLength[edgeTbl[u][v]]` をコストにした Prim MST で、xor hash によりメモ化する。
- 初期グループは、推定座標に密度補正 `add[u]+add[v]` を入れた辺順で DSU 貪欲に構築する。単独グループも後処理する。
- 改善は `mergeTree` と `mergeTree2`。近い2グループを統合して Prim MST を作り、1本切って元サイズに戻せるなら改善差分で採択する。`mergeTree2` は乱択 Prim で小さい側を育てる。

## 解法の全体像

矩形中心を仮座標として貪欲にグループを作るところから始め、クエリで得たMSTとの差分を使って座標や辺順序を修正していく。クエリは、最終的に採用しそうな辺集合を含む都市集合に投げる方針へ寄せ、容量制約付きDSUでちょうど `L` 個程度の集合を作って多様に質問する。

座標を完全に推定するのではなく、占い結果から辺の大小関係を得て、全都市対の辺長順位を修正する。順位だけではMSTコストとして扱いづらいため、順位から実長の近似値を手作業で作る。構築はグループごとのMSTを基本にし、2グループをマージしてMSTを作り直し、辺を1本切って2グループに戻す山登りで改善する。

## 主要アイデア

- 初期は矩形中心間距離で、サイズの大きいグループから貪欲に作る。
- クエリ応答のMSTと推定座標上MSTを比較し、使われなかった辺は遠ざけ、採用された辺は近づけるように座標を修正する。
- MSTに含まれない辺を追加したとき、その閉路上の木辺は非木辺以下という性質で辺順序を修正する。
- クエリ集合は、最終解で使いそうな近い辺を含む集合を選ぶ。
- 容量制約付きDSUで `L` 個の都市集合を作り、同じ辺を周期的に使いすぎないよう前周期の辺を禁止する。
- 辺の順位から実長らしいコストへ変換する近似式を使う。
- 出力改善は、2グループを一度マージし、合併集合上のMSTを1辺カットして2グループに戻す山登り。
- `L=3,4` では情報が少ないため、クエリに入れる辺長差へ制約を入れる。
- 終盤では、バラツキの大きい都市から近そうな都市を選んで聞く単純方針も有効だった。

## 実装上重要な断片

```text
greedy_groups:
    sort group sizes descending
    for each group size g:
        pick shortest edge with both endpoints unused
        merge it
        while group size < g:
            scan edges from short side
            add edge whose one endpoint is already in the group

query_and_adjust:
    C = selected L vertices
    predicted = MST(C, estimated_distance)
    actual = oracle(C)
    for edge in predicted - actual:
        push endpoints apart within rectangles
    for edge in actual - predicted:
        pull endpoints closer within rectangles

improve_two_groups:
    pool = group_a + group_b
    mst = MST(pool, approximated_rank_cost)
    for edge e in mst:
        split mst by removing e
        if component sizes match original sizes:
            if new_cost < old_cost:
                accept split
```

## この解法の本質

この解法の本質は、距離の絶対値を正確に推定できなくても、辺の順序と最終的に使う近辺の情報が十分なら構築を改善できる、という割り切りである。クエリを座標推定だけに使うのではなく、辺順序の補正や採用候補辺の確認に使っている。

また、構築改善を「2グループ合併後のMSTを切り直す」という大きめの近傍にしている点も重要である。1頂点交換より構造が変わりやすく、グループ内MSTの性質を保ったまま改善を試せる。

## 真似するならまず実装する部分

まずは中心距離でグループを作り、各グループ内MSTを出す貪欲を作る。次に、クエリ応答から非木辺と閉路辺の大小関係を使って辺順序を補正し、その順位でMSTを組む。

その後、2グループ合併MSTからの切り直し山登りを追加するとよい。座標を近づける・遠ざける更新は壊れやすいため、先に辺順序ベースで構築を安定させる方が実装しやすい。
