## 解法の全体像

左上から確定する貪欲をベースに、手数配分を固定している。左上 6x6 は基本1回ずつ、右上 6x3 は各行3回、左下 3x6 は各列3回、右下 3x3 は6回押す。これで78回なので、余った3回を左上 6x6 のどのマスに追加で使うかを山登りで探す。

最終コードは、指定した領域 `(h,w)` と回数 `cnt` に対して、同じ左上位置へ `cnt` 個のスタンプを押す重複組合せを全探索し、対象領域の値の総和が最大になるスタンプ集合を選ぶ。余り3回の配分先集合を変えながら、構築全体をやり直して最終スコアが改善したら採用する。

## 主要アイデア

- 一度合わせた場所は後から触らないように、左上から確定する。
- 左上 6x6 は1マスだけを見る。余り手数を割り当てたマスだけ2回押す。
- 右端の各行は1x3、下端の各列は3x1、右下は3x3を対象領域として最大化する。
- 同じ場所に複数回押すときは、スタンプ種類の重複組合せを全列挙する。
- 余った3手の割当先を、左上 6x6 の36箇所から3箇所選ぶ問題として扱う。
- 割当先集合を1箇所だけ変える近傍で山登りする。
- 採択判定は構築後の盤面全体スコアで行う。

## 最終コードの構造

### 状態表現

- `a[9][9]`: 初期盤面。
- `s[20][3][3]`: スタンプ。
- `P { m, x, y }`: 1操作。
- `Sol = vector<P>`: 出力操作列。
- `Board`:
  - `_b[9][9]`: 現在構築中の盤面。
  - `_sol`: 現在構築中の操作列。
- `ords`: 左上 6x6 のうち、2回押すマスの集合。`ord = 6*x + y` で表す。

### 観測・制約・入力の扱い

- 入力を `int` 配列に読み、盤面更新は `atcoder::modint998244353` で行う。
- 操作は固定された位置 `(x,y)` へ、選ばれたスタンプ集合をすべて押す。
- `greedy_step` は出力操作列が `K` 未満なら操作を追加し、その後盤面を更新する。
- 手数配分は、左上36回 + 余り3回 + 右端18回 + 下端18回 + 右下6回 = 81回である。

### 評価関数

- `solve_range(x,y,h,w,cnt)` では、対象領域 `h*w` の mod 値総和を最大化する。
- 山登りでは、構築後に `calc_score(sol)` で盤面全体の最終スコアを計算し、それが過去最高なら採用する。
- 途中の貪欲選択は対象領域だけを見ており、未確定領域の値は評価しない。

### 探索・構築・更新

- `make_candidate(cnt)`:
  - `cnt` 個のスタンプIDの非減少列を全列挙する。
  - これにより、同じスタンプを複数回押す重複組合せを扱う。
- `solve_range(x,y,h,w,cnt)`:
  - 各候補について、対象領域内の加算値を合計する。
  - 現在盤面に加えた後の対象領域スコアが最大の候補を返す。
- `greedy_ans(ords)`:
  - 左上 6x6 を順に処理し、`ords` に含まれるマスは2回、それ以外は1回押す。
  - 右端6行を `1x3, cnt=3` で処理する。
  - 下端6列を `3x1, cnt=3` で処理する。
  - 右下を `3x3, cnt=6` で処理する。
- `solve()`:
  - 1900ms まで山登りする。
  - `ords` を近傍へ動かして構築し直す。
  - スコアが改善したら採用し、悪化したら元の `ords` に戻す。

### 操作・クエリ・出力選択

- 山登り中に最高スコアを出した `_sol` を `best_sol` として保存する。
- 最後に `best_sol.size()` と各操作 `m x y` を出力する。
- クエリ型ではないため、途中出力や対話はない。

### 時間配分・パラメータ

- `solve()` の探索時間は 1900ms。
- 余り手数は3回。
- 2回押し候補の初期集合は36箇所から3箇所を乱択する。
- 近傍は集合から1箇所削除して1箇所追加する。
- コード上、追加候補が `mt() % m` で選ばれており、`m=20` なので追加先が0..19に偏る。意図的かバグかは記事からは分からない。

```text
solve_range(x, y, h, w, cnt):
    best = -inf
    for multiset in combinations_with_repetition(stamps, cnt):
        score = 0
        for cell in target rectangle h*w:
            score += (board[cell] + sum(stamp[cell_offset] for stamp in multiset)) mod MOD
        if score > best:
            best = score
            best_multiset = multiset
    return best_multiset
```

## この解法の本質

ビームサーチではなく、手数配分をほぼ固定した貪欲を最後まで磨く解法である。強い点は、複数回スタンプを同じ場所に押す候補を重複組合せとして正確に全探索し、端や右下の低くなりがちな領域にまとまった手数を与えるところにある。余り3手だけを山登り対象にするため、探索空間は小さいが、貪欲構築全体のスコアで採択できる。

## 真似するならまず実装する部分

まず `solve_range` 相当を作るとよい。指定した位置・対象領域・押す回数に対して、重複組合せを全列挙し最良のスタンプ集合を返す関数である。これができれば、左上 6x6、右端、下端、右下を順に呼ぶだけで基礎解法になる。山登りはその後に、左上の2回押しマスを変えるだけで追加できる。

## 注意点・未理解点

- `solve_range` は対象領域だけを評価するため、未確定領域への影響は後続処理に任せている。この処理順を崩すと弱くなる。
- `make_candidate(cnt)` は候補数が `20Hcnt` なので、`cnt=6` ではかなり重い。C++なら成立するが、他言語では注意が必要である。
- 山登りでは構築全体を毎回やり直すので、繰り返し回数は貪欲パートの速度に強く依存する。
- 近傍の追加先が0..19に偏るコード上の挙動は、記事から意図が判断できない。
- 記事にもある通り、終盤のパラメータ調整ではスコア上昇がなかったため、どの定数が本当に効くかは要検証である。
