## 解法の全体像

操作順はスコアに影響しないが、実装上は左上からマスを確定していく順番を決め、確定済みマスの値だけを評価しながら貪欲またはビームサーチを行う。スタンプは局所的に9マスしか変えないため、すでに確定したマスへ影響しない位置だけを順に処理すれば、未確定領域への悪影響を後回しにできる。

基本形は、左上 6x6 を1マスずつ、右 6x3 と下 3x6 を3マスずつ、右下 3x3 をまとめて確定する貪欲である。さらにビームサーチ化し、確定スコアと残り操作回数の価値を使って状態を選ぶ。高速化では、複数回同じ場所に押すスタンプ列を合成スタンプとして前計算し、候補探索を二分探索・バケット・優先度付きキューで削る。

## 主要アイデア

- 操作は可換なので、出力順そのものではなく「どの位置で何回押すか」を探索対象にできる。
- 1回の操作で変化するのは3x3だけであり、局所性が強い。
- 局所探索で良い状態同士を滑らかにつなぐ近傍は作りにくいため、確定順序つきの構築に寄せる。
- 左上 6x6 は1マス単位、右端・下端は3マス単位、右下は9マス単位で確定する。
- ビームサーチでは、確定済みマスの総和に残り操作回数ボーナスを加えた評価を使う。
- 3マス確定が連続するとビームの多様性が失われやすいので、上の行と左の列を交互に確定する。
- 同じ位置に複数回押すスタンプ列を重複組合せとして合成し、1個の仮想スタンプとして扱う。

## 最終コードの構造

Browserで読んだ提出 #52179376 の実装構造である。スライドの「高速化したビームサーチ」とほぼ対応し、合成スタンプ候補と大きなビーム幅をC++で実装している。

### 状態表現

- 盤面 `B[9][9]`: 現在までに採用した操作を反映した mod 値。
- 操作列: 合成スタンプを使う場合も、最終出力用に元のスタンプ列を保持する。
- ビーム状態:
  - 現在の確定ターン `t`
  - 確定済みマスの総和
  - 使用済み操作回数
  - 盤面全体または差分適用可能な盤面
  - 復元用の親・操作情報
- 合成スタンプ:
  - 押す元スタンプ列
  - 3x3 の加算値
  - 構成スタンプ数
- 実装上の `Candidate`:
  - 確定セルへの `score`
  - 残り手数価値 `saving`
  - 親状態ID
  - 合成後の `Stamp`
  - 出力復元用の元スタンプID列

### 観測・制約・入力の扱い

- `N=9, M=20, K=81, MOD=998244353` 固定として扱える。
- すべての盤面値・スタンプ値は `MOD` で管理する。
- 操作位置は `0 <= p,q <= 6` の49箇所だけである。
- 合成スタンプを採用した場合、構成数ぶんだけ操作回数を消費する。
- 出力では合成スタンプを元の単発操作列に展開し、合計操作数が `K` を超えないようにする。

### 評価関数

- 貪欲では、今回確定するマス集合の mod 値総和を最大化する。
- 提出コードでは次の形の評価を使う。

```text
eval = fixed_score
     + 0.06 * MOD * (1 - progress) * remaining_operations
progress = t / 49
```

- `score` は確定済みマスの総和である。
- `saving` は残り操作回数相当で、`kSavingBonus = 0.06 * MOD` と進行度から終盤に向けて価値を小さくする。

### 探索・構築・更新

- 確定ターンごとに、その位置で使う合成スタンプ候補を列挙する。
- 候補操作を適用して、対象の1マス・3マス・9マスの値を評価する。
- ビーム幅ぶんだけ良い状態を残す。
- 提出コードでは `kBeamWidth = 65000`。
- 候補管理は優先度付きキューで行い、現在の最悪候補より悪いものを即不採用にする。
- 1マス確定では、1個・2個・3個の合成スタンプを左上値でソートし、欲しい値付近から探索する。
- 3マス確定では、関連する3成分をバケットに入れておき、欲しい値に近いバケットだけを見る。
- 9マス確定も3マス確定とほぼ同じ考え方で枝刈りする。

### 操作・クエリ・出力選択

- 確定順に選ばれた合成スタンプを採用する。
- 最後に合成スタンプを元のスタンプ列へ展開して出力する。
- 不正出力条件は、操作数 `L > 81`、範囲外位置、範囲外スタンプ番号である。

### 時間配分・パラメータ

- 制限時間は2秒。
- 単純貪欲の操作回数上限は、1マス確定が1回、3マス確定が3回、右下9マス確定が9回という配分。
- ビームサーチでは、最後の `(6,6)` だけ7回まで、それ以外の位置は3回まで操作できる形が示されている。
- 合成スタンプは7個までの重複組合せを列挙する。
- 4個以上からなる合成スタンプは、特定成分が弱いものを閾値で捨てる枝刈りが使われている。

## 実装上重要な断片

```text
for turn in fixed_order:
    next_beam = bounded_priority_queue(width)
    for state in beam ordered by eval desc:
        for composite_stamp in candidates(turn, state):
            if state.used + composite_stamp.count > K:
                continue
            ns = state.copy()
            ns.apply(composite_stamp, turn.position)
            ns.fixed_score += score_of_newly_fixed_cells(ns)
            ns.used += composite_stamp.count
            next_beam.insert_if_better(ns)
    beam = next_beam.items()
```

```text
precompute_composites(max_count):
    for multiset of stamps with size <= max_count:
        add 3x3 sums modulo MOD
        keep original stamp ids for output expansion
        prune weak large composites
```

## この解法の本質

この問題は全体スコアを直接改善し続けるよりも、あとで触らない場所を順に高値へ固定するほうが強い。スタンプは3x3に広がるが、左上から処理すれば、確定済みセルに再び影響する操作を避けながら未確定セルへ影響を押し流せる。局所探索の近傍が滑らかでないことを受け入れ、探索空間を「確定順序に沿った候補列」へ落とすのが本質である。

## 真似するならまず実装する部分

まずは左上 6x6 を1マスずつ、右端・下端を3マスずつ、右下を9マスで確定する単純貪欲を実装するのがよい。各位置では、同じ場所に1回から数回押すスタンプの重複組合せを全探索し、対象セル集合の値が最大になるものを選ぶ。その後、同じ候補生成を使ってビーム幅を小さくしたビームサーチへ拡張する。
