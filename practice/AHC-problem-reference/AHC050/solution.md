## 問題の本質

AHC050 は、ロボットの位置分布を直接観測できないが、岩配置と確率遷移から正確に計算できる問題である。最適化対象は、各ターンで岩を置いたときにロボットを潰さない生存確率の総和である。

解法視点では、単に「ロボットがいなさそうなマスを潰す」問題ではない。岩を置くことで、次ターン以降の滑走停止位置が変わり、ロボット分布の形も変わる。したがって重要なのは、現在の危険度が低いマスを選びつつ、将来ロボットが少数のマス・通路・終局パターンへ集まるように盤面を変形することである。

## 共通している考え方

どの解法も、存在確率またはそれに比例するロボット数を持つ。ロボットの移動は乱数だが、分布としては完全に計算できるため、シミュレーションの核は確率遷移である。

共通する改善点は、低確率マスが大量にある局面でのタイブレークである。存在確率最小だけでは市松模様や分散を作りやすい。そこで、隣接確率、通過確率、通路、距離期待値、短期先読み、分布の尖りなどを使い、ロボットが広がらず集まる盤面を作る。

## 解法の分類

- 正当出力型: 空きマスを任意順、またはシャッフルして出力する。
- 存在確率貪欲型: 移動後の存在確率が最小のマスを潰す。
- タイブレーク貪欲型: 隣接確率、通過確率、壁距離、分散、ランダム順序で低確率タイを選ぶ。
- 先読み評価型: 候補を置いた後に数ターン進め、確率分布の集中度を評価する。
- 距離期待値型: 高確率マス群や終局中心への滑走距離期待値を最小化する。
- 構築型: 通路や終局パターンを先に決め、そこへロボットを誘導する。
- 後処理改善型: 生成済み列の insert や swap で期待値を改善する。

## 推奨して理解すべき順序

2. 公式解説の解法3までで、`spread` と存在確率最小貪欲を実装できる形にする。
3. ALGO ARTIS の貪欲評価式で、低確率タイブレークの重要性を理解する。
4. uta_c と a2 の先読み評価で、距離を明示しない未来評価を理解する。
5. 公式解説の解法6以降で、距離期待値、終局形、後処理の上位化を見る。

## 実装するならどのルートか

理解のための最小実装は、公式解説の `spread` と存在確率最小貪欲である。これだけでかなり高いスコアになり、問題の確率遷移も確認しやすい。

次に実装するなら、ALGO ARTIS と shira_111 のタイブレークを混ぜるのがよい。具体的には、候補を存在確率の小さい順に取り、隣接 4 マスの存在確率和が大きいものを優先するか、`C*p-q` または `600a+3b-c` に近い式を試す。

上位化するなら、公式の距離期待値ルートが最も筋がよい。存在確率が低い上位 `K` 候補だけを見て、現在高確率なマス群への滑走距離期待値、または `4^d-1` の写像距離期待値を最小化する。さらに時間があれば、終局パターンと insert 後処理を追加する。

## 重要な実装要素

- 状態表現:
  - `rock` と `dp` を持つ。`dp` は移動後、岩配置前の存在確率である。
  - 1 次元配列にすると公式最終コードのように高速化しやすい。
- 評価関数:
  - 最初は `dp[cell]` 最小。
  - 次に `dp[cell]` が低い範囲で、隣接確率、通過確率、短期集中度、距離期待値を足す。
- 近傍:
  - 構築中は「次に置くマス」。
  - 後処理では swap または 1 要素 insert。
- 差分更新:
  - `spread` は行・列走査で十分速い。
  - さらに高速化するなら `next_pos[cell][dir]` と、岩を置いた同じ行・列の区間更新を考える。
- 候補管理:
  - 全候補を重い評価にかけるとTLEする。
  - 存在確率の低い上位 `K` または上位 100 に絞る。
  - 序盤は上位集合からランダムに選ぶと、多様な閉じ込め形を試せる。
- 出力判定:
  - 初期空きマスを全てちょうど 1 回ずつ出す。
  - 岩を置くたびに `rock[cell]=true` とし、二重出力を防ぐ。
- パラメータ:
  - 候補数 `K=10` から `100`。
  - 距離写像 `f(d)=d`、`d^2`、`4^d-1`。
  - 先読みターン数 1 から 10。
  - 序盤ランダム期間 200 ターン程度。

## 落とし穴

- 初手の前にもロボットは移動する。初期 `dp` のまま最初の岩を置くと評価がずれる。
- `dp[cell]` を潰した後は、生存確率から引き、`dp[cell]=0` にする必要がある。
- 存在確率最小だけだと、市松模様を作ってロボットを分散させやすい。
- 高確率マスを直接潰す評価は短期的に損が大きい。候補は低確率マスに絞るべきである。
- 先読みや距離評価を全空きマスに対して行うとTLEしやすい。
- 浮動小数で `best == dp[i][j]` のようにタイ判定する場合、計算変更で挙動が変わる可能性がある。
- 整数近似は速いが、小さい確率が 0 になりタイが増える。タイブレークが弱いと不安定になる。
- 山登りや後処理は、列全体のスコア計算が重い。前後の寄与を使わない単純再評価では回数が足りない。
