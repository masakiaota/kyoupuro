## 解法の全体像

この記事は単一の最終コード解説ではなく、上位者や参加者の発想を比較するレポートである。全体としては、存在確率を基本にした貪欲が共通土台であり、その上で「どうタイブレークするか」「どう閉じ込め構造を作るか」が主題になっている。

方針は大きく 2 つある。1 つは、通路や T 字に近い構造を作り、ロボットをそこへ誘導して閉じ込める構築型である。もう 1 つは、毎ターン存在確率や通過確率、隣接確率を評価して、低リスクかつ将来の集中を促すマスを選ぶ貪欲型である。記事では後者の評価式設計が詳しく、特に itigo の `600a + 3b - c` が紹介されている。

## 主要アイデア

- T 字や通路は、滑走ロボットを脱出しにくい形へ誘導するための構造である。
- 通路型では、長い未ブロック列を選び、その両側や到達経路に岩を置いてロボットを通路へ流し込む。
- 存在確率だけで選ぶと市松模様になりやすく、ロボットが広く分散してスコアが伸びにくい。
- タイブレークとして、隣接 4 マスの存在確率、通過確率、壁への距離、隣接確率の分散などを見る。
- itigo の評価式は、`a=存在確率`、`b=通過確率`、`c=隣接4マス存在確率` として `600a + 3b - c` を小さくする。
- 序盤 200 ターンは評価値上位 100 個からランダムに選び、閉じ込め構造の多様性を持たせる。

## 最終コードの構造

コードなし。以下は記事本文から推測できる実装構造である。

### 状態表現

- `rock[i][j]`: 現在岩が置かれているか。
- `p[i][j]`: 移動後、岩配置前のロボット存在確率。
- `pass[i][j]`: 候補マスをロボットが移動中に通過する確率。itigo の `b` に相当する。
- `adj[i][j]`: 隣接 4 マスの存在確率和。terry_u16 の `q` や itigo の `c` に相当する。
- 通路型では、通路セル集合、通路の端、通路へ 1 手で到達できるマス集合、通路周辺の誘導用候補を持つと考えられる。

### 観測・制約・入力の扱い

- 初期岩を `rock` に入れ、初期空きマスに一様な存在確率を置く。
- 毎ターン、ロボットのランダム滑走を確率遷移で更新する。
- 通路型では、通路として使う連続空きマスを探す。両端周辺の存在確率がほぼ 0 であることを条件にして、通路を作る際の事故を避ける。

### 評価関数

- Kiri8128 のビーム評価:
  - これまでのスコア。
  - 今の存在確率が今後変わらないと仮定し、残りマスを低確率順に潰した場合の将来スコア見積もり。
- terry_u16 の貪欲:
  - `C * p - q` を最小化する。`p` は自身の存在確率、`q` は隣接 4 マスの存在確率和。
  - `C` は複数値を試して最良を採用する。
- G4NP0N の方針:
  - 存在確率が同程度に低い候補の中で、隣接 4 マスの存在確率の分散が大きいものを優先する。
- tempura0224 の方針:
  - 存在確率が最小の候補の中から、四方の壁までの距離和が小さいものを選ぶ。
- itigo の方針:
  - `600a + 3b - c` を最小化する。
  - `b` を正に入れて、ロボットが閉じ込められている構造を壊しにくくする。
  - `c` を負に入れて、高確率領域の周囲を囲むくぼみを作りやすくする。

### 探索・構築・更新

- Kiri8128 は幅 9 のビームサーチを使う。遷移は次に置くマスの選択で、評価は過去スコアと将来見積もりの和である。
- MathGorilla の通路型は、列数・通路長・調査順序などを変えながら 200 回程度試し、最良を出力する。
- 貪欲型は毎ターン全候補を評価するが、序盤だけ上位集合からランダム選択するなど、乱択で盤面構造の多様性を確保する。

### 操作・クエリ・出力選択

- 通路型:
  1. 通路候補をランダム個数作る。
  2. 通路の隣接マスに岩を置いて、通路へ誘導する。
  3. 通路に 1 手で到達できるマスの周辺を存在確率の小さい順に埋める。
  4. 通路以外の低確率マスを埋める。
  5. 通路をロボットを潰さないよう半分埋める。
  6. 残りを低確率順に埋める。
- 貪欲型:
  - 毎ターン、評価値最小の候補を出力列に追加する。
  - itigo は序盤 200 ターンだけ評価値上位 100 個からランダムに選ぶ。

### 時間配分・パラメータ

- Kiri8128 のビーム幅は 9。
- MathGorilla は通路の個数、長さ、調査順などを変えて約 200 試行。
- itigo は序盤 200 ターン、上位 100 個からランダム。
- itigo の評価式係数は `600, 3, -1`。記事中では `b:c=3:1` が重要らしいと述べられている。

## 実装上重要な断片

```text
greedy_itigo():
    update existence probability p
    compute pass probability b for each candidate
    compute neighbor probability c = sum p[4-neighbors]
    value = 600 * p[cell] + 3 * b[cell] - c[cell]
    if turn < 200:
        choose random cell from top 100 lowest value
    else:
        choose lowest value
```

corridor_trial():

## この解法の本質

この記事で共通している本質は、確率が低いマスを潰すという安全策だけではなく、ロボットの将来の移動可能性を制御する盤面形状を作ることである。AHC050 では、岩は単にマスを消すだけでなく、滑走の停止位置を変える。したがって、置くマスの価値は「今ロボットがいない」だけでなく、「高確率領域を分散させるか、閉じ込めるか」で決まる。

itigo の式はその典型で、自身の存在確率を強く避けつつ、通過確率や隣接確率で構造を守る。通路型はさらに直接的で、ロボットが集まる器を作ってから外側を安全に埋める。

## 真似するならまず実装する部分

最初に真似するなら、itigo 風の乱択貪欲が実装しやすい。存在確率 `a` と隣接存在確率 `c` だけでも始められる。余裕があれば、通過確率 `b` を追加し、序盤だけ上位 100 候補からランダムに選ぶ。通路型は強いが、通路候補の安全判定と誘導ルールが必要なので、確率貪欲に慣れた後がよい。
