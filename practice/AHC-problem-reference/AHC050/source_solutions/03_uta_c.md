## 解法の全体像

この記事は、ChatGPT とのやり取りで方針を試しながら解を伸ばした記録である。最終的な本番方針は、存在確率を持つ貪欲をベースに、候補を低確率マスに絞り、その候補を置いた後の短期シミュレーションで「高確率マスが少量に固まるか」を評価するものだったと読める。

初期の「特定領域へ閉じ込める」方針は弱く、存在確率貪欲へ移る。さらに、各候補を置いた後に数ターン進めて盤面を評価する先読みが入り、速度面では候補数削減やビットボード風高速化が試された。本番25位の重要な偶然として、低確率マスの選び方が盤面全体に散ったことが効いたと書かれている。延長戦では、候補評価を存在確率と盤面評価の加重平均へ修正し、序盤のシミュレーションターン数を多めにしてさらに伸ばしている。

## 主要アイデア

- ロボット存在確率を管理し、毎ターンの配置候補を選ぶ。
- 最初のターンも「ロボットが 1 回動いてから岩を置く」ため、最初に全マスについて存在確率更新をする必要がある。
- 低確率マスを全て詳細評価すると重いので、低確率上位 100 個程度に候補を絞る。
- 候補を置いた後、盤面を固定して 1 ターンまたは 10 ターン程度シミュレーションし、高確率マスが少数に固まる状態を良いとする。
- `select_nth_unstable_by()` による低確率候補抽出で候補が盤面全体に散り、それがスコア改善に効いた可能性がある。
- 延長戦では、先読み後の盤面評価だけでなく、候補自身の存在確率も加重平均に入れる。

### 探索・構築・更新

- 各ターンで以下を行う貪欲と考えられる。

  2. 未岩マスから存在確率が低い候補を抽出する。

## 実装上重要な断片

```text
for turn in all_empty_cells:
    prob = move_once(prob, rock)
    low = low_probability_candidates(prob, limit=100)
    best = None
    for cell in low:
        tmp_rock = rock + cell
        tmp_prob = prob with cell removed
        future = simulate(tmp_prob, tmp_rock, lookahead_turns)
        concentration = evaluate_concentration(future)
        value = weighted(prob[cell], concentration)
        update best
    place best
```

low_probability_candidates:
    use partial selection, not full sort

## この解法の本質

この解法の本質は、低確率候補の中から「数ターン後に確率が集中する候補」を選ぶところにある。現在の安全性だけでは市松模様や分散を招きやすいため、候補を置いた未来の分布を直接見る。公式解説の距離期待値に近い発想だが、こちらは距離を明示的に定義するのではなく、短期シミュレーション後の分布評価で代用している。

また、候補の散り方が効いたという観察も重要である。低確率候補をただソート上位から取ると局所に偏りやすいが、候補が盤面全体に散ると多様な構造を試しやすくなる。

## 真似するならまず実装する部分

まず存在確率更新と低確率候補 100 個の抽出を実装する。次に、各候補を置いて 3 から 10 ターン程度だけ盤面固定でシミュレーションし、`sum p^2` や `sum p^5` のような集中度を最大化する候補を選ぶ。最後に、候補自身の存在確率も評価に混ぜて、先読み評価だけで危険なマスを選ばないようにする。

## 実装確認（提出 67661088）

キャッシュ実装は Nim で、外周込み `W=42` の `array[42, uint64]` bitset を岩配置に使う。存在確率 `prob` は整数配列で、初期値を `1 << (31 - log2(maxTurn))` に置く。`propagate` は各マスから4方向の停止位置へ `p >> 2` を加算する形で、正規化ではなく固定小数点風の整数近似で通している。

序盤は本文の「短期シミュレーションで確率集中を見る」ではなく、5x5 のT字/ホーム形状候補を4回転し、追加岩コスト、滑走BFS距離和、距離5以内マス数でホーム位置を選ぶ。最初にこのホーム形状の岩をまとめて置き、その後はホーム基準の距離場を使う。

通常ターンでは、未岩マスから `prob + rand(1<<3)` が小さい上位100候補を取り、各候補を一時岩にしたときの `sum(dist_home[i][j] * prob[i][j])` を評価する。比較キーは候補マスの存在確率と重み付き距離和で、本文から想像した数ターン先読み評価とはかなり違う。
