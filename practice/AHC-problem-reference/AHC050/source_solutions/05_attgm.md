## 解法の全体像

この記事の本番解法は、各マスから次にどこへ滑るかを管理し、存在確率を遷移させながら、存在確率が最小のマスへ岩を置く貪欲である。新しく岩を置いたとき、移動先が変わるのは、その岩と隣の岩との間にあるマスだけだと観察し、移動先テーブルを差分更新する方針を取っている。

本番中には山登りも試したが、近傍評価回数が少なく効果がほぼなかった。延長線では、低確率候補の中でどれを選ぶかが重要だと見て、候補を置いたまま数ターン回し、存在確率の偏りが大きくなるものを選ぶ方針を実装した。さらに、確率計算を整数で近似して高速化した。

## 主要アイデア

- 各マスにロボットがいる場合、4方向それぞれで次に止まるマスは岩配置から一意に決まる。
- 岩を 1 つ置いたときに移動先が変わる範囲は、その岩と同じ行・列で隣の岩までの区間に限られる。
- 存在確率を持ち、次の移動先へ 1/4 ずつ配ることでゲームを模擬できる。
- 存在確率最小マスを潰す貪欲は簡単で強い。
- 低確率マスが多い状況では、どの低確率マスを選ぶかが重要である。
- 数ターン先を見て、確率分布の偏りが大きい候補を選ぶ。
- `float` を整数演算近似に変え、初期値を `4^8` とすることで 30% 程度高速化した。

## 最終コードの構造

コードなし。以下は記事本文から推測できる実装構造である。

### 状態表現

- `rock[i][j]`: 現在の岩配置。
- `prob[i][j]`: 各マスの存在確率。
- `next_pos[i][j][dir]`: マス `(i,j)` にいるロボットが方向 `dir` を選んだときの停止位置。
- `answer`: 岩を置く順番。
- 延長線の整数版では、`prob` は整数値で、初期空きマスに `4^8` を入れる。

### 観測・制約・入力の扱い

- 初期空きマスの存在確率は `1/(N^2-M)`。
- 岩を置いたら、同じ行・列の隣接岩までの範囲だけ `next_pos` を更新すればよい。
- 整数近似では、最大値は `4^8*(N^2-M) <= 2^27` と見積もり、32bitに収まるとしている。
- 最小値は `1/(4^8*(N^2-M))` 相当で、`1e-8` 以下は 0 になり得るが問題なさそうだと判断している。

### 評価関数

- 本番貪欲:
  - 候補マスの存在確率 `prob[cell]` を最小化する。
- 山登り:
  - 岩を置く順番の入替を近傍とする。評価は列全体のスコア計算だが、記事ではスコア計算ミスもあり効果を確認できなかった。
- 延長線:
  - 候補を置いた状態で何ターンか回す。
  - 存在確率の偏りを評価する。記事では具体例として「確率の5乗の和」をスコアに使ったとある。
  - `sum prob[cell]^5` が大きいほど、確率が少数マスに集中していると見なす。

### 探索・構築・更新

- `next_pos` を使った確率更新:
  - 各マスの確率を、4方向の停止位置へ 1/4 ずつ足す。
  - 岩を置いた後、影響範囲の `next_pos` を差分更新する。
- 貪欲:
  - 毎ターン `prob` を更新し、最小確率の空きマスを選ぶ。
- 山登り:
  - 順番の swap を近傍にするが、150 個ほどしか近傍を回せず、効果が薄い。
- 延長線:
  - 最小確率候補の中から、候補配置後の数ターンシミュレーションで `sum p^5` が大きいものを選ぶ。

### 操作・クエリ・出力選択

- 各ターンで選んだマスを出力列へ追加する。
- 後処理の山登りを使う場合は、列全体の順番を入れ替えてスコアが上がるものを採用する。
- 延長線ではTLEしたため、本番提出として完成したわけではない。

### 時間配分・パラメータ

- 山登りは近傍 150 個程度しか回せなかった。
- 整数近似の初期値は `4^8`。
- 整数化で実行時間は約30%削減。
- 延長線の改良はローカルでは seed0 で984,270点、サーバではTLE。

## 実装上重要な断片

```text
update_next_pos_after_placing(cell):
    for each of 4 directions:
        find nearest rock on both sides in same row/column
        only cells between those rocks can have changed stop position
        rewrite next_pos for that interval
```

```text
lookahead_candidate(cell):
    tmp_rock = rock + cell
    tmp_prob = prob with cell removed
    repeat L turns:
        tmp_prob = transition(tmp_prob, tmp_rock)
    return sum(tmp_prob[x]^5 for all x)
```

## この解法の本質

この解法の本質は、盤面変化の局所性を使って移動先計算を差分化しようとした点である。ロボットの遷移は岩配置で決まるため、愚直に毎回全方向を探索しなくても、停止位置テーブルを持てば確率更新を安くできる。さらに、低確率候補が大量にある局面では、単なる最小値ではなく、数ターン後の分布の尖りを評価することで、将来の生存確率を高める。

整数近似も実装上の重要な観点である。AHC050 は `N=40` でターン数が多く、候補評価を増やすとすぐTLEする。精度を少し落としても候補評価回数を増やす価値がある。

## 真似するならまず実装する部分

まずは `next_pos[cell][dir]` を持つ確率シミュレーションを実装する。差分更新が難しければ、最初は公式解説の行列走査 `spread` でよい。次に、存在確率最小貪欲を作り、低確率候補が複数ある場合に `sum p^5` の数ターン先読みで選ぶ。整数近似は速度が足りなくなってから導入する。
