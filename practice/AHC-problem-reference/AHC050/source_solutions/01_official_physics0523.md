## 解法の全体像

公式解説は、正当な出力から始め、ロボット存在確率の正確な遷移計算を核にして段階的に改善する構成である。基本は各ターンの移動後の存在確率 `dp[cell]` を持ち、確率が低いマスを潰す貪欲を行う。そこから、低確率マス同士のタイブレークを工夫して市松模様を避け、ロボットの存在確率を少数領域へ集める方向に進む。

上位版では、現在高確率なマス群を「集めたい中心」として、各マスから中心へ何回の滑走で届くかという距離を計算する。岩を置く候補は存在確率が低いマスに絞り、その候補を置いた後の距離期待値または写像後距離期待値を最小化する。最終提出は、理想の終局形を作るルールベース、中心集約貪欲、保険用の中央集約貪欲、最後の insert 改善を組み合わせている。

## 主要アイデア

- `dp` は各ターンの「移動後、岩を置く直前」の存在確率を表す。
- 4方向の遷移は、各行・列を端から走査して「その方向へ滑った停止位置」に確率を足すことで高速に計算する。
- 単純な「存在確率最小」貪欲は強いが、確率 0 のマスが多いと市松模様を作り、ロボットの存在成分を分断しやすい。
- タイブレークにはランダム順序、行列順序、距離期待値、写像距離期待値、終局形ルールを使う。
- 良い状態は、ロボットの存在確率が広く分散せず、少数のマスや通路に集まっている状態である。
- 最終盤は、最後に潰すマスを決めておき、そこへ確率を流し込める構造を途中から守る。
- 生成した列は、後から 1 要素を抜いて最適位置へ insert する改善でさらに伸ばす。

## 最終コードの構造

### 状態表現

- `array<bool, N*N> as`: 初期岩。最終コードでは 1 次元添字 `i*N+j` で扱う。
- `array<bool, N*N> s`: 現在の岩配置。`true` が岩である。
- `array<double, N*N> dp`: 各マスの存在確率。
- `vector<pi> res`: 出力する岩配置順。
- `vector<int> base`: 距離 0 として扱う集中先のマス集合。
- `vector<int> block`: 理想終局を作るため、確率が十分低ければ早めに埋めたいマス集合。
- `vector<int> save`: 埋める優先度を下げたいマス集合。評価値に微小な下駄を履かせる。
- `array<double,128> evf`: 距離を評価値へ写像する配列。最終提出では `min(4^d - 1, 1e18)` 系の写像を使う。

### 観測・制約・入力の扱い

- `N=40` 固定として実装している。
- 入力の `#` を初期岩として `as` に入れ、空きマスには初期確率 `1/(N^2-M)` を置く。
- 出力は初期空きマス全てをちょうど 1 回ずつ並べる。最終コードの各貪欲は `s` が未岩のマスだけを候補にする。
- 岩を置いたマスの存在確率を生存確率から引き、`dp[pos]=0` にする。

### 評価関数

- 解法3から5の基本評価は、候補マスの存在確率 `dp[pos]` を小さくすること。
- 解法5では `dp[pos] - eps * min(random_row_order[i], random_col_order[j])` とし、低確率マスの選び方を直線的に偏らせる。
- 解法6では、存在確率が最大に近いマス群を中心 `cent` とし、候補を置いた直後の `sum dist_to_cent[cell] * dp[cell] / sum dp` を最小化する。
- 解法7では距離 `d` を `f(d)=min(4^d-1, 1e18)` のように写像してから期待値を取る。遠いマスを強く罰する。
- 最終コードの `eval(res)` は、列を先頭から正確にシミュレートして生存確率和を返す。

### 探索・構築・更新

- `spread(dp, s)`:
  - `dp` を 4 で割る。
  - 各行を左から、右から走査して、その方向に滑った停止マスへ確率を加算する。
  - 各列も上下について同様に走査する。
  - 1 回の遷移は `O(N^2)` で、全ターンの評価は `O(N^4)` となる。
- 解法4以降は、乱数を使った試行を時間いっぱい繰り返し、`eval` または構築中スコアが最大の列を採用する。
- 解法6・7は、存在確率が低い順の上位 `K=10` 程度だけを候補にし、各候補について距離期待値を計算する。
- 最終コードの `greedy_good` は、理想終局用の `base/block/save` を渡され、距離期待値を差分更新しながら低確率候補から選ぶ。
- `greedy_good2` は、終局パターンが弱い場合のフォールバックで、中央付近の最大連結成分内のマスを集中先にする。
- `improve` は 1 要素を抜いて全位置への insert を評価する後処理である。前からの `dp` と後ろからの残りターン寄与を使い、1 回の改善を `O(N^4)` 相当に抑えている。

### 操作・クエリ・出力選択

- 操作は固定長列 `P` の出力だけである。
- 最終コードは、まず `findC` で終局パターン候補を探し、その候補に基づく `greedy_good` を 1 秒程度試す。
- スコアが閾値未満なら `greedy_good2` も試す。
- 残り時間で `improve` を回し、得られた `res` を全行出力する。

### 時間配分・パラメータ

- 公式最終コードはおおむね、初期構築を `current_clock()<1000000`、後処理を `current_clock()<1970000` で切る。
- 解法5は 1.98 秒程度まで乱択試行する。
- 解法6・7は `K=10`、存在確率の最小値から `1e-6` 以上大きい候補は切る。
- 最終コードでは `stp=20`、`CAND=45`、候補確率のカット幅 `5e-4`、低確率ブロック閾値 `1e-7` から倍増などを使う。
- 終局パターンを使った解が `993000` 未満ならフォールバックを試す。

## 実装上重要な断片

```text
spread(dp, rock):
    divide all dp by 4
    for each row:
        scan left to right, add mass to current left-stop cell
        scan right to left, add mass to current right-stop cell
    for each column:
        scan top to bottom
        scan bottom to top
    dp = next_dp
```

```text
choose_by_distance(dp, rock):
    center = cells with dp >= max(dp) - eps
    candidates = low dp cells with tiny random tie-break
    for fill in first K candidates:
        temporarily place rock
        dist = sliding-distance-to(center)
        value = sum f(dist[cell]) * dp[cell] / sum dp
    choose minimum value
```

```text
improve_insert(order):
    choose one position me
    remove order[me]
    compute prefix dp/prob without it
    compute suffix remaining-turn contribution backward
    insert removed cell at best position
```

## この解法の本質

この問題では「存在確率が低いマスを潰す」だけで高得点になるが、それだけでは低確率マスの選び方がほぼ任意になり、盤面構造が悪くなる。公式解説の本質は、低確率という安全性を第一制約に置いたうえで、タイブレークや候補評価で「ロボットが集まる構造」を作りに行く点である。

特に距離期待値の導入が重要である。現在の生存確率を大きく削らない候補だけを見ながら、将来ロボットが中心へ滑って集まりやすいかを評価する。局所的な安全性と将来の閉じ込めやすさを分離しているため、短期コンでも段階的に実装しやすい。

## 真似するならまず実装する部分

まずは `spread` による正確な存在確率シミュレーションと、存在確率最小貪欲を実装するのがよい。次に、確率最小タイの中からランダムや隣接確率で選ぶだけでも大きく伸びる。上位化を狙うなら、存在確率が低い上位数十候補に絞り、候補を置いた後の「高確率マスへの滑走距離期待値」を評価するのが自然な次段階である。

## 注意点・未理解点

- `spread` は「移動後に岩を置く」順序で呼ぶ必要がある。初期状態から最初の配置前にも 1 回移動が起こる。
- `dp[pos]` を生存確率から引いてから `dp[pos]=0` にする。ここを忘れると評価がずれる。
- 浮動小数の完全一致でタイ集合を作るコードがあるが、実装言語や変更次第では比較に注意が必要である。
- 最終提出の終局パターン探索はアドホックで、パターン座標や閾値の意味は公式スライドの説明とコードを合わせてもチューニング依存が強い。
- 最終コード中の連結性チェックらしき部分は、空き連結成分を厳密に判定している意図だと思われるが、コード上の細部は完全には追い切れていない。
