## 問題の本質

この問題は、目的地列を順に訪問する最短行動列を作る問題だが、核は「滑走を止めるためのブロックを、いつ・どこで・どの順に設置するか」である。壁なしでは移動と外周停止だけで進むため、滑走で大きく短縮できる場面が限られる。ブロックを置くと停止位置を作れるが、`A` 自体が1手かかり、隣接マスにいる時しか操作できず、未来の目的地や経路を塞ぐ危険がある。

したがって、解法視点では次の二層を同時に扱う必要がある。

- 固定された壁盤面で、`M` と `S` を使って目的地間を最短移動する。
- 壁盤面をどう構築・更新すれば、追加した `A` のコスト以上に将来の滑走短縮が得られるかを評価する。

## 共通している考え方

どの解法も、固定盤面での最短移動計算を基本部品としている。`M` は隣接1マス、`S` は壁または外枠までの直線移動であり、目的地上を通過しても到達ではないため、到達判定は停止位置で行う。

また、ブロックは置けば必ず得ではない。`A` の1手を払ってでも、そのブロックが複数区間の滑走停止に効くか、少なくとも現在区間で2手以上短縮できる必要がある。そのため上位寄りの解法ほど、現在区間だけでなく残り目的地や全体再シミュレーションで評価している。

さらに、ブロック操作の実行可能性が重要である。現在位置の隣に置く、過去に隣接していたターンへ挿入する、仮想目的地として置きに行く、という違いはあるが、どれも「その壁を本当に出力できるか」を状態に含める工夫である。

## 解法の分類

- 貪欲型: kaede2020 の隣接壁5候補貪欲、uta_ccc の目的地順処理。
- ビームサーチ型: yoichiro の壁配置ビーム、shira_111 の操作直接ビーム。
- 焼きなまし型: thunder の仮想目的地解法、kaede2020 の貪欲後改善。
- 後処理・過去改変型: uta_ccc の `res2` への過去挿入。
- 構築型: yoichiro の壁追加候補生成、kaede2020 の現在位置隣接候補。
- 高速化型: thunder のbit並列BFSとキャッシュ、yoichiro のbit盤面とBFS作業配列再利用。

5. thunder を読み、仮想目的地と焼きなましによる全体最適化、高速評価の方向を理解する。

## 実装するならどのルートか

理解のための最小実装なら、yoichiro + kaede2020 のルートがよい。まず固定盤面BFSを作り、各目的地の前で「壁なし + 隣接4マスに壁」の候補を試す。次に、状態を複数残すビームへ拡張し、評価値を `ここまでのコスト + 残りBFS距離和` にする。

上位化を狙うなら、次のどちらかへ進む。

- 過去改変ルート: uta_ccc のように、過去に変更可能だったマスを記録し、未来の滑走停止壁を `res2` へ挿入する。
- 全体最適化ルート: thunder のように、ブロック設置を仮想目的地として持ち、焼きなましで追加・削除・移動・タイミング変更を行う。

操作直接ビームは実装練習には良いが、強くするには評価関数をかなり設計する必要がある。

## 重要な実装要素

- 状態表現:
  - 位置、壁盤面、目的地番号、累積行動列、累積コストを最低限持つ。
  - 過去改変では、壁の作成・削除履歴、各ターンで変更可能なマス、移動本体と挿入操作列を分けて持つ。
  - 焼きなましでは、ブロックそのものではなく、仮想目的地と対応ブロックの組で持つと操作可能性を扱いやすい。
- 評価関数:
  - 現在区間だけの手数では弱い。
  - `cost + remainCost`、全体再シミュレーション、または焼きなましの総ターン数評価が有効。
  - `A` の1手を必ず評価に含める。
- 近傍:
  - 現在位置隣接壁追加。
  - 次目的地への経路途中での壁追加。
  - 仮想目的地とブロックの追加・削除・移動・タイミング変更。
  - 操作直接ビームでは `M/S/A` × 4方向。
- 差分更新:
  - この問題では壁1個の影響が後続全体に広がるため難しい。
  - まずは再シミュレーションで正しさを優先し、高速化としてBFSキャッシュやbit盤面を入れる方が堅い。
- 候補管理:
  - ビームでは壁盤面のコピーと重複削除がボトルネックになる。
  - ハッシュには位置、目的地番号、壁盤面、必要なら評価値を含める。
- 出力判定:
  - 滑走で目的地を通過しただけでは到達ではない。
  - 目的地上に壁を置いた場合は、訪問前に除去しないと不正になる。
  - `A` は盤外に対して行えない。
- パラメータ:
  - ビーム幅、壁数上限、途中壁を見るprefix長、焼きなまし時間、温度が主要パラメータである。
  - 2秒制限なので、1.7から1.9秒で止める安全側の時間管理が必要である。

## 落とし穴

- `S` の到達判定を通過マスで行うとWAになる。
- 置いた壁が未来の目的地を塞ぎ、訪問時に除去できず詰む。
- 壁を置く1手を評価に入れず、壁だらけの過大評価状態を選ぶ。
- 過去挿入した `A` が、後続の滑走経路を変えてしまう。
- 現在目的地だけの近さで評価し、将来に効く壁を落とす。
- 盤面コピーが重く、ビーム幅を上げるとTLEする。
- 焼きなましで毎回全体BFSをすると、キャッシュなしでは試行回数が伸びない。
- `A` はトグルなので、設置のつもりで除去、除去のつもりで設置になる履歴バグが起きやすい。
