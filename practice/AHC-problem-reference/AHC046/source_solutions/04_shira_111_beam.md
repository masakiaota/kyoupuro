## 実装キャッシュで確認した内容

- 実装は操作列を直接伸ばすビームサーチで、各遷移は `M`, `S`, `A` の4方向を候補にする。次目的地への厳密BFSは使わない。
- 状態は `eval, lv, h,w, move_remain, block_num, block_code, G, action`。`G` には未到達目的地の番号とブロック `-1` を置く。
- `move_len` は行・列ごとに直進/壁まで滑走を概算し、`cum_move` に残り区間見積もりを前計算する。直線上にブロックがある場合は `+2` する。
- 評価は `1000 - move_remain + block_num*2`。ブロック数を少し加点し、残り推定手数を小さくする。
- `put_block` は隣接空マスにだけ置き、7x7 周辺と同一行列11マス程度に既存ブロックがある配置を禁止する。削除操作は扱わない。
- priority queue で評価上位を残し、ビーム幅は初期800、`loop_cnt==80` 以降400。重複キーは `(eval,pos,block_code)`。
- 1.9秒または最大800ループで終了し、`lv==M` に到達した候補から出力する。

## 解法の全体像

目的地を1つずつ処理し、現在の目的地に到達するまでビームサーチを行う。各状態から毎ターン、3種類の行動 `M/S/A` と4方向の合計12通りを展開する。目的地に到達した状態が見つかると、そこから次目的地に向けたビームサーチへ移る。

評価値は、現在の目的地へどれだけ近づいたかを主軸にし、ブロックを置いた価値や危険なブロック配置へのペナルティを加える。ブロックを自由に置くと状態空間が爆発し、また自分や目的地を塞いで詰むため、ブロック配置制約と重複除去を強く入れている。

## 主要アイデア

- 各ターンで `M/S/A` × `UDLR` の12遷移をビーム展開する。
- 目標に近づいた量を、壁なし貪欲での到達手数との差として評価する。
- ブロックを置く行動には小さな加点を与える。
- 自分、次目的地、現在位置を直線上で挟むようなブロックには減点を入れる。
- ブロック同士が近すぎると扱いにくくなるため、周囲2マス以内に別ブロックがある場所には置かない。
- 状態重複は、評価値・現在位置・ブロック配置のハッシュで管理する。
- 時間切れや到達不能を避けるため、400msごとにビームを打ち切り、幅を落とす調整も行う。

### 探索・構築・更新

- `priority_queue<board>` のような構造で良い状態を取り出し、次の状態を展開する。
- 各状態から12通りを試す:
  - `M d`: 隣接マスへ移動できるなら移動。
  - `S d`: ブロックまたは外枠まで滑走。
  - `A d`: 隣接マスのブロックを反転。ただし設置制約を満たす場合だけ。
- ビーム幅は最終的に300程度。
- 重複管理では、同じ評価値・同じ現在位置・同じブロック配置の状態を削る。
- 現在目的地に到達した状態が出たら、その操作列を確定して次目的地へ進む。

### 操作・クエリ・出力選択

- ビームサーチで復元した操作列を順に出力する。
- 到達判定は、移動または滑走で目的地に停止したときだけ行う。
- 時間切れが近い場合は、そこで探索を切り上げる設計がある。

### 時間配分・パラメータ

- ビーム幅は300に落としたと説明されている。500では重すぎた。
- 400msごとに打ち切り処理を入れたとある。
- 全体の制限に対して 1.9 秒程度を目安にしている。
- ブロック設置制約:
  - 近傍に他ブロックがある場所は避ける。
  - 自分・目的地との一直線上で邪魔になりやすい場合に減点する。

## 実装上重要な断片

```text
while current_target is not reached:
    next = []
    for state in beam:
        for action in {M, S, A}:
            for dir in UDLR:
                ns = apply(state, action, dir)
                if invalid: continue
                ns.eval = progress_to_target(ns) + block_bonus(ns) - penalties(ns)
                if not duplicated(ns):
                    next.push(ns)
    beam = best WIDTH states from next

fix best reached state
move to next target
```

## この解法の本質

この解法は、「盤面を決めてから最短路」ではなく、「操作列そのもの」を毎ターン展開する。これにより、ブロックの設置・除去・移動・滑走が同じ探索の中に入るため、設計は素直である。一方で状態空間が大きいため、評価関数と重複削除でかなり強く誘導する必要がある。

初めて実装するビームサーチとしては、問題の操作をそのまま遷移にする分かりやすい方針である。スコアを伸ばすには、ブロック配置の価値を現在目的地だけでなく将来目的地にも反映する必要がある。

## 真似するならまず実装する部分

まず、`M/S/A` の12遷移を正しくシミュレートする状態クラスを作る。次に、現在目的地までの壁なし距離を事前に計算し、近づいた量でビームをソートする。

ブロック評価は最初は「置いたら少し加点」「近すぎる壁は禁止」だけでよい。目的地到達時にビームをリセットして次目的地へ進む構造を先に完成させるべきである。
