## 解法の全体像

まず、各目的地へ向かうたびに「現在位置の隣接4マスに壁を1枚置くか、置かないか」を試し、その後の経路をシミュレーションして良い候補を採用する貪欲を作っている。壁の候補は現在位置から置けるものに限定されるため実装しやすい。

その後、貪欲解で得たブロック操作列を初期解として、ブロック追加・削除を焼きなましで改善している。変更した地点以降を再シミュレーションしてターン数を評価し、時間内に良い配置を探す。記事では、差分更新が難しく全体または後半の再シミュレーションを使ったこと、時間管理がスコアとTLEに直結したことが説明されている。

## 主要アイデア

- 目的地ごとに、現在位置の隣接4マスへの壁設置と壁なしの5候補を試す。
- 候補を採用した場合の残り行動数をシミュレーションし、最も良いものを貪欲に選ぶ。
- この貪欲だけで高いベースラインを作れる。
- さらに、ブロック配置を焼きなましで変更し、毎回再シミュレーションして評価する。
- 近傍は、次目的地へ向かう前の現在位置周辺に壁を追加、または既存ブロックを削除する操作が中心である。
- 制限時間いっぱいではなく、1.7秒程度で止める方が安定したとされる。

```text
    state = empty board
    for target in targets[1:]:
        best = simulate(state, no_wall)
        for dir in UDLR:
            if adjacent cell can be toggled:
                cand = simulate(state with wall placed, dir)
                best = min(best, cand)
        commit best operation for this step
    return state
```

## この解法の本質

この解法は、強い初期解を「現在位置から置ける壁だけ」に絞った貪欲で作り、その小さな設計空間を焼きなましで揺らしている。壁を任意マスに置こうとすると操作可能性の制約が重いが、現在位置の隣だけに限定すれば常に出力可能な `A` 操作として扱える。

また、評価を局所式にせず再シミュレーションで行っている点が実装上の割り切りである。20x20、40目的地という小さい設定なら、差分更新を頑張る前に再評価で十分な改善が得られる。

## 真似するならまず実装する部分

まず、壁盤面を固定したときの `M/S` 最短路を作る。次に、各目的地の前で「壁なし + 隣接4マスに壁」の5候補を試し、残りターン数をシミュレーションして採用する貪欲を作る。

焼きなましはその後でよい。初期解の操作列を保持し、ランダムに1つの壁操作を追加・削除して全体再評価するだけでも、記事の方向性を再現できる。
