## 解法の全体像

実サイズがだいたい `10000..100000` にあることから、`A = 50000 * sqrt(N) * 1.3` 程度の正方形外形を目標にする。まず全箱を縦長にして横方向へ並べ、幅が `A` 付近になる「Aブロック」を作る。各Aブロックは実際にクエリして幅を測り、想定より小さければ箱を1個追加し、大きければ1個減らす。

その後、Aブロックを段として縦に積む基本形、最終行の回転を反転した形、最終行を横から付け直す形の3つを提出し、観測 `W+H` が最もよいものを基準解とする。残りターンでは基準解の各箱回転を低確率でランダム反転したものを提出し、全提出の最小スコアに期待する。

## 主要アイデア

- 入力生成範囲から、平均辺長を約50000と置き、正方形外形の一辺を `50000 * sqrt(N) * 1.2..1.3` と見積もる。
- 箱を縦長に統一して、幅 `A` の行ブロックを作る。
- 行ブロック単体を計測し、明らかに短い/長い場合だけ箱数を1個補正する。
- 3種類のルールベース配置を提出し、観測上よいものを選ぶ。
- 余ったターンで回転をランダムに変えた変異解を提出する。
- 複雑な探索をせず、極めて高速に動く保険的な構築を重視する。

## 最終コードの構造

### 状態表現

- `PRDB`
  - 出力操作 `p,r,d,b`。
- `WH`
  - 箱または観測外形の `w,h`。
- `XY`
  - 座標。
- `Placement`
  - シミュレーション用の配置済み座標列。
- `A_blocks`
  - 各Aブロックを構成する `PRDB` 列。
- `results_info`
  - 観測された `W+H` と操作列のペア。初期3状態の比較に使う。

### 観測・制約・入力の扱い

- 入力サイズは `10000..100000` にクランプする。
- ローカル用には真値と観測ノイズも読めるようになっているが、提出ではサーバーからの応答だけを読む。
- `simulate` は問題文通り、`U` ならx位置を決めて下から上に詰め、`L` ならy位置を決めて右から左に詰める。
- Aブロック作成時は `L, b=-1` で横方向に並べ、幅を測る。
- ブロック幅が `A + sigma` より小さければ次の箱を追加し、`A + 6sigma` より大きければ最後の箱を取り除く。

### 評価関数

- ルールベース3状態の比較には、返ってきた観測 `W+H` をそのまま使う。
- 内部で真値スコアを推定する複雑な評価関数はない。
- 最終的な問題スコアは全ターンの最小値なので、ランダム変異提出のどれかが改善すればよい。

### 探索・構築・更新

- Aブロック構築
  - `A = 50000 * sqrt(N) * 1.3`。
  - 各箱を縦長になるよう回転し、`cur_len > A` または最終箱でブロックを閉じる。
  - ブロック単体をクエリし、観測幅に応じて1箱増減する。
- 状態1
  - 各Aブロックを1行として、`U` 操作で左から右へ並べる。
  - 行の先頭は `b=-1`、2個目以降は前の箱を基準にする。
- 状態2
  - 状態1をコピーし、最終行の箱だけ回転を反転する。
- 状態3
  - 状態1をコピーし、最終行の箱の方向を `L` に変える。
- ランダム変異
  - 初期3状態のうち観測 `W+H` が最小の操作列をコピーする。
  - 各箱について5%程度の確率で回転を反転して提出する。

記事本文では「良ければ新しい拠点にしてまた回転」と説明されている。一方、読んだ提出コードでは、ランダム変異の観測結果を `results_info` に反映して基準解を更新する処理は見当たらず、初期3状態のベストを毎回変異させて提出しているように見える。

### 操作・クエリ・出力選択

- Aブロック計測で `sqrt(N)` 程度のターンを使う。
- その後、状態1、状態2、状態3を提出する。
- 残りターンは、初期ベスト解のランダム回転変異を提出する。
- すべての出力後に必ず応答 `W,H` を読む。

### 時間配分・パラメータ

- `A` の係数はコードでは `1.3`。
- ブロック補正の閾値は、小さい側 `A + 1*sigma`、大きい側 `A + 6*sigma`。
- ランダム回転の変異確率は5%。
- 実行時間は提出で48ms程度と非常に軽い。

## 実装上重要な断片

```text
make_A_blocks:
    A = 50000 * sqrt(N) * 1.3
    cur_block = []
    for i in 0..N-1:
        rotate to vertical
        append command(i, rot, L, -1)
        cur_len += horizontal side
        if cur_len > A or i == N-1:
            measured = query(cur_block)
            if measured_width < A + sigma:
                append one more rectangle
            elif measured_width > A + 6*sigma:
                remove last rectangle
            save block

build_three_states:
    state1 = stack blocks as rows with U and previous base
    state2 = state1 with last row rotations flipped
    state3 = state1 with last row direction changed to L
    best = min by observed W+H

remaining_turns:
    cand = best
    for each command:
        with probability 5% flip rotation
    query(cand)
```

## この解法の本質

この解法の強みは、問題を「正方形に近い段組みを安定して作る」だけに絞った点である。Aブロックを実測して1箱だけ増減するため、初期観測誤差で行幅が大きく外れる問題を少し補正できる。複雑な推定やビームを使わなくても、外形を正方形へ寄せるだけで一定のスコアが出る。

また、インタラクティブで複数回提出できる性質を使い、3つの構造違いとランダム回転変異を実際に試している。内部評価を作り込む代わりに、ジャッジから返る観測値を候補比較に使う発想である。

## 真似するならまず実装する部分

まずAブロックを作り、状態1だけを出す実装でよい。次に、状態2と状態3を追加して実測比較する。最後に余りターンで低確率回転反転を提出する。短時間で作れるため、他の高度な探索解の保険解としても使いやすい。

## 注意点・未理解点

- 記事の山登り説明と提出コードには差がある。提出コード上は、ランダム変異で改善した場合に基準解を更新する処理が確認できなかった。
- ブロック補正は1箱増減だけなので、観測ノイズが大きい場合や箱サイズが偏る場合は外れる。
- `A=50000*sqrt(N)*1.3` は経験的な係数で、入力ごとの面積差は反映していない。
- 最終行だけの変形に頼るため、途中行の無駄は改善できない。
- ランダム回転は観測結果を使って次へつなげない場合、純粋な複数回試行に近い。
