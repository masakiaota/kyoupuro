## 解法の全体像

最初の `4T/5` ターンを使い、全箱をランダムにL字型へ配置して、幅・高さの合計観測を集める。その観測と初期入力に対する対数尤度が大きくなるように、各箱の推定サイズを焼きなましで調整する。

残りターンでは、その推定サイズを中心に小さく乱択し、各乱択サイズに対して差分ビームサーチで配置を作る。ビームで見つけた配置が現在ベストより悪そうなら出力せず再サンプルし、良さそうなものだけを提出する。観測結果が良ければ、その乱択サイズを新しい推定サイズとして採用する。時間が切れたら、これまでのベスト配置を回転だけ少し乱して提出する。

## 主要アイデア

- 推定にかなり多くのターンを割き、合計幅・合計高さの観測からサイズを調整する。
- サイズ推定は厳密なベイズ更新ではなく、初期観測と配置観測への対数尤度総和を最大化する焼きなましで行う。
- ビーム探索は全探索型に近く、方向 `U/L`、回転、基準候補を列挙する。
- 基準候補は全箱ではなく、`-1`、直近数箱、終盤だけさらに数箱に絞る。
- 評価は `W+H` だけでなく、正方形らしさ、無効面積、接触辺長を混ぜる。
- 推定サイズでの接触判定が危ないため、配置済み矩形の判定範囲を `1.5sigma` 程度広げる。
- 同じような盤面を避けるため、座標とサイズからZobrist風ハッシュを作って重複を潰す。

## 最終コードの構造

### 状態表現

- `Size`
  - 各箱の推定 `w,h`。
- `Action`
  - `op`: `U` または `L`。
  - `idx`: 沿わせる箱。`-1` なら壁。
  - `spin`: 回転有無。
  - `x,y`: 配置左上相当の座標。
- `Evaluator`
  - `turn`, `length`, `area`, `w`, `h`。
  - `length` は接触辺長、`area` は無効そうな面積、`w,h` は外接幅・高さ。
- `State`
  - 配置済み矩形の `x,y` 範囲。
  - `nx,ny` は誤差対策で拡張した判定範囲。
  - `wh` は探索で使う推定サイズ。
- `Tree` / `Selector`
  - Euler Tour型の差分ビーム。状態本体をDFSで前進/後退し、候補は小さい差分だけ持つ。

### 観測・制約・入力の扱い

- 初期入力 `WH` は推定の初期値として使う。
- サイズ下限 `L` は、平均観測値から `(2*ave - 100000).clamp(10000,50000)` で雑に推定し、サンプリング時の下限に使う。
- 推定クエリでは、各箱をランダムに `L` 側または `U` 側へ振り分け、幅合計・高さ合計を作る。
- `histRes` に各推定クエリの操作列、`histSize` に観測された外接サイズ、`sumSize` に現在推定値から計算される合計を持つ。
- 配置探索時の衝突判定では、配置済み範囲を `offset = 3*sigma/2` だけ広げた `nx,ny` で判定する。

### 評価関数

ビームの評価は小さいほどよい。

```text
evaluate =
    10 * (W + H)
  + 5  * sqrt(W^2 + H^2) * remaining_rate
  + 10 * sqrt(dead_area) * remaining_rate
  - 8  * contact_length * remaining_rate
```

- `sqrt(W^2+H^2)` は正方形に近い形を促す。
- `dead_area` は、新規矩形が接触矩形からはみ出した辺長と奥までの距離から近似する。
- `contact_length` は接触が多いほど密に詰まっていると見て減点ではなく加点扱いにする。
- `remaining_rate` により、終盤ほど素の `W+H` を重視する。

サイズ推定の評価は対数尤度総和である。

- 初期観測 `WH[i]` と現在推定 `wh[i]` の差に対する正規分布対数密度。
- 推定クエリの観測 `histSize[t]` と、現在推定サイズから再計算した `sumSize[t]` の差に対する正規分布対数密度。

### 探索・構築・更新

- 推定用焼きなまし
  - 近傍は箱 `idx` を1つ選び、`w,h` を現在値中心、標準偏差 `sigma/6` の正規乱数で再サンプルする。
  - その箱に関係する初期観測尤度と、各推定クエリの合計幅/高さの尤度だけを差分更新する。
  - `diff > 0` または焼きなまし確率で採択し、棄却なら `wh`, 尤度配列, `sumSize` を戻す。
- ビームサーチ
  - `guideList[i]` で候補基準を絞る。序盤は `-1` 中心、途中は直近3箱、最後5箱は直近5箱まで見る。
  - 各手で回転2通り、`U/L`、基準候補を試す。
  - 配置座標は問題文と同じく、重なる既存矩形の端の最大値で止める。
  - `Selector` はビーム幅分だけ候補を保持し、ハッシュ重複は良い評価だけ残す。
- 山登り的更新
  - 現在推定 `wh` から各箱を `sigma/6` で乱択したサイズ集合を作り、ビームを走らせる。
  - ビーム上の推定スコアが `best + sigma` より悪ければ出力を省略する。
  - 未提出の操作列なら提出し、観測 `W+H` がベスト以下なら、その乱択サイズを推定値として採用する。

### 操作・クエリ・出力選択

- `search()` が推定クエリを `sCnt = 4T/5` 回出力する。
- `solve()` が残りターンで詰め込み解を作る。
- 出力済み操作列は `scoreTable` で管理し、同じ操作列を重複提出しにくくする。
- 時間切れ時は `bestRes` を出力し、`f=true` の場合は一部の回転をランダムに反転して提出する。

### 時間配分・パラメータ

- 推定クエリ数は `T*4/5`。
- 推定焼きなまし時間はコード上 `100_000_000ns` 程度。
- ビーム幅は `2000000 / T / N`。
- サイズ乱択の標準偏差は `sigma/6`。
- 接触判定の安全マージンは `1.5sigma`。
- 出力全体は `2.8s` 付近で打ち切る。

## 実装上重要な断片

```text
estimate_sizes:
    collect sCnt random L-shaped measurements
    initialize likelihood from initial sizes and measured query sums
    while time remains:
        idx = random rectangle
        new_size = normal(current_size, sigma/6)
        update likelihood terms that include idx
        accept by log-likelihood difference
        otherwise rollback

beam_transition:
    for rotate in {0,1}:
      for dir in {U,L}:
        for base in guideList[turn]:
            simulate stop position
            update W,H, contact_length, dead_area
            push if hash is not dominated

submit_loop:
    sample sizes around current estimate
    run beam
    if estimated W+H <= best + sigma:
        submit
        if observed W+H improves:
            current estimate = sampled sizes
```

## この解法の本質

「サイズ推定の精密なモデル化」よりも、「観測に矛盾しないサイズへ寄せ、その周辺を何度も試す」ことを重視している。詰め込みは推定誤差に弱いので、単に初期入力でビームするのではなく、観測尤度で少しでも真値らしいサイズに寄せる。さらに、推定値を固定せず毎回乱択して提出候補を作るため、観測ノイズと推定誤差の両方に対するランダムリスタートにもなっている。

ビームの評価に無効面積と接触長を入れている点も重要である。`W+H` だけだと途中状態で細長い・隙間が多い形を許しやすいが、接触を増やし、死に領域を減らすことで、最終盤面につながりやすい形を残している。

## 真似するならまず実装する部分

まずは推定を省き、`guideList` で候補を絞った差分ビームと、4要素評価関数を実装するのがよい。次に、L字型の合計計測と対数尤度焼きなましを追加する。最後に、推定サイズの周辺乱択と「良さそうなものだけ提出する」ループを入れると、この解法の雰囲気に近づく。

## 注意点・未理解点

- `dead_area` の式には `self.wh[i]` を参照する箇所があり、`i=-1` のときの扱いはNimの添字仕様や実行経路を意識して読む必要がある。実際にACしているが、移植時は壁基準を明示的に分ける方が安全である。
- 推定の対数尤度は独立性をかなり仮定しており、厳密な事後分布ではない。
- `guideList` を絞りすぎると良い配置を捨てるが、広げすぎるとTLEしやすい。
- 観測 `W+H` はノイズ付きなので、良い観測を見たサイズ推定へ寄せる更新は過適合にもなりうる。
- 出力回数が足りなくなったときのランダム回転は保険だが、ベスト解を壊す提出も混ざる。スコアが全ターン最小なので成立している。
