## 解法の全体像

前半を推定、後半を詰め込みに分ける。推定では、全長方形の縦横長をまとめたベクトルを多変量正規分布として持ち、初期観測と追加クエリで平均・共分散をベイズ更新する。追加クエリは、縦横に長くなるL字/T字状の配置を焼きなましで選び、更新後の共分散のトレースが大きく減るものを投げる。

詰め込みでは、推定分布からMCMCで長方形サイズを16セット同時にサンプリングし、その16セットに対して同じ操作列を評価する。中盤まではBottom-Left系のビームサーチで詰め、最後の十数手をMCTSで仕上げる。16セットを同時に見ることで、1つの推定値にだけ都合のよい脆い配置を避ける。さらに16セットはAVX2 SIMDの16レーンに対応させて高速化している。

## 主要アイデア

- 長方形サイズを独立点推定でなく、平均ベクトルと分散共分散行列で持つ。
- 入力生成の事前分布を正規分布で近似し、平均65000、標準偏差21280程度から始める。
- 追加計測は、観測ベクトル `c` に対する1次元観測として扱い、カルマンフィルタ型の正規分布更新を行う。
- 推定クエリは、共分散トレースの減少量を評価値にして焼きなましで構築する。
- 詰め込み時はMCMCで16個の世界をサンプルし、同じ操作列の高さ・幅を16並列で評価する。
- ビームでは幅を `alpha * sqrt(sum area)` 付近に固定し、下から入れる操作だけに寄せる。
- 遷移候補は、壁または他長方形の側面に十分接触するもの、かつ今後の有効基準になりうるものに絞る。
- 終盤はMCTSで候補手を展開し、ランダムプレイアウトで詰め切り性能を補う。
- SIMD化のため、座標・長さは128単位に丸めて16bit整数に収め、SoAで持つ。

## 最終コードの構造

### 状態表現

- `GaussEstimator`
  - `mean`: 長さ `2N` の平均ベクトル。コード上は高さ群、幅群の順で保持する。
  - `variance`: `2N x 2N` の分散共分散行列。
  - `measure_variance`: 計測誤差 `sigma^2`。
- 推定クエリ用 `State`
  - 各長方形を `Up` / `Left` / 未使用のどれで使うか、回転、T字の `pivot`。
  - `ScoreCalculator` が観測ベクトルとトレース減少量を差分管理する。
- MCMC用 `State`
  - `rect_w`, `rect_h`: 16レーン分のサンプル長方形サイズ。
  - `log_likelihood`: 初期観測と過去配置観測に対する対数尤度。
- ビーム/MCTS用状態
  - 配置済み矩形の `x0,x1,y0,y1` を16レーン並列の配列で持つ。
  - 現在の外接幅・高さ、幅制限、高さ制限、有効な基準長方形集合を持つ。
  - `SmallState` / `Action` は1手の差分、操作 `Op`、評価値を持つ。

### 観測・制約・入力の扱い

- 初期入力の各 `w'_i, h'_i` は、単一成分だけ1の観測ベクトルとして `2N` 回更新する。
- 追加推定クエリは、配置から得られる「外接幅/高さを構成した長方形の辺の和」を観測ベクトルにする。
- MCMCでは、初期観測に加えて、推定用クエリと詰め込み後の観測も尤度計算に入れる。
- サイズは `10000..100000` にクランプし、SIMD処理では128単位へ丸める。
- L字配置の干渉で、推定上の観測ベクトルと実際の接触がずれることがあるため、最終的なサンプル生成ではMCMCで過去操作を再シミュレーションする。

### 評価関数

- 推定クエリ:
  - 観測ベクトル `c` に対する共分散トレースの減少量。
  - コードでは `tr_numerator / tr_denominator` を縦横それぞれ計算し、和を焼きなましスコアにする。
- MCMC:
  - 初期サイズ観測と過去配置観測の正規分布対数尤度。
  - 差分は `exp(new_log_likelihood - old_log_likelihood)` 相当でメトロポリステストする。
- ビーム:
  - 16セットの高さを昇順ソートし、`H0 + beta H1 + ... + beta^15 H15` 型の重み付き和を最小化する。
  - 実装上は大きいほどよいスコアへ符号反転している。
- MCTS:
  - 16セットそれぞれの `W+H` を昇順ソートし、重み付き和を正規化した値を使う。
  - 平均よりも、良いサンプルを重く見る上振れ狙いの評価である。

### 探索・構築・更新

- 推定クエリの焼きなまし
  - 近傍は、ある長方形の方向・回転・未使用化の変更、またはpivot変更。
  - 変更後の観測ベクトルを作り直し、`ScoreCalculator` で差分更新する。
- MCMC
  - ランダムな長方形と幅/高さを選び、現在の推定標準偏差を使った正規乱数で差分を作る。
  - 16レーンすべてを同時に動かし、各レーンごとに採択/棄却する。
  - 20反復ごとにサンプルを保存し、最終的に16セットの矩形集合として使う。
- ビームサーチ
  - 現在の長方形番号 `turn` を置く。
  - 回転2通り、基準なしまたは有効基準集合に対する `Up` 操作を候補化する。
  - 実装では `Left` の処理をx/y反転で再利用し、出力は `Up` 主体に戻す。
  - 基準より手前で止まる操作、幅制限超過、接触長が足りない操作を捨てる。
- MCTS
  - ビームで得た途中手順を初期状態に適用し、残り手を探索する。
  - ノードは一定訪問回数で展開し、候補手はtoplineが小さいものから数個持つ。
  - 子の選択はUCB1-Tuned。
  - プレイアウトは回転を乱択し、toplineが最小になる位置へ貪欲配置する。

### 操作・クエリ・出力選択

- `arrange_count` より前のターンは推定専用クエリを投げる。
- 残りターンでは毎回、MCMCサンプル、ビーム、MCTSで操作列を作って出力する。
- 最後以外の詰め込み結果も観測としてMCMCへ追加し、次回サンプルの尤度に反映する。
- 問題のスコアが全ターンの最小値なので、後半に複数回配置を出し、観測も活用する。

### 時間配分・パラメータ

- 最終コードは `Params` を `(N,T,sigma)` から推定する。記事ではGoogle Cloud上でOptunaとガウス過程回帰によりチューニングしたと説明されている。
- デフォルト値例は、`arrange_count=10`, `mcts_turn=15`, `mcts_expansion_threshold=3`, `mcts_candidates_count=4`, `parallel_score_mul=0.9`, `width_buf=1.1`。
- 実行時は残り時間を残り試行数で割り、MCMC・ビーム・MCTSに比率配分する。
- ビーム幅は実行時間観測を用いた `BayesianBeamWidthSuggester` で安全側に調整する。

## 実装上重要な断片

```text

initial_update:
    prior mean = 65000, covariance = 21280^2 * I
    for each observed side:
        c = unit vector for that side
        gaussian_update(y=observed, c)

query_selection:
    state = random L/T-shaped measurement plan
    while time remains:
        mutate one rectangle direction/rotation/pivot
        recompute affected observation vectors
        accept by trace_reduction score
    output plan and update Gaussian with measured W,H

packing_turn:
    samples = mcmc(previous_samples, all_observations, duration)
    prefix_ops = simd_beam(samples, fixed_width, until N - mcts_turn)
    suffix_ops = mcts(samples, prefix_ops, remaining_time)
    output prefix_ops + suffix_ops
    add measured W,H to MCMC observations unless last turn
```

## この解法の本質

不確実なサイズを単一の推定値に潰さず、分布として最後まで持ち回る点が本質である。推定クエリでは、箱を多く足し合わせても観測ノイズが一定という問題の性質を利用し、情報量の大きい合計長を測る。詰め込みでは、1つの推定値で良い解を作るのではなく、複数のあり得る世界で同時に破綻しにくい操作列を選ぶ。

もう1つの本質は、計算量をアルゴリズムと実装の両方で削っている点である。候補基準の削減、終盤だけMCTS、16bit SIMD、バイトニックソート、時間からのビーム幅制御が合わさって、複雑な確率推定と探索を3秒に収めている。

## 真似するならまず実装する部分

最初からMCMC・MCTS・SIMDまで真似するのは重い。まずは次を実装するのがよい。

- 初期観測を正規分布として扱う平均・分散更新。
- L字状に複数箱を並べる推定クエリと、観測ベクトルによる更新。
- 推定平均値を使った固定幅Bottom-Left系ビーム。
- 複数サンプルを持つ代わりに、平均値、平均+sigma、平均-sigma程度の少数ケースでロバスト評価する。

その後、MCMCでサンプルを作る、候補基準を削る、終盤MCTSを入れる、SIMD化する、の順で上位解法に近づけるのが現実的である。

## 注意点・未理解点

- 記事中のPDFメモは画像PDFでテキスト化できず、内容を精読できていない。
- 提出コード全体のチューニングパラメータは、巨大な埋め込みデータから復元されるため、係数の意味を全て追うのは難しい。
- 推定クエリで得た観測ベクトルが実際の接触とずれる問題は、簡易実装では特に壊れやすい。
- SIMD実装は符号なし16bit比較や丸め誤差に依存するため、素直な実装へ戻す場合は評価値や閾値が変わる。
- MCTSの `best_ops` 復元は帰りがけに操作を積む実装で、順序管理を誤ると簡単に壊れる。
