## 解法の全体像

推論を行わず、初期の計測値だけで段分け配置を作る軽量方針である。全解法で、`d_i` は `U` のみ、`b_i` は `-1` または `i-1` のみとする。こうすると、各段を左から右へ並べ、新しい段は左端から始める形になり、想定外の引っかかりを避けやすい。

1投目は、合計面積から理想的な正方形外形を見積もり、その周辺の横幅基準で順に段へ詰める。2投目は、各段の横幅を均等にするため、回転を固定したうえで段数を決め、Yokan Party的な分割で最大段幅を抑える。余った時間で、長方形1個の回転を変える焼きなましを行う。

## 主要アイデア

- 操作を `U` と直前基準に制限し、干渉しない段組み問題へ落とす。
- 推定はせず、入力の観測サイズをそのまま使う。
- スコア `W+H` は正方形に近い外形が有利なので、合計面積から理想正方形を考える。
- 段の横幅が目標を超えそうになったら次段へ進む。
- 回転を決め、段数を決めると、箱幅列を段へ分割して最大段幅を抑える問題になる。
- 段数は全探索し、段数ごとの分割はYokan Partyのように貪欲/判定で行う。
- 焼きなましの近傍は、長方形1個の回転反転のみ。

## 最終コードの構造

Browserで読めた提出 #60618928 を主実装として書く。記事内にコードリンクはないが、提出コードで段分けと焼きなましの具体実装を確認できた。

### 状態表現

- 入力サイズ `w[i], h[i]`。
- 回転状態 `rot[i]`。
- 段分割 `rows`: 各段に入る連続した箱の範囲。
- 各段の幅 `row_width[k]` と高さ `row_height[k]`。
- 評価用の外接幅 `W = max(row_width)`、外接高さ `H = sum(row_height)`。

操作は番号順で固定されるため、段分割は連続区間の列として表せる。

### 観測・制約・入力の扱い

- 追加観測によるサイズ更新は行わない。
- `b_i=-1` は段の先頭、`b_i=i-1` は同じ段で直前箱の右端に揃える操作として使う。
- `d_i=U` のみなので、横方向の段詰めに固定される。
- こうした制限により、箱が別の箱に予想外に引っかかるケースを減らす。

### 評価関数

- 基本評価は推定外接サイズの `W+H`。
- 1投目:
  - 合計面積を少し超える正方形の一辺を理想横幅とする。
  - 横幅基準を理想値の周辺でランダムに変化させ、複数回提出する。
- 2投目:
  - 段数を固定したときの最大段幅を小さくする。
  - 段数ごとの `W+H` を比較して最小のものを選ぶ。
  - 焼きなまし中は、毎回全段数を見ず、初期貪欲で得た段数の `±2` だけ見る。

### 探索・構築・更新

- 1投目構築
  - 全箱を縦長になるよう回転する。
  - 現在段の幅に次の箱を足して横幅基準を超えそうなら新段へ移る。
  - これを全箱に対して行う。
  - `T` 回の操作では横幅基準を理想値の周辺で乱択する。
- 2投目構築
  - 回転状態を固定する。
  - 段数 `k` を `1..N` で試す。
  - `k` 段に連続列を分け、最大段幅を抑える。本文ではYokan Party的な考え方とされている。
  - 推定 `W+H` が最小の段数・分割を選ぶ。
- 焼きなまし
  - 近傍は `rot[i]` の反転。
  - 変更後は、初期段数の近傍だけ再評価する。
  - 改善または温度に応じた確率で採択すると考えられる。

### 操作・クエリ・出力選択

- 各提出は全箱を置く。
- 段の先頭は `p i, rot, U, -1`。
- 同じ段の2個目以降は `p i, rot, U, i-1`。
- 1投目では横幅基準を変えて `T` 回提出する。
- 2投目では焼きなましで得た複数候補を提出する方針と読み取れる。

### 時間配分・パラメータ

- 1投目の横幅乱択範囲は、理想値の `±10^5` と書かれている。
- 2投目の焼きなまし評価では、探索段数を初期段数の `±2` に絞る。
- 推定や複雑な配置シミュレーションをしないため、時間は主に回転近傍の再評価に使える。

## 実装上重要な断片

```text
build_rows(width_limit, rot):
    rows = []
    cur = []
    cur_width = 0
    for i in 0..N-1:
        side_w, side_h = rotated_size(i, rot[i])
        if cur is not empty and cur_width + side_w > width_limit:
            rows.push(cur)
            cur = []
            cur_width = 0
        cur.push(i)
        cur_width += side_w
    rows.push(cur)
    return rows

emit(rows):
    for row in rows:
        first = true
        for i in row:
            base = -1 if first else i - 1
            print(i, rot[i], U, base)
            first = false

anneal_rotation:
    i = random rectangle
    flip rot[i]
    evaluate only row_count around initial_row_count +- 2
    accept or rollback
```

## この解法の本質

問題の難しさを、操作制約をさらに強くすることで捨てている。`U` と直前基準だけにすれば、配置はほぼ「番号順の段組み」になる。これは上位の自由なパッキングより弱いが、インタラクティブな誤差や予想外の接触に強く、実装も短い。

もう1つの本質は、`W+H` 最小化を正方形外形と段幅均等化に翻訳している点である。厳密な長方形パッキングを解かずとも、連続列を均等な段へ分けるだけでそれなりに強い形が得られる。

## 真似するならまず実装する部分

最初に実装するなら、この解法が最も軽い。`U` のみ、段先頭 `-1`、同段内 `i-1` として、目標幅で段分けするだけでよい。次に、段数を全探索して最大段幅を均等化する。最後に、回転反転の山登りまたは焼きなましを入れる。

## 注意点・未理解点

- 提出 #60618928 では、`Input`、`Square`、`Placement`、`Output` を持ち、`solve` が段数 `div_num` を全探索して最良を選ぶ。`annealing` は回転列と段数を近傍にし、`T0=2e3`, `T1=6e2` の温度で回転反転を受理する。
- 推定を全く行わないので、観測誤差が大きいケースでは回転や段幅判断がずれる。
- `U` と `i-1` に制限するため、上位解法のような隙間活用はできない。
- 回転を1個変えると段分割全体が変わる可能性があり、差分評価を雑にすると遅くなる。
- 段数 `±2` の制限は高速化には効くが、大きな回転変更後の最適段数を見逃す可能性がある。
