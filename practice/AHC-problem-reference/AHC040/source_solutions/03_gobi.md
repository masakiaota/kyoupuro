## 解法の全体像

`T-10` ターンを各箱単体の計測に使い、箱ごとに複数サンプルを得て平均サイズを更新する。残り10ターンのうち6ターンはルールベースの保険解を提出し、最後の4ターンは正方形容器へのビームサーチ解を提出する。

ビームサーチでは、全箱を一辺 `limit_side` の正方形枠内に収められるかを判定する。`limit_side` は、理論的な正方形一辺長に係数を掛けた値として扱い、その係数を `1.0..1.4` で二分探索する。成功したサイズのうち良いものから複数解を残し、壊れ対策として4回提出する。

## 主要アイデア

- まず単体クエリを繰り返し、各箱サイズの標本平均を作る。
- スコア上有利な正方形外形を仮定し、容器サイズを二分探索で詰める。
- 二分探索の判定関数を「その容器にビームサーチで全箱を置けるか」にする。
- ビームの遷移は、回転、方向、隣接箱を全列挙する。
- 重複盤面はZobrist hashで削る。
- 推定誤差で実際には通れない隙間を通る配置が壊れやすいため、`2sigma` 程度の危険判定で遷移を捨てる。
- ビームが壊れるケースに備え、短時間のルールベース解を6パターン先に提出する。

## 最終コードの構造

### 状態表現

- `GoodsInfo`
  - 箱IDと推定サンプル列 `est_values`。
  - `get_goods()` はサンプル平均を取り、`10000..100000` に正規化する。
- `Goods`
  - 箱ID、現在の `Rect`、回転状態、`w+h`。
- `Command`
  - `id`, `is_rotate`, `dir`, `adjacency_id`。
  - `encode/decode` で16bitに圧縮し、ビーム状態の操作列に持つ。
- `BeamState`
  - 配置済み箱の左上・右下座標列。
  - 操作列 `ans`。
  - `zobrist_hash`。
  - 原点から右下座標への距離二乗和 `dist_pow2_sum`。

### 観測・制約・入力の扱い

- `Input` は `goods_list` とクエリ済み回数を持つ。
- `single_query(id)` は箱1個だけを出し、返ってきた `W,H` をその箱のサンプルとして追加する。
- サンプル数は若いIDを優先しつつ均等になるよう循環する。若いIDは後続配置の基準になりやすいため重要度が高いという意図が記事脚注にある。
- 信頼区間風の長さは `coeff / sqrt(sample_num) * sigma` で計算する。
- 実際の配置判定では、置く箱側と配置済み箱側にそれぞれ `2sigma` 系の補正を入れて危険域を検出する。

### 評価関数

- ビームの前半80%:
  - `dist_pow2_sum` を小さくする。箱を原点側へ詰め、隙間を抑える意図である。
- ビームの後半20%:
  - `dist_pow2_sum + calc_score() * 1e8`。
  - `calc_score()` は外接 `W+H`。大きな係数で最終スコアを優先し、距離和はタイブレークに近い。
- 二分探索の成功判定:
  - `limit_side` 内に全箱を置けるビーム状態が空でないこと。
- 最終出力候補:
  - 成功したビーム結果は `W+H` で並べ、上位2つを保持する。これを二分探索中の過去ベストと合わせて最大4つ残す。

### 探索・構築・更新

- 単体推定
  - `while queried_num < T-10` の間、箱IDを循環しながら1個だけ配置する。
- 保険貪欲
  - 係数 `1.00, 1.05, ..., 1.25` の6通りで正方形一辺を決める。
  - 箱を縦長にし、1行ずつ横幅いっぱいになるまで `U` で前の箱に沿わせる。
  - 1つ上の行の右端に差し込める場合はそこを使う。
  - 最終行が短い場合は横長モードにする。
- ビームサーチ
  - `limit_side = theoretical_side * coeff`。
  - 各深さ `ni` でビーム幅まで状態を残す。
  - 遷移は `adjacency_id in None or 0..ni-1`, 回転2通り, `U/L`。
  - `calc_putting_rect` で問題と同じ停止位置を計算する。
  - 危険接触、隣接指定箱まで届かない操作、正方形枠超過を捨てる。
  - 各層でZobrist hashにより同一盤面を除外する。
- 二分探索
  - `coeff` を `1.0..1.4` で二分探索する。
  - 成功なら上側を下げ、失敗なら下側を上げる。
  - 時間 `2700ms` を超えたら探索を打ち切る。

### 操作・クエリ・出力選択

- 先に単体計測を大量に行う。
- 次に保険貪欲解を6回出力する。
- 残り4回でビーム由来のベスト候補を出す。候補が足りない場合は `0` 個配置を出す。
- 問題のスコアは最小ターンなので、保険解と攻めたビーム解を混ぜる構成になっている。

### 時間配分・パラメータ

- 推定: `T-10` ターン。
- 保険: 6ターン。
- ビーム: 4ターン。
- ビーム幅: `N=30` で最大1250、`N=100` で最小100へ線形に下げる。
- ビーム打ち切り時刻: `2700ms`。
- 二分探索係数範囲: `1.0..1.4`。
- 保険係数: `1.00..1.25` を0.05刻み。
- 危険判定係数: 置く箱側・配置済み側ともにおおむね2.0。

## 実装上重要な断片

```text
single_query_phase:
    while queries < T - 10:
        output only rectangle id
        add measured W,H to est_values[id]
        id = (id + 1) mod N

beam_check(limit_side):
    states = [empty]
    for id in 0..N-1:
        next = []
        for state in top states:
            for base in None + placed_ids:
              for rotate in {0,1}:
                for dir in {U,L}:
                    rect = simulate(command)
                    reject if danger, not reaching base, or out of square
                    push unique hash
        keep states sorted by evaluate()
    return states is not empty

binary_search:
    coeff = mid(lo, hi)
    if beam_check(theoretical_side * coeff) succeeds:
        save best candidates
        hi = coeff
    else:
        lo = coeff
```

## この解法の本質

この解法は、サイズ推定の高度化よりも「壊れにくい探索問題へ変換する」ことを重視している。正方形容器という強い外枠を置くことで、評価を難しい充填率そのものではなく、枠内に置けるかどうかへ変える。二分探索とビームを組み合わせることで、実装しやすい判定問題として詰め込みを進めている。

また、不確実性に対しては保険を明確に分けている。ビーム解は強いが壊れる可能性があるため、先に堅いルールベース解を複数提出し、最後に攻めた解を4つ出す。スコアが全ターンの最小値であることを素直に利用している。

## 真似するならまず実装する部分

最初に実装するなら、単体計測による平均更新と、保険貪欲だけでよい。これだけでも記事では224位相当の方針になっている。次に、正方形枠を固定したビーム判定を作る。二分探索はその後でよく、危険判定とZobrist hashはTLEや壊れが目立ってから入れると理解しやすい。

## 注意点・未理解点

- 単体計測は分かりやすいが、複数箱をまとめて測る上位解法より情報効率は低い。
- 危険判定は経験的であり、`2sigma` の係数を変えると成功率と探索幅のトレードオフが変わる。
- `dist_pow2_sum` は実装しやすいが、なぜ最良の中間評価になるかは記事でも経験寄りの説明である。
- ビームが失敗した場合、係数を上げる二分探索になるが、時間制限により十分な回数試せないケースがある。
- `undo` は `put_goods_list.len()` からIDを復元しており、順番固定に依存する。順番を入れ替える問題へ流用すると壊れる。
