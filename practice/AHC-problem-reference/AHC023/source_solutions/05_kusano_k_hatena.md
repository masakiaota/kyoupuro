## 解法の全体像

全域木を作り、その部分木を1つの領域として切り出す。各領域では、期間をいくつかの区間に分け、その区間に作物を割り当てる。期間の区切り方を焼きなましで改善し、作物割当は「長い作物から、なるべく短くぴったり入る区間へ入れる」貪欲で行う。さらに、通路として使っている木上のセルにも、到達イベントを邪魔しない期間だけ後処理で作物を詰め込む。

公開コードは、記事の「領域の広さと1区画あたりスコアを見積もり、その見積もりで木DPにより部分木を領域化する」という説明を実装している。木候補を複数作り、部分木を採用するか子部分木へ分けるかを DP 的に決める。時間方向の区切りは焼きなましで、追加・削除・移動の3近傍を使う。

## 主要アイデア

- 一毛作なら、出入口から近い順に収穫月が早い作物を置けばよい。
- 複数作をするには、空間方向に領域を区切り、領域ごとに時間方向を分割する。
- 全域木の部分木を領域とすれば、領域内の奥・手前関係を木上の深さで扱える。
- 領域サイズだけで切ると悪い場合があるため、サイズごとの期待スコアを経験式で見積もり、木DPで切り出しを決める。
- 期間の区切りは焼きなましで改善する。
- 作物割当は、長い作物を優先し、入る区間のうち最も短い区間へ入れる。
- 焼きなまし中の局所更新では割当が偏るため、後半で全体再割当を行う。
- 最後に、通路セルにも作付け可能な期間を探して追加する。

## 最終コードの構造

### 状態表現

- `Node`:
  - `x, y`: セル座標
  - `d`: 親から来た方向
  - `cn`: 部分木サイズ
  - `ln`: 葉数
  - `C`: 子ノード配列
- `ST`: 領域として採用された部分木根の配列。
- `SP[s]`: 領域 `s` の時間区切り。`0` と `T` を含む昇順配列。
- `C[s][p]`: 領域 `s` の区間 `p=[SP[s][p], SP[s][p+1])` に割り当てた作物 ID 配列。
- `used[k]`: 作物使用済みフラグ。
- `score`: `25*(D-S+1)` の合計。`HWT=40000` なので問題スコアへの変換係数が25になる。
- `SPbest`, `Cbest`, `score_best`: 焼きなまし中のベスト状態。

### 観測・制約・入力の扱い

- `S,D` は0-index化する。
- 水路を見て、隣接可能な方向だけ木構築時に辿る。
- 出入口セル `(0, y0)` を根にする。
- 作物は長さ降順の `I` と、収穫月別の `I2[D]` を作る。
- 領域内の配置では、部分木セルを深さ昇順に並べ、区間内の作物を `D` 昇順で割り当てる。手前ほど早く収穫されるようにする意図である。

### 評価関数

- 領域切り出しの見積もり:
  - コードでは `int((98.077 - cn*0.5668) * 25 * cn)` を部分木サイズ `cn` の領域スコア見積もりとしている。
  - 各ノードで「この部分木を1領域にする」か「子の採用領域を合算する」かを比較する。
- 焼きなましの実スコア:
  - 採用作物ごとに `25*(D_i-S_i+1)` を加算する。
  - 区間に入る条件は `SP[s][p] <= S_i` かつ `D_i < SP[s][p+1]`。

### 探索・構築・更新

- 木構築:
  - 16通りの木を試す。
  - 最初の4回は固定方向順、次は親方向、以降は乱数方向順で探索する。
  - BFS/DFS 的に未訪問セルを木へ追加する。
- 領域切り出し:
  - 後行順に部分木サイズを計算する。
  - 各ノードで子のスコア合計と、このノード部分木を単一領域にした見積もりを比較し、高い方を採用する。
- 初期時間区切り:
  - 各領域に `0,T` とランダムな7個の切れ目を入れてソートする。
- 初期割当:
  - 作物を長さ降順に見て、容量があり、作物区間を含められる最短区間へ割り当てる。
- 焼きなまし近傍:
  - 追加: ある区間内に新しい切れ目を入れ、元区間を2区間に分けて再割当。
  - 削除: 内部切れ目を消し、隣接2区間を1区間にマージして再割当。
  - 移動: 内部切れ目の位置を動かし、左右2区間を再割当。
- 採択:
  - スコア改善は必ず採用。
  - 悪化は事前計算した exp テーブルで確率採用。
  - 温度は `temp = 100*(1-time)`。
- 全体再割当:
  - ベスト更新後、経過時間が半分を超えていれば全 `C` と `used` を空にし、長さ降順貪欲で全体を詰め直す。

### 操作・クエリ・出力選択

- ベスト状態から、領域ごと・区間ごとの作物をセルに配置する。
- 各領域の部分木セルを深さ順に並べ、区間内作物を収穫月昇順にして対応させる。
- その後、「置けるところに詰め込む」後処理を行う。
  - 領域根を `st` としてマークする。
  - 木を DFS し、子部分木の植え付け・収穫イベントを `A[cell][2*T]` に集約する。
  - 自セルの既存作物の占有月を `B[T]` に持つ。
  - `canplant` が真の通路セルで、子孫のイベント `A` と自セル占有 `B` を塞がない未使用作物を追加する。
  - 直前の到達イベントから植え始められる場合は、植え月を `S` より前へずらす。

### 時間配分・パラメータ

- 制限時間は `TIME=1.9` 秒として管理。
- 焼きなましは `iter % 0x100 == 0` で時刻更新。
- 初期区切りは各領域7個。
- 木候補は16本。
- `my_exp` は `exp` を1024個のテーブルにして高速化。
- 乱数は `xor64`。

## この解法の本質

空間は全域木の部分木、時間は区間分割として扱う。部分木を領域にすれば、領域内のアクセス順は木の深さで単純化できる。どの部分木を領域にするかは経験的なサイズ別スコア見積もりで DP 的に決め、時間方向だけ焼きなましで詰める。固定通路型の実装難度を保ちながら、領域切り出しと時間区切りを最適化している点が強い。

## 真似するならまず実装する部分

まずは出入口根の全域木を1本作り、適当な部分木サイズ閾値で領域を切る。各領域に固定個数のランダム切れ目を入れ、長さ降順の作物を最短フィット区間に入れる。次に、切れ目追加・削除・移動の焼きなましを入れる。最後に、木DP による領域切り出しと通路セルへの後処理作付けを追加するとよい。

## 注意点・未理解点

- 領域サイズから期待スコアを出す係数 `98.077` と `0.5668` は経験的なフィットであり、記事の図からの見積もり以上の導出はコードからは分からない。
- 区間再割当は長さ降順貪欲なので全体最適ではない。後半の全体再割当が効く。
- 通路セルへの追加作付けはイベント配列 `A` と占有配列 `B` の条件が壊れやすい。
- 木候補や初期切れ目の乱数依存があるため、再現には乱数・時間配分の調整が必要である。
