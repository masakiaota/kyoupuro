## 解法の全体像

公式ページ自体は解説リンク集に近い。解法として最も具体的なのは chromate00 の "Simplistic approach" で、問題を「どの区画を作付候補にするか」と「候補区画に作物区間を割り当てるか」に分ける。

前半では、常に空ける区画集合を連結支配集合として扱う。作付候補 `C` は、空き集合 `D = V \ C` に隣接し、かつ `D` が連結であれば、作物を植える・収穫するための到達性を単純化できる。後半では、候補区画数を同一機械数 `m` と見なし、作物の時間区間を重ならないように機械へ割り当てるスケジューリング問題として解く。

公式動画では、サンプルコードの限界、同月の植え付け・収穫順序の判定、木の葉や通路を使った実装、上位解法が固定通路を減らしていたこと、`S` の前倒し自由度が重要であることが話されていた。

## 主要アイデア

- 作付区画と常時通れる区画を分けると、到達性制約がかなり単純になる。
- 作付候補を増やす問題は、空き区画側の連結支配集合を小さくする問題として見られる。
- 空き集合から関節点でない低次数頂点を削って作付候補に回す貪欲で、実装しやすい近似解を作る。
- 固定された作付候補数 `m` に対する作物割当は、区間スケジューリングを `m` 台の同一機械へ詰める問題になる。
- Arkin and Silverberg の区間スケジューリング手法を使うと、最大クリーク数と最大クリークの個数を通じて min-cost flow に落とせる。
- この問題では時間 `T=100` が小さいため、理論上の `O(n^2 log n)` より軽く `O(TK log K)` 程度として扱える、という説明である。

## 最終コードの構造

Browserで読めたchromate00提出 `45448511` と公式ページ・動画から読める構造である。

### 状態表現

- グリッドを水路を除いた無向グラフ `G=(V,E)` として持つ。
- `D`: 常時空ける区画集合。出入口を含み、誘導部分グラフが連結である必要がある。
- `C=V\D`: 作付候補区画集合。各頂点が `D` に隣接していれば、植え付け・収穫時に隣接通路から入れる。
- 作物は `(S_k, D_k, weight=D_k-S_k+1)` の区間として持つ。
- スケジューリング側では、作付候補区画数 `m=|C|` を機械数として扱う。

### 観測・制約・入力の扱い

- `h`, `v` から区画間グラフを作る。
- 出入口の区画を空き集合 `D` に含める。
- 固定された `D` が連結か、各 `C` が `D` と隣接するかを保つ。
- 同月の植え付け・収穫順序は、公式動画では「植える前または収穫後の状態で到達できるか」を判定すればよい、という話が出ていた。ただしこれはサンプルコードや検証観点の話で、chromate00 の固定通路解ではより単純化される。

### 評価関数

- 作付候補集合構築では、`|C|` を大きく、同値に `|D|` を小さくする。
- スケジューリングでは、採用作物の `sum(D_k-S_k+1)` を最大化する。
- 最終スコアは `10^6 * sum duration / (HWT)` であり、`H=W=20,T=100` なので `sum duration * 25` に対応する。

### 探索・構築・更新

- 連結支配集合の貪欲:

```text
D = all cells
C = empty
while true:
    candidates = vertices in D that are not articulation points of D
    if no useful candidate:
        break
    choose v in candidates with minimum degree in D
    move v from D to C
```

- `D` から関節点でない頂点だけを削るので、`D` の連結性を壊しにくい。
- 低次数頂点を削ることで、周囲に空き集合が残りやすく、`C` が `D` に隣接する条件を保ちやすい。
- 作物割当は、区間集合を `m` 台の同一機械に入れる重み最大化として min-cost flow へ変換する。

### 操作・クエリ・出力選択

- 固定通路解では、各作付候補区画に割り当てられた区間をその区画の作物列として出力する。
- 植える月は `S_k` 以前ならよい。固定通路があるため、各候補区画への到達性は他候補に依存しない。

### 時間配分・パラメータ

- chromate00 の本文では具体的パラメータはほぼない。
- スケジューリングは `K` が概ね 4000 から 7000、`T=100` であることを利用して十分高速と説明されている。
- 公式動画では、サンプルコードを作物数だけ増やすと 190 個前後で TLE しそう、という趣旨の話があり、愚直な到達性判定が重いことが強調されていた。

## 実装上重要な断片

```text
build_graph(h, v):
    for each cell:
        add edge to neighbor if inside grid and no canal

make_candidate_cells:
    D = all cells
    repeat:
        recompute articulation in induced graph D
        pick non-articulation cell with small degree
        if removing it keeps every planted cell adjacent to D:
            D.remove(cell)
            C.add(cell)

schedule_crops(C):
    m = len(C)
    build interval scheduling / min-cost flow model
    choose crop intervals maximizing total duration on m machines
```

## この解法の本質

到達性制約を正面からシミュレーションせず、常時空いている連結集合を先に確保することで、空間問題と時間問題を分離している。上位解法ほど高得点ではないが、問題の難しい相互依存を「連結支配集合」と「同一機械区間スケジューリング」という既知の形へ落とす点が本質である。

## 真似するならまず実装する部分

まずは固定通路を作り、作付候補をその隣接セルに限定する実装から始めるとよい。厳密な min-cost flow まで入れず、候補区画ごとに終了月順・長さ順の貪欲で作物を割り当てるだけでも問題の構造を理解できる。次に、関節点でない頂点を削る貪欲で通路を細くする。
