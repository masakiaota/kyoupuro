## 解法の全体像

各ロボットをまず担当領域の始点へ移動させ、その後は 3 個のボタンだけでジグザグ移動を繰り返す方針である。ジグザグは横方向の往復と縦方向の 1 歩を組み合わせた掃除パターンで、向きは 8 通りある。各ロボットについて、ジグザグ開始点と向きの組を山登りで改善し、全体の塗れたマス数を最大化する。

ジグザグだけでは開始位置が合わないので、残り 7 個のボタンを使って初期位置からジグザグ開始点まで移動する。既存ボタンで全ロボットのうち最も遠いロボットの距離を縮められるならそれを使い、なければ未使用ボタンに新しい行動ベクトルを割り当てる。ジグザグの移動回数や開始点・向きを時間内で調整し、全マスを塗れる構成を探す。

## 主要アイデア

- 塗りの本体を「3 ボタンで実行できるジグザグ」という固定マクロに落とす。
- ロボットごとにジグザグ開始点と 8 通りの方向パターンを持つ。
- 評価値はシミュレーションで塗れたマス数とし、同点なら初期位置から開始点が近いものを優先する。
- 各ロボットの開始点・方向を全通り試す座標降下的な山登りで改善する。
- 全マスを塗れない場合は、ジグザグの移動回数を増やして再探索する。
- 初期移動では、ジグザグ用 3 ボタンを固定し、残り 7 ボタンを距離減少用に貪欲に割り当てる。

## 最終コードの構造

以下は記事本文から推測できる実装構造である。キャッシュは本体前で切れており、実装本体は確認できていない。

### 状態表現

- `start[k]`: ロボット `k` のジグザグ開始点。
- `pattern[k]`: ロボット `k` のジグザグ方向パターン。横方向 2 通り、縦方向 2 通り、曲がり方 2 通りで合計 8 通りと考えられる。
- `zigzag_len`: 横移動回数、縦移動回数、または 1 周期内の長さ。
- `button[b][k]`: ボタン `b` を押したときのロボット `k` の行動。
- `ops`: 押すボタン列。
- `visited`: 全ロボットの軌跡で塗れたマス集合。

### 観測・制約・入力の扱い

- 壁を反映した移動シミュレーションが必要である。
- 初期位置から開始点までの距離は、壁を考慮した最短距離として扱うのが自然だが、記事では距離計算の詳細までは明記されていない。
- 出力操作数は最大 `2N^2 = 1800` なので、ジグザグ長と初期移動の合計がこれを超えないようにする。

### 評価関数

- 基本評価は、ジグザグをシミュレーションしたときの塗れたマス数。
- 同点時は、初期位置から開始点までの距離が短い方を優先する。
- 最終的には全マスを塗れる構成の中で操作回数を短くすることがスコアに直結する。

### 探索・構築・更新

- ジグザグ移動回数を仮定する。
- 各ロボットについて、開始点と方向パターンの候補を全通り試す。
- そのロボットだけ候補へ差し替えたときの塗れたマス数を比較し、最良候補を採用する。
- 更新がなくなるまで繰り返す。
- 全マスを塗れない場合は、ジグザグ移動回数を増やして再試行する。

### 操作・クエリ・出力選択

- ジグザグ用に 3 ボタンを確保する。
- 残り 7 ボタンで、各ロボットを初期位置から担当開始点へ運ぶ。
- 初期移動中は現在位置から開始点までの距離を見て、最大距離を減らすボタンを押す。
- 既存ボタンで改善できないときは、新しいボタンに各ロボットの行動を割り当てる。
- 全ロボットが開始点に着けば、固定したジグザグ操作列を続ける。

### 時間配分・パラメータ

- ジグザグの横移動回数・縦移動回数を調整対象にする。
- 山登りが止まったら長さを増やして再試行する。
- 時間がある限り、ジグザグ長、開始点、方向パターンを変えて改善する。

## 実装上重要な断片

```text
search_zigzag():
    choose tentative zigzag length
    initialize start[k], pattern[k]
    while improved:
        improved = false
        for each robot k:
            best = current
            for each cell s:
                for each pattern p in 8 patterns:
                    score = simulate_with(k replaced by (s, p))
                    tie_break by distance(initial[k], s)
                    update best
            if best improves:
                apply best
                improved = true
    if all cells covered:
        build_initial_move_buttons()
    else:
        increase zigzag length and retry
```

```text
build_initial_move_buttons():
    reserve 3 buttons for zigzag
    while some robot is not at start[k]:
        d = max distance(pos[k], start[k])
        if existing free-button assignment can reduce d:
            press it
        else if unused button remains:
            assign per-robot actions that move robots closer
            press it
        else:
            fail and retry with another zigzag plan
```

## この解法の本質

単一コントローラ問題を、全ロボットが共有できる高頻度マクロと、個別性を吸収する低頻度の初期移動に分解している点が本質である。ジグザグはグリッド全体を少ない重複で覆いやすく、しかも 3 ボタンで表現できるため、残りのボタンを配置調整へ回せる。この「塗る形を先に強く制限し、ボタン資源を節約する」考え方が強い。

## 真似するならまず実装する部分

まず 3 ボタンのジグザグシミュレータを作り、各ロボットに開始点と 8 方向パターンを与えて塗れたマス数を評価する部分を実装するのがよい。初期移動ボタンの最適化は後回しにして、最初は各ロボットを開始点へ最短路で動かす専用操作を仮に作って、ジグザグ配置の良し悪しを確認する。その後、残り 7 ボタンに落とし込む貪欲を追加する。
