## 解法の全体像

インタラクティブに目的地を推定して逐次妨害するのではなく、事前に強い迷路盤面を設計しておく方針である。最初は入口から花までの長い一本道を焼きなましで作り、その道沿いに「目的地に選ばれたときだけ入る未探索の袋小路」を多数発生させる。袋小路の価値を期待訪問回数で評価し、袋小路間の距離も含めた推定スコアを焼きなましの評価値にする。

最終的には一本道だけでは往復距離が足りないと判断し、入口付近で盤面を大きく分断する構造へ移行する。入口から早い段階で左右または上下の両側へ伸びる2本の長い経路を作り、冒険者が目的地を変えるたびに両端を往復しやすいようにする。分断用の初期経路は複数パターンをビームサーチで作り、詰みやすい候補を短い焼きなましで補正する。その上で、メインの焼きなまし、花の隠蔽、袋小路内部への追加木、未使用領域の解放を重ねる。

## 主要アイデア

- 冒険者の目的地推定より、どの位置で何が見えるかを事前設計するほうが支配的だと見る
- 目的地に選ばれていない限り通らない袋小路を作り、後から戻らせる
- 袋小路の期待訪問回数を、深さ `n` に対する調和級数に近い値で評価する
- 袋小路間の距離の重み付き和で、目的地変更を繰り返すときの総移動距離を近似する
- パスの一部を切り取り、ランダムDFSでつなぎ直す焼きなましを行う
- パス上セルに連続値の時刻を割り当て、木がいつ視認されるかを全体再計算せず近似更新する
- 花は「花自身が目的地に選ばれた場合以外は見えない」状態を強く要求し、事故マス数で減点する
- 一本の長い袋小路より、入口付近で盤面を分断して両端を往復させる構造を重視する
- 分断の初期経路は複数パターンと回転を試し、面積バランス・経路の近さ・ジグザグ性で評価する
- 大きい袋小路には内部に追加木を置き、局所シミュレーションで期待訪問回数を増やす

## 最終コードの構造

以下は記事本文から読み取れる実装構造である。キャッシュは本体前で切れており、実装本体は確認できていない。

### 状態表現

- 盤面は、初期木、追加予定の木、最終的に空ける通路を持つグリッドで表す
- 主状態は、入口から伸びるパス列、または入口付近で分岐する2本の主経路である
- 各パスセルには「パス上の時刻」を `double` で持たせ、周辺木がどの時点で視認されるかを比較できるようにする
- 袋小路候補は、入口セル、未探索領域、深さ、期待訪問回数、他袋小路までの距離を持つ
- 花周辺については、花を見てしまう危険マス数、花の直前で見せるべきマス、撤去候補の木を別に評価する
- 分断構築では、2本の主経路、経路に挟まれた領域、既存木で詰む位置、回転パターンを状態に含める

### 観測・制約・入力の扱い

- 初期の木は固定障害物であり、追加木や通路設計はそれを避ける
- 初手で完成盤面に必要な追加木を置く静的方針として扱うため、確認済み制約は入口以外に木を置かないことを主に見る
- 入口から花までの空き経路は常に残す
- 木が視認された時点で冒険者の暫定地図がどう分断されるかを局所的に判定し、袋小路が成立するかを見る
- 花は終端に置き、花の直前で曲がること、花の二つ前に来た時点で必要な周辺マスが見えていることを重視する
- 木を撤去して花周辺の必要マスを見せる場合でも、短絡路が発生しないか確認する必要がある

### 評価関数

- 袋小路の期待訪問回数は、直進BFSで測った深さ `n` に対して `1 + 1/2 + ... + 1/n` に近い値を使う
- 実際には未探索エリアの面積にも小さな係数を足して、深いだけでなく広い領域も少し評価する
- 袋小路集合 `D` について、各袋小路 `i` の重み `w_i` と距離 `d(i,j)` から、目的地変更後の平均移動距離を重み付き距離和で近似する
- 主経路の長さ、ジグザグ性、左右または上下の面積分割の均等さも評価に入れる
- 花が目的地以外で見える危険マスが `m` 個ある場合、花が早期発見される確率が上がるため強く減点する
- 分断初期経路の評価では、2本のパスが離れすぎないこと、早く反対側へ到達すること、残りを伸ばせることを評価する

### 探索・構築・更新

- 初期は長いパスを作り、その両脇に木を置くと仮定して袋小路候補を評価する
- パス焼きなましの近傍は、パスの一部をランダムに切り取り、ランダムDFSで再接続する操作である
- 受理時は切り取った区間だけ時刻を等分配し、100回程度受理するごとに時刻を全体再計算する
- 盤面分断では、入口から左右方向へ分岐するパターン、入口からすぐ下へ伸びるパターン、左右対称・回転パターンをビームで探索する
- 分断経路候補が木で詰みそうな場合、道を長くすることだけを考える短い焼きなましで救済する
- 袋小路内部への追加木は、各袋小路でランダムシミュレーション50回程度により候補を評価し、200反復程度の焼きなましを行う
- 袋小路にはならないが目的地次第でスルーされる領域は、木を撤去して未使用領域として解放する

### 操作・クエリ・出力選択

- 基本は完成盤面を先に決め、最初の配置機会で追加木をまとめて出力するタイプの解法である
- 以降の冒険者の目的地推定や逐次対応は主戦略ではない
- 出力対象は、最終盤面で木にしたいマスから初期木と入口・花・主経路などの空きマスを除いた集合である
- 花を目的地以外で視認させる危険が残る候補は採用しない、または評価で大きく落とす

### 時間配分・パラメータ

- 分断用のビーム幅は太くなくてもよいとされる
- 初期経路候補は、入口から左、入口からすぐ下、入口から右、および回転パターンを試す
- パスの時刻は100回受理ごとに再計算する
- 袋小路内部への追加木は、各袋小路でランダムシミュレーション50回、焼きなまし200反復程度
- 未探索エリア面積には `0.01` 程度の係数を足したとある
- 細かな係数、温度、ビーム幅、受理式は記事からは分からない

## 実装上重要な断片

袋小路を作る木の局所判定:

```text
is_gate_tree(c):
    around = 3x3 neighborhood of c
    mark cells whose blocking tree is visible earlier than c
    mark c as blocked
    return remaining white cells are split into at least two components
```

袋小路重みの計算:

```text
dead_end_weight(entry):
    depths = straight_move_bfs_inside_hidden_area(entry)
    max_depth = max(depths)
    return harmonic(max_depth) + 0.01 * hidden_area_size
```

パス焼きなまし:

```text
transition(path):
    [l, r] = random segment
    erase path[l:r]
    new_segment = random_dfs(path[l-1], path[r+1])
    if new_segment exists:
        replace and redistribute timestamps in [l, r]
```

花事故の減点:

```text
danger = count cells whose selection reveals flower before flower is target
score *= expected_survival_factor(danger)
```

## この解法の本質

この解法の本質は、冒険者を「未知マスをランダムに目的地へ選び、見えている地図上の最短路を歩くエージェント」として直接追うのではなく、視認情報を制御する迷路構造へ落とす点である。強い盤面は、単に長い通路を持つ盤面ではない。冒険者に「今はここへ行く必要がない」と分からせる未探索領域を残し、目的地に選ばれた瞬間だけ既知経路を大きく戻らせる盤面である。

また、花の早期発見を確率的な致命傷として扱っている点も重要である。スコアの平均は、花が目的地に選ばれるまでどれだけ候補を消費できるかに強く依存する。袋小路の期待訪問回数、袋小路間距離、花事故数を同じ評価の中で扱うことで、局所的に見栄えのよい迷路ではなく、実際に目的地変更を長引かせる迷路を探索している。

## 真似するならまず実装する部分

まずは、完成盤面を初手で作る静的解法として、入口から伸びるジグザグ主経路と花を終端に置く構築を実装する。次に、主経路沿いの木を1つ外したときに未探索袋小路ができるかを局所判定し、袋小路の深さに調和級数の重みを付ける。

その後、パスの一部をランダムDFSでつなぎ直す焼きなましを入れると、記事の中心部分を小さく再現できる。上位化するなら、入口付近で盤面を二分する初期経路ビーム、花事故判定、袋小路内の追加木探索、未使用領域の解放を順に足すのがよい。
