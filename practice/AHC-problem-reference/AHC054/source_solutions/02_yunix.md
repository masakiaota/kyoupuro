## 解法の全体像

ルールベースで完成盤面候補を多数生成し、公式テスター相当のシミュレーションを複数回走らせて平均スコアの良い盤面を選ぶ方針である。最終盤面の狙いは、盤面を左右の2部屋に分け、両部屋の移動に長い外周または中央経路を使わせ、冒険者を右往左往させることにある。

単に左右を壁で分断すると、冒険者が抜け道を探して中央付近を大量に探索してしまう。そこで、最初に中央を縦断するようなルートを見せ、左右を移動するには長いパスが必要だと冒険者の地図上でも分かるようにする。左右の部屋内部には階段状パターンを多く詰め、目的地に選ばれたときだけ奥が観測される未探索マスを残す。花周辺には防御機構を作り、花が目的地に選ばれたとき以外に見えにくくする。

## 主要アイデア

- インタラクティブな目的地推定より、完成盤面の良し悪しとシミュレーション評価を重視する
- 左右2部屋に分断し、部屋間移動で長い経路を往復させる
- 冒険者にあえて木の配置を見せ、中央に抜け道がなさそうだと理解させる
- 部屋内には階段状の構造を置き、周囲を歩いても奥の未観測マスが残るようにする
- 階段状パターンはサイズ5から小さいものへ順に試し、追加木の少ないものを優先する
- 花の2方向を開口部として残し、近くを通りそうなときに開口部を塞ぐ防御機構を用意する
- 左右分断位置、外周パス長、階段配置順、花防御の開口方向に乱択を入れる
- 1盤面あたり20回程度のシミュレーションで平均スコアを評価する
- 悪い試行は20回すべてを回さず早期打ち切りする
- 花が目的地に選ばれる順番が偏らないよう、評価シミュレーションの乱数を調整する

## 最終コードの構造

以下は記事本文から読み取っていた実装構造である。キャッシュ実装は本文説明と大きく異なるため、差分は後述する。

### 状態表現

- 盤面グリッドに初期木、追加木、空きマス、入口、花を持つ
- 完成盤面候補は、左右を分ける中央構造、外周または部屋間パス、左右部屋内部の階段状パターン、花防御機構を含む
- 階段状パターンはサイズ1から5程度までのテンプレートとして持つ
- 各候補には、乱択パラメータ、配置済みパターン、シミュレーション平均スコア、途中打ち切り判定用の暫定平均を持つ
- 冒険者シミュレーションでは、現在位置、確認済みマス、目的地、暫定地図上の最短経路を持つ

### 観測・制約・入力の扱い

- 初期木を避けて追加木を置く
- 初手で多くの木を配置する静的構築に近いが、花周辺の開口部を後から塞ぐ限定的なリアクティブ要素も考慮されている
- 入口から花までの経路は残す
- 花が目的地でないのに視界に入る事故を避ける
- 中央分断は、冒険者が部屋間の移動経路を早期に理解できるよう、見せるべき木と隠すべき未探索マスを分ける
- 階段状構造では、目的地に選ばれていない奥のマスが観測されないことを期待する

### 評価関数

- 完成盤面候補に対し、冒険者の探索を20回程度シミュレーションし、得点の平均を評価値にする
- 花が序盤・中盤・終盤のどこで目的地に選ばれるかにより良い盤面が変わるため、評価用乱数を均等にばらけさせる
- 途中経過の得点が悪い候補は早期打ち切りし、評価回数を節約する
- 高速な近似評価として、左右往復回数、階段状構造数、部屋間パス長の積を見る案も試したが、精度不足だった
- 精度不足の主因として、花防御機構のレイアウトの良し悪しを近似評価に入れにくい点が挙げられている

### 探索・構築・更新

- 乱択で左右分断の形を決める
- 中央を縦断するルート、左右部屋、部屋間の長いパスを作る
- 左右部屋内に階段状テンプレートを大きい順に詰める
- 配置できたテンプレート領域を埋め、次のテンプレートを試す
- 花周辺に防御機構を置き、開口方向も乱択する
- 盤面を構築したら複数回シミュレーションし、ベスト盤面を保存する
- `N` が大きいほど1盤面のシミュレーションが重くなるため、数十から数百程度の盤面候補を試す
- 毎ターンBFSは重いので、新たな観測により既存最短ルートがブロックされた場合だけBFSする

### 操作・クエリ・出力選択

- 基本は完成盤面を作ってから、追加木集合を出力する
- 花の開口部を塞ぐ操作は、冒険者が花の近くを通りそうなタイミングに依存する限定的な逐次配置として扱われる
- 最終的に採用するのは、複数回シミュレーション平均が最も良い盤面である
- 評価時に花事故が多い候補や途中成績が悪い候補は捨てる

### 時間配分・パラメータ

- 階段状パターンはサイズ5から小さいものへ試す
- 盤面評価は20回シミュレーションの平均
- 悪い候補は途中で打ち切る
- 試行盤面数は `N` に依存して数十から数百程度
- 分断位置、外周パス長、階段配置順、花防御の開口方向をランダム化する
- 近似評価関数は試したが最終採用ではなく、シミュレーション評価が主である

## 実装上重要な断片

盤面候補生成:

```text
generate_board(seed):
    choose split position and long path parameters
    build central visible route
    create left/right rooms
    place staircase patterns from large to small
    install flower guard with random openings
    return board if entrance-to-flower path remains
```

階段テンプレート配置:

```text
for size in [5, 4, 3, 2, 1]:
    for pattern in randomized_patterns(size):
        if can_place(pattern, room):
            place pattern
            mark occupied area
```

評価の早期打ち切り:

```text
score_sum = 0
for q in 1..20:
    score_sum += simulate(board, q)
    if upper_bound_average(score_sum, q) < current_best:
        break
```

BFS抑制:

```text
if destination_path_still_valid_after_observation:
    continue along cached path
else:
    recompute shortest distances
```

## この解法の本質

この解法の本質は、冒険者を遠くへ行かせるだけでなく、「遠くへ行くしかない」と冒険者の暫定地図にも理解させる点である。左右分断そのものは強そうに見えるが、中央に抜け道があるかもしれない状態では、冒険者が部屋内を探索し尽くして未観測候補を失う。そこで最初に中央構造を見せ、無駄な探索を減らしたうえで、部屋間移動だけを長くする。

また、部屋内の階段状構造は、未観測マスを単に増やすのではなく「目的地に選ばれるまで見えない」形で残すためのテンプレートである。高度な評価関数を作れなくても、シミュレーションを信じて大量のルールベース候補を試すことで、構造の良し悪しを拾っている。

## 真似するならまず実装する部分

最初に実装すべきなのは、左右分断と部屋内階段テンプレートを持つ静的盤面生成である。入口から中央を縦断する見せるルートを作り、左右部屋の中に小さな階段パターンを詰め、花周辺を簡単にガードする。

次に公式テスター相当のシミュレーションを複数回走らせる評価器を作る。高速化は最初から凝りすぎず、既存最短路が壊れたときだけBFSするキャッシュを入れるとよい。上位化するなら、花防御の開口操作、評価乱数のばらけ、悪候補の早期打ち切りを足す。

## 実装確認（提出 69809775）

キャッシュ実装は、本文の左右2部屋・階段テンプレートを直接作る形ではなく、各セルの優先度 `prio` をSAして「開ける木構造」を作る静的解法である。`evaluate_plan` は入口から優先度キュー3本で開くセルを選び、親が2つ以上になるセルは開かない。最終的に開かなかった未確認セルを初手で木にする。

`evaluate_finish` は、花がopenでない、花親の次数が1でないなどを強く罰する。そのうえでopen/closed構造をhashしてキャッシュし、closedセルがどのopenセルから見えるか、木+外周の8近傍連結、見えた木による分岐確率をRollback Union FindとDFSで推定する。

近傍は2セルの優先度変更と、低スコア時の全優先度リセットである。温度は `N` で線形補間し、TLは約1.96秒。出力は `initial_trees` との差分ではなく、最終的にopenでないセルを追加木として1行で出し、その後 `-1` で打ち切る。本文の「動的に開口部を塞ぐ」方針とは実装の表現がかなり異なる。
