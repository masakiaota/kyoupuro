## 解法の全体像

出口セルだけに識別用の温度を固定し、それ以外のセルは周囲平均を反復して滑らかにする。計測では各ワームホールごとに出口候補の確率分布を持ち、観測値の確率を掛けてベイズ更新する。候補上位2つを分けやすい移動を選び、まず全ワームホールを粗く調べ、その後に確信度順で追加計測する2段階構成である。

最終回答は各ワームホールで最尤の出口を選ぶ。後半では、すでに十分高い確率で使われた出口を他候補から除外し、1対1対応に寄せる。

## 主要アイデア

- 出口セルを「固定セル」とし、そこだけ識別温度を直接与える。
- 固定セル以外は隣接4セルの平均化を多数回行い、配置コストを下げる。
- 観測値 m が真値 p から出る確率 `prob[p][m]` を事前計算する。
- 各ワームホールについて、出口候補ごとの確率 `nowprob[k]` を持つ。
- 計測後、候補出口 k の対応確率に `prob[P[pos[k]+move]][observed]` を掛けて正規化する。
- 次の移動は、候補上位2出口で観測温度差が大きくなる位置を選ぶ。
- 仮質問で全体を粗く並べ、本質問で残り回数を配分して確信度を上げる。

## 最終コードの構造

### 状態表現

- `pos`: 出口セル座標の配列。
- `space`: 出口セルかどうかの真偽表。
- `P`: L x L の温度配置。
- `sample[t]`: 真温度 t のとき、丸め・クリップ込みの観測値の期待値に近い値。
- `prob[p][m]`: 真温度 p のセルで観測値 m が出る確率。
- `movescore`: 候補移動 `(y,x)` の識別力を持つリスト。
- `nowprob`: 1つのワームホールについて、各出口候補の相対確率。
- `order`: 仮質問後の確信度、ワームホール番号、確率分布、最後の移動をまとめたもの。
- `preuse`: 高確率で割り当て済みとみなす出口集合。

### 観測・制約・入力の扱い

- `question(i,y,x,...)` はトーラス上で短い同値移動に直してから出力する。
- 計測は最大10000回なので、変数 `base` を残り回数として管理する。
- 観測値が得られたら、全出口候補について「その出口から同じ移動をしたセルの温度」が観測された確率を掛ける。
- 公式コードにはローカル用の隠し対応 `A` やノイズ生成がコメントとして残っているが、提出時はジャッジから観測値を読む。

### 評価関数

- 配置側は明示的な最適化ではなく、出口セル温度を固定した上で非出口セルを4近傍平均へ反復更新し、二乗差コストを下げる。
- 確率更新では `nowprob[k] *= prob[expected_temp][observed]` を行い、合計が100になるように正規化する。
- 移動選択の評価は、主に上位2候補の観測温度差である。コード上は `min(S*4, abs(temp0-temp1))` を大きくし、同点なら距離の小さい移動を選ぶ。
- `movescore` の事前スコアでは、出口セルを中心距離順に並べた列に対して、移動後温度と固定温度との差の変化が大きい移動を上位にする。

### 探索・構築・更新

- 固定温度は S と N に応じて2方式を切り替える。
- 比較的扱いやすいケースでは、中心に近い出口から順に温度を広い範囲で等間隔に割り当てる。
- 厳しいケースでは、低温側と高温側の2群に分ける。
- 非出口セルは1000回程度、4近傍平均に更新する。
- 仮質問:
  - 各ワームホールに最大30回、初手は移動なしで計測する。
  - 最大確率が95%を超えたら打ち切る。
  - 結果を確信度順に保存する。
- 本質問:
  - 仮質問で確信度が高い順に処理する。
  - 残り計測回数を残りワームホール数で割って上限を決める。
  - 閾値は基本98.8%、Sが大きい場合は99.7%。

### 操作・クエリ・出力選択

- 次クエリは、現在の上位2出口候補で温度差が大きくなる移動を候補移動リストから探す。
- 計測のたびに候補確率を更新し、閾値を超えたらそのワームホールの追加計測を止める。
- 最終的には `nowprob` 最大の出口を回答する。
- 確信度が68%を超えた出口は `preuse` に入れ、以降のワームホールでは確率を0にして重複を抑える。

### 時間配分・パラメータ

- 非出口セルの平均化反復: 1000回。
- 仮質問の上限: 30回。
- 仮質問の確定閾値: 95%。
- 本質問の確定閾値: 98.8%、S>50 では 99.7%。
- 重複抑制に使う確信度: 68%。
- 固定温度範囲は、おおむね `500 +/- N*sqrt(S)/2` または `500 +/- S`。
- 移動探索は `|y|+|x| <= 2*MOVE` 程度に制限する。

## 実装上重要な断片

```text
for each query result observed:
    sum = 0
    for each exit candidate k:
        expected = P[exit[k] + move]
        prob[k] *= normal_table[expected][observed]
        sum += prob[k]
    for k:
        prob[k] = prob[k] / sum * 100
```

```text
select_move(prob):
    top2 = two largest candidates
    choose move maximizing abs(P[exit[top2[0]]+move] - P[exit[top2[1]]+move])
    tie-break by smaller |dy|+|dx|
```

## この解法の本質

この解法の本質は、配置で出口セルに識別信号を与え、計測でその信号を直接読むのではなく、ノイズ込みの確率更新で候補を絞る点である。温度配置は完全な符号化ではなくてもよく、候補上位同士を分ける場所を逐次選べば、必要な識別情報を追加で取りに行ける。

また、非出口セルを平均化することで配置コストを下げる発想が重要である。出口セルの温度差を情報量として使い、その周囲を滑らかにしてコストだけを削るという分離が効いている。

## 真似するならまず実装する部分

まずは出口セルに等間隔の温度を置き、非出口セルを4近傍平均で平滑化する配置を作る。次に、正規分布の観測確率テーブルと、ワームホールごとの候補確率更新を実装する。移動選択は最初から全候補を見る必要はなく、上位2候補の温度差が最大になる移動を小さな範囲で探すだけでもよい。

上位化するなら、残り計測回数の配分、出口重複の抑制、S/Nに応じた固定温度の切替を追加する。

## 注意点・未理解点

- 記事の温度設定条件とコード上の条件式は完全には一致しない。記事は本質説明、コードはチューニング込みと見るべきである。
- 確率を通常の `double` で積むため、非常に多い計測ではアンダーフローの危険がある。コードでは頻繁に正規化することで回避している。
- `preuse` は厳密な割当最適化ではなくヒューリスティックなので、誤って除外すると後続を悪化させる。
- 閾値 95%、98.8%、99.7%、68% は理論最適というより経験的な値である。
