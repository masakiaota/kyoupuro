## 解法の全体像

複数の温度配置をSやNに応じて使い分ける方針である。小さいSでは出口周辺に局所的な模様を埋め込む。中程度のSでは盤面全体の大きな模様で大まかな領域や境界を調べる。大きいSでは1か所だけ高温にし、各出口からその高温点への相対移動を試して対応を判定する。

計測では候補出口ごとの相対尤度を持ち、観測値が出る確率を掛けて更新する。測定位置は、候補確率を重みとした温度の重み付き分散を計測コストで割った評価で選ぶ。確率が十分高くなったら確定するが、最後に未使用候補や自信のない回答を余りから割り直し、誤答数を減らす。

## 主要アイデア

- まず正規分布のCDFを使い、丸め・クリップ込みの観測確率を正確に扱う。
- 相対尤度は、各更新前に最大値で割ることでアンダーフローを避ける。
- 測定位置は「候補を半々に分けられそうな温度分散が大きい場所」を選ぶ。
- 小Sでは、出口と周辺セルに多段階温度の模様を埋め込む。
- 模様同士が重なる場合も、模様外の位置を測定候補にして補えるようにする。
- 中Sでは、盤面全体に大きな境界・領域パターンを作り、足元測定と境界測定で位置を絞る。
- 大Sでは、1点高温で配置コストを抑え、候補出口から高温点への相対移動を短距離順に試す。
- 最終的に、S/N/Lごとに相性のよいパターンを選ぶ。

- 出口セル座標 `exit[k]`。

小Sの模様方式では追加で次を持つと考えられる。

- 出口ごとの符号、または出口周辺の温度パターン。
- 温度固定セルのマスク。
- 模様外も含む測定候補集合。

1点高温方式では追加で次を持つ。

- 高温点座標。
- 各出口から高温点への相対移動。
- 移動距離順の候補リスト。

### 観測・制約・入力の扱い

- 観測確率は正規分布のCDFを使って計算し、0/1000へのクリップも含める。
- 計測値の丸め仕様を単体テストで確認している。
- 同じワームホールについて、候補出口ごとに「その出口から指定移動した位置の温度」が観測される確率を掛ける。
- 相対尤度がアンダーフローしないよう、更新時に最大値で割る。

### 評価関数

- 測定位置の評価は、候補出口の相対尤度を重みとした予測温度の分散を、計測コストで割るもの。
- 目的は、次の観測で候補集合をなるべく割ることである。
- 絶対確率は、相対尤度を総和で割って得る。
- 確定判定は、ある出口候補の絶対確率が0.999に到達すること。
- 配置では、温度差による配置コストと、測定コストと、誤答数のバランスを見る。特に大Sでは配置コストを測定コストと同程度まで下げることを重視する。

### 探索・構築・更新

小Sの局所模様:

- 出口と周辺セルを複数段階の温度で符号化する。
- 初期案は出口と4近傍の5マスに4段階温度を置く方式。
- 隣接セルでは温度差吸収が弱いため、最終的には2マス先のセルも使う方向に改善した。
- 模様固定セル以外を平均化して配置コストを下げる。

中Sの全体模様:

- 盤面全体に大きな領域・境界を作る。
- 足元の測定で属する領域を知り、隣接領域の温度や境界位置を追加で調べる。
- Sが上がるほど、ある程度明確な温度差を持つ境界が必要になる。

大Sの1点高温:

- 1か所だけ高温にすると、配置コストは高温点の周囲だけに集中する。
- 各出口から高温座標への相対移動を候補として、短距離順に測る。
- 高温を測ったはずなのにノイズで外れ判定になった場合の長距離ロスを避けるため、「入口に対応する出口を探す」よりも「出口に対応する入口を探す」向きにした。

### 操作・クエリ・出力選択

- 通常の尤度方式では、未確定の入口を選び、重み付き分散/コストが大きい移動を測る。
- 1点高温方式では、各出口候補から高温点への相対移動を、距離の短い順に試す。
- 確率が0.999を超えるか、入口ごとの計測回数上限に達したら打ち切る。
- 最後は、浮いた入口や自信のない回答を余り候補から再割当する。

### 時間配分・パラメータ

- 1入口あたりの測定上限は記事上100回。
- 確定閾値は絶対確率0.999。
- 小Sでは局所模様、S=36,49付近や64から121付近では全体模様、より大きいSでは1点高温が主役になる。
- S/N/Lに応じてパターンを選ぶが、具体的な閾値表は記事だけでは完全には分からない。

## 実装上重要な断片

```text
update_relative_likelihood(observation):
    mx = max(like)
    for k:
        like[k] /= mx
        expected = P[exit[k] + move]
        like[k] *= probability(expected, observation)
    prob[k] = like[k] / sum(like)
```

```text
score_move(move):
    mean = sum_k prob[k] * P[exit[k] + move]
    var = sum_k prob[k] * (P[exit[k] + move] - mean)^2
    return var / (10 + abs(move.y) + abs(move.x))
```

## この解法の本質

この解法の本質は、Sの大きさによって「情報をどこに埋めるべきか」が変わると見ている点である。小Sでは局所的な多値符号が安く読めるが、大Sでは多くの高低差を置く配置コストが重く、1点高温のような少数の強いアンカーが有利になる。

また、観測の選び方を固定せず、現在の候補分布に対して分散が大きい地点を選ぶ方針が汎用的である。これは、次の測定で候補を分ける情報量を取りに行く考え方であり、盤面の符号化方式が変わっても使える。

## 真似するならまず実装する部分

まずは相対尤度更新と `分散 / 計測コスト` の移動選択を実装するのがよい。配置は、最初は出口セルに等間隔温度を割り当てて平滑化する簡易版でよい。

次に大S用として1点高温方式を追加する。高温点を1つ置き、各出口から高温点への相対移動を短距離順に試すだけでも、この参照元の重要な気づきである「配置コストを抑え、測定で補う」方向を再現できる。
