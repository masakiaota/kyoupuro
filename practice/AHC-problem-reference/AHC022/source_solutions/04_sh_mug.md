## 解法の全体像

出口セルに順序付きの温度を割り当て、非出口セルはぼかして滑らかな温度勾配を作る。計測では各ワームホールの出口候補に対する対数尤度を持ち、最も確信度が低いワームホールを選ぶ。移動量は、そのワームホールの候補分布のもとで、観測される温度の分散が最大になる場所を選ぶ。

最後は各ワームホールを独立に最尤へ割り当てるのではなく、全体の対数尤度合計が最大になる出口の順列を最小費用流で求める。対応が1対1であることを最終回答に明示的に使う解法である。

## 主要アイデア

- 出口セルに `0, P, 2P, ...` のような温度を割り当てる。
- 温度順序は、ある中心出口からのマンハッタン距離順にする。
- 中心出口は、配置コストが最も小さくなるものを全探索で選ぶ。
- 非出口セルは最近傍出口の温度で初期化し、固定出口セルを保護してガウシアンぼかしを繰り返す。
- S/Nが大きいケースでは、極端な温度のセルを1個または2個作って識別力を上げる。
- 計測対象ワームホールは、現在の最大事後確率が最も低いもの。
- 移動量は、候補出口ごとの予測温度の分散が最大になる場所。
- 最終割当は最小費用流で、1対1制約つきの尤度最大化を行う。

## 最終コードの構造

### 状態表現

- `IO`: 入力、温度配置出力、計測、回答出力を担当する。
- `State`:
  - `temp_board`: 温度盤面。
  - `ll_table[wormhole][exit]`: 対数尤度。
  - `temp_exit_cells`: 出口セル温度。
  - `temp_centered[dy][dx][exit]`: 各移動で各出口から見える温度。
  - `protected_mask`: 出口セルをぼかしから守るマスク。
  - `erf_log`, `erf_sum_log`: 観測確率の対数テーブル。
  - `count_measure`: ワームホールごとの計測回数。
- `measure_t`: `(wormhole, delta)`。

### 観測・制約・入力の扱い

- 丸められた観測値の確率を、正規分布のCDF相当の `erf` で事前計算する。
- 観測値が0または1000の場合は、クリップされた裾確率を使う。
- 各計測後、全出口候補 `j` に対して `ll_table[i][j] += log P(response | expected_temp)` を行う。
- 対数尤度を使うため、計測回数が増えてもアンダーフローしない。

### 評価関数

- 配置コストは通常の隣接二乗差の合計。
- 中心出口の選択では、各候補中心で配置を作ってコストを計算し、最小のものを採用する。
- ワームホール `i` の確信度は、`ll_table[i]` から計算した最大事後確率である。
- 移動量 `delta` の評価は、候補出口確率を重みとした `P[exit[j]+delta]` の分散。
- 最終回答の評価は、`sum_i ll_table[i][E_i]` の最大化。最小費用流では辺コストを `-ll_table[i][j]` とする。

### 探索・構築・更新

配置:

- 各出口セルについて、中心候補からのトーラスマンハッタン距離を計算し、距離順に温度を割り当てる。
- 最大温度は `sqrt(K * sqrt(1 + L/10) * S * (N-1))` 風の式で決め、0からその範囲に広げる。
- 非出口セルを最近傍出口の温度で埋める。
- 4近傍と中心に重みを置くフィルタで100回ぼかす。
- `N*S` が閾値以上のとき、最小側・最大側を反転したり、中心出口を高温にしたり、極端なセルを追加したりする。

計測:

- `most_likely(i)` でワームホール `i` の最尤出口とその事後確率を求める。
- `lowest_confidence()` で最も自信のないワームホールを選ぶ。
- `search_highest_variance_delta(i)` で全 `dy,dx` を走査し、予測温度分散が最大の移動を選ぶ。
- 小さめの `N*S` では、移動距離が `L/4` を超える候補を捨てて計測コストを抑える。
- 全ワームホールの最低確信度が閾値を超えたら計測を打ち切る。

回答:

- `estimate_by_mincostflow()` で、ワームホール側N点、出口側N点、source/sinkを持つ二部グラフを作る。
- 各 `(i,j)` 辺の容量は1、コストは `-ll_table[i][j]`。
- N流を流し、フローが流れた出口を `E_i` とする。

### 操作・クエリ・出力選択

- クエリ対象は、現在最も確信度が低いワームホール。
- クエリ移動は、そのワームホールの候補分布で温度分散が最大の位置。
- 計測終了条件はSや `N*S` により変わり、厳しいケースほど低めの確信度で止める。
- 出力は最小費用流で得た順列である。

### 時間配分・パラメータ

- 実行時間上限意識: `time_limit = 3.95` が定義されているが、最終コードの主処理はほぼ決定的処理である。
- ガウシアンぼかし: 100回。
- 計測上限: 10000。
- `THRESHOLD_NS = 11500`, `THRESHOLD_NS_2 = 67500`。
- `N*S` によって極端温度の追加、計測打ち切り閾値、移動制限を切り替える。
- 小Sでは移動量を制限し、計測コストを下げる。

## 実装上重要な断片

```text
choose_measure():
    wh = argmin_i max_posterior_probability(i)
    if confidence_threshold_reached:
        stop
    delta = argmax_delta weighted_variance(
        P[exit[j] + delta],
        posterior_probability(j | wh)
    )
    return (wh, delta)
```

answer_by_assignment():

## この解法の本質

この解法の本質は、計測と回答の両方で「不確実性」を直接扱う点である。次に測るべきワームホールは最も不安なもの、次に測る位置は候補を最も分散させるもの、最後の回答は個別最尤ではなく全体尤度最大の順列である。

配置は比較的素直な連続勾配だが、計測位置を分散最大で選ぶことで、同じ配置からより多くの情報を引き出している。最小費用流によって1対1制約を使う点も、独立推定より安定する。

## 真似するならまず実装する部分

まずは対数尤度テーブルと最小費用流による最終割当を実装するのがよい。配置は出口セルを距離順に等間隔温度へ割り当て、非出口セルを平均化する簡易版で足りる。

次に、最も確信度の低いワームホールを選び、候補分布に対する予測温度分散最大の移動を選ぶ。これがこの解法の中心部分であり、配置の細部より先に再現する価値が高い。

## 注意点・未理解点

- 記事では「ガウシアンぼかし」と説明されるが、コードのフィルタは中心と4近傍に重みを置く簡易的な平滑化である。
- `temp_exit_cells` の添字と出口番号の関係はコード上やや読みづらく、記事の高レベル説明を優先して理解した。
- 最小費用流は全体正解率を上げる一方で、2個を同時に入れ替えて間違える危険もある。
- `N*S` 閾値や最大温度式はチューニング値であり、理論式としては説明されていない。
- 大S向けの極端温度セルは、記事でも理屈に不確かさが残るとされている。
