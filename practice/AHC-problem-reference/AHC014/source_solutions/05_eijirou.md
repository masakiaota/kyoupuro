## 解法の全体像

操作の依存関係を管理し、削除可能な追加点だけを取り消せるようにしたうえで、部分破壊と貪欲再構築を焼きなましで繰り返す。初期解は偶奇パターンを256通り試し、それぞれ貪欲に作って良いものを残す。探索中も複数状態を持ち、段階的に状態数を絞り込む。

提出コードは、`locks[x][y]` でその頂点が他の操作から依存される回数を持つ。`locks == 0` の追加点だけを削除候補にできる。ランダムな矩形領域にある削除可能点を取り消し、そこから優先度付き貪欲で再構築する。

## 主要アイデア

- 追加点は後続の長方形の頂点として使われるため、操作には依存関係がある。
- `locks[x][y]` を使い、依存されていない追加点だけを安全に削除する。
- ある点を削除すると、新たに削除可能になる点が出るためスタックで連鎖的に処理する。
- 1個おきに正方形を書く市松模様のような密なパターンを重視する。
- 可能な操作数を増やす操作を優先し、オセロの「合法手が多いほど有利」に似た見方をする。
- 周長が短い長方形を少し優先し、疎な配置を避ける。
- 256通りの偶奇パターンを多点スタートとして試す。

## 最終コードの構造

### 状態表現

- `State`
  - `marked[x][y]`: 印の有無。
  - `locks[x][y]`: その頂点が依存されている数。初期点は削除不可にするため1で初期化される。
  - `edges[x][y][d]`: `(x, y)` から方向 `d` に進んだときの境界情報。最初にぶつかる頂点や辺所有者を保持する。
  - `rectangulars[x][y]`: 追加点 `(x, y)` に対応する長方形。
  - `actions`: 候補操作の優先度付きキュー。
  - `revert_points`: 削除処理で使うスタック。
  - `unlocked_marks`: `locks == 0` の削除可能点集合。
  - `phase`: 偶奇パターン。
  - `score`: 現在の重み和。
- `Solver`
  - `states` と `best_states` を複数本持つ。
  - 最後に最良状態から答え列を復元する。

### 観測・制約・入力の扱い

- 初期点を `marked = true`、`locks = 1` にする。
- 各初期点から8方向に `fill` し、方向ごとの最初にぶつかる点を埋める。
- `push_action(x, y, d)` は、直交2方向の既存点から新点を計算し、外周が空いていれば候補に入れる。
- `can_act` で候補が現在も合法かを確認し、優先度付きキューの古い候補は `update_actions` で遅延削除する。

### 評価関数

- `evaluate(rect)` は、基本的に 1x1 に近い固定パターンを優先する。
- 1x1でない候補には、長方形サイズに応じた負の乱数評価を与える。
- 1x1候補は `phase` と盤面上の領域グループに応じて、縦横・斜めの偶奇が合うものを高く評価する。
- `get_bonus(rect)` は、その候補を置いた後に増える可能操作数を概算し、`choose_action` の見比べに使う。
- 焼きなましの採択は `delta = new_score - old_score` と温度から判定する。

### 探索・構築・更新

- `join(rect)`:
  - 新点を追加する。
  - 長方形の3既存点の `locks` を増やす。
  - 新点が既存辺上なら、その辺を作った点への依存も増やす。
  - 辺情報を `fill` で更新する。
  - 新点周辺から新候補を追加する。
- `revert(x, y)`:
  - `locks[x][y] == 0` の点だけ削除する。
  - 対応長方形の辺を消し、境界情報を戻す。
  - 依存先の `locks` を減らし、0になった点を削除候補へ積む。
- `random_greedy()`:
  - 優先度付きキューから候補を取り出す。
  - 上位候補を少し先読みし、`get_bonus` が大きいものを選ぶ。
  - 候補が尽きるまで `join` する。
- `range_revert()`:
  - ランダム矩形領域内の削除可能点を集めてシャッフルする。
  - 指定上限まで `revert` し、壊した長方形列を返す。
- `solve()`:
  - 256フェーズをすべて初期状態として貪欲構築する。
  - 状態数を 16, 8, 4, 2, 1 と絞りながら、各状態に破壊再構築をかける。

### 操作・クエリ・出力選択

- 最終的に `best_states.front().make_answer()` で長方形列を復元する。
- 出力は長方形数と、各長方形の4点。

### 時間配分・パラメータ

- 制限時間は 4.9 秒。
- 状態数の各段階に `time_limit / 5` ずつ割り当てる。
- 焼きなまし温度は `t0=1000.0`, `t1=100.0`。
- 破壊上限は、現在の追加点数とランダム矩形領域の面積比から決める。
- 記事によれば試行回数はケースにより1万から15万回程度。

## 実装上重要な断片

```text
join(rect):
    add rect[0] as a mark
    for rect[1..3]:
        locks[vertex] += 1
    if new mark lies on an existing edge:
        lock the rectangle that owns the edge
    write four edges
    push newly enabled actions
```

```text
revert(point):
    assert locks[point] == 0
    erase the rectangle created by point
    remove its edges
    decrement locks of dependent vertices
    newly unlocked points are pushed to revert stack
```

```text
solve:
    for phase in 0..256:
        state = greedy(State(input, phase))
    for selects in [16, 8, 4, 2, 1]:
        keep best `selects` states
        until time slice ends:
            destroy random rectangle area
            greedy rebuild
            accept by annealing
```

## この解法の本質

この解法の核は、依存関係を `locks` として盤面上に持ち、削除可能性を局所的に更新できるようにした点である。これにより、AHC014の「操作列の順序を壊すと不正になる」という難しさを、削除可能点集合の管理問題へ落としている。さらに偶奇パターンの多点スタートで、密に伸びる構造へ誘導している。

## 真似するならまず実装する部分

まず `marked`, `edges`, `locks`, `rectangulars` を持ち、`join` と `revert` が正しく逆操作になるところを作るべきである。次に、1つの固定パターンだけで貪欲を動かし、最後に256フェーズや複数状態絞り込みを追加するとよい。

## 注意点・未理解点

- `edges` に負値で辺所有者を埋める実装は強力だが、バグりやすい。
- 初期点を `locks=1` にする設計により削除不可を表しているため、追加点と初期点の区別を壊すと復元が破綻する。
- `get_group` の座標判定はコード上では盤面中心を引いた座標を前提にしているように見えるが、該当箇所だけでは意図を完全には追い切れていない。
- パラメータやフェーズ絞り込みは実験依存で、簡略実装では再調整が必要である。
