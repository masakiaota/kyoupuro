## 解法の全体像

複数の評価関数による貪欲で初期解を作り、その中で最もスコアの高いものを採用する。その後、いくつかの長方形とそれに依存する長方形を削除し、貪欲で作り直す焼きなましを行う。

削除方法と再構築時の評価関数をランダムに選ぶことで探索の多様性を出す。削除量が大きすぎる場合は再構築せず棄却し、局所破壊として機能する範囲に抑える。

## 主要アイデア

- 初期解は5種類の貪欲評価で作り、最良を選ぶ。
- 貪欲評価は、4つの外側仮想点 `q` から新点 `p1` への距離を周長で割るものと、新点の重みである。
- 焼きなまし近傍は、長方形を複数削除し、依存する長方形も削除してから貪欲再構築する。
- 削除方法を複数持つ。
  - 依存関係DAGを後ろから削る。
  - ランダムな長方形と依存先を削る処理を繰り返す。
  - ランダムな長方形の新点周辺4点または8点に関係する長方形を削る。
- 再構築時には、削除した長方形を戻しにくくする意図が記事に書かれている。ただし提出コード上では明示的な `taboo` 名の処理は確認できず、最終版では十分に効いていない可能性がある。
- 小さいケースでは一定回数改善しなければ初期解からやり直す。

## 最終コードの構造

Browserで AtCoder 提出 `35326899` を読んだ。以下は記事本文と提出コードから確認できた実装構造である。

### 状態表現

- `State`: 印の有無、辺の使用状況、現在の長方形列を持つ。
- `Rect`: 追加点 `p1` と残り3点を持つ長方形。
- `PointUsageManager`: 削除対象になった追加点を管理する。
- `child_count`: 追加点の依存数を数え、子が無くなった長方形を削除候補へ広げる。
- `candidates`: 現在の候補集合。`update_candidates` で無効化と新規追加を行う。
- `cur_score`, `best_score`: 焼きなまし中の現在スコアと最良スコア。

### 観測・制約・入力の扱い

- 入力生成器も自作し、`N` と `M` の分布を均等に見るテストセットを用意している。
- 合法手列挙では、傾いた長方形同士の辺共有判定を45度回転して軸平行の場合に帰着する高速化に触れている。
- ローカル実行で時間超過を検出するため、`main` 最後で経過時間を確認して異常終了する仕組みを入れている。

### 評価関数

- 初期解と再構築で使う基本評価:
  - `d(q, p1)^2 / 周長`。`q` は4つの外側仮想点。
  - 新点 `p1` の問題本来の重み。
- 再構築時の追加評価:
  - `p1` からマンハッタン距離2以下に既に使われている点が多い候補を優先。
  - 候補全体から一様ランダム。
- 焼きなまし温度:
  - `N <= 37` は初期温度 20000。
  - `N >= 39` は `N=39..61` で 30000 から 10000 へ減少する一次関数。
  - 最終温度は初期温度の `1/10`。

### 探索・構築・更新

- 近傍生成:
  - 削除対象を選ぶ。
  - 依存関係を辿って削除対象を閉包にする。
  - 削除数が `min(解の長さ/2, 2N)` を超えたら再構築せず棄却する。
  - 選んだ評価関数で候補を追加し尽くす。
- 候補更新は差分化している。
  - 追加した長方形と重なる候補を消す。
  - 追加した新点 `p1` を使ってできる長方形を追加する。
- レプリカ交換法も試したが、大きいケースでは試行回数不足で最終採用していない。

### 操作・クエリ・出力選択

- 焼きなましで最良となった長方形列を出力する。
- 記事上はタブー長方形を低評価にする意図があるが、提出コードでは明示的なタブー名は確認できなかった。実際には削除点集合と候補再構築のランダム性で戻りにくくしている可能性がある。

### 時間配分・パラメータ

- 大きいケースで4万回程度、小さいケースで50万回程度の試行。
- Nが小さい場合、一定回数更新がなく残り時間が500ms以上あれば初期解からやり直す。
- やり直し閾値は `p = (M - N) / (floor(N^2 / 12) - N)` に応じて 10000 または 20000。
- 880ケースの自作テストセットでパラメータを検証している。

## この解法の本質

この解法は、貪欲構築の評価を単一の「点の重み」にしないことと、破壊の種類を複数持つことにより、多様な局所解を探索している。特に、削除後に同じ長方形を戻さないタブー処理は、部分破壊再構築が単なる復元で終わる問題を軽減している。

## 真似するならまず実装する部分

まずは5種類すべてではなく、「短い周長優先」「外側優先」「ランダム」の3種類程度の貪欲を実装する。次に、長方形1個削除と依存削除だけで焼きなましを作る。候補差分更新と複数削除近傍は、動作確認後に追加するのがよい。

## 注意点・未理解点

- 提出コードで依存削除と候補差分更新の構造は確認できた。
- 記事内で「タブーを選ばないようにするのを忘れていた」とある再構築評価があり、コード上でも明示的な `taboo` 処理は見当たらないため、理想設計と最終挙動が一部ずれている可能性がある。
- 評価関数や再スタート閾値は実験依存で、別実装では再調整が必要になる。
- 改善判定は多数ケースで見ないとぶれやすく、少数ケースの改善を信じると悪化しうる。
