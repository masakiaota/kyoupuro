## 解法の全体像

グリッドに魚の差分を乗せ、二次元累積和で任意のグリッド長方形の `サバ数 - イワシ数` を高速に求める。try2 では、全ての長方形を全探索して最も得点が高い長方形をそのまま出力する。本番最終はこの try2 である。

try3 では、最良長方形の四隅に負の領域があるなら、その角の長方形を削る。各隅について、中心側までの範囲で最も負の小長方形を探し、負なら角を切り欠いた頂点列を出す。これにより、長方形から十字・プラス型に近い多角形へ改善する。

## 主要アイデア

- 実装が重い一般多角形を避け、まず長方形に限定する。
- グリッド化と二次元累積和で、長方形内部の魚差分を O(1) で計算する。
- `O(M^4)` で全長方形を調べても、`M=125` 程度なら 2 秒内に動く。
- 長方形の四隅に負領域がある場合、その部分を削っても周長の増加を抑えつつスコアを改善できる。
- グリッド座標と実座標の境界変換が重要で、右下側は `index * R - 1` とするなど、点の属する範囲に注意する。
- 乱択長方形探索も考察しているが、実装は確定的な累積和全探索が中心である。

## 最終コードの構造

try2 と延長戦 try3 の提出コードを読んだ内容を書く。

### 状態表現

- `M = 125`, `R = 100000 / M`。
- `saba[N]`, `iwashi[N]`: 魚座標。
- `field[M+1][M+1]`: 1-origin のグリッド差分。
- `SUM[M+1][M+1]`: 二次元累積和。
- `max_left, max_right, max_up, max_bottom`: 最良長方形のグリッド範囲。
- try3 では `result: vector<pair<int,int>>` に最終多角形の頂点列を入れる。

### 観測・制約・入力の扱い

- 魚座標 `(x,y)` を `x / R + 1`, `y / R + 1` でグリッドに割り当てる。
- try3 では実座標へ戻すとき、左・上側は `(index - 1) * R`、右・下側は `index * R - 1` を使う。これは頂点重複や境界の所属ずれを避けるためである。
- 本番で try3 が壊れた原因は、累積和用グリッド座標と実座標の変換を十分考慮できていなかったことだと記事にある。

### 評価関数

- 長方形 `[left, right] x [up, bottom]` のグリッド差分合計を二次元累積和で求める。

```text
rect_sum(left, right, up, bottom):
    return SUM[bottom][right]
         - SUM[bottom][left - 1]
         - SUM[up - 1][right]
         + SUM[up - 1][left - 1]
```

- try2 は `rect_sum` を最大化する。
- try3 は各隅について、削る候補長方形の `rect_sum` が最小、つまり最も負になるものを探し、負なら削る。

### 探索・構築・更新

- try2:
  - `left < right`, `up < bottom` の全組を 4 重ループで試す。
  - `rect_sum` が最大の長方形を記録する。
  - 4 頂点を出力する。
- try3:
  - try2 の最良長方形を基礎にする。
  - 長方形の中心で 4 象限に分ける。
  - 左上、左下、右下、右上の各隅について、角に接した小長方形を全探索する。
  - その小長方形の合計が負なら、角を切り欠く 3 頂点を出す。負でなければ元の角 1 点を出す。
  - 最大で 12 頂点程度の多角形になる。

### 操作・クエリ・出力選択

- try2 は次の順で 4 点を出力する。
  - 左上、左下、右下、右上に相当する座標。
- try3 は左上、左下、右下、右上の順に、切り欠きの有無に応じて頂点を追加して出力する。
- 出力は 1 回のみ。

### 時間配分・パラメータ

- `M=125`, `R=800`。
- try2 提出は 63 ms、コードサイズ 2051 Byte。
- try3 延長戦提出は 68 ms、コードサイズ 5944 Byte。
- 本番では try3 を通せず、try2 の 291,267 点が最終。
- 延長戦で座標変換を修正し、try3 は 316,906 点になった。

## 実装上重要な断片

長方形全探索は次の形である。

```text
build_prefix_sum(field)
best = 0
for left in 1..M:
  for right in left+1..M:
    for up in 1..M:
      for bottom in up+1..M:
        score = rect_sum(left, right, up, bottom)
        if score > best:
            save rectangle
```

四隅削りは次の形である。

```text
for each corner:
    min_score = 0
    for candidate rectangle anchored at corner within its quadrant:
        score = rect_sum(candidate)
        if score < min_score:
            save candidate
    if min_score < 0:
        output vertices that skip this corner rectangle
    else:
        output original corner
```

記事中の乱択案は、長方形をランダムに選んで内部スコアを計算し、最大を更新するというシンプルな形である。最終提出コードでは使っていない。

## この解法の本質

この解法は、形状表現を長方形に限定することで、問題を「二次元配列上の最大部分長方形探索」に落としている。一般の多角形より表現力は低いが、累積和により評価が明快で、実装が壊れにくい。

四隅削りは、長方形制限を少しだけ緩める後処理である。長方形の内側に含めたくない負の塊が四隅にある場合、それを削るだけでスコアが上がる。中央や辺中央の負領域は削れないが、短時間で実装できる改善としては費用対効果が高い。

## 真似するならまず実装する部分

まず try2 の `M=125` グリッド、二次元累積和、長方形全探索を実装する。これは短く、デバッグもしやすい。次に、座標変換を丁寧に確認したうえで四隅削りを足す。

さらに改善するなら、長方形を乱択で多点スタートする、複数の `M` を試す、四隅だけでなく辺沿いの切り欠きを扱う、といった方向がある。ただしその分、自己交差と座標変換のリスクが上がる。

## 注意点・未理解点

- グリッド座標から実座標への変換を誤ると、想定したセル範囲と出力多角形がずれる。記事でも本番 try3 のバグ原因として挙げられている。
- 長方形だけでは、離れた複数クラスタや曲がった境界を表現できない。
- 四隅削りは角にある負領域にしか効かない。
- `O(M^4)` は `M=125` なら通るが、分割を増やすと急に重くなる。
- グリッド境界上の魚の扱いは実スコアとずれる可能性があるため、最終的にはビジュアライザや公式採点関数で検証した方がよい。
