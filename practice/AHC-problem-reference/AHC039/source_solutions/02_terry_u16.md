## 解法の全体像

平面全体を `M x M` グリッドに分け、どのマスを網の内側にするかを焼きなましで決める。初期は `M=10`、全マス ON、つまり `10^5 x 10^5` 全体の正方形から始める。一定時間焼いたらグリッドを `2x2` に細分化し、前段階の ON/OFF をコピーして次段階の初期解にする。これを `20, 40, ..., 320` 程度まで繰り返す。

探索中は 1 マス ON/OFF 反転だけを行う。ただし、ON マス集合と OFF マス集合の連結性を保ち、周長制限を守る遷移だけを採択候補にする。最後は ON/OFF 境界を左手法で辿り、多角形として復元する。

## 主要アイデア

- 幾何問題として直接辺を動かすのではなく、グリッド問題として解く。
- 評価関数は素直に `サバ数 - イワシ数` の生スコアを使う。
- 近傍は 1 マスの ON/OFF のみで、スコア差分は O(1)。
- 粗いグリッドから始めることで、遠いクラスタをつなぐ大域的な形を作りやすくする。
- 細分化で局所的なイワシ回避やサバ追加を可能にする。
- ON/OFF 両方の連結性を保つことで、穴や自己交差のない単純多角形として復元できる。
- 連結性判定は周囲 `3x3` のみを見る安全側判定で高速化する。
- 有効な反転候補は境界周辺に限られるため、境界隣接マス集合を O(1) 集合で管理する。

## 最終コードの構造

Browserで読めた提出 #59660035 を主実装として書く。記事本文と疑似コードの内容はこの提出の構造とほぼ対応している。

### 状態表現

- `Input`: サバ座標、イワシ座標、`MAP_SIZE=100000`、`LEN_LIMIT=400000` を持つ。
- `Env`: 現在のグリッド分割、座標変換、各マスの魚差分を持つ。
- `State`: `Map2d<bool>` のON/OFF、`score`、`len`、`on_candidates`、`off_candidates` を持つ。
- `OffNeigh` / `OnNeigh`: 1マス反転近傍。反転後の魚差分、周長差分、連結性を差分で確認する。
- `CONNECTION_CHECKER.can_remove` でON集合とOFF集合の局所連結性を判定する。
- `split_half` で `10 -> 20 -> 40 -> ...` の細分化を行う。

### 観測・制約・入力の扱い

- 各細分化レベルごとに、全魚を現在のグリッドへ割り当てて `saba_iwashi_grid` を作る。
- 記事の脚注では、グリッド境界上の魚が片方のマスにしか含まれない問題はスコア影響が小さいため無視したとされている。
- 周長 `4e5` は探索中のハード制約として扱う。
- `M > 250` では周長制限を満たしても頂点数 1000 を超える可能性があるため、復元後に一直線上の不要頂点を削除する。

### 評価関数

- 評価関数は生スコアそのままである。

```text
score = sum(saba_iwashi_grid[y][x] for grid[y][x] == ON)
```

- 網の長さは評価に混ぜず、制約として扱う。短くすれば常に良いわけではなく、離れたクラスタへ伸ばしたい場合があるためである。

### 探索・構築・更新

- 初期解は全 ON。
- 遷移は 1 マスの ON/OFF 反転。
- 反転時に次を確認する。
  - ON/OFF 両方の連結性が壊れない。
  - 周長制限を超えない。
  - 自己交差のない 1 つの境界を保てる。
- スコア差分は反転マス 1 個の値だけで計算できる。
- 周長差分は 4 近傍の ON/OFF を見れば計算できる。
- 連結性は DFS や lowlink ではなく、周囲 `3x3` の局所パターンで安全側に判定する。
- 境界周辺以外を反転してもほぼ非連結になるため、境界隣接マス集合から候補を引く。

### 操作・クエリ・出力選択

- 最終グリッドの ON/OFF 境界を左手法で辿る。
- 得られた頂点列から一直線上の中間点を削除し、頂点数を抑える。
- 時計回り、反時計回りはどちらでもよいが、全頂点相異なる必要がある。

### 時間配分・パラメータ

- 記事では最終的に `10x10 -> 20x20 -> 40x40 -> ... -> 320x320` と細分化したと説明されている。
- `10x10` の初期実装で seed 0 が 2300 点程度、`80x80` までの細分化で 551,282 点、境界候補集合管理で 552,871 点、`320x320` と不要頂点削除で 565,986 点、最終調整で 566,997 点。
- ジャッジサーバー上で約 `10^7` 回の焼きなまし遷移が回るように高速化したとある。
- 提出 #59660035 では温度列 `TEMPS = [5e2, 5e1, 1e1, 3e0, 1e0, 3e-1]` を確認できた。段階ごとの厳密な時間配分は、コード中の時間打ち切りと細分化ループに従う。

## 実装上重要な断片

記事中の疑似コードは次の流れである。

```text
m = 10
on_off_grid = all_on_grid(m)
while m <= 320:
    cell_score = calc_saba_iwashi_grid(m, points)
    on_off_grid = simulated_annealing(cell_score, on_off_grid)
    m *= 2
    on_off_grid = split_grid_half(on_off_grid)
```

反転処理は次の形になる。

```text
try_toggle(cell):
    if cell is not near boundary:
        reject
    if not safe_local_connectivity(cell):
        reject
    delta_len = calc_perimeter_delta(cell)
    if length + delta_len > 400000:
        reject
    delta_score = +cell_score[cell] if turning_on else -cell_score[cell]
    accept by annealing
```

`IndexSet` は、配列 `que` と位置配列 `pos` を持ち、削除時に末尾要素を空いた位置へ移すことで、追加・削除・存在確認・ランダム取得を O(1) にするデータ構造である。境界候補集合の管理に向いている。

## この解法の本質

本質は、複雑な軸平行多角形の探索を「穴のない連結グリッド領域の探索」に変換した点である。多角形の辺を直接操作すると、自己交差や出力順の管理が重い。グリッドなら、反転 1 回のスコア差分、周長差分、連結性判定をすべて局所化できる。

さらに、粗いグリッドから細かいグリッドへ移すことで、局所探索の弱点である大域移動の難しさを避けている。粗い段階で形の骨格を作り、細かい段階で境界の無駄を削るという分業が効いている。

## 真似するならまず実装する部分

最初に作るべきは `M=40` 程度の単一グリッドである。全 ON から始め、ON/OFF の 1 マス反転、スコア差分、周長差分、復元を実装する。連結性判定は最初は DFS でもよいが、動作確認後に `3x3` 安全判定へ置き換える。

その後、`M=10` から始めて `2x2` に細分化する処理を追加する。上位スコアの核はこの細分化にある。

## 注意点・未理解点

- 提出 #59660035 では温度列 `TEMPS = [5e2, 5e1, 1e1, 3e0, 1e0, 3e-1]` を使う。候補集合更新は `postprocess` で周辺候補を追加・削除する構造として確認できた。
- `3x3` 連結判定は安全側であり、反転可能でも拒否する場合がある。この保守性が探索性能にどの程度効くかは実装依存である。
- ON 側だけでなく OFF 側の連結性も見る必要がある。OFF 側を見ないと穴ができ、単純多角形制約を壊す。
- グリッド境界上の魚を雑に扱うと厳密スコアとずれる。ただし記事では影響が小さいとして無視している。
- `M=320` では頂点数制限が厳しいため、復元後の直線上頂点削除は必須である。
