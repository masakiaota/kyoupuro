## 解法の全体像

最初にランダムな一辺 `20000` の正方形を多数作り、公式 visualizer 由来のスコア関数で最も良い正方形を選ぶ。その後、現在の多角形の各辺からランダムな長方形を外側または内側へ生やす候補を作り、スコアが改善したら採用する。これを複数回繰り返す、純粋な山登り解法である。

グリッド化ではなく、多角形頂点列を直接持つ。ただし一般の辺移動ではなく、「既存の 1 辺の間に 4 点を挿入して長方形を追加する」という限定操作にしているため、実装可能な範囲に収めている。

## 主要アイデア

- まず単純な正方形でもある程度取れると見て、一辺 `2e4` の正方形をランダム探索する。
- 評価は公式 visualizer の `compute_score_details` 相当をコードに入れ、実際の点包含と周長・自己交差を調べる。
- 多角形を複雑化する操作は、既存辺からランダムな長方形を 1 個追加するだけにする。
- 候補多角形を丸ごと評価し、スコアが上がったときだけ採用する。
- 焼きなましではなく、悪化を受け入れない山登りである。
- 周長超過や自己交差は評価関数が 0 を返すため、自然に採用されない。

## 最終コードの構造

提出コードを読んだ内容を書く。

### 状態表現

- `Input { N, ps }`: 魚の座標配列。前半 `N` がサバ、後半 `N` がイワシ。
- `ansvec: Vec<(i64, i64)>`: 現在の多角形頂点列。
- `score`: `compute_score_details` が返す現在スコア。
- ランダム候補生成には `rand::thread_rng()` を使う。

### 観測・制約・入力の扱い

- 入力座標はそのまま保持し、評価時に全点について多角形内判定を行う。
- 各辺が軸平行であるか、連続頂点が同一でないか、連続する同一直線辺が折り返していないか、非隣接辺が交差しないか、周長が `4e5` 以下かを評価関数で確認する。
- 点が辺上にある場合は内側として扱う。
- 頂点全体の相異なる制約は、評価関数で完全に検査しているようには見えない。候補生成の乱数に依存して実害を避けている可能性がある。

### 評価関数

- `compute_score_details(input, out)` は visualizer 由来の関数で、制約違反なら 0 点を返す。
- 有効な場合は初期値 1 から始め、内側のサバで `+1`、イワシで `-1` し、最後に `max(0)` を取る。
- 点包含は水平辺を使う偶奇判定と、辺上判定を組み合わせている。

### 探索・構築・更新

- 初期解:
  - 一辺 `ami_length = 20000`。
  - `stx, sty` を `0..75000` から 1000 回ランダムに選ぶ。
  - 正方形を作り、最良スコアを採用する。
- 改善操作:
  - 関数名は `iikandinityouhoukeikaktyou`。
  - 現在の各辺について 50 回候補を作る。
  - 縦辺なら、その辺上の 2 つの `y` を選び、別のランダム `x` へ伸ばす長方形を作る。
  - 横辺なら、その辺上の 2 つの `x` を選び、別のランダム `y` へ伸ばす長方形を作る。
  - 元の頂点列で対象辺の直後に 4 点を挿入し、新しい多角形候補を作る。
  - 候補を全評価し、スコアが改善した場合だけ `ansvec` を更新する。
- この改善関数を初回 1 回、その後さらに 6 回呼んでいる。

### 操作・クエリ・出力選択

- 最後の `ansvec` の長さと各頂点座標を出力する。
- 複数解を逐次出力するのではなく、最終解のみ出す。

### 時間配分・パラメータ

- 正方形初期候補数: 1000。
- 初期正方形の一辺: 20000。
- 各辺あたり長方形追加候補: 50。
- 改善関数の呼び出し: 合計 7 回。
- 提出実行時間は 1895 ms で、評価関数が全点・全辺を走査するためかなり重い。

## 実装上重要な断片

長方形追加の考え方は次の形である。

```text
extend_polygon(poly):
    best = poly
    best_score = exact_score(poly)
    for each edge AB in original poly:
        repeat 50:
            choose two points P, Q on AB
            choose random coordinate perpendicular to AB
            make rectangle P-R-S-Q
            candidate = insert P,R,S,Q after A
            if exact_score(candidate) > best_score:
                best = candidate
                best_score = exact_score(candidate)
    return best
```

初期解は次の形である。

```text
best_square = none
repeat 1000:
    x = random(0, 75000)
    y = random(0, 75000)
    square = [(x,y), (x+20000,y), (x+20000,y+20000), (x,y+20000)]
    keep if exact_score is better
```

## この解法の本質

この解法は、一般の多角形最適化を避け、正方形から「辺に長方形を足す」操作だけで表現力を増やしている。評価は近似ではなく実スコアなので、グリッド境界の誤差や点包含のずれに悩まない。実装方針としては、候補生成を単純にして、評価関数に合法性とスコア判定をまとめて任せる設計である。

強い局所探索というより、短期コンテストで確実に動く幾何山登りである。初期正方形から少しずつ腕を伸ばすだけでも、クラスタ状のサバを追加で囲える。

## 真似するならまず実装する部分

まず公式 visualizer 相当のスコア関数を移植し、ランダム正方形を 1000 個試す実装を作る。次に、1 辺から長方形を生やす候補を作り、スコア改善時だけ採用する。

上位化を狙うなら、候補の方向を「外側だけ」に制限する、重複頂点を明示的に拒否する、全評価を差分評価へ変える、悪化受理を入れる、といった順で改良できる。

## 注意点・未理解点

- 多角形を直接いじるため、自己交差や重複頂点が出やすい。提出コードは自己交差を評価関数で弾くが、全頂点相異なる制約の明示チェックは薄く見える。
- 候補の長方形がどちら側へ伸びるかはランダム座標次第で、内側へ食い込む場合も外側へ飛び出す場合もある。
- 毎回全点・全辺で評価するため重い。点数を伸ばすには候補数と実行時間のバランスが厳しい。
- 悪化を受け入れないため、初期正方形や初期の長方形追加で局所解に入りやすい。
- 記事では「徐々に複雑な網に変形」と説明されているが、最終コードの形は長方形追加にかなり限定されている。
