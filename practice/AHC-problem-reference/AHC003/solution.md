## 問題の本質

AHC003は、未知重みグリッド上で1000回の最短路クエリに逐次回答するオンライン推定問題である。各回答後に得られる情報は「自分が通したパスの合計長に10%程度のノイズが乗った値」だけなので、観測は能動的に選んだ経路に偏る。つまり、短そうな道を使ってスコアを稼ぐ活用と、未知の行・列・辺を通って地図を学習する探索を同時に設計する必要がある。

もう一つの本質は、辺長が完全ランダムではなく、行・列単位の基本値、`M=1/2`、`D`、区切り位置という生成構造を持つ点である。上位解法ほど、この構造を確率モデルや回帰特徴量として使い、観測数1000に対して辺数1740という情報不足を補っている。

## 共通している考え方

- 出力したパスを特徴量、返却値を目的値として、辺長または生成パラメータをオンラインに推定する。
- 推定値だけでDijkstraすると未探索の短い道を発見できないため、何らかの探索補正が必要になる。
- `M=1/2` と行・列構造を利用すると、1740辺を独立に推定するより観測効率が上がる。
- 観測ノイズがあるため、過去クエリを完全に満たす方向へ最適化すると過学習する。Ridge、L2正則化、事前分布が重要になる。
- 序盤の探索が後半スコアに効く一方、遠回りしすぎる探索は即スコアを落とす。
- Dijkstraで出力する限りパスの妥当性を保ちやすいが、負に近い補正や経路依存コストを入れると注意が必要になる。

## 解法の分類

- 貪欲型: マンハッタン最短、全辺同一初期値でのDijkstra。
- 辺コスト直推定型: 通った辺を返却値/辺数へ寄せる、過去パス誤差を局所探索する。
- Ridge回帰型: パスを線形特徴量として、正則化つき最小二乗で推定する。
- 確率推定型: 事前分布、観測分散、事後平均・分散・尤度を扱う。
- 生成構造利用型: 行・列基本値、`M=1/2`、境界、`D` を特徴量やモデルに入れる。
- 探索補正型: 未探索行・列報酬、低め初期値、LCB風コスト、序盤専用探索。
- 後処理・時間管理型: モデル枝刈り、TLE回避、更新頻度調整、Optunaチューニング。

## 実装するならどのルートか

理解のための最小実装は、`makibishi -> threecourse/ymatsux簡略版` の順がよい。

1. 全辺5000または3000でDijkstraする。
2. 返却値をパス辺数で割り、通った辺を平均更新する。
3. 過去クエリを使ったRidge回帰に置き換える。
4. 行・列ごとの基本値を特徴量に入れる。
5. 未探索行・列の使用回数に応じたボーナスを入れる。

上位化を狙うなら、`ymatsux -> contramundum簡略版` がよい。まず `M=1/2` の2モデルだけを持ち、モデル別の平均・不確実性・尤度を扱う。MCMCや8モデル化は、可視化とベンチマークが整ってから入れるべきである。

## 重要な実装要素

- 状態表現: 辺ID、過去パスの辺ID列、返却値、行・列通過回数、回帰パラメータ、推定辺コスト。
- 評価関数: 観測パス長と返却値の誤差、Ridge/L2正則化、モデル尤度、探索ボーナス。
- 近傍: 辺コスト1点変更、生成パラメータ1点変更、境界1マス移動。
- 差分更新: 各クエリの現在推定パス長を持つと、辺1つの変更で影響するクエリだけ更新できる。
- 候補管理: Dijkstra用の辺コスト配列、探索フェーズの候補パス、未探索行・列のカウント。
- 出力判定: 必ずグリッド内の単純な `s-t` パスを出す。Dijkstra復元なら安全。
- パラメータ: 正則化係数、探索ボーナス、探索終了ターン、`M` 分類閾値、時間制限回避。

## 落とし穴

- 返却値はノイズ付きなので、過去クエリを完全に満たすように推定すると過学習する。
- 辺数1740に対して観測1000なので、辺を独立に推定すると情報不足になりやすい。
- 初期コストを低くする探索は簡単だが、複数モデルの尤度を使う解法では嘘の事前分布として悪影響を与える。
- 未探索ボーナスを強くしすぎると、マンハッタン距離より長い経路を選びすぎて序盤スコアを落とす。
- 標準偏差を辺ごとに引いたコストは扱いやすいが、経路全体の分散とは一致しない。
- 経路依存の情報量ゲインをDijkstraに混ぜると、Dijkstraの最適性が崩れる。
- `M=2` の境界推定は、左右基本値の差が小さいとノイズに負けやすい。
- interactiveなので、出力後のflush漏れはTLEにつながる。
- 同じ頂点を複数回通る、範囲外に出る、始点終点が違うパスはWAになる。
