## 解法の全体像

入力生成パラメータをほぼそのまま推定対象にする。`M` は2固定、`D` は無視し、`H_{i,p}`, `V_{j,p}`, 境界 `x_i,y_j`, 辺別誤差 `delta,gamma` を合わせた1920パラメータを持つ。各クエリから得られる「出力パスの推定長とフィードバック値の差」をMSEとして評価し、過学習を防ぐために辺別誤差にL2正則化を入れる。

パラメータ更新は解析解ではなく焼きなましで行う。各フィードバックのたびに制約式を追加し、パラメータの1点変更近傍を毎クエリおよそ1000から10000回試す。経路選択は推定コストによるDijkstraを基本にしつつ、最初の15クエリだけは探索用に「各辺に累積された平均実測値」を使う。

## 主要アイデア

- クエリの返却値を、通った辺長の線形和にノイズが乗った制約式として扱う。
- 辺数1740に対してクエリ1000なので、単純な連立方程式は不良設定になる。
- 生成パラメータ全体を推定すれば、問題文の構造を利用できる。
- `M=1` は `M=2` で左右基本値が等しい場合として吸収する。
- 評価は観測値とのMSEに、辺別誤差のL2正則化を加える。
- 更新は焼きなましで、パラメータ1点変更を近傍にする。
- 序盤だけ、通った辺に `F_k/|P_k|` を足した累積値+1を辺コストにして探索する。
- UCB系やThompson Samplingも試したが、経路問題への落とし込みが難しく捨てている。

## 最終コードの構造

提出 #23031070 の実装に基づく構造である。記事の「生成パラメータを焼きなましで推定する」方針は、実装では `SplittedBoard` として、低周波成分、境界、辺別高周波成分を分けて持つ形になっている。

### 状態表現

- 推定パラメータは実装上、`SplittedBoard` に集約される。
  - `board_distances`: Dijkstra用の現在推定辺長。
  - `low_pass_board`: 行・列の低周波な基本値。
  - `splits`: 行・列の境界位置。
  - `high_pass_board`: 辺別の高周波補正。
  - `counts`, `distance_sum`: 通過回数と観測距離の累積。
  - `low_pass_related_paths`, `high_pass_related_paths`: 変更時に影響する過去パスを引くための逆引き。
- 各過去クエリについて、出力した辺ID列とフィードバック値 `F_k` を保持する。
- 序盤探索用に、各辺へ `F_k / |P_k|` を加算した累積値を持つ。
- Dijkstra用の現在辺コスト配列を持つ。

### 観測・制約・入力の扱い

- `e_k` のノイズは無視し、フィードバック `F_k` を真のパス長の近似値として扱う。
- それぞれのクエリは「推定パラメータから計算したパス長が `F_k` に近い」という制約になる。
- `D` は推定せず、辺別誤差や正則化で吸収する。
- `M` は常に2として扱い、`M=1` ケースでは左右基本値が自然に近づくことを期待する。

### 評価関数

- 主目的は、過去クエリに対するMSEの最小化。

```text
loss_observation = mean_k (predicted_path_length(path_k) - F_k)^2
```

- 過学習を防ぐため、辺別誤差にL2正則化を入れる。

```text
loss = loss_observation + lambda * (||delta||_2 + ||gamma||_2)
```

- 途中段階では、辺コスト直推定に対する二乗ペナルティ、隣接辺の差の二乗ペナルティなども試している。

### 探索・構築・更新

- 各フィードバック後にオンラインで観測制約を追加する。
- 焼きなましでパラメータを更新する。実装では主に以下の関数に分かれる。
  - `low_pass_value_annealing`: 基本値を動かす。
  - `low_pass_split_anneling`: 境界を動かす。
  - `high_pass_value_annealing`: 辺別補正を動かす。
  - `low_pass_value_search`: 低周波値を探索で整える。
- 毎クエリの時間は約2ms未満だが、近傍評価は1000から10000回程度回ったとされる。
- 後半ほど制約式が増え、RMSE計算が重くなるため、近傍数は減りやすい。

### 操作・クエリ・出力選択

- 序盤15クエリは、各辺の探索累積値 `sum(F_k/|P_k| over paths containing edge) + 1` に相当する距離情報をDijkstraコストにする。
- 中盤以降は、`SplittedBoard` の `board_distances` を使ってDijkstraする。
- Dijkstraで得た経路を `U/D/L/R` に変換して出力する。
- 出力後、返却値を観測制約に追加し、焼きなまし更新する。

### 時間配分・パラメータ

- 序盤探索は最初の15クエリ。
- 毎クエリの焼きなまし近傍回数はおよそ `10^3` から `10^4`。
- 正則化係数や焼きなまし温度などの具体値は記事からは分からない。
- パラメータ調整は手作業で行ったと述べられている。

## 実装上重要な断片

```text
predict_edge(edge):
    if horizontal edge (i,j):
        base = H[i][0] if j < x[i] else H[i][1]
        return base + delta[i][j]
    else:
        base = V[j][0] if i < y[j] else V[j][1]
        return base + gamma[i][j]
```

after_feedback(path, F):

## この解法の本質

この解法は、線形代数で正確に解く代わりに、生成パラメータをそのまま大きなヒューリスティック最適化問題として扱っている。未知辺長そのものを1740個ばらばらに持つより、問題文の `M=2` 構造を入れることで、少ない観測からでも地図の形を推定しやすくしている。

また、過学習対策が重要である。クエリ数より変数が多く、観測ノイズもあるため、制約を満たすだけでは壊れた辺長になる。辺別誤差に正則化を入れることで、基本値で説明できる部分は基本値に任せ、細かな差分を暴れさせないようにしている。

## 真似するならまず実装する部分

まずは境界 `x_i,y_j` を固定または中央固定にして、`H,V,delta,gamma` のうち基本値だけを回帰・局所探索で推定する簡略版がよい。次に、辺別誤差とL2正則化を入れる。最後に境界を近傍として動かす。

焼きなましで完全再現するより、同じ状態表現を使って勾配法やRidge回帰に寄せる実装の方が、調整はしやすい可能性がある。

## 注意点・未理解点

- 最終提出 #23031070 はBrowserで読めたため、`SplittedBoard`、`low_pass/high_pass`、`add_path`、Dijkstra、時間制限配列 `get_time_limits` の存在は確認済みである。ただし、提案幅や温度定数の全値はこのメモでは網羅していない。
- `x_i,y_j` のような離散境界と、`H,V,delta,gamma` の連続値を同じ焼きなましで扱うため、近傍設計がスコアに大きく影響するはずだ。
- 観測ノイズ `e_k` を無視してMSEにしているため、後半の過去データが増えた状態でノイズに引っ張られやすい可能性がある。
- 序盤探索は15クエリだけで、UCB系は使っていない。探索不足のケースは残り得る。
- 1920パラメータを毎クエリ最適化するため、実装の定数倍と差分計算が重要である。
