## 解法の全体像

短時間で作れるランダム順貪欲をベースにし、それを部分破壊再構築で繰り返し改善する解法である。まず住民をランダム順に見て、今の出力から追加コストが最小になる放送局でその住民をカバーするよう出力を引き上げる。次に、正の出力を持つ放送局を頂点 1 に接続するため、全点対最短路を使った Prim 風のシュタイナー木近似を作る。改善では一部の放送局出力を 0 にして、影響を受けた住民だけ貪欲で修復する。

## 主要アイデア

- 住民をランダム順に処理し、追加コストが最小の放送局を選ぶ。
- 追加コストは、距離二乗 `d^2` と現在出力二乗 `P_i^2` の差で評価する。
- 放送局と住民のペアは、距離 5000 以内のものだけ列挙して枝刈りする。
- 各住民から近い放送局リスト `norms` と、各放送局から近い住民リスト `rnorms` を前計算する。
- 2回目以降の反復では、各放送局を約10%の確率で破壊し、破壊で影響した住民だけ再更新する。
- 接続は全点対最短路を前計算し、現在連結済みの頂点から未連結の正出力頂点への最短パスを優先度付きキューで足す。
- 同じ正出力頂点集合に対する辺集合を `HashMap` でメモ化し、接続計算を省く。
- 時間いっぱい反復し、実コスト `sum(P_i^2)+sum(w_e)` が最良の解を保持する。

## 最終コードの構造

### 状態表現

- `power: Vec<i32>`: 各放送局の出力強度。
- `onoff: Vec<i64>`: 各辺を使うかどうか。
- `bests: (i64, Vec<i32>, Vec<i64>)`: 最良コスト、最良出力、最良辺集合。
- `norms[j]`: 住民 `j` をカバー可能な放送局を `(二乗距離, 放送局)` の昇順で持つ。
- `rnorms[i]`: 放送局 `i` から距離 5000 以内の住民を `(二乗距離, 住民)` の昇順で持つ。
- `update[j]`: 今回の貪欲修復で住民 `j` を処理すべきか。
- `cond[i] = power[i] > 0`: 辺集合メモ化用の正出力頂点集合。
- `memo: HashMap<Vec<bool>, Vec<i64>>`: `cond` から辺ON/OFFへのキャッシュ。
- `sp[s]`: 各始点 `s` からの Dijkstra 距離と、最短路復元用の親情報。

### 観測・制約・入力の扱い

- 距離 5000 を超える放送局-住民ペアは使わない。
- 距離は二乗距離で前計算する。
- `pow = ceil(sqrt(norm))` によって、対象住民をちょうどカバーできる整数出力へ上げる。
- グラフは重み付き無向グラフとして読み、全始点 Dijkstra で最短路距離と親辺を保存する。
- 出力が正の放送局だけ接続対象にする。

### 評価関数

- 厳密な提出コスト `S = sum(power[i]^2) + sum(w[e] for onoff[e]=1)` を使う。
- 貪欲修復中の選択では、住民 `j` に対して `norm - power[i]^2` が最小の放送局を選ぶ。これはその放送局の出力を対象住民まで上げた場合の追加二乗コストに相当する。
- 接続コストは各反復で辺集合を得た後に加算する。辺集合がキャッシュ済みなら再計算しない。

### 探索・構築・更新

- 初回反復では `update[j] = true` とし、全住民をランダム順貪欲で処理する。
- 2回目以降は最良解の `power` から始める。
- 各放送局について 10% 程度の確率で破壊する。
  - 破壊前の半径内にいた住民を `update=true` にする。
  - その放送局の出力を 0 にする。
- `update=true` の住民だけ、`norms[j]` から `norm - power[i]^2` 最小の放送局を選び、必要なら出力を上げる。
- 正出力頂点集合 `cond` が未キャッシュなら、Prim 風に辺を構築する。
  - 根 0 を連結済みにする。
  - 連結済み頂点から未連結の正出力頂点への最短路をヒープへ入れる。
  - 最短候補を取り、最短路の親辺を復元して ON にする。
- 得られた `S` が最良なら更新する。

### 操作・クエリ・出力選択

- 最終的に `bests` に入っている `power` と `onoff` を出力する。
- 接続対象は `power[i] > 0` の頂点だけである。
- `memo` によって同じ接続対象集合に対する辺集合を再利用する。

### 時間配分・パラメータ

- コードでは `now.elapsed() < 1.95` 秒まで反復する。
- 破壊確率は各放送局ごとに `0.1`。
- 全始点 Dijkstra を前計算して、接続構築を高速化する。
- 提出は 1961 ms、メモリ 36528 KiB で AC。

## 実装上重要な断片

```text
repair(updated_residents):
    shuffle(residents)
    for j in residents:
        if not update[j]:
            continue
        choose (norm, i) minimizing norm - power[i]^2
        power[i] = max(power[i], ceil_sqrt(norm))
```

```text
destroy():
    for each station i:
        if random() < 0.1:
            for resident j within old power[i]:
                update[j] = true
            power[i] = 0
```

```text
build_edges(active):
    if memo has active:
        return memo[active]
    used = {root}
    heap = shortest paths from used to active
    while heap not empty:
        take nearest active station u
        turn on parent edges along shortest path
        add u to used
    memo[active] = onoff
```

## この解法の本質

この解法の本質は、複雑な焼きなましではなく、速い貪欲修復を何度も回すことにある。出力を 0 にする破壊は局所解から抜ける効果があり、修復は `norm - P_i^2` だけで軽く判断できる。さらに、住民と放送局の到達可能ペアを前計算し、影響した住民だけ更新するため、単純な全再計算より反復数を稼げる。

## 真似するならまず実装する部分

まず `norms` と `rnorms` を作り、ランダム順貪欲で全住民をカバーする出力を作る。次に全点対 Dijkstra と Prim 風接続を実装する。最後に、最良解から一部の放送局を 0 にして影響住民だけ貪欲修復するループを入れる。この順序なら、常に提出可能な解を保ちながら改善できる。

## 注意点・未理解点

- 提出コードの貪欲修復は `update=true` の住民だけを見るため、破壊で影響した住民を漏らすと未カバーが発生する。
- `ceil(sqrt(norm))` は浮動小数を使うと境界誤差がありうる。安全には整数平方根で補正する方がよい。
- 辺集合キャッシュのキーは `power[i] > 0` の真偽列なので、同じアクティブ集合であれば出力値が変わっても接続は同じとみなす。
- Prim風接続は厳密シュタイナー木ではない。
- 記事本文では「1割くらい？」とあるが、提出コードでは各放送局を独立に 10% 確率で破壊している。
