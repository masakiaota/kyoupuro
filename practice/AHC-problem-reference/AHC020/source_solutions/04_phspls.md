## 解法の全体像

住民ごとに「どの放送局がその住民へ放送を届けるか」を明示的に割り当て、その割当を焼きなましで変える解法である。出力強度 `P_i` を直接自由に動かすのではなく、各放送局に割り当てられた住民の最大距離から `P_i` を自動的に決める。これにより、全住民カバーと「出力を下げると担当住民が欠ける」という性質を保ちやすくしている。辺は、正の出力を持つ放送局を Prim 法風に接続し、後から不要な葉を削る。

## 主要アイデア

- 住民 `X` を放送局 `Y` に割り当てる状態を持つ。
- 各放送局の出力は、割り当てられた住民への必要距離の最大値で決まる。
- 初期解は、住民を順に見て出力二乗コストの増分が最小になる放送局へ割り当てる貪欲で作る。
- 近傍では、現在担当放送局の出力強度を決めている「最遠の担当住民」を選び、別の放送局へ割り当てる。
- ある住民を新しい放送局へ割り当てたら、その新半径内にいる住民もまとめて新放送局担当にする。
- 悪化量を考慮する焼きなましを導入して 496M 点帯へ到達している。
- 通信ケーブルは、使う放送局すべてが頂点 1 と連結した時点で止める Prim 風構築を行い、その後 `P=0` の葉を削る。
- 著者は、`P_i` を自由に変更する実装はバグりやすく、無駄な遷移も多そうだとして避けている。

## 最終コードの構造

Browserで読めた提出 `42961812` と記事本文を分けて読む。本文は住民割当状態の説明だが、読めた提出コードは `P` と接続木を直接更新する実装である。

### 状態表現

- `assign[k]`: 住民 `k` を担当する放送局。
- `owned[i]`: 放送局 `i` に割り当てられた住民集合、またはその距離分布。
- `P[i]`: `owned[i]` に含まれる住民までの最大必要距離。
- `critical_residents`: `dist(assign[k], k) == P[assign[k]]` を満たし、その放送局の出力を決めている住民候補。
- `active[i]`: `P[i] > 0` の放送局。
- `B[e]`: 最終接続に使う辺。
- `score`: 出力コストと辺コストの合計。

### 観測・制約・入力の扱い

- 各住民について、`P_i <= 5000` で届く放送局候補を持つ。
- 割当状態で全住民が常にどこかの放送局に担当されるため、未カバー状態を避けやすい。
- 各放送局の `P_i` は担当住民の最大距離で決まるため、余分な半径が残りにくい。
- 通信ケーブルは最後に、正出力放送局を根 1 へ接続する木として構築する。

### 評価関数

- 基本は `S = sum(P_i^2) + tree_cost(active)` の最小化。
- 記事の最終解では、焼きなましの悪化量を考慮する採択を使っている。
- 初期解の貪欲では、放送局 `i` に住民を追加したときの `new_P_i^2 - old_P_i^2` を見る。
- 木構築は近似であり、厳密な最小シュタイナー木ではない。

### 探索・構築・更新

- 初期解:
  - 住民を順番に処理する。
  - その住民をカバーできる放送局の中で、出力二乗増分が最小のものへ割り当てる。
- 近傍:
  - 現在の担当放送局の出力を決めている住民からランダムに1人選ぶ。
  - その住民をカバー可能な放送局をランダムに選ぶ。
  - 新放送局がその住民をカバーするのに必要な半径を計算する。
  - 新半径内の住民をまとめて新放送局担当に変更する。
  - 元放送局は最遠担当住民を失うため、出力が下がる可能性が高い。
- 採択:
  - 当初は悪化量を考えない焼きなましだったが、最終的には悪化量と温度に基づく焼きなましへ修正している。
- 辺構築:
  - Prim 法風に、使う放送局がすべて頂点 1 と連結した段階で構築を止める。
  - その後、木の葉で `P=0` の頂点を順に削除する。

### 操作・クエリ・出力選択

- 最終的な割当から `P` を再計算する。
- `P_i > 0` の放送局を通信網で接続し、不要葉を削った辺集合を `B` とする。
- 出力は `P` と `B`。

### 時間配分・パラメータ

- 焼きなましの反復回数はローカルで 30,000 から 40,000 回程度と書かれている。
- 高速化はあまり入れていないと明記されている。
- 山登り版では 200 から 300 msec 程度で収束する様子をビジュアライザで確認している。
- 温度はビジュアライザを見ながら感覚的に調整したとされ、具体値は公開されていない。

## 実装上重要な断片

```text
recompute_power(i):
    P[i] = max(ceil_distance(i, k) for k assigned to i)
    if no assigned residents:
        P[i] = 0
```

```text
transition():
    k = random resident whose current station radius is tight
    old = assign[k]
    new = random station that can cover k
    r = distance(new, k)
    move all residents within radius r of new to new
    update P[old], P[new], and affected score
    accept by SA
```

## この解法の本質

この解法の本質は、半径を直接状態にせず、住民の割当を状態にすることで無駄な半径を自然に消す点である。`P_i` を少し変えるだけの探索では、カバー集合が変わらない無意味な遷移や、未カバー判定の重さが問題になる。割当で持てば、各放送局の半径は担当住民の最大距離に固定されるため、状態が常に「誰を守るための半径か」を持つ。さらに、最遠担当住民だけを近傍起点にすることで、元放送局の半径が下がる可能性のある遷移を狙える。

## 真似するならまず実装する部分

まず、住民からカバー可能な放送局候補を作り、住民割当と `P` 再計算を実装する。次に、出力二乗増分最小の貪欲で初期解を作る。最後に、最遠担当住民を別放送局へ移す山登りを作り、動作確認後に焼きなましへ拡張するのがよい。辺構築は最初は単純な Prim 風で十分だ。

## 注意点・未理解点

- 提出コードの温度・採択式・木構築は確認できた。一方、本文で説明された住民割当版との対応や途中版の差分更新粒度は不明である。
- 割当をまとめて変更する近傍は強いが、どの住民がどの放送局に移ったかのロールバックが壊れやすい。
- `P_i` の再計算を毎回全担当住民から行うと重い。最遠住民を管理する構造が必要になる可能性がある。
- Prim 風接続と葉削除は厳密シュタイナー木ではない。
- 記事中では、初期解の増分評価で二乗を忘れるバグ、priority queue の向きで最大木になるバグがスコアに大きく響いたと説明されている。
