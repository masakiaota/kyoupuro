## 問題の本質

この問題は、住民を円で覆う集合被覆と、使う放送局を根に接続するシュタイナー木近似を同時に最適化する問題である。高スコア帯では全住民カバーがほぼ必須で、その上で `sum(P_i^2)` と辺コストを下げる。出力コストが二乗なので、大きな半径を少数残すより、担当を分散して半径を下げる再配置が効きやすい。一方、放送局を増やすと接続コストが増えるため、出力削減と通信網削減のバランスが本質になる。

## 共通している考え方

- 全住民カバーを基本制約として扱う。
- 出力半径は、住民をちょうど覆う境界だけを候補にする。
- `P_i^2` の増分を評価し、出力を上げる価値と下げる価値を比較する。
- 使う放送局集合が決まったら、辺は Prim/Kruskal/最短路ベースのシュタイナー木近似で決める。
- 厳密な木計算は重いため、探索中は省略、キャッシュ、近似のいずれかを使う。
- 部分破壊再構築が強い。ある放送局を消して、未カバー住民を貪欲に修復するだけでも局所解を崩せる。
- 距離は二乗整数で扱い、平方根の境界誤差を避ける。

## 解法の分類

- 貪欲型: HBit初期解、phspls初期解、FakePsyho `kgreedy`。
- 焼きなまし型: terry-u16公式、WA_TLE、phspls。
- 山登り型: HBit提出コード、FakePsyhoコード、phsplsの途中版。
- 部分破壊再構築型: HBit、jetbeadの推奨、FakePsyho。
- 住民割当型: phspls。
- 強度直接探索型: terry-u16公式、WA_TLE。
- 接続木近似型: 全参照元で Prim/MST/最短路ベースの近似を利用。

## 推奨して理解すべき順序

1. まず HBit を読む。貪欲、破壊、修復、接続の最小構成が提出コードで分かる。
2. 次に公式スライドを読む。HBit型から差分更新、焼きなまし、MST近似へ発展する流れが分かる。
3. phspls を読む。`P` ではなく住民割当を状態にする別の見方が得られる。
4. WA_TLE を読む。塔を強くして周辺塔を弱くする上位近傍を理解する。
5. jetbead を最後に読む。複数方針の共通部品と落とし穴を整理できる。

## 実装するならどのルートか

理解のための最小実装は HBit ルートがよい。`norms/rnorms` を前計算し、ランダム順貪欲で全住民をカバーし、正出力放送局を Prim 風に接続する。次に、最良解から一部放送局を 0 にして影響住民だけ修復する。

上位化の方向は2つある。1つ目は公式ルートで、被カバー数と距離順リストによる差分更新を入れ、焼きなまし回数を増やす。2つ目は phspls/WA_TLE ルートで、住民担当や半径境界を状態にし、出力再分配そのものを近傍にする。

## 重要な実装要素

- 状態表現: `P[i]`, `active[i]`, `cover_count[k]`, `assign[k]`, `B[e]` のどれを主状態にするかを決める。
- 評価関数: 最終的には `sum(P_i^2)+sum(w_e)`。探索中は木コストを厳密に見るか、近似するか、最後だけ見るかを選ぶ。
- 近傍: 放送局を 0 にする、半径を住民境界へ動かす、最遠担当住民を移す、1塔を強めて他塔を弱める。
- 差分更新: 住民の距離順リストと被カバー数を持つと、半径変更でまたがる住民だけ見ればよい。
- 候補管理: 距離 5000 以内の放送局-住民ペアだけを持つ。候補数を近い10件などに絞る実装もある。
- 出力判定: 全住民カバー、`0 <= P_i <= 5000`、ON辺による根からの到達を最後に検証する。
- パラメータ: 破壊確率、温度、候補数、クラスタ数、木計算キャッシュの有無が効く。

## 落とし穴

- 未カバー住民を1人でも出すと、高スコア帯から大きく落ちる。
- `P_i > 0` でも根から到達できない放送局は無効なので、辺構築の連結性確認が必須である。
- `P=0` の葉を削るとき、根や中継に必要な頂点まで消すと壊れる。
- `sqrt` と `ceil` の境界で、本来届く/届かない判定を誤る可能性がある。
- 半径を1ずつ増減するだけだと、カバー集合が変わらない無駄な遷移が多い。
- 木コストを完全に無視すると、出力は良いが接続が高い解を選びうる。
- 厳密シュタイナー木を毎反復で解こうとすると、探索回数が足りなくなる。
- 貪欲修復で候補放送局を絞りすぎると、遠いが接続上有利な放送局を見逃す。

## 未解決・要検証事項

- WA_TLE の提出コードは読めたが、クラスタリング間引き距離や温度係数の調整理由は不明である。
- 公式writer提出は読めたが、スライドの各改善段階とコード差分の完全対応は未確認である。
- phspls は提出コードを読めたが、本文で説明された住民割当版と提出コードの差分は一部不明である。
- 厳密シュタイナー木ソルバをキャッシュ付きで探索へ入れる価値は、実装コストと時間制限の面で要検証である。
- X/Twitterリンク集の短文知見は全件精読していないため、jetbeadメモ内の外部短文由来の細かな工夫は拾い切れていない。
