## 解法の全体像

各送信グラフについて、ノイズ後に得られるソート済み次数列の期待値をシミュレーションで作る。クエリでは観測グラフの次数列を取り、各候補の期待次数列との距離が最小のものを答える。

重要なのは、送るグラフ集合をこの距離で識別しやすいように事前に選ぶことだ。17種類の規則で候補グラフを生成し、候補から `M` 個を焼きなましで選ぶ。`M, N, epsilon` ごとに選んだID列を圧縮して提出コードに埋め込む。`N` も事前実験で選ぶ。

## 主要アイデア

- 頂点番号が失われても次数列は不変なので、ソート済み次数列を特徴量にする。
- 各候補グラフについて、ノイズを400回シミュレーションし、次数列各順位の平均を保存する。
- 距離は `sum |observed_rank[k] - expected_rank[k]|^2.60117`。指数はOptunaで選んだ値。
- 候補グラフは、辺数を等間隔に変えたものを17種類の詰め方で生成し、合計 `17M` 個から選ぶ。
- グラフ集合選択の焼きなましは、選ばれたグラフ間距離を小さい順に並べ、`sum d_k * 0.9^k` を最大化する。
- 提出サイズ制限対策として、選択ID列を差分化してASCII文字列へ圧縮する。
- `epsilon=0` は別処理で、同型類代表グラフを使って完全復元を狙う。

## 最終コードの構造

提出コードはC++で、次数列方式の本体、`epsilon=0` 用の同型判定系、大量の事前計算配列・圧縮文字列を含む。記事で説明された圧縮ID列がそのままコード中に埋め込まれている。

### 状態表現

- `EncodedBits`:
  - `id`: 候補ID。
  - `mat`: 候補グラフの隣接行列。
  - `bits`: 上三角01文字列。
  - `edge_count_ranking`: 元グラフのソート済み次数列。
  - `ranking_mean`: ノイズ後次数列の順位ごとの平均。
  - `ranking_sigma`、`ranking_distribution_counts`: 分布確認用の値。
- `N_arr`: `(M, epsilon)` から選ぶ `N` の事前計算表。
- `selection_string_vec_small/large`: `epsilon < 0.3` とそれ以上で分けた、選択ID列の圧縮文字列。
- `selection_vec`: 現在のケースで使う候補ID列。

### 観測・制約・入力の扱い

- `M, epsilon` を読み、`epsilon < 0.009` なら同型グラフ方式へ分岐する。
- それ以外では `N_arr[M-10][epsilon*100]` で目標 `N` を決める。
- コードサイズ削減のため、実際の `N` は記事通りに間引いた候補へ丸める。
- 観測グラフは上三角01文字列から各頂点次数を数え、降順ソートした次数列にする。
- 各候補は出力前に400回ノイズシミュレーションして `ranking_mean` を作る。

### 評価関数

クエリ時の候補距離は以下の形である。

```text
distance(m, H) = sum_k |rank_H[k] - mean_rank_m[k]|^2.60117
```

グラフ集合選択時は、選択済みグラフ間の距離を小さい順に並べて重み付き和を最大化する。

```text
score(selected) = sum_k sorted_pair_distances[k] * 0.9^k
```

最小距離だけを見ると状態空間が平坦になるため、近いペアほど強く、遠いペアも少し効くようにしている。

### 探索・構築・更新

- 候補構築では、辺数 `edge_count = floor(C(N,2)/(M-1)) * id` を使う。
- 17種類の詰め方には、star、dense、star+dense、star+sparse、dense+sparse、両側dense、右上、チェッカー状などがある。
- 事前計算時の焼きなまし状態は `M` 個の候補ID集合。
- 近傍は、使用中候補を1つ外し、未使用候補を1つ入れる交換。
- `N` とID列はローカルで探索し、提出時には圧縮文字列として埋め込む。

### 操作・クエリ・出力選択

- 起動時に `selection_vec = decode(N_ind_val())` でケース用のID列を復元する。
- `make_encoded_vec` で各IDから行列を生成し、グラフを出力し、同時に次数列分布をシミュレーションする。
- クエリごとに観測次数列を作り、`distance_between_rankings2` が最小の候補番号を出す。
- `epsilon=0` 分岐では、`N=5..9` 程度の代表グラフを出し、入力グラフを同型類にデコードして一致候補を返す。

### 時間配分・パラメータ

- ノイズシミュレーション回数は候補ごとに400回。
- 距離指数は `2.6011738528635786`。
- `epsilon` の大小分岐はID列選択では `0.3`。
- `N` の埋め込みは、小さい `N` は細かく、大きい `N` は偶数または4の倍数に間引く。
- 提出サイズは512KiB制限ぎりぎりで、ID列圧縮が実装上の大きな要素になっている。

## 実装上重要な断片

```text
prepare_candidate_graph(m):
    for repeat in 1..400:
        noisy = flip_each_edge(candidate[m], epsilon)
        rank = sorted_degrees(noisy)
        mean_rank[m] += rank / 400
```

```text
answer(H):
    x = sorted_degrees(H)
    best = argmin_m sum_k abs(x[k] - mean_rank[m][k])^2.60117
    return best
```

```text
decode_selection_string(s):
    base = 0
    for token in encoded_ascii_tokens(s):

```

## この解法の本質

この解法の本質は、グラフ同型性を完全に解こうとせず、頂点番号に依存しない次数列へ情報を圧縮する点にある。次数列は頂点シャッフルに強く、ノイズ後の期待値もシミュレーションで簡単に見積もれる。その代わり、識別できる情報量は少ないため、送信グラフ集合の選び方が性能を大きく左右する。

候補グラフの事前選択と提出サイズ制限への圧縮まで含めて、シンプルな特徴量を大量のローカル探索で支える解法である。

## 真似するならまず実装する部分

まずは、固定 `N` で辺数の異なる単純な候補グラフを作り、ノイズ後次数列の平均と観測次数列の距離で分類する部分を実装する。これだけで「次数列でどこまで情報が残るか」を確認できる。

次に、17種類すべてでなくてもよいので複数のグラフ生成規則を作り、候補集合の焼きなまし選択を入れると、この解法らしい改善が見える。

## 注意点・未理解点

- 次数列だけでは異なるグラフが同じ特徴になる。候補選択が悪いと一気に混同する。
- 距離指数 `2.60117` は経験的パラメータで、理論的根拠は薄い。
- 候補グラフの焼きなましスコアと実際の問題スコアは完全には一致しないと記事脚注で述べられている。
- 提出コードの圧縮文字列は実装都合の塊で、生成過程を再現しないと意味を追いにくい。
- `epsilon=0` 分岐と次数列分岐は別方式なので、1つの統一モデルとして理解しない方がよい。
