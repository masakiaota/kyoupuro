## 実装キャッシュで確認した内容

- 状態は `next[[usize;2];100]`, `counts`, `score`。初期解は全員 `a_i=b_i=i` の自己ループである。
- 評価は `env.weeks` だけ実遷移を回す。`person = next[person][counts[person] % 2]` とし、スコアは `1e6 - sum_abs * 500000 / env.weeks`。
- 焼きなましは `3906,7812,15625,31250,62500,125000,250000,500000` 週の8段階。各段で評価長を伸ばし、合計1.99秒程度に正規化している。
- 近傍は 1-edge change、誤差頂点を狙う suitable change、random swap、suitable swap、2本を1本へ寄せる one-to-two swap、`a/b` の順序入れ替え。`shift` は `weeks < 250000` では無効化される。
- suitable 系は、過不足の大きい頂点を `excess^4` や `diff^4` で重く選び、その頂点への入辺を中心に局所改善を見積もる。候補選択だけ近似し、採択判定は実シミュレーション評価で行う。
- デフォルト温度列と近傍確率がコード内に固定されている。代表値は `swap=0.0308500969`, `swap_suit=0.8386667150`, `change=0.0300141678`, `change_suit=0.8165241569`, `shift=0.3729115680`。

## 解法の全体像

`a_i, b_i` を長さ `2N` の配列として持ち、焼きなましで辺を変更する。評価は実際の遷移をシミュレーションして訪問回数を数えるだけの素直なものだが、最初から `L=500000` を使わず、短いシミュレーション長から段階的に伸ばして評価を精密化する。

近傍は1点変更と2点swapを基本にする。ただし完全ランダムな近傍ではなく、現在の訪問回数と目標値の差が大きい頂点を優先し、その頂点へ入る辺を入れ替えると局所的に改善しそうな候補を重み付き乱択する。最終的には温度や近傍選択確率をOptunaで調整している。

## 主要アイデア

- 解を `c=(a_0,...,a_{N-1},b_0,...,b_{N-1})` と見なして、辺の付け替え問題にする。
- 初期解は `a_i=b_i=i` という単純な自己ループから始める。
- 評価はシミュレーション長を `3906, 7812, ..., 250000, 500000` と2倍ずつ伸ばす多段焼きなましにする。
- 1点変更と2点swapを使うが、変更対象を現在の誤差と局所改善見込みに基づく重み付き乱択で選ぶ。
- swap候補の見込み改善は、本来波及する子孫全体ではなく、入れ替え先の頂点だけを見た近似で十分と割り切る。
- 重みは最終的に誤差や改善量の4乗を使い、悪い頂点・良い候補をより強く引く。

## 最終コードの構造

以下は本文ベースの整理を含む。提出 #63970541 の実装差分は上の「実装キャッシュで確認した内容」を優先する。

### 状態表現

- `to[2N]`: `0..N-1` が `a_i`、`N..2N-1` が `b_i` に対応する遷移先。
- `cnt[N]`: 現在評価での各社員の訪問回数。
- `in_edges[N]`: 各社員へ入る `to` の添字集合。近傍候補列挙に使う。
- `score` または `error`: `sum |cnt_i - target_i|`。短縮評価では目標値も同じ比率に縮尺していると考えられる。

### 観測・制約・入力の扱い

- 入力は `N=100, L=500000` 固定として扱える。
- 出力制約は各 `a_i,b_i` が `0..N-1` に入ることだけである。
- 連結性は明示的には管理しない。記事では「グラフの連結性を考慮しなくてもよい」としている。

### 評価関数

- 遷移規則を `L_k` 週だけシミュレーションし、訪問回数 `cnt_i` を得る。
- `sum_i |cnt_i - T_i * L_k / L|` を小さくする近似評価と解釈できる。
- 最終段では `L_k=500000` なので実スコアと同じ誤差を直接見る。

### 探索・構築・更新

- 多段焼きなまし:
  - 短い `L_k` で焼いた解を次の長い `L_{k+1}` の初期解にする。
  - 温度、各段の時間、近傍比率はOptunaで調整した。
- 近傍:
  - 1点変更: `to[p]` を別の社員に変える。
  - 2点swap: `to[p]` と `to[q]` を交換する。
- 候補選択:
  - `|cnt_i - target_i|` が大きい社員を重く選ぶ。
  - 選んだ社員へ入る辺と、交換候補の辺を列挙し、対象頂点だけを見た改善量を見積もる。
  - 改善見込みが正の候補だけ残し、改善量の4乗に比例して選ぶ。
- 採択:
  - 候補を実際に適用して再シミュレーションし、焼きなましの確率で採択する。

### 操作・クエリ・出力選択

- 最終的に保持している `to[0..N-1]` と `to[N..2N-1]` を各行 `a_i b_i` として出力する。
- インタラクティブではないため、途中提出やクエリはない。

### 時間配分・パラメータ

- 評価長は8段階で `L/128` から `L` まで増やす。
- 温度・段階ごとの時間・近傍選択確率はOptunaでチューニング。
- 重み付き乱択は最終的に `誤差^4` と `改善量^4` を使う。

## 実装上重要な断片

```text
simulate(to, steps):
    cur = 0
    cnt = [0] * N
    for week in 0..steps-1:
        cnt[cur] += 1
        if cnt[cur] % 2 == 1:
            cur = a[cur]
        else:
            cur = b[cur]
    return cnt

choose_swap_candidate(cnt):
    i = weighted_sample(|cnt_i - target_i|^4)
    candidates = []
    for edge_i in in_edges[i]:
        for edge_j in all_edges:
            gain = local_gain_if_swap(edge_i, edge_j)
            if gain > 0:
                candidates.push((gain^4, edge_i, edge_j))
    return weighted_sample(candidates)
```

## この解法の本質

問題構造の数式化より、評価を実スコアに近いシミュレーションへ寄せ、その重さを段階的精緻化で処理している点が本質である。さらに、近傍選択を「完全ランダムな辺変更」から「少なくとも局所的には改善しそうな辺変更」に寄せることで、重い評価回数を無駄にしない。

最終スコアを押し上げているのは、焼きなまし自体よりも、誤差が大きい頂点と改善しそうな入辺を意識した近傍生成である。

## 真似するならまず実装する部分

まずは `to[2N]`、シミュレーション評価、1点変更、2点swapの焼きなましを実装する。次に評価長を短いものから伸ばす多段化を入れる。最後に、現在の `cnt` から誤差が大きい頂点を選び、その入辺を優先して変更する重み付き近傍を追加するのがよい。
