## 実装キャッシュで確認した内容

- 評価は50万週シミュレーションではなく、流量近似である。各社員 `i` から `ab[i][0]` へ `(T_i+1)//2`、`ab[i][1]` へ `T_i//2` を足し、`1e6 - sum |T_i-cnt_i|` を返す。
- 初期解は `T` 降順で処理し、残量 `last[j] - t//2` が大きい2頂点を選ぶ。`j != i` として自己ループを避け、入次数も管理する。
- 焼きなましは1.95秒、温度10から1。近傍確率は `[50,50,10,1]` で、1-edge change、edge swap、行全体swap、同一行の `a/b` swap。
- 1-edge change は旧行き先の入次数が1を超える場合だけ行い、新行き先は `sqrt(T)` 重みの累積から選ぶ。評価は毎回 O(N) の流量評価で再計算する。
- 最終出力前に実際の `L` 週シミュレーションを行い、頂点 `1..N-1` の実訪問回数と目標 `T` をそれぞれソートして対応付け直す。ラベルの再割当てが実装上の大きな差分である。

## 解法の全体像

最初は実シミュレーション評価の焼きなましから入り、途中で短縮シミュレーションや構築初期解を試す。最終的には「各社員の目標値の半分を遷移先へ配る」という目標値ベース評価に戻り、自己ループを禁止することで大きくスコアを伸ばしている。

参加記としての価値は、上位解法の完成形というより、素直な焼きなましから問題の本質である流量近似へたどり着く過程が具体的に分かる点にある。

## 主要アイデア

- まず `L=500000` の愚直シミュレーションで、1点変更と2辺swapの焼きなましを行う。
- 小ケースから、2人で `1:2` の頻度、拡張して `1:2:4:8` の頻度を作れることを観察する。
- 目標値を `[9600,4800,2400,...]` のような近い値でグループ化し、二冪比率の初期解を作る。
- 評価回数を増やすため、`L/100` だけシミュレーションして訪問回数を100倍する短縮評価を使う。
- 入次数0の頂点を作らない制約を試す。
- 最終盤に、目標値 `T_i/2` を行き先へ振り分ける評価へ切り替える。
- 自己ループを許すと `T_i/2` 評価で自分自身への寄与を過大評価するため、自己ループ禁止が重要になる。

### 観測・制約・入力の扱い

- ビジュアライザを見て、偶奇は週数の偶奇ではなく「その社員が何回目の担当か」の偶奇だと確認している。
- 出力上は自己ループも許されるが、目標値ベース評価では自己ループが危険になるため禁止する。

- 初期:
  - `L=500000` を愚直にシミュレーションし、`sum |cnt_i - T_i|` を評価する。

  - `L/100` 週だけシミュレーションし、訪問回数を100倍して誤差を見積もる。
- 最終盤:
  - 各社員 `i` から `a_i,b_i` へ `T_i/2` ずつ流すと仮定し、各頂点に集まる流量と `T_j` の誤差を見る。

## 実装上重要な断片

```text
target_flow_error(a, b):
    flow = [0] * N
    for i in 0..N-1:
        if a[i] == i or b[i] == i:
            return INF
        flow[a[i]] += T[i] / 2
        flow[b[i]] += T[i] / 2
    return sum_abs(flow[i] - T[i])
```

## この解法の本質

高得点帯では実際の訪問回数が目標値にかなり近いはずなので、「親の実訪問回数」ではなく「親の目標値」を使って子の訪問回数を見積もれる。この飛躍が本質である。自己ループを禁止したことで、その近似が破綻する代表例を取り除き、目標値ベース評価が機能するようになった。

## 真似するならまず実装する部分

最初から愚直シミュレーション焼きなましを長く作るより、`T_i/2` を `a_i,b_i` へ配る評価関数と、自己ループ禁止付きの1点変更・2辺swapを実装するのがよい。理解用には、短縮シミュレーション評価と目標値ベース評価を両方作り、どの候補で乖離するかを見ると問題の性質を掴みやすい。
