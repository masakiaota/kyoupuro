## 実装キャッシュで確認した内容

- コードは2部構成で、前半に e869120 風のビーム/ビンパッキング初期解、後半に ymatsux の定常分布最適化がある。
- 初期解生成は `T_i` を降順に並べ、各社員を `(T_i+1)/2` と `T_i/2` の2アイテムとして扱う。候補は1/2/3個詰めを前計算し、段階に応じて0個から4個までの箱詰め候補を使う。
- ビーム候補は、最初の25箱で連結性チェックを行い、最終的に上位100候補を実際の50万週シミュレーションで評価する。mode1/mode2 の2種類を走らせて良い方を初期状態にする。
- 定常分布側の `State` は逆辺集合と `weights` を持つ。`weights_1[v] = 0.5 * sum incoming weights_0[u]` を最大差 `0.2` 未満または1000反復まで回して収束近似する。
- グラフ妥当性は SCC で見て、成分0以外へ入る逆辺がある状態を落とす。強連結でない場合の定常分布破綻を避けるための実装である。
- 実際に呼ばれる最適化は `OptimizePhase2`。1900ms、温度20から2、100手単位のループで、局所差分近似で候補を作り、収束重みで正確なスコアを確認する。
- 近傍比率は change 10%、swap 60%、one-to-two 30%。`u` の重みが小さいと change をスキップし、自己ループは禁止している。

## 解法の全体像

決定的に `a_i,b_i` を交互に使う元問題を、各頂点から `a_i,b_i` へ確率 `1/2` で移動するランダムウォークで近似する。固定したグラフの評価は、遷移行列の定常分布 `x` を求め、`sum |x_i L - T_i|` を見る。

定常分布は連立一次方程式を解くと `O(N^3)` だが、グラフが疎で近傍変更も小さいため、前回の定常分布を初期値にした反復法で高速に更新する。探索は一点変更、二点swap、一対二swapを使った山登り・焼きなましで行い、悪い遷移は反復1回分の近似差分で早期棄却する。

## 主要アイデア

- AHC044を「各頂点から2本の辺を持つ有向グラフのランダムウォーク」として見る。
- 目標値 `T_i/L` を定常分布の目標確率と見なし、定常分布ベースで評価する。
- `x_{t+1}=P x_t` の反復法を使う。近傍後の定常分布は前状態に近いため、前の `x` を初期値にすると少ない反復で収束する。
- 一点変更・二点swapだけではなく、一対二swapで各頂点の入次数の偏りも変えられるようにする。
- 反復1回だけのスコア悪化が大きい遷移は、完全収束を待たずに棄却する。
- 序盤は反復法の収束が遅いので、別方針の焼きなましを500ms実行して初期解を作る。

## 最終コードの構造

以下は本文ベースの整理を含む。提出 #63966268 の実装差分は上の「実装キャッシュで確認した内容」を優先する。

### 状態表現

- `to[2N]`: 各社員から出る2本の遷移先。
- `out[i] = {a_i, b_i}`、`in[j]`: 定常分布更新と近傍管理用の辺集合。
- `x[N]`: 現在グラフの定常分布近似。
- `target_prob[i] = T_i / L`。
- `approx_error = sum |x_i * L - T_i|`。

### 観測・制約・入力の扱い

- `N=100`、各頂点の出次数は2本固定。ただし `a_i=b_i` も問題上は許される。
- ランダムウォーク近似が有効であるには、到達可能性・強連結性・周期性が実スコアに影響する。記事はランダムウォークの定常分布の十分条件として強連結性と非周期性を説明している。
- 元問題の決定的交互遷移との差は小さく、記事では近似スコアと実スコアの誤差が20程度だったと述べている。

### 評価関数

- 遷移行列 `P` は `P[j][i] += 1/2` for `i -> j` と置く。
- 定常分布 `x` は `x = P x`、`sum x_i=1` を満たす。
- 評価値は `sum_i |x_i * L - T_i|`。
- 収束判定は `|x_{t+1}-x_t| < epsilon` で、記事では `epsilon = 0.1 / L` が使われている。

### 探索・構築・更新

- 近傍:
  - 一点変更: 辺 `(u,v0)` を `(u,v1)` に変える。
  - 二点swap: `(u0,v0),(u1,v1)` を `(u0,v1),(u1,v0)` にする。
  - 一対二swap: 1本の行き先と、同じ行き先に向かう2本を入れ替え、入次数を変える。
- 定常分布更新:
  - 近傍を仮適用する。
  - まず反復1回相当の差分を局所的に `O(1)` で見積もる。
  - 悪化が大きければ焼きなましの受理判定だけ行い、完全な反復を省く。
  - 候補が残れば前回の `x` を初期値にして収束まで反復する。
- 序盤対策:
  - 別の焼きなましを約500ms走らせ、ある程度良いグラフから定常分布ベースの焼きなましに移る。

### 操作・クエリ・出力選択

- 最終グラフの `a_i,b_i` をそのまま出力する。
- 定常分布評価は近似なので、最終候補を実際に `L=500000` でシミュレーションして確認する実装にすると安全である。

### 時間配分・パラメータ

- 収束閾値は `epsilon = 0.1 / L`。
- 初期解生成に500ms、その後を定常分布ベースの焼きなましに使う。
- 温度や近傍比率の具体値は記事にない。

iterate_stationary(to, x):
    repeat:
        nx = [0] * N
        for u in 0..N-1:
            nx[a[u]] += x[u] * 0.5
            nx[b[u]] += x[u] * 0.5
        if norm(nx - x) < eps:
            return nx
        x = nx

try_move(move):

## この解法の本質

決定的な交互遷移を、長期的には「各出辺へ半分ずつ流量が流れる」問題として扱っている点が本質である。実際の50万週シミュレーションを捨て、定常分布という連続値の評価に置き換えることで、スコアの滑らかな近似と高速な差分更新を得ている。

また、一対二swapは単なる微調整ではなく、二点swapでは固定されがちな入次数分布を変え、定常分布そのものを動かすための重要な近傍である。

## 真似するならまず実装する部分

まずはランダムウォーク評価だけを実装する。`to` から `x_{t+1}=P x_t` を反復し、`sum |x_i L - T_i|` を返せるようにする。次に一点変更と二点swapで山登りを行う。最後に、前回の `x` を初期値にした反復継続、一対二swap、早期棄却を足す。
