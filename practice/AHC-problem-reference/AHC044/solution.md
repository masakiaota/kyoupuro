## 問題の本質

各社員 `i` が十分多く担当するなら、`i` は自分の担当回数を `a_i` と `b_i` へほぼ半分ずつ渡す。したがって高得点解では、社員 `j` の訪問回数は「`j` へ向かう親たちの訪問回数の半分の和」として近似できる。

高得点域ではさらに `t_i ≈ T_i` と見なせるので、`j` の目標 `T_j` に対して、親から来る `T_i/2` の和を近づける問題になる。これは、各社員 `i` からサイズ `T_i/2` のアイテムを2個作り、容量 `T_j` の箱 `j` へ詰めるビンパッキング問題に近い。

ただし、ビンパッキング上の誤差が小さくても、実際の遷移で0番から到達できない成分、自己ループ、閉じた成分があると実スコアは崩れる。評価近似と実遷移の整合性を最後に確認することが重要である。

## 共通している考え方

多くの解法は、直接または間接に「各社員の担当回数は親の担当回数の半分ずつの和」という流量保存を使っている。

- terry_u16は本文中でこの本質に気付いていなかったと述べているが、近傍選択では「誤差が大きい頂点に入る辺を動かす」ため、結果的に流量調整をしている。
- ymatsuxは流量をランダムウォークの定常分布として定式化している。
- uta_cと公式解説は、`T_i/2` を子へ配る評価として使っている。
- okudeottuは流量式ではなく、交互遷移が作る訪問頻度比を構築部品として使っている。

もう1つの共通点は、近似評価だけを信じると壊れるという点である。自己ループ、同一行き先、到達不能成分、分離した閉路は、`T_i/2` 評価や定常分布評価では良く見えても実遷移で失敗することがある。

## 解法の分類

- シミュレーション焼きなまし型: terry_u16、uta_c前半。
- 目標流量評価型: uta_c後半、公式の山登り。
- 確率推定型: ymatsuxのランダムウォーク定常分布。
- 構築型: okudeottuの一列グラフ。
- ビームサーチ型: 公式のe869120氏方針。
- 後処理・検査型: 公式の実シミュレーション確認、連結性検査、自己ループ禁止。

## 推奨して理解すべき順序

1. まずuta_c参加記を読む。素直なシミュレーションから `T_i/2` 評価に移る流れが分かりやすい。
2. 次に公式AHCラジオの前半を読む。`T_i/2` 評価がビンパッキング問題になる理由を理解する。
3. okudeottu解を読む。探索せずに訪問頻度比を設計する別視点を得られる。
4. terry_u16解を読む。流量式に頼らず、強い近傍選択で焼きなましを押し上げる実戦的な方法が分かる。
5. 最後にymatsux解を読む。定常分布近似と反復法は強力だが、実装難度が高い。
6. 公式AHCラジオ後半のビームサーチを読む。上位化の候補管理と失敗パターン対策を学べる。

## 実装するならどのルートか

理解のための最小実装は、uta_c・公式前半をベースにした `T_i/2` ビンパッキング山登りがよい。

1. サイズ `T_i/2` のアイテムを各社員から2個作る。
2. 箱 `j` の容量を `T_j` とする。
3. 箱2つを選び、中身を全探索で組み替えて誤差を下げる。
4. 自己ループと `a_i=b_i` を避ける。
5. 局所最適ごとに実際の50万週シミュレーションを行い、最良を保存する。

上位化を目指すなら、次のどちらかに進む。

- terry_u16ルート: 実シミュレーション焼きなましを多段化し、誤差頂点に入る辺を狙う重み付き近傍を作る。
- 公式・ymatsuxルート: ビンパッキングビームまたは定常分布反復で、評価を高速かつ滑らかにする。

## 重要な実装要素

- 状態表現:
  - 出力状態は `a[N], b[N]` または `to[2N]`。
  - 流量評価では、各出辺を「社員 `i` 由来のアイテム」として持つと実装しやすい。
- 評価関数:
  - 実評価: `simulate(L=500000)` の `sum |cnt_i - T_i|`。
  - 短縮評価: `L'` だけシミュレーションし、目標も縮尺する。
  - 流量評価: `sum |inflow_j - T_j|` または二乗誤差。
  - 定常分布評価: `sum |x_j L - T_j|`。
- 近傍:
  - 1点変更。
  - 2辺swap。
  - 2箱組み換え。
  - 一対二swap。
  - kickによる局所最適脱出。
- 差分更新:
  - シミュレーション評価は重いので、候補選択だけでも局所改善見込みで絞る。
  - 定常分布評価では、前回の `x` を初期値にした反復が重要。
  - ビンパッキング評価では、箱の合計値を持てば2箱組み換えを軽く評価できる。
- 候補管理:
  - 誤差が大きい頂点を優先する。
  - 小さい箱から処理する。
  - ビームでは前半の多様性消失を検査する。
- 出力判定:
  - 近似評価が良い候補でも、最後に実シミュレーションする。
  - 到達不能成分や閉じた成分を検出する。
- パラメータ:
  - 多段シミュレーション長。
  - 焼きなまし温度。
  - 近傍選択重み。
  - ビーム幅。
  - ビーム評価の各係数。

## 落とし穴

- `t` の偶奇は週数ではなく、その社員が担当した回数の偶奇である。
- `T_i/2` 評価で自己ループを許すと、自分が自分へ流量を渡すため過大評価になりやすい。
- `a_i=b_i` は出力上は合法だが、実質的に片側へ流量が偏るため高得点方針では危険になりやすい。
- 入次数が正でも、0番から到達できない成分なら実訪問回数は0になり得る。
- ビンパッキング誤差が小さいだけでは、遷移グラフとして良いとは限らない。
- 短縮シミュレーションは高速だが、周期や到達不能成分の事故を見逃すことがある。
- 定常分布近似は強力だが、強連結性・非周期性が崩れると意味が不安定になる。
- 構築型の見積もり式は高速だが、最後の実訪問回数とはずれる可能性がある。
