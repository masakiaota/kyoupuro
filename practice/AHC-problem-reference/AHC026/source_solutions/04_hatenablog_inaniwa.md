## 解法の全体像

明示的に全列ソートを作るというより、「次に取り出す箱の上をどう除けるか」をルールベースで改善していく方針である。最初は、対象箱の上を山の最小値が最大の山へ移す貪欲を作り、その後、移動を複数回に分ける、直近使う箱を別扱いする、良い分割位置をシミュレーションで選ぶ、という形で伸ばしている。

良い状態の見方として、「各山の上側N枚が最小値からソート済み」であることを重視している。下側や大きい番号同士の転倒より、近い将来取り出す小さい箱が塞がれないことを優先する。

## 主要アイデア

- 動かす箱数だけでなく、移動回数の手数料も重要である。
- すぐ使わない山、すなわち山の最小値が大きい山へ退避する基本方針が強い。
- 全部を一度に動かすのではなく、分割して動かすと転倒数や上側の順序を改善できる。
- 近い将来使う箱は、単独で良い山へ逃がす。
- 良い移動先は、山の最小値を下回らない範囲で最小値が小さい山である。
- 大量移動側は、移動する塊の最小値が上に来るような分割が効いた。
- 分割位置は局所シミュレーションで評価する。ただしシミュレーション中は爆発防止のため分割移動を抑える。

## 最終コードの構造

BrowserでAtCoder順位表から提出 #47305648 を辿り、C#コードを読めた。以下は記事本文と提出コードを合わせた構造である。

### 状態表現

- 10本の山を配列またはvectorで持つ。
- 各箱の現在位置を持ち、次に取り出す箱の山を高速に見つける。
- 各山の最小値、上側のソート済み長、トップ付近の小さい箱の状態を評価用に持つ。
- 分割移動候補を試すため、盤面コピーまたは巻き戻し可能なシミュレーション状態を持つ。
- 提出コードでは `Inputs`, `State`, `Solver` が中心で、`State.Stacks` に各山を持つ。

### 観測・制約・入力の扱い

- 出庫順は固定なので、次に取り出す箱とその上にある箱列を中心に見る。
- 移動先候補は、対象山以外の9本から選ぶ。
- 単独移動で良い状態を作れる箱だけを別処理し、それ以外は基本退避先へまとめる。
- 分割移動の候補数が増えすぎないよう、シミュレーションでは追加分割を禁止して評価している。
- 提出コードでは `TryPop` で出庫可能箱を処理し、`Move` で山の部分列を移動する。

### 評価関数

- 初期改善では、山の最小値が大きい山へ退避することを局所評価にしている。
- 次段階では、各山の上側N枚が小さい順に取り出しやすい状態かを重視する。
- 分割位置探索では、実スコアに近いシミュレーションコストで評価する。
- 分割しすぎると手数料が増えるため、分割回数へのペナルティが必要だと述べられている。

### 探索・構築・更新

- 基本は次に必要な箱の上を順に処理する貪欲である。
- 上から走査し、各列の最小値より小さい箱が出たら、その箱を単独で別列へ退避する。
- その箱より上は予定移動列へ移す。
- 最後まで見終わったら、残りを何回かに分けて移動する。
- 大量移動の分割位置をいくつか試し、シミュレーションで良いものを採用する。
- 終盤にビームサーチも試したが、良い結果には至らなかったとある。
- 提出コードでは `GetGreedyCommands`, `GetGreedyScore`, `GreedyMoveTest`, `MoveDetailTest` が移動先・分割候補の評価を担う。

### 操作・クエリ・出力選択

- 次の出庫対象が頂上に来たら出庫する。
- 直近使う箱を塞がないことを優先して移動先を選ぶ。
- 単独移動可能な箱は、山の最小値を下回らない範囲で最小値が最小の山へ置く。
- その他の箱は、最後まで使わない見込みの山、つまり最小値が最大の山へ逃がす。

### 時間配分・パラメータ

- 具体的なパラメータ値やコード上の時間配分は記事からは読めない。
- 分割移動では、移動個数の下限を増やすとスコアが少し伸びたとある。
- シミュレーション評価では、分割しすぎペナルティが必要そうだと述べられている。
- ビームサーチは残り1時間で試したが、最終方針にはならなかった。

## 実装上重要な断片

```text
process target box:
    scan boxes above target from top
    if x can be moved alone to improve top sorted region:
        move boxes above x to default buffer
        move x to best compatible column
    else:
        keep x in the bulk segment

    for candidate split of remaining bulk:
        simulate without recursive split
        score = simulated_cost + split_penalty
    apply best split moves
    remove target when exposed
```

```text
best column for a single small box x:
    candidates = columns whose minimum is >= x
    choose the column with the smallest minimum among candidates
```

## この解法の本質

この解法は、完成形を厳密に作るより、出庫順に近い上側だけを良くすることを重視している。AHC026では次に使う箱が小さい番号に限られるため、下側の大きい箱同士の乱れはすぐには問題にならない。局所的に「小さい箱を塞がない」「まとめて動かして手数料を節約する」ことに集中して、短時間実装で高順位まで到達している。

## 真似するならまず実装する部分

まずは、対象箱の上を山最小値最大の列へ逃がす単純貪欲を作る。次に、上にある小さい箱を単独退避できる場合だけ特別処理する。分割移動とシミュレーション評価は、基本貪欲の正当性とコスト計算が固まってから追加するのがよい。
