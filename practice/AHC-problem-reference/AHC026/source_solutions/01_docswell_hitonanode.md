## 解法の全体像

全列を番号順に整えれば、その後は追加コストなしで出庫できる、という「各列ソート」方針を土台にしている。本番優勝時は、掃き出す列の順序だけを探索し、各列の掃き出し・積み直しはルールベースで決めていた。延長戦解法では、各列を掃き出す局面で「どの箱をどの箱の上に置くか」を割当問題として定式化し、その良い解をk-best列挙してゲーム木探索の候補手にする。

つまり、探索対象は単なる列順序ではなく、「次にどの列を掃き出すか」と「その列をどのように掃き出すか」の組になる。掃き出し方候補は評価関数付きの割当問題から多数生成し、実行可能な候補だけを盤面遷移として採用する。

## 主要アイデア

- 完成形は、各列が以降放置できるソート済み区間を持つ状態である。
- 掃き出しフェーズでは、後で高く積み上げやすい隣接関係を増やすことが重要である。
- 「動かす箱」と「置き先の下の箱」の対応を割当問題にし、隣接評価と移動コストを目的関数に入れる。
- 最良解だけでなく、Murty法系のk-best列挙で複数の掃き出し候補を得る。
- 掃き出し方の微差が後の積み直しに大きく効くため、候補多様性を乱数ではなく構造的な列挙で確保する。
- 盤面評価は、全ての箱の隣接評価の総和と、ソート済み・除去済み箱への好意的評価で行う。
- 実行時間のぶれが大きいため、固定ビーム幅ではなくchokudaiサーチを採用している。

## 最終コードの構造

AHC026本体コードは公開されていないため、以下はスライド本文と公開ライブラリから読める範囲での構造である。

### 状態表現

- 盤面は10列の箱列として持つ。
- 各列について、未ソート部分、ソート済み区間、除去済み箱を区別して評価する。
- 探索ノードは少なくとも盤面、累積コスト、出力操作列、次の掃き出し候補生成に必要な補助情報を持つと考えられる。
- 割当問題では「動かす箱」集合と「下の箱」集合を行・列に対応させ、割当結果 `mate` が箱の置き先を表す。
- 公開ライブラリの `best_assignments` は、優先度付きキュー上のノードに、目的値、マッチング、双対変数、固定行数、禁止列集合を持たせる。

### 観測・制約・入力の扱い

- 入力はランダム順列を10列に分けた固定サイズの盤面である。
- 掃き出し候補生成では、動かせる箱を「掃き出し列の全箱」と「他列の一番上の箱」に制限する。
- 各箱の移動は最大1回、掃き出し列への移動は禁止する。
- 絶対に隣接できない組は割当コストを十分大きくし、候補から除く。
- 割当解が循環や依存順序の矛盾を含み、実行不能なら捨てる。

### 評価関数

- 基本は、未ソート部分の隣接ペアに対する「将来コストをどれだけ節約しそうか」の評価である。
- 盤面全体の評価は、箱隣接評価の総和に、ソート済み区間や除去済み箱のボーナスを足したものとして扱う。
- ソート済み区間に含まれる箱は、未ソート隣接評価では存在しないものとして扱う。例えばソート済み箱をまたいで隣接可能な番号を評価する。
- 移動コストも割当コストへ反映し、既に隣接しているペアには手数料補正を入れる。
- スライドでは、最終的に箱1個あたり2.3程度のコスト感を基準に、ソート済み箱を好意的に評価する説明がある。

### 探索・構築・更新

- 探索ノードから、次に掃き出す列を分岐する。
- 各列について割当問題を作り、k-best列挙で複数の掃き出し案を出す。
- 各割当案を実際の操作列へ変換し、実行不能なら破棄する。
- 掃き出し後はルールベースで積み直す。
- 盤面評価により候補ノードを優先し、chokudaiサーチで時間内に探索を進める。
- 序盤の掃き出しほど影響が大きいため、列挙数を多めにする。

### 操作・クエリ・出力選択

- 操作は、掃き出し候補を実盤面上で順に実行して生成する。
- ソート済みになった列は、原則として以後壊さず放置する。
- 最終的に全箱を出庫できる操作列のうち、累積移動コストが最小のものを出力する。
- 割当問題が想定していない出庫が途中で生じた場合は、掃き出し方を再最適化する。

### 時間配分・パラメータ

- k-best列挙の個数は序盤ほど大きくする。
- 最適解より目的関数値が2.0以上悪い解が出たら列挙を途中打ち切りする。
- 実行可能解が出やすい制約を追加し、失敗時は一時的にルールベースへ切り替える。
- 実験ではビーム幅20から50、列挙数1/5/10/100などを比較している。
- ランダムノイズで多様化するより、k-best列挙の方が性能改善に効いたと報告されている。

## 実装上重要な断片

```text
generate_candidates(state, flush_col):
    movers = boxes in flush_col + top boxes of other columns
    targets = possible lower boxes
    C = adjacency_cost(mover, target) + move_cost_correction
    set C[mover][target] = INF if impossible
    for assignment in k_best(C):
        if assignment is executable:
            yield apply_flush_and_restack(state, assignment)
```

```text
search:
    push initial state into time-bucketed queues
    while time remains:
        state = pop promising state
        for col in candidate flush columns:
            for next in generate_candidates(state, col):
                evaluate board by adjacency + sorted bonuses
                push next
```

公開ライブラリ側では、通常の線形和割当をJonker-Volgenant系の増加路で解き、`best_assignments::yield()` が現在最良の割当を返しつつ、その割当と先頭から一致する範囲・一致しない要素を分岐条件にした子問題を優先度付きキューへ積む。

## この解法の本質

この解法の本質は、ヒューリスティックな「次の一手候補生成」を、解きやすい組合せ最適化問題へ落としている点である。盤面全体を完全に最適化するのは難しいが、一列の掃き出しという局所局面なら、置き先対応の割当問題として扱える。さらに最良手だけではなくk-bestを列挙することで、局所評価の誤差に耐える候補多様性を得ている。

AHC026固有の見方としては、箱を直接出庫することより、「将来まとめて安く動かせる隣接関係」を作ることがコスト削減に直結する、という理解が重要である。

## 真似するならまず実装する部分

最初に作るべきなのは、全列ソート方針の単純版である。次に、盤面の隣接評価を作り、掃き出し列を1つ固定したときに「動かす箱をどの箱の上に置くか」の候補を評価できるようにする。k-best列挙やchokudaiサーチはその後でよい。

最小構成は、次の順がよい。

1. ソート済み列を壊さない掃き出し・積み直しシミュレータ
2. 隣接ペアの評価関数
3. 1列掃き出しの割当問題化
4. 最良割当だけの探索
5. k-best列挙による候補多様化

## 注意点・未理解点

- AHC026本体の実装コードは公開リンクがなく、詳細なデータ構造や出力手順はスライドからの推測を含む。
- 隣接評価関数の具体的な曲線値は、スライド画像のため厳密には読めていない。
- 割当問題上の良い解が実盤面上で実行可能とは限らないため、依存関係の検査が壊れやすい。
- 評価関数を調整しすぎると、特定seedに寄った候補生成になりうる。
- k-best列挙は候補品質を上げるが、候補を実行操作へ落とす部分の実装量が大きい。
