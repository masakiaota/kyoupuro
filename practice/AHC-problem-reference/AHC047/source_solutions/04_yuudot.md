## 解法の全体像

本番では、`C` を `aabbccddeeff` に固定し、近似スコアを使って遷移確率を山登り・焼きなましで変える方針を採った。最初はPythonで単純な確率変更の山登りを作り、その後、焼きなまし化、`P_i^2` による評価重み付け、Rust化、Kick、Optunaによる温度調整を順に入れてスコアを伸ばした。

延長戦では、序盤に上位4スコアの文字列だけを対象にして焼く方針を追加し、さらにMoegi解説のような `Q_i^alpha` 補正を入れることで大きく改善した。

## 主要アイデア

- `C` は固定し、`A` の整数確率だけを探索する。
- 高速な近似スコアを作り、確率を動かす山登り・焼きなましを可能にする。
- 近傍は単純な確率変更で、記事中では `±15` 程度の変更から始めている。
- 一度出現確率が0になると、その文字列は単純な近傍では復活しにくい。
- `P_i^2` で重み付けし、高得点文字列が評価から消えにくいようにする。
- 改善が止まったときに現在解を大きくランダム変更するKickを入れる。
- 延長戦では、序盤の評価対象を高得点上位4個に絞り、高得点文字列を先に確保する。
- `Q_i^0.38` 付近の冪乗補正で、小さい出現確率の改善を評価する。

```text
anneal(A):
    best = A
    stagnant = 0
    while time remains:
        if stagnant is large:
            A = kick(A)
            stagnant = 0
        next = move_probability(A)
        diff = eval(next) - eval(A)
        if accept(diff, temperature):
            A = next
            update best and stagnant
    return best
```

## この解法の本質

近傍が単純でも、評価関数と初期の対象選択を変えれば大きく伸びることを示している。特にAHC047では、高得点文字列が一度死ぬと復活しにくいため、全体スコアを最初から均等に見るより、まず少数の高得点文字列を確保する方が探索が安定する。

また、Kickはこの問題の局所最適性に合っている。確率行列は小さい変更だけでは到達できない構造差があり、停滞時に大きく崩すことで、別の高得点文字列の組み合わせへ移れる。

## 真似するならまず実装する部分

まず `C=aabbccddeeff` 固定、`A` の同一行 `+d/-d` 近傍、近似スコア評価の焼きなましを作る。次に `P_i^2` または `Q_i^alpha` を入れて、高得点長文の出現確率が評価に残るようにする。

KickとOptunaは、基本の焼きなましが動いてから入れる。最初からパラメータ探索に頼ると、評価関数が悪いのか温度が悪いのか切り分けにくい。
