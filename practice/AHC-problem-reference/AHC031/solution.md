## 問題の本質

AHC031 は、各日の長方形詰め込みを作る問題に見えるが、本質は「日をまたいで内部仕切りの形をどれだけ保てるか」を最適化する問題である。

面積不足は 1 マスあたり 100 点で重いので、基本的には要求面積を満たす方向に配置する。一方、面積だけを満たす日別最適配置を作ると、日間で仕切りが大きく変わり、仕切り変更コストが増える。したがって、空き領域をうまく残し、翌日以降の境界合わせに使える配置表現を選ぶ必要がある。

上位解法は共通して、完全自由な長方形配置を捨て、短冊、列、行、分割線などの扱いやすい表現へ制限している。その代わり、日間境界の評価と局所更新を高速にして、3秒内で多くの候補を試している。

## 共通している考え方

- 配置の自由度を制限し、非重複制約を自然に満たす。
- 各予約の面積不足を避けるため、幅または高さを `ceil(area / strip_size)` で決める。
- 前日と同じ内部境界を使うことを高く評価する。
- 外周は仕切りコストにならないため、右端・下端まで伸ばす配置が有利である。
- 日別に最適化するだけでなく、前後日を評価に入れる。
- 焼きなまし、山登り、DP、ビームサーチを組み合わせ、局所更新でスコアを下げる。
- 実スコアを完全計算する箇所と、探索用の近似評価を使う箇所を分ける。

## 解法の分類

- 短冊焼きなまし型: oimo_shr、bowwowforeach。
- 固定列・余り伝播型: tishii24。
- 分割線探索型: Ang107。
- 固定行・DP・ビーム型: TAISA_。
- 後処理改善型: 右端・下端への伸長、余りを使った境界合わせ、残り予約の `1x1` 埋め。

## 推奨して理解すべき順序

1. TAISA_ のメモを読む。固定行、行内 DP、ビームサーチが具体的で、実装の入口にしやすい。
2. tishii24 のメモを読む。列ごとの差分評価と余り伝播により、上位化のための評価設計が分かる。
3. oimo_shr のメモを読む。1位解法として、短冊型をどこまで強くできるか、近傍と時間配分の方向を見る。
4. bowwowforeach のメモを読む。改善履歴から、短冊型の何が効いたかを補強する。
5. Ang107 のメモを読む。短冊型以外の自由度を持つ線集合方針の比較材料にする。

## 実装するならどのルートか

理解のための最小実装は、TAISA_ 型の固定行分割がよい。

```text
fixed_rows:
    choose row heights
    for each day:
        place rectangles left-to-right in rows
        match right edges to previous day's cuts by DP
    improve daily order by local search
```

このルートは、非重複と出力復元が簡単で、前日仕切り位置への DP という問題固有の重要要素を試せる。

上位化を狙うなら、tishii24 型の列ごとの差分評価を足すのがよい。特に、`d` 日目だけでなく `d+1` 日目も同時に評価すること、余りを境界合わせに使うことが強い。

さらに上を狙うなら、oimo_shr 型の近傍設計と時間配分を取り入れる。短冊割り当て、短冊内順序、短冊幅、複数初期解を動かし、近傍ごとの成功率を見ながら調整する。

## 重要な実装要素

### 状態表現

- `rect[d][k]`: 最終出力用の長方形。
- `strip_size`: 行高さまたは列幅。
- `assign[d][strip]`: 各短冊に入る予約 index の列。
- `order[d][strip]`: 短冊内の順序。
- `cut_set[d][strip]`: 短冊内で使った累積境界位置。
- `score_part[d]`: 面積不足と仕切り変更の寄与。

上位化するなら、tishii24 のように `prev_rem` やグラフで余りを持つ。

### 評価関数

基本形は実スコアと同じである。

```text
score =
    100 * shortage_area
  + changed_horizontal_segments
  + changed_vertical_segments
```

短冊型では、内部線分の全列挙を避け、境界座標の集合で近似または差分計算する。

```text
strip_boundary_cost =
    cost_of_strip_outer_boundaries
  + cost_of_inner_cuts_not_reused
```

探索中は、面積不足が閾値を超えた時点で打ち切ると反復数を増やせる。

### 近傍

- 同じ短冊内で2つの予約を swap。
- 短冊間で1つの予約を移動。
- 2短冊間で連続ブロックを交換。
- 短冊境界 bit を反転し、隣接する短冊を結合・分割する。
- 短冊幅または行高さを少し変える。
- 初期解を複数作り、良い候補だけ残す。

近傍ごとに影響する短冊と日を限定し、差分評価できるようにすることが重要である。

### 差分更新

最低限、変更した短冊だけ再計算する。

```text
try_move(move):
    affected = strips touched by move
    old = sum(score_part[affected])
    apply(move)
    rebuild affected rectangles and cuts
    new = sum(score_part[affected])
    if accept(new - old):
        commit
    else:
        rollback
```

隣接日の仕切りコストは `d-1, d, d+1` に波及するため、影響範囲を間違えない。

### 候補管理

- 単一路線なら現在解と最良解を持つ。
- 日を逐次確定するなら、ビームで前日状態を複数持つ。
- 候補ごとに、座標だけでなく前日から引き継ぐ境界集合も保存する。

### 出力判定

- `0 <= i < i' <= W`、`0 <= j < j' <= W` を必ず満たす。
- 同日の長方形同士が正面積で重ならない。
- 面積が足りない長方形も WA ではなくペナルティなので、最後まで有効な長方形を出す。
- 余った予約を `1x1` で埋める処理は、スコアは悪いが WA 回避に効く。

### パラメータ

- 短冊数、行高さ、列幅。
- 焼きなまし温度。
- 近傍選択比率。
- ビーム幅。
- 日ごとの時間配分。
- bit DP を使う行内個数の上限。
- 評価打ち切り閾値。

## 落とし穴

- 初日 `L_0=0` を忘れると、初日の仕切りを過剰に嫌う。
- 外周上の辺を内部仕切りとして数えると評価がずれる。
- 境界集合だけで評価する場合、線分の長さを掛け忘れる。
- 短冊を結合・分割したとき、予約 id と出力座標の対応を壊しやすい。
- 面積不足を避けるために幅・高さを切り上げると、短冊合計が `W` を超えて破綻しやすい。
- 焼きなましで悪化を許すのにロールバックが不完全だと、非重複が壊れる。
- 日ごとに最適化しすぎると、翌日以降の仕切り変更で負ける。
- 短冊型は実装しやすいが、疎なケースや偏った面積分布で弱くなることがある。

## 未解決・要検証事項

- oimo_shr は提出 #51940007、bowwowforeach は提出 #51939990 をBrowserで読めた。ただしどちらも大規模実装で、差分更新やパラメータの意図は追加実験が必要である。
- Ang107 の Nim コードは読めたが、マクロ展開後の補助関数が多く、全ての改善が最終方針に残ったかは確信できない。
- どの短冊幅・行高さが入力分布に対して最も安定するかは、手元の seed 実験が必要である。
- 余り伝播を入れた評価が、実スコアとどの程度一致するかは実装ごとに検証が必要である。
- ビーム幅を増やすべきケースと焼きなまし反復を増やすべきケースの切り替えは未整理である。
