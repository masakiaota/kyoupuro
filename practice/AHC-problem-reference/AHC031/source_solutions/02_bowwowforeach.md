## 解法の全体像

短冊型の配置をベースにし、各日を独立にきれいに詰めるだけでなく、前後日の仕切りが合うように配置を調整する。記事では、最初に単純な構築で十分な形を作り、そこから分割パターンや予約順序を改善してスコアを詰めていく過程が説明されている。

1位解法と同じく、完全自由な長方形分割ではなく、扱いやすい配置クラスへ制限している。ただし記事から読める重点は、配置の形そのものよりも、改善の履歴と、どの改善が効いたかの比較にある。

## 主要アイデア

- 問題を「全日で似た構造の区画分割を保つ」問題として見る。
- 短冊または階段状に近い配置で、二次元詰め込みを一次元の並びへ落とす。
- 予約面積をそのまま満たすことを優先し、仕切り変更コストは境界の再利用で抑える。
- 初期配置の質が重要で、単純な貪欲でも形を揃えれば一定のスコアが出る。
- 改善では、順序や分割の微調整により、面積不足と境界差分のバランスを取る。
- 近傍は、同じ表現の中で日ごとの構造を壊しすぎないものが有効である。

## 最終コードの構造

Browserで読んだ提出 #51939990 の実装構造である。記事本文の「扱いやすい配置クラスに制限して改善する」方針に対応し、短冊・分割線・焼きなましバックアップを明示的に持つ。

### 状態表現

- `Line`, `DayLine`, `ResultLines`: 各日の水平・垂直内部線分を持ち、`CalcTotalSize` で仕切り長を評価する。
- `Table` 系の構造: 日ごとの区画、予約割当、面積コスト、分割位置を保持する。
- `SnapShot`: 現在解のテーブルと `rawScore_` を保存する。
- `StateBackup`: `MoveDivAction`, `MoveItemAction`, `MoveAction` を持ち、焼きなまし近傍のロールバックに使う。
- `SABackup`: 現在状態・最良スナップショット・温度・受理判定を管理する汎用焼きなまし枠。

実装は内部線分も評価用に復元し、短冊内の分割位置と日間線分差分を合わせて見る。`MoveDiv` は分割位置を動かし、`MoveItem` 系は予約の所属や順序を動かす。

### 観測・制約・入力の扱い

- 各日の要求面積合計は `W^2` 以下なので、空き領域を仕切り再利用の余裕として使える。
- 面積は昇順入力だが、配置では大きいものを先に扱う方が破綻しにくい。
- 出力長方形は軸平行、格子点、正面積、同日非重複を満たす必要がある。

### 評価関数

実スコアに近い評価として、次を使うと読める。

```text
eval =
    100 * area_shortage
  + changed_internal_boundaries
```

短冊型に制限している場合、`changed_internal_boundaries` は短冊境界の変化と短冊内の累積位置の不一致で計算できる。記事は詳細なコード式より、どの構造を動かすとスコアが改善したかに重点がある。

### 探索・構築・更新

- まず貪欲に分割・配置する。
- 予約順序や分割線を変えた候補を作る。
- 候補配置を評価し、改善するものを採用する。
- `SABackup::Check` が改善受理と温度による悪化受理を行う。
- `StateBackup` に変更内容を記録し、棄却時に分割線・アイテム移動を戻す。
- 面積不足評価と仕切り線評価を分けて持ち、局所変更後に影響部分を更新する。
- 全日を別々に最適化しすぎると仕切り変更が増えるため、前後日の構造を評価に入れる。

### 操作・クエリ・出力選択

- 各日の予約順序と分割位置から座標を復元する。
- 不足ペナルティが高いため、可能なら要求面積以上の長方形を出す。
- 右端・下端など外周に接する部分は内部仕切りにならないため、復元時に外周を活用する。

### 時間配分・パラメータ

- 記事本文から具体的な温度や反復回数は確認できなかった。
- パラメータとしては、分割数、初期配置の種類、近傍選択比率、探索時間の割り振りが重要だと読める。

## 実装上重要な断片

```text
evaluate(day):
    shortage = sum(max(0, demand[k] - area(rect[k])))
    boundary = diff(partitions[day - 1], partitions[day])
    return 100 * shortage + boundary
```

```text
local_search():
    cur = greedy_layout()
    while time remains:
        nxt = modify_order_or_split(cur)
        if accept(eval(nxt) - eval(cur)):
            cur = nxt
```

## この解法の本質

この問題では、面積不足をゼロに近づけるだけでは上位に届かない。重要なのは、全日を通じて似た分割構造を保つことである。bowwowforeach の参加記からは、扱える配置クラスを決めたうえで、どの改善がどの段階で効いたかを見ながら解を育てる姿勢が読み取れる。

短冊型にすると探索空間は小さくなるが、日間の境界再利用が明確になる。これは「制約で自由度を捨てる代わりに、評価と更新を速く正確にする」方針である。

## 真似するならまず実装する部分

固定短冊で各日を貪欲に配置し、実スコア計算を作るのが最初である。その後、短冊内順序を入れ替える山登りを追加し、前日との境界差分を評価に入れる。分割パターンの複数候補比較は、その後に追加するとよい。
