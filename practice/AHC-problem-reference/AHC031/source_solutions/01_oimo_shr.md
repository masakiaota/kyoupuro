## 解法の全体像

全日を「縦方向に短冊へ分け、各短冊の中で横方向に長方形を積む」形に制限する。各短冊は全日で対応づけられるため、日をまたいで同じ短冊境界や同じ横座標を使いやすくなる。

解法の中心は、短冊の幅、各予約をどの短冊に入れるか、短冊内の順序、境界の合わせ方を焼きなましで改善することだ。面積不足を避けつつ、隣接日の仕切りが一致するように「配置の自由度」を短冊型へ落とし込んでいる。

記事では、単純な短冊分割から始め、割り当て失敗を減らす工夫、前後日の境界を流用する工夫、近傍の重みづけ、時間配分などを段階的に説明している。

## 主要アイデア

- 長方形配置の自由度を、列または行の短冊分割に落とす。
- 短冊幅を固定または準固定にし、各予約は短冊内の連続区間として置く。
- 各短冊で予約を縦または横に順に並べることで、非重複を自然に満たす。
- 日間コストは、短冊境界と短冊内の分割位置がどれだけ一致するかで近似・評価する。
- 大きい予約や詰め込みにくい予約を早く処理し、面積不足を避ける。
- 焼きなましの近傍として、予約の短冊移動、短冊内順序変更、短冊幅変更、複数要素の入れ替えを使う。
- 配置に失敗しやすいケースでは、短冊数や幅の候補を変え、初期解の多様性を持たせる。
- 最終出力では、短冊型配置を実際の長方形座標へ復元する。

## 最終コードの構造

Browserで読んだ最終提出 #51940007 の実装構造である。記事本文の短冊型焼きなましと対応しており、座標復元・境界一致・短冊混合を大きなC++実装にまとめている。

### 状態表現

- `Entry`: 予約番号、要求面積、短冊幅ごとの必要高さを持つ。
- `Day`: その日の `Entry` 群を持つ。
- `Block`: 短冊内に置かれた予約の index、高さ、位置を持つ。
- `Wall`: 日・短冊・範囲を持つ境界要素で、親子関係により前後日の境界接続を表す。
- `Strip`: 幅、残り縦幅 `room`、`walls`、短冊内の `Block` 列を持つ。
- `State`: 全日の短冊集合、無視日、境界情報、焼きなまし用の現在解を持つ。
- `Solver`: 初期構築、短冊混合、壁位置調整、焼きなまし、最終出力をまとめる。

短冊をまたいだ長方形は基本的に使わず、予約は1本の短冊内に収める。`Strip::updateRoom` で短冊内の残り高さを管理し、`Wall` の `range` と親子接続を更新しながら日間の仕切り一致を調整する。

### 観測・制約・入力の扱い

- `W=1000` 固定であることを前提に、短冊幅の候補やパラメータを調整する。
- 各日の要求面積は昇順で与えられるが、配置時には面積の大きい順や短冊への収まりやすさを使う。
- 各日の総要求面積は `W^2` 以下なので、全体としては不足なし配置が存在しうる。ただし短冊制限により局所的な不足は発生する。
- WA を避けるため、各長方形は正面積、グリッド内、同日非重複を必ず保つ。

### 評価関数

評価はおおむね次の合計である。

```text
score =
    100 * sum(max(0, demand - assigned_area))
  + partition_change_cost
  + search_only_penalty
```

記事からは、実スコアをそのまま厳密計算する箇所と、探索高速化のために近似評価する箇所を分けていると読める。特に、短冊内の境界一致数を高くすることが、仕切り変更コストの削減に直結する。

### 探索・構築・更新

- 初期解は短冊型の貪欲配置で作る。
- 焼きなましで、短冊への割り当て、順序、幅、境界の使い方を変える。
- 近傍は単発の小変更だけでなく、成功率を上げるために複数要素をまとめて動かすものも使う。
- 実装では `mixStrips` が複数短冊の予約を混ぜ直す大きめの近傍になっている。
- `State` は影響する短冊・壁を局所的に修復し、受理しなかった場合は変更前状態へ戻す。
- スコア差が改善なら採択し、悪化でも温度に応じて確率採択する。
- 近傍ごとに成功率や効き方が異なるため、選択確率を調整する。
- 時間配分は、序盤で大きく構造を動かし、後半で細部を合わせる方向だと読める。

### 操作・クエリ・出力選択

- 出力は各日の各予約に対する長方形座標。
- 短冊ごとに、累積座標から各予約の左上・右下を復元する。
- 不足や空きが出る場合も、長方形が正面積で非重複になるように最後まで座標を埋める。

### 時間配分・パラメータ

- 3秒制限に合わせ、焼きなましの反復回数と近傍比率を調整する。
- 短冊数、短冊幅候補、温度、近傍選択確率、複数初期解の扱いが主なパラメータである。
- 記事では、分割成功率改善と時間配分が重要な調整対象として扱われている。

## 実装上重要な断片

```text
build_initial():
    choose strip widths
    for each day:
        assign reservations to strips
        order reservations in each strip
        build rectangles by cumulative coordinates
    evaluate full score
```

```text
try_move(move):
    old_delta = local score contribution
    apply move to strip assignment/order/width
    rebuild affected strips and adjacent-day boundary info
    new_delta = local score contribution
    accept by annealing
    if rejected:
        rollback
```

```text
restore_rectangles(day):
    for strip in strips:
        pos = strip_start
        for reservation in strip.order:
            allocate interval from pos
            emit rectangle
            pos += allocated length
```

## この解法の本質

二次元長方形詰め込みをそのまま探索すると自由度が大きすぎる。短冊型に制限すると表現力は落ちるが、非重複と復元が簡単になり、日間の仕切り再利用も一次元境界の一致問題として扱える。

この解法の強さは、制限した形の中でスコアに効く自由度を残している点にある。短冊の割り当て、順序、幅を動かせば、面積不足と仕切り変更の両方へ働きかけられる。さらに、近傍設計と時間配分で「動くけれど壊れにくい」探索空間にしている。

## 真似するならまず実装する部分

まずは短冊幅を固定し、各日について大きい予約から短冊へ貪欲に入れる実装を作るのがよい。次に、短冊内の順序 swap と短冊間移動だけの焼きなましを追加する。最初から短冊幅変更や高度な境界合わせを入れるより、非重複な出力とスコア計算を安定させることが重要である。

## 注意点・未理解点

- 最終提出 #51940007 は読めたが、コード量が大きく、全ての近傍重みと調整値の意図までは追い切れていない。
- 記事本文には提出リンクがなく、実装URLはBrowserでAtCoder提出一覧から辿ったものである。
- 記事で説明される近傍の全てを同時に入れると、ロールバックや局所評価が壊れやすい。
- 短冊型は疎なケースや極端な面積分布では弱くなりうる。
- 面積不足を避ける評価と仕切り一致を増やす評価の重みを誤ると、片方だけが良い解になりやすい。
- 初日 `L_0=0` の扱いをスコア計算に入れ忘れると探索の方向がずれる。
