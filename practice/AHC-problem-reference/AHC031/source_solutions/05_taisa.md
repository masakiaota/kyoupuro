## 解法の全体像

縦方向をあらかじめ複数の行に分け、各行に左から右へ長方形を並べる。行の高さ列は固定候補から選び、行仕切りの有無を bit で表す。日ごとに、予約を並べる順序と行仕切り bit を焼きなましで調整し、さらにビーム幅 5 で複数の前日状態を持ちながら日を進める。

行内では、前日に使った縦仕切り位置へ次の長方形の右端を合わせるために DP を使う。予約数が少ない行では bit DP で行内順序も含めて最適化し、多い行では順序固定の DP と乱択入れ替えで近似する。

## 主要アイデア

- 行高さ列を固定し、各予約をどれかの行へ横向きに配置する。
- 行仕切りの有無を bit mask として持ち、複数の小さい行を結合できるようにする。
- 各行で、予約幅は `ceil(area / row_height)` として計算する。
- 前日の同じ行範囲で使った縦仕切り位置を `set` に持ち、DP で右端をその位置に合わせる。
- 焼きなましの主近傍は予約順序の 2 点 swap、まれに行仕切り bit の反転。
- 各日の上位候補を保存し、翌日は各候補を初期状態にして探索するビームサーチを行う。
- 面積不足コストが閾値を超えた時点で評価を打ち切り、高速化する。
- 最右の長方形を右壁まで伸ばし、内部仕切りを減らす。

## 最終コードの構造

### 状態表現

提出コードの主な配列は次の通りである。

- `a[d][k]`: 要求面積。焼きなまし中は順序 swap のため一時的に入れ替える。
- `uy, ux, vy, vx`: 各予約の出力座標。
- `lsc`: 基本行高さ列。最終的には `{153, 134, 125, 106, 93, 81, 72, 66, 53, 47, 38, 32}` を使用。
- `bit`: 行仕切りの有無。bit が立っている場所で行を区切り、連続する基本行を結合する。
- `st[row]`: 前日状態から引き継ぐ縦仕切り位置の集合。
- `ids[row]`, `wids[row]`: 各行に入った予約 id と幅。
- `bdp`, `bfr`: 行内個数が小さい場合の bit DP。
- `dp`, `fr`: 順序固定 DP。
- `sux/suy/svx/svy`: ビーム候補保存用の座標配列。
- `global_sts`, `global_scs`, `global_prev_bits`: ビーム候補ごとの仕切り集合、スコア、bit。

### 観測・制約・入力の扱い

- 行高さは `W=1000` に合うよう合計 1000 の候補を使う。
- 予約幅は `ceil(a[d][id] / row_height)`。
- まず大きい予約から行に詰め、残った予約は空きが大きい行へ入れる。
- どうしても入らない予約は最後に `1x1` として置き、面積不足ペナルティで処理する。
- 各行で左から右へ置くため、同じ日の非重複は保ちやすい。

### 評価関数

`optimize(d, bit, dplim, itrlim, updateset, sclim)` が配置生成と評価を兼ねる。

主な評価は次の合計である。

```text
score =
    100 * area_shortage
  + vertical_partition_change_estimate
  + row_partition_change_estimate
```

焼きなまし中は、行仕切り bit の前日との差に `1000 * popcount(bit ^ prev_bit)` を足している。これは横方向の行仕切り変更を粗く見積もる値である。

行内の縦仕切りは、前日の `st` に右端座標が存在すればコスト増なし、存在しなければ対象行高さ分のコストを加える。コードでは内部線分の設置・撤去を見て `2 * row_height` 相当を加える形になっている。

### 探索・構築・更新

`optimize` は以下を行う。

1. `bit` から結合後の行高さ列を作る。
2. 大きい予約から各行へ左から詰める。
3. 残った予約を空きが大きい行へ入れ、不足コストを加える。
4. 行ごとに、前日の縦仕切り位置に合わせる DP を行う。
5. 必要なら `nst` に当日の縦仕切り位置を保存する。
6. 最後に残った予約を `1x1` で埋める。

行内個数が `dplim` 未満なら bit DP を使い、予約順序も含めて前日仕切りへの一致数を最大化する。多い場合は順序固定 DP を行い、さらに `itrlim` 回のランダム swap で局所改善する。

`annealing` は、予約順序 swap と `bit` 反転を近傍にする。最良だけでなく上位 `C=4` 候補を保存する。

`beamsearch` は、ビーム幅 `B=5` で日を進める。各ビーム候補から `C` 個の次候補を作り、合計 `B*C` から上位 `B` 個を残す。

### 操作・クエリ・出力選択

- 最終的に `load(0)` で最良ビームを復元し、全日の `uy ux vy vx` を出力する。
- 行内 DP の復元時に、各予約の `ux, vx` を累積位置または前日仕切り位置へ合わせる。
- 行座標は結合後の行高さ累積 `ys` から決まる。
- 最右の予約は可能なら `vx=W` に伸ばす。

### 時間配分・パラメータ

- `R=11`, `B=5`, `C=4`。
- 焼きなまし反復数は `N*D` に応じて調整する。
- 1日・1ビームあたりの時間はおおむね `2400ms / D / B` で打ち切る。
- 温度はコード上 `T0=100`, `T1=1`。
- 行仕切り bit 反転は swap より低頻度で、`bitr=49` によりほとんどが予約 swap になる。
- 最終行高さ候補は `lsc11`。

## この解法の本質

固定行分割という強い制限で配置を単純化し、その中で前日の縦仕切りを DP で再利用する点が本質である。全体を完全に自由に焼くのではなく、「順序」と「行仕切り bit」だけを大域探索し、行内の境界合わせは DP に任せている。

また、ビームサーチ化により、日ごとの貪欲最適から脱している。前日状態を複数残すことで、ある日に少し悪くても後の日で効く仕切り構造を保持できる。

## 真似するならまず実装する部分

固定行高さで、各行に左から予約を置く貪欲を作る。次に、前日の縦仕切り位置集合を使い、行内の右端をなるべく既存位置に合わせる DP を実装する。その後、予約順序 swap の焼きなましを足す。ビームサーチと bit DP は、単一経路の実装が動いてから追加するのがよい。

## 注意点・未理解点

- `bit` による行仕切り変更コストは探索用の近似であり、実スコア完全一致ではない。
- コードには試行錯誤のコメントや未使用候補が多く、最終的に効いた要素と実験要素を完全には分離しにくい。
- DP 復元と予約順序の入れ替え後の id 対応を間違えると、正しい予約へ座標を戻せない。
- `1x1` 埋めは WA 回避として重要だが、スコアは大きく悪化する。
- 行高さ列は手調整色が強く、別分布のケースで最適とは限らない。
