## 解法の全体像

毎ターン、過去のAI行動から内部パラメータを推定し、その推定値を使ったモンテカルロ法でplayer0の行動を選ぶ。推定は、まず確定でランダム行動だと分かる観測から `eps` の初期値を作り、その後 `eps, wa, wb, wc, wd` を尤度最大化するように山登りする。

行動選択では深さ10ターンのプレイアウトを行う。プレイアウト中の貪欲行動は、AIが全員貪欲に動くと仮定したときの `S0/SA` が最大になる行動を選ぶ方針で、終端盤面評価も単純に `S0/SA` を使う。各候補手のプレイアウト平均が最大のものを採用し、一定時間後に評価の良い6手へ絞って再度モンテカルロを回す。

## 主要アイデア

- 確定ランダム行動を使って `eps` の初期推定値を作る。
- パラメータ候補を尤度関数に入れ、過去行動の対数尤度を最大化する。
- 現在推定値での評価最大マス集合と、実際のAI移動先が一致したかで観測確率を計算する。
- 評価最大マスが複数ある場合、貪欲行動の確率を最大マス数で割る。
- パラメータの誤差を見るときは単純差ではなく比率が重要だったとある。
- モンテカルロ深さは10ターン。
- 終端評価は `S0/SA` に絞る。複雑な評価関数は多く試したが悪化した。
- 一定時間後、候補を上位6手に絞ってプレイアウト精度を上げる。
- 枝刈りとして、自陣レベルUのマスは選択肢から除く。
- ビットボード、時刻取得制限、xorshift、`array` などで高速化し、seed0で1ターン約1000プレイアウトを回した。

## 最終コードの構造

以下は記事本文とキャッシュ実装 `#73569535` から確認した構造である。

### 状態表現

- 盤面所有者、レベル、価値、プレイヤー位置、現在スコアを持つ。
- プレイアウト用に状態コピーまたは差分適用・巻き戻しが必要である。
- 高速化としてビットボードを使ったとあるため、合法手や連結成分はビット集合で扱っていた可能性が高い。
- 推定器はAIプレイヤーごとに `eps, wa, wb, wc, wd` の現在推定値と観測履歴を持つ。

### 観測・制約・入力の扱い

- 各AIの観測行動について、その時点の合法手をカテゴリごとに評価する。
- 各カテゴリ内で `V` が最大でない場所をAIが選んだ場合、その行動は確定ランダム行動とみなし、`eps` 推定の材料にする。
- 以降の最尤推定では、過去の貪欲行動の可能性がある行動統計を使って尤度を計算する。
- 公式のAI行動では同点最大から一様ランダムに選ぶため、最大マス数で割る処理が必要である。

### 評価関数

- パラメータ推定の尤度は、各ターンのAI選択確率の対数和。
- 現在推定パラメータで評価値最大のマス集合を求め、観測手がそこに含まれるなら確率は `(1-eps)/k + eps/n`、含まれないなら `eps/n` とする。ここで `n` は合法手数、`k` は評価値最大マス数。
- プレイアウト終端評価は単純な `S0/SA`。
- プレイアウト中の貪欲手選択では、AI全員が貪欲行動をすると仮定したときの `S0/SA` 最大化を使う。

### 探索・構築・更新

- パラメータ推定は山登り法で尤度を高くする。
- 山登りの近傍や刻みは記事からは分からない。
- モンテカルロでは各候補手を初手として深さ10ターンのプレイアウトを行う。
- プレイアウト評価平均が最大の行動を採用する。
- 一定時間が経過したら上位6手に候補を絞り、その候補だけでさらにモンテカルロを回す。
- 自陣LvUマスは候補から除く。

### 操作・クエリ・出力選択

- 毎ターン、現在の合法手から候補を作る。
- 候補ごとにプレイアウト評価値を蓄積する。
- 最後に平均評価が最大の候補を出力する。
- 出力後、観測されたAI行動と盤面を読み、次ターンの推定に反映する。

### 時間配分・パラメータ

- プレイアウト深さは `PLAY_OUT_DEPTH=10`。
- 候補絞り後に残す手は6個。
- 総時間予算は `TOTAL_TIME_BUDGET_MS=1970`。
- 序盤20ターンは `10 + turn/2` ms程度に抑える。
- 推定予算は `turn_budget * 0.01 * M`、残りをモンテカルロへ使う。
- パラメータ推定の摂動幅は0.5から始め、250反復ごとに0.7倍する。

## 実装上重要な断片

キャッシュ実装の `EnemyEstimator` は、各観測で合法手とカテゴリを保存し、3観測以降に推定を走らせる。カテゴリは空き、自陣LvU未満、敵Lv1、敵Lv2以上、自陣LvUに分ける。尤度は、観測手が推定パラメータで評価最大なら `(1-eps)/n_best + eps/n_moves`、そうでなければ `eps/n_moves` で計算する。

推定は、確定ランダム由来の観測から `eps_base` を作り、`wa,wb,wc,wd,eps` を公式範囲内で山登りする。`eps` は `eps_base ± 0.25` にも制限する。状態更新は `step_with_undo` / `unstep` で差分適用し、positions、scores、territory bitboard、変更セルを巻き戻す。

`MonteCarloSolver` は前半で全候補をround-robin評価し、後半で平均+0.004*最大値が良い上位6手だけを評価する。playout中のplayer0は、AI全員を予測貪欲で動かしたときの次ターン `S0/SA` が良い手を選ぶ近似greedyで動かす。

```text
likelihood(params, history):
    ll = 0
    for obs in history:
        greedy_set = argmax_cells_by_ai_value(obs.legal_moves, params.wa..wd)
        n = len(obs.legal_moves)
        k = len(greedy_set)
        if obs.chosen in greedy_set:
            prob = (1 - params.eps) / k + params.eps / n
        else:
            prob = params.eps / n
        ll += log(prob)
    return ll
```

## この解法の本質

この解法は、相手方策が低次元パラメータで書けることを素直に最尤推定へ落とし、その推定結果を使って未来をサンプリングする。ベイズやEMほど複雑にせず、観測行動の確率を直接計算して山登りするため、比較的実装しやすい。

また、盤面評価を複雑にしすぎず、終端の `S0/SA` に寄せた点も重要である。AHC061では「よさそうな境界」「連結性」「選択肢数」などを入れた評価が必ずしもスコアに結びつかず、実際に短く進めて比を見る方が安定したという示唆がある。

## 真似するならまず実装する部分

まずは尤度式をそのまま実装し、`eps, wa, wb, wc, wd` の山登り推定を作るのがよい。ベイズ推定より簡単で、観測手が推定パラメータでどの程度説明できるかを確認しやすい。

次に、深さ10のモンテカルロを作り、終端 `S0/SA` の平均で行動を選ぶ。高速化前でも小さいseedで動作を確認し、最後にビットボードや候補6手絞りを入れるとよい。

## 注意点・未理解点

- キャッシュ実装で、山登りの摂動幅、減衰、`eps_base` 制限、時間配分は確認できた。
- プレイアウト中の自分手は、AIを予測した一手先スコア変化と衝突を使う近似greedyで実装されている。
- 終端評価を単純にする方がよかったとあるが、ケースによっては局所評価を足したくなるため過学習に注意が必要である。
- M=2でAIを閉じ込める戦略は考えたが、実現が難しく断念されている。
- Vの分布をあまり活用できなかったと反省されており、高価値地帯への長期戦略には改良余地がある。
