## 解法の全体像

この記事はAHC061の最終方針全体ではなく、上位解法で重要だった高速化の部品を説明している。主眼は、10x10グリッド上の到達可能領土、合法手、候補数、連結性判定を、配列とキューではなくビット列演算で高速に扱うことにある。

特に、BitBoardによるBFS、`popcnt` による候補数カウント、`pdep` と `tzcnt` によるビット集合からのランダム抽出、`pext` と `pdep` による3x3近傍パターン抽出が説明されている。モンテカルロ型解法ではプレイアウト回数がスコアに直結するため、状態更新や合法手列挙の定数倍削減が本質的な武器になる。

## 主要アイデア

- グリッドのマス集合を整数のビット集合として持つ。
- BFSの1ステップを上下左右シフトとORで行う。
- 行をまたぐ左右移動のワープを防ぐため、左右シフト前に行端マスクをかける。
- 到達可能領土の更新は、変化がなくなるまで `visited` を拡張する。
- 候補数は `popcnt(mask)` で数える。
- ビット集合から一様ランダムに1つ選ぶときは、`k` 番目の1を `pdep(1<<k, candidates)` で取り出し、`tzcnt` で添字に戻す。
- 3x3近傍パターンは `pext` で盤面上の対象ビットを詰め、外周など欠ける場所は `pdep` で9bit配置へ戻して辞書を引く。
- `pdep/pext` は便利だが単純ビット演算より重いため、実測が必要である。

### 探索・構築・更新

- BitBoard BFSは次のように行う。

```text
visited = start
while true:
    next = visited
    next |= (visited & left_mask) << 1
    next |= (visited & right_mask) >> 1
    next |= visited << W
    next |= visited >> W
    next &= movable_mask
    if next == visited:
        break
    visited = next
```

- 候補集合が得られたら `popcnt` で数える。
- ランダム候補選択は、候補を配列へ詰めずにビット演算だけで行える。

```text
cnt = popcnt(candidates)
k = random(0, cnt-1)
one = pdep(1 << k, candidates)
cell = tzcnt(one)
```

- 3x3近傍パターンは、各セルについて「盤面上に存在する近傍ビット」と「3x3辞書上の配置」を前計算し、`pext -> pdep -> table lookup` で判定する。

## 実装上重要な断片

キャッシュ実装の `GameState` は、各プレイヤーの領土、領土ビット、全領土、全駒、最大レベル、レベル1、スコア、位置、ターンを持つ。合法手は「自分位置から自領土内で到達できる成分」を1手膨張し、相手駒を除いた集合として求める。`apply_actions` は衝突、所有者更新、連結成分、スコアをまとめて更新する。

AI推定は、各観測についてカテゴリ別最大値、合法手数、選択手のランダム確率と貪欲確率を `ActionHistory` に保存する。`run_mcmc` は前回候補とランダム候補から始め、尤度 `eps * random_prob + (1-eps) * greedy_prob` を使ってMetropolis更新する。カテゴリ評価の比較にはAVX風の `AlignedF64` を使っている。

## この解法の本質

AHC061の盤面は小さいが、モンテカルロやMCTSでは同じ種類の処理を膨大に繰り返す。キューBFSや候補配列構築を素朴に行うと、探索回数がすぐに頭打ちになる。ビットボード化すると、到達可能判定、候補数、ランダム選択、局所連結判定をCPU命令数の少ない処理へ落とせる。

この考え方は、グリッド上の「集合の膨張」「集合の境界」「集合からの抽出」が多い問題に移せる。ただし `pdep/pext` のような特殊命令は、命令の重さや環境差まで含めて測らないと逆効果になる可能性がある。

## 真似するならまず実装する部分

まずは特殊命令を使わず、`u128` または `__uint128_t` で4方向シフトBFSと `popcount` による合法手数カウントを実装するのがよい。これだけで、到達可能領土や候補管理の構造がかなり明確になる。

次に、候補ビット集合からのランダム選択を実装する。`pdep` が怖ければ、最初は `mask &= mask-1` をk回行うフォールバックでよい。最後に3x3近傍テーブルや `pext/pdep` を試し、実測で速くなる場合だけ採用する。

## 注意点・未理解点
