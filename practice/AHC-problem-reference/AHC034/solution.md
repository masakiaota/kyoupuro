## 問題の本質

この問題は、土の供給量と需要量が総和0で釣り合っている盤面で、どの順序で移動し、どこでどれだけ土を積み下ろすかを最小コストで決める問題である。積み下ろし自体は土量に比例するだけだが、移動コストは `100 + 積載量` なので、重い土を長く運ぶほど悪い。

解法視点では、最適化対象は大きく2つに分かれる。

- 経路: どのマスをどの順に通るか、どの辺を輸送路として使うか。
- 土量: 経路上の各時点で、どれだけ積み、どれだけ降ろし、どれだけ運ぶか。

上位解法ほど、この2つを分離している。特に固定walk+最小費用流は、経路を固定した瞬間に土量最適化を厳密に解ける点が強い。

## 共通している考え方

複数解法に共通するのは、積み下ろし量を細かく連続最適化しようとせず、先に扱いやすい構造を決める点である。

- yosupo/physics0523は、walkを決めてから最小費用流で土量を決める。
- wanuiは、最近傍貪欲の大局挙動を「何個山を積むか」の列で制御する。
- ki84zvkzz4は、周回順と局所的な土補給ルールを固定し、曲がり方を乱択する。
- a01sa01toは、訪問したマスは必ず一度で0にすることで状態遷移を単純化する。

また、どの解法でも「移動固定費100」と「重いまま移動する追加費」のバランスが中心になる。全マスを何度も巡ると固定費が重く、逆に土を遠くまで運びすぎると積載費が重い。

## 推奨して理解すべき順序

1. a01sa01toのDP風構築を読む。各マスを一度で0にする単純化で、コスト計算と積載制約の基本を掴める。
2. wanuiの最近傍貪欲を読む。山と谷を行き来する自然な貪欲が、積み回数列という小さな変数で制御できることを理解する。
3. physics0523を読む。2巡walkを輸送路と見て、最小費用流で土量を決める考え方へ移る。
4. yosupoを読む。訪問時刻頂点とマス頂点を分けることで、固定walk時の最適化をより一般的・厳密に扱う構造を理解する。
5. ki84zvkzz4を読む。フローやSAなしでも、地形生成に合った局所ルールで高順位に届く例として見る。

## 実装するならどのルートか

理解のための最小実装なら、a01sa01to型のDP風構築か、wanui型の固定しきい値最近傍貪欲から始めるのがよい。どちらも操作列生成とコスト計算を直接確認しやすい。

上位化を狙うなら、yosupo型の固定walk+MCFを実装するのが最も筋がよい。MCFを一度作ると、任意のwalk候補の評価と操作列復元に使える。初期walkは行ジグザグ+列ジグザグで十分で、その後は中間2点削除の山登りを足す。

実装負荷と得点のバランスを取るなら、physics0523型も有力である。2巡walk、列飛ばしwalk、末尾削除を組み合わせるだけで、MCFの評価対象を増やせる。

## 重要な実装要素

- 状態表現
  - MCF型では `walk` と、訪問時刻ごとの頂点を分けるかどうかが重要。
  - 貪欲型では現在位置、積載量、残り高さを必ず同期させる。
  - DP型では `done` と `tank` を状態に含める。
- 評価関数
  - 実コストは `移動距離 * (100 + 積載量) + abs(積み下ろし量)`。
  - MCF型ではフローコストに固定移動費 `100 * 辺数` を足す。
  - 重み付きDPでは、評価用コストと実コストを混同しない。
- 近傍
  - yosupo: `walk[i]` と `walk[i+3]` が隣接するとき中間2点削除。
  - wanui: `plus` の1移動、隣接結合、分裂。
  - wanui後処理: 同符号連続区間内の2点swap。
  - physics0523: walk末尾削除。
- 差分更新
  - yosupoはMCFを再計算するため差分更新なし。
  - wanuiの小区間swapは局所コスト差分で高速化できる。
  - DP型は遷移ごとのO(1)緩和。
- 候補管理
  - MCF型は複数初期walkを持つと強い。
  - 最近傍型は正/負マス候補を距離順に前計算すると速い。
  - DP型で複数候補を持つ場合はメモリ増に注意。
- 出力判定
  - 積載量が負にならないこと。
  - 最終的に全高さ0、積載量0になること。
  - 0の積み下ろしを出さないこと。
  - 操作数10万以下に収まること。
- パラメータ
  - wanuiの初期積載しきい値200。
  - wanuiの温度 `2000 -> 20`, `200 -> 20`。
  - yosupoの山登り時間約1900ms。
  - physics0523の全体評価時間約1980ms。

## 落とし穴

- 固定walk+MCFで、同じマスを複数回訪れるのに訪問時刻を分けないと、一般には積み下ろし復元が難しくなる。
- MCFのフローコストだけを使い、移動固定費100を足し忘れると評価がずれる。
- 負のマスへ行く前に積載量が足りるか確認しないと、降ろし操作が不正になる。
- 「重い荷物を早く降ろす」だけを局所的に狙うと、余計な移動が増えて悪化する。ki84zvkzz4の150以上なら捨てる案がその例である。
- 最近傍貪欲のタイブレークを無視すると、同じ距離でも盤面の残り方が大きく変わる。
- a01sa01to型を厳密DPだと思い込むと危険である。コードは訪問集合を添字にしておらず、代表履歴を捨てている。
- ランダムに曲がる周回貪欲は、未処理マスを残さないルート管理が壊れやすい。
- 出力復元で「移動してから積む」のか「積んでから移動する」のかを誤ると、コスト評価や積載制約がずれる。
