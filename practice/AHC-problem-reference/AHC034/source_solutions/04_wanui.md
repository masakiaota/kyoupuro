## 解法の全体像

最近傍貪欲で操作列を作る。山、すなわち正のマスをいくつか連続で回収し、谷、すなわち負のマスに移動して降ろす、という動きになる。この「連続して何個の山を回収するか」の列を焼きなましで最適化する。さらに、連続する積み操作区間や連続する降ろし操作区間の内部順序は入れ替えても解の整合性が壊れないため、小区間内のswap焼きなましで移動距離を減らす。

後日改善では、最近傍の距離が同じときに外周側のマスを優先するタイブレークを入れ、山や谷を中央に寄せて平均移動距離を下げている。

## 主要アイデア

- 基本貪欲は「現在位置から最も近い処理可能な山または谷へ行く」。
- 積載量が0なら谷へ行かない。積載量が一定以上なら山へ行かない、という制限で山と谷の往復を作る。
- 固定の積載上限200は硬すぎるため、山を連続で何個積むかの列 `X1, X2, ...` に一般化する。
- `sum(Xi) = 山マス数` を保ちながら、`Xi` の移動、隣接項の結合、項の分裂を焼きなましする。
- ある解の操作列を、積みが連続する区間、降ろしが連続する区間に分ける。区間内の順番を入れ替えても積載量の入口・出口は変わらず、外側に影響しない。
- 小区間内の2点swapを焼きなましして、細かい経路の無駄を取る。
- タイブレークはスコアに大きく影響する。外周優先にすると未処理の山谷が中央に集まり、移動距離が短くなりやすい。

## 最終コードの構造

ここでは後日改善版 [Submission #54651523](https://atcoder.jp/contests/ahc034/submissions/54651523) を中心に書く。本番版との差分は、タイブレークと小区間swapの差分評価が主である。

### 状態表現

- `INIT_H[400]`: 初期高さを1次元化した配列。
- `distance_table[400][400]`: マンハッタン距離。
- `near_minuses[p]`, `near_pluses[p]`: 各位置から見た負/正マスの優先順リスト。
- `nexts[p]`: 4近傍移動先。
- `state_t { p, d, h[400] }`: 現在位置、積載量、残り高さ。
- 操作は内部的に
  - 移動先マス番号
  - `inf + delta` で表した積み下ろし
  を混ぜた列、または `(マス, delta)` の列で持つ。
- 焼く対象の `plus`: 連続して積む山マス数の列。

### 観測・制約・入力の扱い

- 入力を1次元配列に変換する。
- 全マス間マンハッタン距離と、各マスの4近傍を前計算する。
- 正マス・負マスの候補リストを各現在位置ごとにソートする。
- 後日版の候補順は、距離を最優先し、同距離では外周側を優先するキーを使う。

### 評価関数

`greedy1(plus)` は、`plus` 列に従って貪欲を実行し、実コストの負値を返す。

```text
score = -cost
cost += distance(current, dest) * (100 + load)
cost += abs(load_or_unload_amount)
```

小区間swapでは、後日版は対象区間と次の1操作だけを取り出し、区間入口の位置と積載量から局所コストを計算する。採択後は

```text
new_total_score = old_total_score - old_local_score + new_local_score
```

の形で差分更新する。

### 探索・構築・更新

最初に固定上限200の最近傍貪欲で初期操作列を作る。正マス候補は `load < 200` のときだけ、負マス候補は `load > 0` のときだけ見る。

次に初期操作列から、正マスが連続する長さ列 `plus` を抽出する。焼きなましの近傍は3種類である。

```text
90%: two positions x,y
     plus[x] -= 1
     plus[y] += 1
     if plus[x] == 0: remove it

5%: merge plus[x] and plus[x+1]

5%: split plus[x] into a and plus[x]-a
```

各候補は `greedy1` で最初から評価する。温度は概ね `begin_temp = 2000`, `end_temp = 20`。

最後に `greedy2(bestplus)` で `(マス, delta)` 列を復元し、`small_ops_bf` で同符号連続区間内の2点swapを焼く。温度は概ね `begin_temp = 200`, `end_temp = 20`。

### 操作・クエリ・出力選択

`greedy2` はマス単位の積み下ろし列だけを作る。最終出力時には、前の操作マスから次の操作マスへマンハッタン最短路で移動し、到着後に `delta` を出す。

```text
for each (dest, delta):
    while current != dest:
        move to neighbor that decreases distance to dest
    output delta as +d or -d
```

### 時間配分・パラメータ

- 本番版は積み回数列の焼きなましを約1400msまで、小区間swapを約1900msまで行う。
- 後日版は積み回数列を約1800msまで、小区間swapを約1980msまで行う。
- 焼きなましの温度は積み回数列で `2000 -> 20`、小区間で `200 -> 20`。
- 積み回数列の近傍割合はおおむね `90:5:5`。
- 初期貪欲の固定積載しきい値は200。

## 実装上重要な断片

`plus` 列に従う貪欲の中核は次の形である。

```text
for pcnt in plus:
    while true:
        pcnt -= 1
        near_plus = nearest positive if pcnt >= 0
        near_minus = nearest negative if pcnt < 0 and load > 0
        if neither exists:
            break
        dest = closer of near_plus and near_minus
        if dest is positive:
            load all
        else:
            unload min(load, need)
```

同符号区間のswapは、外側に影響しない範囲だけを触る。

```text
split ops into ranges where delta signs are equal
while time remains:
    choose range
    choose two operations in range
    compute local old cost
    swap them
    compute local new cost
    accept by annealing
```

## この解法の本質

この解法は、操作列全体を直接焼くのではなく、解の大局構造を決める低次元の変数を見つけて焼いている。最近傍貪欲の動きは「何個山を集めてから谷に向かうか」で大きく変わるため、積み回数列は小さい表現ながら経路全体に影響する。

一方で、連続する積み区間や降ろし区間の内部順序は局所的なTSPに近い。ここを後処理で改善することで、大局と局所を分けて最適化している。

## 真似するならまず実装する部分

まずは固定しきい値200の最近傍貪欲を実装する。次に、そのしきい値を `plus` 列へ置き換え、`plus` を3近傍で焼く。小区間swapは後処理として独立に足せるため、最初の実装では省いてよい。

理解のための最小実装なら、外周優先タイブレークも早めに入れる価値がある。実装は候補リストのソートキーを変えるだけで効果が大きい。

## 注意点・未理解点

- `plus` を少し変えただけで貪欲の実際の動きがどの程度変わるかは、記事でも完全には分かっていないとされている。
- 候補リストのタイブレークは見落としやすいが、盤面の残り方を大きく変える。
- 小区間の厳密最適化は記事中で試行されたが、実装負荷が高く断念されている。swap焼きなましの方が堅実である。
- `adds` 変数が使われていないなど、提出コードには実験痕跡が残る。意図を読む際は記事の説明と照合する必要がある。
- 最短路復元では、同距離の近傍選択が固定される。ここもタイブレークの影響を受けうる。
