## 解法の全体像

整地済みマス数 `k` と現在位置 `(x,y)` を軸にしたDP風の構築で、次にどの未整地マスへ移動して0にするかを順に決める。各状態には、累積コスト、積載量、直前位置、整地済み集合のbitsetを持つ。遷移では任意の未整地マスを選び、マンハッタン距離で移動して、そのマスの高さを一気に0にする。

コード上は `dp[k][pos]` に1つ、または最終実験では上位5つの代表状態だけを持つ。訪問集合をDP添字に含める厳密な部分集合DPではなく、同じ整地済み数・現在位置に来る多数の履歴を代表状態に潰す近似的なDPである。

## 主要アイデア

- 各マスを中途半端に整地せず、訪れたときに必ず高さ0にする。
- 正のマスなら全量積み、負のマスなら必要量を降ろす。
- 負のマスへ遷移するには、現在積載量がその不足量以上である必要がある。
- 移動コストはマンハッタン距離と現在積載量から即座に計算できる。
- 整地済み集合は400ビットの `bitset` として状態値に持つ。
- コスト式の移動部分と積み下ろし部分に重みを掛け、複数重みのDPを試す。
- 最後に、各 `dp[k][pos]` に上位5候補を持つ案も試しているが、記事によると大きな改善はなかった。

## 最終コードの構造

「最も点が高かった提出」は重み調整版 [Submission #54639166](https://atcoder.jp/contests/ahc034/submissions/54639166) である。一方、記事最後の上位候補保持案 [Submission #54641862](https://atcoder.jp/contests/ahc034/submissions/54641862) も構造上重要なので併記する。

### 状態表現

基本版・重み版:

- `Grid[20][20]`: 初期高さ。
- `bitset<400> done`: 整地済みマス集合。
- `dp[t][pos] = (cost, tank, prv, rawcost, done)`:
  - `cost`: 重み付き評価コスト。
  - `tank`: 現在積載量。
  - `prv`: 復元用の直前位置。
  - `rawcost`: 実コスト。重み探索時に最良判定で使う。
  - `done`: ここまでに整地した集合。

上位候補保持版:

- `dp[t][pos][cand] = (cost, tank, prv, prvidx, done)`。
- `MaxCand = 5`。
- 同じ `t,pos` に複数履歴を残す。

### 観測・制約・入力の扱い

- `N = 20` を `assert` する。
- 遷移先がすでに `done` なら飛ばす。
- 遷移先の高さが負で、`tank < -Grid[i][j]` なら飛ばす。
- 遷移可能なら、そのマスを一気に0にするものとして `tank += Grid[i][j]` とする。
- 高さ0のマスも遷移先になりうる。操作は出さないが、移動経路としては選ばれる。

### 評価関数

基本版の遷移コストは次である。

```text
ccost =
    current_cost
  + manhattan(prev, next) * (100 + tank)
  + abs(Grid[next])
```

重み版では、評価用コストと実コストを分ける。

```text
weighted_cost += move_cost * weight_d + load_unload_cost * weight_c
rawcost       += move_cost            + load_unload_cost
```

試した重みのうち、復元候補の `rawcost` が小さいものを採用する。読めた提出では `weight_d` を1から5、`weight_c` を1,3,5で試す版が最高点だった。

### 探索・構築・更新

DP遷移は全状態から全未整地マスへ飛ぶ。

```text
for t in 0..399:
    for pos in all cells:
        state = dp[t][pos]
        if state is invalid:
            continue
        for next in all cells:
            if done[next]:
                continue
            if Grid[next] < 0 and tank < -Grid[next]:
                continue
            relax dp[t+1][next]
```

基本版は各 `dp[t+1][next]` に最小コストの1状態だけを残す。上位候補保持版は、最大5個の候補のうち最悪のものを置き換える。

### 操作・クエリ・出力選択

最良終端状態から `prv` を辿って訪問マス列を復元する。復元は後ろ向きに行い、最後に反転する。

各訪問マスについて:

- `Grid[cell] > 0` なら `+Grid[cell]`。
- `Grid[cell] < 0` なら `-abs(Grid[cell])`。
- 前のマスから現在マスまで、マンハッタン最短路で `UDLR` を出す。

コードは逆向き復元中に操作と移動を積み、最後に `reverse(ans)` して正順にしている。

### 時間配分・パラメータ

- 基本版は約100ms。
- 重みを複数試す版は約1.0から1.8秒。
- 上位5候補保持版は約1.1秒、メモリ約66MB。
- `MaxCand = 5`。
- 重み探索の最高点提出では `weight_d in {1,2,3,4,5}`, `weight_c in {1,3,5}`。

## 実装上重要な断片

遷移の本質は短い。

```text
relax(state, next):
    if done[next]:
        skip
    if height[next] < 0 and tank < -height[next]:
        skip
    move = manhattan(pos, next) * (100 + tank)
    work = abs(height[next])
    new_tank = tank + height[next]
    new_done = done with next set
    update dp[t+1][next]
```

復元では「訪問時に一気に整地する」という前提をそのまま操作に変換する。

```text
for visited cell in order:
    move from previous cell by Manhattan path
    if height[cell] > 0: output +height[cell]
    if height[cell] < 0: output height[cell]
```

## この解法の本質

この解法は、土の流れやwalk形状を最適化するのではなく、「次にどのマスを確定させるか」という構築順序に問題を落としている。各マスを一度で0にするという制約を自分で入れることで、状態遷移が非常に単純になる。

厳密な部分集合DPではないため理論的な最適性はないが、`N=20` かつ高さが小さいこの問題では、代表状態だけでもかなり良い訪問順が得られる。実装時間に対する得点が高い方針である。

## 真似するならまず実装する部分

まずは `dp[t][pos]` に1状態だけ持つ基本版を実装する。遷移条件は「未訪問」「負なら積載が足りる」の2つだけでよい。これで7.7G級に届く。

次に、移動コストと積み下ろしコストの重みを複数試す。上位候補保持はメモリが増える割に記事では改善が小さいため、後回しでよい。

## 注意点・未理解点

- 記事ではDPと呼ばれているが、コード上は訪問集合をDP添字に含めず、`dp[t][pos]` の値として1つのbitsetを持つだけである。同じ `t,pos` に到達する別集合は捨てられるため、厳密DPではない。
- 負のマスを訪問するには積載量が足りる必要がある。ここを忘れると不正出力になる。
- 復元時の移動と積み下ろしの順序を誤ると、積載量制約や位置が壊れる。
- 重み付き評価で選んだDPの `cost` と、最終的に出したい実コスト `rawcost` を混同しないこと。
- 上位候補保持版は候補同士の訪問集合重複が多い可能性があり、単純に候補数を増やしても改善しにくい。
