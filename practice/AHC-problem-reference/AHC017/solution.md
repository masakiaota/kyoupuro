## 問題の本質

AHC017 は、各辺を1日だけ工事する日程を決め、各日の「辺削除後の全点対最短距離増加」を小さくする問題である。解法視点では、工事日割り当てそのものより、辺を同じ日に止めたときに最短路網がどれだけ壊れるかを高速に見積もることが本質である。

素直な評価は、日ごとに全頂点始点の Dijkstra を走らせる必要があり、1辺移動の探索すらほとんどできない。強い解法はすべて、次のどちらか、または両方を使っている。

- 全点対評価を代表点からの距離和で近似する。
- 1辺追加・削除で影響する最短路木の一部だけを更新する。
- 直接距離を見ず、辺ペアの相性スコアへ圧縮して高速な探索にする。

## 共通している考え方

共通点は、1回の操作で全体を再評価しないことである。1辺を日 `a` から日 `b` へ移すと、影響するのは基本的に2日だけである。さらに、その2日の中でも、すべての代表点、すべての頂点の距離が変わるわけではない。

距離ベースの解法では、各代表点からの最短路木を持ち、工事追加なら最短路木の壊れる部分木だけ、工事キャンセルなら新しく短縮される範囲だけを更新する。この状態を保つために、距離配列、親辺、日別工事辺、復元履歴が必要になる。

もう一つの共通点は、評価精度を固定しないことだ。bowwowforeach は代表点を32段階で増やし、FakePsyho は日候補を段階的に絞る。nikaj も終盤にサンプルを増やす。粗い評価で探索回数を稼ぎ、終盤に実スコアへ寄せる発想が重要である。

## 解法の分類

- 距離差分更新型: bowwowforeach、ymatsux、nikaj。代表点からの距離和を持ち、1辺追加・削除で更新する。
- 貪欲構築型: FakePsyho、bowwowforeach の初期解。辺順と日選択評価で強い初期割り当てを作る。
- 1辺移動 SA/HC 型: bowwowforeach、ymatsux、nikaj、FakePsyho の後処理。
- 複数辺遷移型: bowwowforeach の頂点周辺遷移。1辺移動だけで固まった状態を崩す。
- 辺相性型: msmits、ymatsux の7位版概要、nikaj の追加改善。辺ペアの同日適性を事前または局所的に評価する。

## 推奨して理解すべき順序

1. ymatsux を読む。代表点近似と最短路木差分更新の最小構成が分かる。
2. bowwowforeach を読む。代表点の段階的増加、評価打ち切り、複数辺遷移を理解する。
3. FakePsyho を読む。強い貪欲構築、辺順、ビーム的な日候補絞りを理解する。
4. nikaj を読む。上位解法に共通する抽象化と、辺相性改善の方向を見る。
5. msmits を読む。距離評価から離れて、辺ペア関係を直接最適化する発想を理解する。

## 実装するならどのルートか

理解のための最小実装は ymatsux 型がよい。代表点を少数に固定し、初期解を `edge_id % D` で作り、1辺移動 SA を行う。最初は対象2日で Dijkstra をやり直して正しさを確認し、その後、最短路木の差分更新に置き換える。

スコアを伸ばすなら、次に bowwowforeach 型の代表点段階増加と評価打ち切りを足す。1辺移動だけでは局所最適に入りやすいので、頂点周辺の辺をまとめて再割り当てる遷移も有効である。

さらに上位化するなら、FakePsyho 型の初期構築を入れる。重要辺順に処理し、候補日を代表点ビームで絞る貪欲は、探索開始時点の解を大きく改善できる。別方向の強化として、msmits 型または ymatsux 7位版の辺相性初期解を使う選択肢もある。

## 重要な実装要素

- 状態表現: `assign[e]`、日別工事辺集合、日別工事数、日別 active edge 配列。
- 距離状態: `dist[day][sample][v]`、`parent_edge[day][sample][v]`、代表点ごとの距離和。
- 代表点: 2x2 や 5x5 格子、円周付近、座標上で分散した集合など。探索中に増やす設計も有効。
- 評価関数: 代表点から全頂点への距離和増加。移動では移動元日と移動先日の差分だけを見る。
- 差分更新: 辺削除は最短路木の部分木無効化、辺追加は端点緩和からの Dijkstra。
- 復元: 棄却時に距離、親辺、日別距離和、工事日、日別工事数を戻す。
- 近傍: 1辺移動、1頂点周辺の複数辺再割り当て、辺相性スコア上の1辺移動。
- 候補管理: 日容量 `K`、非連結判定、代表点ビーム、評価打ち切り。
- 時間配分: 前半は粗い評価で回し、後半は代表点を増やすか HC に切り替える。
- 出力判定: すべての辺に `1..D` の日を割り当て、各日の本数が `K` を超えないことを守る。

## 落とし穴

- 全点対 Dijkstra を毎回やると、探索回数がまったく足りない。
- 代表点が少なすぎると、近似スコアだけ良くなり実スコアが悪化する。
- 辺削除時に、最短路木で影響を受ける子孫を取り漏らすと距離が過小評価される。
- 辺追加時に、端点の短縮判定を間違えると更新が伝播しない。
- 到達不能を `INF` として距離和へ入れないと、非連結な日を過小評価する。
- 棄却時の rollback で親辺や日別距離和を戻し忘れると、次の評価が壊れる。
- 工事日移動では移動先容量だけでなく、移動元と移動先の active edge 状態の反転方向を混同しやすい。
- 距離丸めは速いが、実スコアとのずれを生む。正しさ確認前に入れるとバグと近似誤差を区別しにくい。
- 辺相性型は高速だが、relation score と本来の距離スコアがずれることがある。
