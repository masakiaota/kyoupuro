## 解法の全体像

主方針は、高速な貪欲構築である。まず各辺を「単独で工事したときの不満度増加」が大きい順に並べる。次に、その順番で辺を1本ずつ見て、追加不満度が最も小さい日へ割り当てる。候補日評価は代表点集合を使い、最初は少ない代表点で粗く候補日を絞り、段階的に代表点数を増やして最終候補を決める。

最短路計算は重みを `DIST_DIV = 1000` で丸め、バケット型 Dijkstra に近い形で `O(E + max_dist)` を狙う。さらに、辺を1本追加・削除するときは動的 Dijkstra で差分更新する。貪欲が終わった後に時間が残れば、1辺を別日に移す単純な山登りを行う。

## 主要アイデア

- 辺を重要度順に固定して処理する。重要度は、単独工事時の代表点距離和増加で見る。
- 日を選ぶとき、追加不満度だけでなく、序盤に日を適度に埋めるための補正を掛ける。
- 代表点評価はビームサーチのように段階的に精度を上げる。
- 距離を1000で割って小さい整数にし、通常の priority queue Dijkstra より速いバケット処理へ寄せる。
- 代表点集合が小さいときは、座標上で互いに離れるように選ぶ。
- 貪欲の途中で時間消費を見て、ビーム幅と代表点数を増減する。
- 後処理はランダムな1辺移動の山登りで、改善する場合だけ採用する。

## 最終コードの構造

### 状態表現

- `edges`: 各辺の両端点。重みは別途 `fd[u][v]` に持つ。
- `ove`: 元グラフの隣接リスト。
- `fd`: 1000で丸めた辺重み。
- `subset`: 評価に使う始点集合。
- `ddist[D][subset][N]`: 各日、各代表点から各頂点への現在距離。`short` で保持する。
- `ddist_sum[D][subset]`: 代表点ごとの距離和。
- `days_edges[D]`: 各日に工事する辺リスト。
- `days_dist[D][subset]`: 代表点 prefix ごとの日別距離和。
- `bsol[M]`: 各辺の割り当て日。
- `beam`: 代表点数と残す候補日数の段階リスト。

距離は丸めた値で保持するため、速度と精度を交換している。記事でも、この近似でどれだけ損しているかは確信がないと述べている。

### 観測・制約・入力の扱い

- 入力の重み `w` は `(w + DIST_DIV / 2) / DIST_DIV` で丸める。
- 日ごとの工事数が `K` に達した日は候補から外す。
- 未使用の空日は対称なので、候補日列挙時には空日を1つだけ見る。
- 代表点数が小さい場合は `find_subset` で座標上の分散を良くする。代表点数が多い場合は単純な頂点番号順に近い。
- グラフが非連結になる候補は、距離計算で大きな値を返す扱いになっている。

### 評価関数

貪欲で辺を日へ置くときの評価は、代表点距離和の増加に、日を埋めるための補正を掛ける。

```text
eval = added_frustration
       * (1 - 0.30
              * ((edges_left / M) ^ 3.5)
              * ((day_edges_left / K) ^ 12)
              * empty_day_bonus)
```

- `empty_day_bonus` は空日の場合だけ少し強く働く。
- 序盤は空きの多い日を使いやすくし、終盤は実際の追加不満度に寄せる形である。
- 後処理の山登りでは、移動元日で工事をキャンセルした距離和と、移動先日で工事を追加した距離和の合計が悪化しなければ採用する。

### 探索・構築・更新

- 辺順の決定:
  - 元グラフで代表点距離を計算する。
  - 各辺を単独で工事した場合の距離和を `calc_all_distances_rem_edge<false>` で見積もる。
  - 増加が大きい順に辺を処理する。

- 貪欲割り当て:
  - 現在の辺に対し、容量のある日を候補にする。
  - 代表点集合を段階的に増やしながら、候補日数を減らす。
  - 最終的に残った最良日へ辺を入れ、日別距離状態を確定更新する。

- ビーム的評価:
  - コードでは `beam_days = {4, 4, 3, 2, 1}`、`beam_mul = {1, 4, 7, 10, 50}` を元に代表点数と候補日数を構成する。
  - 各段階で代表点を追加し、候補日を上位だけに絞る。
  - 時間が足りなさそうならビームを縮め、余りそうなら広げる。

- 動的距離更新:
  - 工事追加、つまりグラフから辺を削除する場合、削除辺が代表点からの最短路木に関係しなければスキップする。
  - 関係する場合は、遠い側の端点から最短路木の部分木を BFS で集める。
  - 部分木の境界から再接続候補を作り、バケット Dijkstra で距離を直す。
  - 工事キャンセル、つまりグラフへ辺を追加する場合は、その辺で距離が短縮される端点から緩和を開始する。

- 後処理山登り:
  - ランダムな辺と移動先日を選ぶ。
  - 移動先が満杯ならスキップする。
  - 移動元日では辺を追加、移動先日では辺を削除した評価を計算する。
  - 悪化しないなら日別リストと距離状態を確定更新する。

### 操作・クエリ・出力選択

- 出力は `bsol[edge] + 1` を全辺分並べる。
- 貪欲構築中に `days_edges` と `bsol` は常に一致する。
- 後処理山登りで採用したときだけ、`days_edges[d1]` から辺を削除し、`days_edges[d2]` へ追加する。

### 時間配分・パラメータ

- `TIME_LIMIT = 5.9` 秒。
- `DIST_DIV = 1000`。
- `POST_HC = true`。
- `ADJUST_BEAM = true`。
- 代表点とビーム幅は、推定される距離計算呼び出し回数から調整する。
- 後処理の山登りは、貪欲後に残った時間だけ実行する。

## この解法の本質

この解法の本質は、強い局所探索よりも、強い初期構築に寄せている点である。AHC017 では、1本の辺を追加した評価を高速に出せれば「どの日に置くべきか」という貪欲がかなり戦える。そこで、辺順、日選択評価、代表点ビーム、動的 Dijkstra をすべて貪欲のために組み合わせている。

また、実スコアを完全に追うのではなく、距離丸めと代表点近似で速度を大きく取る。近似の粗さを、辺順と段階的評価で補っている。後処理山登りは補助的で、記事の ablation でも主な強さは高速 pathfinding、辺順、評価式にある。

## 真似するならまず実装する部分

まずは、代表点を固定して、辺を単独不満度の大きい順に並べる貪欲を実装するのがよい。日選択では、全候補日を同じ代表点集合で評価し、最良日へ置くだけでよい。

その後、動的 Dijkstra、代表点の段階的追加、日を絞るビーム評価、時間に応じたビーム調整を加える。距離丸めは効果と副作用があるため、最初は通常の整数距離で正しさを確認してから入れる方が壊れにくい。

## 注意点・未理解点

- 距離を1000で丸めるため、実スコアとのずれが出る。記事でも、この近似の損得は完全には確信されていない。
- 動的削除更新では、削除辺が最短路木に入っているかの判定と、影響部分木の抽出が壊れやすい。
- バケット Dijkstra は距離上限に依存する。丸めない場合は同じ配列実装をそのまま使えない。
- 貪欲が時間切れしそうなときのビーム調整は、コード上もかなり実用的な時間管理であり、再現にはチューニングが必要である。
- 記事からは AtCoder 提出 ID と提出時スコアを確認できなかった。
