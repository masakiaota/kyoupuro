## 解法の全体像

完成図作成とスライドパズル解法を分ける。まず、タイル枚数を無視して適当な全域木を作り、木構造を保ったまま焼きなましでタイル種類の枚数を入力と一致させる。次に、スライドパズルを解く段階では、次に揃える行または列が合わせやすくなるように完成図をその都度焼きなましで改変し、双方向 IDA* でその行・列を揃える。

揃える単位は、残り領域が大きい間は 1 行・1 列、5x5 以下では行列をまとめた「く」の字型、最後の 3x3 はまとめて探索する。完成図を固定せず、現在盤面に近い完成図へ随時変形するのが大きな特徴である。

## 主要アイデア

- 完成図作成は、タイル枚数を常に満たすのではなく、木であることを常に保つ近傍にする。
- 近傍は「木の辺を 1 本切って、別の辺で繋ぎ直す」。連結性と閉路なしを保ったままタイル種類の分布を変える。
- 完成図作成の評価関数は、各タイル種類の使用枚数と入力枚数の差の二乗和を最小化する。
- パズル中も完成図を改変する。次に揃える行・列に必要なタイルが現在位置に近くなるよう、マンハッタン距離二乗和を焼きなましの評価に入れる。
- タイル対応は種類ごとに重み付きマッチングで決める。実際の完成図改変中の評価では、重い厳密マッチングを避けて貪欲な近似マッチングも使う。
- タイル合わせは双方向 IDA*。片側を IDA*、反対側を IDDFS 的に展開し、Zobrist Hash で中間一致と重複除去を行う。
- 探索爆発時は、状態数が一定以上になったら最も見込みのよい盤面だけ残して仕切り直す。

## 最終コードの構造

in-app Browser で読んだ提出 #32266050 の構造である。Rust 実装で、記事本文の完成図焼きなまし、動的改変、双方向 IDA* が確認できる。

### 状態表現

- `init_blueprint::AnnealingState` が初期完成図を作る。木構造を保ったままタイル種類数の差二乗をスコアにする。
- `blueprint::AnnealingState` がパズル途中の完成図改変を扱い、`target_map`、`fixed`、`matching_scores` を持つ。
- パズル状態 `State` は盤面、逆引き、空きマス、stage、直前手、128bit hash、score を持つ。
- 揃える対象は `get_stages` で作り、外周を互い違いに処理し、残り5x5以下と最後3x3をまとめる。

### 観測・制約・入力の扱い

- 入力からタイル種類ごとの枚数を数え、完成図の枚数制約として使う。
- 木構造を保つ焼きなましでは、辺を削除してできる 2 成分を DFS で調べ、別の辺で再接続できる候補を選ぶ。
- パリティが合わない完成図は同種タイル 2 枚の対応を入れ替えることで解消できる。ただし同種タイルがない場合は困るため、その段階では完成図改変を諦める方針としている。
- 固定済み領域は以降の IDA* で壊さない制約として扱う。

### 評価関数

- 完成図作成: `sum_i (actual_count[i] - target_count[i])^2` を最小化する。
- 初期に試した失敗寄りの評価: 連結成分サイズとループ数を使う評価。大きい成分を評価しつつ、ループを減点する意図だった。
- 完成図改変: 次に揃える行・列のタイルについて、現在位置と完成図位置のマンハッタン距離の二乗和を小さくする。タイル枚数差の評価との線形結合も使う。
- IDA*: `現在手数 + sum(対象タイルのマンハッタン距離^1.5)` を探索コストにする。

### 探索・構築・更新

- 初期完成図は `create_init` 後、0.1秒程度の焼きなましで枚数を合わせる。
- 各 stage の前に、重複タイルがあれば完成図を 0.2/0.1/0.03 秒程度再焼きなましして現在盤面へ寄せる。
- `match_pazzle` で同種タイルの対応を作り、パリティ不一致時は同種タイルの目標を swap する。
- `get_inv_goals` で目標側から逆方向 depth の hash 集合を作る。
- `ida_star` で探索し、状態数が増えすぎたら `ida_star_best` で最良状態だけ残して仕切り直す。

### 操作・クエリ・出力選択

- 1 行・1 列を揃えるたびに、対応する IDA* 経路を操作列に追加する。
- 残り 5x5 以下は複数行列をまとめて揃え、最後の 3x3 は全体を IDA* で合わせる。
- 最終出力は、完成図に到達するまでの操作列である。

### 時間配分・パラメータ

- 完成図作成は 0.1 秒未満で多数見つかるようになったとしている。
- 完成図改変は、37M 台から 40M 超への大きな改善要因とされる。
- IDA* の探索状態数上限を設け、爆発したら仕切り直す。
- Zobrist Hash は衝突を恐れて 128 bit を使う。
- 揃えたいタイル以外を同一視することで、微妙に違うだけの盤面をまとめ、探索効率を上げる。

## この解法の本質

この解法は、難しい条件をどちらか一方だけ固定して扱う。完成図生成では木であることを不変条件にし、タイル枚数だけを評価で寄せる。パズル解法では全体を一気に合わせず、固定済み領域を増やしながら局所的な探索問題へ分解する。さらに完成図を途中で変形することで、「目標が遠いせいで操作列が長い」という問題を緩和している。

木の構造を保つ近傍を選ぶ発想が特に重要である。完成図が木でない状態を評価関数で救うより、木である空間だけを歩く方が局所探索しやすい。

## 真似するならまず実装する部分

まずは「木構造を保つ辺の切断・再接続近傍」と、タイル枚数差二乗和の焼きなましを実装するのがよい。これだけで、到達可能な完成図を安定して作る部分が見える。次に、行単位に固定する簡易パズル解法を作る。双方向 IDA* や Zobrist Hash は最後に入れる要素でよい。
