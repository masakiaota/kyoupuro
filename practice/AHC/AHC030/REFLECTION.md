# REFLECTION

## AHC030

- 丁寧に式変形すると、このコンペでは尤度が高い油田配置だけが重要だと判明した。
  - \(p_t(\theta)\) が十分小さい候補は、相互情報量や事後確率への寄与が小さい。
  - 式を丁寧に解釈すると、全候補を同じ重みで扱う必要がなくなり、計算量を一気に落とせる。

- 重い点を特定するには、やはり計測が重要である。
  - 体感やコード上の見た目では `refresh_candidate_pool` が怪しく見えた。
  - 実際に profile すると、主因は `optimize_query_mask_by_mi_per_cost` の hill climb だった。
  - 特に、改善を 1 個見つけるたびに `cell_order` の先頭から再走査する構造が重かった。

- 厳密ではなくなるが、高速化の恩恵が大きい軽量化は積極的に検討する価値がある。
  - 今回なら、\(\mathrm{MI}/\mathrm{cost}\) を指標にした占い集合 \(S\) の特定は、本来なら山登りや焼きなましの方が理想に近い。
  - しかしそれは重すぎたため、単体マス MI でソートし、上から add / 下から remove を sweep するだけの貪欲的な近似にした。
  - その結果、厳密性は落ちたが、計算時間が大幅に減り、結果的にスコアも改善した。

- 他のコンペでも、厳密解法に近い処理が重すぎる場合は、次の一手を有利にする貪欲的なスコアを差し込む余地がある。
  - 例: DP のタイブレークに、厳密な目的関数ではないが将来の局面をよくしやすい評価値を入れる。
  - 重要なのは、厳密性を捨てる箇所と、その代わりに得る計算量削減を明確にすること。
