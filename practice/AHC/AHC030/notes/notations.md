# 記号一覧

このファイルは、AHC030「Polyomino Mining」で使う記号とコード上の代表名・型・制約の正本である。解法考察や探索上の仮説はここに混ぜない。


## 基本入力

### 島の大きさ `N`

`N x N` マスの島の一辺の長さを表す。

- コード上の代表名: `n`
- Rust の想定型: `usize`
- 制約・不変条件: `10 <= N <= 20`
- 備考: 有効な座標は `0 <= i < N`, `0 <= j < N` である。


### 油田の個数 `M`

島の地下に存在する油田の個数を表す。

- コード上の代表名: `m`
- Rust の想定型: `usize`
- 制約・不変条件: `2 <= M <= 20`
- 入力生成上の制約: `M = rand(2, floor(N^2 / 20))`
- 備考: 全く同じ形状の油田が複数含まれる場合がある。


### エラーパラメータ `epsilon`

占いクエリの応答分布を決める誤差パラメータである。問題文では `ϵ` と書かれる。

- コード上の代表名: `eps`
- Rust の想定型: `f64`
- 制約・不変条件: `0.01 <= epsilon <= 0.2`、`0.01` の倍数
- 入力生成上の制約: `epsilon = 0.01 * rand(1, 20)`


## 座標とマス

### マス座標 `(i, j)`

一番左上を `(0,0)` とし、下方向を `i`、右方向を `j` とする 0-indexed 座標である。

- コード上の代表名: `i`, `j`
- Rust の想定型: `usize`
- 制約・不変条件: 島上のマスなら `i < n && j < n`
- 備考: 入力中のポリオミノ形状座標も同じ向きの座標系を使う。


### マス集合 `S`

占いクエリまたは回答で指定する、互いに異なる島上のマスの集合である。

- コード上の代表名: `cells`, `query_cells`, `answer_cells`
- Rust の想定型: `Vec<(usize, usize)>` または集合性が必要なら `HashSet<(usize, usize)>`
- 制約・不変条件: すべて `0 <= i,j < n`、同じ座標を重複して含まない
- 備考: 問題文では占い対象も回答対象も `S` と表すため、コードでは用途ごとに名前を分ける。


## 油田形状と真の配置

### `k` 番目の油田

油田を識別する 1-indexed の添字である。コード上では 0-indexed の添字として扱うのが自然である。

- コード上の代表名: `oil_idx`, `k`
- Rust の想定型: `usize`
- 制約・不変条件: 問題文上は `1 <= k <= M`、コード上は `0 <= oil_idx < m`


### 油田面積 `d_k`

`k` 番目の油田を構成するマス数である。入力では各油田行の先頭に現れる。

- コード上の代表名: `area`, `oil_area`
- Rust の想定型: `usize`
- 制約・不変条件: `4 <= d_k <= N^2 / M`
- 備考: クエリ形式の `q d ...` における `d` は指定マス数であり、油田面積 `d_k` とは別物である。


### 油田形状座標 `(i_{k,t}, j_{k,t})`

`k` 番目の油田形状に含まれる `t` 番目のマス座標である。形状は、上端と左端の座標がどちらも `0` になるように平行移動された状態で入力される。

- コード上の代表名: `shape_cells`, `polyomino`
- Rust の想定型: `Vec<(usize, usize)>`
- 制約・不変条件: `shape_cells.len() == d_k`、辺連結なポリオミノである
- 備考: 油田の向きは入力時点で固定されており、回転や反転は行わない。


### 油田形状の外接範囲 `i_max`, `j_max`

ある油田形状に含まれるマスの `i` 座標最大値、`j` 座標最大値である。

- コード上の代表名: `max_i`, `max_j`
- Rust の想定型: `usize`
- 制約・不変条件: 真の配置オフセット `(deltai_k, deltaj_k)` は `0 <= deltai_k <= N - i_max - 1`, `0 <= deltaj_k <= N - j_max - 1`
- 備考: 入力生成方法と、配置候補が島内に収まるかの判定で使う。


### 真の配置オフセット `(deltai_k, deltaj_k)`

`k` 番目の油田形状を島上に置くための平行移動量である。`deltai_k` は `i` 方向、`deltaj_k` は `j` 方向の移動量を表す。問題文では入力生成方法に `(d_i, d_j)` として現れるが、このプロジェクト内の議論では混同を避けるため `(deltai_k, deltaj_k)` を正本とする。

- コード上の代表名: `deltai_k`, `deltaj_k`, `offset_i`, `offset_j`, `placement`
- Rust の想定型: `(usize, usize)`
- 制約・不変条件: 形状全体が `N x N` の範囲内に収まる。形状内のマス `(i_{k,t}, j_{k,t})` は島上のマス `(deltai_k + i_{k,t}, deltaj_k + j_{k,t})` に対応する
- 備考: 油田同士は重なってよい。


### 油田 `k` の配置候補集合 `Theta_k`

`k` 番目の油田形状が島内に収まるすべての配置オフセット `(deltai_k, deltaj_k)` の集合である。

$$
\Theta_k = \{(deltai_k, deltaj_k) \mid 0 \le deltai_k \le N - i_{max,k} - 1,\ 0 \le deltaj_k \le N - j_{max,k} - 1\}
$$

- コード上の代表名: `placements_by_oil[k]`
- Rust の想定型: `Vec<Placement>`
- 制約・不変条件: 各要素は `k` 番目の油田形状全体が `N x N` の範囲内に収まる配置である


### 全体配置候補集合 `Theta`

全油田の配置候補全体の直積集合である。

$$
\Theta = \Theta_1 \times \cdots \times \Theta_M
$$

- コード上の代表名: `candidates`
- Rust の想定型: `Candidates`
- 制約・不変条件: `Theta` の各要素は、各油田 `k` について `Theta_k` から 1 つずつ配置候補を選んだものである


### 全体配置候補 `theta`

`Theta` の 1 要素である。各油田 `k` について 1 つずつ `(deltai_k, deltaj_k)` を選んだ全体配置候補を表す。

- コード上の代表名: `candidate_id`
- Rust の想定型: `usize`
- 実装上の対応: `Candidates` 内の `placement_indices[candidate_id * m + k]` が、`theta` における油田 `k` の配置候補 index を表す


### 全体配置候補数 `|Theta|`

全体配置候補集合 `Theta` の要素数である。

$$
|\Theta| = \prod_{k=1}^{M} |\Theta_k|
$$

- コード上の代表名: `theta_size`
- Rust の想定型: `usize`
- 備考: 全探索可能性の判定で使う。


### 候補 `theta` の対数重み `ell_t(theta)`

観測履歴 `D_t` までを反映した、全体配置候補 `theta` の対数尤度または未正規化対数事後重みである。

$$
\ell_t(\theta) = \sum_{r=1}^{t} \log P(Y = y_r \mid \theta, S_r)
$$

- コード上の代表名: `logw`
- Rust の想定型: `f64`
- 備考: 実装では正規化せず、候補間の相対重みとして保持する。回答失敗などで除外された候補は `-inf` にする。


## 石油埋蔵量

### マスの石油埋蔵量 `v(i,j)`

マス `(i,j)` を含む油田の数である。

- コード上の代表名: `v`, `oil_amount`, `amount`
- Rust の想定型: `usize` または `i32`
- 制約・不変条件: `0 <= v(i,j) <= M`
- 備考: 掘削クエリ `q 1 i j` の応答では真値が返る。


### 集合の石油埋蔵量 `v(S)`

集合 `S` に含まれるマスの石油埋蔵量の総和である。

$$
v(S) = \sum_{(i,j) \in S} v(i,j)
$$

- コード上の代表名: `sum_v`, `oil_sum`
- Rust の想定型: `usize` または `i32`
- 制約・不変条件: `0 <= v(S) <= |S| * M`
- 備考: 占いクエリではこの真値そのものではなく、ノイズ付きの近似値が返る。


### 候補 `theta` におけるマスの石油埋蔵量 `v_theta(i,j)`

全体配置候補 `theta` が真の配置だと仮定したときの、マス `(i,j)` の石油埋蔵量である。

- コード上の代表名: 明示関数は未確定
- Rust の想定型: `usize` または `i32`
- 制約・不変条件: `0 <= v_theta(i,j) <= M`
- 備考: 真の `v(i,j)` と区別して、候補ごとの尤度計算で使う。


### 候補 `theta` における集合の石油埋蔵量 `v_theta(S)`

全体配置候補 `theta` が真の配置だと仮定したときの、集合 `S` に含まれる石油埋蔵量の総和である。

$$
v_\theta(S) = \sum_{(i,j) \in S} v_\theta(i,j)
$$

- コード上の代表名: `sum_v`
- Rust の想定型: `usize` または `i32`
- 制約・不変条件: `0 <= v_theta(S) <= |S| * M`
- 備考: 現在の実装では明示的な履歴関数ではなく、占いクエリごとに計算する。


### 石油が存在するマス集合

`v(i,j) > 0` である島上の全マス集合である。回答操作ではこの集合を正確に出力する必要がある。

- コード上の代表名: `positive_cells`, `answer_cells`
- Rust の想定型: `Vec<(usize, usize)>` または `HashSet<(usize, usize)>`
- 制約・不変条件: 掘削により `v(i,j) > 0` と判明済みのマスは必ず含める


## 操作と応答

### 操作回数上限 `2N^2`

初期入力後に行える操作の最大回数である。

- コード上の代表名: `query_limit`, `turn_limit`
- Rust の想定型: `usize`
- 制約・不変条件: `query_limit == 2 * n * n`
- 備考: 掘削、占い、回答失敗後の再挑戦はいずれも操作回数に含まれる。


### 掘削クエリ `q 1 i j`

1 マス `(i,j)` を掘り、真の `v(i,j)` を得る操作である。

- コード上の代表名: `dig`, `Dig`
- Rust の想定型: 出力操作または enum variant は未確定
- コスト: `1`
- 応答: `v(i,j)` の真値
- 制約・不変条件: 既に掘ったマスを再度掘ってもよいが、通常は利点がない


### 占いクエリ `q d ...`

`d >= 2` 個の互いに異なるマス集合 `S` を指定し、`v(S)` のノイズ付き近似値を得る操作である。

- コード上の代表名: `forecast`, `query`, `Forecast`
- Rust の想定型: 出力操作または enum variant は未確定
- 指定マス数の代表名: `k`, `len`, `query_size`
- 制約・不変条件: `2 <= |S| <= N^2`、座標重複なし
- コスト: `1 / sqrt(|S|)`
- 応答: `max(0, round(x))`


### 占い応答の分布 `x`

占いクエリで内部的にサンプルされる実数値である。

$$
x \sim \mathcal{N}(\mu, \sigma^2)
$$

$$
\mu = (|S| - v(S))\epsilon + v(S)(1 - \epsilon)
$$

$$
\sigma^2 = |S|\epsilon(1 - \epsilon)
$$

- コード上の代表名: `sample`, `mean`, `variance`
- Rust の想定型: `f64`
- 備考: 解答プログラムが受け取る値は `max(0, round(x))` であり、真の `x` は直接観測できない。


### 占い応答値 `y`

解答プログラムが占いクエリの応答として実際に受け取る整数値である。内部サンプル `x` を丸め、`0` でクリップした値である。

$$
y = \max(0, \mathrm{round}(x))
$$

- コード上の代表名: `y`
- Rust の想定型: `i32` または `usize`
- 制約・不変条件: `y >= 0`
- 備考: `x` は観測できず、尤度計算では観測値 `y` の確率を使う。


### 占い応答の確率変数 `Y`

占いクエリ `S` を出したときに返る、丸め・クリップ後の整数応答を表す確率変数である。実際に観測された値は `y` と書く。

- コード上の代表名: 明示変数は未確定
- Rust の想定型: 確率変数そのものは保持せず、分布や観測値 `y` として扱う
- 制約・不変条件: `Y >= 0`
- 備考: 相互情報量や尤度では、観測前の応答を `Y`、観測後の実現値を `y` と区別する。


### 候補条件付き占い応答確率 `P(Y = y | theta, S)`

全体配置候補 `theta` が真だと仮定し、占い集合 `S` を指定したときに、応答値 `y` が返る確率である。

$$
P(Y = y \mid \theta, S)
$$

- コード上の代表名: `log_observed_probability`, `logp_by_sum_v`
- Rust の想定型: `f64`
- 制約・不変条件: `v_theta(S)` と `|S|` が決まれば分布が決まる
- 備考: 実装では確率そのものではなく、対数確率として扱うことが多い。


### 予測占い応答分布 `P(Y = y | D_t, S)`

観測履歴 `D_t` 後の事後分布で候補 `theta` を混合した、占い集合 `S` に対する観測前の応答分布である。

$$
P(Y = y \mid \mathcal{D}_t, S)
=
\sum_{\theta \in \Theta}
P(\theta \mid \mathcal{D}_t)
P(Y = y \mid \theta, S)
$$

- コード上の代表名: `pred_y`
- Rust の想定型: `Vec<f64>`
- 備考: 相互情報量 `I(theta; Y | D_t, S)` の計算で使う。


### 観測履歴 `D_t`

`t` 回目までの占いクエリと応答値の履歴である。

$$
\mathcal{D}_t = \{(S_r, y_r)\}_{r=1}^{t}
$$

- コード上の代表名: `observations`, `history`
- Rust の想定型: `Vec<(Mask, i32)>` または `Vec<(Vec<(usize, usize)>, i32)>`
- 備考: 現在の実装では履歴を明示保存せず、候補ごとの `logw` に畳み込んでいる。


### 回答操作 `a d ...`

`v(i,j) > 0` と判断したマス集合を出力し、正誤応答を受け取る操作である。

- コード上の代表名: `answer`, `Answer`
- Rust の想定型: 出力操作または enum variant は未確定
- 指定マス数の代表名: `answer_size`, `d`
- 制約・不変条件: 座標重複なし、掘削で石油ありと判明済みのマスをすべて含む
- 応答: 正解なら `1`、不正解なら `0`
- 備考: `1` が返ったら即座に実行を終了する。


## スコア

### 支払ったコスト総和 `C`

終了までに支払った操作コストの総和である。

- コード上の代表名: `cost`, `total_cost`
- Rust の想定型: `f64`
- 制約・不変条件: 掘削は `1`、占いは `1 / sqrt(|S|)`、不正解の回答は `1`
- 備考: 公式 scorer では正解回答自体にはコストが発生しない。


### 占い集合のコスト `cost(S)`

占いクエリで集合 `S` を指定したときに支払う操作コストである。

$$
\mathrm{cost}(S) = \frac{1}{\sqrt{|S|}}
$$

- コード上の代表名: `query_cost`, `survey_cost`
- Rust の想定型: `f64`
- 制約・不変条件: 占いクエリでは `2 <= |S| <= N^2`
- 備考: 掘削クエリ `q 1 i j` のコストは `1` なので、この記号は主に `|S| >= 2` の占い集合に対して使う。


### 絶対スコア

全特定できた場合に得られるテストケースごとの絶対スコアである。小さいほど良い。

$$
\mathrm{absolute\_score} = \mathrm{round}(10^6 \times \max(C, 1/N))
$$

- コード上の代表名: `absolute_score`
- Rust の想定型: `i64` または `usize`
- 失敗時: 指定操作回数以内に全特定できなかった場合は `10^9`


### 相対評価スコア

各テストケースで、自身の絶対スコアを全参加者中の最小絶対スコアで割って計算されるスコアである。

$$
\mathrm{relative\_score} = \mathrm{round}\left(10^9 \times \frac{\mathrm{own\_absolute\_score}}{\mathrm{best\_absolute\_score}}\right)
$$

- コード上の代表名: `relative_score`
- Rust の想定型: `i64` または `usize`
- 備考: 提出の得点はテストケースごとの相対評価スコアの和である。


## 入力生成方法の記号

### 乱数関数 `rand(L,U)`

`L` 以上 `U` 以下の整数値を一様ランダムに生成する関数である。

- コード上の代表名: `rand`
- Rust の想定型: 公式 generator 側の実装に依存
- 制約・不変条件: 両端を含む整数一様乱数


### 形状生成パラメータ `a`, `d`

油田形状のサイズばらつきを決める入力生成用パラメータである。解答プログラムには直接与えられない。

$$
a = \left\lfloor \frac{\mathrm{rand}(\lfloor N^2/5 \rfloor, \lfloor N^2/2 \rfloor)}{M} \right\rfloor
$$

$$
d = \mathrm{rand}(0, a - 4)
$$

- コード上の代表名: `gen_a`, `gen_d`
- Rust の想定型: `usize`
- 備考: ここでの `d` は、油田面積 `d_k` やクエリの指定マス数 `d` とは別物である。


### 生成時の油田サイズ `s_k`

入力生成時に選ばれる `k` 番目の油田形状のマス数である。

- コード上の代表名: `shape_size`
- Rust の想定型: `usize`
- 制約・不変条件: `s_k = rand(a - d, a + d)`
- 備考: 生成後の入力では油田面積 `d_k` として現れる。
