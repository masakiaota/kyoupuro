# 記号一覧

このファイルは、問題で使う記号とコード上の代表名・型・制約の正本である。解法考察や仮説は含めない。

## 固定サイズ

### グリッドサイズ `N`

30x30 頂点のグリッドの一辺の頂点数を表す。

- コード上の代表名: `N`, `GRID_SIZE`, `n`
- Rust の想定型: `usize`
- 制約・不変条件: `N = 30`
- 備考: 頂点座標は `0 <= i < N`, `0 <= j < N`。

### クエリ数 `Q`

処理するクエリ数を表す。

- コード上の代表名: `Q`, `query_count`
- Rust の想定型: `usize`
- 制約・不変条件: `Q = 1000`

## 座標・頂点

### 頂点 `(i,j)`

一番左上を `(0,0)` とし、下方向に `i` 回、右方向に `j` 回移動した頂点を表す。

- コード上の代表名: `pos`, `Point { i, j }`, `(usize, usize)`
- Rust の想定型: `(usize, usize)` または専用 `struct`
- 制約・不変条件: `0 <= i < 30`, `0 <= j < 30`

### 始点 `s_k=(si_k,sj_k)`

`k` 番目のクエリで与えられる始点。

- コード上の代表名: `s`, `si`, `sj`
- Rust の想定型: `(usize, usize)`
- 制約・不変条件: 全頂点から一様ランダムに選ばれる。`t_k` とのマンハッタン距離は10以上。

### 終点 `t_k=(ti_k,tj_k)`

`k` 番目のクエリで与えられる終点。

- コード上の代表名: `t`, `ti`, `tj`
- Rust の想定型: `(usize, usize)`
- 制約・不変条件: 全頂点から一様ランダムに選ばれる。`s_k` とのマンハッタン距離は10以上。

## 辺・長さ

### 横辺長 `h_i,j`

頂点 `(i,j)` と `(i,j+1)` を結ぶ無向辺の長さ。

- コード上の代表名: `h`
- Rust の想定型: `[[i64; 29]; 30]` または `Vec<Vec<i64>>`
- 制約・不変条件: `0 <= i < 30`, `0 <= j < 29`
- 備考: ローカルテスト入力では最初の30行に各行29個で与えられる。

### 縦辺長 `v_i,j`

頂点 `(i,j)` と `(i+1,j)` を結ぶ無向辺の長さ。

- コード上の代表名: `v`
- Rust の想定型: `[[i64; 30]; 29]` または `Vec<Vec<i64>>`
- 制約・不変条件: `0 <= i < 29`, `0 <= j < 30`
- 備考: ローカルテスト入力では `h` の後の29行に各行30個で与えられる。

### パラメータ `D`

辺長生成時のゆらぎ幅に関わるパラメータ。

- コード上の代表名: `d`
- Rust の想定型: `i64`
- 制約・不変条件: `100 <= D <= 2000`

### パラメータ `M`

行・列ごとの基準値が1区間か2区間かを表すパラメータ。

- コード上の代表名: `m`
- Rust の想定型: `usize`
- 制約・不変条件: `M in {1, 2}`

### 横辺の基準値 `H_i,p`

横辺長 `h_i,j` の生成に使う行 `i`・区間 `p` の基準値。

- コード上の代表名: `h_base`
- Rust の想定型: `i64`
- 制約・不変条件: `0 <= i < 30`, `0 <= p < M`, `1000 + D <= H_i,p <= 9000 - D`

### 横辺の基準値推定 $\hat{H}_{i,p}$

横辺長 `h_i,j` の生成元である行 `i`・区間 `p` の基準値 `H_i,p` に対する推定値。

- コード上の代表名: `estimated_h_base`
- Rust の想定型: `[[f64; 2]; 30]`
- 制約・不変条件: `0 <= i < 30`, `0 <= p < 2`
- 備考: `M=1` の場合は通常 `p=0` のみを有効に扱う。`M=2` の場合は分割位置 `x_i` によって各横辺がどちらの区間に属するかを決める。

### 縦辺の基準値 `V_j,p`

縦辺長 `v_i,j` の生成に使う列 `j`・区間 `p` の基準値。

- コード上の代表名: `v_base`
- Rust の想定型: `i64`
- 制約・不変条件: `0 <= j < 30`, `0 <= p < M`, `1000 + D <= V_j,p <= 9000 - D`

### 縦辺の基準値推定 $\hat{V}_{j,p}$

縦辺長 `v_i,j` の生成元である列 `j`・区間 `p` の基準値 `V_j,p` に対する推定値。

- コード上の代表名: `estimated_v_base`
- Rust の想定型: `[[f64; 2]; 30]`
- 制約・不変条件: `0 <= j < 30`, `0 <= p < 2`
- 備考: `M=1` の場合は通常 `p=0` のみを有効に扱う。`M=2` の場合は分割位置 `y_j` によって各縦辺がどちらの区間に属するかを決める。

### 横辺のノイズ `delta_i,j`

横辺長 `h_i,j` の生成に使う独立な乱数値。

- コード上の代表名: `delta`
- Rust の想定型: `i64`
- 制約・不変条件: `-D <= delta_i,j <= D`

### 縦辺のノイズ `gamma_i,j`

縦辺長 `v_i,j` の生成に使う独立な乱数値。

- コード上の代表名: `gamma`
- Rust の想定型: `i64`
- 制約・不変条件: `-D <= gamma_i,j <= D`

### 横辺の分割位置 `x_i`

`M=2` のとき、行 `i` の横辺基準値を切り替える位置。

- コード上の代表名: `x`
- Rust の想定型: `usize`
- 制約・不変条件: `1 <= x_i <= 28`

### 縦辺の分割位置 `y_j`

`M=2` のとき、列 `j` の縦辺基準値を切り替える位置。

- コード上の代表名: `y`
- Rust の想定型: `usize`
- 制約・不変条件: `1 <= y_j <= 28`

## クエリ・出力

### パス `P_k`

`k` 番目のクエリで出力する `s_k` から `t_k` へのパス。

- コード上の代表名: `path`
- Rust の想定型: `String` または `Vec<char>`
- 制約・不変条件: 文字は `U`, `D`, `L`, `R`。同じ頂点を複数回通らず、30x30の外へ出ず、`s_k` から `t_k` に到達する必要がある。

### 移動文字 `U`, `D`, `L`, `R`

隣接頂点への移動を表す。

- コード上の代表名: `dir`, `Direction`
- Rust の想定型: `char` または `enum`
- 制約・不変条件:
  - `U`: `(i,j) -> (i-1,j)`
  - `D`: `(i,j) -> (i+1,j)`
  - `L`: `(i,j) -> (i,j-1)`
  - `R`: `(i,j) -> (i,j+1)`

### 実パス長 `b_k`

出力されたパス `P_k` の真の辺長合計。

- コード上の代表名: `b`, `path_len`
- Rust の想定型: `i64`
- 制約・不変条件: ジャッジが真の `h`, `v` から計算する。

### 最短路長 `a_k`

`k` 番目のクエリに対する真の最短路長。

- コード上の代表名: `a`, `shortest`
- Rust の想定型: `i64`
- 制約・不変条件: ローカルテスト入力では各クエリ行に含まれる。通常ジャッジの標準入力では与えられない。

### ノイズ `e_k`

ジャッジが返す観測値に掛ける一様乱数。

- コード上の代表名: `e`
- Rust の想定型: `f64`
- 制約・不変条件: `0.9 <= e_k <= 1.1`

### 観測結果 `round(b_k * e_k)`

パス出力後に標準入力から与えられる整数値。

- コード上の代表名: `prev_result`, `observed`
- Rust の想定型: `i64`
- 制約・不変条件: 次クエリの処理前に読み込む必要がある。

## スコア

### クエリごとの比 `a_k / b_k`

最短路長に対する出力パス長の良さを表す比。

- コード上の代表名: `ratio`
- Rust の想定型: `f64`
- 制約・不変条件: 有効なパスなら `0 < a_k <= b_k`

### テストケース得点

1テストケースに対するスコア。

- コード上の代表名: `score`
- Rust の想定型: `i64` または `f64` の累積後に丸め
- 定義:

```text
round(2312311 * sum_{k=1}^{1000} 0.998^{1000-k} * a_k / b_k)
```

## ローカルテスト入力

ローカルテスト用入力は、真の横辺長 `h`、真の縦辺長 `v`、1000個のクエリ情報からなる。

```text
h_0,0 ... h_0,28
...
h_29,0 ... h_29,28
v_0,0 ... v_0,29
...
v_28,0 ... v_28,29
si_1 sj_1 ti_1 tj_1 a_1 e_1
...
si_1000 sj_1000 ti_1000 tj_1000 a_1000 e_1000
```
