# 記号一覧

このファイルは、問題で使う記号と、実装・会話で使う代表名・型・制約の正本である。

## notation 方針

- 公式記号名は保持する。公式が `n`, `m` なら `n`, `m` と書く (本問題は小文字で固定)。
- 問題文は 1-based だが、実装・議論では原則 0-based の `b[i,j]` 形式に直す。1-based と 0-based の対応はそれぞれの節に明記する。
- 問題文にない実装用の状態量は、`top[i]`, `pos[v]` のようにコードとの対応が見える名前にする。
- TeX は総和、比例、条件など構造だけに使い、コードフェンスには入れない。
- 解法考察や仮説は混ぜない。状態量・添字・型・不変条件だけを書く。

## 固定サイズ

### 箱の総数 `n`

倉庫にあるダンボール箱の総数を表す。

- 議論用 notation: `n`
- コード上の代表名: `N`, `n`
- Rust 型: `usize`
- index 範囲・不変条件: 全テストケースで `n = 200` 固定。箱の番号 `v` は `1 <= v <= n` (議論用)、実装では 0-based `0 <= v < n` に直してよい。

### 山の本数 `m`

箱を積み分ける山の本数を表す。

- 議論用 notation: `m`
- コード上の代表名: `M`, `m`
- Rust 型: `usize`
- index 範囲・不変条件: 全テストケースで `m = 10` 固定。山番号は問題文では `1 <= i <= m`、実装では `0 <= i < m`。

### 山の初期高さ `n/m`

各山が初期状態で持つ箱の個数を表す。

- 議論用 notation: `n/m`
- コード上の代表名: `H0`, `per_pile`
- Rust 型: `usize`
- index 範囲・不変条件: 本問題では `n/m = 20` 固定。`m` が `n` を割り切る前提が問題文で保証されている。

## 入力

### 初期配置 `b[i,j]`

山 `i` の下から `j` 番目に積まれている箱の番号を表す。

- 議論用 notation: 問題文どおり `b[i,j]` (1-based)。実装では 0-based の `b[i,j]` に直す。
- コード上の代表名: `b`, `init_piles`
- Rust 型: `Vec<Vec<usize>>` (外側 `m` 本、内側は初期 `n/m` 個)
- index 範囲・不変条件: 問題文では `1 <= i <= m`, `1 <= j <= n/m`、実装では `0 <= i < m`, `0 <= j < h[i]`。`b[i,j]` は `1,…,n` の置換 (実装では `0,…,n-1` に対応させてよい)。
- 備考: 「下から `j` 番目」が増える順序に積まれている。山の一番上は `j = h[i]` (問題文) または `j = h[i] - 1` (実装)。

## 動的状態

### 現在の山 `pile[i]`

操作によって変化する各山の現在の積み状態を表す。

- 議論用 notation: 現在の山 `i` を下から順に `b[i,1], …, b[i,h[i]]` と書く (問題文の表記をそのまま使う)。
- コード上の代表名: `pile`, `piles`, `stacks`
- Rust 型: `Vec<Vec<usize>>` または `[Vec<usize>; M]`
- index 範囲・不変条件: `0 <= i < m`。空の山も許される (操作2で全て運び出された後、操作1の移動先として再利用可)。

### 山の高さ `h[i]`

山 `i` に現在積まれている箱の個数を表す。

- 議論用 notation: 問題文では `h` (移動先) と `h'` (移動元) のように個別に書かれる。汎用には `h[i]` を使う。
- コード上の代表名: `h`, `pile_len`, `piles[i].len()`
- Rust 型: `usize`
- index 範囲・不変条件: `0 <= h[i] <= n`。合計 `sum_i h[i]` は残っている箱の個数に等しい。

### 箱の位置 `pos[v]`

箱 `v` が現在どの山のどの高さ位置にあるかを表す実装用状態。

- 議論用 notation: `pos[v] = (i, j)` ただし `j` は下から数えた位置 (0-based) とする。運び出された箱は `pos[v] = None` などで表現する。
- コード上の代表名: `pos`, `where_box`
- Rust 型: `Vec<Option<(usize, usize)>>` または `Vec<(u8, u8)>` + 別フラグ
- index 範囲・不変条件: `0 <= v < n` (実装上の 0-based 番号)。`pile[i][j] == v` と同期する。
- 備考: 問題文にはない実装側の補助状態。操作1で動いた箱、操作2で運び出された箱に対し正しく更新する。

### 次に運び出すべき箱 `next_v`

操作2で次に運び出される対象の箱番号を表す。

- 議論用 notation: `next_v`
- コード上の代表名: `next_v`, `target`, `removed_count`
- Rust 型: `usize`
- index 範囲・不変条件: 残っている全ての箱の最小番号。問題文では `1` から開始し、運び出すたびに `+1`。実装で 0-based なら `0` から開始する。

## 操作

### 操作1 (移動)

箱 `v` とその上にある全箱をまとめて別の山に移す操作を表す。

- 議論用 notation: `op_move(v, i)`、移動先の山 `i` に対し問題文では `1 <= i <= m`、実装では `0 <= i < m`。
- 出力形式: `(v_k, i_k) = (v, i)` で `1 <= i <= m`。
- 移動個数: `k = h' - j + 1`。すなわち `pos[v] = (i', j)` のとき `k = h[i'] - j + 1` (問題文 1-based) または `k = h[i'] - j` (実装 0-based)。
- 消費体力: `k + 1`。`i = i'` の場合は何も起こらず体力だけ消費する。

### 操作2 (運び出し)

最小番号の箱が山頂にあるとき、それを倉庫外に運び出す操作を表す。

- 議論用 notation: `op_carry(v)`
- 出力形式: `(v_k, i_k) = (v, 0)`。
- 前提: `v = next_v` かつ `v` が現在いる山の一番上にあること。
- 消費体力: `0`。

## スコア・操作数

### 操作回数 `K`

最終的に出力する操作の総数を表す。

- 議論用 notation: `K`
- コード上の代表名: `K`, `ops.len()`
- Rust 型: `usize`
- index 範囲・不変条件: `K <= 5000`。超過した場合は WA。

### 合計体力消費量 `V`

全操作1の `k + 1` の総和を表す。操作2は寄与しない。

- 議論用 notation: `V`
- コード上の代表名: `V`, `total_cost`, `score_cost`
- Rust 型: `i64` または `u64`
- index 範囲・不変条件: `V >= 0`。

### テストケース得点

1 ケースあたりの得点。

$$
score = \max(1,\, 10000 - V)
$$

提出スコアは 150 ケースの総和。
