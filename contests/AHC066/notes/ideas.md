# 改善アイデアメモ

## 読み方

このメモは、`src/bin/*.rs` にある解法実験を、後から見返しやすいように並べたものである。
各 version はなるべくフラットに扱い、優先順位ではなく「その実験で何を試したか」「結果として何が見えたか」を記録する。

`total_sum` は `results/score_summary.csv` 上の `tools/in` 100 ケース手元ベストである。

## 主要部品の用語

| 部品 | 内容 |
|---|---|
| 距離貪欲 basic route | 現在位置から `ball[k]`、さらに `basket[k]` へ行く距離が短い `k` を順に処理する基本ルート。macro を使わずに片付けを成立させる土台である。 |
| 複数 macro DP 圧縮 | すでに作った basic ops を見て、得しそうな区間を `M ... M` で登録し、後続の同一区間を `P` に置換する後処理圧縮である。配送順や移動経路自体は変えない。 |
| 単一 `q` の `MacroGraph` | `F/R/L` だけからなる movement macro `q` を1つ仮定し、通常操作に加えて「`q` を登録する」「`P` で再生する」を graph の辺として扱う。`P` を移動の cheap edge として経路探索に入れる。 |
| `q` 候補生成 | `F/R/L` の短い列、basic route に頻出する移動断片、手書きの曲がり付き長距離パターンなどから movement macro 候補を作る。 |
| 配送順探索 | どのボールを先に片付けるかを変える探索。greedy、beam、SA などが試されている。 |
| macro 自己複製 | `MPPM` 相当の操作で、登録済み macro を再生しながら新しい macro にも記録し、`q` から `q^2`, `q^4` のような効果を作る考え方である。 |
| post-recompress | 一度作った最終 button 列を basic ops に展開し直し、その basic ops に対して改めて複数 macro DP 圧縮をかける後処理である。 |

## 経験的にスコア寄与が観測された要素

以下は、上の実験群でスコア改善として観測された要素である。採用を指示する方針ではなく、次の実験を考えるときの材料として扱う。

- `P` を単なる後処理圧縮ではなく、移動 graph の 1 button edge として扱うこと。
- `F/R/L` movement macro の候補順を入力ごとに評価し、良さそうな候補を早く試すこと。
- `q` を1つに即決せず、greedy 結果の良い複数候補を pool に残すこと。
- 配送順は距離貪欲だけでなく、macro graph 上のコストを使って SA で入れ替えること。
- SA 対象の `q` を長さ・turn 数・最大連続 `F` で少し多様化すること。
- `MPPM` 相当の自己複製を使い、短い `q` から長い移動効果を作ること。
- 最終解を basic ops に展開してから再圧縮する後処理は、小幅な改善を生むことがある。

## 補助実装メモ

- `P` 高速化:
  - `F/R/L` だけの macro は、登録時に全開始姿勢 `(cell, dir)` への effect を持てる。
  - 状態数は最大 `400 * 4 = 1600` なので、`effect[state] -> state` は軽い。
  - power macro では `effect[level][state] = effect[level-1][effect[level-1][state]]` として倍化できる。
- 検証:
  - ローカル評価は必ず `--features local` 付き。
  - 最終採用候補は `simulate_buttons` で `V=M` を確認してから出力する。
  - 時間判定は必ず `main()` 開始直後の `Timer` 基準で行う。
