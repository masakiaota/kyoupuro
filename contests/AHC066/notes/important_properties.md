# Important Properties

このファイルは、問題の重要な性質を整理する場所である。記号の定義・代表名・型・制約は `notes/notations.md` を参照し、ここでは性質そのものだけを書く。

## 1. 展開前操作列優先原理

### 主張
`V=M` を達成した後のスコアは、展開前の出力操作列長 `A` だけで決まる。

したがって、`expanded_count` は `T` を超えないための制約であり、最小化対象ではない。短い基本操作列を先に作って後処理で圧縮する設計は、目的関数がずれているためスコアが良くなりにくい。

### なぜ成り立つか
絶対スコアの定義では、`V=M` の場合のスコアは `A` である。マクロ展開後の基本操作数は、成功可否には影響するが、成功後のスコア式には現れない。

短い基本操作列が、短い `A` に圧縮しやすいとは限らない。むしろ、基本操作列を先に固定すると、マクロに乗りやすい構造を捨てる傾向があるためスコアが悪化することが経験的にわかっている。

### 実装上どう効くか
探索・経路選択・配送順選択では、展開後の基本操作数ではなく、`M` と `P` を含めた `A` を直接評価する。

## 2. マクロ累乗性

### 主張
`last_macro` がある基本操作列を表しているとき、記録中に `P` を押すと、`P` というボタンそのものではなく、再生された基本操作列が `recording_macro` に追加される。

そのため、`MPPM` を実行すると、現在の `last_macro` を2回連続で実行しつつ、その2回分を新しい `last_macro` として登録できる。これにより、登録済みマクロの効果を `1倍 -> 2倍 -> 4倍 -> 8倍 ...` のように増やせる。

### なぜ成り立つか
問題文の仕様では、マクロ記録中に `P` を押した場合、最後に登録済みのマクロが再生される。このとき、現在記録中のマクロに追加されるのは `P` ではなく、実際に再生された基本操作列である。

したがって、`last_macro` がある基本操作列を表す状態で `MPPM` を実行すると、新しい `last_macro` は元の `last_macro` を2回並べたものになる。

### 実装上どう効くか
短い movement macro を一度登録できれば、`MPPM` によってより長い移動 primitive に育てられる。たとえば短い直進や曲がり付き移動でも、累乗後は `P` 1回で長い移動効果を持つ。

探索 graph では、`last_macro` の累乗段階を状態に持たせるとよい。通常の `P` は現在段階の macro を1 buttonで適用する辺、`MPPM` は4 buttonで次の累乗段階へ進む辺として扱える。

## 3. マクロ合成登録性

### 主張
新しいマクロを登録するとき、登録済みの `last_macro` を部品として使える。

登録したい基本操作列の中に、現在の `last_macro` と同じ断片が含まれるなら、その断片は記録中の `P` で書ける。たとえば `last_macro` が `x` を表しているとき、新しく登録したい列が

```text
a x b x c
```

なら、直接

```text
M a x b x c M
```

と登録する代わりに、

```text
M a P b P c M
```

と登録できる。新しく登録される `last_macro` は `aPbPc` ではなく、`P` が展開された後の `a x b x c` である。

### なぜ成り立つか
問題文の仕様では、マクロ記録中に `P` を押すと、最後に登録済みのマクロが再生される。このとき、記録中のマクロに追加されるのは `P` というボタンではなく、実際に再生された基本操作列である。

したがって、記録中の `P` は「既存の `last_macro` を新しいマクロの中へ貼り付ける操作」として扱える。

たとえば、次のマクロを作りたいとする。

```text
FFLFFFFRFFFFFR
```

まず

```text
MFFFFRM
```

で `last_macro = FFFFR` を作っておく。その後、

```text
MFFLPFPM
```

と登録すると、記録される基本操作列は次のようになる。

```text
FFL + FFFFR + F + FFFFR
= FFLFFFFRFFFFFR
```

直接 `MFFLFFFFRFFFFFRM` と書くより、既存マクロを部品にした方が短くなる場合がある。

### 実装上どう効くか
`last_macro` がすでにあるなら、新しく作りたいマクロ中に現れる `last_macro` の各出現を `P` 1 button に置き換えられる。断片の長さを `L` とすると、1 出現あたり `L-1` button だけ登録操作列を短くできる。

ただし、その断片を使うためだけに先に `last_macro` を登録するなら、最初の登録コスト `M ... M` も必要である。部品として何回現れるか、作ったマクロをその後どれだけ使うか、登録中に実行される基本操作が現在の `cell` と `dir` にどう影響するかを合わせて見る必要がある。

`マクロ累乗性` は、既存の `last_macro` を2回貼り付けて `x x` を作る特殊な合成登録と見なせる。

## 4. 移動マクロの盤面非依存性

### 主張
`F/R/L` だけからなるマクロは、開始時の `cell` と `dir`、および壁配置だけで実行後の `cell` と `dir` が決まる。
手持ちのボール、盤面上のボール配置、どの種類を処理済みかには依存しない。

### なぜ成り立つか
`F` は壁に当たれば同じ `cell` に留まり、進めるなら隣接 `cell` へ移動する。これは `next_cell[cell,dir]` だけで決まる。

`R` と `L` は `dir` だけを変える。どちらもボールやかごや手持ちには触れない。したがって、`F/R/L` だけのマクロを実行しても、変わるのはロボットの `cell` と `dir` だけである。

### 実装上どう効くか
マクロが1つ決まったら、全姿勢 `4*N*N` 個について、実行後の姿勢を前計算できる。

```text
effect[cell,dir] = マクロ実行後の (cell',dir')
```

コード上は、たとえば次のような表にできる。

```text
effect[cell * 4 + dir] = cell' * 4 + dir'
```

これにより、マクロ再生 `P` の効果を毎回マクロ長ぶんシミュレーションせず、表引き1回で適用できる。

マクロ長を `L` とすると、前計算コストはおおよそ `4*N*N*L` である。一方、前計算しない場合、同じマクロの効果を1回参照するたびに `L` かかる。したがって、同じマクロの効果を `4*N*N` 回より多く参照するなら、前計算する方が効率的である。

この性質により、`F/R/L` だけのマクロは探索 graph の遷移として扱いやすい。`S` を含むマクロでは、手持ちや盤面上のボール配置に依存するため、同じ `cell` と `dir` から始めても効果が一意に決まらない。

## 5. マクロ償却性

### 主張
マクロ登録には `M ... M` の2 button と中身の基本操作列ぶんの button が必要だが、登録後の再生 `P` は1 button で済む。したがって、マクロは登録時に先払いし、複数回の `P` でその登録コストを回収する仕組みである。候補評価では、登録コストだけでなく、その後に何回使えるかを見る必要がある。

## 6. 回転正規性

### 主張
連続する回転操作だけを見ると、`R` と `L` は `dir` を 4 周期で変えるだけであり、同じ最終 `dir` になる短い回転列へ置き換えられる。

代表例:

```text
RL   == 空列
LR   == 空列
RRRR == 空列
LLLL == 空列
RR   == LL
RRR  == L
LLL  == R
```

### なぜ成り立つか
`R` は `dir` を `+1`、`L` は `dir` を `-1` する操作である。方向は 4 通りなので、回転列の効果は合計回転量を 4 で割った余りだけで決まる。

回転操作は `cell`、手持ち、盤面上のボール配置を変えない。したがって、同じ合計回転量を持つ回転列は、任意の状態で同じ効果になる。

### 実装上どう効くか
`F/R/L` だけのマクロ候補を生成するとき、無意味な回転の打ち消しを含む候補は、同じ効果でより短い候補に置き換えられる。

たとえば `FRLF` は途中の `RL` が空列と同じなので、`FF` と同じ移動効果を持つ。登録コストは短い方が小さいため、このような候補は短い表現だけ残せばよい。

## 7. 直進飽和性

### 主張
同じ方向へ連続して進む `F` の列は、長さ `N-1` で移動効果が飽和する。

したがって、任意の開始姿勢について次が成り立つ。

```text
F^(N-1) == F^N == F^(N+1) == ...
```

### なぜ成り立つか
`N x N` 盤面では、壁がまったくない場合でも、同じ方向に実際に進めるマス数は最大 `N-1` である。

外周または内部壁に当たった後の `F` は、同じ `cell` に留まるだけである。内部壁がある場合は、`N-1` より短い回数で飽和することもある。

### 実装上どう効くか
`F/R/L` だけのマクロ候補を扱うとき、連続する `F` run は長さ `N-1` まで短縮しても移動効果が変わらない。

たとえば `N=20` なら、連続する `F` は19個まで見ればよい。20個以上の連続 `F` は、同じ向きの直進 run としては冗長である。

途中に `R` や `L` が入る場合は向きが変わるため、別の直進 run として扱う。

## 8. 移動マクロ候補の経験的な生成形

### 主張
`F/R/L` だけからなる移動マクロ候補は、経験的には次の形を優先して生成するとよい。

```text
^F*(?:LL|R|L)(?:F+(?:R|L))*F*$
```

これは、次のように分解できる。

```text
F^a0 c0 F^a1 c1 ... F^a{k-1} c{k-1} F^ak
```

| 要素 | 範囲 | 意味 |
|---|---:|---|
| `k` | `k >= 1` | 曲がりの個数 |
| `a0` | `a0 >= 0` | 最初の曲がり前の `F` 数 |
| `a1..a{k-1}` | `>= 1` | 曲がり間の `F` 数 |
| `ak` | `ak >= 0` | 最後の曲がり後の `F` 数 |
| `c0` | `L`, `R`, `LL` | 最初の曲がり |
| `c1..c{k-1}` | `L`, `R` | 途中の曲がり |

列挙時は、`k` の最大値、各 `a_i` の最大値、全体長の最大値を決めればよい。各 `k` について、曲がり方は `3 * 2^(k-1)` 通り、`F` 数は端を `0` 以上、途中を `1` 以上として列挙する。

経験的には、次の範囲で十分な候補を含むことが多かった。

| パラメータ | 目安 |
|---|---:|
| 全体長 | `5 <= len <= 24` |
| 曲がり個数 | `k <= 6` |
| 各 `F` run | `a_i <= 10` |

短すぎる移動マクロは登録コストに見合いにくく、経験的には有望な候補はおおむね5文字以上だった。ただし、この範囲でも候補数は膨大になる。そのため、全列挙した候補をすべて詳細評価するのではなく、cheap score や sampling によって greedy 評価・SA 評価へ回す候補を絞る必要がある。

### 背景
`回転正規性` から、`RL` / `LR` のような連続回転は冗長になりやすい。また、途中の `LL` / `RR` は SA 込み分析では強い macro として頻出しなかった。

一方で、先頭の `LL` は初期向きから逆方向へ入る初動として働く可能性がある。そのため、先頭だけ `LL` を許し、途中は単発の `L/R` に限定する。

### 実装上どう効くか
`{F,L,R}^len` を直接列挙するのではなく、上の分解に従って `k`, `a_i`, `c_i` を列挙する。

これにより、実験上あまり強くない形を生成段階で減らし、同じ時間内で greedy 評価や SA 評価に回る候補の密度を上げられる可能性がある。

### 注意
これは厳密な最適性の主張ではなく、val1 の分析から得た経験則である。入力全体に対して常に成り立つとは限らない。
