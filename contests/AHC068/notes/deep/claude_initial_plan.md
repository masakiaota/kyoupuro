## 1. スコア構造からの大前提

- E = 0 は絶対条件。E > 0 だと最大 399 点、E = 0 なら T = 10^5 でも 400 点 + log 項。揃えきれない賢い解は必ず揃う愚直な解に常に負ける。
- E = 0 のとき score = 400 + 10^6 * log_2(10^5 / T)。T 半減ごとに +10^6 点/ケース、150 ケースで +1.5 億点。T=1000→500 と 500→250 の改善が等価値なので、終盤の数十手削りまで一貫して価値がある。
- 参考値(1 ケース): T=3125 → 5.00M、T=1600 → 5.97M、T=800 → 6.97M、T=400 → 7.97M、T=200 → 8.97M。
- 情報理論下界 ≈ 190 手。導出: 壁なしの操作種数は、縦が (r,h) 100 通り × (c,w) 210 通り = 21,000、横も対称に 21,000、計 42,000 ≈ 2^15.36。順列の情報量 log_2(400!) ≈ 2886 bit。2886 / 15.36 ≈ 188。各操作が独立に最大情報を運ぶ仮定なので到達不能だが、200 台なら世界水準、400 で上出来、1000 は中位、3000 は素朴解、というスケール感を与える。
- TLE・不正出力は提出全体 WA。150 ケース全てで 2 秒厳守。時間管理は PROGRAM_TIME_LIMIT_SEC 比で行う(AGENTS.md)。
- AGENTS.md は「保険のための fallback 分岐」を許可制としている。E=0 保証は fallback 分岐ではなく、「必ず完了するアルゴリズム構成」(終盤ソルバが引き取る設計)で満たすこと。

## 2. 操作の構造観察(導出付き)

### (a) 対合性 [OBS-C1]
どの操作も同じ操作を 2 回適用すると恒等。よって (i) 逆再生が自明(完成→初期の操作列を逆順に読むだけ)、(ii) 完成盤面に k 回ランダム操作を適用すると「k 手で確実に解ける盤面」を任意生成できる。これは評価関数の較正装置(E3)の基礎。

### (b) 可解性とパリティ [OBS-C2]
h=1, w=2 の横操作は隣接互換そのもの。全マス連結保証より、壁のない隣接互換の集合は全対称群 S_400 を生成する(連結グラフ上の隣接互換は全対称群を生成する標準事実)。よって E=0 は常に達成可能で、パリティ障害はない。

### (c) カード視点では ±h/2 の剛体シフト [OBS-C3]
縦操作 (r,c,h,w) はカードの行番号を ±h/2 だけ平行移動する(h/2 ∈ {1..10})。行差 d の行合わせは d ≤ 10 なら 1 回、11 ≤ d ≤ 19 なら 2 回。列も対称。w=1 の縦操作(1 列の上下半分交換)も合法である点が重要(条件は h 偶数のみ)。単カードの最小巻き込み輸送は w=1 / h=1 の細長操作で行える。

### (d) 補正需要の総量と実効並列度 [OBS-C4]
ランダム順列で行差の分布は P(|Δ|=0) = 1/20 = 0.05、P(|Δ|=d) = 2(20-d)/400 (d ≥ 1)。
- P(|Δ| ≥ 11) = 2(9+8+...+1)/400 = 90/400 = 0.225
- P(1 ≤ |Δ| ≤ 10) = 1 − 0.05 − 0.225 = 0.725
- 行需要の期待値 = 0.725×1 + 0.225×2 = 1.175 回/カード
両軸計 2.35 回/カード、盤面全体で約 940 補正。1 操作あたりの有効補正数(実効並列度 k)を使うと T ≈ 940/k + 干渉解消コスト。k=2 で約 470 手、k=4 で約 235 手。k の実測(E2)が方針選定の分水嶺。
また平均マンハッタン距離は E[|Δ|] = (N²−1)/(3N) = 399/60 = 6.65 で、初期総距離 ≈ 400 × 13.3 ≈ 5320。1×2 操作の距離減は最大 2/手なので、細かい操作に退化した貪欲は T ≈ 2700–3000 に張り付くと予想。

### (e) 軸の直交性とその限界 [OBS-C8] — 本問題の最重要構造(仮説)
縦操作はカードの列座標を変えず、横操作は行座標を変えない。よって:
- 行一致数(pos.row == target.row のカード数)は縦操作のみで変化し、横操作では不変。
- 列一致数は横操作のみで変化し、縦操作では不変。
- 評価関数を (行需要, 列需要) に分離すると、各操作は片側しか壊せない。フェーズ分割・評価分離の根拠になる。
ただし限界がある: 縦操作は各列内のカード多重集合を変えない。同一列に同じ目標行を持つカードが 2 枚以上あると、縦操作だけでは行一致 400 に到達できず停滞する。したがって「行合わせフェーズ」にも列再配分のための横操作の挿入が必要。この停滞頻度と解消コストは Q-C6(E2 で実測)。

### (f) 壁はスリットが基本形 [OBS-C5]
壁は「どの壁にも接していない頂点」から一方向に伸びるので、始端が宙に浮いたスリットが基本形。部屋分割は後続の壁が既存壁・外周に届いたときのみ発生。壁の主効果は連結性破壊ではなく有効長方形の削減と予想(E0 で実測)。W = rand(0,19) なので壁 0–3 本の易ケースも一定数出る。なお W は入力に直接含まれないため、V/H から壁セグメントの連結成分数として復元する。

### (g) 有効長方形の O(1) 判定 [OBS-C6 関連]
長方形 (r,c,h,w) が有効 ⟺ 内部の V 壁数 + H 壁数 = 0。
- 内部 V 壁数 = Σ_{i∈[r,r+h)} Σ_{j∈[c,c+w-1)} V[i][j]
- 内部 H 壁数 = Σ_{i∈[r,r+h-1)} Σ_{j∈[c,c+w)} H[i][j]
V, H それぞれの 2D 累積和を前計算すれば O(1)。壁は不変なので前計算は 1 回。42,000 候補の全列挙も一瞬で、探索のボトルネックにならない。

### (h) 巻き込みゼロの一般互換は 3 手
任意の 2 枚 p, q の交換(他のカードは全て元の位置)は、共役 g·s·g で作れる: g = p を q と同列(または同行)に運ぶ細長操作、s = 同列の 2 枚交換(w=1 縦操作、ただし行差 1 でなければ間のカードを巻き込むので、s も隣接になるよう g を選ぶ)。g は対合なので戻しは g 自身。壁が許せば 3 手・巻き込みゼロ。同列で行差 δ の 2 枚は w=1, h=2δ の縦操作 1 手で交換できるが、間の 2(δ−1) 枚を巻き込む(δ=1 なら巻き込みゼロ)。終盤ソルバ(P5)の基礎パターン。

## 3. 部分問題の仕様

### P1. 盤面幾何の前処理
- 入力: V[i][j], H[i][j]。出力: (i) 2D 累積和 2 本、(ii) 有効長方形判定関数 valid(r,c,h,w)、(iii) 各セル対 BFS 距離表 dist[400][400](壁考慮の 4 近傍 BFS を各セルから、O(400×400))、(iv) 各セルから上下左右に壁なしで伸ばせる最大長 reach[4][i][j]。
- reach の用途: w=1, h=2δ の細長縦操作が位置 (i,j) で使えるかを O(1) で判定(列 j の区間 [i', i'+2δ) に H 壁がないこと)。列ごとの H 壁累積和でも代用可。
- 配置: v000_template.rs に確定実装として置く(更新は許可制なのでユーザーに確認)。

### P2. 単カード輸送(最短操作列)
- グラフ: 頂点 = セル 400 個。辺: セル (i,j) から、(i') 同列で区間 [min(i,i±δ)…] に壁がなければ行 ±δ へ(w=1, h=2δ 縦操作)、(ii') 同行対称(h=1, w=2δ 横操作)。辺数は頂点あたり最大 38。
- BFS で opdist[400][400](操作回数での距離)を前計算。壁なしなら対角以外ほぼ 2、|Δ|>10 で 3。
- 用途: 方針 A の運搬、マクロ手の下界見積もり h 値、終盤ソルバのコスト表。
- 確定領域保護版: 「操作が巻き込む区間に確定セルを含まない」制約を辺に付けた BFS を、確定集合が変わるたびに再計算(1 回 O(400×38)、400 回やっても軽い)。

### P3. 並列輸送スケジューリング(需要被覆)
- 需要: (card, axis, δ)。縦操作 (r,c,h,w), h=2δ がカバーする行需要 = 「上半分にいて行差 +δ」∪「下半分にいて行差 −δ」のカード。
- 操作の純益 = 解消需要数 − 新規発生需要数(行差 0 のカードを動かした等)。needs 差分は操作内のセルだけ見れば O(hw) で計算できる。
- 貪欲: 全有効操作から純益最大を選ぶ。42,000 候補 × O(hw) は 1 手あたり最大 ~10^7 セルで重め。絞り込み: δ ごとに「行差 +δ のカードの位置集合」を持ち、密度の高い矩形だけ試す、または候補を (δ, r) で束ねて c,w を走査(ヒストグラム法)で 1 手 O(N³) 程度に。
- 停滞(OBS-C8 の限界)への対処: 純益 > 0 の縦操作が無くなったら、列再配分の横操作(列needs を壊さず、目標行重複を減らすもの)を挿入。

### P4. 干渉管理の 2 モード
- 保護モード: 確定領域を巻き込む操作を禁止(方針 A/A')。実装が簡単、並列度を捨てる。
- 評価モード: 全操作可、評価関数で回収(方針 B/C/E)。破壊は片軸ずつ(OBS-C8)なので見かけより穏やか。

### P5. 終盤精密整列
- 状況: 非固定点(pos ≠ target のカード)が少数。残差置換をサイクル分解し、パターンで解消する。
- パターン表(壁が許す場合のコスト):
  - 同列(同行)隣接の 2 枚交換: 1 手。
  - 同列で行差 δ の 2 枚交換: 1 手(巻き込み 2(δ−1) 枚、needs を悪化させない場合のみ使用)or 3 手(共役、巻き込みゼロ)。
  - 一般位置の 2 枚交換: 3 手(共役 g·s·g)。
  - 3 サイクル: 互換 2 つ = 2–6 手。同列に 3 枚並ぶ場合は縦 2 手で解消できる形がある(実装時にパターン精査)。
- コスト目安: 非固定点 m 枚あたり 0.5–1.5 手。フェーズ切替閾値の設計(E5)に使う。
- 割当: サイクル群に対し、パターン適用順を小さなビームか DP で最適化(相互作用が薄いので貪欲でもほぼ最適のはず)。

### P6. 探索フレームワーク
- 状態: board(セル→カード)、pos(カード→セル)、needs_row/col の集計、Zobrist ハッシュ、累積操作列。
- マクロ手: 「1 需要(または 1 需要クラスタ)を解消する 1–3 操作の列」を 1 分岐単位にする。分岐数を数十に抑え、深さ = 残需要に比例させる。
- 候補生成(ターゲット駆動): 未解消需要のカードを優先度順(needs 大、密度の高い矩形に属す等)に数十枚選び、各カードに対し「その δ を消す操作」のバリエーション(w=1 最小版、純益最大の幅広版、その中間 2–3 個)を生成。
- 評価: E3 で選ぶ。第 0 候補は f2 = Σ needs(残り操作数の下界に比例)、タイブレークに f1 = Σ opdist。
- ビーム: 差分評価 O(hw)、Zobrist で同一盤面刈り。幅と分岐数は 2 秒バジェットから逆算(E4 でバジェット表を作る)。
- 時間管理: フェーズ配分を PROGRAM_TIME_LIMIT_SEC 比で指定(AGENTS.md)。

### P7. 壁適応
- 有効長方形の削減は valid() が自然に吸収する。細長操作の可否は reach で吸収。
- 真の部屋分割(稀)では、部屋間の搬送がボトルネック。E0 の統計で分割ケースの頻度を見てから、専用処理(部屋間フロー計画)を書くか決める。書かない判断もあり得る(汎用探索が吸収するなら)。

## 4. 方針の詳細設計

### 方針 A: 逐次確定ベースライン [IDEA-C1] — E=0 保険、最小工数
- 確定順: 行 0 から行 17 までは行内を左→右(各行、最後の 2 枚は 2 枚同時の定石処理)。最終 2 行(18,19)は列 0 から列 17 へ 2 枚 1 組で確定し、最後の 2×2 は専用処理。
- 運搬: P2 の保護付き BFS 経路をそのまま操作列に変換。
- 最後の 2×2: 4 枚の置換は、使える操作(2×1, 1×2, 2×2 の V/H)が生成する群の中で解けるはず(隣接互換が 2 本あれば S4 生成)。壁で操作が制限される場合は 2×2 の外を経由(確定領域を一時的に壊して戻す共役)。実装時に全 24 状態を BFS で解いて表引きにするのが確実。
- 予想 T: 900–1600(needs 合計 940 + 保護による迂回)。
- 凝らないこと。これは提出可能状態を作るための保険であり、比較のベースラインである。

### 方針 A': 行ステージング [IDEA-C2] — 中庸の受け皿
- ループ(i = 0..17): カード iN..iN+19 の 20 枚を、未確定領域(行 i..19)内で「行 i+1 に正順」で整列させ、V(r=i, c=0, h=2, w=20) 1 手で行 i を確定。w=20 が壁で無効なら c 区間を分割して複数手。
- 行 i+1 への整列はミニ並列輸送: まず各カードを正しい列へ(横操作、同じ δ をまとめる)、次に列ごとに行 i+1 へ持ち上げ(縦操作、同じ深さ δ のカードを幅方向にまとめて 1 手で)。
- 最終 2 行 40 枚は転置した定石(幅 2 の柱を列ごとに)+ 2×2 専用処理。
- 予想 T: 1 行あたり 20–40 手 × 18 行 + 最終 2 行 ≈ 500–900。
- A の部品(P2)を再利用できるので、A の後に差分実装が小さい。

### 方針 B: 距離和ビームサーチ [IDEA-C3] — 汎用骨格
- P6 のフレームをそのまま使い、マクロ手ではなく 1 操作 = 1 分岐で回す版。評価関数と候補絞りが全て。
- リスク: 評価が悪いと 1×2 連打に退化し T ≈ 2700–3000。E3 の較正で T/k ≤ 1.5 を確認してから本実装する。

### 方針 C: 需要被覆フェーズ型 [IDEA-C4] — 高リスク高リターン
- Phase R(行合わせ): P3 の貪欲被覆で行 needs → 0。停滞したら列再配分の横操作を挿入(OBS-C8 の限界)。このフェーズ中も「列 needs を無償で減らせる操作」を同点タイブレークで優先(Phase C の需要を先に削る)。
- Phase C(行内ソート): 行一致は横操作で不変なので、以後は横操作のみで安全に進められる。20 行の置換を「同じ列差 δ が縦に並ぶ」箇所を狙って複数行同時のブロックスワップで解消。並列度が 1 に落ちたら選択ソート的に。
- Phase F(残差): P5 の終盤ソルバ。
- 予想 T: 行 needs 470 / k_R + 列 needs 470 / k_C + 停滞・残差コスト。k=2 で 470 + α、k=3 で 313 + α。
- 採否は E2 の実測(k と停滞コスト)で機械的に決める。

### 方針 D: 再帰ブロック分割 [IDEA-C8] — 優先度低
- ブロック交換は「対応する位置同士」しか交換できず、象限への自由な振り分けができない。壁にも弱い。E2/E3 が全滅した場合の再検討候補としてのみ残す。

### 方針 E: ハイブリッド [IDEA-C5] — 本命、目標 T 250–400
- 骨格: [序盤] C の需要被覆貪欲(行列両 needs の純減最大、大操作優先)を小ビーム化 → [中盤] P6 のマクロ手ビーム → [終盤] P5 ソルバ。
- フェーズ切替: 残 needs 閾値(E5 でチューニング)と経過時間(PROGRAM_TIME_LIMIT_SEC 比)の早い方。
- E=0 保証: 終盤ソルバは任意の残差を必ず解消できる(OBS-C2 + P5 の一般互換 3 手)。手数上限 10^5 は needs 見積もり × 1.5 で常時監視(超えそうなら太い操作を捨て確実路線に切替 — これは fallback 分岐ではなく通常のフェーズ設計として組む)。

## 5. 実験ロードマップ(実行手順レベル)

実施順の原則: E0 → E1(保険確保)→ E2/E3(adhoc 計測、方針決定)→ E4(本命)→ E5 → E6 → E7。E2/E3 は solver を書かずに答えが出る問いを実験より先に潰すもの(AGENTS.md)。ただし E2 の probe は「操作列を構成する」ため solver 該当性が曖昧である。統計出力のみに限定して実装し、それでも実行後は AI 利用ルール準拠で報告・停止する(安全側に倒す)。
