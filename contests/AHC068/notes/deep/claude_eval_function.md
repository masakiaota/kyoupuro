# 評価関数(盤面の良さ)の設計 [IDEA-C11]

- 出自: 2026-07-18、ユーザー指摘(ビームサーチでは盤面の良さの定義が大事)を受けて Claude が設計。既存実験は未読。
- 位置づけ: 探索基盤(notes/deep/claude_beam_search_infra.md [IDEA-C10])のキュー優先度 ĥ と、E3 較正装置(notes/deep/claude_initial_plan.md)の評価対象を具体化する。E3 の候補リスト(f1, f2 等)は本文書のアブレーション表で置換する。

## 1. 原則

- E=0 前提ではスコアは総手数 T のみで決まるため、盤面 s の良さは一意に「完成までの残り手数の推定 ĥ(s)」である。多目的の曖昧さはない。
- ビーム/chokudai サーチで比較されるのは同深さ(=同消費手数)の状態同士なので、ĥ は絶対値より順序の正しさが重要。ただし f = t + ĥ を枝刈りに使う(基盤 §3)ため、スケールも「手数」に較正されているべき(過大評価は最適枝を刈るリスク、過小評価は枝刈りが弱いだけ)。ĥ は下界寄りに設計し、較正で締める。

## 2. 推奨構成

ĥ(s) = 主項 + β·pairing_deficit + γ·wall_penalty、タイブレークに最良 1 手益と微量乱数。

### 主項: δ ヒストグラム集中度(行・列対称)
- n_δ = 残差 d = δ のカード枚数(δ = -19..19、軸ごと)。needs 和 Σ ceil 系ではなく、ĥ_main = Σ_axis Σ_δ |n_δ| / k(δ) の連続近似を使う。
- k(δ) は「1 手で処理できる同 δ 需要の実効数」。初期値は stage_probe(claude_hierarchical_stages.md §6)の副産物(ステージ別 1 手平均益)から取り、E3 で較正する。
- 根拠: 1 回の縦操作は単一の δ しか処理できないため、needs 総数が同じでも δ が集中している盤面ほど残り手数が少ない。d=1 と d=8 は needs 上同じ「あと 1 回」だが、仲間(n_δ)の多い方が良い、という相乗り可能性を捉える。ステージ制(IDEA-C9)は n_δ を意図的に集中させる方式であり、本主項はステージ進行を自動的に表現する(大 δ の n_δ が残っていれば序盤、と評価が知る)。|d| ≥ 11 のカードは 2 回に分解して 2 つの δ に計上する(例: d=17 → 10 と 7 に計上。分解の割り当ては固定規則でよい)。

（A1 の優先度を下げる理由: 現行の Σn_δ/k(δ) は n_δ に対して線形であり、同じ残差の空間的な集中や合法長方形への詰めやすさを表現しない。）

### ペアリング対面性(停滞予兆)
- pairing_deficit = Σ_axis Σ_{δ>0} max(0, 需要枚数(±δ) − 対面成立数(δ))。対面成立 = 「+δ 需要カードの δ 下のセルに −δ 需要または無害(動かしても不変量を壊さない)カードがいる」ペアの数。
- 根拠: 縦操作は上下ペアの交換なので、対面が成立していない需要は整地(横操作)を要する。needs 和が同じでも詰みかけた配置を早期に沈める。OBS-C8 の停滞の予兆検出。

### 壁補正
- wall_penalty = Σ_c max(0, opdist(pos(c), target(c)) − ideal_needs(c))。opdist は P2 の操作距離表。壁で理想 needs より実コストが高いカードだけ加算される(壁なしケースでは自動的に 0)。

### タイブレーク
- 展開時の候補生成(Kadane 帯最適化)の副産物である「最良 1 手の益 g*(s)」を −α·g* として加える(1 手先読み相当、追加コストほぼゼロ)。キュー投入時にまだ g* が無い場合は 0 でよい(pop・展開時に判明する値は子の評価に使う)。
- 最後に微量乱数(同値多発の粗さ対策と多様性)。

## 3. 評価設計に効く確定事実 [OBS-C11]

- 行残差の総和 Σd は操作で不変であり、順列性から常に 0。偏りの指標には使えない(Σ|d| や符号別 n_δ を使う)。
- needs は 1 手で 1 枚あたり最大 1 しか減らない。よって「1 手の needs 総減少」がそのまま実効並列度の測定値になる(probe の統計と直結)。
- 直交性(OBS-C8): 縦操作は列側の n_δ・pairing を一切変えない。評価の差分更新は動いた軸だけでよい。
- 全構成要素は O(hw) で差分更新可能: n_δ は動いたカードの出し入れで ±1、pairing は動いたカードとその対面セル近傍のみ再計算、wall_penalty は動いたカードのみ。undo=apply の対称性も保つ(基盤 §1 と整合)。
- E(不一致マス数)を評価に直接使うのは needs より情報が粗く、終盤ソルバへの切替閾値にのみ使う。

## 4. ステージ制との関係(評価難度のトレードオフ)

- ステージ制を採る場合: 評価は「当ステージの残対象枚数 + 整地性(pairing)+ 次ステージ以降の needs」で単純・安定。非定常性をステージ構造が吸収する。
- 自由探索(chokudai)の場合: 本文書の ĥ が全域で一貫している必要があり設計は難しいが、ステージ境界の人為的制約がない分だけ上限が高い。
- どちらの評価が扱いやすいかも stage_probe + E3 の比較論点に含める(Q-C7 の判断に付記)。
