# v005_chokudai_free の振り返り(棄却)

- 作成: 2026-07-18、Claude。journal の v005_chokudai_free エントリからリンクされる詳細版。
- 結果サマリ: 100/100 で E=0・正当性 gate 全通過。平均得点 3,709,129 = v001 比 +5.1%、v003 比 −5.8% で採用候補基準未達。幾何平均 T ≈ 7,651(v001 ≈ 8,667、v003 ≈ 6,527、天井は OBS-A02 より ≈ 217)。

## 1. 技術的敗因

### (a) 評価関数と目的関数の乖離 — 主因
総 T = prefix 手数 + tail 長で、tail(葉剥がし ≈ 7,000 手)が総 T の 95% を支配する構成だった。tail 長を決めるのは「E と、不一致カードの木上距離」であり、私がキュー順序に使った needs 和(残り必要シフト回数)ではない。needs 和は「|d|>10 を 10 以下へ」「|d|≤10 を 0 へ」を同価値に扱うが、tail 短縮に効くのは完全一致(E 減)だけ。結果、探索は needs を削り続けても E は 400→336 までしか動かず、tail はほぼ縮まなかった。

自分で書いた評価設計原則(notes/deep/claude_eval_function.md §1「ĥ は完成までの残り手数の推定でなければならない」)を、初版実装の簡略化で自ら破った。tail 支配構成での正しい ĥ は tail 長推定であり、needs 和は prefix 進捗の proxy にすぎない。

### (b) tail 実走の過剰な間引き
「tail は重い」と想定して E 記録 8 更新ごとに間引いた結果、tail_runs は 10 回しか発火しなかった。実測では tail 1 回は数 ms で、1.4 秒の探索中に数百回は実走できた。v003 が全ビーム終端で tail を実走し総 T そのものを評価に使って勝ったことと対照的で、**評価に総 T を使えるのに proxy で代用したことが 5.8% 差の本質**と推定する。

### (c) 深さ上限 320 の見積もりミス — 軽微
best prefix は 317 で上限に張り付いた。needs 940 を 1 手 3〜4 で削る算術(250〜300 手)は自分で書いていたのに、「E まで削り切るにはさらに深い」ことを織り込まなかった。

## 2. プロセス面の反省

- **最小差分の軽視**: v003 に対して「自由 δ / chokudai / tail 間引き」の 3 要素を同時に変えたため、負けた原因の特定が事後推論になった。機構確認の数値(E 336 止まり・tail 支配)から評価関数が主因とほぼ特定できたのは幸運であり、設計の勝利ではない。AGENTS の「ベース version との最小差分」を新規実装の勢いで軽視した。
- **機構確認時点の予兆**: ケース 0000 の機構確認で「E 336 止まり、tail 支配」は見えていた。事前登録基準があるので評価まで進める運用は正しいが、次からは機構確認の時点で「仮説が成立しないときの数値の形」を事前登録に書き添えておくと、この予兆をより機械的に扱える。
- **良かった点**: (i) 事前登録 → 実装 → 機構確認 → 評価 → 停止のフローを守った。(ii) OBS-A02 で較正した達成可能な採否基準(v003 実測比)を置いた。(iii) anytime 構造(初期盤面への tail 実走で完成列を初期化)により E=0 が構造的に保証され、探索の失敗がスコア事故にならなかった。

## 3. 再利用可能な資産(確認された事実)

- フルクローン型 chokudai 探索は 46,415 ノード / 1.41 秒 ≈ **33k ノード/秒**(200 帯の Kadane 候補生成込み)。Q-C9 のクローン側に部分回答。
- Zobrist 深さ別重複排除のヒット率 61%(28,293/46,415)。可換性による同一盤面多発の予想(OBS-C10)は正しく、重複排除は必須部品。
- 葉剥がし tail の部品化(任意盤面から実走、前計算共有)と、出力列の再生 assert。

## 4. 次実験への具体的示唆

1. **最小差分の本命: 評価の差し替えだけを行う** — v005 の骨格を保ち、キュー優先度を needs 和から「tail 長推定 = Σ_{card≠pos} 木上距離(pos(card), target(card))」へ差し替える。木上距離は 400×400 テーブル(320KB)を前計算でき、needs 同様 O(動いたカード) で差分更新できる。これで評価が「総 T の直接推定」になり、chokudai の寄与を交絡なしで再測定できる。tail 実走の間引きも撤廃し、時間予算内で頻繁に実走する。
2. `v008_chokudai_treedist`はv005の骨格を保って評価だけを差し替える後継実験である。これはv004との交配ではなく、v004側は別に`IDEA-D17`で評価proxyを一手rollout較正し、現行評価がgateを通った場合だけ状態・候補・評価を固定して探索スケジュールだけをchokudaiへ変える`IDEA-D19`を独立実験する。
3. E 主導評価(タイブレークでなく主項に E)と 1 の木距離評価の比較は、同一骨格での 1 変更ずつの独立実験として扱う。
