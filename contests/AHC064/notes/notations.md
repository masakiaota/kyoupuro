# 記号一覧

このファイルは、問題で使う記号とコード上の代表名・型・制約の正本である。解法考察や仮説は混ぜない。

## 固定値・サイズ

### 出発線・待避線の本数 `R`

- 意味: 出発線と待避線の本数。どちらも左から右へ `0,1,...,R-1` と番号付けされる。
- コード上の代表名: `r_count` または `R`
- Rust の想定型: `usize`
- 制約・不変条件: 全テストケースで `R = 10`。

### 初期車両数 `10`

- 意味: 初期状態で各出発線に配置される車両数。
- コード上の代表名: `INIT_LEN`
- Rust の想定型: `usize`
- 制約・不変条件: 各出発線にちょうど 10 両。待避線は空。

### 総車両数 `10R`

- 意味: 全車両数。
- コード上の代表名: `CAR_COUNT` または `car_count`
- Rust の想定型: `usize`
- 制約・不変条件: 車両 ID は `0..10R` をちょうど 1 回ずつ含む。`R = 10` なので `100` 両。

### 出発線容量 `15`

- 意味: 1 本の出発線に入れられる最大車両数。
- コード上の代表名: `DEP_CAP`
- Rust の想定型: `usize`
- 制約・不変条件: 各出発線の長さは常に `0 <= len <= 15`。

### 待避線容量 `20`

- 意味: 1 本の待避線に入れられる最大車両数。
- コード上の代表名: `SIDING_CAP`
- Rust の想定型: `usize`
- 制約・不変条件: 各待避線の長さは常に `0 <= len <= 20`。

### 最大ターン数 `4000`

- 意味: 出力できる操作ターン数の上限。
- コード上の代表名: `MAX_TURNS`
- Rust の想定型: `usize`
- 制約・不変条件: `T <= 4000`。超えると `WA`。

## 添字・ID

### 出発線番号 `r`, `i`

- 意味: 出発線の番号。`r` は一般の出発線、`i` は操作で使う出発線を表す。
- コード上の代表名: `r`, `i`, `dep_idx`
- Rust の想定型: `usize`
- 制約・不変条件: `0 <= r,i < R`。

### 待避線番号 `j`

- 意味: 待避線の番号。操作で使う待避線を表す。
- コード上の代表名: `j`, `sid_idx`
- Rust の想定型: `usize`
- 制約・不変条件: `0 <= j < R`。

### 位置 `c`

- 意味: 出発線の先頭から数えた位置。入力と目標配置で使う。
- コード上の代表名: `c`, `pos`
- Rust の想定型: `usize`
- 制約・不変条件: 入力では `0 <= c < 10`。

### 車両 ID

- 意味: 各車両に付けられた一意な ID。
- コード上の代表名: `id`, `car`
- Rust の想定型: 入出力・添字計算では `usize`、`State` 内の車両列では `u8`
- 制約・不変条件: `0 <= id < 10R`。

### 入力配置 `Y_{r,c}`

- 意味: 初期状態で、出発線 `r` の先頭から `c` 両目にある車両 ID。
- コード上の代表名: `y`, `initial`
- Rust の想定型: `[[usize; INIT_LEN]; R]`
- 制約・不変条件: `Y_{r,c}` 全体は `0..10R` の順列。

### 目標配置

- 意味: 出発線 `r` には、先頭から `10r,10r+1,...,10r+9` を並べる。
- コード上の代表名: `target_id(r, c)`, `target`
- Rust の想定型: `usize` または `Vec<Vec<usize>>`
- 制約・不変条件: `target_id(r, c) = 10 * r + c`。

### 目標列 `target_seq(r)`

- 意味: 線 `r` に最終的に並べたい車両列。
- コード上の代表名: `target_seq(r)`, `target_ids`
- Rust の想定型: `[usize; INIT_LEN]` または `Vec<usize>`
- 制約・不変条件: `target_seq(r) = [10r,10r+1,...,10r+9]`。

### prefix / suffix

- 意味: ある線の先頭から連続する部分列を `prefix`、その後ろ側の残りを `suffix` と呼ぶ。
- コード上の代表名: `prefix_len`, `fixed_len`, `suffix_start`
- Rust の想定型: 長さや境界は `usize`
- 制約・不変条件: `dep[r][0..p]` は出発線 `r` の長さ `p` の prefix を表す。

### 連続ブロック `block`

- 意味: 1 回の移動でまとめて扱う、同一線上の連続した車両列。
- コード上の代表名: `block`, `segment`, `chunk`
- Rust の想定型: 参照としては範囲 `(start, len)`、実体としては `Vec<usize>` など。
- 制約・不変条件: 移動中に block 内部の車両順序は保存される。

## 状態

### 出発線状態

- 意味: 各出発線にある車両列。
- コード上の代表名: `dep`, `dep_len`
- Rust の想定型: `dep: [[u8; DEP_CAP]; R]`, `dep_len: [u8; R]`
- 制約・不変条件: 各 `dep[r][0..dep_len[r]]` は先頭から末尾の順に保持する。長さは 15 以下。操作は末尾からの取り出し・末尾への追加のみである。

### 待避線状態

- 意味: 各待避線にある車両列。
- コード上の代表名: `sid`, `sid_head`, `sid_len`
- Rust の想定型: `sid: [[u8; SIDING_CAP]; R]`, `sid_head: [u8; R]`, `sid_len: [u8; R]`
- 制約・不変条件: 各 `sid[j]` はリングバッファとして保持する。論理位置 `pos` の物理 slot は `(sid_head[j] + pos) mod SIDING_CAP`。論理順は先頭（出発線に近い側）から末尾の順。操作は先頭からの取り出し・先頭への追加のみである。

### 車両所在

- 意味: 各車両が現在どちらの種類の線路のどの位置にあるか。
- コード上の代表名: `car_area`, `car_line`, `car_slot`
- Rust の想定型: `car_area: [u8; CAR_COUNT]`, `car_line: [u8; CAR_COUNT]`, `car_slot: [u8; CAR_COUNT]`
- 制約・不変条件: `car_area[id]` は `AREA_DEP` または `AREA_SIDING`。`car_line[id]` は出発線番号または待避線番号。`car_slot[id]` は出発線では先頭からの位置、待避線ではリングバッファの物理 slot。

## 操作・出力

### ターン数 `T`

- 意味: 出力した操作列のターン数。
- コード上の代表名: `t_count`, `turns.len()`
- Rust の想定型: `usize`
- 制約・不変条件: `T <= 4000`。

### ターン内移動数 `K_t`

- 意味: ターン `t` で同時に実行する移動数。
- コード上の代表名: `k_t`, `moves.len()`
- Rust の想定型: `usize`
- 制約・不変条件: `1 <= K_t <= R`。

### 移動 `(type, i, j, k)`

- 意味: 出発線 `i` と待避線 `j` の間で、連続する `k` 両を移動する。
- コード上の代表名: `Move { kind, i, j, k }`
- Rust の想定型: `struct Move { kind: usize, i: usize, j: usize, k: usize }`
- 制約・不変条件: `type in {0,1}`, `0 <= i,j < R`, `k >= 1`。
- `type = 0`: 出発線 `i` の末尾から連続する `k` 両を取り出し、待避線 `j` の先頭に連結する。
- `type = 1`: 待避線 `j` の先頭から連続する `k` 両を取り出し、出発線 `i` の末尾に連結する。
- どちらも対象車両列の順序は保存される。

### 同一ターンの非交差制約

- 意味: 同じターン内の移動経路は互いに交差してはならない。
- コード上の代表名: `is_non_crossing(moves)`
- Rust の想定型: `fn(&[Move]) -> bool`
- 制約・不変条件:
  - 同じターン内で、1 本の出発線または待避線を 2 回以上使用してはならない。
  - 2 つの移動 `(i_1, j_1)`, `(i_2, j_2)` を同時に行う場合、`i_1 < i_2` ならば `j_1 < j_2` でなければならない。
  - 移動方向 `type` は交差判定に影響しない。

## スコア

### 完成時スコア

- 意味: 全出発線が目標配置と完全一致している場合のスコア。
- コード上の代表名: `perfect_score`
- Rust の想定型: `i64`
- 制約・不変条件: `100R + 4000 - T`。`R = 10` なので `5000 - T`。

### 未完成時スコア

- 意味: 目標配置と完全一致していない場合の部分点。
- コード上の代表名: `partial_score`
- Rust の想定型: `i32`
- 制約・不変条件:
  - 出発線にある各車両について、正しい出発線にあれば 1 点。
  - さらに先頭からの位置も正しければ追加で 9 点。
  - 待避線に残った車両は得点対象ではない。
  - `State` では出発線から抜く車両の寄与を引き、出発線へ入れる車両の寄与を足すことで差分更新する。

### 不正出力

- 意味: 出力が制約違反になる条件。
- コード上の代表名: `validate_output`, `is_valid`
- Rust の想定型: `fn(...) -> bool`
- 制約・不変条件: `T > 4000`、非交差制約違反、容量制約違反、不正な移動形式などは `WA`。
