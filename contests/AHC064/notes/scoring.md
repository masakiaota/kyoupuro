# 評価基準

## 基本方針

盤面の価値は、完成に向けて「どれだけ目標列上の境界を消せているか」で測る。

目標列 `target_seq(r) = [10r, 10r+1, ..., 10r+9]` において、隣り合うべき 2 両
`10r+c` と `10r+c+1` が同一線上で正順に隣接しているなら、その 2 両の間の境界は
すでに解消済みである。

移動では block 内部の順序が保存されるため、一度正順に隣接した 2 両は、以後 1 つの
block として扱える。したがって、評価すべきなのは長い block そのものではなく、
解消済みの隣接境界の個数である。

## 評価値

盤面 `state` の評価値 `P(state)` を次の 2 項の和で定義する。

```text
P(state)
  = 正順隣接ペア数
  + 出発線先頭アンカー数
```

### 正順隣接ペア

各 `r` と `c = 0..8` について、`10r+c` の直後に `10r+c+1` が同一線上で正順に
隣り合っていれば `+1` 点とする。

```text
... 10r+c, 10r+c+1 ...
```

この `+1` 点は、目標列上の境界が 1 つ消えたことを表す。

### 出発線先頭アンカー

各 `r` について、車両 `10r` が出発線 `dep[r]` の先頭 `dep[r][0]` にあれば `+1`
点とする。

```text
dep[r][0] = 10r
```

これは、目標列 `r` を出発線 `r` 上で完成させるための基準点が置けていることを表す。

## 最大値

各 `r` について、目標列には正順隣接ペアが 9 個あり、出発線先頭アンカーが 1 個ある。
したがって `R = 10` では最大評価値は `100` である。

```text
10 lines * (9 adjacent pairs + 1 anchor) = 100
```

完成状態では必ず `P(state) = 100` になる。

## 解釈

この評価では、長い連結 block を短い連結 block より特別に高く評価しない。

長さ `L` の正順 block の価値は、内部に含まれる正順隣接ペア数 `L-1` である。
例えば、長さ 4 の block は `3` 点であり、それ以上の追加価値は持たない。

```text
[10r, 10r+1, 10r+2, 10r+3] => 3 点
```

これは、「同一線上で `10r+c` の直後に `10r+c+1` が正順に隣り合っているなら、
この 2 両は以後 1 つの block として扱える」という性質に基づく。

つまり、探索中の move は、基本的には `P(after) - P(before)` をどれだけ増やせるか
というゲームとして解釈できる。

## 検討候補: 緩和アンカー

出発線先頭アンカーの代替として、より緩いアンカー条件も考えられる。

元の条件は次である。

```text
dep[r][0] = 10r なら +1 点
```

これは、車両 `10r` がすでに最終的な置き場所である出発線 `r` の先頭にいることを
評価する。

一方、緩和版では、車両 `10r` がまだ `dep[r][0]` にいなくても、出発線 `r` と
待避線 `r` の中で、他のどの車両よりも先頭にあれば `+1` 点とする。

### アクセス順

ここでの「先頭」は、物理的な配列位置ではなく、その線から取り出せる順番で定義する。

- `dep[r]` は末尾から取り出すので、アクセス順は末尾から先頭へ向かう順である。
- `sid[r]` は先頭から取り出すので、アクセス順は先頭から末尾へ向かう順である。

したがって、線 `r` に対応する候補列 `access_seq(r)` を次のように定義する。

```text
access_seq(r)
  = reverse(dep[r]) followed by sid[r]
```

この列は、「出発線 `r` から取り出せる車両」と「待避線 `r` から取り出せる車両」を、
それぞれ取り出しやすい順に並べたものである。この検討候補では、この列を
`dep[r] + sid[r]` に対応する緩和的な先頭順とみなす。

### 緩和アンカー条件

車両 `10r` が `access_seq(r)` の先頭にあれば `+1` 点とする。

定式化すると、次の条件である。

```text
access_seq(r) が空でなく、
access_seq(r)[0] = 10r
なら +1 点
```

言い換えると、`dep[r]` と `sid[r]` を「次に取り出せる順」に見たとき、`10r` が
その中のどの車両よりも前にあればよい。

### 意味

この緩和アンカーは、`10r` がまだ完成位置 `dep[r][0]` に固定されていなくても、
その `r` の完成列を組み始める起点として利用できる状態を評価する。

元の出発線先頭アンカーは「すでに置けている基準点」を評価する。
緩和アンカーは「次に基準点として使える位置にあること」を評価する。
