# AHC073

VS Code でこのフォルダを開く。解法は `main.py` に書く。

## 必要な環境

- Python 3：`setup.py` と `eval.py` を動かす。
- PyPy 3.11：評価対象の解法を動かす。`.venv/bin/python` または `pypy3` として使える状態にする。
- Rust（`cargo`）：公式の採点ツールをビルドする。

## 1. 公式ツールを準備する

問題ページから公式ツールの Rust ソース版 ZIP をダウンロードし、そのパスを指定する。

```bash
python3 setup.py ~/Downloads/tools.zip
```

`setup.py` は ZIP を `tools/` に展開し、公式ツールをビルドする。入力が配布されていなければ生成する。

- **「準備完了」と表示された場合**：次の「解法を書く」へ進む。
- **「採点方式を選択」と表示された場合**：`tools/README.md` の実行方法を読み、下表に対応するコマンドを一つ実行する。

| 公式 README の実行方法 | 実行するコマンド |
| --- | --- |
| `tester cmd ...` で解法を起動する | `python3 setup.py --mode tester` |
| `vis in.txt out.txt` に入力と解法の出力を渡す | `python3 setup.py --mode vis` |

選択を求められた時点で ZIP は展開済みなので、2回目のコマンドでは ZIP を指定しない。「準備完了」が表示されたら次へ進む。

## 2. 解法を書く

1. 下表から方式を選ぶ。単純な初期解なら、現在の `main.py` を使う。他の方式なら、コピー元のファイル全体を `main.py` にコピーする。
2. [入力テンプレート一覧](snippets/read_input/README.md)から形式を選び、`read_input()` 全体を置き換える。
3. 残りの関数を埋める。各関数のコメントに、引数、戻り値、記入例がある。
4. `TIME_LIMIT` がある方式では、公式の実行時間制限より余裕を残して設定する。

| 方式 | コピー元 | 自分で決める内容 |
| --- | --- | --- |
| 単純な初期解 | 現在の `main.py` | 入力、解を作る処理、出力 |
| 貪欲法 | `snippets/greedy.py` | 初期状態、候補、候補の良さ、段階数 |
| 乱択 | `snippets/random_search.py` | 完成解の作り方、完成解の得点 |
| 焼きなまし | `snippets/annealing.py` | 初期解、完成解の得点、変更候補 |
| ビームサーチ | `snippets/beam.py` | 初期状態、次状態、段階数、途中の見込み、完成時の得点 |
| 対話型 | `snippets/interactive.py` | 初期入力、手番入力、行動、最初の送受信順 |

- 評価関数は、大きいほど良い数値を返す。最小化なら `-cost` を返す。
- 対話型は行単位で入力を読み、出力を `flush=True` で送る。1手が複数行なら `write_output` も変更する。
- 未記入の関数が残っていると、評価時に `TODO: 関数名` の一覧が表示される。

## 3. 評価する

評価時の解法は **PyPy で実行する**。コマンドの `python3` が動かすのは、ケースの実行と結果集計を管理する `eval.py` だ。PyPy が見つからない場合は停止する。

| 評価したい対象 | コマンド |
| --- | --- |
| 全ケース | `python3 eval.py` |
| 先頭10ケース | `python3 eval.py --quick` |
| 指定した1ケース | `python3 eval.py --case 0000` |
| 別名で保存したコード | `python3 eval.py v001.py` |
| 単独実行で時間を確認 | `python3 eval.py --quick -j 1` |

- **並列数**：既定は最大25ケース。変更する場合は `-j 8` のように指定する。
- **強制終了までの時間**：1ケース10秒。変更する場合は `--timeout 30` のように指定する。公式の実行時間制限とは別の設定である。
- **ショートカット**：Shift + Command + B で先頭10ケースを評価できる。付属の `.vscode/tasks.json` が `python3 eval.py --quick` を実行するため、コマンドの手入力は不要だ。

時間で探索を打ち切る解法は、並列実行時の負荷によって探索量が変わる。実行時間の確認には `-j 1` を使う。

## 4. 結果を確認して提出する

評価結果は次の場所に保存する。

| 保存先 | 内容 |
| --- | --- |
| `results/summary.csv` | 評価ごとの集計一覧 |
| `results/日時/scores.csv` | ケース別の得点、時間、成否 |
| `results/日時/main.py` | 実際に評価したコード |
| `results/日時/cases/0000/out.txt` | ケース `0000` の出力 |
| `results/日時/cases/0000/` 内のログ | 実行エラーや採点器の説明 |

- 終了時に、集計結果と保存先を表示する。同条件の前回評価があれば、平均得点の差も表示する。
- 失敗を含む評価では、平均と合計を確定しない。表示されたケースのログを確認する。
- 提出には、採用した評価の `results/日時/main.py` を使う。

## 追加の部品

- `snippets/annealing_delta.py`：差分評価で高速化する焼きなまし。変更による得点差と、変更を取り消す処理を書く。
- `snippets/graph.py`：BFS、Dijkstra、Union-Find。必要な関数やクラスだけを `main.py` に貼る。
