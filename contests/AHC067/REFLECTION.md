# AHC067 反省

## 折り返し距離の見落とし

ボタン同士を遠く置くことに意識が寄りすぎていた。

この問題で稼げる距離は、単純な「次のボタンまでの距離」だけではない。
ボタンを全体的にゴール側へ寄せても、扉の開閉状態によって入口側へ大きく折り返させ、再びゴール側へ戻らせる経路を作れる。

つまり、評価すべきだった距離は次の形だった。

```text
ボタンを押す
-> 状態が変わる
-> 開いた扉と閉じた扉の都合で遠くへ折り返す
-> 次のボタンまたはゴール側へ戻る
```

Chinese rings 型の構築では、前段のスイッチほど何度も押される。
そのため、頻繁に発生する折り返しを長くできるなら、ボタン同士の直接距離が短くても十分に効く。
この見方に気付けなかった。

## 実装意図をコメントに残さなかった

実装に「なぜその処理があるのか」をコメントとして残さなかったのも反省点である。

今回のコードは、`goal_cage`、`augmented_goal_cage`、`pairwise_rescue`、`permanent_extra`、`rewire_path_doors` のように、発想の名前だけが残っている。
しかし、どの失敗ケースを救うための処理なのか、どの距離を稼ぐ意図なのか、後から読むと追いにくい。

少なくとも主要関数の先頭には、次のような意図を短く書くべきだった。

```rust
// ボタン同士の直接距離ではなく、押下後に入口側へ折り返して戻る距離を稼ぐ。
// ゴール近傍を cage して、最終突破前に複数回の往復を強制する。
```

```rust
// 既存構築は扉を使い切るため、最短路上の追加扉を入れる余地がない。
// 重要度の低い扉を少し外し、実測 T を落としすぎない範囲で改善用 slot を作る。
```

```rust
// greedy assignment だけだと局所的に近いスイッチ配置へ偏る。
// 候補間距離を beam の評価に入れて、折り返し距離を持つ配置を拾う。
```

AHC のコードは、提出物であると同時に探索過程の記録でもある。
意図コメントがなければ、実装から反省を復元するコストが高くなる。

## 必要な壁枚数の最小化を考え切れなかった

Chinese rings 型の構築について、必要な壁の枚数をもっと深く考えるべきだった。

当初は、各スイッチへ向かう通路に条件扉をそのまま並べる発想に引きずられていた。
そのため、スイッチ数が増えるほど必要な扉が三角数的に増えるものだと見なし、壁を多く使う構築にとらわれていた。

しかし、各スイッチへの条件には共通 prefix がある。
たとえば、`S5` へ行く条件に含まれる `bit0=0, bit1=0, bit2=0, bit3=0` は、`S3` や `S4` へ行く条件とも重複している。
この共通部分を decoder tree として共有すれば、同じ条件扉を何度も置く必要はない。

非圧縮の発想では、壁枚数を次のように見ていた。

```text
S1: 1 枚
S2: 2 枚
S3: 3 枚
...
```

一方で、共通 prefix を共有すれば、必要なのはおおむね次の 2 種類である。

```text
低位 bit が 0 であることを確認する共通通路の扉
各段階で bit が 1 であることを確認する分岐扉
```

この違いにより、必要な壁枚数を大きく削減できる。
削減した分の壁を長い通路のショートカット封鎖に回せば、平均移動距離を大きく伸ばせた。

この点を詰め切れなかったことが、順位で 50 位程度の差につながったと考えている。
