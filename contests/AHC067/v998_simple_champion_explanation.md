# 入れ子の部屋でスイッチ状態を運ばせる解法

この問題では、勇者は現在位置だけでなく `mask` も状態として持つ。
したがって、同じマスへ戻らせても、戻るたびに `mask` が違えば別の状態として扱われる。

この解法は、その性質を使って「同じ中継点へ何度も戻るが、毎回違う扉だけが開く」構造を作る。
盤面上の距離を一度だけ稼ぐのではなく、同じ距離を `mask` の変化によって何百回も支払わせる。

## 基本の形

まず、空きマスだけからなる無向グラフを作る。
各空きマスを頂点、上下左右に隣接する空きマスの間を辺とする。
扉はこの辺に置く。

作りたい形は、一本の背骨と、その背骨から横に出る枝である。
背骨の先は玉座へ向かう。
枝には次のスイッチを置く。

```text
outside
  |
  s0
  |
  x0 -- b1(s2)
   |
  x1 -- b2(s3)
   |
  x2 -- b3(s4)
   |
  ...
   |
  x8 -- gate9 -- goal side

別の小部屋:
  p1(s1)
```

ここで `s0` はスイッチ 0 の位置、`p1` はスイッチ 1 の位置である。
`b1` から `b8` には、スイッチ 2 からスイッチ 9 を置く。

この図は実際の座標を表すものではない。
背骨は盤面上の単純パスであり、枝は背骨上の選んだ点に隣接する背骨外の空きマスであればよい。

背骨上の制御点は `spine_pos[0..8]` として扱う。
`spine_pos[0]` は必ず背骨の先頭 `0` にする。
`spine_pos[0..7]` はそれぞれ枝スイッチ `s2..s9` に対応する。
`spine_pos[8]` は最後の型 `19` の扉を置く位置であり、枝セルを置かない。

したがって、枝セルは 8 個である。
「背骨上の制御点は 9 箇所、枝は 8 個」と分けて考える。

## 扉型の役割

扉型は、偶数型が `mask` の bit が 0 のとき開き、奇数型が bit が 1 のとき開く。
この解法では、その性質を次のように使う。

- 型 `0`：スイッチ 0 を押す前だけ開く外周の扉。
- 型 `1`：スイッチ 0 を押した後だけ開く小部屋の扉。
- 型 `2i`：スイッチ `i` を押す前だけ開く背骨上の扉。
- 型 `2i+1`：スイッチ `i` を押した後だけ開く枝への扉。
- 型 `19`：スイッチ 9 を押した後だけ開く最後の扉と追加の妨害扉。

背骨上では、`spine_pos[0..8]` に特別な扉を置く。
`i=1..8` について、`spine_pos[i-1]` から背骨を 1 歩先へ進む辺には型 `2i` を置く。
同じ `spine_pos[i-1]` から枝へ入る辺には型 `2i+1` を置く。
枝のセルにはスイッチ `i+1` を置く。
最後に、`spine_pos[8]` から背骨を 1 歩先へ進む辺には型 `19` を置く。

```text
背骨:

  x0 ==g2== x1 ==g4== x2 ==g6== ... ==g16== x8 ==g19== goal side
   |         |         |
  g3        g5        g7
   |         |         |
  s2        s3        s4
```

`g2` はスイッチ 1 を押す前だけ開く。
`g3` はスイッチ 1 を押した後だけ開く。
したがって、同じ場所から「先へ進む」か「枝のスイッチへ入る」かがスイッチ 1 で入れ替わる。
この入れ替えをスイッチ 1 から 8 まで重ねると、勇者は深いスイッチへ近づくたびに、前の段の状態を用意してから戻る必要がある。

## 外側から部屋を切り離す

背骨と枝だけでは、勇者が別の隙間から内部へ入る。
そのため、内部構造そのものと、外側から切り離すための領域を分けて作る。

内部構造そのものを `in_u` と呼ぶ。
`in_u` には、背骨の先頭 `spine[0]` を除く背骨セルと、枝セルを入れる。
入口 `(0,0)` が `in_u` に入った候補は捨てる。

外側から切り離すための領域を `in_r` と呼ぶ。
`in_r` は次の手順で作る。

1. `in_u` をコピーする。
2. 背骨の先頭 `spine[0]` を `in_r` に入れる。
3. `in_u` に隣接する空きマスをすべて `in_r` に入れる。
4. `in_r` の外側の空きマスで、隣接 4 方向のうち 3 方向以上が `in_r` に接しているものを、なくなるまで `in_r` に入れる。
5. 入口 `(0,0)` が `in_r` に入った候補は捨てる。

この膨張を行う理由は、1 マス幅の抜け道を残しにくくするためである。
3 方向を `in_r` に囲まれたマスを外に残すと、そのマスを経由する短い横道ができやすい。
先に `in_r` へ吸収してから境界を塞ぐほうが、少ない扉で外側と内側を分けやすい。

`in_r` と外側をまたぐ辺には型 `0` の扉を置く。
型 `0` は初期状態では開いているが、スイッチ 0 を押すと閉じる。
これにより、勇者は最初だけ内部へ触れられ、スイッチ 0 を押した後は別の入口から内部へ戻りにくくなる。

`in_u` に直接接する余計な辺には型 `1` の扉を置く。
ただし、背骨上で普通に歩かせたい辺、枝へ入る辺、型 `2i`、型 `2i+1`、型 `19` を置く辺には型 `1` を置かない。
型 `1` はスイッチ 0 を押した後だけ開くので、内部の移動をスイッチ 0 後の状態へ寄せられる。
`in_u` 内部の余計な接続を型 `0` で塞ぐと、スイッチ 0 前後の通行可能性が逆になり、短絡が生じやすい。

## スイッチ 1 の小部屋

スイッチ 1 は、`in_r` の外側にある小部屋 `p1` に置く。
`p1` に接するすべての辺には型 `1` の扉を置く。

この小部屋は `in_r` に接していない場所から選ぶ。
`in_r` に接していると、スイッチ 1 の小部屋が内部への近道になり、背骨の順番が崩れるからである。
`p1` の全隣接辺を型 `1` にしても扉数が `M` を超えないことも必要である。

スイッチ 0 を押す前、型 `1` は閉じているので `p1` へ入れない。
スイッチ 0 を押した後、型 `1` が開き、勇者は `p1` へ入ってスイッチ 1 を押せる。
その後は、型 `2` が閉じ、型 `3` が開くので、背骨の第 1 段では先へ進む代わりに枝のスイッチ 2 へ入れる。

`p1` は 1 点に決め打ちしない。
候補を複数サンプルし、各 `p1` 候補ごとに次の節の `s0` を選び直す。

## 共通の戻り先

スイッチ 0 の位置 `s0` は、各段から戻る共通の目標として選ぶ。
`s0` 自体は特殊な部屋に閉じ込めない。
むしろ、さまざまな `mask` から `s0` へ遠回りで戻れることが価値になる。

`s0` は `p1` を仮置きした後に選ぶ。
順序を逆にして、先に `s0` を選んでから遠い `p1` を探すと、最も重い `512 * dist(p1,s0,1)` の項を最適化できない。

候補を作ったら、各 `p1` 候補について次の固定 `mask` BFS を計算する。

- `mask=0` で、入口から `s0` への距離。
- `mask=1` で、`p1` から `s0` への距離。
- `mask=1<<(i-1)` で、スイッチ `i` から `s0` への距離。ここで `i=2..9` である。
- `mask=1<<9` で、玉座から `s0` への距離。

どれかが到達不能なら、その候補は捨てる。
すべて到達可能なら、`in_r` の外側にある空きマスから、次の推定値を大きくするように `s0` を選ぶ。
`s0` は `p1`、入口、玉座を避ける。

```text
estimate =
    1023
  + dist(start, s0, 0)
  + 512 * dist(p1, s0, 1)
  + 256 * dist(s2, s0, 2)
  + 128 * dist(s3, s0, 4)
  + ...
  +   2 * dist(s8, s0, 256)
  +   1 * dist(s9, s0, 512)
  +       dist(goal, s0, 512)
```

係数が 512、256、128 と半分になるのは、浅い段ほど何度も通るからである。
スイッチ列は、深い bit を立てるまでに浅い bit の準備を何度も要求する。
そのため、浅い段の戻り距離を伸ばすほうが、最終的な `T` に大きく効く。

`1023` はスイッチ押下そのものの回数に対応する。
距離が同じなら、10 個の bit を順に扱う構造だけで、おおよそ `2^10-1` 回の押下が必要になる。

## 候補生成

背骨はランダムに作る。
玉座から逆向きに DFS して、自己交差しない単純パスを作り、最後に向きを反転する。
長さは 9 以上 28 程度からランダムに選ぶ。

DFS では、次のセルを完全な一様乱択にしない。
すでに作ったパスに接する数が多いセル、まだ伸ばせる隣接セルを持つセルを少し優先する。
この優先は、背骨の近くに枝を作れる場所を増やすためである。

背骨ができたら、制御点 `spine_pos[0..8]` を選ぶ。
`spine_pos[0]` は 0 に固定する。
`spine_pos[1..7]` は、背骨外の隣接空きマスを持つ位置から、前から順に進むように選ぶ。
`spine_pos[8]` は最後の型 `19` 用であり、`spine_pos[7]` より後ろで、背骨上に次のセルが残る位置から選ぶ。

枝セルは、`spine_pos[0..7]` の各位置に対して 1 個ずつ割り当てる。
前から貪欲に即決すると、後ろの位置で候補が尽きやすい。
各位置の候補を列挙し、候補数が少ない位置から DFS などで重複しないセルを割り当てる。
割り当てられなければ、その候補は捨てる。

この段階では、スコアの高い候補を 20 個程度だけ残せばよい。
すべての候補を厳密評価すると時間が足りない。
固定 `mask` BFS による推定値で上位を残し、最後に本当の状態 BFS で `T` を計算する。

## 型 19 の追加扉

基本構造を作った後、扉数が余っていれば型 `19` の扉を追加する。
型 `19` はスイッチ 9 を押すまで閉じている。
したがって、最終段に到達する前の移動を妨害でき、スイッチ 9 後の玉座側移動は妨害しにくい。

追加候補は、推定式で使った各固定 `mask` 経路の最短路上にある未使用辺から選ぶ。
単一の復元最短路だけを使わない。

`src` から `s0` への距離を `d` とする。
`src` からの距離配列を `ds`、`s0` からの距離配列を `dt` とする。
未使用辺 `(a,b)` が次のどちらかを満たすなら、その辺は `src` から `s0` への最短路上にある。

```text
ds[a] + 1 + dt[b] == d
ds[b] + 1 + dt[a] == d
```

辺ごとに、どの重みの経路の最短路に乗っているかを数え、重みが大きい経路上の辺を優先する。

追加は貪欲でよい。
上位の辺を一つ仮に型 `19` にし、推定値を再計算する。
推定値が悪化しない辺のうち最もよいものを採用する。
これを扉数が 50 に達するか、時間がなくなるまで繰り返す。

この追加扉は、構造の発想を変えるものではない。
入れ子の部屋で作った反復移動を、余った扉で少し長くする処理である。

ただし、型 `19` を追加した候補だけを残すわけではない。
追加扉は推定値を改善しても、本当の状態 BFS では短絡や到達不能を生むことがある。
そのため、型 `19` を追加する前の候補も、最後の本評価候補に残しておく。

型 `19` の追加は効きやすいが、どの候補に何枚足すのがよいかは盤面に依存する。
推定値上位の少数だけに追加して終えると、たまたま悪い候補だけを強くしてしまうことがある。
時間が許す範囲で、複数の上位候補に型 `19` 追加を試し、追加前と追加後の両方を本評価へ回す。

## 最後は本当の BFS で選ぶ

推定値は候補を絞るための値であり、提出する候補は必ず本当の `T` で選ぶ。
本当の `T` は、状態 `(mask,i,j)` に対する BFS で計算する。

移動では、辺に扉がなければ通れる。
扉型 `g` がある場合は、次の条件を満たすときだけ通れる。

```text
((mask >> (g / 2)) & 1) == (g & 1)
```

現在地にスイッチ `s` があれば、`mask ^ (1 << s)` へ遷移する。
この BFS で玉座に初めて到達した距離が `T` である。

実装では、推定上位をある程度広めに残し、その中で `T` が最大のものを出力する。
推定値は、深いスイッチ状態を作るための戻り距離を近似しているだけであり、勇者の本当の最短行動列を完全には表さない。
したがって、推定値上位だけを狭く残しすぎると、本当の `T` が大きい候補を捨てやすい。
候補が一つも作れなかった場合だけ空出力にする。
ただし、この場合は得点が低いので、探索時間と候補生成を調整して通常ケースでは候補が出るようにする。

## 実装上の目安

`N=20`, `K=10`, `M=50` は固定で扱ってよい。
状態数は `2^10 * 400 = 409600` なので、本評価 BFS は十分に間に合う。

固定 `mask` BFS は、通常の 400 頂点 BFS でよい。
候補生成中に何度も呼ぶので、配列を使い回すと速い。

時間配分は次のようにすると安定する。

- 前半 85%：背骨と枝をランダム生成し、推定値で候補を集める。
- 次の 10%：上位候補に型 `19` の追加扉を入れる。
- 最後：本評価 BFS で提出候補を選ぶ。

この比率は目安である。
型 `19` 追加を完全に省くと大きく落ちやすい一方で、追加後候補だけを信じるのも危ない。
候補生成、型 `19` 追加、本評価の三つをすべて残すほうが安定する。

乱択は固定 seed でよい。
入力ごとに空き辺数などを seed に混ぜると、ケース間で候補の偏りが少し減る。

出力では、内部で辺番号を持っていても、最後に公式形式へ戻す。
上下方向の辺は `d=0`、左右方向の辺は `d=1` である。
同じ辺へ複数の扉を置かず、扉数が 50 を超えないことだけは必ず検査する。
