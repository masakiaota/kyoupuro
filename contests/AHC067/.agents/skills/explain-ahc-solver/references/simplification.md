# 簡素化による本質抽出

対象 solver をそのまま説明すると、過去の試行、ログ、補助探索まで本文に混ざりやすい。
まず得点を保ったまま削れるものを削り、残った構造から解説を書く。

## 手順

1. 対象 solver をコピーして、簡素化用の新規 solver を作る。
   既存 solver を直接破壊しない。

2. `main` から到達する処理を確認する。
   呼ばれていない探索、古い fallback、使われていない統計を候補にする。

3. 小さな削除単位を一つ選ぶ。
   削除理由を「この処理は到達しない」「出力に影響しない」「ログだけである」のように具体化する。

4. `cargo fmt` と compile check を行う。
   AHC project では原則 `--features local` 付きで確認する。

5. `scripts/eval.py` で評価する。
   目標スコア、成功ケース数、`max_elapsed` を見る。

6. 目標を下回った削除は戻す。
   その処理は「本質ではない」と断定しない。

7. 目標を保った削除だけを採用し、残った構造を解説対象にする。

## 削ってよい可能性が高いもの

- `main` から到達しない旧探索
- 評価ログや local debug 専用の集計
- 最終出力に使われない経路復元
- 使われていない型、定数、補助関数
- 以前の候補生成方式の残骸

## 慎重に扱うもの

- 時間管理
- 最後の本評価
- 近似評価と本評価の接続
- 到達不能を避ける補正
- 見かけ上は小さい後処理
- fallback に見えて実際は特定ケースを救う処理

## 解説へ戻す観点

削除できた処理は、本文に書かないか、開発経緯として一文だけにする。

削除できなかった処理は、なぜ効いていたかを説明する。
理由が分からない場合は、分からないと書き、検証事実だけを示す。
