# v005 着手前のギャップ分析 (v501 の損失構造)

分析スクリプトは `adhoc/scripts/analyze_gap_v501.py`、`analyze_reject_v501.py`、`analyze_shape_v501.py`。
すべて v501 の `results/out/` 出力の盤面リプレイと `tools/in` の全グループ情報から計算した。

## 上限比の分解

LP 緩和上限 (時間平均容量 grass×100000 セル時間、価値 V×C_max、コスト P×(T-S)) に対して:

| 指標 | 全体平均 | 意味 |
|---|---:|---|
| ratio | 0.562 | v501 スコア / LP 上限 |
| util | 0.616 | 受け入れセル時間 / 容量 |
| selq | 0.900 | 受け入れ集合の価値 / 同セル時間を密度順に使った価値 |
| realize | 0.794 | スコア / 受け入れ集合の V×C_max 合計 |

- 選別 (selq) は既に高く、伸びしろは util (埋め切り) と realize (形状品質) に集中する。
- 負荷別では load>=1.3 で ratio≈0.52。R による差は小さい (R<=0.02 でも moves は平均16回で、低 R を活かせていない)。

## No の内訳 (Q2 決着)

No 36,060 件 (100 ケース計) の盤面リプレイ分類:

| 分類 | 件数 | 割合 |
|---|---:|---:|
| 絶対容量不足 (空きセル総数 < P) | 4 | 0.0% |
| 断片化棄却 (空き総数 >= P、最大空き成分 < P) | 5,632 | 15.6% |
| 置けたのに No (最大空き成分 >= P) | 30,424 | 84.4% |

- 置けたのに No のうち q>=1 (中央値以上の品質) は 5,365 件。大半は低品質の価格棄却で正当。
- 幾何棄却の実体はほぼ断片化であり、絶対容量不足はゼロに等しい。

## 形状品質の損失 (realize の内訳)

受け入れグループの最悪周長から計算した価値加重コンパクト度:

- 総 V×C_max = 7,726.7M に対し 総 V×C = 6,221.1M。**比 0.805、損失 1,505.6M** (総スコアの約 24%)。
- 移動費は総額 7.45M でスコアの 0.12%。
- slack (worst_L - L_min) 別損失: slack 2..6 (通常探索の周長余裕) は計 73.8M に過ぎず、
  **slack>=8 (growth 配置由来の悪形) が約 1,430M を占める**。slack 10〜60 に厚い塊がある。

## 時間と移動探索の余裕 (case 0002 実測)

- program_elapsed 271ms / 予算 1,520ms (local)。時間が 5 倍以上余っている。
- relocation_attempt 317、repack_attempt 277 に対し repack_success 5。移動先再配置の探索がほぼ失敗している。
- growth_placement_success 504 回 = 悪形受け入れが多発。

## 帰結

移動費 (R×V、平均 5%) で C 改善 (20〜30%) を買う取引が大幅に売れ残っている。
v501 の relocation は「受け入れ不成立時の救済」に限定されており、悪形で受け入れが成立する場合は
移動と比較すらしない。ここを純利益比較で主経路化するのが v005_move_rescue (B-007)。
