# Important Properties

記号、制約、手の分類は[記号一覧](notations.md)に従う。ここには定義を重ねず、性質とその根拠を書く。

## 1. 誤注文ゼロ原則

### 主張
誤注文は許さない（`E=0`）。

### なぜ成り立つか
全商品を表示できる紙を使い、計算時間を考えないとき、どの注文列でも、誤注文をすべて正解に置き換えてスコアを元の方策以下にできる。

元の方策の積み順を内部で追跡する。元の方策が誤る注文では、実際の山で正しい商品を表示する。その後、元の方策が初めて正解する注文では、その注文の終了時の積み順に直接そろえる。どちらも第7節より高々 `K` 手ででき、未来の注文は使わない。

手順を置き換えるのは、元の誤注文とその直後の注文を合わせて高々 `2E` 件である。追加手数は高々 `2KE` で、消える罰点 `2KE` を超えない。

## 2. 階段可視性

種別: 定理

### 主張
prefix 紙（先頭から長さ L だけ色があり、残りは穴）だけで山を作ると、紙が見えるのは上のどの紙よりも長いときだけである。表示は、上から長さが増えていく紙の列が、左から順に各区間の色を見せる階段になる。系として、上に同じ長さ以上の紙がある紙は全マスが隠れ、掴めない。

### なぜ成り立つか
長さ L' ≥ L の紙は窓 0〜L-1 をすべて覆う。窓 j に映るのは j を覆う一番上の紙なので、紙が映る窓は「上にある紙の最大長 ≤ j < 自分の長さ」に限られる。

### 実装上どう効くか
- 可視判定は、上から最大長を更新するだけで済む。1 注文の最短手数を DP で正確に求められる。
- 限界：目的の紙が同じ長さ以上の紙の下にあると、その紙は掴めない。掴むには、上にある同じ長さ以上の紙を 1 枚ずつ、目的の紙より下へ動かすしかない。v0030 の紙を固定し、未来の注文を知っているとして探索しても、14,888 までしか下がらなかった（O-P2-oracle。有限の探索で得た値で、下限ではない）。
- 伸びしろ：入れ子を崩しつつ、同じくらい安い操作計画を持つ構造が見つかれば、スコアが大きく伸びる可能性がある。ただし未発見で、prefix 紙から出発した局所探索は prefix 紙の近くから出られなかった（O-P2-large）。

## 3. 隠蔽コスト原理

種別: 定理（最小手数）と実測。手の役割についての後半は仮説を含む

### 主張
- 穴でない窓を少なくとも 1 つ持つ紙 v を対象とする。v が穴でない窓ごとに、上から覆う紙の枚数を数える。その最小値が、v を見えるようにするまでの正確な最小手数である（定理）。
- v 自身を実際に取り出し、任意の位置へ挿し直すまでなら、最小手数は上の値に 1 手を加えたものになる。ただし、他の紙の最終配置は指定しない。
- 複数の紙の取り出し費用を足すだけでは、注文全体の最小手数は求められない。一度の退避が、表示や他の紙の取り出し費用も変えるためである。
- v より下へ動かした紙は、見えなくなる（埋める手になる）とは限らない。v より下でも、一部の窓から見え続けることがある。
- ただし、埋める手のすべてが余分な手ではない。出どころが「開始時」の埋める手は、前の表示に出ていた紙を隠して下の正しい色を見せる手であり、新しい表示に必要な手の一部である。余分な手にあたるのは、主に出どころが「途中」の埋める手、つまり注文の途中で見えるようになった紙を埋める手である。

### なぜ成り立つか
紙 v を掴むには、v が穴でないどれかの窓 j で、v が見えている必要がある。窓 j で v より上にあり、j が穴でない紙は、v より上に置き直す限り覆い続ける。そのため、それぞれ少なくとも 1 回は v の下へ動かすしかない。よって v を見えるようにするまでの手数は、その枚数を窓 j ごとに数えた最小値以上になる。逆に、最小値を与える窓 j を覆う紙を上から順に 1 枚ずつ v より下へ入れれば、各紙は移動時に窓 j から掴め、最後に v が見えるようになる。したがって、この最小値が v を見えるようにするまでの正確な手数である。紙の形によらず成り立つ。

v 自身を移動するには、見えるようになった後に v を動かす 1 手が必要である。その 1 手で任意の位置に挿し直せるため、他の紙の最終配置を問わなければ、上の最小値に 1 手を加えた手数も達成できる。

### 実測
- v0171（ケース 0000）：1 注文 13.65 手のうち 7.99 手（約 58%）が、行き先が「見えない」紙を動かす手だった。

### 実装上どう効くか
- 減らす対象は、上被せ手・一部見せ手・埋める手の合計である。埋める手だけを減らせばよいわけではない。
- 出どころが「途中」の埋める手を減らす。設計では、使う紙を見えるようにするのに動かす紙の枚数（窓ごとの最小値）を費用として見積もる。v0111 は、使う紙の上に重なる紙の枚数を設計の費用に入れて改善した。
- どの紙も常にどこかの窓で見えるようにする構造（B-515）は、出どころが「途中」の埋める手を減らす案である。

## 4. 必要修正効率

種別: 恒等式にもとづく必要条件

### 主張
E=0 で 1 ケースのスコア S を出すには、上被せ手・一部見せ手・埋める手のすべてを含めた全操作の平均で、1 手あたり約 32×1024/S 窓の純修正（直した窓 − 壊した窓）が必要である。

| 目標スコア | 手数／注文 | 必要な純修正（窓／手） |
|---|---|---|
| 15,000 | 14.65 | 2.18 |
| 13,000 | 12.70 | 2.52 |
| 10,000 | 9.77 | 3.28 |

実績は v0030 時点で約 2.12 窓／手である（O-P2-large）。

### なぜ成り立つか
- 1 注文の純修正の和は、初期の誤った窓の数 − 終端の誤った窓の数に等しい。成功が続く限り、初期の誤った窓の数は前後の商品のハミング距離になる。
- 黒が 32 個ずつのランダムな 2 列は、黒の重なりが期待値 16 窓なので、距離の期待値は 2×(32−16) = 32 窓である。全体の純修正は約 32R になり、これを T で割った値が必要な効率になる。
- 誤注文を許しても、この要件は緩まない（O-P2-theory）。

### 実装上どう効くか
- 新しい構造や方策の見込みは、1 手あたりの純修正で比べる。都合のよい数例ではなく、すべての手を含めた平均で測る。
- 1 手で多くの窓を直せても、その紙を掴めるようにするための埋める手が増えれば効率は下がる。10,000 の水準なら、2 手の組で合計約 6.55 窓、3 手の組で約 9.83 窓を直す必要がある。
- 理論面では、「どんな設計と操作を使っても、1 注文あたりこの手数以上はかかる」と証明できている値が、公開入力 0000 で約 1.83 手しかない。実績の約 15 手との間には大きな隙間があり、10,000 が達成できるかどうかは理論からは分からない（O-P2-theory）。

## 5. 可視紙の上限

種別: 定理

### 主張
操作できる（見えている）紙は、常に高々 N=64 枚である。見えている紙の色は、その窓の表示色そのものである。

### なぜ成り立つか
見えている紙とは、ある窓で穴でない紙のうち一番上の紙である。各窓の一番上は1枚なので、見えている紙は窓の数を超えない。窓に表示されるのはその紙の色である。紙の形によらず成り立つ。

### 実装上どう効くか
- 少なくとも K−N=128 枚は常に掴めない。注文に隠れた紙が必要なら、構造によらず、それを見えるようにする手が要る。
- 常に見えている紙を増やすことは、表示に出る紙を増やすことと同じで、その紙の色を合わせる手を払う。
- 次に必要な紙が 192 枚に一様に散らばっているなら、見えている紙を最大の64枚にしても、その紙が見えている確率は約1/3である（prefix の現状は約23.5枚、約12%）。必要になりやすい紙を見える位置に集める設計なら、この確率は上がりうる。

## 6. prefix 紙の最短手順 DP

### 主張

prefix 紙だけの山では、表示可能な目標に対し、現在の積み順から **1注文を完成させる最短手数と合法な手順**を求められる。同じ手数でも終了時の積み順によって次の注文の費用は変わる。

### 固定した表示順の最短手数

完成時に見える紙を上から順に固定する。第2節より、その長さは狭義に増加する。長さ `L` の紙の次に長さ `H` の紙を置くなら、新たに見える窓 `L` から `H-1` がすべて目標色でなければならない。先頭では `L=0` とする。

1. **必ず動かす紙を数える。** 完成時に見える各紙について、開始時にそれより上にある同じ長さ以上の紙に印を付ける。これらは対象の紙を完全に隠すため、その紙を掴むにも、据え置いて最後に見せるにも、必ず動かす。複数の紙を隠していても1枚と数える。
2. **残った順序違反を数える。** 完成時に見える長さ `H` の紙に印がなく、その上に長さが `L` より大きく `H` 未満の無印の紙があれば、もう1手が必要になる。そのままでは後者が窓 `L` を隠すため、少なくともどちらかを動かす。同じ `H` にこうした紙が何枚あっても、`H` の紙を動かす候補に1枚加える。異なる段の長さ区間は重ならず、各段が要求する追加の1手は別々に必要である。

例えば、上から `0.`、`0.`、`11` の山で目標が `11` なら、必須の印は0枚、追加は1枚である。右窓から `11` を掴んで先頭へ移すと、上の2枚を同時に追い越して完成する。

### 下界を達成する手順

印を付けた紙と追加した紙のうち、現在最も上にある1枚を取る。上に同じ長さ以上の紙があれば、それも選んだ表示紙を隠すか、選んだ必須紙と同じ表示紙を隠すので、先に取る対象だったはずである。よって選んだ紙は掴める。

- 完成時に見えない紙なら底へ移す。これでその紙の印が消え、新しい順序違反は生じない。
- 完成時に見える紙なら、完成順で先行する表示紙のうち、**現在の山で最も深いものの直下**へ挿す。先行紙がなければ先頭へ置く。移した紙は先行紙を隠さず、その上に残る長さ `L` 超の紙は、最も深い先行紙（長さは `L` 以下）を隠すため既に印を持つ。したがってこの段に追加の1手は残らない。他の紙の印も変わらない。移動前にこの紙だけを隠す必須紙が上にあれば、そちらを先に選んでいたはずである。

どちらの操作も選んだ1枚だけを移動候補から除く。候補が尽きると、各表示紙より上の紙はすべて直前の表示長 `L` 以下になり、指定した窓が見える。よって「印の枚数＋追加が必要な段数」が、その表示順に対する最短手数になる。

### DPで選ぶ範囲

DPは目標色に合う表示紙を順に選び、上の手数が最小の列を求める。状態には、確定した表示長と、それまでに選んだ表示紙の開始位置の最大値を持つ。後者があれば、次の段の長さ区間に属する紙のうち、先行する表示紙を隠すものを数えられる。最長の紙より右は常に背景の白で、全穴紙は計算から除ける。[実装](../adhoc/bin/probe_prefix_planner.cpp)・[独立な幅優先探索との照合](experiments/v0023.md)

窓を並べ替えて全紙が prefix になる場合にも同じ議論を使える。紙の印字範囲が互いに交わらない窓群に分かれ、各紙が一群に収まり、群内では prefix になる場合は、群ごとの最短手数を足せる。他群の紙は把持を遮らず、一方の群内の移動は他方の相対順を変えない。一般の穴あき紙では、上から `1.`、`.0`、`01` のように、どの1枚も下の紙全体を覆わなくても2枚で完全に隠せる。長さだけでは必ず動かす紙を判定できない（第3節）。

## 7. 上から紙を選ぶ貪欲法による表示可能性の判定

種別: 定理

### 主張

完成した山の上から順に、まだ色が決まっていない窓に目標色だけを見せる紙を選べば、バーコードを作れるか厳密に判定できる。穴の位置は任意でよい。

商品 `v` に対し、紙 `k` の印字窓を $I_k=\{j\mid S[k,j]\ne\texttt{'.'}\}$、そのうち誤色の窓を $D_k=\{j\in I_k\mid S[k,j]\ne A[v,j]\}$ とする。確定窓 $C$ を空集合から始め、$D_k\subseteq C$ かつ $I_k\setminus C\ne\varnothing$ の紙を任意に1枚選び、$C\gets C\cup I_k$ とする。これを繰り返し、停止時の未確定窓がすべて「全紙が穴で目標は白」なら表示可能、それ以外は表示不能である。

### なぜ成り立つか

選んだ紙を順に下へ置けば、新たに見える窓はすべて正色になる。確定窓が増えるほど下の紙の誤色を隠せるので、選び直しは要らない。完成順があるなら、未確定窓に印字する最上の紙は必ず選べる。したがって、印字のある窓を残して止まれば完成順は存在しない。

### 実装上どう効くか

- `N=64` では各集合を64ビット整数で表せる。全 `K` 枚の走査で更新があれば少なくとも1窓が確定するため、停止確認を含めて `N+1` 周以内、全 `P` 商品を $O(PKN)$ で判定できる。
- 表示可能なら任意の初期順から高々 `K` 手で完成する。選ばなかった紙を完成順の末尾に足す。全穴紙を除き、未処理紙を上から1枚ずつ取り、未処理紙すべての下へ、処理済み紙が完成順に並ぶように挿せばよい。各紙を動かすのは高々1回である。

### 設計時に1マスの印字を変更できる条件

全商品を表示できる紙の組で、印字済みの1マス `S[k,j]` だけを変更する。紙 `k` を抜き、商品 `v` に対して上の貪欲法を最後まで適用したときの確定窓の集合を $C_v$ とする。

$j \in \bigcap_v C_v$ は、どの商品でも紙 `k` を使う前に窓 `j` を目標色で覆えることを表す。全商品の表示可能性を保つうえで、この条件は次のように使える。

- **白黒を反転する場合は必要十分条件**である。
- **穴にする場合は十分条件だが、必要条件ではない。** 上から覆えなくても、穴を通して目標色が見えれば表示は保たれる。

**両方に共通する十分性。** 各商品について、貪欲法で選んだ紙をその順に上に置き、残りを元の完成順に並べる。選んだ紙が見せる色はすべて正しく、変更したマスは隠れる。

**白黒反転の必要性。** 反転前後とも商品 `v` を表示できるとする。どちらか一方では `S[k,j]` が目標色と異なるため、その完成順では紙 `k` より上の紙が窓 `j` を目標色で覆っている。よって $j \in C_v$ であり、これは全商品について成り立つ。[v6045の導出](experiments/v6045.md)

## 8. 再移動の必要性

種別: 定理（反例による）

### 主張

同じ注文内で同じ紙を2回動かすことが、最短手数の達成に必要な場合がある。各紙を高々1回しか動かさない制限は、第7節の表示可能性を保つが、最短手数を保たない。

### なぜ成り立つか

3窓・6枚の例を示す。`0` は白、`1` は黒、`.` は穴、積み順は左が上である。

```text
紙       C = 100（1枚）   Q = .1.（4枚）   A = 0..（1枚）
初期順   C Q Q Q Q A
目標     000
```

左窓を白にするには `A` が `C` より上、中央窓を白にするには `C` が全 `Q` より上に必要である。したがって完成順は `A C Q Q Q Q` に限られる。

**再移動を許すと最短3手。** 最初に `C` をどけて `A` を露出させ、最後に右窓から `C` を掴んで全 `Q` をまとめて覆う。

```text
C Q Q Q Q A  →  Q Q Q Q A C  →  A Q Q Q Q C  →  A C Q Q Q Q
                 Cを底へ          Aを先頭へ         CをAの直下へ
```

2手では完成できない。初手で掴めるのは `C` だけなので、残り1手で `A` を全 `Q` より上にするには `A` を動かすしかない。ところが `A` が掴めるのは `C` を底へ移した場合だけで、その状態から `A` を動かしても `C` は全 `Q` の下に残る。

**各紙を高々1回に限ると最短5手。** 初手で `C` を底へ移さなければ、`A` は `C` に隠れたままになる。底へ移した後は `C` を再移動できないため、4枚の `Q` を上から1枚ずつ `C` の下へ移す必要がある。これでちょうど5手となる。[全探索による検証](../adhoc/bin/probe_laminar_repeated_moves.cpp)

### 実装上どう効くか

任意形状の紙で最短手順を探索するときは、**各手の後の可視性で移動候補を決める**。同じ注文内ですでに動かした紙も、現在どれかの窓から見えていれば候補に含める。
