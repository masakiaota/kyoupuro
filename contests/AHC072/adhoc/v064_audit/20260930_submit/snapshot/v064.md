# v064: 関係操作を絞った区間再構築を提出用探索へ追加する

## 実験前（2026-09-30）

- 根拠: B-80、O75、O78、重要な性質3・4・7〜9。長いケースの保存改善には64操作で閉じないものが多く、v062では最大452操作にまたがる専用短縮が成立した。ユーザーから、試す価値のある案をAtCoder提出版にして実験する指示を受けた。B-84として、v063の方式を最優先で組み込む。
- 仮説: 少数個体に関係する操作だけを探索の時間層として扱い、途中の全盤面へ再接続する除去・再挿入を加えると、長い手順でも短縮や同手数の組み替えを低費用で生成でき、通常2秒版の完成スコアが改善する。
- 変更: 完成版の直接の親はv059。構築、修復負担による順位、既存近傍、候補短縮、受理式、最終処理を引き継ぐ。v063から任意終点への逐次再挿入と無関係な背景操作の省略を移す。保存解や既知の改善区間を本番へ入力せず、探索中の現在解と既存の候補集合から区間を自動選択する。v062の専用短縮やB-82の順位計算の高速化は含めない。変更はLOCALと非LOCALの両方で有効。
- 機構確認: LOCALあり・なしをビルドし、登録差分を戻した親とのソース一致と完全な前処理結果の一致を確認する。任意終点、帰巣、塔の途中への挿入、同乗、独立操作の省略の人工例を検証する。64操作を超える人工区間で、対象外の操作を保存し、塔が残る出口へ短く再接続できることを、省略しない対照とともに確認する。保存v059の指定6解では各64回だけ新しい近傍を呼び、完成した候補の合法性、E=0、手数非増加、乱数消費0、盤面領域の返却を検証する。完成候補1件以上と背景操作の省略1回以上を通常評価へ進む条件にする。短縮の大小に応じた設定変更は行わない。
- 採否基準: 機構確認後、`tools/in`の100件をLOCAL、時間補正0.80、`-j 2`で1回評価する。全件合法、E=0、100,000操作以下、最大2,000 ms以内、0000が43手以下、構築・LNS・不正候補・作り直しのエラーと盤面領域の未返却0を必須とする。通常評価でも新近傍の受理1件以上、背景操作の省略1回以上を確認する。保存v059より全100件の合計Tが小さく、事前指定の長い14件の合計Tが悪化しなければ今回の比較で採用する。未発動と効果不足は分ける。親や同一版の再評価によるノイズ測定は行わない。

## 区間と候補の選び方

1. v059の現在の候補順位から1〜4匹の集合を先頭64件まで取り、独立した巡回番号で選ぶ。新処理自身は乱数を消費しない。
2. 対象個体を運ぶ元操作の時刻から開始点を巡回選択する。その時点ですべての対象が残る条件を使い、親の16操作ごとの盤面記録から入口を復元する。
3. 対象が元の出発塔や着地塔に含まれる操作から対象マスを増やす。対象12マス以下、そこに接触する操作32以下を保てる最大の接頭区間を作る。後からマスを加えた場合は、それ以前の背景操作も数え直す。対象全員が帰巣した場合はそこで止める。区間全体には64操作の上限を設けない。
4. 同じ入口と出口の全盤面を保って対象を除去し、1匹ずつ戻す。元の出口の位置と段を再挿入先に使う。同色個体の出口交換を網羅するとは主張しない。追加移動と同乗は対象マス内に制限し、その外側だけに触れる背景操作は盤面へ適用しつつ探索の時間層から省く。
5. 除去後の修復は元区間+4手まで、再挿入後の総手数は元区間以下とする。対象のID順から全順列を調べ、短いものを優先し、元と異なる同手数候補も保持する。完成した候補だけを外側へ接続して既存の短縮と受理へ渡す。

診断版にあった全候補の再列挙と外部ファイル出力を本番へ移さず、既存候補と作業配列を再利用する。探索範囲の上限、失敗した段階、同手数候補、直接削減、受理後の最良更新を区別して記録する。

## 時間配分

64反復ごとに新近傍を選び、その反復の既存近傍を置き換える。新近傍の総予算はLNS経過時間の3%、初期猶予は`PROGRAM_TIME_LIMIT_SEC * 0.02`の3%とする。1回の上限は`PROGRAM_TIME_LIMIT_SEC * 0.001`で、累積予算の残額と親LNSの期限でも制限する。準備、候補選択、盤面復元、検証も計測へ含める。期限終了時は、その呼び出しで既に完成した候補だけを返す。未完成の候補は出力しない。

再挿入のリンク生成上限200,000件はv063から保持する。通常経路の処理失敗を別解で隠す分岐は追加しない。時間と状態数による打ち切りを計数し、不変条件違反はエラーとして表に出す。solverは単一C++ファイルで、外部データ不要、単一スレッドとする。
