# v035: v028の地形参照を保ってTower配列を床数別容量にする

## 実験前

- 根拠: B-45、Q8とv034の測定。v033の構成は容量400でも元のv028より10.320%遅かった。一方、同じ構成内でTower配列だけを縮めると保存量が平均47.636%減り、固定候補の合計時間は1%以内の非劣性を満たした。ユーザーから、遅延を生んだ構成変更を持ち込まず、Tower配列の容量削減をv028へ取り入れて新しい実験の検証まで行う指示を受けた。backlog全体とv001〜v034のFront Matterを照合し、v028、v033、v034の関連記録を確認した。
- 仮説: 共有地形への直接参照と容量に依存しない処理を保ち、複製するTower配列だけを床数以上の32刻みに縮めれば、v028の主処理を悪化させず、省メモリ化と一部のコピー処理の高速化が得られる。短縮した時間を探索に使える場合は、完成スコアも改善し得る。
- 変更: v028を直接の親とし、通常Boardを容量別の固定長配列にする。Geometryは元のグローバル実体と配置を保ち、共有ポインタを加えない。読み取り専用の初期配置はGeometry内の400要素を保ち、試行盤面を作るときに必要な容量だけコピーする。WorldとConstructorを容量別の型にし、TemporalLNSはTower配列を扱うメンバー関数だけをテンプレート化する。容量に依存しない探索の補助型は共有し、探索全体を包むSolver型は作らない。個体ID盤面、距離表、他の作業配列、塔の32 bit表現と操作、探索方針、乱数、最適化設定、時計と時間配分はv028を保持する。変更はLOCALありとなしの両方で有効である。v000と既存solverは変更しない。
- 機構確認: LOCALありとなしをビルドし、完全な前処理結果とソース差分を保存する。容量に無関係なクラスと塔の操作が親と一致し、Geometryへの直接参照が残ることを静的に確認する。全13容量と全400床数の選択、保存済み100ケース20,894操作、38境界盤面の内容を照合する。固定時計で全100件の出力、共通計数、乱数状態、時計呼び出し数を親の保存診断と一致確認する。同じ候補処理でも成否と全操作列を照合し、生成命令を確認する。LOCALログに選択容量とBoardの保存量を加える。
- 採否基準: 全件の内容一致を必須とする。固定候補の通常99件合計CPU時間の5巡中央値と全5巡が、元のv028比で1%以内の増加なら速度の非劣性を確認する。中央値が1%以上短く、5巡中4巡以上で短ければ速度改善を確認する。容量400の対照版が同基準を満たさない場合は、導入時の構成変更の影響を避けたとは判定しない。通常評価はtools/in全100件、LOCAL、時間補正0.80、既定並列数2で1回のみ行う。公式採点と独立再生の全件成功、E=0、100,000手以内、最大2,000 ms未満、構築とLNSのエラー、不正候補、初期解と最終解の作り直しの計数0を必須とする。速度の非劣性と必須条件を満たし、保存済みv028より合計Tが増えず、case0000が43手以下なら提出候補として採用する。小差の恒常的なスコア改善までは断定しない。

## 比較条件と実行順

1. ソースを確定し、静的照合と両ビルド、生成命令の確認を行う。
2. 保存操作の再生と固定時計で挙動を照合する。固定時計は1回の読み取りを100,003 nsとし、親のv033診断に保存された出力と比較する。
3. 固定候補で、元のv028、v035の容量400、v035の床数別容量を比較する。v034と同じ100ケース6,357候補を使い、前回の保存チェックサムとも照合する。
4. 1巡のウォームアップを除外し、実行順を巡回ごとに入れ替える5巡を一度の計測計画として実施する。主計時はCPU時間、実経過時間は補助指標とする。通常99件の合計を主指標とし、ケース別と容量別の逆転も残す。
5. ソースを変更せず通常評価を1回実施し、結果と考察を記録する。実行結果を見て実装や採否基準を調整しない。

固定候補の区間は候補とチェックポイントの生成、除去から2通りの再挿入まで、経路短縮とする。入力準備、地形構築、内容照合は計測外とし、補助コードでは時計による打ち切りを無効にする。測定は非LOCALの単一プロセスで行い、評価用ロックを使う。v028の保存評価は`20260927T184531+0900_v028_two_order_lns_c6311b`を比較対象とし、親の通常評価は繰り返さない。

## 実行前の実装確認

最初の実装では、共有地形を元の実体に戻しても、TemporalLNSを容量別のクラスにすると、insertAtの静的な呼び出し箇所が親の40箇所から62箇所に増えた。まだ解法プログラムは実行していない。TemporalLNSはBoardをメンバーに持たないため、クラスと補助型を元の共有型に保ち、配列が必要な関数だけをテンプレート化する。仮説と採否基準は変更しない。修正後の同じ測定用実行ファイルでは、親のinsertAtが2,155命令と50呼び出し箇所、v035の容量400が1,342命令と32箇所、容量192が1,353命令と32箇所だった。命令数は次のシンボルまでの静的な数であり、実行回数や速さを示さない。速度の判定は事前登録した測定で行う。
