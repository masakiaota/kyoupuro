## 全体計画として確認したこと

### 共通区間に入る前の合流

0025では色0と色2を同じ列に沿って南へ運び、下側で左右の巣へ分けた。一方を先に単独で送り出すと、同じ区間をもう一度運ぶ必要があった。両方が途中の同じマスへ来るまで待ってまとめることで4手短縮できた。

0033でも、合流後に西へ運ぶことを先に決め、その共通区間が長くなる場所で合流させると2手短縮できた。どちらも既存の混載・合流の性質を複数の輸送へ適用した例であり、新しい不変量ではない。

### 逆方向へ進む輸送の順番

0035では、南側の色0と色3は北へ、色4は東へ帰す必要があった。色4を先に送る案と、色0・色3を集めてから発射台として利用する案を全帰巣まで比較した。後者は、色4の長距離移動と北へ帰す塔の集約を両立し、3手短くなった。

ただし、保存済みv037の63手解には、途中に置いた混色塔を利用した長距離移動、複数色の共輸送、南側で集めた塔から色4を6マス送る操作、その後の北への回収が既に含まれていた。手動で気づいた連携を、既存実装に欠けている戦略とは扱えない。

### 発射後に残る塔の回収

0025では、踏み台も荷物と同じ方向へ帰る局面で、踏み台ごと途中まで運んだ方が全帰巣まで2手短かった。0033では荷物の一部を残して先行便を飛ばすと、その1匹の後続輸送が必要となり、既存の踏み台まで全員を運ぶ案より4手多かった。

この比較は、飛んだ荷物だけでなく、残った塔の移動まで含めて経路を選ぶ必要性を再確認したものだ。踏み台の回収費という既存の問いに当たり、新しい定理としての追加は行わない。

## 共通経路を使った再構築候補の診断

手動例から、「初期位置が近い集合に加え、将来同じ長い区間を通る集合もまとめて再構築する」という案を考えた。solverへ組み込む前に、保存済みv037の100解を個体単位で再生し、次の厳しい条件を満たす組を数えた。

- 異なる2つのまとまりが、向きと両端の座標が一致する3区間を、それぞれ続けて通る。
- 両者に同じ個体は含まれず、合計8匹以下で2色以上となる。
- その個体集合が、既存解の途中で一つの塔になったことがあるかも調べる。

該当したのはcase0005の1組だけで、その個体集合は既存解で既に同じ塔になっていた。したがって、この条件から未接触の集合を追加する機会は確認できなかった。新しいsolver実験へ進む根拠としては弱いため、厳密に一致する3区間を候補追加の起点とする案は取り下げた。

この診断は、近い別経路、飛距離の分け方が異なる経路、現在解に現れていない迂回や合流を調べていない。また、該当した1組についても合法な同乗や手数短縮を保証しない。広域の共同再構築全般を否定する結果ではない。

診断コードは `adhoc/scripts/inspect_shared_routes_20260928.py`、結果は `shared_routes.json` にある。solverの変更・再実行は行っていない。次にこの案を検討するには、既存解で別々に運ばれている集合について、全体の手数を実際に短縮する具体例が必要である。
