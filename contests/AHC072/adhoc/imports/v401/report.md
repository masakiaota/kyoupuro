# v401: 帰巣なしCNNの厳密差分更新

## 実験前

- 仮説: B-159（O14・O15・O40・O47、cloud_survey_20261004.md）。E不変の操作で入力と4層の影響マスだけ再計算すれば、同一方策の推論費用が減り、変更しない既存LNSに使える時間が増える。
- 変更: v311のみを直接の親とし、入力投影と4残差ブロックの活性値を検索単位で保持する。前回bitsとの比較で変更床を特定し、3x3依存関係で毎層広げる。初回・E変更・明示無効化は全量更新。積和・global poolingの床順、重み、方策、合法手、同点規則、対称生成、育成・LNSを保持。特徴生成そのものは親を保持。追加戦略・学習なし。LOCAL/非LOCALとも機構有効。非LOCAL時計・定数は親を厳密保持。LOCALだけcloud基準と同じLOCAL_TIME_RATIO=1.90/1.930（最終1.900秒）とする。
- 機構確認: 親全量encodeを独立参照にし、入力と各層活性値・global/value・logitsをbit一致で確認、固定step時計で選択手と完成NN列を比較する。tools/inの全100件を原方向で診断（通常スコア評価とは別）。各層処理床数、初回/E変更/強制無効化の発火を記録。固定された同じ状態列で全量と差分のencode費用を測る。失敗時は機械的な誤実装のみ修正し、別仮説・スコア起因改良へ移らない。LOCAL/nonLOCALビルド、完全前処理差分、重み同一性、独立合法性確認も行う。
- 採否基準: 機構確認を通過し、tools/in100を1回だけ共通1.9秒LOCAL・-j8で評価、全件合法E=0・既存エラー0を必須とする。外部時間は基準同様の起動/出力超過を含め記録し、2秒超があれば採用しない。絶対合計手数が基準v311以下、固定参照指数が100より厳密に改善なら採用候補。固定参照はresults/analysis/cloud_baseline/fixed_reference.json（SHA256 71f2c83402b7f84663a10d735fb1768009e37f7e65ca333c954a6f300ed98d35）、指数=100*mean(reference_score/candidate_score)、切り詰めなし。公式順位の相対スコアとは区別する。
- 履歴照合: backlog全体と全実験Front Matterを確認、既存静的調査とv311本文を参照。B-159は未着手であり、時間方向のCNN再利用は既存SIMD化と異なる。screen記録はresults/analysis/v401/history_screen.json。保護対象notations/important_propertiesは変更しない。
- 停止: 評価結果を報告したら停止。v402、再評価、スコア起因の変更は新たな明示指示が必要。

## 機構確認とビルド

- 100入力の原方向NN完成列と、step呼出し37回で打ち切る固定時計の列を親と照合し、全件一致した。27,023状態、8,796,854 logits、入力投影＋4層・global・valueはbit単位で一致。帰巣による全無効化3,365回と強制無効化1,638回を確認した。原方向以外の全閉ループ列の直接照合はしていないが、キャッシュはsearchごとに新規生成される。
- 固定状態列のencode時間は全量3.026333秒・差分1.363797秒（2.219倍）。特徴生成・変更判定・影響範囲伝播・cache維持・結果コピー・global再加算を含む。参照を先に測り、層captureを計測外で追加しているため、cache/順序効果を分離した一般的速度比ではない。solver全体の速度比とはしない。
- 初回診断の参照タイマは層captureの追加コピーを含んでいた。この計測専用の誤差を修正し同じ診断を再実行した。solver本体は変更せず、最初の数値2.460倍は採用しない。初回診断も保存し、再診断をscore評価の再実行と混同しない。
- 差分機構の診断処理床数は入力から順に1,144,138 / 1,335,957 / 1,621,532 / 1,988,022 / 2,415,373、全量相当は各層6,239,436（強制無効化呼出しも含む）。本評価では105,928推論中92,640回が差分、12,890回が帰巣に伴う全量更新。処理床数と分母はresult.jsonに保存。
- GCC15.3のLOCAL/nonLOCALビルド成功。非LOCAL完全前処理差分はencode/cache/search呼出しのみ。LOCALでは追加計数もある。LOCAL比較相手は原本0.80ではなく、baseline wrapperで1.90/1.930へ較正済みの保存ソース。同じ最終1.900秒・main探索約1.870466秒である。非LOCALの親タイミング式は無変更。packed重みも同一。静的な別レビューでも依存範囲/E無効化/検索ごとの寿命に誤りなし。

## 実験後

- 判定: **採用候補**（この事前固定In100比較）。リポジトリ全体の採用現行版v214は自動変更しない。
- 結果: 基準v311比で合計68手減（0.340955%改善）、固定基準指数は100から+0.304115ポイント。42勝23分35敗。100件すべて公式採点成功、独立の色配列再生でも合法・E=0・公式score一致。既存construction/lns error、baseline/final recoveryはすべて0、state poolは全件返却。各ケース値と絶対値はresults/analysis/v401/{result.json,paired.csv,records.json}を正本とする。
- 時間: 内部最終期限は全件1900ms。外部平均1902.74ms、最大1916ms、2秒超0件。起動・出力込みで外部1.9秒は全件超えており、厳密な外部1.9秒以内とは報告しない（同条件baselineも平均1902.83ms）。trace total最大1909.235ms。単回のスケジューリング・打ち切り粒度を含む値である。
- メモリ: /procのVmHWMを100ms間隔で採取、観測最大17,608KiB。warmupも含む観測下限であり終了時の厳密peakではない。新しい活性値5層自体は384,000 byte、cacheは検索ごとに確保・破棄。
- 考察: E不変で同一活性値を再利用できる機構は確認でき、完成手数もこの単回比較では改善した。速度差が対称初期解数・LNSの開始/探索経路へ波及するため、68手の差を純粋なcache単独の確定利得とはしない。別入力や実行ノイズの検証は未実施。E変更は全床特徴を変えるため引き続き必須全量更新である。
- 停止: 本評価はwarmupを除き各入力1回のみ。実行結果に基づくsolver改良・パラメータ調整・v402は行わず停止した。
