# v047: 保存解から始める長時間探索と参照手順の蓄積

## 実験前

- 根拠: B-64、O49、O55、O57〜O59、O62。ユーザーから、性質の異なる5〜10ケースを1件30分〜1時間探索する実装、同時に使う探索コアを2以下にすること、ログと実行コマンドの用意を依頼された。実行はユーザーが手動で行う。v001〜v046のFront Matter、backlog、親v039の探索・時計・保存量を照合した。長時間探索の記録基盤は既存実験と重複しない。
- 仮説: v039の再挿入近傍を保存済みの短い解から長時間動かすと、既存の参照解を更新できる。長い1探索と、初期解・乱数を変える複数探索では、改善の続き方と到達する解が異なり得る。
- 変更: v039の再挿入探索・候補生成・受理条件を引き継ぎ、初期構築を保存解の読み込みへ置き換える。実時間の探索予算、乱数種、保存先を明示的な引数とする。改善時の操作列、変更直前の現在解、変更前後の共通区間、近傍の種類、経過時間、CPU時間、乱数状態、定期進捗を保存する。長時間だけ必要になる履歴の掃除は、最大200反復の再試行制限を既に過ぎた項目に限る。不正候補・入出力の失敗を隠さず異常終了する。v000と既存solverは変更しない。
- 機構確認: 今回はLOCALあり・なしのビルド、探索を呼ばない準備処理、保存済み初期解の独立再生、引数・保存・並列上限の検証まで行う。solverは実行しない。ユーザー実行時には、初期解と改善解の合法性・E=0、単調に減る最良T、継続側の1回の探索、再出発側の異なる乱数・初期解、同時子プロセス数2以下、計算時間と進捗の保存を確認する。
- 採否基準: 実装の受け渡しはビルド・準備・保存契約の検証を通過し、ユーザーが1コマンドで起動できること。探索結果は実行前に固定したケースごとの最良保存解と比較する。全成果物の合法性と追跡可能性を必須とし、1件でも厳密な短縮が得られれば参照解の収集として有効、短縮0件なら今回の探索構成では成果なしと記録する。継続と再出発の優劣は、このケース群・時間配分での観測として報告し、準最適性や2秒版への効果は主張しない。実行後の改良は新しい指示を受けてから行う。

## 固定する初期条件

通常生成ケースから次の10件を選ぶ。seed 0は含めない。以前の比較対象5件を保持し、壁、色数、匹数、色の偏りが異なる5件を加える。数値は入力から静的に計算し、実行manifestへ保存する。

| ケース | 選定理由 |
|---|---|
| 0035 | 13匹で、通常99件の最少匹数 |
| 0033 | 壁なし、9色 |
| 0023 | 12色・26匹で色の偏りが小さい |
| 0064 | 4色で最多色が約70% |
| 0060 | 疎な配置・多い壁。既存の連携比較対象 |
| 0066 | 壁率が通常99件で最大 |
| 0068 | 大盤面・少ない色・多い匹数 |
| 0005 | 高密度・多い壁 |
| 0097 | 保存版間に大きな手数差がある比較対象 |
| 0019 | 大盤面・12色・217匹 |

保存済みv020〜v046の通常評価出力のうち、手元に存在し、入力との再生で全帰巣を確認した異なる操作列を準備時に凍結する。短い順に最大8本を保持する。連続探索は最短の保存解から始める。再出発側は、偶数ラウンドで自身の最良解、奇数ラウンドで保存初期解を順番に使う。両ワーカー間で解を交換せず、等しい実時間予算で独立に比較する。初期解を生成する探索は行わない。

## 実行と計時

- ケースを順に処理し、各ケースで単一スレッドC++を2プロセスだけ並行実行する。1つが継続探索、もう1つが既定60秒の再出発探索を繰り返す。ケースの並列実行はしない。OpenMP等のスレッド上限も1へ固定する。
- 既定は1ケース30分。10件で約5時間、60分へ変更すると約10時間となる。準備・ビルド・保存・検証の時間は別途かかる。OSの物理コアへの固定は行わず、同時に計算する探索プロセス数で上限を管理する。
- `JUDGE_TIME_LIMIT_SEC=1.90`、`LOCAL_TIME_RATIO=0.80`、`PROGRAM_TIME_LIMIT_SEC` は共通の値とする。CLIの秒数は実時間であり、`PROGRAM_TIME_LIMIT_SEC` に対する倍率に換算して長時間予算を作る。通常評価のLOCAL補正と既存evalは変更しない。探索期限・温度・近傍の時間配分はその予算に対する割合を使う。
- main開始直後から計時する。1回の長い探索では全時間をかけて温度を下げ、再出発側では各ラウンドで同じ温度曲線をやり直す。2秒版を中断してそのまま継続した比較ではなく、時間尺度と出発点を変えた診断である。
- `results/long_search/v047/<run_id>/` にソース、実行ファイル、入力、初期解、設定とSHA-256、各プロセスの履歴、最良解、集計を置く。通常評価のCSV・JSONL・scratchへ追記しない。同時実行の重複を避けるためevalと同じロックを使う。
- 初期解と改善解は保存前に再生検証し、操作列は一時ファイルからrenameする。Ctrl+Cでは子へ停止要求を送り、保存済みの最良解と途中集計を保持する。異常終了を正常完了扱いにしない。
