# ケース0060の16手差と、踏み台を共有する順序

## 結論

保存済みv022の145手解は、逆向きに帰す束を同じ場所へ集め、互いを踏み台にしている。v039の161手解では、対応する束が別の経路や時刻に運ばれている。改善案を絞るうえでは、合流位置に加えて「踏み台になる束を、誰が来るまで残すか」を探索対象にする根拠になる。

南東で協力する6匹を追うと、v039では全員が盤上にいる間、常に3塔以上に分かれていた。この完成解から作る通常の除去候補と依存拡張には、6匹を一緒に選ぶ集合がなかった。3塔を同時に選ぶ案B-54を具体化する材料である。ただし、6匹が改善に必要な最小集合だとは確認していない。現行の探索でも、複数回の変更を経て同じ構造へ移れる可能性がある。

## 対象と確認方法

- 入力は `tools/in/0060.txt`。`N=17, K=10, M=34`。
- 比較は `results/out/v022_dependency_lns/0060.txt` と `results/out/v039_exact_board_lns/0060.txt`。
- 保存された操作だけを再生し、全操作の合法性と最終的な `E=0` を確認した。solverは実行していない。
- 個体IDを付けた再生結果を、既存の色だけの再生器と全操作で照合した。個体ごとの移動距離と、巣までの距離の増減も照合した。
- 本文と `case0060_pair.json`、個体ID付き操作表は、座標と操作番号を0-basedで表す。塔は下から上の順で書く。`a1` などの添字は、同色の個体を初期盤面の行順で区別する、この分析だけの番号である。

| 項目 | v039 | v022 |
|---|---:|---:|
| 操作数 `T` | 161 | 145 |
| 未帰巣数 `E` | 0 | 0 |
| 2マス以上のジャンプ | 23 | 28 |
| 混色の束を動かす操作 | 85 | 74 |
| 総輸送量 `W`（匹×マス） | 701 | 681 |
| H色の輸送量（匹×マス） | 202 | 162 |

H色の輸送量は差を探す手掛かりになったが、輸送量と手数は別の量である。北側の操作数は同じであり、H色の遠回りだけで16手差を説明することはできない。

## 16手差の場所別の内訳

| 操作の場所 | v039 | v022 | v039の増加分 |
|---|---:|---:|---:|
| 南西 | 35 | 27 | +8 |
| 南東 | 23 | 18 | +5 |
| 中央の横通路 | 35 | 32 | +3 |
| 北側 | 68 | 68 | 0 |
| 合計 | 161 | 145 | +16 |

分類は次の順で行った。出発か着地が9行目より南なら南側とし、そのうち両端が10列目以東なら南東、それ以外を南西とした。南側に入らず両端が9行目なら中央、それ以外を北側とした。全操作を重複なく数えている。

これは差の所在を示す会計である。各地域の入口や出口の塔は2解で異なるため、「その地域だけを置き換えれば、この手数が減る」という因果的な寄与ではない。

## 南東：A色の帰巣を、北へ戻る5匹の踏み台に使う

v022では、A色2匹が南へ帰る途中で、北へ戻したい個体と合流する。

| 操作番号 | 動作 | 残す踏み台 |
|---:|---|---|
| 67 | A色2匹とH色1匹を `(10,15)` から `(13,15)` へ3マス南へ飛ばす | D色1匹とH色1匹 |
| 68〜70 | `(14,15)` に集め、横から来たC、H、E色を載せる | 合流後の塔は `A A H J C H E` |
| 71 | 上の5匹 `H J C H E` を `(14,15)` から `(11,15)` へ3マス北へ飛ばす | A色2匹 |
| 73〜74 | 残ったA色2匹を2手でAの巣へ帰す | なし |

この操作71の直前は、次の配置である。

```text
(11,15)  北へ戻る5匹の着地点
    ↑
    │  3マスを1操作で移動
    │
(14,15)  下 [A A] [H J C H E] 上
               └踏み台┘ └移動する5匹┘

残るAの2匹は (14,16) → (15,16) と動いて帰巣する。
```

v039では、南東のC、E、H、J色の4匹を先に北へ運ぶ。A色2匹が `(9,15)` から帰巣を始めるのは操作154で、そのとき `(10,15)` のD色とH色はすでに移動している。Aの束は7手をかけて帰巣する。v022のA色2匹は、同じ `(9,15)` からの帰巣に5回の移動を使い、途中で北向きの輸送も助けている。

## 南西：4匹を残し、5マスジャンプを2回使う

v022は `(9,1)` に `F I C H` の4匹を残す。

1. 操作81で、その上のD色3匹を `(14,1)` まで5マス飛ばす。
2. 操作84で、後から来たG色3匹とD色1匹も、同じ踏み台で5マス飛ばす。
3. 南側へ運んだD色4匹を使い、操作95でH、C、B色の3匹を `(12,1)` から `(9,1)` へ3マス北へ戻す。
4. D色はその後に帰巣し、F色とI色も残りの輸送を進める。

南へ運ぶ束と北へ戻す束が、異なる時点で踏み台役を交代している。南側のH色とC色の回収も、この流れに組み込まれている。

v039では、F、I、C、H色の束が先に南側へ入り、H、C、B色の束と合流して中央へ戻る。D色とG色の7匹が `(9,1)` に揃う操作129の時点では、この4匹は別の場所へ移動済みで、F色は操作125で帰巣している。D色とG色はまず3回の1マス移動で `(12,1)` へ進む。

南西の8手差には、D色とG色の輸送だけでなく、H色とC色の回収経路の違いも含まれる。

## 現行探索が一度に選ぶ範囲

南東の構成に参加した、A色2匹とC、E、H、J色各1匹の計6匹を追った。v039の操作23直後には、次の3塔に分かれている。

| 位置 | 対象の個体 |
|---|---|
| `(4,11)` | A色1匹 |
| `(9,15)` | A色1匹 |
| `(13,11)` | C、E、H、J色の4匹 |

6匹全員が残る79個の境界状態を調べると、対象を含む塔数は最小でも3だった。v022では操作70直後に、この6匹と別のH色1匹が `(14,15)` に合流している。

v039の `makeCandidates` と `growDependency` の集合生成規則を、保存済み161手解の軌跡に適用した。移動の生成や再挿入は行っていない。

| 調べた候補 | 集合数 | 対象6匹をすべて含む集合数 |
|---|---:|---:|
| 通常の除去候補 | 191 | 0 |
| 各候補を依存関係で拡張した後の異なる集合 | 155 | 0 |

1塔の分解再挿入と2塔の再挿入でも、この完成解の同じ境界から6匹全員を一度に選ぶことはできない。通常の依存拡張は「除去で壊れる既存の長距離ジャンプ」を追うので、まだ存在しない協力関係を直接指定する仕組みにはなっていない。

一方、近い初期個体を組み合わせる候補と、相手の塔を選ぶ2塔近傍は既にある。「まだ会っていない相手を一切選べない」という意味ではない。今回の診断は完成解1本に対するもので、探索途中の候補、受理、複数段階の移行可能性は調べていない。

対応するコードは `src/bin/v039_exact_board_lns.cpp` の `growDependency`、`insertAt`、`pairedNeighbor`、`makeCandidates` である。1匹ずつの再挿入では背景の操作を固定し、追加手数を優先する。ただし、この6匹を選んだときに再挿入が失敗するか、同時探索なら何手になるかは未検証である。

## 次に確かめる範囲

B-54の具体的な対象は、「逆向きの輸送を行う3塔をまとめて選び、合流と踏み台役の交代を作れるか」とする。根拠は重要な性質3の踏み台の再利用と、今回の保存解比較である。

まず0060の南東について、候補を選べないことと、選んでも1匹ずつの再挿入では作れないことを切り分ける。この結果で、3塔の候補追加で足りるか、操作列を共同で探索する必要があるかを判断する。

前回案の「短区間」には注意が必要である。2解では合流の時刻も帰巣の順序も広く変わっており、同じ開始盤面と終了盤面を持つ短区間の置換で16手減らせるとは確認していない。

前回の順位表換算で20位との差は平均約6.9手だった。0060には16手短い既存解があるが、これは1ケースを選んだ比較である。3塔を選ぶ変更の平均改善量や、20位以内への到達可能性はまだ分からない。
