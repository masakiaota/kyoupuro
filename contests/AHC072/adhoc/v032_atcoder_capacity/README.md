# AtCoderコードテスト用のコピー比較

現在のソースは **revision 2** である。初回のAtCoder出力ではCPU時間が約1 ms刻みとなり、多くの計測区間が0だった。比較処理を維持し、主指標を `steady_clock` の経過時間に変更した。初回の時間比は速度の判断に使わない。

## 実行方法

1. [v032_state_capacity_atcoder_bench.cpp](../bin/v032_state_capacity_atcoder_bench.cpp) の全文をコードテストのソース欄へ貼る。
2. 言語を `C++23 (GCC 15.2.0)` にする。
3. 標準入力を空にして1回実行する。
4. 冒頭の `revision=2` を確認し、CPU・コンパイラ表示から末尾の `verified=YES` まで、標準出力全体を保存する。

ソースは単一ファイルで完結する。プロジェクト内のヘッダー、入力ファイル、保存解は不要である。

## 結果の読み方

| 列 | 意味 |
|---|---|
| `floors` | 床数 |
| `capacity` | 32刻み固定配列の容量。最大400 |
| `pool` | 事前確保して循環利用するコピー先の状態数 |
| `task` | `copy` はコピーのみ、`copy_tower_op` はコピー後に2塔の分割・反転・結合・帰巣を行う |
| `fixed_ns` / `exact_ns` | 1回あたりの経過時間。各4区間の中央値、単位ns |
| `exact_over_fixed` | ぴったり配列の時間 ÷ 固定長配列の時間。1未満ならぴったり、1超なら固定長が速い |
| `exact_faster_rounds` | 4区間のうち、ぴったり配列が速かった区間数 |
| `timing_status` | 時計の刻みに対して区間の長さが足りれば `OK`。短すぎれば `TOO_SHORT` とし、時間比と勝数は `NA` |
| `fixed_base_mod64` / `exact_base_mod64` | コピー先の先頭アドレスを64で割った余り |
| `fixed_samples_wall_ns` / `exact_samples_wall_ns` | 4区間それぞれの経過時間を `|` で区切った値。1区間16,384回分。優劣とばらつきはこの値で確認する |
| `fixed_samples_cpu_ns` / `exact_samples_cpu_ns` | 同区間のCPU時間。診断用に残すが、0でも速度の判定や割り算には使わない |

例えば比率0.90はぴったり配列が10%短時間、1.10はぴったり配列が10%長時間という意味である。後者は固定長が約9.1%短時間となる。

床数は32〜400の24サイズ、保存先は1・64・8192状態、処理は2種類で、計144条件を出力する。各区間の直前にウォームアップし、両方式の計測順を交互にしている。全コピー先とコピー元、チェックサムを計測外で検証し、最後まで通過したときだけ `verified=YES` を表示する。これはデータの正しさの確認であり、計時の精度を保証しない。

`observed_wall_step_ns` は、起動時に時計を8,192回読んだときの最小の正の差である。最短の計測区間がその200倍以上ある条件を `OK` とし、その条件数を末尾の `clock_ok_conditions` に表示する。`OK` でも割り込みや待ち時間は含みうるため、全4区間の生の値を併せて確認する。CPU時計の読み出し自体は経過時間の計測区間に含めない。

## 比較の範囲

固定長は `array<Tower, capacity>` の通常代入、ぴったり配列は実行時の床数を長さに使う `memcpy` である。両方式とも領域を先に確保し、計測中には確保・解放・初期化を行わない。`noipa` により、ぴったり版の床数が呼び出し側の定数から特殊化されることを防ぐ。コピーと書き戻しの消去も両方式で同じように防いでいる。

塔操作にはv000と同じ4 bitの表現と更新を使う。着地点と巣は指定済みとし、`Board.ray` の参照、合法手の生成、探索、スコア計算は含まない。盤面は人工データなので、v030の実100件の測定と同一条件ではない。

今回の目的はx86環境で勝敗が変わる条件を調べることである。3%未満の差は同程度とし、4区間中3区間以上で同じ側が速いことも確認する。人工サイズの平均を実際の入力分布やsolver全体の高速化率とは扱わない。

実験の事前登録と進捗は [v032](../../notes/experiments/v032.md) に記録する。[AtCoder初回出力](atcoder_revision1.txt) と [初版ソース](source_revision1.cpp.txt) は診断用に保存した。修正版はAtCoderの全144条件で計時が成立した。[修正版の結果と床数別の詳細表](atcoder_revision2_summary.md) を参照する。

ローカルの `--check` 引数は計時を行わず全条件を検証するためのものである。コードテストでは引数も標準入力も不要である。
