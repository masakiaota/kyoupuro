# v046: 共用経路へ運び込み、途中の合流と分離を続ける構築

## 実験前

- 仮説: 全個体の帰巣先から色ごとの輸送路を決め、同じ方向へ流れる区間を色をまたいで共用すれば、枝からの運び込みを共同輸送へ結び付けられる。合流後も最初の分離・帰巣・中継地点で制御を戻し、残った荷物と別の荷物を合流させることで、便ごとの完了と集荷の往復を避け、完成Tを下げられる。
- 根拠: O2、O9、O18、O24、O50、O57、O60、Important Properties 3〜9、およびv045に対するユーザーの訂正。v045は初期個体の位置へ束が出向く集荷と便ごとの全帰巣を使い、求められた途中の共同輸送を制約していた。保存出力の追加分析では、同じ個体が直後に元の床へ戻る往復が通常99件で1,796組、そのうち集荷後の往復が1,167組あった。同じ指標でv039は9組だった。
- 変更: v039の盤面、途中で合流する構築、部分配送DP、時刻を扱う再挿入、最終転送圧縮を継承する。構築の合流地点と集荷経路を、入力全体から作る共用経路で選ぶ。中継地点で荷物を保持し、分離・帰巣後も盤上に残る束を次の候補へ渡す。v045の一つの根、地域ごとの処理完了、7匹の便、幹線個体の一括回収は引き継がない。
- 機構確認: 経路の循環がないこと、共用経路に沿う集荷経路の合法性、待機する塔への運び込み、途中で一色を帰した残りと別の塔の合流、下段を残すジャンプを小局面で照合する。最良の構築解とその節目をLOCALの標準エラーログへ記録し、独立した個体ID再生で、混載した荷物が予定した共通区間を進んだことを確認する。候補全体・選ばれた構築解・最終解を分けて数える。
- 達成条件: `tools/in`全100件をLOCAL・既定2並列で1回評価する。全件合法かつE=0、処理エラーと例外による作り直し0、最大経過時間2,000 ms未満、機構確認通過を必須とする。その上で通常99件の平均Tが200以下、すなわち合計19,800手以下を今回の達成条件とする。v039比の改善だけでは目標達成としない。全100件の差とcase0000、0005、0019、0060、0068、0097も報告する。最終解の即時往復数は保存済みv039の9組を上回らないことを必要条件とする。

### 経路と共同輸送の構成

1. 各色の巣へ向かう経路木を作る。他色の初期個体が使う有向辺の需要を数え、需要の多い辺ほど費用を小さくして経路を3巡作り直す。辺費用は `64 + 64 / (1 + min(需要, 7))` とする。全辺の費用を正に保つため、各色の経路には循環がない。色数の多い順、少ない順、色ID順の3通りを用意し、構築の開始ごとに順に使う。
2. 合流候補は、両方の束がそれぞれの経路を前進して到達でき、合流後も共通の方向へ進める床から選ぶ。両側からの運び込み順と積み順を比べる。経路上の既存の塔を残したジャンプも集荷経路の候補に含める。
3. 共通区間を進む途中に別の塔や合流地点があれば、そこで荷物を保持して次の合流を検討する。経路上の前進と、部分配送DPによる最初の分離・帰巣を候補にする。分岐・帰巣の処理は積み順、着地容量、帰巣直前の踏み台利用を含む。分離後も便全体を直ちに完了させず、残った盤面から探索を続ける。
4. v039の構築解の比較と後半の再挿入を使い、全帰巣までのTで最良解を選ぶ。後半には経路の固定を課さず、構築で作った連携を修正できる。経路計画の内部費用やWを提出解の採否基準には使わない。

構築の候補を比較する既存の仕組みと時間配分を引き継ぐ。既存の正常終了用の処理は保持し、新しい例外回復経路を追加しない。新機構が使われず従来の基準構築だけが選ばれたケースは、その事実を明記する。最良の構築解に新機構が一度も採用されない場合、今回の共同輸送構築の効果は未確認と判定する。

### 照合と検証順

- backlog全体、v001〜v045のFront Matterを照合した。v014・v016の集荷方向と継続配送、v021以降の時刻を扱う再挿入、v045の固定構造を確認した。今回の親はコードを引き継ぐv039だけである。v016の継続配送一般の再評価にはせず、全体の経路計画と途中の共同輸送を組み合わせる1実験とする。
- 変更はLOCAL・非LOCALの両方で有効とする。共通の1.90秒とLOCALの0.80倍を使い、両方でmain開始直後から計時する。v039から継承する時間配分は共通定数に対する割合として保つ。この計時の整理も差分に含め、挙動保持の移植とは扱わない。
- 実行前にLOCAL・非LOCALをビルドし、差分とソースハッシュを保存する。先に小局面で経路と合流の照合を行い、0000・0060・0019を各1回だけ機構確認する。失敗したら中断し、結果を記録する。
- 通過したら同じソースで全100件を1回評価する。全出力と選ばれた構築解をPythonで独立再生し、帰巣、混載、再合流、ジャンプ、予定経路の利用、即時往復を調べる。
- 最初の解プログラム実行後は、結果に基づくコード・パラメータ・仮説の変更や追加条件の実行を行わない。機構が未発動なら効果を否定せず、未確認として報告する。
