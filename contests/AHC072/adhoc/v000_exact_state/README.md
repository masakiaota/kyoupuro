# v000への床数ぴったりのStateの反映

2026-09-28、ユーザーの採用指示により、v039で検証した領域再利用方式を`src/bin/v000_template.cpp`へ反映した。v039の実験結果は`notes/experiments/v039.md`に保持する。

## 実装

- `StatePool::prepare(床数, 最大同時保持数)`で塔配列と空き領域の管理配列を事前確保する。
- `State`は全床数で共通の1種類とした。1枚の塔配列は床数×4 byte、`State`の管理部分はこの環境で8 byteである。
- `State trial = state;`は床数分を独立した領域へコピーする。代入は確保済みの領域を上書きし、移動構築は所有するポインタを渡す。領域の取得・返却は定数時間である。
- 引数なしの`State`は空盤面を作る。入力からの初期化も全床を書き込むため、再利用した領域の内容は残らない。コピー構築では事前のゼロ埋めを行わない。
- `state.tower[p]`、塔操作、`State::apply`の呼び出し方を保った。`const State`から塔を変更することはできない。

## 利用時の設定

現在のテンプレートは初期盤面1枚だけなので、`main`の`state_slots`を1にしてある。探索を追加する際は、初期盤面・保持する候補・一時コピーを含めた最大同時保持数へ変更する。v039の4枚という上限は、その探索の呼び出し関係に基づく値である。

初期盤面、現在の盤面、試行盤面の3枚を保持する例は次のとおりである。

```cpp
state_pool.prepare(board.cell_count, 3);
const State initial(input, board);
State current = initial;
{
    State trial = current;
    trial.apply(board, move);  // moveは合法手。
    current = std::move(trial);
}  // 使い終えた領域が返却される。
```

全Stateの生成前にプールを準備し、Stateが残っている間は再初期化しない。同時保持数の上限を超えないことを呼び出し側の前提とし、探索中の動的拡張や上限検査は追加していない。移動元への操作は再代入・破棄に限る。
