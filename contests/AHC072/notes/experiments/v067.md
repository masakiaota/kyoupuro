# v067: 修復負担による候補順位と共同短縮の重点配分を組み合わせる

## 実験前

- 仮説: v059で修復しやすい除去候補を選び、再挿入後にはv058の配分で4マス共同短縮を多く試すと、同じ時間予算で完成スコアを下げられる。根拠はB-86、O77、B-76である。v059の保存評価でも共同短縮による受理候補内の延べ削減は561手あり、適用機会が残っていた。単独実験の改善幅を足して予測しない。
- 変更: v059のsolverを土台に、v058の重い短縮処理の呼び出し列とLOCAL専用の処理別最良更新計数を移す。4マス共同短縮、厳しい向き変更、1手超過を許す向き変更、有限区間共同探索の比率を1:1:1:1から9:1:1:1へ変える。v059の順位式、候補集合、乱数、再挿入、受理式、各短縮処理、総予算3%、各呼び出しの期限、適用条件、完成後処理は保持する。配分変更はLOCALと非LOCALの両方で有効、追加計数はLOCALだけで有効とする。
- 機構確認: 登録差分を戻したソースがv059と完全に一致し、短縮配分と計数がv058からそのまま移ったことを確認する。LOCALありとなしのビルドと完全な前処理結果を照合する。人工盤面で実際の短縮入口を24回呼び、登録した12呼び出しの列を2周すること、4種類の省略条件で巡回位置が進まないこと、追加乱数消費0、全出力の合法性、盤面領域の全返却を確認する。通常評価では各ケースの重い処理の総呼び出し数から周期途中までの期待回数を独立に求め、実測と一致することを必須とする。v059の減点付き候補の選択と再挿入完了、および4種類の重い短縮の発動も確認する。
- 採否基準: 機構確認後、tools/in全100件をLOCAL、時間補正0.80、既定並列数2で1回評価する。全件合法かつE=0、100,000操作以内、外部計測2,000 ms以内、0000が43手以下、構築とLNSのエラー、不正候補、作り直し、診断エラー、盤面領域の未返却0を必須とする。共同短縮が受理候補で1手以上削減し、保存済みv059より合計Tが少なければ今回の比較で採用する。長い6件の差は内訳として記録し、採否条件には加えない。通常評価と親の評価を繰り返して変動幅を測らない。

## 差分と計数の範囲

12呼び出しの順序は「共同、共同、共同、厳しい向き変更、共同、共同、共同、1手超過の向き変更、共同、共同、共同、有限区間」とする。1候補に重い処理を1種類だけ呼び、既存の予算判定を通過したときだけ巡回位置を進める。

`search_reductions_<kind>_best_created_with`は、短縮前には最良更新にならず、短縮後に最良更新した候補のうち、その種類も削減に関わった件数である。同じ候補を複数種類に数えるため、種類別の合計を最良更新候補数と扱わない。各処理の独立した因果効果も表さない。

既存の呼び出し数、短縮手数、受理候補内の延べ削減、処理時間に加え、v059の`lns_repair_priority_*`を保持する。重い短縮全体の費用と探索試行数、初期構築終了時、LNS終了時、完成後処理の手数差を分けて記録する。計算時間に応じて探索経路も変わるため、単回の差を安定した改善幅とは断定しない。

backlogの全項目と再開条件、v001からv066およびv800のファイル名とFront Matterを照合した。直接の親v058とv059の本文、ソース差分、保存済み計数を確認した。B-75の途中候補の短縮を共通の土台とし、今回の中心アイデアは候補順位と配分の組み合わせである。v066で試した同色便の専用短縮は含めない。別の組み合わせで直接短縮と完成スコアが一致しなかったO80も踏まえ、完成スコアの条件を保持する。既存の保存ログだけから今回の併用結果は確定できないため、新しい通常評価を行う。

## 実験後

### 判定

今回の組み合わせは棄却する。通常100件の合計Tが保存済みv059より106手増え、事前の完成スコア基準を満たさなかった。提出用の基準はv059を維持する。機構確認は通過しており、未発動による失敗ではない。

### 通常評価の結果

run_idは`20260930T015711+0900_v067_repair_joint_priority_b2d3d9`。LOCAL、時間補正0.80、並列数2で通常100件を1回評価した。親v059比で106手増（0.51574%悪化）、35勝12分53敗だった。事前指定した長い6件は10手増だった。補足比較ではv057比50手減、v058比41手増であり、両親の良い部分を足し合わせた結果にはならなかった。絶対手数は評価CSVと`results/analysis/v067/summary.json`に保存した。

公式採点と独立再生は全100件で成功した。全件合法かつE=0、0000は43手、外部計測の最大は1,702 ms、平均は1,561.49 msだった。構築とLNSのエラー、不正候補、作り直し、診断エラー、盤面領域の未返却は0だった。全100件で周期途中までの呼び出し回数も一致した。

### 共同短縮と最良更新

配分変更は意図どおり発動した。以下の削減は受理候補内の延べ合計であり、完成スコアの差とは分けて読む。時間は1ケース当たりの平均である。

| 重い短縮処理 | 呼び出し数 v059 → v067 | 延べ削減 v059 → v067 | 平均時間 v059 → v067 |
|---|---:|---:|---:|
| 4マス共同短縮 | 2,475 → 8,452 | 561 → 921手 | 7.855 → 24.427 ms |
| 厳しい向き変更 | 2,456 → 952 | 4 → 0手 | 0.475 → 0.174 ms |
| 1手超過の向き変更 | 2,447 → 926 | 2 → 0手 | 2.130 → 0.791 ms |
| 有限区間共同探索 | 2,440 → 898 | 31 → 8手 | 22.781 → 7.760 ms |

共同短縮の延べ削減は360手増えた。他の処理は、転送圧縮が135手減、経路短縮が54手減、同色便集約が8手増、重い他3処理が計29手減だった。軽い処理も含めた受理候補内の延べ削減は2,155手から2,305手へ150手増えた。

短縮前には最良更新にならず、短縮後に最良更新した候補は273件から328件へ55件増えた。v067では、そのうち220件で共同短縮も削減に関わった。処理別の関与は転送圧縮117件、同色便集約7件、経路短縮2件、有限区間1件にも記録された。同じ候補の重複を含むため合算しない。

v059の減点も保持され、22,411,057候補に正の減点が付き、減点のある候補から113,610件の再挿入が完了した。順位式と候補生成は静的照合で親と一致した。両方の機構が動作した状態での完成スコアの不採用である。

### 探索全体で生じた差

初期構築後の操作数は全100件で親と一致し、探索開始時の経路短縮と並べ替えの合計削減も一致した。最終差はその後に生じた。

| 測定位置 | v059に対する合計手数差 |
|---|---:|
| 初期構築終了時 | 0手 |
| LNS終了時 | +93手 |
| 完成後の共同短縮後 | +98手 |
| 最終出力 | +106手 |

LNS内の最良更新回数は3,170件から3,059件へ減り、最良値の累積削減は93手減った。短縮処理が最良更新を作る件数は増えた一方、探索全体の最良更新は減った。その後の既存の共同短縮による削減が5手少なく、最後の追加処理による削減も8手少なかったため、最終差は106手増となった。

重い短縮全体の平均時間は33.247 msから33.162 ms、軽い処理を含む短縮全体は51.802 msから50.667 msだった。今回の集計では短縮処理全体の時間は増えていない。一方、探索試行数は606,345回から571,433回へ5.758%減り、候補構築時間は平均160.298 msから182.313 msへ増えた。対象となる途中解、候補数、作り直す回数、実行待ちの内訳が同じではないため、この差を配分変更だけの速度低下と断定しない。

### 考察と次の前提

v059の候補順位へv058の重点配分を移しても、共同短縮の適用機会は残り、受理候補内の削減と短縮後の最良更新候補は増えた。しかし、候補の内容と受理後の探索経路も変わるため、その増分は完成スコアへそのまま加算できなかった。次の前提は、今回の9:1:1:1の併用を提出基準へ入れず、v059を保持することである。

今回の1回の実時計比較では、106手の悪化を配分変更の安定した効果量と実行時の変動へ分離できない。同一実装の再評価は行っていない。仮説、配分、solver、入力、親出力、検証器は固定したまま評価と集計を終えた。

再開条件: 共通の途中候補で、重点配分が追加で得る短縮と減らす他の機会を同じ費用条件で比較し、現在の配分から変える条件の根拠が得られた場合。今回の結果だけで比率を変えて続行しない。
