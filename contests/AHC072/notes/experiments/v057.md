# v057: 探索候補への短縮処理の組み合わせ

## 実験前

- 仮説: 生成した候補を受理前に短縮すると、完成後だけでは次の探索へ引き継げなかった分割や合流の改善を探索途中へ戻せる。軽い圧縮を先に使い、共同探索の対象と時間を絞ることで、追加費用を上回る完成スコアの改善を狙う。根拠はB-72の第3段階、B-66、O48、O65〜O69、O72と、v055を基準に進めるユーザー指示である。
- 変更: v055の構築、近傍生成、再挿入の2順序選択、受理式、乱数、既存の時間配分、完成後処理を保持する。v040の受理前への適用位置を引き継ぎ、転送圧縮と同色便集約をLNS開始時と生成候補へ適用する。短縮した場合は経路短縮を再適用し、時間内で手数不変まで反復する。4マス共同短縮、厳しい費用条件と1手超過を許す向き変更、巣を含む有限区間共同探索も、下記の選択と予算の下で候補へ適用する。v056の高速化は取り込まない。変更はLOCALと非LOCALの両方で有効とする。
- 機構確認: v055の固定例と長時間探索の参照例を新しいソースで照合する。保存済みの候補操作列と対応する現在解に対し、短縮前後の合法性、全帰巣、手数非増加、乱数消費0、短縮処理別の削減、受理確率と最良値の関係の変化を確認する。変更箇所の範囲抽出、期限切れ、予算不足、重い処理の巡回順を独立に確認する。通常評価では処理別の呼び出し、削減、時間、受理された候補内の削減、短縮によって初めて非悪化または最良更新になった件数を保存する。
- 採否基準: 固定例と保存候補の独立検証を通過し、候補の追加短縮が1手以上あれば通常評価へ進む。各部品に個別の正の削減を要求しない。tools/in全100件をLOCAL、時間補正0.80、既定並列数2で1回評価する。全件合法かつE=0、100,000操作以内、外部計測2,000 ms以内、case0000が43手以下、構築とLNSのエラー、不正候補、作り直し、盤面領域の未返却0を必須とする。受理候補で追加短縮が1手以上発動し、保存済みv055より合計Tが少なければ今回の比較で採用する。単回評価の小差から恒常的な優位とは断定しない。

## 適用範囲と時間配分

通常の経路短縮の後に、転送圧縮、同色便集約を適用する。この2処理で手数が減れば経路短縮へ戻り、同じ巡回で手数が減らなくなるかLNS期限に達したら終える。LNS開始時の現在解と、開始時の並べ替え候補も同じ処理を受ける。既存の再挿入が失敗した候補は対象にせず、再挿入器内部の手数上限も変えない。

重い4処理は4反復ごとの候補のうち、軽い処理の後で現在解+2手以下かつ最良解+4手以下で、現在解と操作列が異なるものへ適用する。4マス共同短縮、厳しい向き変更、1手超過を許す向き変更、有限区間共同探索をこの順で1回ずつ巡回する。各呼び出しに1種類を使い、短縮できれば軽い処理を再適用してから受理判定へ渡す。

重い処理の累積時間はLNS経過時間の3%を目安に制限する。開始直後の基準経過時間はPROGRAM_TIME_LIMIT_SECの2%とする。残予算がPROGRAM_TIME_LIMIT_SECの0.05%未満なら着手せず、1回の期限は残予算、同0.15%、LNS期限の最小とする。既存の期限確認の粒度による超過は計測する。探索全体の期限と完成後の時間枠は親を保持する。軽い処理の費用と、重い処理の予算管理に使う実時間は分けて記録する。

重い処理では現在解と候補の共通接頭辞と共通接尾辞を操作単位で除いた範囲を求め、その前後64操作に開始位置がある区間だけを抽出する。これは探索費用を制限する選択条件であり、操作記述が同じ接尾辞で盤面も一致するとは仮定しない。各置換の正しさは従来どおり全盤面一致で確認する。完成後の呼び出しでは範囲を制限せず、親の動作を保つ。

## 機構確認

未定義動作検出を有効にし、固定例14,530確認、適用条件と予算の20確認、長時間探索の4例について元と参照の計8確認を通過した。4例すべてで参照と同じ手数以下の置換を自動で求めた。予算不足時の省略、期限切れ時の操作列保持、重い4処理の巡回順も確認した。

保存済み4,382候補のうち571候補を短縮し、候補ごとの削減の延べ合計は1,080手だった。内訳は転送圧縮935手、4マス共同短縮59手、同色便集約1手、有限区間共同探索85手。経路の再短縮と2種類の向き変更は0手だった。現在解の短縮も含めて比較すると、現在解より短いかの関係が55候補で、登録した温度での受理確率が111候補で変わった。この延べ削減は完成スコアの改善量ではない。

重い処理400回で、範囲付きの区間抽出が全抽出後に同じ範囲で絞った結果と一致した。短縮処理11,140回の合法性、帰巣、手数非増加を確認し、乱数消費は0だった。別のPython実装でも4,482操作列、短縮した603回の置換境界、長時間探索由来の4出力を再生して照合した。

診断の平均費用は1候補3.437 msだったが、時計を外した重い処理、独立再生、区間抽出の照合を含むため、通常評価の処理費用として使わない。機構確認を通過したので、ソースとパラメータを保持して通常100件の評価へ進む。資料は`static_verification.json`、`diagnostic_verification.json`、`diagnostic.csv`、`passes.jsonl`、`outputs.jsonl`に保存した。

## 実験後

### 判定

今回の比較では採用する。機構確認、合法性、時間、case0000、受理候補の短縮、合計Tの全条件を満たした。第3段階の基準版をv055からv057へ進める。v056の高速化は含めない。

### 通常100件の結果

run_idは`20260929T145653+0900_v057_search_reductions_af817c`。LOCAL、時間補正0.80、既定並列数2で1回評価した。保存済みv055より合計103手減（0.49491%改善）、47勝12分41敗だった。第1段階の基準だった保存済みv050との比較でも49手減った。

公式採点と独立再生は全件成功し、合法かつE=0、最大1,587 ms、case0000は43手だった。構築とLNSのエラー、不正候補、作り直し、診断エラー、盤面領域の未返却は0だった。手数の絶対値とケース別の比較は`results/score_summary.csv`、`results/score_detail.csv`、`results/analysis/v057/`に保存した。

### 探索途中で起きた短縮

228,834候補のうち4,886候補を短縮し、そのうち1,711候補が受理された。受理された候補に適用した削減の延べ合計は2,113手だった。これは別々の候補への短縮を含み、完成スコアの103手減と足し算できない。LNS開始時の現在解にも計275手の追加短縮があった。

| 処理 | 呼び出し数 | 受理候補内の延べ削減 | 1ケース当たり平均時間 |
|---|---:|---:|---:|
| 転送圧縮 | 233,975 | 1,450手 | 8.849 ms |
| 4マス共同短縮 | 2,311 | 560手 | 7.909 ms |
| 同色便集約 | 233,974 | 50手 | 6.941 ms |
| 有限区間共同探索 | 2,269 | 28手 | 22.525 ms |
| 他処理の短縮後の経路短縮 | 4,572 | 25手 | 0.424 ms |
| 厳しい費用条件の向き変更 | 2,287 | 0手 | 0.450 ms |
| 1手超過を許す向き変更 | 2,277 | 0手 | 2.087 ms |

呼び出し数と時間には、LNS開始時の処理や棄却候補への適用も含む。受理候補内の削減には含めない。転送圧縮は全100件、4マス共同短縮は91件で受理候補を短縮した。

短縮前には最良更新にならなかった候補が、短縮後に最良更新になった件数は89ケース・288件だった。現在解より長かった候補が同手数以下になった件数は1,233件、受理確率が変わった件数は3,767件だった。候補を短くしてから探索へ戻す経路が実際に使われたことを確認できた。

追加処理は平均49.185 ms、最大78.547 msだった。重い処理の呼び出し全体は平均32.978 msで、これは各部品の時間と重なる。探索試行数は親比7.126%減った。探索する解が変わるため、この減少率を処理速度の低下率や追加時間の比率とは扱わない。

重い処理は9,144回呼ばれ、予算不足などで36,133回省略された。細かい呼び出し期限を2,380回超えたが、solver全体は時間基準内だった。有限区間共同探索は2,269回すべてで期限に達しながら、うち短縮を得たケースでは合法な置換を保存した。計算費用と期限確認の粒度が残る制約である。

### 完成スコアとの関係

構築終了時の手数は2ケースで変わり、合計では親より7手少なかった。LNS終了時には190手少なく、その後の転送圧縮と共同短縮を経たv055追加処理の入口では106手少なかった。引き継いだ最後の追加処理は7ケース・8手減で、親の11手減より3手少ないため、完成版の差は103手減となった。

途中の短縮を採用すると、その後の候補生成、温度、打ち切り、乱数消費が変わる。各短縮処理自体の乱数消費0と、solver全体の探索経路が同じことは別である。最良更新288件は各候補の短縮前後から直接確認した事実だが、完成版の103手差すべてを追加機構の因果効果とは断定しない。単回評価であり、改善幅の再現性や各部品の単独寄与は未測定である。

### 次の検討の前提

第3段階では、途中候補の短縮が受理と最良更新に届き、完成スコアの基準も満たした。次の基準はこの組み合わせを保持したv057とする。

利益と費用は部品ごとに偏っていた。受理候補内の削減は転送圧縮と4マス共同短縮が約95%を占めた。有限区間共同探索は追加時間の約46%を使った一方、受理候補内の削減は約1.3%だった。2種類の向き変更は発動したが短縮0手だった。これらは今回の条件下の観測であり、部品を取り除けば完成スコアが改善するとはまだ言えない。対象選択や費用配分の良否を判断するには、今回の利益を保持できるかの切り分けが必要である。

solverは最初の機構確認から変更せず、通常評価も繰り返していない。README、v000、記号一覧、重要な性質、親のソースと保存出力は実行前のハッシュと一致した。
