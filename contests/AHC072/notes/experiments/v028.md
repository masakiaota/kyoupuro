# v028: 少人数の再挿入順を2通り比較する

## 実験前

- 仮説: 先に戻した個体の経路が後続の同乗や踏み台利用を制約しているなら、最初に戻す個体を変えた順序も完成まで比較することで、再挿入に失敗した集合や長い再構築を改善できる。根拠はB-31、O28、O34と、通常の集合再挿入が1つの順序を使う実装である。
- 変更: v026の通常候補と依存関係から拡張した候補のうち、除去と修復が成功した2〜4匹を対象とする。親と同じ乱数付き距離順を第1候補にし、先頭2匹だけを交換した順序を第2候補にする。同じ除去後の盤面と操作列から両方を戻し、完成した操作列が短い方を選ぶ。同点なら第1候補を保持する。候補集合、初期構築、1匹の再挿入器、塔の部分再構築、近傍の選択頻度、受理条件、時計、最適化設定は親から引き継ぐ。変更はLOCALと非LOCALの両方で有効である。
- 機構確認: 保存済みv026の全100出力から、各件の上位64個までの対象集合を取り、集合から決めた共通乱数で順序を固定する。2通りを独立に最後まで戻す参照処理と新処理を比較し、成否、選ぶ順序、操作数、同点時の第1候補保持を照合する。完成した全操作列をC++の盤面適用と独立Python再生で確認する。参照処理と新処理を用意してソースを確定した後に診断を実行し、診断結果に応じたソルバー変更は行わない。本評価では通常99件で第2順序の試行、完成、選択、受理が正であることを必要とする。最良解更新、元順序の失敗後の完成、元順序より短い完成、計算時間も記録する。
- 採否基準: `tools/in` 全100件をLOCAL、時間補正0.80、並列数2で1回評価する。公式採点と独立再生が全件で成功し、合法かつE=0、100,000操作以内、外部計測の最大2,000 ms未満、構築エラーとLNSエラー、初期解と最終解の例外による作り直し0を必要条件とする。機構確認を満たし、合計Tが保存済みv026を下回り、case0000が43手以下なら今回の提出候補に採用する。局所短縮だけで採用せず、同じ実装の評価を繰り返してノイズを測ることもしない。

## 事前照合と設計

ユーザーはv027を不採用とし、v026を基準に案3の検討、実装、検証を指示した。backlogとv001〜v027のファイル名およびFront Matterを照合した。B-31は未着手で、同じ仮説の完了実験はなかった。親v026の本文と、添付資料にある案3の説明を確認した。

v026の塔の分解再挿入は4匹以下で既に2種類の順序を試し、2塔再構築も3匹以下で2種類を試す。一方、初期位置から個体集合を戻す通常経路は、巣までの距離へ乱数を掛けた1種類だけを使う。今回の変更先はこの通常経路で、依存関係から作った集合も同じ経路を通る。既に複数の順序を試す塔の近傍は変更しない。

第2順序は先頭2匹だけを交換する。3匹目以降の優先順を保持し、最初の個体の選択が及ぼす影響を限定して調べる。途中で枝を増やすビーム探索や全順列の列挙は今回の範囲に含めない。2〜4匹に限定するため、再挿入器の呼び出しは1候補につき最大4〜8回となる。

第1順序が完成した場合、第2順序の上限をその完成長より1手短くする。1匹の再挿入は背景の操作を削除せず、追加操作数は非負なので、この打ち切りは完成前の操作数で適用できる。第1順序が失敗しても第2順序を試すことは、この比較の通常の動作である。両方が失敗したときは候補を棄却する。完成候補の比較後に既存の経路短縮と受理判定を1回だけ行うため、同じ長さの候補の経路短縮後の優劣は探索しない。

新処理は乱数を追加で使わず、親と同じ順序生成を引き継ぐ。ただし追加計算と採用候補の違いから、温度、打ち切り時刻、後続の探索経路は変わる。試行数差を純粋な速度差とは扱わない。第2順序の短縮量は同一実行内の指標であり、版間の完成スコア差と分けて記録する。

比較基準はv026のrun_id `20260927T172632+0900_v026_late_start_lns_973c99` とする。親ソースのSHA-256は `83fbf8fd338c22f4f5809a5b4a5be5df751cc2e137323ce76027187c4dca04ed` である。v027の時刻の選び直しと、未着手B-36の近傍配分変更は含めない。LOCALありとなしをビルドし、`-E -P` による完全なマクロ展開結果を親と照合してから診断と評価を行う。

## 評価前の確認

LOCALありとなし、診断用コードが警告なしでビルドできた。`-E -P` による完全なマクロ展開結果を親と照合し、assertの表示用ファイル名と行番号を正規化した差分を保存した。非LOCALの処理差は2通りの再挿入と対象サイズの分岐、LOCALにはその計測が加わる。初期構築、1匹の再挿入器、候補選択、塔の再構築、受理規則、時計、最適化設定の意図しない差はなかった。

診断と本評価に使うソースのSHA-256は `29aa1b31304a06d63db75ad152be6a9e52c2aa752c7e8d7b516b506e9334e717` である。診断対象は候補の優先順に通常集合と依存関係で拡張した集合を列挙し、同じ集合を重複させず、各件64個までとした。診断で生成した操作列を次の試行へ引き継がない。

全100件の6,360集合を診断し、除去が成功した5,919集合で参照処理と新処理の成否、選んだ順序、操作数、全操作列が一致した。完成した参照2順序と選択結果の合計12,694本は、C++と独立Pythonの盤面再生でも合法かつ全回収だった。追加の乱数消費がないことも確認した。

第2順序は743集合で選ばれ、そのうち193集合は第1順序が失敗した集合、550集合は第1順序より短い集合だった。両方が完成した集合における短縮の合計は743手である。第2順序は全100ケースのいずれかの集合で選ばれた。これらは保存解を入力にした固定診断であり、時間制限内の本評価の改善量ではない。対象サイズは2匹2,123集合、3匹2,651集合、4匹1,586集合だった。

本評価前の機構確認を通過したため、ソースを変更せず、ラベル `two_order_lns` で全100件を1回評価する。

## 実験後

### 判定

採用（事前登録した今回の比較における提出候補）。全必要条件と機構確認を満たし、完成版は保存済みv026比で6手減（0.02871%改善）、46勝10分44敗だった。case0000は43手を維持した。参考比較のv022比では57手減（0.2721%改善）だった。

ただし、案3の優位性は未確認である。初期構築終了時点で既に親より7手少なく、LNSの短縮量は親より1手少なかった。最終6手の差を新処理の効果とは帰属できない。同一実装の繰り返し評価は行っておらず、AtCoderには未提出である。親v026もそのまま保持した。

### 評価と合法性

全100件をLOCAL、時間補正0.80、並列数2で1回評価した。run_idは `20260927T184531+0900_v028_two_order_lns_c6311b` である。既定のウォームアップは集計に含めていない。

全100件で公式採点が成功し、独立したPython再生でも合法かつE=0、100,000操作以内を確認した。最大実行時間は外部計測1,543 ms、内部計測1,521.569 msだった。構築エラー、LNSエラー、不正な再構築候補、初期解と最終解の例外による作り直しはすべて0だった。評価前後のソースのSHA-256も一致した。

### 本評価の機構確認

以下はcase0000を除く通常99件の集計である。新処理は168,230回呼ばれ、2匹60,079回、3匹67,622回、4匹40,529回だった。第2順序は全99件で完成候補として選ばれた。

| 指標 | 回数 |
|---|---:|
| 第1順序の完成 | 125,295 |
| 第2順序の試行 | 168,230 |
| 第2順序の完成と選択 | 21,449 |
| うち第1順序が失敗した候補の完成 | 5,089 |
| うち第1順序より短い完成 | 16,360 |
| 第2順序を選んだ候補の受理 | 12,527 |
| 第2順序を選んだ候補の最良解更新 | 392 |

新処理によって完成した候補は130,384回で、第1順序だけの125,295回より5,089回多かった。両順序が完成した場合の短縮合計は21,570手である。これは途中解に対する候補生成時点の差分であり、完成スコアの差ではない。

第2順序から92ケースで392回の最良解更新が生じ、同一実行内で697手を短縮した。第1順序を選んだ場合まで含む新処理全体では、1,476回の最良解更新で2,533手を短縮した。これらは通常近傍の短縮に含まれる内数で、案3を追加しなかった場合との比較値ではない。追加順序の試行、完成、選択、受理はすべて正であり、事前登録した機構確認を満たした。

### 計算負担と完成スコア

第2順序の探索時間は1ケース平均97.313 ms、第1順序は152.041 msだった。追加順序はLNS全体の平均時間の約8.65%を占めた。打ち切りを含めた第2順序の1匹再挿入は418,474回である。

探索全体の試行数は親の671,834回から614,558回へ8.525%減った。依存関係の拡張や再試行抑制による中断まで含めた反復数も8.214%減った。一方、再挿入の成功回数は1,779,503回から1,966,808回へ増えた。この回数には採用されない順序の途中の成功も含む。1試行で2つの順序を戻すため、試行数と再挿入の仕事量は同じ方向へ変わるとは限らない。

初期構築終了時点は0019、0056、0076の3ケースで変わり、親との差は合計7手減だった。LNSで短縮した量は親より1手少なく、完成版は6手減となった。通常近傍の短縮は17手増えた一方、2塔再構築の短縮は24手減るなど、他の近傍も変わった。時間に依存する探索経路の変化を含むため、この内訳から個々の機構の因果効果は分離できない。

### 考察

次の検討では、少人数の再挿入で最初の個体を変えると、同じ集合でも成否と手数が変わることを前提にできる。固定診断で参照処理と一致し、本評価でも第2順序から最良解更新が起きているので、未発動による結果ではない。

一方、追加順序で得られる短縮が、その計算時間と探索機会の減少に見合うかは未確定である。今回確認できたのは、既存の順序と先頭2匹を交換した順序を比較する構成である。ビーム探索や全順列の探索の効果までは評価していない。

採否基準上は6手の改善で採用候補となったが、案3が完成スコアを改善すると確認した結果とは扱わない。評価後のソルバー変更と追加の評価は行っていない。
