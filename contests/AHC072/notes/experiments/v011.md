# v011: 現行の踏み台網に合わせた配送グループ再分割

## 実験前

- 仮説: B-14、O8、O9、O18に基づく。v010で残る少量輸送に対し、現在の踏み台網で経路を共有できる複数便の所属と便数を組み直せば、集荷・設置・全帰巣を含むTを減らせる。高さ別容量を候補評価に反映し、7匹便の集約利益と5〜6匹便の使える経路の違いを扱う。
- 変更: v010の混載・踏み台配置・共同配置・実経路構築を引き継ぎ、共同配置後の `tall_refine` フェーズを、配置固定の配送グループ再分割へ置き換える。実際の輸送経路から2〜3便を選び、踏み台個体の担当便を固定したうえで通常個体を再配置する。最大1便の追加と空になった便の削除を許す。候補順位には現行の高さ別ジャンプ距離を使った小規模な集荷木・巣巡回の近似費用を使い、採択には既存の全計画シミュレーションを使う。solverは `src/bin/v011_network_regroup.cpp` とする。直接のコード派生元はv010だけであり、v006からは複数の細い経路をまとめ直す着想を参照する。
- 機構確認: `network_models`、`network_support_models`、`network_metric_calls` で踏み台込みの候補評価を確認する。`network_proposals`、`network_trials`、`network_valid`、`network_multi_trials`、`network_group_count_trials` で候補生成・全計画評価・3便以上の同時変更・便数変更を区別する。`network_accepted`、`network_saved`、`pre_network_ops - post_network_ops` で実T改善を確認する。LOCALでは踏み台個体の所属、再配置先と設置イベント順の保存を確認し、最終出力を独立再生して全操作の合法性・容量制約・全帰巣・行数一致を検証する。候補の評価と合法な再分割が未発動なら機構未確認として停止する。
- 採否基準: `tools/in` 全100件を既定のLOCAL・`-j 2`で1回evalする。全件で公式scorer成功、`E = 0`、操作数制限内、ローカル実行時間2,000 ms未満を必要条件とする。通常生成99件で踏み台込みの候補評価、複数便を変更した合法候補、再分割の採択と実T削減が正に発動し、全100件の合計Tが保存済みv010より小さければ提出候補として採用する。通常生成99件の比較も併記する。3便同時変更と便数変更の各効果は副指標とし、発動しなければその部分の効果を主張しない。

## 事前照合と設計

- backlog全体とv001〜v010のファイル名・Front Matterを照合し、関連するv006・v010とv006の踏み台網の派生元v003を確認した。B-14は未着手であり、今回のユーザー指示で着手する。B-15は別案として未着手を維持する。
- v006は同色輸送木の枝の再接続であり、v011は混載も含む配送便の所属・分割の変更である。v010の内部の経路DPはそのまま利用する。
- 再配置に指定された個体、および段階境界で既に組まれた塔の構成員は元の担当便に固定する。再分割で設置先を変更せず、便の挿入・削除時は元の便の直前という設置イベントの順序を保持して段階番号を写し直す。通常個体の帰巣時期が変わることによる他便への影響は全計画評価に含める。
- 各候補便の時点の盤面から、再分割対象の通常個体とその便自身の踏み台個体を除いた高さで距離表を作る。5・6・7匹の容量別に距離を計算し、候補の近似費用では集荷と巣巡回を評価する。候補便どうしが通常個体を踏み台にする効果、混色の積み順、集荷途中の荷物サイズの変化は近似から外れるため、この費用は順位付けに限定する。
- v010と同じフェーズ終了時刻 `PROGRAM_TIME_LIMIT_SEC * (1805 / 1900)` まで再分割を行い、その後の固定計画refreshとpolishへ接続する。後半の踏み台再調整との時間交換を含む比較であり、同一実行内の再分割前後差と完成版どうしの差を分けて記録する。
- LOCALあり・なしのビルドと静的確認を済ませ、`0019.txt` で機構確認してから同じソースを全100件でevalする。solver実行後は実行結果を根拠とした実装変更を行わず、結果の記録と報告へ進む。

## 実装・検証ログ

- `v010_scaffold_chain.cpp` を派生元として、再分割フェーズと専用の計測値を追加した。既存の配送経路構築・踏み台設置・共同配置は引き継いだ。

- LOCALでは個体の重複・欠落、固定した踏み台個体の所属、設置先と設置イベント順、塔の所有関係を検査する。新しい機構の累積削減量とフェーズ前後のT差も照合する。
- GCC 15 / C++23でLOCALあり・なしの両ビルドが成功し、最終ビルドに警告はなかった。SDKは `xcrun --show-sdk-path`、deployment targetは15.0を指定した。

- `0019.txt` の単発確認で、公式scorer成功、全217匹の帰巣、全操作の合法性を確認した。再分割では踏み台込みの距離モデル12件、高さ2以上を含むモデル5件、全計画評価13件、完了した合法候補4件を確認した。1候補を採用し、同一実行の再分割前から2手削減した。3便以上の変更は10候補、便数変更は8候補を評価したが、この単発では両者の採用はなかった。記録は `adhoc/v011_mechanism.out` と同 `.err`。

## 実験後

### 判定

採用（今回の評価セットでの提出候補）。合法性・全帰巣・時間・機構発動と、全100件の合計Tがv010を下回るという事前基準を満たした。ただし、全体の削減率は約0.15%であり、再分割フェーズ単独の削減は小さい。v010の後半の踏み台再調整より再分割が有利とまでは、この比較から確定できない。

### 結果

- 全100件で公式scorerが成功し、公式スコア、最終T、独立検証した操作数、出力行数が一致した。全件で `E = 0`、操作数制限内だった。保存出力をPythonでも個体ID付きで再生し、全操作の合法性と全帰巣を確認した。
- 保存済みv010との比較は次のとおりである。勝ちはTが少ない場合を表す。

| 評価セット | 合計Tの差 | 削減率 | 勝・分・敗 |
| --- | ---: | ---: | ---: |
| 全100件 | -39手 | 0.1515% | 41・15・44 |
| 通常生成99件 | -39手 | 0.1518% | 41・14・44 |

- 全100件のローカル実行時間は平均1,458.06 ms、最大1,468 msであり、全件2,000 ms未満だった。再分割フェーズは通常生成99件で平均128.16 msだった。
- 通常生成99件の機構確認は次のとおりである。合法候補数は、全帰巣まで計画でき、現在解に対する打切り幅内に収まった候補数である。

| 機構 | 合計 | 発動ケース数 |
| --- | ---: | ---: |
| 踏み台を含む距離モデル `network_support_models` | 85,954件 | 99 / 99 |
| 高さ2以上を含む距離モデル `network_tall_models` | 67,658件 | 94 / 99 |
| 全計画評価 `network_trials` | 20,680件 | 75 / 99 |
| 完了した合法候補 `network_valid` | 3,808件 | 75 / 99 |
| 再分割の採用 `network_accepted` | 14件 | 10 / 99 |
| 再分割による削減 `network_saved` | 18手 | 10 / 99 |
| 3便以上を変更した候補の採用 `network_multi_accepted` | 2件 | 2 / 99 |
| 便数変更の採用 `network_group_count_accepted` | 7件 | 7 / 99 |
| 空盤面費用が5手超悪化する候補の採用 `network_static_worse_accepted` | 1件 | 1 / 99 |

- 便数は再分割前より5件で増え、2件で減った。どちらの方向にも実Tを減らす採用があった。踏み台個体の担当便・配置先・設置イベント順を保存したうえで、便数を変更して全帰巣する機構が成立した。
- 全体の空盤面費用が5手超悪化しても実Tが減る候補が1件採用された。ただし、3便以上を変更した場合の差でもあり、旧2便近傍の枝刈りを外す効果と同一視しない。

### フェーズ前後の切り分け

通常生成99件の合計で、再分割開始直前のv011は、対応するv010の共同配置終了時点より既に82手少なかった。そこからv011の再分割は18手、その後の処理は2手を削減した。一方、v010は共同配置終了後に63手を削減していた。

完成版どうしの差は `-82 - 18 - 2 + 63 = -39` 手となる。前半の時間打切りに伴う探索差を含むので、39手すべてを新しい再分割機構の効果とは解釈しない。保存された別実行どうしで後半の削減量だけを比較しても、開始計画が異なるため厳密な機構比較にはならない。

完成版の1匹輸送は通常生成99件でv010より93操作少なかった。ただし、この差にも前半の配置・グループ構成の違いを含む。再分割そのものが1匹輸送を93操作減らしたという意味ではない。

### 考察

現在の踏み台網の高さと容量を反映した候補選び、複数便の再分割、設置イベントを保った便数変更が成立し、一部のケースで実Tを削減した。便を増やす変更にも採用があり、便数の少なさだけでは輸送の良否を判断できないことが確認できた。

一方、実T改善は10件・18手にとどまり、機構が発動したことと、大きな改善余地を取り出せたことは区別する必要がある。今回の結果は「踏み台固定のグループ再分割には有効な変更が存在する」という前提を確定するが、「v010の後半の踏み台再調整を置き換えるほど強い」という前提までは確定しない。事前基準上はv011を候補として採用し、v010との完成版比較の差は小幅なものとして扱う。
