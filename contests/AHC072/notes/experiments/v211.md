# v211: ジャンプと合流先を同時に選ぶ同色集荷

## 実験前

- 仮説: 同色集荷の経路と合流先を部分集合DPで選ぶことで、v210の隣接移動による集荷を短縮し、計算費用を含めても完成手数を減らせる。根拠はユーザーの添付実装、B-130の併用結果、長距離移動を含む集荷表現の拡張を課題とするO12である。
- 変更: ユーザーの `v211_jump_steiner_collection.cpp` を新規実験v211として登録する。直接の親はv210であり、添付ヘッダーの親SHA-256も登録済みv210と一致する。同色の3〜6塔、合計8個以下について、背景の塔を固定した有向ジャンプ経路と合流を部分集合DPで選ぶ。背景が空の床から合流先を選び、親の集荷計画より評価が高い完成計画を使う。親の集荷候補選別、2塔構築、再挿入、候補保持、NN、初期解選抜を保持する。変更はLOCALと非LOCALの両方で有効である。時間式は既にv210と一致しているため、そのまま保持する。登録用の先頭コメントだけ整理し、添付の処理と数値は変更しない。
- 機構確認: 初回実行前にLOCALと非LOCALをビルドし、`-E -P` による完全な前処理結果が添付版と一致することを確認する。診断用のファイル名とassertの行番号だけ正規化する。親との差分も照合し、ソース、両実行ファイル、100入力、比較対象の保存結果、検証器を固定する。0000と0001を両モードで各1回診断し、合法性と全帰巣を独立再生で確認する。LOCAL診断の2件合計で新DPのcallsとcompletedが正であり、親の同色同一視、候補保持、集荷、段階選抜が整合することを必須とする。本評価では新DPのimproved_plansとadoptedも正であることを必須とし、長距離ジャンプ、合流先変更、固定合流先での短縮、時間切れ、消費時間を集計する。従来の木だけのpositive計数と、新DPによる改善と採用を区別する。
- 採否基準: `tools/in` の100件をLOCAL、時間補正0.80、既定2並列で1回評価する。先頭入力のウォームアップ1回は保存と集計から除く。全件合法、E=0、100,000操作以内、外部時間2,000ms以内、既存エラーと作り直し0、盤面領域4枚の全返却を必須とする。機構確認を満たし、絶対スコア合計が保存済みの親v210を厳密に下回れば採用とする。v209とv204の保存結果との比較も併記する。最初の診断以降はsolverを変更せず、同条件の再評価や別セットの追加評価は行わない。

## 移植と診断

先頭コメントの整理だけで登録し、時間式の修正は不要だった。GCC 15.1.0でLOCALと非LOCALを警告なくビルドした。両モードの完全な前処理結果は、ファイル名とassertの行番号を正規化すると添付原版に一致した。登録版のSHA-256は `d470f1f7934980ce59c8c814e103cd472abf25c8076775438339629261a679b1` である。

親との差分も照合した。候補選別と従来の集荷木、TemporalLNSと段階選抜、計時開始位置と時間式はv210と一致した。追加は集荷計画の部分集合DP、その採否用情報、呼び出し、計数と出力に限られた。

初回実行前に入力、原版と登録版、両実行ファイル、比較する3版の保存出力、検証器を固定した。0000と0001を両モードで各1回診断し、全4出力が合法で全帰巣した。LOCALでは既存エラー0、盤面領域4枚の全返却、段階選抜の整合を確認した。

LOCAL診断2件の合計で、新DPは1,135回呼び出され、1,133回完了し、2回は期限で終了した。従来計画を上回る完成計画340件のうち42件を構築で採用し、その操作には長距離ジャンプ79手が含まれた。合流先を変えた計画の採用は33件だった。累積時間は2件合計76.008msとなり、同色同一視と候補保持の計数も発動した。計画の評価差とこの採用回数は、最終手数の削減量を表さない。

機構確認を通過し、solverを変更せず通常100件の本評価へ進んだ。

## 実験後

### 判定と比較

棄却。新DPの発動と健全性は確認できたが、通常100件の完成手数は親v210より増え、事前の採用基準を満たさなかった。

| 比較対象 | 合計差 | 増減率 | 勝敗 |
| --- | ---: | ---: | --- |
| 親v210 | ＋114手 | 0.56632%増 | 42勝9分49敗 |
| v209 | ＋35手 | 0.17319%増 | 44勝11分45敗 |
| v204 | −126手 | 0.61856%減 | 53勝11分36敗 |

全100件で公式採点と独立再生を通過し、合法、E=0、100,000操作以内、既存エラーと作り直し0、盤面領域4枚の全返却を確認した。外部時間は平均1,559.73ms、最大1,599msだった。LOCAL、時間補正0.80、2並列で1回評価し、要約と詳細へ各1行、ケース正本へ100行を登録した。評価後も固定した742ファイルのハッシュが一致した。

### 新DPの発動と計算費用

全100件で新DPを呼び出し、完了した計画を得た。99件で従来計画の評価を上回り、98件で構築中に採用した。採用計画に長距離ジャンプを含むものが97件、合流先を変えるものが96件あった。新DPが未発動だったことによる不採用ではない。

100件合計で29,642回呼び出し、29,570回完了し、72回は期限で終了した。評価が改善した完成計画は20,591件、そのうち構築で採用した計画は6,555件だった。採用計画には長距離ジャンプ8,962手が含まれ、合流先を変えた採用は4,963件だった。固定合流先でも従来の木より短かった計画は13,192件あった。これらは候補計画と構築中の計数であり、完成手数の削減量ではない。

追加DPの時間は1件平均35.149ms、最大38.701msだった。累積予算による見送りは15,883回、7塔以上による見送りは13,894回だった。各ケースで呼び出し、予算による見送り、塔数による見送りの合計が従来の集荷計画数に一致した。

| 指標 | 親v210 | v211 |
| --- | ---: | ---: |
| 構築試行数 | 4,736回 | 4,360回 |
| 完成した構築数 | 2,131回 | 1,880回 |
| LNS試行数 | 599,450回 | 584,295回 |
| 構築の平均時間 | 389.535ms | 397.161ms |
| LNSの平均時間 | 1,130.722ms | 1,123.885ms |
| LNS候補生成の平均時間 | 126.929ms | 126.816ms |

構築全体は平均7.626ms長く、LNSは平均6.836ms短くなり、LNS試行数は2.53%減った。追加DPの平均35.149msが、そのまま構築全体の増加時間になったわけではない。構築した候補の数と内容も変わっている。

### 親から継承した機構

同色同一視の4計数は全100件で正であり、候補保持の5計数も発動した。初期候補5本が96件、4本が1件、3本が3件で、計396回の継続再開と段階選抜が整合した。

集荷を含む初期解は94件で保持候補に残り、88件で最終選抜の勝者となった。保持した初期解のうち集荷を含むものは446本だった。親v210では86件、83件、405本だった。この計数には従来の集荷木も含まれるため、新DPを含む初期解だけの成績は区別できない。

### 次の比較の前提

構築直後の合計は親v210より127手少なかったが、LNS終了直後は115手多く、終了処理後は114手多くなった。今回の新DPは初期構築の合計を改善したものの、その差を最終結果まで維持できなかった。LNS時間と試行数の減少を伴うが、初期解の内容と探索経路も変わっているため、悪化を計算費用だけに帰属させない。

比較基準はv210を維持する。単回の実時間比較であり、安定した効果量や非LOCALの提出時の性能は未確認である。登録した工程を完了し、診断後のsolver変更、追加設定の評価、再評価は行っていない。

再開条件: 親v210を上回ることを狙った別条件の比較について、新たな明示指示を受けた場合。
