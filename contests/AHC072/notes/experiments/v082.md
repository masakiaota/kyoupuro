### 固定する追加14特徴

以下の個体は初期床IDで識別する。現在の保存操作列を再生し、各便の乗客と下段を求める。候補に含む乗客数を`s`、含まない乗客数を`r`、取り除く下段数を`lost`、元の支持余裕を`slack = k + 1 - l`とする。これらは補助コード内の局所変数名である。候補匹数で割る量は候補ごと、時刻は現在列の長さで正規化する。

| 列 | 追加情報 |
|---|---|
| 32 | 下段を失い、対象外の乗客が残る長距離便の数 |
| 33 | それらの便の`lost * r`の合計／候補匹数 |
| 34 | 対象外の乗客が残る便の`max(0, lost - slack)`の合計／候補匹数 |
| 35 | 支持不足になる便の対象外乗客数の合計／候補匹数 |
| 36 | 候補の乗客数×対象外の下段数の合計／候補匹数 |
| 37 | 候補内外が同乗する便の候補乗客数の合計／候補匹数 |
| 38 | 候補の乗客がいる便の対象外乗客数の合計／候補匹数 |
| 39 | 候補と同乗した対象外個体の異なり数／M |
| 40 | 候補個体の輸送距離の合計／候補匹数 |
| 41 | 候補個体の初乗車時刻の平均／現在列長 |
| 42 | 候補個体の最終乗車時刻の平均／現在列長 |
| 43 | 候補個体の連続する乗車の最大時刻差／現在列長 |
| 44 | 下段を失って対象外乗客が残る便の、除去後の非負の支持余裕の乗客数による加重平均 |
| 45 | 候補個体の各ペアの輸送期間が重なる長さの平均／現在列長 |

列32〜36と44の支持は`l > 1`の便を対象とする。乗車0回の個体の時刻と輸送期間、乗車1回以下の最大間隔、個体ペアのない候補の期間重なり、対象便がない列44は0と定義する。期間重なりは`max(0, min(last_a,last_b)-max(first_a,first_b))`を全候補ペア数で割る。実際の再挿入の可否や新しい便乗経路を計算した特徴ではなく、現在列の関係を表す量である。

個体ごとの時刻と輸送距離は、現在列から1回計算して候補間で共有する。現在列の候補を作り直すたびに無効化する。C++費用測定にはこの準備も含める。旧32特徴の算術と結果は保持し、便の走査で既に得た乗客数を追加特徴へ使うことは許す。

### 教師、初期化、学習条件

教師はv077の`20261002T021222_studio`、比較対照はv080の`20261002T113935_studio/models/n49152_h16`とする。入力単位の所属、最大4局面と32候補、3欠測局面の除外を引き継ぐ。旧32列の正規化済み配列をそのまま使う。追加14列の平均と標準偏差は学習49,152入力の有効候補だけから求める。

seed78001で作った従来32→16→1の初期重みとbiasを移し、追加14列の第一層重みは0で初期化する。他の層を再初期化しない。パラメーター数は545から769へ増えるため、情報と容量の効果を完全には分離しない。Adamの学習率0.001、256局面のバッチ、入力の巡回順をv080とそろえ、新規学習する。11,520と92,160更新で保存し、判定は後者だけに固定する。

主検証2,048入力と追加診断14,336入力は既知の検証集合である。入力ごとに局面を平均し、M<80とM>=80の2層内で6,000回復元抽出する。比較は1つとし、95%区間を使う。追加診断や途中の重みで主判定を差し替えない。短縮候補の捕捉率、候補対正解率、観測最良値との差、Mの2群も報告する。

### C++照合と探索全体の評価

学習用32入力の128保存局面を使い、最終モデルの特徴、予測、選択をLOCALと非LOCALで照合する。生特徴の許容差は`1e-10 + 1e-12 * abs(参照値)`、推論値は`2e-4 + 2e-5 * abs(CPU参照値)`、選択候補は全件一致を要求する。各構成で各局面を1回だけ測り、共通準備、候補抽出、特徴、推論を含む費用を記録する。

探索評価へ進む条件を通過した場合は、最終重みを単一C++へ機械的に埋め込む。入力は公式の通常分布からseed930000000以降の未使用200件を生成し、既存の学習、検証、本評価入力とseedおよびハッシュで重複を除く。v076、v079、v082を同じStudio、LOCAL、既存時間補正、20並列で各1回評価する。全件合法、E=0、操作数100,000以内、既存エラー0、盤面領域全返却を要求する。v079比を採用候補の判定に用い、v076比で平均5手の目標との差も報告する。各版の最小手数を共通参照値として擬似相対を計算する。

v079との探索差には学習量と更新数の違いも含む。特徴追加の比較はv080の保存対照で行い、探索比較は完成したモデルの有効性を判定する。LOCALと非LOCALをビルドして意図した変更を確認し、通常探索の機構確認を学習入力2件で行う。M3の最終100入力評価はこの実験に含めない。

CPUのデータ準備は最大20プロセス、GPUは1学習プロセスとする。MPS上限16 GB、CPUとGPUを保守的に合算する既存監視の停止閾値56 GB、ユーザー上限64 GBを維持する。学習は1,024更新ごとに再開可能な状態を保存する。全体上限は90分とし、その1分前から保存して停止する。重複起動と完了済み評価の再実行を拒否する。

## 実験後

### 判定

**主検証の基準に未達。今回の14関係特徴を加えたモデルは採用見送りとし、探索全体の評価は実行しない。** 機構確認と費用条件は通過した。

| 対象 | 選択直後手数の平均差 | 入力単位の95%区間 | 短縮選択率の差 |
|---|---:|---|---:|
| 主検証2,048入力 | −0.004028手 | −0.011111〜+0.003052手 | +0.439ポイント |
| 追加診断14,336入力 | −0.005633手 | −0.008231〜−0.002999手 | +0.371ポイント |

主検証で短縮可能な局面の捕捉率は24.14%から25.65%へ、候補対正解率は71.35%から71.79%へ上がった。学習用の候補対正解率は71.60%から72.28%だった。追加診断にも小幅改善があるが、主判定を差し替えない。平均5手への進展を示す結果は得られていない。

### 機構と費用

全65,536入力で元データの対応と旧32特徴を照合した。独立再生による32入力、128局面、4,096候補の追加14特徴の最大誤差は約1.12e-16だった。人工順位と実4局面の学習は100%、CPUとMPS、再開後のAdam更新の一致も通過した。

最終モデルのC++は両構成の全256局面で特徴と候補選択が一致し、最大予測誤差は約1.91e-6だった。機械的に埋め込んだモデルと照合用モデルの出力も一致した。共通準備を含む選択全体の平均費用はLOCALで約0.0652 ms、非LOCALで約0.0659 ms、保存対照比はそれぞれ1.615倍、1.617倍だった。費用は2倍以内だが増加している。

本計算は13:06:04〜13:09:49 JST、約225秒で正常終了した。監視上の最大使用量は約7.55 GB。本体と監視の終了コードは0だった。最終重みは`src/bin/v082_nn_relation.cpp`へ機械的に書き出したが、採用版v079は維持する。探索用に固定した新規200入力は生成済みだが、solver評価には使っていない。

### 考察と次の前提

この14特徴の追加は、支持と同乗の情報を使って候補選択を小幅に改善した範囲にとどまった。関係を直接符号化する別モデルまで無効と確認した結果ではない。一方、v080〜v082の量、容量、損失、少数特徴の比較では、目標へ大きく近づくモデルは得られていない。

ユーザーは細かな調整を続けず、高品質な教師と長期的な利益の学習を優先するよう明示した。次はB-105として、同じ局面と対応する乱数条件で後続探索を比較し、独立な試行でも利益が残る教師を作れるかを検証する。v082の結果に合わせた特徴の再調整はしない。
