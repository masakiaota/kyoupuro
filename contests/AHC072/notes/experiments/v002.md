# v002：同色の容量制約付き最小集約木

## 実験前

- 仮説：backlog の O1、O2 と B-01 に基づく。同色を集める距離の負担を、巣への共通経路をまとめて運ぶ利益が上回るなら、混色巡回の v001 より `T` を減らせる。グループ内の集約木を厳密最適化し、その費用でグループ分けを探索する。
- 変更：v001 から時間管理、盤面距離の前計算、実盤面での操作検証を引き継ぐ。混色の集荷と配送を、同色7匹以下のグループを根付き Steiner 木で巣へ集約する構成へ置き換える。各辺で、その下のグループ内スライム全員を1回だけ運ぶ。
- 機構確認：`merge_vertices`、`multi_carry_moves`、`steiner_rows_computed` で集約と厳密DPの発動を確認する。`sa_evaluated`、`initial_T - final_T` でグループ分けの探索を確認する。DPの最適値、復元した木の辺数、出力の操作数が一致し、全グループが帰巣することを検証する。
- 採否基準：既定の `tools/in` 全100件を `scripts/eval.py` の既定 `LOCAL`、`-j 2` で1回評価する。全件で公式 scorer 成功、`E = 0`、ローカル実行時間2,000 ms未満を必要条件とする。集約と厳密DPが発動し、合計 `T` が初期構築より小さく、同じ100件の既存 v001 より小さければ、提出候補として採用する。通常生成99件の比較も併記する。

## 実装設計

### グループ内の厳密最適化

各グループを同色7匹以下とし、他グループの初期個体を通過時に下段へ保存する。合流後も反転で色順を考慮する必要がなく、グループを結ぶ木の使用辺数が操作数になる。

端点の部分集合と合流する床マスについて、2つの部分集合の合流と、隣接辺による最短距離の伝播を行う。これは盤面グラフ上の Steiner 木の厳密DPである。端点集合をソート済みのキーでメモ化し、グループ間の移籍や交換でも変わらない部分集合を再利用する。距離の伝播は整数バケットで行う。

得られた木を巣から根付け、葉から順に部分木内の匹数を送る。各操作の移動対象は7匹以下なので、外部の1匹を残す場合も高さ8以内になる。すべてのグループの全帰巣を通常の構成に含める。

### グループ分けの探索

初期構築では、巣から遠い個体を核にして、既存の集約経路を共有しやすい同色個体を加える。焼きなましでは同色グループ間の移籍、交換、複数個体の交換、分割、結合を行う。費用は厳密な集約木の辺数で比較する。

ある色が全体で7匹以下なら、その全員を1グループにした最小木がこのモデル内で最適である。該当色には不要な分割探索を行わず、8匹以上いる色の分け方に時間を使う。

採択した各グループについて実行可能な集約木も保持する。最良解は常に全帰巣までの木の集合として保持し、終了時にはその木を出力する。

### 時間とメモリ

タイマーは `main` 開始直後に作り、`JUDGE_TIME_LIMIT_SEC = 1.90`、`LOCAL_TIME_RATIO = 0.80` を使う。`PROGRAM_TIME_LIMIT_SEC` の96%までグループ分けを探索する。DPの配列はまとめて確保し、キャッシュの使用量を制限する。キャッシュを破棄する場合も、すでに保持した集約木とその費用は維持する。

### 検証順序

ビルドと静的確認の後、`0001.txt` で機構確認し、同じ実装を全100件で評価する。solver 実行後は結果に基づくコード変更を行わず、記録と判定を行う。macOS のビルドには v001 と同じ `SDKROOT` と `MACOSX_DEPLOYMENT_TARGET=15.0` を指定する。

## 実験後

### 判定

棄却。提出候補としての事前基準である、v001 より小さい合計 `T` を満たさなかった。A案の実装と全帰巣の構成は成立しており、機構未発動による棄却ではない。

### 結果

- 全100件で公式 scorer が成功し、スコアと出力行数が一致した。全件で `E = 0`、`fallback_count = 0` だった。DPの最適値、復元した木の辺数、操作数の一致と、各グループの全帰巣も内部検証を通過した。
- v001 に対して合計 `T` は5.92%増加した。ケース別では17勝、0引き分け、83敗だった。手作りの seed 0 を除く通常生成99件では5.94%増加し、16勝83敗だった。
- 初期構築に対して合計 `T` は3.81%減少し、81件で改善した。個別最短距離合計に対しては64.17%減少した。
- 全100件で合流と複数匹輸送が発動した。合流点は計5,019か所、そのうち初期のグループ端点以外での合流は2,102か所、2匹以上の輸送は19,673操作、7匹の輸送は4,172操作だった。
- 部分集合DPの計算行数は計6,343,171だった。保持したDP配列は最大61,407,600要素で、設定したキャッシュ破棄は発動しなかった。
- ローカル実行時間は平均1,326.61 ms、最大1,609 msで、全件が2,000 ms未満だった。全色が7匹以下で、色ごとの最小木だけでこのモデル内の最適解が得られた11件は、グループ分けの探索を行わずに終了した。
- グループ分けを探索した89件では、焼きなまし部分が平均1,451.77 ms、solver 内部の終了計測が平均1,459.94 msだった。時間予算の大部分を探索に使っている。
- 単発の `0001.txt` でも全29匹の帰巣、17か所の合流、93回の複数匹輸送を確認した。その後、同じ実装を全件評価し、結果に基づくコード変更は行っていない。

### 入力群ごとの比較

通常生成99件を入力の `K` で分けると、v001 に対する差は次のようになった。増加率は各群の合計 `T` の比であり、ケースごとの比の平均ではない。

| 入力群 | 件数 | v001 に対する操作数増加率 | 勝敗 |
| --- | ---: | ---: | --- |
| `K <= 6` | 42 | +1.11% | 14勝28敗 |
| `7 <= K <= 9` | 31 | +7.19% | 2勝29敗 |
| `K >= 10` | 26 | +11.27% | 0勝26敗 |

最多色が全体の40%以上を占める31件でも、合計では v001 に対して2.64%増加した。今回の実装と評価セットでは、色数が少ない群ほど差は小さいが、色の偏りだけで A案が優位になるとは確認できなかった。

### 考察

最小集約木の構築と、合流後の経路を複数匹で共有する機構は成立した。同色7匹以下という各グループの内側では木を厳密に最適化しており、その費用を使ったグループ分けも初期構築を改善した。

一方、この構成全体は、評価した100件の平均で混色配送の v001 を上回らなかった。特に `K >= 10` の群では全26件で v001 の方が良かった。これは今回の2実装の比較結果であり、同色集約を用いるすべての解法の上限を示したものではない。

次の実験では、A案についても全帰巣する実装が存在し、その厳密な集約木を使ったグループ分けが、今回の評価では v001 より平均で劣ることを前提にできる。同色の集約そのものが未発動だった可能性と、機構が発動した上で平均スコアが届かなかった結果を区別できた。
