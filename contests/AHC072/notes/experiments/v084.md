### 個体20特徴

現在の完成操作列を一度走査し、元の個体IDごとに以下を作る。教師の試行後の情報は使用しない。移動とはその個体が便の乗客になる操作を指し、時刻は0始まりとする。

| 列 | 内容 | 規格化 |
|---:|---|---|
| 0 | 初期位置から自色の巣への床上最短距離 | Nで割る |
| 1 | 同じ2地点のマンハッタン距離 | Nで割る |
| 2 | 初期位置の隣接床数 | 4で割る |
| 3 | 巣の隣接床数 | 4で割る |
| 4 | 移動回数 | 現在列の手数で割る |
| 5 | 移動距離の合計 | Nで割る |
| 6、7 | 最初と最後の移動時刻 | 現在列の手数で割る |
| 8 | 連続する移動の最大時刻差（移動1回なら0） | 現在列の手数で割る |
| 9、10 | 同乗する他個体数の平均と最大 | 7で割る |
| 11 | 単独移動の割合 | 移動回数で割る |
| 12 | 同乗した他個体の延べ数に占める同色の割合 | 同乗なしなら0 |
| 13 | 別色の同乗者を含む便の割合 | 移動回数で割る |
| 14 | 2マス以上のジャンプに乗る割合 | 移動回数で割る |
| 15 | 2マス以上のジャンプで下段の支持役に入る回数 | 現在列の手数で割る |
| 16 | その支持で支えた乗客の延べ人数 | 現在列の手数で割る |
| 17 | 支持時の最小の余裕（k+1−l） | 8で割る。支持なしは8を使い、列15と区別する |
| 18 | 乗車時の下段高さkの平均 | 8で割る |
| 19 | 乗る束の下からの順位の平均 | 7で割る |

同じ現在列に対する生特徴は共通とする。個体の埋め込みは、その個体が初めて選択対象に含まれたときに計算し、現在列が変わるまで再利用する。進行度、停滞数、現在手数と最良手数、支持と乗車の係数は既存32特徴から候補側へ渡す。

この表現は、全移動系列や具体的な個体対の対応を保持しない。完全な操作列モデルやグラフモデルとしては扱わない。

### モデルと固定した学習条件

共有部は20→16→8とし、両層にReLUを使う。候補内の個体について8次元の平均と最大を求め、既存32特徴と連結した48次元から16→1で順位を出す。隠れ層にReLUを使い、出力が小さい候補を選ぶ。全1,273パラメーター。

教師はv077の保存した初回試行後の現在手数とする。v083の8試行平均は再現性の診断にだけ使い、本学習へ混ぜない。v080と同じ65,536入力を使い、学習49,152、検証16,384に分ける。既存の主検証2,048入力を主判定とし、残り14,336入力は診断とする。分割の再選択はしない。既存の教師を再利用するため、新しい教師生成は行わない。

20特徴の平均と標準偏差は学習入力内の実在する個体と局面だけで求める。標準偏差が1e-6未満なら1とする。既存32特徴の正規化はv080の保存値を維持する。seed78001、Adam、学習率0.001、バッチ256局面、v080と同じ順位損失と局面順で92,160更新する。11,520更新も診断として保存するが、モデルの選択には使わない。

初期の候補側の既存32列とバイアスは、v080のseed78001の初期モデルへそろえる。追加16列の重みを0にし、初期関数が同じになるようにする。共有部は同じseedで初期化し、追加列と共有部へ勾配が流れることを確認する。人工順位の正解率99%以上、既存の固定実4局面への正解率95%以上を要求する。最終C++予測はCPUと相対2e-5、絶対2e-4以内で一致し、候補順位の同点は元順位で解決する。

### 実行と費用

抽出は保存済みの操作列の再生だけを行い、探索を実行しない。C++抽出器と独立したPythonの再生で固定32入力の個体20特徴を照合する。すべての入力では旧32特徴と教師、候補IDの対応を照合する。学習配列の個体枠は凍結した入力集合の最大個体数に合わせ、存在しない個体は学習と正規化から除外する。C++側のsolverは元の問題上限を維持する。

学習後はLOCALと非LOCALでC++の保存候補予測を確認する。費用判定は共通処理を毎局面から準備する場合を使い、埋め込みを再利用する場合も別に記録する。通常探索の2入力では合法性と経路の発動を確認する。探索用200入力はseed950000000以降から生成し、既知の学習用、検証用、本評価用とのseedと入力ハッシュの重複を除く。結果を見て入力や条件を入れ替えない。

入力単位の抽出完了印と1,024更新ごとの学習状態を保存する。CPU20並列、GPU学習1プロセスとし、MPS上限16 GB、大規模学習のCPU子群とGPUの監視値56 GBで停止する。全工程の保護上限は4時間。10分以内の見込みなら監視して次工程へ進み、それを超える場合は計算を放流して見込み時刻を伝える。
