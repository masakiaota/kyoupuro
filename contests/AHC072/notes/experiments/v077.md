## 最初の作業単位と長時間計算の区切り

次の作業単位は段階1〜5とし、128入力の試作データ生成から初回学習の結果報告までを目指す。小規模確認、生成、検査、初回学習のコード、仕様、進行条件を、最初のsolver実行前に固定する。検査に通れば、コード変更を挟まず次の固定処理へ進める。

1. 既存入力のseedと内容ハッシュを調べ、重複しない入力集合と用途を固定する。
2. 候補抽出規則、特徴の順序、保存状態、時計、期限超過時の扱いを定める。
3. v076を基に、途中状態を保存し、同じ状態から各候補を試す採取器を実装する。学習環境とコード、生成から検査と学習へ進む実行スクリプトも用意する。
4. 学習用96入力のうち4入力を事前に選ぶ。`M >= 80`と`M < 80`を2入力ずつ使い、各4局面、最大32候補で確認する。最大512候補である。
5. 機構確認を通過した採取結果は試作データの一部として保持し、残る124入力を実行する。完了分を同じ条件で再測定しない。
6. データの検査と事前の進行条件を満たしたら、固定条件の初回学習へ進む。
7. 長時間計算になる場合は、起動したプロセス、保存先、進捗、再開方法を本ノートへ追記し、計算を継続したまま応答を終える。短時間で完了する場合は初回学習の結果まで確認して報告する。

初回の128入力は試作である。6時間の不在中に進める追加指示を受け、増量条件を末尾へ事前登録した。候補間の差と教師の成立を確認したら、固定条件の学習と次の節目への増量を自動で進める。採取器では、現在列だけでなく、乱数、候補順位、再試行履歴、処理別の使用時間も複製する。

今回の用途別集合を入力seedと内容ハッシュで分離する。同じ入力の途中局面や変換例は、その入力と同じ用途に置く。`tools/in`、`tools/validation1`、過去の調整入力も重複確認の対象とする。seedが600以上という理由だけでは未使用と判断しない。最終評価入力のsolver出力を、今回の特徴選択やモデル選択へ使わない。`tools/in`を最終評価に使う場合は過去の開発に使った既知入力として報告する。

教師生成は以下の条件から始める。

- 採取局面は、LNS進捗10%、35%、60%、85%を過ぎて最初に対象の通常順位選択へ入った時点とする。
- 各局面で、適格な候補の現行上位16件と、残りの順位帯から16件を抽出する。現行が選ぶ候補を含め、候補が不足すれば実在する分だけを使う。後半16件の厳密な抽出規則は実装前に固定する。
- 保存状態はStudioで生成する。各候補を一度強制選択し、その後はv076の選択へ戻して探索を続ける。
- 最初の候補試行と後続探索の合計予算は`PROGRAM_TIME_LIMIT_SEC * 0.02`とする。LOCALでは30.4 msである。状態の復元と保存の時間を除き、探索中の通常処理の時間を含める。
- 温度計算は元の探索進捗を引き継ぐ。教師分岐の停止期限は別に扱い、期限内に確定した最良手数を教師とする。
- 最初の候補の成功、失敗、同手数受理、時間切れ、即時短縮、後続での短縮を別々に保存する。これらの試行後の情報をNN入力へ入れない。
- 入力間は最大30プロセスとし、同じプロセス内の候補を順に試す。プロセス内の追加並列を重ねず、メモリ使用量も確認する。小規模確認や終盤は入力数に応じて稼働数が少なくなるため、並列上限と実際の処理単位を記録する。保存局面と教師分岐を通じて、元の採取軌跡へ分岐結果が混ざらないようにする。

最大件数は128 × 4 × 32 = 16,384候補である。対象分岐への未到達や候補不足は理由を記録する。分岐予算の合計は最大約498秒相当だが、これは処理全体の所要時間ではない。30並列の上限を使えても、基準探索、復元、保存、検証の費用と負荷による違いが加わる。初回にかかる時間には、採取器の設計と実装、ビルド、学習環境の準備も含まれる。計算の所要時間は小規模確認で測り、長時間ならバックグラウンドで続ける。

## 学習と組み込みの計画

特徴は選択前に計算できる約32個から始め、同じ特徴の線形モデルと、32入力、16中間ユニット、1出力の小型NNを比較する。中間層はReLUとし、同じ局面の候補対に対する順位損失で学習する。終了時の最良手数が同じ候補対には優劣を付けない。局面ごとの重みをそろえ、正規化統計は学習用96入力だけから求める。

学習にはPyTorchの専用環境を使う。GPUでの実行可否を確認し、データ読み込みや前処理にもCPU30コアを利用できる構成を選ぶ。モデルが小さいため、GPUとCPUのどちらが速いかは未確認である。利用する計算装置、バッチ数、学習設定、最大反復数を開始前に固定する。途中保存には重み、最適化器、乱数状態、反復番号を含める。具体的な版、学習率、打ち切り条件は事前登録の未確定事項である。

提出用は`src/bin/v077_nn_rank.cpp`を予定する。重みと正規化を固定配列へ出力し、C++の積和とReLUで推論する。採取器と提出用で特徴順序、候補抽出、同点時の選択をそろえる。PythonとC++の照合を終えてから、探索全体を評価する。

## 段階ごとの判定

### 教師生成

全ての保存された完成解が合法で`E = 0`を満たし、状態復元、候補の適格性、領域の返却、予算内の教師確定が検査に通ることを必須とする。期限を超えた後の短縮を予算内の教師に混ぜない。検査不合格なら試作用教師の生成へ進まず、結果を報告する。

試作用教師の生成後は、採取数、欠測数、同点率、時間切れ、現行選択と観測最良候補の差を集計する。学習用と調整用の双方で優劣のある候補対が得られたことを確認する。教師に差がない場合はその事実を報告し、教師や時間幅を変える前に新しい指示を受ける。

### 学習

調整用32入力で、現行順位、線形モデル、NNが選ぶ候補の教師手数を比較する。局面内の比較を入力ごとに平均し、入力を等重みで集計する。NNが現行順位より低い平均教師手数を得ることを、順位学習の改善と判定する。候補対の正解率、両匹数群の結果、観測最良候補との差も報告する。

### Studio検証とM3本評価

基準版とNN版を同じ入力、LOCAL時間補正0.80で各1回評価する。`scripts/eval.py`の並列数は、ユーザー指定によりStudioを20、M3を既存の2とする。比較する2本は必ず同じマシンと並列数で実行する。先頭入力のウォームアップは評価スクリプトの既存動作に従い、集計しない。学習や教師生成を同時に走らせず、比較条件を記録する。

採用条件の初稿は次のとおりである。

1. 全件合法、`E = 0`、100,000操作以内、既存エラー計数0、盤面領域の全返却、最大外部時間2,000 ms以内を満たす。
2. NNの発動と選択の変化を確認し、候補抽出、特徴抽出、推論の合計時間のケース平均が`PROGRAM_TIME_LIMIT_SEC * 0.02`以内となる。
3. 同じマシンのv076に対し、共通参照値を使う擬似相対平均が厳密に改善し、`M >= 80`群の操作数合計が悪化しない。

主指標はv076の経緯を引き継いだ擬似相対とする。参照する版をv076と凍結したv077の2本に固定し、ケース別の両版の最小`S`を共通の`MIN`として、`round(10^9 * MIN / S)`を計算する。操作数の合計、ケース別の勝敗、両匹数群の差、最大時間も報告する。これは手元2版の比較であり、公式の相対スコアや順位の予測ではない。

Studioで条件を満たした場合は「Studio検証通過」と記録し、最終採用は事前に選んだ100入力を使うM3で判断する。未使用100入力と`tools/in`100入力のどちらを使うかは評価前に決める。同じ実装を再評価してノイズを測る運用は行わず、単回比較の差と変更の因果的な効果を区別する。

## 実行結果を受けた変更の境界

[AGENTS.md](../../AGENTS.md)は、実行結果の報告後について「After reporting them, you must stop and wait for a new instruction from the user before making any improvement based on those results.」と指定している。採取器もこの対象として扱う。

事前に固定した試作用教師の生成や学習処理は、長時間計算中も継続できる。一方、新しい実行結果を受けて採取器、特徴、教師、解法を変更する場合は、結果と必要な変更を報告して応答を終え、新しい指示を受ける。小規模確認の不合格を隠して試作用教師の生成へ進む処理は加えない。
