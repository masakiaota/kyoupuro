# v023: 合流候補の試行をB表現と差分復元で処理する

## 実験前

- 根拠: O31では逐次操作がB、盤面のコピーを含む処理がAに有利だった。ユーザーから、既存提出の差分更新可能な箇所でBの効果を検証する指示を受けた。v019〜v021の `Constructor::planPair` は第1経路の試行ごとに盤面全体をコピーしており、操作で変わる2マスを保存して戻せる。
- 仮説: 試行盤面を高さ・向き付きのB表現にし、各操作の変更前の2マスだけを保存して復元すれば、盤面全体のコピー費用を除き、Bの操作適用と高さ参照の利点を生かせる。候補単位のAからBへの変換費用を含めても、Aのコピー方式とAの差分復元方式を上回る。
- 変更: v021の `planPair` 内で第三のマスに合流する試行だけをB表現と差分復元へ変更する。確定盤面、探索戦略、評価関数、乱数、時間配分を保持する。Bは色列32 bitと高さ・向き1 byteの配列とし、試行ごとの保存領域を再利用する。途中のcontinueと例外でも変更前の盤面へ戻す。LOCALと非LOCALの両方で有効で、LOCALだけで変換数・試行数・保存操作数を計測する。v000は変更しない。
- 機構確認: 補助コードでAコピー、A差分復元、Bコピー、B差分復元を同じ候補に適用する。操作後の盤面、復元後の盤面、経路探索結果と候補の評価・操作列の一致を確認する。新しいsolverの本処理もAコピーの参照処理と照合する。全ケース評価では `trial_board_conversions`、`trial_undo_attempts`、`trial_undo_moves` が発動し、合法性・E=0・既存のエラー計数を確認する。
- 採否基準: 正しさの照合が全件一致し、固定仕事量でB差分復元の合流候補処理のCPU時間中央値がAコピーとA差分復元の両方より5%以上短いことをB採用の条件とする。提出候補としては、さらに既定100件が全件成功・E=0、最大2,000 ms未満、処理エラーの増加なし、総操作数が保存済みv021以下であることを要求する。固定仕事量と時間制限下のスコアは別々に判定し、1回のスコア差から恒常的な性能効果を断定しない。

### 比較条件

- 既存候補の照合: v007の差分評価は木の近傍評価であり、今回の塔の試行盤面とは別である。v013、v015、v016にもコピーを伴う試行があるが、個体情報を含むため変更範囲が広い。直接の派生元には最新のv021を選ぶ。v022は別会話の共同再挿入実験に割り当て済みのため、本実験はv023とする。
- 固定仕事量: 通常99件の入力と保存済みv021出力を使う。操作列の0、1/4、1/2、3/4時点の盤面ごとにvariant=0で既存の候補生成を行い、優先度上位4候補までを比較する。保存済み解の途中盤面から再生成した候補であり、元実行の内部探索履歴とは区別する。
- 4方式とも同じ候補を8巡し、ケースと巡回ごとに測定順を交代する。準備・一致検証・DPの初回計算は計測外、必要な盤面コピー・Bへの変換・操作適用・復元・経路探索・候補比較は計測内とする。候補処理全体の時間を主指標とし、部分処理だけの短縮を全体の短縮として扱わない。全99件のCPU時間を巡回ごとに合計し、その8値の中央値を比較する。計時打ち切りを無効にするのは補助コードだけである。
- 実行環境: Apple M3、GCC 15、既定のビルド条件にv021のO3 pragmaを保持する。LOCALと非LOCALをビルドし、差分を確認してから実行する。
- 通常評価: `scripts/eval.py --wait-lock --label lazy_trial_undo v023_lazy_trial_undo` を既定のLOCAL・並列数2・tools/in全100件で1回実行し、保存済みv021と比較する。同じ実装の再評価はしない。
- 実行後は結果を記録し、実行結果に基づくコード修正・方式変更は追加のユーザー指示を待つ。

## 実験後

### 判定

棄却。合流候補の試行にB表現と差分復元を組み合わせる今回の構成は、固定仕事量での5%短縮と総操作数の条件を満たさなかった。差分復元自体は正しく発動しており、未発動による失敗ではない。v000と親v021は変更していない。

### 固定仕事量での結果

通常99件の396盤面から1,561候補を生成した。8,115回の試行・22,254操作について、4方式の操作後の盤面、復元後の盤面、経路距離、経路、評価値、選ばれる操作列が一致した。v023の実際の `planPair` とAコピーの参照処理も一致した。高さ・分割位置・向き・帰巣を組み合わせた26,112件と、保存済み20,910操作の逐次再生、99件の例外時復元にも成功した。

同じ1,561候補を処理したCPU時間の8巡中央値は以下のとおりだった。経路探索と候補比較を含む `planPair` 全体の時間であり、Bへの変換と復元も含む。

| 表現と試行方式 | CPU時間 | Aコピー比 |
| --- | ---: | ---: |
| A・盤面コピー | 83.723 ms | 基準 |
| A・差分復元 | 83.820 ms | 0.116%増 |
| B・盤面コピー | 84.547 ms | 0.984%増 |
| B・差分復元 | 83.584 ms | 0.166%減 |

B差分復元はA差分復元比でも0.281%減にとどまった。各方式の巡回間の幅より小さな差であり、今回の条件では同程度と判断する。Aの盤面は1,600 byte、Bは2,000 byteである。差分の保存要素はAが12 byte、Bが16 byteで、v023のB用保存領域は800要素を再利用する。コピーする量を減らせても、対象処理全体の明確な高速化にはつながらなかった。

### 全ケース評価

既定のLOCAL・並列数2で1回評価し、公式採点は全100件成功した。独立再生でも合法・E=0、操作数と出力行数および計測値の一致を確認した。構築エラー、LNSエラー、例外による作り直しは0、最大実行時間は1,619 msで、全件2,000 ms未満だった。

本評価ではBへの変換121,469回、差分復元を伴う試行784,206回、保存した操作2,915,993回を確認した。全100件の総操作数は保存済みv021比49手増、0.2339%悪化し、42勝17分41敗だった。case0000は同じ操作数だった。時間依存の探索を1回ずつ比較した結果であり、49手の差をB表現に固有の性能劣化とまでは断定しない。

### 考察と次の前提

差分復元できる箇所が存在することと、コピー方式より速くなることは別に確認する必要がある。今回の合流試行ではAでも差分復元の優位は見えず、Bと組み合わせても採用に足る改善は得られなかった。O31のコピー比較だけで差分復元よりコピーが速いと一般化することも、今回の結果でBがあらゆる処理で不利と一般化することもしない。

現時点ではv021の当該箇所をAコピーのまま保持する。再開条件: より大きな状態をコピーする箇所、状態の保存・復元が実行時間の主要部分を占める箇所、またはBへの変換が不要な構成について、追加の検証指示を受けた場合。評価後のsolver変更と追加評価は行っていない。

生の測定値、照合件数、全ケースの検証と比較は `adhoc/v023_trial_undo/`、正式な評価記録は `results/eval_records.jsonl` と2つのCSVに保存した。再現手順は [比較レポート](../../adhoc/v023_trial_undo/README.md) を参照する。
