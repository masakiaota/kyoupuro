# v004：踏み台網上の選択的な混載便

## 実験前

- 仮説：backlog の B-04 / D と O2、O3、O7、O8 に基づく。Cに残る局所的な少量輸送を異色間で共有し、実在する踏み台から長距離移動できれば、混載による巡回距離の増加と踏み台の早期消費を含めても総操作数が減る。
- 変更：`v003` の踏み台配置・色順・単色輸送木を土台とし、`v001` の混載と両端荷下ろしの操作モデルを組み合わせる。色の処理前に、近い処理順の2色の2地点から合計4匹以下を運ぶ混載便を選択する。混載便の集荷・配送を現在の踏み台配置で探索し、個体を取り除いた後の単色便・後続便まで再評価する。単色便の容量に応じた最大8匹輸送は引き継ぐ。solver は `src/bin/v004_mixed_spring.cpp` とする。
- 機構確認：`mixed_shipments`、`mixed_carry_moves`、`mixed_long_jump_moves` で混載と長距離移動の併用を確認する。`source_returned`、`home_launch_long_moves` で両端荷下ろしを記録する。`mixed_proposals`、`mixed_evaluated`、`mixed_accepted`、`before_mixing_T - final_T` で探索の発動と同一実行内の改善を測る。各便の対象全帰巣・他個体保存、各色の残需要の全帰巣、予測Tと出力操作数の一致、最終E=0を検証する。
- 採否基準：`tools/in` 全100件を既定のLOCAL、既定 `-j 2` で1回評価する。全件の公式 scorer 成功、E=0、ローカル実行時間2,000 ms未満を必要条件とする。通常生成99件合計で実際の混載便・混載輸送・混載長距離移動がそれぞれ正であり、合計Tが保存済み `v003_spring_network` より小さければ採用する。機構不発と発動後のスコア不足は区別する。

## 実装設計

### 単色便と混載便の一つの完成計画

全個体を先にCの設置・単色輸送へ割り当て、混載便への所属変更を探索する。混載便の対象を単色便の需要から引くと同時に、以降の踏み台の高さも減らして評価する。混載便の後には、その便の対象全員が帰巣し、対象外の静的配置が保存される。

混載便は早い方の色の処理直前に置き、相手色は1〜2段後までとする。1便は異色の2地点から合計2〜4匹を扱う。少数色だけでなく、匹数の多い色の局所的な少量輸送も選択対象にする。

### 混載便の経路

現在地、2地点の集荷済み状態、残る色列を状態にする。集荷と操作する塔の選び直しをコスト0、合法な宙返りジャンプをコスト1とする探索で、集荷途中の帰巣も含めて全対象の帰巣を計画する。通常の全体移動に加え、巣にある下端の同色連続部分を残して上段を発射する操作を扱う。反転と両端での自動帰巣を再現する。

実装は0-1 BFSである。実際に異色を同時に動かしたかどうかも状態に持ち、少なくとも1回混載した全帰巣経路を求める。現在の全待機塔の高さと便の指定をキーに経路をキャッシュする。混載が成立しない組や、後の便と対象が重なる組は候補として棄却する。

待機塔は最大4匹、混載便も最大4匹なので、他個体を保存した隣接移動が常に可能である。長距離移動は、その時点で実際に残る下段から計算する。

### 時間と検証

テンプレートの時間定数を引き継ぎ、timerはmain冒頭で作る。Cの配置・単色経路探索に `PROGRAM_TIME_LIMIT_SEC` の65%まで、混載便の選択と経路探索に96%までを使う。時間切れでは評価途中の候補を捨て、全帰巣まで評価済みの最良計画を出力する。

ビルド・静的確認を済ませてから単発の機構確認を行い、同じ実装を全件評価する。solverの実行結果に基づく実装・方針変更は行わず、結果を記録する。評価は `--wait-lock` を付け、同時進行の実験と評価ログを競合させない。

機構確認には、多色かつ少数個体の `0001.txt` を使う。GCC 15のLOCALビルドと、LOCALなしの構文・警告チェックを実行前に完了した。

## 実験後

### 判定

棄却（現時点の提出候補として）。合法性、全帰巣、時間、混載と長距離移動の併用は事前条件を満たしたが、保存済みv003の合計Tを下回らなかった。機構不発による棄却ではない。

### 結果

- 全100件で公式scorerが成功した。全件で公式スコア、出力行数、予測Tが一致し、E=0、`fallback_count=0` だった。各混載便の全対象帰巣と対象外の配置保存、単色便の残需要の全帰巣も検証した。
- 通常生成99件で、v003比の合計Tは13手増、0.0479%の悪化だった。45勝10分44敗。seed 0を含む100件でも13手増、0.0478%の悪化で、45勝11分44敗だった。
- 通常生成99件の同一実行内では、混載探索開始前から79手、0.2902%を削減し、27件で改善した。この探索には、混載便の追加・変更と、それに伴う後続の単色経路の再評価・再構築が含まれる。
- 最終計画の混載便は計33便、対象74匹、混載便に属する操作は448手だった。異色を同時に動かす操作は215回、混載した長距離移動は50回だった。混載便は27件、混載長距離移動は23件で採用されていた。
- 出発点で23匹が帰巣し、帰巣する下段を使った長距離発射は11回だった。これらはそれぞれ18件、11件で発動した。
- ローカル実行時間は全100件で平均1,472.90 ms、最大1,479 msだった。前半のC型探索は平均984.61 ms、混載探索は470.96 ms、復元・検証は0.034 msだった。
- 通常生成99件では混載候補の全体費用を計1,434,210回評価した。一方、経路の実探索は32,681回であり、経路キャッシュを1,599,558回利用した。途中帰巣により指定2地点の混載を成立させられない候補は10回棄却された。
- 入力別では、`M <= 35` の21件でv003比1.34%改善、`M >= 100` の21件で0.51%悪化した。同一実行内の79手削減のうち54手が前者、5手が後者だった。`K >= 10` の26件ではv003比1.32%改善したが、この条件別比較には前半のC型探索の結果差も含まれる。
- 単発の `0001.txt` でも公式scorer成功と全帰巣を確認した。混載便2便、混載輸送11回、混載長距離移動2回が発動し、混載探索開始前から8手減った。以後、同じsolverを変更せず全件評価した。

### 考察

混載便と踏み台からの長距離移動を組み合わせ、便の全帰巣後に単色便へ接続する構成は成立した。最終計画への採用と同一実行内の操作削減が実測できたため、Dの機構自体を未成立・不発として扱う必要はなくなった。

一方、完成版の合計Tはv003を更新できなかった。差を分解すると、混載探索に入る前の計画が保存済みv003より92手多く、混載探索が79手を減らし、最終的に13手の増加となった。前半の探索時間と探索軌跡がv003と異なるため、92手すべてを時間配分変更の因果効果と断定することはできない。

今回の2色・2地点・合計4匹以下、色順を固定した混載では、改善が小規模入力に偏った。多数個体の入力に残る局所的な少量輸送へ広く効くという期待は、今回の実測では十分に裏付けられなかった。大規模入力でも混載は成立したが、同一実行内の削減は21件合計で5手にとどまった。

採否基準に従って提出候補としては棄却するが、0.05%弱の差をD全般の効果の否定とは解釈しない。次の実験の前提は「混載と踏み台輸送の接続は可能だが、この構成と時間配分では全体の改善に届かなかった」である。
