# v326: v325の提出時終了目標を1.990秒へ延長

## 実験前（2026-10-05）

- 根拠: minibookの保存比較でv325がv113を上回ったことと、ユーザー報告のv113・係数1.988でAtCoder実行時間1989ms。ユーザーが係数1.990の提出用ファイル作成を明示指示した。O25/O26に従い、時間変更による探索経路の変化と性能の因果効果を区別する。
- 仮説: v325の既存の時間配分を比例延長し、提出の制限内で探索に使える時間を増やすと完成スコアを改善できる。
- 変更: 非LOCALの`LOCAL_SECONDS`の係数だけを`1.880 / 1.900`から`1.990 / 1.900`へ変える。親の計時開始位置、重み、探索処理、LOCAL補正0.80は保持する。ファイル名と説明コメントを更新する。
- 機構確認: ソース差分、GCC15のLOCAL/非LOCALビルド、完全前処理結果を親と照合する。LOCALは診断用ファイル名を除き一致、非LOCALは指定係数の展開差だけとする。今回はsolverを実行しない。
- 採否基準: 提出用ファイルの完成条件は上記の静的照合と両ビルドの成功。時間変更の採否は未判定とし、ユーザーが手動提出後に全件AC、2秒以内の実行時間、リーダーボードのスコアを確認して判断する。LOCALの保存スコアをこの非LOCAL変更の効果とは扱わず、現行指定v113は自動変更しない。

## 時間設定

`PROGRAM_TIME_LIMIT_SEC=1.90`を保持し、式は`1.990 * value / 1.930`に相当する。主探索の期限`value=1.900`は約1.959067秒、最終期限`value=1.930`は1.990秒で、両者の間は約30.933ms。2秒との差10msは式上の余白であり、最終検証・出力を含む実行時間の保証ではない。元v325の同じ最終期限は1.880秒である。

推奨の目安は、少し余白を残すなら1.988（2秒との差12ms）、より余裕を取るなら1.980（20ms）。いずれもv325で未測定の判断であり、今回はユーザー指定の1.990だけを作成する。
