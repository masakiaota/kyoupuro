# A・B・Cの実測比較と次の改善方向

作成日：2026-09-25。対象は A=`v002_mono_steiner`、B=`v001_mixed_deque`、C=`v003_spring_network` である。

## 分析方法

既存の評価記録、各ケースの `TraceStats`、保存された操作列を照合した。全300解を個体ID付きで再生し、操作の合法性、全帰巣、ログの `final_T` との一致を確認した。solver の追加実行はしていない。

- 評価の正本：`results/eval_records.jsonl`、`results/score_summary.csv`
- 再現スクリプト：`adhoc/scripts/analyze_approach_outputs.py`
- ケース別の入力特徴・ログ・再生集計：`adhoc/approach_output_analysis_20260925.json`
- 再集計：`python3 adhoc/scripts/analyze_approach_outputs.py`

評価順位には全100件を使い、生成分布についての分析は手作りの `0000` を除いた99件を使う。以下の操作割合は、断りがなければ99件の操作を合算した割合である。入力特徴の平均はケース等重みである。

## 比較の結論

全100件で3案とも `E = 0` であり、比較対象は操作数 `T` となる。

| 案 | 平均T | Cとの比較 |
| --- | ---: | --- |
| A：同色の集約木 | 323.31 | Cが100勝、合計Tを15.94%削減 |
| B：混色の集荷と両端荷下ろし | 305.24 | Cが90勝2分8敗、合計Tを10.97%削減 |
| C：寿命を計画した踏み台網 | 271.76 | 現時点の最良 |

**次の土台はCが妥当である。** Aは精密な合流経路、Bは混載による積載率の確保に価値がある。Cを基準に、それぞれの機構を盤面内の適した部分へ導入する方向を検討する。

ケース単位でBとCの良い方を選べたとしても、通常生成99件でCから減るのは63操作、0.23%である。提出版の単純な切替だけでは、今回求める大幅な改善には届きにくい。

## 各案の長所と制約

### A：経路を共用する設計は有用だが、隣接移動だけの表現が狭い

同色のグループを固定すると、操作数がSteiner木の辺数と一致する。7匹以下の端点に部分集合DPを使い、合流点も含めて厳密に求められる点が長所である。各操作の `(h - k) * l` を足した延べ移動量は、初期の自色巣までの最短距離合計に対して6.66%の超過だった。

一方、1匹輸送が操作の39.19%を占め、全操作が `l = 1` である。同色の少ない地域では、合流する前の枝に費用がかかる。全色7匹以下で、この構成内では色ごとに最適な木を求め終わっているケースが10件あるが、それらもすべてCに負けた。探索時間の追加だけで説明できる負けではなく、扱う操作と状態の拡張が必要である。

AがBに勝った通常生成16件は、平均 `K = 5.0`、最多色割合40.68%、3匹以下の色に属する匹数割合3.63%だった。同色の量がまとまる条件では、Aの経路共用が生きている。ただし、その16件でもCがすべて勝っている。

多数の端点がある場合は、厳密な部分集合DPの再計算も重い。`M >= 100` の21件では評価済み近傍数の中央値がAで7,234、Cで31,136だった。近傍の内容が異なるため単純な速度比較ではないが、全体を毎回厳密化する設計には計算量の制約がある。

### B：積載率は最良だが、荷物ごとの遠回りが増える

平均積載数はAが2.98匹、Bが3.77匹、Cが2.76匹であり、Bが最も多い。Bの1匹輸送率は17.74%にとどまる。通常生成99件で混色輸送14,413操作、出発点での帰巣1,774匹、帰巣する下段を使う長距離発射709操作が実際に使われていた。混載と両端荷下ろしは、機構として成立している。

代償として、延べ移動量の最短距離合計に対する超過は30.66%と大きい。集荷順と積み順が配送順を制約し、異なる巣への輸送を一つにまとめると、各個体の移動距離が増える。集荷経路は決め打ちの最短路であり、途中の外部踏み台による長距離移動も評価モデルに入っていない。

BがCに勝った8件は、平均29匹、3匹以下の色に属する匹数割合40.37%だった。小さい荷物を単色に分けすぎる問題を、Bが補っていると解釈できる。ただし、これは条件別の観察であり、混載だけの効果を分離した実験ではない。

### C：移動距離とジャンプを両立したが、細い輸送枝が残る

Cの延べ移動量の超過は5.76%であり、通常生成99件で長距離移動を4,453回使っている。設置した踏み台による長距離移動は2,154回、初期の1匹によるものは2,299回だった。設置・配送・踏み台自身の帰巣を含む実際の `T` を評価している点も強い。

残る課題は以下の3点である。

1. **小さい荷物が別々の経路を通る。** 設置後の配送23,222操作のうち、1匹輸送が9,421操作、40.57%を占める。そのうち5,351操作は、全体では8匹以上いる色の輸送だった。少数色だけの問題ではない。
2. **踏み台の場所と寿命が粗い。** 640基を最初に設置し、それぞれ同じ場所に置いたまま、担当色の番に撤去・帰巣させる。利用のあった踏み台のうち205基は、最後に利用されてから担当色の番まで、少なくとも1色分の処理が挟まっていた。
3. **複数経路を協調させる変更が弱い。** 現実装は一辺の付替え、処理順位の隣接交換、単一フェーズの再構築が中心である。順位は変更可能なので、巣から遠ざかる辺が完全に禁止されているわけではない。ただし、合流点や共有区間を複数の枝で同時に変えるには、小さな変更を積み重ねる必要がある。

## 次案を選ぶために切り分けたこと

### 積み方だけの修正は主戦場になりにくい

各色・各有向辺について、現在の総通過匹数を、その辺の固定された出発点・着地点の容量で割って切り上げた値を足した。これは、**現在の辺と流量を変えない場合**の操作数の下界である。

配送23,222操作に対して下界は23,162操作で、差は60操作だった。全 `T` の0.22%にすぎない。下界が達成できると断定するものではないが、現経路のまま荷物を詰め直すだけでは、大きな改善を説明できない。

さらに、1匹輸送9,421操作のうち9,264操作、98.33%は、その色の全輸送を通して1匹しか通らない有向辺だった。空き容量が生じる主因は、同じ辺で何便にも分けてしまうことではなく、荷物が別の枝を通っていることである。

### 設置費は重要だが、その全額が無駄ではない

設置は3,904操作で全 `T` の14.39%、低密度24件では25.77%だった。一方、設置によって同色の個体が集約され、その後の自色配送も安くなる。したがって、この設置費全体を削減可能量とみなしてはいけない。

長距離利用0回の踏み台は16基、1回は119基、2回以上は505基だった。利用回数だけで不要と判定することもできない。移設や統合の判断では、元の個体配置から最終帰巣までの総費用を比較する必要がある。

### Cの利益は直線の多さだけでは説明できない

CのBに対する合計T削減率は、壁率10%以下の16件で9.93%、壁率25%以上の43件で11.76%だった。一方、スライム密度25%未満の24件では5.69%、50%以上の22件では14.33%だった。

入力要因は相互に相関しており、因果効果を分離した数字ではない。それでも、直線の有無だけでなく、繰り返し使う輸送需要と設置費の回収を重視すべき根拠になる。

ここからは未実験の仮説である。どの案も、設置や移設に使った個体まで最初から帰巣計画に含め、総 `T` を最小化する。末尾に残存個体だけを消す処理は設けない。

| 案 | 変える主対象 | 引き継ぐ長所 | 狙う損失 |
| --- | --- | --- | --- |
| D：踏み台網上の選択的な混載便 | 一緒に運ぶ荷物 | Bの積載率＋Cの長距離移動 | 別々の色・局所的に少ない荷物の重複輸送 |
| E：二地点で働く移動式踏み台 | 同じ個体を使う場所と時刻 | Cの反復利用 | 別地点ごとの設置費、利用終了後の待機 |
| F：複数枝をまとめ直す容量付き集約網 | 合流点と共有経路 | Aの小規模な厳密構築＋Cの輸送網 | 同色の荷物が別々の枝を通る費用 |

### D：踏み台網上の選択的な混載便

**根拠：O2、O3、O7、O8。** Cに残る1匹輸送を減らすため、近くにいて経路の一部を共有できる異色の荷物を混載する。Bの「近くから集荷する」長所を、Cのジャンプ可能な盤面で使う案である。

#### 構成

1. Cの踏み台配置を出発点にし、近い処理順の2〜3色から、同じ通路を通る小さな荷物を候補にする。匹数の少ない色だけでなく、匹数の多い色で離れた場所にいる1〜2匹も対象にする。
2. 混載便の集荷順、色列、帰巣順を同時に評価する。Bの両端荷下ろしに加え、実在する踏み台からの長距離移動を使う。長距離移動では格子の偶奇だけに頼らず、色列の反転を追跡する。
3. 混載便を終えるたびに消費した個体と残る踏み台を更新する。後続の便の費用も、その実在する配置で再評価する。
4. 大きな単色便と小さな混載便を同じ全体計画に入れ、どの個体をどちらへ所属させるかを探索する。

最初の成立しやすい実装では、混載便を4匹以下、未担当の待機塔を4匹以下にする。これなら混載便は、他の待機塔を保存しながらどの床も通過できる。**単色の大量輸送まで4匹に制限する必要はない。** 単色便にはCの容量に応じた最大8匹輸送を残す。

各便の対象個体を重複なく割り当て、便の終端をその対象全員の帰巣とする。他便の個体は保存する。混載便は端の色を順に帰巣させられるので、便の実行順を含む完成計画の終端が `E = 0` になる。

#### 勝ち筋と不確実性

単にBへ切り替えるだけでは得られない、「積載率を上げてから長く跳ぶ」効果を狙う。Cの1匹輸送の過半数が8匹以上いる色に属するため、小規模ケース専用に閉じない余地がある。

一方、混載による巣巡回の遠回りと、踏み台の消費時刻の変更が利益を消す可能性がある。近い個体だから混ぜるのではなく、全帰巣までの実 `T` が減る組を選ぶ必要がある。

最初の実験では、踏み台の移設は扱わず、混載便の導入を中心差分にする。機構確認では、混載した長距離移動、混載便へ移した1匹輸送区間、後続便まで含む費用変化を調べる。

### E：二地点で働く移動式踏み台

**根拠：O5、O10、O11。** 一度集めた下段2〜4匹を、前半と後半で異なる地点の踏み台として使い、最後に自色の巣へ送る。

#### 構成

最初の実装は、各踏み台に高々1回の移設を許す二段階構成とする。

1. 前半に需要がある場所へ設置し、予定した便が利用する。
2. 最終利用後の色フェーズ境界で、その塔全体を後半の需要地点へ移す。担当色の帰巣時刻は、この段階では元の色順のままにしてよい。
3. 後半の便が新しい場所を利用する。担当色の番では、新しい場所の個体も通常の単色輸送に含めて帰巣させる。

探索では、移設先・移設時刻・利用する便を一組として変更する。新しい場所に別の踏み台を設ける計画と比較し、設置から移設、全利用、最終帰巣までの費用を計上する。移設によって巣へ近づく場合は、その移動が帰巣経路の一部も兼ねられる。

二つの利用期間は実行順に並べ、古い場所を必要とする便を終えてから移す。移設中の自動帰巣と着地容量も計画する。個体は最初から「初期位置→前半の設置場所→後半の設置場所→自色の巣」に割り当てられているため、終盤に未計画の踏み台が残らない。

#### 勝ち筋と不確実性

Cは踏み台を作る利益を確認できているが、一つの塔を一地点でしか使っていない。205基の利用終了後の空白は、後半の別需要へ転用する候補になる。複数地点のために別々の個体を集める負担を、同じ資材の再利用で下げる狙いである。

待機中であるだけでは移設する価値はない。移設費を回収できる後半需要があり、元の場所の利用と競合しないことが必要になる。この対応が何件見つかるかは未確認であり、3案の中では評価状態の増加も大きい。

機構確認では、同じ個体集合の二地点での長距離利用、移設費、既存設置の統合、担当色の帰巣費を追う。設置費を単純に削った数字で利益を主張しない。

### F：複数枝をまとめ直す容量付き集約網

**根拠：O8、O9、O12。** Cの踏み台配置と色順を固定したまま、同じ色の複数の細い枝をまとめて作り直す。Aの厳密構築を小さな部分問題に使い、Cの長距離移動と最大8匹輸送を保つ案である。

#### 構成

1. 同じ色の、近接する3〜6本程度の小さな枝を選ぶ。各枝が運ぶ匹数と、外側の経路への接続条件を保持して切り出す。
2. 合流点、合流までの経路、共有区間への接続先を同時に再構築する。少数端点には部分集合DPを使い、踏み台から跳べる有向辺と着地容量を扱う。端点数や対象領域を絞り、全盤面の全候補を毎回厳密化しない。
3. 巣へ向かう各個体の最短距離だけでなく、合流後に何操作を共有できるかを評価する。少し寄り道してでも、長い区間をまとめられる候補を含める。
4. 根に到達する閉路のない木へ接続し、処理順位も作り直す。Cのシミュレータで実際の `T` を確かめ、全体の焼きなましへ渡す。

容量から計算する辺ごとの必要便数は、現在のCでは実操作数との差が小さかった。この値を候補の下界や軽い見積りに使い、有望な複数枝変更へ計算を集中させる。ただし、下界だけでは実行順の容量制約まで保証できないため、採用判断は操作シミュレーションに基づく。

再構築の前後とも、全需要が自色の巣へ向かう根付き木に属する。固定された他色の下段を保存しながら、容量に合わせて全需要を送る構成はCから引き継ぐ。`E = 0` を保った完成計画どうしを比較できる。

#### 勝ち筋と不確実性

現在の1匹輸送は、その場に後続便を待たせればまとまるものがほとんどではない。別々の経路を通る個体を、同じ経路へ誘導する必要がある。一辺だけを変えると損でも、複数の枝と合流点を一緒に変えると得になる変更を狙う。

不確実なのは、現在残る細い枝のうち、集荷の追加費用を払ってなお共有できる割合である。1匹輸送40.57%を、そのまま削減可能量とはみなさない。また、厳密部分問題が重すぎると、他の有効な探索を減らしてしまう。

機構確認では、複数枝の同時変更による採用数、共有された区間、1匹流量の辺の減少、再構築費用と実 `T` の差を確認する。最初の実験では混載や踏み台移設を加えず、経路再構築を中心差分にする。

## 推奨する着手順

**F → D → E** を推奨する。

- **Fを最初にする。** Cの全帰巣構成を保ちやすく、匹数の多い色の細い輸送枝にも効く可能性がある。既存ログから、積み方より経路そのものを変えるべき根拠が得られている。
- **Dで混載と長距離移動の相乗効果を試す。** Bの長所は実測できている。少数色だけでなく、各色の局所的な少量輸送を対象にする。
- **Eで踏み台の時間方向の自由度を広げる。** 資材を複数地点で使う余地は大きいが、移設費の回収と依存関係の評価が難しいため、独立した実験として扱う。

これは着手のしやすさと根拠の強さによる順序であり、未実験の改善率の順位ではない。いずれも制限時間の中で全帰巣する最良計画を更新し続ける設計とする。現状もB・CはLOCALの探索に約1.46秒を使っているため、単に待ち時間を延ばすより、同じ時間で到達できる計画の範囲を広げることを重視する。
