# AHC072 の初期アプローチ3案

作成日：2026-09-25。問題文、公式の操作実装、生成入力99件の構造を調べた設計メモである。solver の実装や実行によるスコア比較はまだ行っていない。

## 結論

最初の本命は **B：混色の集荷と両端荷下ろし** とする。近くのスライムを色不問で集められ、巣で下段を帰巣させながら上段を発射する、この問題固有の操作を使えるためだ。対抗の A は同色の大量輸送、C は踏み台を繰り返し使う輸送に、それぞれ異なる改善余地がある。

| 案 | 最適化する対象 | T を減らす機構 | 有利と考える入力 |
| --- | --- | --- | --- |
| A：同色の容量制約付き集約木 | 同色のグループ分けと巣へ合流する木 | 合流後の経路を1回の輸送で共用する | 色数が少ない、色数分布が偏る、共通の通路がある |
| B：混色の集荷と両端荷下ろし | 近傍グループ、集荷順、塔の両端からの配送順 | 集荷の近さと混色での経路共用、帰巣時の発射を使う | 少数しかいない色が多い、異色が近くに混在する |
| C：寿命を計画した踏み台網 | 踏み台の位置、高さ、担当色、色の処理順 | 同じ踏み台を複数の荷物が利用して長距離を跳ぶ | 直線通路が長く、同じ区間を繰り返し運ぶ |

3案とも、全スライムを最初から輸送計画に含める。終了時の `E = 0` は通常の構成の帰結とし、残存分を別方式で消す処理は設けない。公式の絶対スコアは小さいほどよく、`E = 0` のとき目的は `S = T` の最小化である。

## 設計の根拠となる操作の性質

以下は問題文と `tools/src/lib.rs` の `State::apply` からの演繹であり、スコア実験による知見ではない。記号は [notations.md](notations.md) に従う。

### 積載量と飛距離の交換条件

動く匹数は `h - k`、飛距離は `l <= k + 1` なので、次が成り立つ。

- `(h - k) + l <= 9`。8匹をまとめて動かすときは1マスしか進めない。
- `(h - k) * l <= 20`。上限は「5匹を4マス」または「4匹を5マス」で達する。
- 下段3匹と荷物5匹、または下段4匹と荷物4匹が、理想的な輸送量の組み合わせになる。

ただし、この20は1操作での「匹数×進むマス数」の上限である。踏み台の収集費、その後の帰巣費、目的地に近づく方向かどうかを含まない。長距離ジャンプだけを数えて優劣を決めることはできない。

### 他のスライムをその場に保存した輸送

初期状態の他グループは各マス高々1匹である。運ぶグループを7匹以下にすると、その上へ着地しても高さ8以下になる。次の操作でその1匹だけを `k = 1` として残せば、他グループの配置を変えずに通過できる。

この性質により、A と B では「今回扱うグループ以外を初期位置に保存する」という構成が使える。全グループを順番に処理しても、後続グループのために障害物を退避させる必要がない。

7匹はこの構成を簡潔に成立させる値である。8匹をまとめる場合も、8匹になる区間の着地点が空であるなど、帰巣前の高さ制約を満たす経路を計画できればよい。

### 巣で塔の両端から帰巣させる

巣の色が塔の上端にあれば、着地時に同色の連続部分が消える。下端にあれば、その同色部分を残して上側を跳ばすことで、出発時に下段が消える。後者では、帰巣する下段をその操作の踏み台にも使える。

例えば、色 `a` の巣に下から `[a, a, b, b]` があり、同じ直線上の3マス先に空の色 `b` の巣があるとする。間がすべて床なら `k = 2, l = 3` の1操作で上の2匹を送り、出発点と着地点の計4匹が帰巣する。

混色の塔も、現在の両端のいずれかの色を次の配送先に選べる。途中で全体が反転しても、両端にある色の集合は変わらない。この性質が B の全消去構成を支える。

### 反転の偶奇は集荷順の制約になる

運搬中の塊全体を `l = 1` で動かす区間では、1操作ごとに塊の上下とマスの市松模様の偶奇がともに反転する。一方の偶奇のマスにいるときだけ塔を逆向きに読み直せば、その読み順は移動では変わらない。

この読み順では、新しく集める1匹は、集荷マスの偶奇に応じて列の左端か右端に加わる。したがって、集荷順と積み順は独立には決められない。隣接移動の遠回りは偶数長しか増やせず、反転の偶奇だけを修正する目的には使えない。長距離ジャンプを使った場合は、操作ごとの反転を別途追跡する。

### 操作数の尺度

`E = 0` の任意の解では `T >= M` である。各初期スライムは巣以外の別々のマスにいるため、それぞれの初期マスを少なくとも1回は出発点にしなければならない。

各スライムから自色の巣への床上最短距離の合計を考えると、1操作での減少は高々20である。したがって、その初期値を20で割って切り上げた値も `T` の下界になる。全操作を `l = 1` に限定する場合は、同様に8で割った値が下界になる。いずれも粗い下界であり、達成可能なスコアの予測ではない。

なお、操作する塔を選ぶ指揮者の移動費は存在しない。1グループが消えた後、別の場所のグループを直ちに操作できる。配送案に空荷の帰路を加算してはいけない。

## A：同色の容量制約付き集約木

### 仮説と構成

根拠は backlog の O1 と O2 である。同色を集める距離の負担があっても、合流後の長い経路を共用できれば、操作数の削減が上回ると考える。

同色のスライムを基本7匹以下のグループに分ける。各グループの初期位置とその色の巣を結ぶ小さな木を作り、巣を根として、葉から順にスライムを送る。ここでいう集約木は、選んだ初期位置以外の床も合流点に使う Steiner 木である。

枝の下にあるグループ内のスライムをすべて集めてから、親へ1マス送る。別グループの1匹がそのマスにいる場合は、それだけを下段に残す。同色なので反転しても輸送方針は変わらない。

### T を直接評価できる点

1グループの操作数は、その根付き木の使用辺数になる。各辺は、その下にいるスライムをまとめて1回だけ運ぶためだ。複数の枝を先に合流させるほど、巣までの共通部分を節約できる。

探索の主対象は、グループへの所属変更、グループ間の交換、合流点の移動、根へ向かう枝の付け替えである。単純な「最短路を個別に歩かせて、出会ったら合流」よりも、どの経路を共用するかを先に最適化する。

少数端点の木には部分集合DPを使える。7匹を端点にして各部分集合と床マスの状態を持てば、巣への Steiner 木を厳密に求められる。多数の候補には既存枝を安く評価する近似構築を使い、有望なグループだけを厳密化する構成が考えられる。2秒で何回評価できるかは未測定である。

### E = 0 が構成に含まれる理由

処理中のグループは総数7匹以下、他グループは各マス高々1匹なので、どの合流でも高さは8以下になる。処理後に他グループは元の場所へ残り、処理したグループはすべて根の巣へ入る。この不変条件を全グループに適用すれば、最後に盤面が空になる。

### 勝ち筋と限界

- 多数派の色を長い共通経路へまとめられる場合に強い。細い通路も経路の共有に使える。
- 木の使用辺数が実際の `T` なので、目的関数と実行結果が対応しやすい。
- 少数色には積載量の利益が小さい。同色を集めるための枝が長いと B に負けうる。
- 基本構成は `l = 1` なので、長距離ジャンプによる輸送量の上限20を使い切らない。

機構確認では、合流後に2匹以上を運んだ辺数、グループの積載数、個別最短距離合計からの操作削減を数える。距離の短縮が集約によるものかを確認する。

## B：混色の集荷と両端荷下ろし

### 仮説と構成

根拠は backlog の O2 と O3 である。色不問の近傍距離は同色限定の約3分の1なので、集荷を近傍で済ませ、複数の巣まで途中の移動を共用すれば有利と考える。

近くにいる基本7匹以下を色不問でグループにする。1つの塔でそれらを拾い、集荷順から決まる積み順を追跡する。グループ外の初期スライムには乗っても、それだけを下段へ残して移動する。

集荷後は、塔の両端のいずれかの色の巣へ向かう。着地時に目的の色が上側なら自動で帰巣する。下側なら、その色の連続部分を巣に残して上段全体を次へ発射する。残す下段が多ければ、その最初の1操作を長距離ジャンプにできる。

集荷中に自動帰巣が起きた場合も、その時点の塔を正確に更新する。全員を拾う前に塔が空になったら、未集荷のスライムから次の操作を始められる。

### 配送部分を小さな厳密探索にできる点

集荷後の色列を固定すると、帰巣させるのは列の端の連続部分だけでよい。残る列は常に元の列の連続区間か、その反転になる。

そのため、配送状態は「残る区間、上下の向き、現在の床マス」で表せる。7匹なら区間は最大28通り、向きは2通り、床マスは最大400なので、非空状態の上限は22,400である。

遷移を次の2種類に限定しても、全帰巣まで探索できる。

1. 塊全体を隣の床へ送り、反転と着地時の帰巣を適用する。
2. 現在地が下端の色の巣なら、下端の同色部分を残して上段全体を合法な距離だけ送り、両端の帰巣を適用する。

各遷移のコストは1なので、BFSでこの制限内の最短配送を求められる。他グループの踏み台による2マス移動はこの基本モデルに含めず、他グループがすでに帰巣したかどうかに依存しないようにする。7匹以下なら、それらの有無は着地容量にも影響しない。

この22,400は配送だけの上限であり、集荷順を同時に厳密最適化できるという主張ではない。外側でグループ分けと集荷順を近傍探索し、変わったグループの配送だけを再計算する。集荷時の経路と自動帰巣も評価に含める。

### E = 0 が構成に含まれる理由

集荷後の非空の塔には必ず端の色がある。床は連結しており、7匹以下の塊は他の初期1匹を保存したまま、その色の巣へ運べる。到着時または次の発射時に少なくとも1匹が帰巣する。最後が単色になれば、その巣への着地で塔が消える。

下段に残すのはその場で帰巣する色だけであり、配送途中の別の床へ未処理の塊を放置しない。この構成をすべてのグループで実行すれば `E = 0` になる。下段の帰巣が発射時まで遅れる状態も、物理的な塔のまま探索すれば扱える。

### 勝ち筋と限界

- 少数色を混ぜても積載量を確保でき、色ごとに独立した遠距離輸送を減らせる。
- 「下端を帰巣させながら上段を跳ばす」操作では、踏み台の帰巣に追加の後始末が要らない。
- 集荷順で配送しやすい色列を作る必要がある。市松模様の偶奇と積み順を無視した巡回路最適化では不十分だ。
- 巣が互いに遠いと、混載の利益より巡回の遠回りが大きくなる。グループの所属変更まで探索する必要がある。
- 個々の配送BFSは小さいが、外側の候補数を含めた2秒での実行量は未測定である。

機構確認では、混色のまま運んだ操作数、1操作当たりの運搬匹数、出発点での帰巣数、帰巣する下段を使った長距離発射数を数える。単に近くの個体を集めた結果だけになっていないか確認する。

## C：寿命を計画した踏み台網

### 仮説と構成

根拠は backlog の O4 と O5 である。初期の1匹を待機させるだけでも踏み台として使える地点があり、壁の少ない入力には4マスの直線も多い。同じ場所を複数回通る輸送なら、踏み台による削減が設置費を上回る可能性がある。

色を処理する順序を決め、後で処理する色のスライムを、それ以前の色の踏み台として使う。初期の1匹はそのまま利用できる。繰り返し使う場所では、後で処理する同色の数匹を集めて、高さ2〜4の踏み台を設置する。

踏み台は、構成員の初期位置から設置場所を経由して、その色の巣へ運ぶ計画の一部分とする。設置場所は空き床か同色のいる床から選ぶ。自色の巣では単色の踏み台が直ちに帰巣するため、そこへ常設することはできない。

設置する複数の踏み台に同じスライムを重複して割り当てない。設置用の集荷経路も、自色の巣で途中帰巣してしまわない経路であることを確認する。まず設置後の配置を確定させ、その配置から色順の輸送を計画する形なら、踏み台の実在と利用可能な期間を明確にできる。

説明用の成立しやすい構成では、待機中の塔を高さ3以下、輸送グループを5匹以下とする。下段3匹を残すと5匹を4マス跳ばせる。着地点にも高さ3の塔があってよい。実際の最適化では、高さと積載量を経路ごとの容量制約として扱い、一律にこの組み合わせへ固定する必要はない。

### 利用順序も輸送費になる点

ある踏み台を消してしまうと、それを使う後続の移動が増える。そこで、踏み台の担当色を処理する前に、その踏み台を使う輸送をすべて済ませる。

色の処理順を使えば、この依存関係は自動的に非巡回になる。後の色の踏み台は、前の色からだけ使われる。担当色の番では、その踏み台自体も通常の輸送グループへ含めて巣へ送る。

踏み台の配置が固定されると、色ごとの輸送路は有向グラフで扱える。出発点に残せる高さに応じて、長さ1〜`k + 1` の直線をコスト1の辺とする。壁と着地前の容量を満たす辺だけを使う。先に処理済みの色の踏み台は、このグラフから外れる。

### 設置の判断と探索

利益は「設置後に荷物が減らせる操作数」から「集めて設置する操作数」と「踏み台側の帰巣経路が増やす操作数」を引いて考える。高さだけを評価したり、踏み台の帰巣費を最後へ持ち越したりしない。

例えば、下段3匹がすでにある地点から、5匹を4マス先へ送れるなら、その区間は隣接移動4回からジャンプ1回になる。1回の通過で3操作を節約するが、設置して1回しか使わないなら得とは限らない。複数回の利用で初めて設置費を回収する場合がある。

探索では、踏み台の追加と削除、場所の変更、高さの変更、担当色の変更、色の処理順の変更を扱う。利用者のいない踏み台を保持しない。

固定された踏み台配置のもとで隣接する2色の処理順を交換した場合、その2色以外では「残っている色の集合」が変わらない。各色の輸送が他色の配置を保存する構成なら、再評価する輸送をこの2色に絞れる。2秒の探索では、このような差分を使える点が利点になる。

### E = 0 が構成に含まれる理由

全スライムは、その色の処理時に巣へ送る対象として登録する。踏み台になったものも例外にしない。処理済みの色は盤面から消え、未処理の色だけが計画された踏み台として残る。

高さ3以下の待機塔と5匹以下のグループを使う構成なら、隣接移動を含む通常の輸送経路はどの待機塔も容量8以内で通過できる。全色を処理した時点で、踏み台を含めた全員が帰巣する。設置するための移動も、高さと帰巣を満たす操作列として先に計画する。

### 勝ち筋と限界

- 同じ踏み台を何度も使えれば、A の隣接集約より輸送量を増やせる。
- 最初からある1匹にも利用価値があり、先に帰巣させることが常に得とは限らない。
- 少数の荷物、曲がり角の多い地形、利用の少ない場所では設置費を回収できない。
- 高い踏み台は荷物の容量を削る。空の床なら8匹を運べても、下段3匹の上には5匹しか載せられない。
- 利用できる踏み台と「目的地へ近づく方向へ使える踏み台」は異なる。幾何的な候補数だけでは効果を主張できない。

機構確認では、各踏み台の利用回数、設置に要した操作数、担当色の帰巣まで含めた操作数、実際に短縮した輸送区間を記録する。長距離ジャンプが発動しても、総 `T` が減らなければ採用の根拠にならない。

## 次に判断したいこと

1. **B の最初の検証**：集荷順と小規模な厳密配送を組み合わせると、混色のままの輸送と出発点帰巣が十分使われるか。近い個体を集める利点が配送の遠回りを上回るかを調べる。
2. **A との比較**：同色の集約木は、色の偏りが大きいケースでどの程度の差を作るか。多数派の輸送と少数色の輸送を分けて観察する。
3. **C の回収条件**：初期の1匹の利用だけでどこまで改善できるか。新しい踏み台を設置する場合は、設置から帰巣まで含めた総操作数を比較する。

3案の実験を分け、まず各機構自体の効果を確かめる。比較の中心は全ケース `E = 0` のもとでの絶対スコア `S = T` とし、入力の色の偏り、少数色の割合、壁率ごとの違いも見る。現時点では、スコアの優劣や改善率は未確認である。
