# REFRECTION

## コンベア配置の発想

- 既存実装では「次の箱をどう出口へ運ぶか」に囚われていた。beam や future score も、基本は箱を個別に出口へ近づける発想だった。
- もう一つ、コンベア配置は焼きなましで決めるものだと思い込んでいた。高速に操作列を評価できるなら自然な発想だが、配置の構造そのものを先に決める視点が弱かった。
- 出口に接するコンベアだけが搬出順を直接決めるので、これを幹線 `main` と見る。
- 1箱ずつ出口へ運ぶと操作数が重い。`main` に箱列を作り、回すだけで多くの箱が出口へ向かう形にしたい。
- そのため `main` はできるだけ長くしたい。
- ただし全マスを `main` にすると、箱を途中で差し込む場所や保持する場所が消える。
- 欲しい構造は「長い `main` + たくさんの 1箱バッファ」である。
- 各マスの所属は高々2本なので、最小のバッファは `main` に隣接する長さ2コンベアになる。
- 長さ2なら副コンベア内の順序管理がなく、`main` 側と `side` 側の swap として扱える。
- 盤面は `main` と `side` におおよそ二分するのが自然。
- `main` は密に通しつつ、隣に `side` 用の余白を残す必要がある。
- その結果、櫛型・粗い蛇行型の配置が自然に出る。
- 目的は綺麗な巡回路ではなく、`main` の多くの位置に `side buffer` を付けることである。

## 運用上の反省点

- fallback を勝手に実装しない。失敗時の挙動を入れる必要がある場合は、目的と影響を明示してから判断する。
- 素早く分析するための仕組みが必要。評価結果、ケース別の失敗、盤面・操作列の特徴をすぐ見られる補助入口を整える。
